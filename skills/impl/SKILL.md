마일스톤 문서대로 구현을 진행해줘. 대상 지정: "$ARGUMENTS"
- 인자로 마일스톤 번호(예: M3)가 오면 docs/milestones/M3.md를 대상으로 (재실행·이어하기 용도)
- 생략하면 docs/milestones/M*.md 중 번호가 가장 큰 문서를 대상으로

**대상 레포**: 시작 시 대상 레포 루트를 정한다 — 기본은 세션 레포(현행 단일 레포 동작 그대로),
상위 폴더 단일 세션에서 특정 자식 레포를 지시받으면 그 자식 레포 루트. 이 커맨드의 모든
상대경로 산출물(`docs/`·`.tide/phase`)·테스트 명령은 **대상 레포 루트 기준/cwd**로 수행한다.
상세·격리 규약은 `docs/conventions.md`의 "멀티 레포 / 대상 레포" 절.

시작 전 검사: 대상 마일스톤 문서가 존재하는지 확인해줘.
없으면 아무것도 구현하지 말고, /tide:milestone 을 먼저 실행하라고 안내한 뒤 중단해줘.

검사를 통과하면 (대상 레포 루트의) .tide/phase 파일에 `impl` 한 줄을 기록해줘 (.tide/ 디렉터리가 없으면 생성).

docs/project-context.md가 있으면 먼저 읽어 기존 구조를 파악한 뒤 구현해줘
(없으면 평소대로 진행).

진행:
- 태스크를 의존성(deps) 위상 순서로 구현하되, **독립(무의존) 태스크는 아래 "병렬
  디스패치"대로 동시 실행**한다
- 구현 후 프로젝트의 테스트 명령(cargo test / npm test / pytest 등)을 실행해 결과 확인

## 병렬 디스패치 (독립 태스크 동시 실행)

이 절은 tide의 **병렬 실행 단일 원본**이다 — `/tide:cycle`의 impl 단계도 이 규약을
그대로 따른다.

태스크의 `(deps: M{N}-T01, …)` 표기로 의존 그래프를 만들고 위상 정렬한다. 선행이 모두
끝난 같은 레벨에 **무의존 태스크가 2개 이상**이면 그 태스크들을 **하나의 메시지에서
동시에** Agent(서브에이전트) 도구로 위임한다(한 메시지에 복수 Agent 호출 = 동시 실행).
레벨 간에는 배리어 — 다음 레벨은 현재 레벨의 모든 서브에이전트가 끝난 뒤 착수한다.

**서브에이전트에 전달할 것**(재해석 없이 착수 가능하도록): **대상 레포 루트**(서브에이전트도
그 레포 루트를 기준으로 산출물·cwd를 두고 git 금지를 상속), 대상 마일스톤 문서 경로,
`docs/project-context.md`(있으면), 맡은 **태스크 ID·상세·해당 완료 기준**, 그리고
부수효과 분리 상속 — "코드·테스트만 남겨라. git commit/tag/push·코드 리뷰 금지.
완료보고서는 메인이 쓴다." **반환 계약**: 각 서브에이전트는 수행 내용·**실제 변경 파일
목록**·테스트/검증 결과·미해결 이슈를 구조화해 돌려준다.

### 파일 충돌 안전장치

공유 워킹트리에서 같은 파일을 동시에 고치면 경쟁이 난다. 한 레벨을 병렬로 내리기 전,
각 태스크의 마일스톤 "파일 변경 요약"·상세로 **예상 변경 파일 집합**을 추정한다.

- 두 독립 태스크의 예상 집합이 **겹치면 그 겹치는 태스크들만 순차**로 내리고(부분 폴백),
  비겹침 태스크는 병렬을 유지한다.
  - 겹침 판정은 **정규화된 파일 경로의 교집합**으로 한다. 한쪽 집합이 비었거나(예: "변경
    파일 (없음)") **조건부**(예: "결함 발견 시 X 수정")여서 단정할 수 없으면 그 태스크는
    안전 측으로 **잠재적 겹침**으로 보고 관련 태스크와 순차로 내린다 — 모호한 집합을
    비겹침으로 낙관하지 않는다.
- 겹침이 잦으면 그건 마일스톤 분해 신호다(conventions: "태스크를 가능한 한 독립적으로,
  파일 비중첩"). 폴백은 안전망이지 정상 경로가 아니다.
- **워크트리 격리**(선택·고급, 기본 비활성): 파일 경쟁이 불가피한데 병렬 이득이 크면
  서브에이전트를 격리된 git worktree에서 돌리는 옵션을 쓸 수 있으나, 병합 비용·복잡도
  때문에 기본은 "공유 트리 + 비겹침" 경로다.

### 결과 병합·부분 실패

병렬 서브에이전트 결과를 메인이 모아 **단일** `docs/reports/M{N}-impl.md`로 병합한다
(보고서 형식은 평소와 동일 — 병렬이라고 형식이 바뀌지 않는다). 변경 파일 요약·테스트
결과를 통합한다.

- **부분 실패**: 한 서브에이전트가 실패/중단되면 — 같은 레벨의 다른 병렬 결과는 보존하고,
  실패 태스크는 메인이 순차로 재시도한다. 재시도도 실패면 "중단 처리"대로 어느 태스크에서
  왜 멈췄는지 보고하고 멈춘다.
  - "실패/중단"은 ① Agent 호출이 오류로 끝났거나 ② 반환 계약(수행 내용·변경 파일·검증
    결과)을 못 채우고 **미완료·미해결 이슈를 보고**한 경우다(반환이 산문으로 "못 했다"여도
    실패로 친다). 재시도는 **1회**(메인이 직접 순차로); 그 1회도 실패면 멈춘다.
- **폴백 조건**: Agent 도구를 쓸 수 없거나, 레벨에 태스크가 1개뿐이거나, deps 이상
  (순환·미존재 ID)·파싱 불가면 **메인이 직접 순차** 구현한다(위상 순서는 지킴).
- **tide-guard 정합**: 서브에이전트는 phase=`impl`에서 동작하므로 그 안에서 git을
  시도하면 가드가 차단한다 — 부수효과 분리가 병렬에서도 기계적으로 강제된다.

완료보고서 작성 — docs/reports/M{N}-impl.md (재실행이면 기존 보고서를 갱신):
- ${CLAUDE_SKILL_DIR}/template.md 템플릿을 읽어 그 구조 그대로 작성
  ({} 자리를 채우고 안내문은 제거)
- 템플릿을 읽을 수 없으면 폴백 — 개요 / 태스크별 수행 내용 / 변경 파일 요약 /
  테스트 결과 / 미해결·후속 메모 5개 섹션
- **개요에 재작업 라운드(rework)를 적는다** — 정의·기록 방식·수렴 조건의 단일 원본은
  `docs/conventions.md`의 "리뷰 검증 규율" 절(재작업 라운드 소절)이며 여기서 재정의하지 않는다.
  - **최초 실행은 라운드 `0`**이고 그때도 값을 적는다 — 값이 없는 보고서는 리뷰가 0으로 해석하므로
    (하위 호환) 기존 보고서(M1~M31)를 소급 갱신하지는 않는다.
  - **재실행**(`/tide:impl M{N}`)이면 직전 `docs/reports/M{N}-review.md`의 판정을 확인해,
    **판정이 `불가`였으면 라운드를 +1**한다. 값의 근거는 **직전 impl 보고서 개요에 적힌 값 + 1**이며,
    직전 보고서에 값이 없으면 **0에서 시작**한다(→ 첫 재작업은 `1`).
  - 판정이 `불가`가 아닌 재실행(이어하기·부분 보완)이면 **값을 올리지 않고** 기존 값을 그대로 옮긴다.
  - 리뷰 보고서의 계측 줄이 이 값을 읽어 가므로 **개요의 값이 단일 출처**다 — 둘을 어긋나게 두지 않는다.

구현·테스트·완료보고서까지 마치면 .tide/phase를 `idle`로 되돌린 뒤 결과를 보고해줘.
다음은 절대 수행하지 마: 코드 리뷰 / git commit / git tag / git push
