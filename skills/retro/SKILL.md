누적된 tide 사이클을 가로질러 읽고 회고 문서를 생성·갱신해줘. "$ARGUMENTS"가 있으면
이번 회고 시점의 메모로 쓴다.

**대상 레포**: 읽어들이는 문서와 산출물 `docs/reports/retro.md`는 대상 레포 루트 기준이다(읽기 전용). 규약은 `docs/conventions.md`의 "멀티 레포 / 대상 레포" 절.

`/tide:status`와 같은 **읽기 전용 원칙**으로 동작한다 — 회고 문서 **하나**(`docs/reports/retro.md`)만
생성/갱신하고, 그 외 코드·문서·`.tide/phase`는 일절 건드리지 않으며 git 작업도 하지 않는다.

## 수집 (읽기 전용)

다음을 모두 읽어들인다:
- `docs/milestones/M*.md` — 마일스톤별 목표·완료 기준·목표 버전
- `docs/reports/M*-impl.md` — 완료보고서(태스크 수행·미해결·후속 메모)
- `docs/reports/M*-review.md` — 리뷰보고서(비판점 차단/권장/사소·릴리즈 판정·추천 버전)

(자기 자신 `docs/reports/retro.md`는 입력에서 제외한다.)

## 집계 규칙

1. **반복된 문제·이슈 군집** — 리뷰보고서의 차단/권장 이슈를 주제별로 묶어, 두 사이클
   이상에서 되풀이된 주제(예: 자동 발견·등록 확인, 문서-실동작 일치, 설치 충돌)를 추린다.
   각 군집에 등장 위치(M번호)와 처리 추이(수정/수용/이월)를 단다.
2. **수용된 트레이드오프** — 각 리뷰의 "사소"·"수용" 항목과 impl 보고서가 의도적으로
   남긴 한계를, 그 **사유**와 함께 목록화한다.
3. **후속 항목 추적** — impl/review의 "미해결·후속 메모"로 표기된 항목이 **이후
   마일스톤·보고서에서 실제로 반영됐는지** 추적한다. 각 항목을 반영/미반영으로 분류하고
   반영된 경우 어느 마일스톤이 집어갔는지 적는다(미반영은 다음 사이클 후보로 부각).
4. **릴리즈 판정·버전 추이** — 마일스톤별 릴리즈 판정(가능/불가)과 확정 버전(major/minor/
   patch)의 추이를 한 줄씩 요약한다.

이상 상황 처리 — 보고서가 하나도 없거나 한 사이클뿐이면 회고 이득이 작음을 명시하고,
가진 입력 범위로만 집계한다(없는 항목은 "해당 없음"으로 둔다).

## 산출물

- 위치: `docs/reports/retro.md` (갱신형 단일 문서 — 보고서 디렉터리 일관성 + 이력 보존)
- 회고 시점마다 문서 **최상단에 새 회고 섹션을 누적**한다(기존 섹션은 보존).
- 참고: 과거 회고 섹션은 보존을 위해 `docs/reports/retro-archive.md`로 분리돼 있을 수 있다.
  분리되더라도 동작은 불변 — `/tide:retro`는 여전히 `retro.md`(및 archive)를 입력에서 제외하고
  새 섹션을 `retro.md` 최상단에 쌓으며, "기존 섹션 보존"은 아카이브가 충족한다.
- 형식: `${CLAUDE_SKILL_DIR}/template.md` 템플릿을 읽어 그 구조 그대로 작성
  ({} 자리를 채우고 안내문은 제거). 템플릿을 읽을 수 없으면 폴백 — 집계 범위 /
  반복된 문제·이슈 군집 / 수용된 트레이드오프 / 후속 항목 추적 / 릴리즈 판정·버전 추이 /
  회고 메모 6개 섹션.

생성/갱신을 마치면 회고 핵심(반복 문제·미반영 후속 중심)을 요약해 보고해줘.

다음은 절대 수행하지 마: 회고 문서 외 파일 생성·수정 / `.tide/phase` 변경 / git 작업
(읽기 전용 커맨드 — `/tide:status`와 동일 원칙)
