빌드 후 사용자 테스트 등에서 **발견한 에러를 그 자리에서 고치고**, 그 발견-수정을 하나의 세션으로
묶어 `docs/reports/debug-{N}.md` 보고서 하나로 남겨줘. 인자: "$ARGUMENTS"
- `done` (단독 토큰) → 아래 "세션 종료 (done)" 경로
- 그 외 문자열 → 세션 열기/이어가기. 그 문자열을 첫 증상으로 취급
- 인자 없음 → 열린 세션이 있으면 이어가기, 없으면 세션만 열고 증상을 물어봄

**대상 레포**: 산출물·`.tide/phase`·테스트는 대상 레포 루트 기준/cwd다. 규약은 `docs/conventions.md`의 "멀티 레포 / 대상 레포" 절.

계획 우선 사이클(milestone → impl → review)과 달리 debug는 **발견 우선**이다 — 무엇을 고칠지는
고쳐 보기 전엔 알 수 없으므로 마일스톤·태스크·deps를 요구하지 않는다. 대신 tide가 실제로 지키는
두 가지는 그대로 보존된다: **부수효과 분리**(git 쓰기는 release에서만)와 **산출물 추적**(무엇을
왜 고쳤는지가 문서로 남고 CHANGELOG로 간다). `/tide:cycle` 자동 체이닝의 대상은 **아니며**
(체이닝은 계획 우선 전용), 출구는 사이클과 같은 `/tide:release`다.

## 세션 상태

- `.tide/debug-session` — **활성 debug 보고서 번호 한 줄**(예: `3`). 파일 존재 = 세션 열림.
- `.tide/phase` — 종전 계약대로 **단계명 한 줄**만 담는다(debug 세션 중에는 `debug`).
  세션 번호를 phase에 섞지 않는다 — phase 계약은 불변이다.

## 세션 열기 / 이어가기

1. `.tide/debug-session`이 있으면 그 번호 N을 그대로 쓴다(이어가기). 없으면
   `docs/reports/debug-*.md` 중 최대 번호 + 1(하나도 없으면 1)을 N으로 정해
   `.tide/debug-session`에 한 줄로 기록한다. 번호는 마일스톤 번호와 무관한 **독립 증가 수열**이다.
2. `.tide/phase`에 `debug` 한 줄을 기록한다 (`.tide/` 디렉터리가 없으면 생성).
3. `docs/project-context.md`가 있으면 먼저 읽어 기존 구조를 파악한 뒤 진행한다
   (없으면 평소대로 진행).

## 항목 처리 (증상 하나마다)

증상마다 **재현 → 진단(원인) → 수정 → 검증**을 수행한다. 검증은 프로젝트의 테스트 명령
(cargo test / npm test / pytest 등) 또는 증상을 재현하던 절차의 재실행으로 한다. 진단에 필요한
git **읽기**(`git log`·`show`·`diff`·`blame`)는 가드가 통과시키므로 자유롭게 쓴다.

**그 항목이 끝날 때마다 곧바로 `docs/reports/debug-{N}.md`에 항목을 append한다** — 세션 종료를
기다렸다가 한꺼번에 쓰지 않는다. 세션은 여러 턴에 걸쳐 길어지고 그 사이 컨텍스트가 요약될 수
있으므로 **파일이 유일하게 믿을 수 있는 누적 저장소**다. 세션이 중단돼 방치돼도 그때까지의
발견이 파일에 남는 것이 의도된 동작이다(미완결 보고서 = 무슨 일이 있었는지의 증거).

- 그 세션의 첫 항목이면 보고서 제목과 "항목별 기록" 골격을 먼저 만든 뒤 항목을 append한다.
  개요·릴리즈 판정 섹션은 `done`에서 채우므로 이때는 비워 둔다.
- **미해결 항목도 반드시 남긴다** — 재현은 됐지만 못 고친 것, 원인만 밝힌 것도 항목으로 기록하고
  상태를 `수정함` / `미해결` / `원인만 규명` / `확인함` 중 하나로 표기한다. "고친 것만 기록"하면
  발견 우선 작업의 절반이 증발한다.
- **`확인함`** = 결함이 아니었거나 **실측만 한 항목**(검증 기록)이다 — 증상·재현·원인·수정은
  "해당 없음"으로 두고 **검증**만 채운다. **용도 경계**: 발견-수정 세션 중 **그 작업과 같은
  맥락에서** 잔여 리스크를 실측한 경우에만 쓴다(예: 같은 릴리즈 전 테스트에서 리뷰가 "실행
  미검증"으로 남긴 항목을 함께 돌려 닫음). **검증만 하러 debug 세션을 열지는 않는다** — 그것은
  `/tide:impl`·`/tide:review`의 일이며, 허용하면 debug가 아무거나 담는 자루가 된다.
  상세는 `docs/conventions.md`의 "debug 세션" 절(항목 상태값 항목)이 단일 원본.

## 정오표 (다른 보고서의 사실 오류를 발견했을 때)

세션 중 **이미 릴리즈된** 보고서(impl·review·debug 무엇이든)의 사실 오류를 발견하면 **본문을 고치지
말고** 그 보고서 말미에 `## 정오표`를 append한다 — 항목마다 **날짜 / 무엇이 틀렸는지(본문 위치) /
실제 사실 / 확인 근거**. 본문은 "그때 무엇을 근거로 릴리즈했는가"의 증거라 소급 수정하면 증거가
지워진다. **미릴리즈 보고서면 본문을 직접 고친다**(아직 배포되지 않았다). 릴리즈 여부는 그 파일이
**마지막 릴리즈 태그의 트리에 포함돼 있는지**로 판단한다(git **읽기** — 가드가 통과시킨다). 정정한
사실은 **이번 세션 보고서에도 한 줄** 남긴다. 단일 원본은 `docs/conventions.md`의 "정오표 (errata)" 절.

## 세션 종료 (done)

1. `.tide/debug-session`이 **없으면** 열린 debug 세션이 없다고 알리고 **아무것도 하지 않고
   중단**한다 — 보고서를 만들지 마(빈 보고서 방지).
2. 있으면 그 번호 N의 `docs/reports/debug-{N}.md`에 **개요·변경 파일 요약·미해결·후속·릴리즈
   판정 섹션을 채워 마무리**한다(항목별 기록은 이미 append돼 있다).
3. `.tide/debug-session`을 삭제하고 → `.tide/phase`를 `idle`로 되돌린 뒤 → 결과와 판정을
   명확히 보고한다.

**변경 파일 요약의 기준선 = 이 세션이 시작될 때의 워킹트리**다 — 추가/수정/삭제는 그 트리 대비
**이 세션이 한 행위**이지 git `HEAD`나 마지막 릴리즈 태그 대비가 아니다. 기준선 트리에 **미커밋
산출물이 섞여 있으면**(직전 단계 산출물이 아직 커밋 전이면) 표 아래에 **한 줄**로 그 사실과 원인을
고지한다. 부수효과 분리(커밋은 release에서만) 때문에 debug는 거의 항상 미커밋 산출물 위에 얹히므로
**이것이 기본 경로**다. 단일 원본은 `docs/conventions.md`의 "변경 파일 요약 기준선" 절.

## 릴리즈 판정 (형식 계약)

`/tide:release` 프리플라이트는 **리뷰보고서와 debug 보고서를 같은 방식으로 읽는다** — 파서를
이중화하지 않기 위해 리뷰보고서와 **동일한 형식**을 쓴다:
- `## 릴리즈 판정` 섹션에 **`가능` / `불가`**와 `추천 버전: **vX.Y.Z**`를 적는다.
- 판정 규칙: 미해결 **차단급** 항목이 없고 검증이 통과하면 **가능**, 아니면 **불가**(사유 명시).
- 추천 버전 기본은 **patch**(버그 수정 묶음). 수정 과정에서 사용자가 관찰 가능한 동작이
  더해졌으면 minor를 제안하되 그 사유를 적는다.

## 보고서 형식

- 위치: `docs/reports/debug-{N}.md` (N = `.tide/debug-session`의 세션 번호)
- `${CLAUDE_SKILL_DIR}/template.md` 템플릿을 읽어 그 구조 그대로 작성
  ({} 자리를 채우고 안내문은 제거)
- 템플릿을 읽을 수 없으면 폴백 — 개요 / 항목별 기록(증상·재현·원인·수정·검증·상태) /
  변경 파일 요약 / 미해결·후속 / 릴리즈 판정 5개 섹션

다음은 절대 수행하지 마: git commit / git tag / git push (가드가 백스톱으로 차단하지만
**규율이 1차**다) / 마일스톤 문서 생성·수정 / 버전 파일·`CHANGELOG.md` 편집 (그것은
`/tide:release`의 일)

**보고서는 금지 대상이 아니다** — 자기 보고서 append도, 릴리즈된 다른 보고서에 정오표를 다는 것도
debug의 정상 행위다(위 "정오표 (다른 보고서의 사실 오류를 발견했을 때)" 절).
