---
description: "[tide] 현재 맥락 기반으로 다음 마일스톤 문서 생성"
argument-hint: "[마일스톤 주제(선택)]"
---
현재 대화 맥락과 "$ARGUMENTS"를 바탕으로 다음 마일스톤 문서를 생성해줘.

**대상 레포**: 산출물·`.tide/phase`·테스트는 대상 레포 루트 기준/cwd다. 규약은 `docs/conventions.md`의 "멀티 레포 / 대상 레포" 절.

시작 시 (대상 레포 루트의) .tide/phase 파일에 `milestone` 한 줄을 기록해줘 (.tide/ 디렉터리가 없으면 생성).

docs/project-context.md가 있으면 먼저 읽어 기존 구조·스택을 파악한 뒤 마일스톤을
구성해줘 (없으면 평소대로 진행).

규칙:
- 파일 위치: docs/milestones/M{N}.md (기존 M*.md 중 가장 큰 번호 + 1, 없으면 M1)
- 형식: ${CLAUDE_SKILL_DIR}/template.md 템플릿을 읽어 그 구조 그대로 작성
  ({} 자리를 채우고 안내문은 제거). 템플릿을 읽을 수 없으면 폴백 — 목표 / 배경 /
  태스크 목록 / 태스크 상세 / 파일 변경 요약 / 완료 기준 / 메타데이터 7개 섹션
- **에픽(방향)**: `docs/epics/E*.md` 중 `status: open`인 것을 먼저 읽고, 새 마일스톤이 어느 줄기에
  속하는지 메타데이터에 `epic: E{N}`으로 적는다. 그 에픽의 「속한 마일스톤」에도 이 번호를 더한다
  (양방향). **열린 에픽이 없으면 이 항목은 발동하지 않는다**(에픽을 쓰지 않는 저장소는 현행 그대로).
  규약의 단일 원본은 `docs/conventions.md`의 "에픽 (방향) 층" 절.
- 태스크 ID: M{N}-T01, M{N}-T02 …
- 태스크는 한 번에 끝낼 수 있는 크기로 분해하고, 가능한 한 서로 독립적으로
- 선행 의존이 있으면 태스크 끝에 (deps: M{N}-T01, …)

번호 사전경고 (브랜치 간 충돌 예방 — advisory·읽기 전용): 위 규칙대로 다음 번호 `M{N}`을 정한
**직후, `M{N}.md`를 만들기 전에** `git log --all --diff-filter=A -- "docs/milestones/M{N}.md"`로
그 번호가 다른 ref에 이미 도입됐는지 확인해줘(git 읽기 — 가드 통과). 있으면 그 ref를 밝혀 한 줄로
경고해줘 — 예: "⚠ M{N}이 이미 다른 ref({branch})에 도입됨 — 병렬 브랜치 번호 충돌 가능(머지 시
재할당 캐스케이드). 조정 후 진행하거나 다음 번호를 쓰세요. 원격 브랜치는 최신 fetch 필요." **경고
뒤에도 번호를 자동으로 바꾸지 말고** 종전대로 `M{N}.md` 생성으로 진행해(사용자 판단). 충돌이 없으면
아무 경고도 내지 말고 조용히 진행해(소음 0). 규약 단일 원본은 conventions "마일스톤 문서"의 번호
사전경고 항목.

다음은 절대 수행하지 마: 작업지시서 생성 / 코드 구현 / 테스트 실행 / git 작업
생성을 마치면 .tide/phase를 `idle`로 되돌린 뒤 내용을 요약해서 보고해줘.
