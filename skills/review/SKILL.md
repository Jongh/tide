최근 구현된 작업 내용을 비판적으로 리뷰하고, 릴리즈 가능한 상태인지 보고해줘.

**대상 레포**: 시작 시 대상 레포 루트를 정한다 — 기본은 세션 레포(현행 단일 레포 동작 그대로),
상위 폴더 단일 세션에서 특정 자식 레포를 지시받으면 그 자식 레포 루트. 이 커맨드의 모든
상대경로 산출물(`docs/`·`.tide/phase`)·테스트 명령은 **대상 레포 루트 기준/cwd**로 수행한다.
상세·격리 규약은 `docs/conventions.md`의 "멀티 레포 / 대상 레포" 절.

시작 전 검사: 대상 마일스톤(docs/milestones/M*.md 중 최대 번호 M{N})의 완료보고서
docs/reports/M{N}-impl.md가 존재하는지 확인해줘.
없으면 리뷰하지 말고, /tide:impl 을 먼저 실행하라고 안내한 뒤 중단해줘.

검사를 통과하면 (대상 레포 루트의) .tide/phase 파일에 `review` 한 줄을 기록해줘 (.tide/ 디렉터리가 없으면 생성).

리뷰 항목:
- 요청/마일스톤 대비 구현 완성도
- 코드 구조 일관성 (기존 패턴 이탈 여부)
- 버그·엣지케이스 누락
- 테스트 통과 여부
- 추천 버전 (major / minor / patch)

차단 등급 이슈는 **고치지 마** — 판정 `불가` + impl 반환으로 처리해. 권장·사소는 in-review 수정을
허용한다(아래 `## 등급 판단` 절). 단, 다음은 절대 수행하지 마:
git commit / git tag / git push

## in-review 수정 후 재검증 (re-verify)

리뷰 중에 고친 것이 **1건이라도** 있으면(in-review 수정), 수정 후 **프로젝트 검증(테스트·하니스)을
재실행**하고 그 결과를 리뷰보고서 `## 검증`에 적은 뒤에만 판정해줘. 재실행이 환경상 불가능하면
그 사실을 **"미검증 잔여 리스크"로 명시**한다 — 조용히 넘어가지 않는다. 수정이 0건이면 이 단계는
발동하지 않는다. 상세는 `docs/conventions.md`의 "리뷰 검증 규율" 절.

## 등급 판단 — 판례를 따른다

비판점의 등급(차단/권장/사소)은 즉흥 판단이 아니라 **이미 내려진 판례**를 따른다. 판례 부류의
이름은 `vacuous-pass`다 — 가드·검증이 **공허하게 통과**하거나 규약·문서가 **집행력을 사실보다 넓게
주장**하는 것이 확인되면 **차단**이다. 판례 3건·부류 정의·부인 기록 의무의 단일 원본은
`docs/conventions.md`의 "차단 등급 판례" 절.

- **차단으로 매긴 이슈는 리뷰가 고치지 않는다** — 판정 `불가` + impl 반환이다. 권장·사소만
  in-review 수정 대상이고, 그 수정이 1건이라도 있으면 위 재검증(re-verify)이 발동한다.
- **부인 기록(`precedent-waiver`)**: 판례 부류에 해당한다고 보면서 차단으로 매기지 않으면
  리뷰보고서 `다음 단계`에 **왜 부인하는지**를 한 줄 남긴다. 기록 없는 하향은 규율 이탈이다.
- 판례는 **앞으로의 기준**이다 — 이미 릴리즈된 보고서의 판정을 소급해 바꾸지 않는다.

## 반증 시도 (refutation) — 판정 직전 독립 패스

판정을 내리기 **직전**, 자기 판정 후보를 **반박하는** 패스를 한 번 거친다. 계약·안전 사이클 한정
재량이 아니라 **모든 리뷰의 기본 경로**다. 상세는 `docs/conventions.md`의 "리뷰 검증 규율" 절.

- **디스패치**: Agent(서브에이전트) 도구가 가능하면 반증 패스를 서브에이전트에 위임한다. 전달하는
  것은 **판정 후보와 그 근거뿐**이다 — 리뷰의 추론 과정을 요약해 넘기지 마라(같은 결론을
  되풀이시키면 독립성이 사라진다).
- **서브에이전트에 전달할 것**(재해석 없이 착수 가능하도록): **대상 레포 루트**(서브에이전트도 그
  레포 루트를 기준으로 산출물·cwd를 둠), 대상 마일스톤 문서 경로, `docs/reports/M{N}-impl.md`,
  **실제 변경 파일 목록**, 검증(테스트·하니스) 결과, 판정 후보와 그 근거, 그리고 **부수효과 분리
  상속** — "git commit/tag/push 금지. 보고서는 메인이 쓴다." 서브에이전트는 이 원자료를 **직접
  읽어** "이 판정이 틀렸다면 어디서 틀렸는가"에 독립적으로 답한다. 서브에이전트도 phase=`review`에서
  돌아 tide-guard가 백스톱이 된다.
- **읽기 전용(필수)**: 반증 서브에이전트는 **아무것도 고치지 않는다** — 파일 수정·생성·삭제 금지.
  성립한 지적은 목록으로만 돌려받고 **수정은 메인 리뷰어가** 한다(반증자가 스스로 고치면 미검증 변경이
  트리에 들어가고 계측이 어긋나며, 자기 발견을 자기가 닫아 판정자=실행자 구조가 재현된다).
  전달 문구에 "**아무것도 남기지 마라 — 읽고 답만 돌려라**"를 명시한다.
- **반환 계약**: 성립한다고 보는 지적을 근거(파일·위치·재현 경로)와 함께 목록으로 돌려준다.
- **폴백**: Agent 도구를 쓸 수 없으면 메인이 반증 패스를 **명시 절차로** 수행한다 — 판정 후보를 적어
  놓고 그것을 공격하는 항목을 따로 나열한 뒤, **폴백 사실을 리뷰보고서에 기록**한다(계측 줄에
  `반증 시도 폴백`). 조용히 생략하지 않는다.
- **결과 반영**: 반증이 성립한 지적은 비판점(차단/권장/사소)에 편입하고 **판정을 재산정**한다.
  성립 **0건도 유효한 결과**다 — 판정을 뒤집어야 성공인 패스가 아니라, 시도했다는 사실과 그 결과가
  기록되는 것이 목적이다.

## 리뷰보고서 작성

docs/reports/M{N}-review.md (대상 마일스톤 번호 M{N}에 맞춤):
- ${CLAUDE_SKILL_DIR}/template.md 템플릿을 읽어 그 구조 그대로 작성
  ({} 자리를 채우고 안내문은 제거)
- 템플릿을 읽을 수 없으면 폴백 — 비판점(차단/권장/사소) / 수정 내용 / 검증 /
  릴리즈 판정(+추천 버전 major/minor/patch) / 다음 단계 5개 섹션
- 릴리즈 가능이면 /tide:release vX.Y.Z 구체 버전을, 불가면 보완 태스크 또는
  /tide:milestone 후속 계획을 다음 단계에 제시
- `## 릴리즈 판정` 섹션의 판정 줄 **아래**에 계측 줄을 **필수**로 남긴다. 고정 형식(문자 그대로):
  `계측: in-review 수정 차단 {n}/권장 {n}/사소 {n} · 반증 시도 {수행|폴백} 성립 {n}건 · 재작업 라운드(rework) {n}`
  판정 표기(`**가능**`/`**불가**`)와 `추천 버전`의 형식·위치는 **바꾸지 않는다**(프리플라이트·
  /tide:status·fleet 계열의 판정 읽기 불변).
- **재작업 라운드(rework) 산정**: 대상 마일스톤의 impl 보고서 docs/reports/M{N}-impl.md 개요에
  적힌 `재작업 라운드(rework)` 값을 읽어 그대로 쓴다. 값이 없는 기존 보고서는 **0으로 본다**
  (소급 갱신 금지).
- 재작업 라운드가 **2를 초과하면** `다음 단계`에 **마일스톤 재분해(/tide:milestone) 권고**를 한 줄
  적는다 — **판정과 독립·비차단**이며 자동 중단·자동 재분해는 하지 않는다.

리뷰·수정·리뷰보고서까지 마치면 .tide/phase를 `idle`로 되돌린 뒤 최종 판정을 명확히 보고해줘.
