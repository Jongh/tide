상위 폴더 아래 여러 자식 tide 레포의 사이클 상태를 한 번에 **읽기 전용**으로 집계하고,
조정된 다음 행동 계획을 advisory로 제시해줘. 대상 부모: "$ARGUMENTS" (생략 시 현재 세션 위치)

이 커맨드는 멀티 레포 오케스트레이션의 **1층(가시성)**이다 — 계층 로드맵·발견/계획 규약의
단일 원본은 `docs/conventions.md`의 "멀티 레포 오케스트레이션" 절이다. fleet은 그 규약을 따른다.

## 자식 tide 레포 발견

대상 부모의 **직속 하위 디렉터리**(기본 = 현재 세션 위치, 인자로 경로 지정 가능) 중 다음을
**모두** 만족하는 것을 자식 tide 레포로 본다:
- git 레포일 것 (`<dir>/.git` 존재 또는 `git -C <dir> rev-parse --show-toplevel` 성공), **그리고**
- tide 산출물을 가질 것 — `docs/milestones/` 또는 `.tide/` 또는 버전 파일(`package.json`/
  `Cargo.toml`/`pyproject.toml`/`.claude-plugin/plugin.json` 등) 중 하나 이상.

**깊은 재귀는 하지 않는다 — 직속 1단계만**. 손주 이하 디렉터리는 보지 않는다.

이름이 `.`으로 시작하는 **숨김 디렉터리는 무시**한다(`.git`·`.claude` 등).

발견이 **0개**면: "자식 tide 레포 0개 — 단일 레포 세션으로 보임"을 안내하고, 현재 레포에 대해
`/tide:status`를 권한 뒤 종료한다(graceful 강등 — 단일 레포에서 안전).

## 레포별 상태 조회 (각 레포 루트 기준, 읽기 전용)

발견된 각 자식 레포에서 확인 항목을 **그 레포 루트 기준**으로 조회한다.
**`docs/conventions.md`의 "상태 확인 항목과 시작점 판단 (선언)" 절이 단일 원본**이다 —
`status-items:` 선언과 「무엇을 읽는가」 표를 그 절에서 읽고 **여기서 다시 열거하지 않는다.**
**대상 레포에 그 파일이 없으면 플러그인 설치본을 읽는다**(도달 규칙은 `docs/conventions.md`의 "멀티 레포 / 대상 레포" 절).

- **선언된 항목을 전부 조회한다.** 표에 무엇을 보일지는 이 커맨드가 정하지만 **수집을 줄이지 않는다** —
  줄이면 아래 4번의 판단 규칙이 **데이터 없이 조용히 발화하지 못한다**(M52-T01 실측: 여섯만 수집해
  debug 규칙이 돌지 못하고 이미 릴리즈된 것보다 낮은 버전의 release를 권했다).
- **고유 항목 하나를 더한다**: `.tide/deps`의 의존 형제 목록 (순서 판정 전용 — 아래
  "`.tide/deps` 읽기" 참조). 이것은 멀티 레포에만 있으므로 규약의 목록에 넣지 않는다.

어떤 레포에서도 **파일·`.tide/phase`·git을 일절 변경하지 않는다**(읽기 전용).

## `.tide/deps` 읽기 (의존성 선언, 옵트인)

각 발견 레포 루트의 `.tide/deps`를 읽어 그 레포의 **의존 형제 목록**을 만든다 — 규약 단일
원본은 `docs/conventions.md`의 "멀티 레포 오케스트레이션" 절이다.
- **선두 BOM 제거**: 파일을 읽을 때 **선두 UTF-8 BOM(`EF BB BF`)을 먼저 제거**한 뒤 줄 단위로
  파싱한다(Windows 편집기·`Set-Content -Encoding utf8`로 만든 BOM 붙은 첫 줄도 올바로 처리되게).
- **파싱**: 한 줄에 의존하는 형제 레포 디렉터리명 하나, 선택적으로 **`<op> 버전` 제약**을 붙인다 —
  `<형제 레포명>[ <op> <버전>]`(예: `svc-auth >= v0.3.0`). **빈 줄과 `#`로 시작하는 주석 줄은
  무시**하고, 줄 앞뒤·토큰 사이 **공백은 트림**한다.
- **버전 제약(옵트인)**: 연산자/버전이 없으면 **이름 의존만**(M16 동작 그대로). **지원 연산자**는
  `>=`·`>`·`=`(또는 `==`)·`<=`·`<` **전체**다 — 각각 "의존 대상의 현재 버전이 요구 버전에 대해
  그 연산자를 만족해야 함"으로 본다(예: `>=`는 이상, `<`는 미만). **알 수 없는 연산자가 오면
  무시하고 경고**한다(안전 측 — 위반으로 단정하지 않음).
- **의미**: "이 레포는 나열된 형제 레포들에 **의존**한다"(의존 대상이 순서상 먼저 처리되어야
  한다). 예 — `svc-orders/.tide/deps`에 `svc-auth` 한 줄 → orders는 auth에 의존, auth가 먼저.
- **옵트인·하위 호환**: 파일이 없거나 유효 줄이 0이면 **의존 0**(현행 동작 그대로 — 독립 노드).
- **미존재명 무시**: `.tide/deps`가 위에서 발견된 자식 집합에 **없는 이름**을 가리키면 그 줄은
  **무시하고 경고**한다(잘못된 선언이 순서를 깨지 않게 — 안전 측).

`.tide/deps`도 **읽기만** 한다 — 생성·수정하지 않는다.

## 출력

1. **레포별 표** — 레포명 | 마일스톤(M{N} 제목) | phase | 판정/추천 버전 | 버전.
   **열린 줄기가 있는 레포는 그 줄기를 함께 보인다** — 표시 여부가 이 커맨드의 재량이 아니라
   규약이 정하는 **예외**다(`docs/conventions.md`의 "상태 확인 항목과 시작점 판단 (선언)" 절의
   `open-epic` 항목). 열린 줄기가 하나도 없으면 아무 것도 덧붙이지 않는다(소음 0).
2. **교차 요약** — position과 1:1로 집계한 고정 버킷을 한 줄로 표기한다(임의 합산 금지, 해당 0건
   버킷도 0으로 명시). 버킷 목록·고정 형식의 단일 원본은
   **`docs/conventions.md`의 "advisory 계획 규칙" 절**이고 여기서 다시 열거하지 않는다.
3. **권장 처리 순서** — `.tide/deps`로 모은 의존 그래프(의존→피의존)를 **위상정렬**해 처리
   순서를 산출한다: **피의존(먼저 필요한 레포)이 의존하는 레포보다 앞**에 온다(예: orders가
   auth에 의존하면 auth 먼저). 결과를 **번호/화살표 목록**으로 제시하되 각 레포의 의존 대상을
   표기한다 — 예: `1) svc-auth  2) svc-orders(→auth)  3) svc-gateway(→auth)`.
   - **순환 의존**(직간접 A→B→…→A): **감지해 보고하고**(고리에 든 레포명을 명시) **상태 기반
     순서로 폴백**한다 — 폴백 사유를 한 줄로 적는다.
   - **미선언 레포**(deps 없음/유효 줄 0): 의존 0인 **독립 노드**로 두고 순서는 상태로 산출한다
     (다른 노드와 위상 제약 없음).
   - **계약 버전 비교**: 의존 줄에 `<op> 버전` 제약이 있으면 의존 대상 레포의 **현재 버전**(상태
     조회 4번)을 읽어 요구 버전과 비교한다. 버전은 `vX.Y.Z`(선행 `v` 선택)로 보고
     **major.minor.patch를 숫자로** 비교한다. **지원 연산자**는 `>=`·`>`·`=`(또는 `==`)·`<=`·`<`
     **전체**다 — 연산자별로 `현재 <op> 요구`가 참이면 **만족(무표기)**, 거짓이면 의존 레포 줄에
     **`⚠ contract` 경고를 표기**하되 메시지에 **연산자·요구·현재를 함께** 적는다 (정확한 문자열
     형식의 단일 원본은 `docs/conventions.md` "계약 비교 규칙") — 예:
     `svc-orders → ⚠ contract svc-auth 0.2.0 < 요구 >= 0.3.0 (upstream behind — svc-auth를 먼저 올릴 것)`,
     `svc-orders → ⚠ contract svc-auth 0.5.0 > 요구 <= 0.4.0 (svc-auth가 너무 앞섬)`.
     **알 수 없는 연산자**나 **어느 한쪽 버전이 비표준·파싱 불가**면 비교를 생략하고 **경고**한다
     (위반·차단으로 단정하지 않음 — 안전 측). **위상정렬 순서·의존 그래프는 버전 제약과 무관하게
     불변**이다 — 경고는 순서를 바꾸지 않고 줄에 덧붙는 표기일 뿐이다.
   - 위상정렬은 **제안만** 한다(아래 부수효과 분리) — 어떤 순서도, `⚠ contract` 경고도
     자동 실행·차단하지 않는다(advisory만).
   - 이 발견·순서를 **보기만** 하지 않고 그 순서대로 각 레포의 milestone→review를 **자동 실행**
     하려면 `/tide:fleet-cycle`(release 제외)을 쓴다 — fleet은 읽기 전용 개요, fleet-cycle은 그
     순서대로 행위.
4. **advisory 다음 행동 계획** — 레포별로 `/tide:status`의 "다음 커맨드 판단 규칙"을 적용해
   각 레포의 position을 정확히 하나로 분류하고 `레포명 → 다음: /tide:...`를 한 줄씩 제시한다.
   position 목록과 인자까지 포함한 커맨드 매핑의 단일 원본은
   **`docs/conventions.md`의 "advisory 계획 규칙" 절**이다 — 그 절을 읽고 **여기서 다시 열거하지 않는다.**
   - **debug position을 먼저 본다** — 열린 debug 세션과 미릴리즈 debug 보고서가 사이클 position보다
     앞선다. 이 둘을 빼고 분류하면 **status와 다른 커맨드를 내게 된다**(M52-T01 실측: 같은 상태에서
     status는 옳게 판단하는데 fleet은 이미 릴리즈된 것보다 낮은 버전의 release를 권했다).
   - **의존성 인식** — `.tide/deps` 선언 시 위상정렬, 순환·미선언은 폴백(위 "권장 처리 순서"
     참조). fleet은 선언된 의존만 알며, 미선언 레포의 순서는 **상태로** 산출한다. 위상정렬은
     권장 순서일 뿐 실제 처리 순서·시점은 사용자가 판단하도록 advisory로 둔다 — 단정하지 않는다.

## 부수효과 분리 (불변)

fleet은 **제안만** 한다 — 어떤 레포에도 사이클을 자동 실행하거나 cross-repo git을 하지 않는다.
release는 끝까지 레포별 수동(`/tide:release`)이며, tide-guard와 레포별 격리가 그대로 적용된다.

다음은 절대 수행하지 마: 파일 생성·수정 / 어느 레포의 `.tide/phase` 변경 / git 작업
(읽기 전용 커맨드 — `/tide:status`·`/tide:retro`와 동일 원칙)
