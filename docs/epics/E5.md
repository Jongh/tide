# E5 — 사이클 계획을 레포의 이슈 트래커에 두고, 닿지 않을 때만 로컬 문서로 둔다

- status: open
- 열린 날: 2026-11-23
- 기반 버전: v2.59.0

## 이 줄기가 노리는 것

**에픽 · 마일스톤 · 태스크가 그 레포의 이슈 트래커(마일스톤 · 이슈)에 산다.** 트래커에 닿지 않는 레포에서만 지금처럼 로컬 문서(`docs/epics/` · `docs/milestones/`)에 살고, 나중에 트래커에 닿으면 로컬 문서를 그 트래커의 항목으로 옮긴다.

지금 tide의 계획은 레포 안의 마크다운에만 있다. 사람이 그 계획을 보려면 레포를 열어 문서를 읽어야 한다. 팀이 이미 쓰는 자리(GitHub · GitLab의 마일스톤 · 이슈 · 보드)에는 아무것도 나타나지 않는다. 그래서 같은 계획을 손으로 두 번 적거나, 트래커가 실제 진행과 따로 낡는다. 이 줄기는 계획의 **집**을 트래커로 옮긴다. 로컬 문서는 **트래커가 없을 때의 대체 자리**이자 **옮기기 전의 대기 자리**가 된다.

**축은 넷이다.**

- **축 ⑴ — 대응(무엇이 무엇이 되는가).** tide의 개념을 트래커의 개념에 플랫폼 중립으로 대응시킨다. 플랫폼마다 없는 개념(GitHub에는 에픽이 없고, GitLab 14.9 Free에도 없다)은 공통으로 있는 것(이슈 · 라벨 · 마일스톤)으로 낮춰 적는다.
- **축 ⑵ — 어댑터(어떻게 닿는가).** 스킬은 플랫폼 이름을 모른다. 대신 작은 **트래커 계약**(아래 「계약」)을 부르고, GitHub · GitLab은 그 계약의 첫 구현 둘이다. 다른 플랫폼(Gitea · Jira · Linear 등)은 같은 계약을 하나 더 구현해 붙인다.
- **축 ⑶ — 판별과 대체(언제 로컬로 가는가).** 레포마다 「트래커에 닿는가」를 정해진 순서로 판정한다. 닿지 않으면 로컬 문서 모드로 가고, **그 사실을 한 줄로 알린다** — 조용히 로컬로 새지 않는다.
- **축 ⑷ — 변환(나중에 닿으면).** 로컬 문서로 관리하던 레포가 트래커에 닿게 되면, 로컬 에픽 · 마일스톤 · 태스크를 트래커 항목으로 만든다. 같은 변환을 두 번 돌려도 항목이 두 벌 생기지 않는다(멱등). 어느 로컬 문서가 어느 트래커 항목이 되었는지는 대응 기록으로 남는다.

## 왜 지금인가 (실측)

2026-11-23 사용자 요청이다. 사용 플랫폼은 **GitHub**과 **자체 호스팅 GitLab 14.9** 둘이고, 그 밖의 관리 플랫폼으로도 넓힐 수 있는 방향을 함께 요구했다.

**지금 계획이 로컬 문서에 얼마나 묶여 있는가** — v2.59.0 작업 트리 실측이다.

| 자리 | 값 |
|---|---|
| `docs/milestones`를 말하는 스킬 | 12종 중 10종(`cycle` · `fleet` · `fleet-cycle` · `fleet-verify` · `impl` · `kickoff` · `milestone` · `release` · `retro` · `review`) |
| `docs/epics`를 말하는 스킬 | 1종(`milestone`) — 열린 줄기 표시는 `status` · `fleet`이 규약을 거쳐 읽는다 |
| 트래커 CLI를 부르는 스킬 | 1종(`release` — `gh release` · `gh pr`, 게시는 옵트인) |
| 하니스 `tests/discover`에서 `milestones`가 나오는 줄 | `run.sh` 29 · `run.ps1` 33 |
| 이 저장소의 마일스톤 문서 | 96 |

**뜻** — 계획 문서의 경로가 스킬 대부분과 하니스에 박혀 있다. 그래서 이 줄기는 「트래커 호출을 덧붙이는 일」이 아니다. **계획을 읽고 쓰는 자리를 한 곳(계약)으로 모으는 일이 먼저다.** 모으지 않고 스킬마다 `gh` · GitLab API를 부르면, 플랫폼이 하나 늘 때마다 열 곳이 같이 낡는다. 규약과 스킬 사이에서 이 저장소가 여러 번 겪은 복제 문제가 그대로 재현된다(E2의 부류).

**GitLab 14.9가 정하는 하한** — 14.9는 2022년 판이고, 자체 호스팅이라 올라갈 시점을 이 줄기가 정하지 못한다.

- Free 등급에는 에픽(그룹 수준) · 범위 라벨(`key::value`의 상호 배타) · 이터레이션이 **없다**(유료 등급 기능이다).
- 있는 것은 프로젝트 · 그룹 마일스톤, 이슈, 라벨, 이슈 본문의 작업 목록, 관련 이슈 연결이다.
- 그래서 대응은 이 공통분모에 맞춰야 GitHub · GitLab 양쪽에서 같은 뜻을 낸다. 플랫폼별 고급 기능(GitHub sub-issue · Projects, GitLab 에픽)은 **있으면 더 쓰는 선택 층**으로 둔다.
- 「Free 14.9에 없다」는 판정은 계획 시점 지식이다. **첫 사이클이 실제 인스턴스에서 확인한다**(아래 사이클 배분 1).

## 방향 (이 줄기가 내린 결정)

### 개념 대응 — 공통분모 우선

| tide 개념 | 공통 대응(필수 층) | 있으면 쓰는 선택 층 |
|---|---|---|
| 에픽 `E{N}` | **추적 이슈** 하나(제목 `E{N} — …`, 라벨 `tide:epic`) — 본문이 이 문서의 필수 섹션을 든다 | GitHub sub-issue · Projects, GitLab 에픽(유료 등급) |
| 마일스톤 `M{N}` | 트래커 **마일스톤**(제목 `M{N} — …`) — 설명에 목표 · 완료 기준 | GitLab 그룹 마일스톤(멀티 레포) |
| 태스크 `M{N}-T{k}` | 그 마일스톤에 든 **이슈**(라벨 `tide:task`) — 본문에 변경 파일 · deps | 이슈 연결(deps), sub-issue |
| 마일스톤 → 에픽 참조 | 마일스톤 설명의 `epic: E{N}` 한 줄 + 추적 이슈 본문 작업 목록에 그 마일스톤 | 플랫폼의 부모-자식 연결 |
| 완료 · 닫힘 | 이슈 닫힘 · 마일스톤 닫힘(릴리즈 단계) | — |
| impl · review 보고서 | **레포에 남긴다**(아래) — 트래커에는 링크와 판정 한 줄만 | — |

- **보고서는 옮기지 않는다.** impl · review 보고서는 시점 기록물이고, 릴리즈 판정의 근거이며, 하니스가 읽는다(완료 기준 대조 · 되돌림 표). 트래커 댓글은 편집 이력이 약하고 오프라인에서 읽을 수 없다. 그래서 보고서는 지금 자리에 두고 트래커 항목이 그것을 **가리킨다**.
- **라벨 이름은 접두 `tide:` 하나로 모은다.** 범위 라벨이 없는 Free 등급에서도 같은 이름이 같은 뜻을 낸다.

### 계약 — 스킬이 부르는 것은 이것뿐이다

스킬과 하니스는 플랫폼이 아니라 아래 연산만 안다. 이름 목록은 첫 사이클이 규약 선언으로 세운다(지금은 방향이라 선언 줄로 적지 않는다).

- **판별** — 이 레포의 트래커가 무엇이고 닿는가(아래 판별 순서)
- **읽기** — 열린 에픽 · 최대 번호 마일스톤 · 그 태스크와 상태
- **쓰기** — 에픽 · 마일스톤 · 태스크 만들기, 상태 바꾸기, 닫기, 링크 · 판정 한 줄 달기
- **대응 기록** — 로컬 키(`E5` · `M97` · `M97-T01`)와 트래커 항목 ID의 짝을 읽고 쓰기

어댑터의 첫 구현은 둘이다.

- **GitHub** — `gh` CLI(이미 release가 인증 · 호스트 검사를 쓴다 — `docs/conventions-release.md`의 "검증 게이트" 절)
- **GitLab** — REST API v4를 개인 접근 토큰으로 부른다. `glab` CLI는 버전과 자체 호스팅 지원 폭이 고르지 않아 **필수로 두지 않는다**. 자체 서명 인증서 · 사내 CA는 사용자 환경 설정으로 넘긴다.

### 판별 순서와 로컬 대체

1. **명시 설정** — 레포의 `.tide/` 아래 트래커 설정(플랫폼 · 호스트 · 프로젝트 · `local` 강제 포함)이 있으면 그것을 따른다.
2. **원격에서 추론** — `origin` 호스트가 GitHub이면 GitHub, GitLab API에 응답하는 호스트면 GitLab이다.
3. **닿는가** — CLI · 토큰 인증과 그 프로젝트 읽기 권한을 확인한다.
4. **하나라도 안 되면 로컬 문서 모드** — 지금의 `docs/epics/` · `docs/milestones/` 동작 그대로다. 출력에 **한 줄로 알린다**. 문구에는 「트래커 미연결 — 로컬 문서로 관리합니다」와 그 사유(설정 없음 · 미인증 · 응답 없음)를 담는다.

- **트래커를 안 쓰는 레포의 동작은 지금과 같다** — tide는 남의 저장소에 얹는 물건이라, 에픽 층이 그랬듯 이것이 계약이다(소음은 위 알림 한 줄뿐).
- **연결된 레포에서 일시적으로 닿지 않을 때** — 쓰기는 로컬 문서에 **변환 대기 표지**를 달아 남긴다. 다음 연결 때 축 ⑷의 변환이 그것을 올린다. 조용히 버리지도, 트래커와 로컬에 두 벌로 갈리게 두지도 않는다.

### 변환 — 로컬에서 트래커로

- **한 방향이다** — 로컬 → 트래커. 연결된 뒤에는 트래커가 원본이고 로컬 문서는 만들지 않는다. 양방향 동기화는 충돌 해소라는 다른 문제를 들여오므로 이 줄기의 범위가 아니다(아래 「못 무는 것」).
- **멱등이다** — 대응 기록에 짝이 있는 키는 다시 만들지 않는다. 중간에 끊긴 변환을 다시 돌리면 남은 것만 만든다.
- **무엇을 옮기는가** — 열린 에픽, 릴리즈되지 않은 마일스톤과 그 태스크, 변환 대기 표지가 붙은 문서. **릴리즈된 마일스톤과 닫힌 에픽은 기본으로 옮기지 않는다**(이 저장소만 해도 96개 — 트래커를 과거로 덮는다). 사용자가 원하면 닫힌 상태로 옮기는 선택지를 둔다.
- **옮긴 로컬 문서는 지우지 않는다** — 시점 기록물이고 보고서가 가리킨다. 머리에 트래커 항목을 가리키는 한 줄을 더해 「원본은 트래커」임을 밝힌다.
- **쓰기 전에 무엇을 만들지 보여주고 확인받는다** — 트래커 쓰기는 push와 같은 바깥 부수효과다. 계획(만들 항목 목록)을 먼저 보이고, 승인 뒤에만 쓴다.

### 부수효과의 자리

지금 git 쓰기는 `/tide:release` 단계에서만 통과한다(`.tide/phase` + 훅). 트래커 쓰기는 git이 아니라 그 훅이 보지 못한다. 그래서 **어느 단계가 트래커에 무엇을 쓸 수 있는가**를 첫 사이클이 규약으로 정한다. 출발점은 이렇다.

- `milestone`은 만들기
- `impl`은 태스크 상태
- `review`는 판정 한 줄
- `release`는 닫기
- `status` · `fleet`은 읽기만

## 완료 신호

1. **GitHub 레포와 GitLab 14.9 프로젝트 각각에서**, `/tide:milestone` → `/tide:impl` → `/tide:review` → `/tide:release` 한 사이클의 에픽 · 마일스톤 · 태스크가 트래커 항목으로 존재하고, 그 사이클 동안 `docs/milestones/` · `docs/epics/`에 새 파일이 생기지 않는다.
2. **스킬 문면에 플랫폼 이름이 박힌 트래커 호출이 없다** — 트래커를 읽고 쓰는 자리는 계약 하나를 거친다. 새 플랫폼을 더하는 편집이 어댑터 하나와 규약 선언 줄에서 끝난다.
3. **트래커에 닿지 않는 레포에서 tide의 동작과 산출물이 이 줄기 전과 같고**, 출력에 로컬 문서 모드임을 밝히는 한 줄이 있다. 하니스가 그 한 줄과 「동작이 같다」를 함께 묻는다.
4. **로컬 문서로 시작한 레포를 트래커에 연결하면**, 변환 한 번으로 열린 에픽 · 미릴리즈 마일스톤 · 태스크가 트래커에 생긴다. 두 번째 실행은 아무것도 만들지 않는다.
5. **`/tide:status`가 연결된 레포에서 트래커를 읽어 같은 다음 커맨드를 낸다** — 시작점 판단 규칙(`docs/conventions.md`의 "상태 확인 항목과 시작점 판단 (선언)" 절)이 로컬 문서 모드와 같은 답을 낸다.
6. **하니스가 실제 네트워크 없이 계약을 문다** — 가짜 어댑터(녹화된 응답)로 판별 · 대체 · 변환의 멱등을 네 실행 환경에서 같은 수로 판정한다.

## 못 무는 것

- **트래커 항목의 내용이 옳은가** — 이슈 본문 · 마일스톤 설명의 품질은 로컬 문서와 같이 리뷰의 영역이다.
- **양방향 동기화** — 사람이 트래커에서 고친 제목 · 본문을 로컬로 되돌려 쓰지 않는다. 연결 뒤에는 트래커가 원본이라 되돌릴 자리가 없다. 다만 「사람이 트래커에서 마일스톤을 닫았는데 tide는 열린 것으로 읽는다」 같은 상태 어긋남은 읽기 쪽이 트래커를 그대로 따르게 해 줄인다.
- **실제 인스턴스의 하니스 집행** — CI는 사내 GitLab에 닿지 않는다. 실물 대조는 사이클마다의 수동 실측(E3의 외부 실측과 같은 꼴)이고, 하니스가 무는 것은 가짜 어댑터까지다.
- **플랫폼 권한 · 토큰 관리** — 토큰 발급 · 저장 · 회전은 사용자 환경의 일이다. tide는 토큰을 파일에 쓰지 않는다.
- **멀티 레포 묶음(GitLab 그룹 마일스톤 · GitHub Projects)** — `/tide:fleet` 계열이 레포를 가로질러 한 마일스톤을 쓰는 일은 단일 레포가 선 뒤의 다음 축이다.
- **회고 행 · 이월 원장의 이전** — `docs/reports/retro.md`의 후속 표를 이슈로 올리는 일은 같은 계약 위에서 할 수 있지만, 처분 규율(하니스 Part O)이 커서 이 줄기의 첫 범위가 아니다. 그때 다시 판단한다.

## 사이클 배분 (계획 — 번호가 아니라 순서가 요지다)

1. **실측과 계약** — 두 플랫폼의 실제 인스턴스에서 대응표 한 줄씩을 손으로 재현한다. GitLab 14.9의 등급별 기능 유무도 그 인스턴스에서 확인한다. 그 결과로 계약의 연산 이름 · 판별 순서 · 단계별 쓰기 범위를 규약 선언으로 세운다. 코드는 아직 바꾸지 않거나, 판별만 넣는다.
2. **읽기 경로 모으기** — 계획 문서를 읽는 자리(스킬 10종 · 하니스)를 계약의 읽기 하나로 모은다. 로컬 문서 어댑터가 첫 구현이다. 이 사이클의 동작은 지금과 같아야 한다(완료 신호 3의 바탕).
3. **GitHub 어댑터** — 읽기 · 쓰기 · 대응 기록. 이 저장소(`Jongh/tide`) 자신이 첫 실측 대상이다.
4. **GitLab 어댑터** — REST v4 · 토큰 · 자체 호스팅 · 14.9 하한.
5. **변환** — 로컬 → 트래커 멱등 변환과 변환 대기 표지. 이 저장소의 열린 에픽 E1~E5를 실제로 옮겨 본다.

**2가 3보다 먼저인 근거** — 읽는 자리를 모으지 않고 어댑터를 먼저 붙이면, 스킬 10종에 플랫폼 분기가 하나씩 들어간다. 그것을 걷어 내는 비용이 2를 먼저 하는 비용보다 크다.

## 사용자 판단으로 남긴 것

- **이 저장소(tide) 자신도 트래커로 옮기는가.** 하니스의 많은 통제가 이 저장소의 `docs/milestones/` 이력을 입력으로 쓴다. 옮기면 그 통제의 입력이 바뀐다. 사이클 배분 5에서 E1~E5를 시험 삼아 옮기되, 하니스 입력을 바꾸는 결정은 그때 따로 받는다.
