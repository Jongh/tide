# M5 완료보고서 (impl)

## 개요

M5 "`/tide:cycle` 오케스트레이션"의 5개 태스크(M5-T01~T05)를 구현했다. `milestone → impl
→ review`를 한 번에 이어 실행하고 `release`는 직전에 멈춰 사용자에게 넘기는 신규 스킬
`skills/cycle/SKILL.md`를 신설했고, 마일스톤 태스크의 `(deps:)` 표기를 독립=병렬·의존=순차
규칙으로 스케줄링하는 규칙과 전제조건·중단 처리를 스킬 본문에 명시했다. `docs/conventions.md`·
`README.md`·`docs/project-context.md`에 cycle 단계를 반영했다.

## 태스크별 수행 내용

- **M5-T01** — `skills/cycle/SKILL.md` 신설. frontmatter는 기존 스킬과 동일 형식
  (`description`·`argument-hint`). 본문은 milestone→impl→review를 순서대로 진행하며 각 단계
  진입 시 `.tide/phase`에 단계명을 기록하고 사이클 종료 시 `idle`로 되돌리도록 기술.
  **플러그인 등록 확인(불확실성 해소)**: `.claude-plugin/plugin.json`·`marketplace.json`
  둘 다 `skills` 배열이 없는데 기존 6종이 정상 노출된다 → 플러그인이 `skills/*/SKILL.md`를
  **자동 발견**함을 확인. 따라서 신규 스킬 등록에 매니페스트 수정이 **불필요**하여
  plugin.json/marketplace.json은 건드리지 않았다(M5 파일 변경 요약의 조건부 "수정" 항목 미발생).
- **M5-T02** — deps 기반 병렬/순차 규칙을 cycle 스킬의 "deps 기반 병렬/순차" 절에 명시.
  의존 없는 태스크 = 병렬 묶음, 의존 있는 태스크 = 선행 완료 후 착수(위상 정렬), 같은
  레벨끼리 재병렬. 이상 표기 폴백 — **순환 의존 / 미존재 의존 ID / 파싱 불가**를 감지하면
  보고하고 보수적으로 파일 순서대로 순차 진행. (실제 병렬 실행 수단은 구현 판단에 위임하고,
  *언제 착수 가능한가*의 해석을 규칙으로 확정.)
- **M5-T03** — release를 자동 체이닝에서 제외. cycle 본문의 "종료" 절에서 review "가능"
  판정 시 사이클을 끝내고 `/tide:release vX.Y.Z`를 안내하도록 기술. "중단 처리" 절에서
  각 단계의 기존 전제조건(impl=마일스톤 문서, review=impl 보고서)을 사이클 안에서도 검사하고,
  미충족·실패 시 사이클 전체를 중단하며 중단 지점·사유와 `.tide/phase`=`idle` 복원을 명시.
  체이닝 구간(milestone~review)에 git 작업이 없음을 본문 주석으로 못박아 tide-guard 비충돌 확인.
- **M5-T04** — `docs/conventions.md`: 사이클 다이어그램에 cycle 구간 추가, "수동 단계별 호출
  vs `/tide:cycle` 자동 체이닝" 단락 신설, 단계별 금지 행위 표에 `cycle` 행 추가.
  `README.md`: 사이클 다이어그램·설명에 `/tide:cycle` 추가, 커맨드 표에 행 추가, 스킬 수
  6종→7종 갱신(설치·구조·자동완성 3곳). `docs/project-context.md` 디렉터리 표의 스킬
  목록도 7종(+cycle)으로 갱신해 구조 문서 일관성 유지.
- **M5-T05** — 자동 테스트 러너가 없는 프로젝트(검증 수단 = 재설치+새 세션 드라이런)이므로
  정적/논리 검증 수행: ① 신규 frontmatter가 기존 스킬과 동형임을 대조, ② 매니페스트에
  `skills` 배열 부재로 자동 발견 확인(T01), ③ deps 스케줄링 규칙을 deps 형태가 다른 두
  마일스톤에 트레이스 — M5/M4(단일 루트 팬: {T01}→{T02,T03,T04}→{T05}), M1(다중 루트:
  {T01,T04,T05,T06,T07}→{T02,T03}→{T08})에서 "독립=병렬(번호순 아님)·의존=순차"가 의도대로
  해석됨을 확인. 순환·미존재 ID 없음. 실제 노출/엔드투엔드 드라이런은 재설치 필요(아래 메모).

## 테스트 결과

자동화된 테스트 러너가 없는 플러그인 프로젝트다(project-context: 검증 = 재설치 후 새 세션
드라이런/도그푸딩). 본 단계에서 가능한 정적 검증을 수행했고 모두 통과:

- **frontmatter 동형성** — `skills/cycle/SKILL.md`가 기존 스킬과 동일한 `description` +
  `argument-hint` 형식. 통과.
- **자동 발견 전제** — plugin.json/marketplace.json grep으로 `skills` 키 부재 확인,
  기존 6종이 등록 없이 노출되는 사실과 합치. 통과.
- **deps 규칙 트레이스** — 형태가 다른 두 마일스톤(M5/M4 단일 루트, M1 다중 루트)에서
  위상 스케줄링이 의도대로 해석됨. 순환/미존재 ID 폴백 조건도 규칙에 명시됨. 통과.
- **잔여 "6종" 점검** — 전 저장소 grep 결과 남은 "6종"은 전부 과거 기록(CHANGELOG
  v0.3.0/v0.4.0, M1~M4 문서)으로 당시 상태를 정확히 기술 → 의도적으로 보존. 현재 상태 문서만
  갱신됨. 통과.

엔드투엔드(실제 `/tide:cycle` 노출·호출, milestone→review 자동 진행, release 직전 정지)는
플러그인 재설치 + 새 세션이 필요하여 이 단계에서 실행 불가 — review/다음 단계에서 수행.

## 미해결·후속 메모

1. **실노출 드라이런 미수행** — `/tide:cycle`이 탭 자동완성/호출에 실제로 뜨는지, 호출 시
   milestone→impl→review가 순서대로 진행되고 review "가능" 후 release 직전에 멈춰 안내하는지는
   재설치+새 세션에서 확인해야 한다(M5 완료 기준 1·2). review 단계에서 도그푸딩 권장.
2. **병렬 실행 수단은 규칙만 확정** — cycle은 "어떤 태스크를 언제 착수해도 되는가"를 규칙으로
   정했고 실제 동시 실행 메커니즘은 impl 구현 판단에 위임한다. 현재 impl 스킬은 순차 진행이
   기본이며, deps 위상 순서를 지키면 규칙 부합. 진짜 병렬 실행이 필요해지면 별도 마일스톤 후보.
3. **CHANGELOG 항목 미작성** — 부수효과 분리 원칙상 release 단계에서 CHANGELOG/README
   릴리즈 노트를 추가한다. 목표 버전은 M5 메타의 v0.6.0(minor — 신규 오케스트레이션 커맨드).
