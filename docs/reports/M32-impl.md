# M32 완료보고서 (impl)

## 개요

M32(루프 신호 복원)의 태스크 7개를 전부 구현했다. `docs/conventions.md`에 `## 리뷰 검증 규율` 절을
신설해 **반증 시도(refutation)·in-review 수정 후 재검증·판정 계측·재작업 라운드(rework)와 수렴 조건**
네 규약의 단일 원본을 세우고, 그것을 리뷰 스킬·리뷰 템플릿·impl 스킬/템플릿·cycle 스킬에 배선한 뒤
`tests/discover`에 **Part E** 선언 정합 가드(양 셸)를 더했다. 카탈로그(`docs/commands.md`)와
프로젝트 컨텍스트에도 반영했다. 레벨 1(T01) → 레벨 2(T02·T03·T04·T05 **4개 동시 디스패치**) →
레벨 3(T06·T07 동시)의 위상 순서로 진행했고, 변경 파일이 전 레벨에서 비중첩이라 순차 폴백은 없었다.

재작업 라운드(rework): 0

## 태스크별 수행 내용

- **M32-T01** — `docs/conventions.md`의 "보고서" 절과 "debug 세션" 절 사이에 `## 리뷰 검증 규율`
  절(4개 `###` 소절 + 불변 소절)을 신설했다. 근거로 "31/31 가능·통산 차단 1건"과 판정자=실행자
  구조를 명시해, 규약이 왜 필요한지가 문서 안에서 자립하게 했다. 네 규약 모두 **발동 조건·폴백·
  비차단 여부**를 갖췄고, ASCII 병기 토큰(`refutation`·`in-review`·`rework`)을 본문에 심어 하니스가
  코드포인트 조립 없이 앵커할 수 있게 했다(Part D 선례). 레벨에 태스크가 1개뿐이라 메인이 직접 구현
  (impl 스킬의 폴백 조건대로).
- **M32-T02** — `skills/review/SKILL.md`(35→74줄, 순수 추가 38줄·삭제 0)에 ① 반증 시도 절(디스패치
  시 **판정 후보와 근거만** 전달, 서브에이전트가 원자료를 직접 읽음, 대상 레포 루트·부수효과 분리
  상속, Agent 불가 시 메인 수행 + **폴백 사실 보고서 기록**, 성립 0건도 유효한 결과) ② in-review
  재검증(수정 ≥1건 → 검증 재실행 후 판정, 불가 시 미검증 잔여 리스크 명시) ③ 계측 줄 필수 + 재작업
  라운드 산정법 ④ 라운드 > 2 시 재분해 권고(판정과 독립·비차단)를 배선했다. 규약 본문은 복제하지
  않고 conventions 절을 인용했다.
- **M32-T03** — `skills/review/template.md`(36→48줄, +12/-0)에 `## 검증`의 재검증 결과 자리,
  `## 릴리즈 판정` 판정 줄 **바로 아래**의 계측 줄 자리, 판정 근거의 반증 시도 한 줄 자리를 더했다.
  **섹션 추가·삭제·개명 0**(기존 5섹션 + `###` 3소절 그대로)이고 판정 표기·추천 버전 줄은 무변경이라
  프리플라이트·status·fleet의 판정 읽기가 그대로 동작한다.
- **M32-T04** — `skills/impl/SKILL.md`(+9줄)에 재작업 라운드 산정·기록 지시를, `skills/impl/template.md`
  (+5줄)에 `## 개요` 내부의 `재작업 라운드(rework): {n}` 자리를 더했다. 재실행 시 **직전 리뷰 판정이
  `불가`였을 때만 +1**하고 그 외 재실행은 기존 값을 승계하며, 값 없는 기존 보고서(M1~M31)는 0으로
  해석한다(소급 갱신 금지 — 정오표 규약과 정합). **병렬 디스패치 절(27~76행)은 무변경**이다.
- **M32-T05** — `skills/cycle/SKILL.md`(91→101줄)의 review 단계 설명에 "반증 시도·재검증·계측이
  자동 상속되며 체이닝이라고 생략되지 않는다"를 명시하고, `## 종료`의 `불가` 분기에 라운드 > 2 시
  재분해 권고를 이었다. cycle이 impl↔review를 스스로 왕복하지 않는다는 현행 동작(중단 처리 규칙)은
  불변임을 함께 못박았다.
- **M32-T06** — `tests/discover/run.{sh,ps1}`에 Part D 뒤·요약 출력 앞으로 **Part E**를 순수 가산했다:
  E1 `refutation` ∈ {conventions, review SKILL}, E2 `in-review` ∈ {conventions, review SKILL, review
  템플릿}, E3 `rework` ∈ {conventions, review 템플릿, impl 템플릿}, 교차 통제(`refutation`이 impl
  템플릿에 **부재**), 음성 통제(`refutation-bogus`가 conventions에 **부재**). 기존 헬퍼
  (`has_token`/`in_all_three`)를 재사용하고 2파일 결합용 `in_both`/`InBoth`만 새로 뒀다. 토큰이 전부
  ASCII라 ps1에 `Uni` 코드포인트 조립이 필요 없었고, **ps1의 ASCII-only(byte>127 = 0)·CRLF 규율을
  유지**했다(바이너리 검사로 확인).
- **M32-T07** — `docs/commands.md`의 `/tide:review` 표 행·상세 절에 반증 시도·재검증·계측을 반영하고
  (커맨드 **수 12종·이름 목록·본문 마커는 무변경** — Part B 정합 유지, 사이트 셸 미변경),
  `docs/project-context.md`의 "핵심 도메인 개념"에 **리뷰 검증 규율(M32)** 항목을, "진입점·빌드/테스트"의
  `tests/discover` 서술에 Part E 구절을 더했다.

### 메인이 직접 처리한 두 건 (병합 시 발견)

- **계측 줄 형식 이형 통일**: T02·T03이 각각 `재작업 라운드 {n}` / `재작업 라운드(rework) {n}`을 써
  갈렸다(마일스톤 문서 안에도 두 이형이 있었다 — T01 ③과 완료 기준 2). **`(rework)` 병기 쪽으로
  통일**했다 — 계측 줄 자체에 ASCII 앵커가 있는 편이 드리프트 가드에 견고하기 때문이다. conventions·
  review SKILL·review 템플릿 세 곳이 **바이트 동일**임을 grep로 확인했다.
- **stale 카운트 정정**: `docs/project-context.md`가 `tests/discover`를 "양 셸 29/29"로 적고 있었는데,
  이는 M30 시점 값이고 **M31의 Part D 가산(+7)이 반영되지 않은 채 남은 드리프트**였다. 실측 기준선은
  36이며 Part E(+5)로 **41/41**이 됐다(마일스톤이 예상한 "29→34"가 아니다 — 그래서 T06 상세에 "실제
  수는 구현 시 확정"이라는 유보를 걸어 두었다). 숫자를 41/41로 고치고, 함께 누락돼 있던 **Part D
  구절**도 서술에 더했다.

## 미해결·후속 메모

1. **런타임 발화는 미실증(설계상 수용)** — Part E는 토큰의 **선언 존재**만 고정한다. 반증 시도가 실제로
   서브에이전트로 디스패치되는지, 계측 값이 정확한지, 재작업 라운드 산정이 옳은지는 프롬프트 규율이라
   하니스가 집행하지 못한다(Part C·D와 동일한 분담). **첫 라이브 실증은 이번 사이클의 `/tide:review`
   자신**이다 — 설치본이 v2.9.0이라 이번 리뷰의 스킬 본문에는 새 규약이 없지만, 리뷰가 레포의 새 규약을 **자발적으로 선적용**하면 이번 사이클에 실증할 수 있다(실제로 그렇게 됐다 — 리뷰보고서 참조). 설치본 기준으로 규약이 라이브가
   되는 것은 **v2.10.0 설치 후 다음 사이클**이다(M31이 겪은 자기수정 1릴리즈 지연과 같은 구조).
   리뷰는 이 점을 잔여 리스크로 다뤄야 한다.
2. **재작업 라운드 증가 경로는 여전히 미실행** — `불가` 판정 자체가 31사이클간 없었으므로 라운드 +1
   경로와 수렴 권고(라운드 > 2)는 선언 정합만 확보됐다. 반증 시도가 실제로 `불가`를 만들어내기 시작해야
   검증되는 경로이며, 그 전까지는 죽은 분기로 남는다.
3. **`/tide:cycle`의 새 토큰은 가드 밖** — Part E의 앵커 대상은 conventions·review SKILL·review 템플릿·
   impl 템플릿 4개뿐이라 `skills/cycle/SKILL.md`의 `refutation`·`rework` 서술은 집행되지 않는다
   (마일스톤 설계대로). cycle 쪽 드리프트는 리뷰·도그푸딩 영역이다.
4. **M31 최우선 후속(커버리지 체크 첫 라이브 실증)** — 이번 사이클의 `/tide:release` 프리플라이트에서
   자연 발생한다(설치본 v2.9.0부터 step 5 라이브). 리뷰의 `다음 단계`에 명시해 회수할 것.
5. **stale 카운트 재발 방지(저위험 후속)** — `project-context.md`의 하니스 PASS 수는 사람이 손으로
   갱신하는 값이라 이번처럼 조용히 낡는다(M31 Part D 가산이 한 사이클 동안 미반영). 카운트 서술을
   문서에서 빼거나 하니스가 출력한 수를 참조하게 하는 방식이 후보다 — 이번 범위 밖.
