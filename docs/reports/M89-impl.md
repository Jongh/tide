# M89 완료보고서 (impl)

## 개요

M89 태스크 일곱(T01~T07)을 구현했습니다. 규약 "완료 기준 대조 (impl)" 절의 「기계가 무는 것」 산문을 판정 이름 선언 `cc-asks:`와 이름별 정의 항목 열일곱으로 바꿨습니다. 이름마다 그 판정을 무는 Part P 케이스는 `cc-ask-cases:`가 들고, 시작은 `cc-ask-from:`, 다른 절 판정인 계측 줄 케이스(`P20`~`P23`)는 제외 선언 `cc-ask-skip:`가 듭니다(`rf-114`).
M88이 세운 파생 기대값을 개수 케이스 줄이 실제로 쓰는지(C5), 파생원을 줄 머리로 좁힌 뒤 같은 수를 다시 적은 자리가 같은지(C6) 묻습니다(`rf-115`). 회고 표에서 직전 섹션의 열린 행이 최상단 표에서 사라지면 `O125`가 붉고, M85 회고 판정의 빈 통제 셋은 `O121`~`O123`이 채웁니다(`rf-105`).
이 사이클은 사용자 지시로 한 번 중단됐다가(2026-11-09) 이어서 마쳤습니다. 중단 전에 구현 · README · 규약과 되돌림 일곱 행을 끝냈고, 이어받은 세션은 트리가 중단 시점 안전 사본과 바이트 단위로 같음을 확인한 뒤 남은 되돌림 행과 보고서를 했습니다. 판정 `불가`를 받은 재실행이 아니므로 라운드는 올리지 않았습니다.

재작업 라운드(rework): 0

## 미해결·후속 메모

1. **다른 축 처리 꼴의 이탈.** 마일스톤 T01의 기본 ⑴(끝 케이스 선언)이 아니라 제외 선언 `cc-ask-skip:`을 썼습니다. 새 케이스가 `P24`부터 붙어 끝 경계를 `P23`에 두면 이 축 자신의 케이스가 범위 밖으로 밀리기 때문입니다. 리뷰가 꼴을 판단해 주시면 좋겠습니다. 제외 목록은 다른 절의 판정이 Part P에 늘 때마다 손으로 늘어야 하고, 늘지 않으면 `P37`이 붉어 드러납니다.
2. **`rt_since_num`의 선언 줄 중복은 고치지 않았습니다.** 마일스톤 T06의 「선언 줄을 둘로 만든 사본」 통제는 손 케이스 `O88`이 선언 줄 수를 이미 물어서 새 케이스로 두지 않았습니다(README Part O에 적음). `rt_since_num`은 두 줄이어도 비지 않는 값을 내므로 합성 사본 통제를 두면 값 판정은 0입니다.
3. **sh 여섯 행의 총계 미기록**(되돌림 표 아래 문단). 붉은 케이스는 기록돼 있습니다.
4. **C5가 찾는 꼴의 경계.** 실측 칸이 개수 헬퍼 호출 하나인 한 줄만 찾습니다. 호출을 감싸거나 여러 줄로 나눈 케이스는 찾지 못하고, 찾은 수가 두 러너에서 같다는 것만 단언합니다(README Part C 「묻지 않는 것」 ⑴).
5. **`rf-114`의 나머지.** 「상호참조 무결성」 절(Part G)이 다음 후보입니다. 무는 것이 G1 · G4 · G5 · G8 등에 흩어져 있어 판정을 떼어 내는 조사가 먼저입니다. `rf-81`(문서의 수 낱말 대조)은 이번 C6과 부류가 가까워 곁들임 후보입니다.
