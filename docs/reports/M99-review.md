# M99 리뷰보고서 (review)

라운드 0 리뷰입니다(재작업 라운드 0). 구현과 리뷰를 같은 세션이 했으므로, 판정 전에 독립 반증 패스를 서브에이전트로 돌렸고 그 지적 열 건을 아래에 편입했습니다.

## 비판점

### 차단 (0건)

차단으로 매긴 것은 없습니다. 판례 부류(`vacuous-pass`)에 닿는 지적이 둘 있고(권장 3 · 4), 둘 다 러너나 자기 선언을 고의로 깨야만 닿아 권장으로 매겼습니다. 부인 기록은 「다음 단계」에 있습니다.

### 권장 (4건 — 모두 수정)

1. **규약 본체와 사이트 도입부가 「판별은 아직 소비자가 없다」고 그대로 적고 있었습니다.** 조각 머리는 「읽기 항목과 판별 순서」로 고쳐졌는데 `docs/conventions.md`의 조각 포인터 문장과 `site/docs/conventions-tracker.md`의 도입 문장이 M98 시점 그대로였습니다. 집행을 넓게 적은 것이 아니라 소비를 좁게 적은 것이라 판례 부류는 아닙니다. 재서술처를 같은 편집에서 고치지 않은 것입니다.

2. **`.tide/tracker`가 `.tide/` 파일 범위의 단일 원본에 없었습니다.** 조각은 「레포에 커밋하는 설정」이라고 정했는데 `docs/conventions.md`의 "상태 파일 (.tide/phase)" 절은 커밋되는 파일로 `deps` · `release-mode` · `autonomy`만 들었습니다. 재서술처(`.gitignore`의 주석 · `docs/project-context.md`의 `.tide/` 행 · `README.md`의 gitignore 안내 · `site/docs/concepts.md`)도 같았습니다. `.gitignore`가 `.tide/` 전체인 옛 레포에서는 이 설정이 커밋되지 않습니다.

3. **새 판정의 갈래 넷에 통제가 없습니다.** 스킬의 `tl-` 토큰 소속(`F130`) · 선언에 없는 스킬이 판별 포인터를 든 방향(`F129`) · 판별 절차 표지의 수(`F127`) · README가 없는 보관 디렉터리(`F131`)입니다. 반증 패스가 사본에서 두 러너의 그 분기 넷을 지웠을 때 Part F가 141/0이었습니다. 판정 자체는 살아 있습니다 — 네 교란을 넣으면 두 러너에서 붉고, pwsh에서는 하나씩도 붉었습니다. 트리거가 러너를 고의로 깨는 것뿐이라 권장과 경계 기록으로 매겼습니다. 통제를 더 세우지는 않았습니다.

4. **조각 「기계가 묻는 것」이 두 자리에서 사실과 어긋났습니다.** M98 문장의 「조각 전체에서 본다」가 M99의 표 단위 판정과 어긋났고, 「새 선언 여섯의 … 이름 유일」은 값이 하나인 `tracker-connect:`에 `dup` 행이 없어 넓게 적혔습니다. 하니스 README는 그 제외를 적고 있었습니다. 뒤쪽은 집행을 사실보다 넓게 적은 것이지만 자기 선언에 같은 값을 두 번 적어야 닿습니다.

### 사소 (6건 — 다섯 수정 · 하나 기록)

5. **impl 보고서의 수와 문장 하나씩이 틀렸습니다.** 되돌림 표는 32행인데 「서른세 행」으로 적혀 있었습니다(기준 사본을 셌습니다). 「커맨드 이름을 든 선언 줄은 `tracker-path-sites:` 하나뿐」은 사실이 아니고 검색 패턴도 없었습니다 — `tracker-phase-writes:` · `autonomy-lines:` · `epic-flow-sites:` · `retro-flow-sites:`도 스킬 이름을 듭니다. 결론(커맨드 명단 전체를 든 선언 줄은 없다)은 그대로 섭니다.

6. **T04가 변경 대상으로 든 「정의의 근거」 표를 고치지 않았고 개요의 달라진 점에도 없었습니다.** `td-reach`의 GitHub 기록 칸이 「—」인 채였습니다. 같은 자리의 `td-reach` 정의는 실패의 꼴로 「설정 없음」을 아직 들어 판별 절차 표(그 사유는 `td-explicit`의 `tl-unset`)와 어긋났습니다.

7. **완료 기준 5의 「충족」은 기준 4 · 10의 「부분」과 잣대가 다릅니다**(기록 — 고치지 않음). 설정 `local` · 설정 없음 칸은 표의 규칙을 손으로 적용한 값입니다. 기준의 문면(「결론과 사유가 표에 있다」)은 충족하므로 판정을 바꾸지 않았습니다. 「설정 없음」은 이 사이클의 핵심 위험(연결하지 않은 GitHub 레포가 빈 트래커를 읽는 것)의 칸이고, 실행으로 잰 것은 없습니다.

8. **고지 없이 초록인 꼴이 둘 있었습니다.** `tracker-record-dirs:`에 없는 보관 디렉터리는 README 대응을 묻지 않고, `tracker-connect:`의 값과 값의 수도 묻지 않습니다. 앞쪽은 다음 사이클이 응답을 다시 보관하면 정상 편집으로 닿습니다. 반증 패스가 사본에서 pwsh Part F 141/0으로 확인했습니다.

9. **GitHub 어댑터 표의 명령에 재지 않은 조건이 둘 더 있습니다.** 표의 `gh` 명령은 저장소를 지정하지 않아 `gh`가 고른 기본 저장소를 읽습니다. 포크에서는 `origin`과 다를 수 있습니다. sub-issue 조회는 한 쪽을 넘으면 잘릴 수 있습니다. 둘 다 `gh` 동작에 대한 추측이고 실측은 없습니다.

10. **자잘한 것 둘.** 보관 기록 `github-04-epic-sub-issues.json`에 라벨의 숫자 ID가 남아 있는데 보관 README의 「남긴 것」에 없었습니다(비밀은 아닙니다). 보관 README가 없을 때 sh 러너만 표준 오류에 `awk` 메시지를 냅니다 — 케이스 수와 붉은 집합은 ps1과 같아 고치지 않았습니다.
