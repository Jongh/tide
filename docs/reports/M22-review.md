# M22 리뷰보고서 (review)

## 개요

M22(사이트 단일 원본화 — 커맨드 카탈로그를 캐노니컬 `docs/commands.md`로 끌어오고 가드로 동결)를
리뷰했다. 회고 교훈 #1("일반 가산 사이클은 단일 검증으로 충분, 계약 동결·선언 사이클만 적대 검증")에
따라 — M22는 하위 호환 가산·정리 minor이므로 — **집중 비판 리뷰**로 수행하되, 교훈 #2("테스트 통과
≠ 정합 — 단언이 의도를 겨냥하는지")에 따라 두 핵심 주장(카탈로그 **바이트 보존**, 드리프트 가드의
**의도 정합**)을 직접 검증했다. 그 과정에서 가드 B3의 substring 오탐 가능성을 적발해 **리뷰에서 직접
수정**했다.

**차단 결함 0. 최종 판정: 가능 — 추천 v2.2.0 (minor).**

## 비판점

### 차단 (0건)

없음.

### 권장 (1건 — 리뷰에서 수정 완료)

1. **B3 카탈로그 완전성 검사의 substring 오탐(prefix 충돌)** — `has_command`가 `grep -qF "/tide:$name"`
   (단순 substring)이라, 이름 `fleet`의 존재 검사가 `/tide:fleet-cycle`에도 substring으로 걸려 **거짓
   통과**할 수 있었다. 즉 캐노니컬 카탈로그에서 standalone `## /tide:fleet` 항목이 사라져도(`skills/fleet/`은
   잔존) fleet-cycle/fleet-verify 항목이 남아 있으면 B3가 드리프트를 놓친다 — 교훈 #2가 경계한 "단언이
   의도를 정확히 겨냥하지 못하는 우연한 green". **영향**: B3가 표방한 "각 커맨드 이름의 카탈로그 등장"을
   fleet 계열에서 불완전하게만 보장. 차단은 아니나(개수 가드 B1·다른 이름 검사는 정상, 실제 11종 전부
   등장해 현 상태 green은 정당) 가드의 자기 주장과 실동작을 일치시키기 위해 수정했다.

### 사소 (3건 — 수용)

- **[sn1] mkdocs 실빌드·`check_paths` 미실행(환경-이월)** — 로컬 mkdocs 부재로 스니펫 인클루드의 실제
  렌더는 빌드하지 못했다. **수용 사유**: 새 스니펫 경로·마커(`<!-- --8<-- [start:body] -->` + `--8<--
  "docs/commands.md:body"`)가 **작동 중인 3페이지**(conventions·orchestration·changelog)와 바이트
  수준으로 동형이고, 가드 B2가 인클루드 라인 존재를 정적 검증한다. 배포 빌드(CI/라이브)에서 최종 확인
  (과거 마일스톤의 빌드 출력 검증 패턴과 동일).
- **[sn2] B2 셸 검증의 음성 경로 미픽스처화** — "셸이 카운트/카탈로그 표를 재선언하면 FAIL"의 양성
  경로만 확인했고, 재수기화 픽스처로 실제 FAIL을 재현하진 않았다. **수용 사유**: M21 가드 정밀 수준과
  동일한 한계. B2의 세 조건(인클루드 보유 AND `N종` 부재 AND `|---|---|---|---|` 부재)은 정적으로 명확해,
  재수기화 시 카운트나 표 구분행이 다시 들어오면 결정적으로 FAIL한다.
- **[sn3] 사이트 셸 도입부 + 본문 도입 문단 공존** — 렌더 시 사이트 전용 도입("…한곳에 모았습니다")과
  인클루드된 본문 첫 문단("tide는 11종의…")이 함께 보인다(약한 중복). **수용 사유**: 이는 `conventions`·
  `orchestration` 셸이 이미 택한 동일 패턴(사이트 전용 도입부 + 본문)으로, 의도된 사이트 전용 도입이다.
  카탈로그 **본문 자체는 바이트 동일**(아래 검증)이라 정보 손실·왜곡 없음.

## 수정 내용

- **이슈 1 (B3 substring 오탐)**: `has_command`를 substring → **경계 일치**로 강화했다. 이름 뒤에
  영문자·하이픈이 아닌 경계를 요구한다 —
  - `run.sh`: `grep -qE "/tide:$2([^a-z-]|$)"`
  - `run.ps1`: `$raw -match ('/tide:' + $name + '([^a-z-]|$)')` (`.Contains` → `-match` 정규식)
  이로써 `/tide:fleet`은 뒤가 공백/괄호일 때만 매치하고 `/tide:fleet-cycle`(뒤가 `-`)엔 걸리지 않는다.
  standalone fleet(카탈로그에서 `/tide:fleet [부모 경로]` — 뒤 공백)은 정상 매치, fleet-cycle/verify도
  각자 정상 매치. 판별 실증(아래 검증). `run.ps1` ASCII 소스 규율 유지(정규식 패턴 전부 ASCII).

## 검증

**핵심 주장 1 — 카탈로그 바이트 보존(비파괴의 근거)**:
- 변경 전 `site/docs/commands.md`(git HEAD)의 `## 한눈에 보기`~끝과 현 `docs/commands.md` 본문의 동일
  구간을 `diff` → **120줄 완전 동일**(차이 0). `11종`을 담은 도입 문단(구 3–6행)도 본문 머리와 **동일**.
- 렌더된 사이트 커맨드 페이지의 카탈로그 내용은 변경 전과 동일(위치만 `docs/`로 이동).

**핵심 주장 2 — 가드의 의도 정합(교훈 #2 직접 확인)**:
- **B3 prefix 오탐 적발·수정 실증**: 수정 후 (a) standalone `/tide:fleet`(공백 경계) → MATCH(정상),
  (b) fleet-cycle/fleet-verify만 있고 standalone fleet이 없는 입력 → 이름 `fleet` **NO MATCH**(이제
  드리프트 적발). 수정 전이라면 (b)가 거짓 통과했을 것 — 단언이 이제 의도를 정확히 겨냥한다.
- **B2 셸 검증**: 인클루드 `8<-- "docs/commands.md:body"` 보유, 셸의 `종` 토큰 0·표 구분행 0 — 셸이
  카탈로그를 재복제하지 않음을 결정적으로 확인.
- **B1 카운트 정합**: 캐노니컬 대상이 셸(`site/docs/commands.md`)에서 `docs/commands.md`로 정확히 이동.
  `docs/commands.md`·README·conventions·getting-started 모두 `11종` 선언, `12종`(N+1) 부재.

**스니펫 메커니즘**:
- `docs/commands.md` 마커: 도입 H1은 마커 **밖**(8행 `[start:body]`, 134행 `[end:body]`), 본문에 H1
  중복 없음 → 사이트 셸 H1과 이중 렌더 방지. conventions.md(9/518행)와 동형.

## 릴리즈 판정

**가능** — 추천 **v2.2.0 (minor)**.

근거: 차단 결함 0. 권장 1건(B3 substring 오탐)은 **리뷰에서 직접 수정**해 가드 단언을 의도와 일치시켰고,
사소 3건은 수용 한계로 종결. 변경은 전부 하위 호환 — 커맨드 11종 이름·역할(2.0 stable 계약)·`.tide/phase`/
tide-guard·보고서·마일스톤 형식 불변이고, 카탈로그 본문 바이트 동일로 렌더 출력 불변. 새 캐노니컬 문서
(`docs/commands.md`) 가산 + 드리프트 가드 확장(강제 수단)이라 patch가 아닌 **minor**. 회고가 M11~M20
내내 지목한 "수기 사이트 페이지 표류" 군집의 잔존 뿌리를, 단일 원본화 + 같은 사이클 가드(2.0 메타 규칙)로
닫았다. 양 셸 그린·바이트 보존·가드 의도 정합을 직접 확인.
