### 차단 (0건)

### 권장 (4건)

1. **규약의 접미 ID 서술이 틀렸습니다** — `docs/conventions.md` 284행(M93이 더한 문장)은 「M93부터 두 러너의 실제 케이스에서 접미 ID는 `G8a` 하나」라고 적었습니다. 하지만 `H17a`도 두 러너에 살아 있습니다(`run.sh` · `run.ps1`의 `H17a:` 줄). impl 보고서 T05의 같은 서술도 틀렸습니다. `H17` 줄이 없어 키 (H, 17)이 겹치지 않으므로 `V72`에는 영향이 없습니다.
2. **경계 ⑹이 ps1 쪽을 잘못 적었습니다** — 「두 러너 모두 그 호출(`$` 라벨) 하나뿐」이라고 적었는데, run.ps1의 등록표 출력은 `$` 라벨이 아니라 괄호 식 라벨 `Chk ($rg[1] + ': ' + $rg[5]) …`(8892행)입니다. 이 꼴도 케이스 줄 규칙 밖이고, 세 자리 어디에도 이름이 없었습니다. 같은 규약 285행의 「두 러너의 케이스 호출은 전부 큰따옴표 · 공백 한 칸 꼴」은 M93 이전부터 있던 문장인데, 이 한 줄 때문에 사실과 다릅니다.
3. **경계 ⑸의 재현 포인터가 끊길 자리를 가리켰습니다** — 규약 ⑸는 「실측과 재현은 … `docs/reports/M93-review.md`에 있다」라고 적었습니다. 하지만 그 재현은 라운드 0 리뷰에만 있었고, 리뷰보고서는 라운드마다 다시 쓰입니다.
4. **사이클마다 변하는 수가 규약에 들어갔습니다** — M93은 「대장 밖 케이스 줄의 수는 사이클마다 변하므로 여기 적지 않는다」를 지우고, 그 자리에 시점 수(「다섯 ID · 실행 케이스 16」, ⑹의 「하나뿐」)를 적었습니다. `F2` · `F32` · `F33`은 선언에서 파생되므로 수가 흘러갑니다. 「사이클 중 변하는 수는 문서에 박지 말고 선언처를 가리킨다」(`CLAUDE.md`)에 어긋납니다.

### 사소 (2건)

5. **T04 다시 재기가 반쪽입니다** — 라운드 0 리뷰의 ⑸는 「전후 세 번씩, 한 번에 하나」를 요구했지만, 라운드 1은 후 쪽만 다시 쟀습니다(412 · 403 · 420초). 그래서 늘어난 35초 가운데 `tr` 프로세스 몫과 흔들림을 가를 수 없습니다. 기준 6은 라운드 0의 전후 세 쌍과 출력 바이트 동일로 여전히 섭니다. 전 쪽 다시 재기(약 45분)는 판정에 닿지 않아 하지 않았습니다.
6. **impl 보고서 후속 메모의 번호 순서가 1 · 2 · 3 · 4 · 8 · 5 · 6 · 7이었습니다.**

## 수정 내용

- **이슈 1**: 규약 284행을 「접미 ID는 `G8a` · `H17a` 둘」로 고쳤습니다. impl 보고서 T05의 서술도 같이 고치고, 라운드 1 리뷰가 고쳤다고 병기했습니다.
- **이슈 2**: 규약 ⑹을 「ID가 리터럴이 아닌 케이스 호출 — `$` 라벨(run.sh)과 괄호 식 라벨 `Chk (…)`(run.ps1)」로 넓혔습니다. 같은 이름으로 하니스 README 두 자리(머리 단락 · Part V 「묻지 않는 것」)와 E2 완료 신호 4도 고쳤습니다. 규약 285행의 「전부 큰따옴표 꼴」에는 ps1 등록표 출력 한 줄이 예외라는 것을 적었습니다. impl 보고서 라운드 1 절에도 넓힌 사실을 병기했습니다.
- **이슈 3 · 4**: 규약 ⑸에서 시점 수를 빼고, 「그런 ID와 실행 케이스의 수는 사이클마다 변하므로 여기 적지 않는다」를 넣었습니다. 셈은 impl 보고서를, 재현은 이 보고서를 가리킵니다. ⑹의 「하나뿐」도 뺐습니다. 재현은 아래 「검증」에 옮겨 실었습니다.
- **이슈 6**: 후속 메모 8을 끝으로 옮겨 1~8 순서로 맞췄습니다.

## 검증

- **경계 ⑸ 재현(라운드 0 리뷰에서 옮김 — 규약이 이 자리를 가리킵니다)**
  - 작업 트리를 사본(`git ls-files` + 미추적 파일을 tar로)으로 떴습니다.
  - `run.sh`의 `for st in 수정함 미해결 "원인만 규명" 확인함`에서 `확인함`을, `run.ps1`의 `foreach ($st in @($ST_FIXED, $ST_OPEN, $ST_CAUSE, $ST_CONFIRM))`에서 `$ST_CONFIRM`을 지웠습니다.
  - 하니스 README는 `cases: 853` · `Part C 36` · Part C 제목 36으로 맞췄습니다.
  - 결과: pwsh 전수 852/1, 붉은 하나는 `T3`(사본에 git 이력이 없음)입니다. 라운드 0 반증자가 git 커밋을 둔 사본에서 같은 편집을 하니 853/0이었습니다. 수를 맞추기 전에는 `F22`가 붉었고, 맞춘 뒤에는 대장 쪽 판정이 하나도 붉지 않았습니다.
  - 라운드 0 시점의 반복 ID 셈: pwsh 전수 출력의 케이스 줄 ID를 `awk '{print $2}' | sort | uniq -c`로 셌습니다. `C1` 4 · `E4` 3 · `F2` 3 · `F32` 3 · `F33` 3이었습니다.
- **라운드 1 반증자의 재대조** — 손대지 않은 사본에서 pwsh 7 전수가 854/0이었습니다. 반복 ID도 위와 같습니다.
  - `git show HEAD:tests/discover/run.sh`와 작업 트리의 `-v 이름=값` 토큰을 모두 견줬습니다. M93이 바꾼 것은 `-v c="$2"` 삭제, `-v mains="$_rlm"` 추가, `rt_keybad`의 `-v q='"'` 하나뿐입니다.
  - 새 awk 코드(`rt_keybad` · `cnt_case_scan` · `rv_lonely_cnt`)에 BSD awk 밖의 기능은 없습니다.
- **리뷰가 직접 본 것**
  - 접미 ID: 두 러너를 줄 머리 공백을 벗겨 `grep -oE '^(chk|Chk) "[A-Z][0-9]+[a-z]+[0-9]*:'`로 훑었습니다. `G8a` · `H17a`가 각 1입니다.
  - 따옴표 밖 호출: `grep -nE '^[[:space:]]*(chk|Chk) [^"]'`는 run.ps1 8892행 하나입니다.
  - PATH 우회: `run.sh`에서 `gawk` · `/usr/bin/awk` · `mawk` 언급 가운데 주석이 아닌 줄은 0이라, 엄격 awk 심을 우회하는 호출이 없습니다.
  - 고친 러너가 같은 사본인지: impl의 심 측정 사본 `m93/post2/tests/discover/run.sh`가 작업 트리와 `diff`로 같습니다.
  - impl의 심 아래 sh 파트별 출력(`m93/final1/sh`)은 853/0이고, `newline in string`이 0파일입니다.
- **경계 문면 대조** — 규약 · 하니스 README · E2 · E4 · `docs/project-context.md`를 「경계 둘」 · 「대장 밖」 · 「반복문」 · `$` 라벨로 읽었습니다. 고친 뒤 셋(규약 ⑴ ⑵ ⑸ ⑹ · README 두 자리 · E2)이 같은 넷을 같은 이름으로 적고, 「둘만 남았다」나 완전성을 주장하는 문장은 0입니다.
