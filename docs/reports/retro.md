# tide 회고 (retro)

> 누적 마일스톤·보고서를 가로질러 본 회고. 회고 시점마다 이 문서 **최상단에** 새 섹션을
> 쌓는다(기존 섹션 보존). `/tide:retro`가 생성·갱신하는 읽기 전용 산출물.

## 2026-06-11 (v0.10.0 시점) — M9 반영, M1~M9 누적; 메모: 백로그가 "신규 기능"→"출시분 실증"으로 전환

### 반복된 문제·이슈 군집

- **release/배포-후 실증의 구조적 연기** (등장: M2~M9, 8사이클) — 여전히 최장수. M9에서
  두 형태로 재현: ① 병렬 동작 런타임 미실증(M9가 단일 파일 편집 위주라 자기적용으로
  병렬을 못 보임), ② **M9 검증이 v0.9.0 release 단계에서 새어든 회귀를 적발**(changelog
  메타 문장의 외부 저장소명 literal이 단일 원본화로 사이트 유입). ②는 "release 단계 추가분이
  impl 검증 이후라 미검증으로 빠진다"는 이 패턴의 **직접 증거**다. 처리 추이: M9가 잡아
  수정 — 사후 검증이 실제로 한 사이클 늦게 결함을 잡는 구조임을 보여줌.
- **release 운영·도구 함정** (등장: M3·M4·M8 → **M9에서 학습·회피**) — M8에서 드러난
  3종(phase 기록↔git 분리·셸 here-string 오용·제외 대상 literal 회피)을 M9 release에서
  **의식적으로 모두 회피**해 재발 없음. 군집이 "반복"에서 "학습됨"으로 이동 — release
  스킬에 운영 노트로 박으면 영구화.
- **문서 ↔ 실동작 동기화 누수** (등장: M2~M7 → M8 완화 → **M9 새 형태**) — M8이 단일
  원본화로 부채를 줄였으나, M9에서 그 **부작용**이 처음 노출됐다: "검증을 서술하는 단어가
  곧 콘텐츠가 된다"(메타 용어 누수). 단일화가 동기화 부채를 줄이면서 새 종류의 누수를
  만든 셈. 처리: 리워딩으로 해소, 규칙화는 미도입.
- **단일 원본 vs 사본의 긴장** (등장: M4·M7·M8·M9) — M9가 cycle의 병렬 서술을 impl 참조로
  단일화(M8 기조 계승). 같은 단일화가 위 메타 누수의 토양이기도 하다 — 양면성.

### 회고 메모

1. **백로그 성격이 전환됐다** — M5~M9로 주요 신규 기능(cycle·retro·사이트·한국어화·단일화·
   병렬)이 소진되고, 남은 미반영은 대부분 **"이미 출시한 것의 실증"**(Pages 소스 전환 3사이클째,

   밟는 안정화 라운드**가 1순위 — 마침 사용자가 `marketplace update`로 캐시를 v0.10.0으로
   올려 **실증 창이 열렸다**.
2. **release 운영 함정은 학습 단계** — M9 release에서 phase 분리·`-m` 플래그·literal 회피를
   모두 의식적으로 피했다. 이 학습을 release 스킬/규약의 운영 노트로 박아 영구화할 가치.
3. **단일 원본화의 양면성** — 동기화 부채를 줄이지만 "메타 용어 누수" 같은 새 함정을
   만든다. 제외 대상 용어를 메타 서술에도 쓰지 않는 규칙 + 빌드 출력 검증을 릴리즈
   체크리스트에 넣으면 v0.9.0류 회귀를 release 시점에 잡는다(지금은 다음 사이클이 잡음).
4. **회고 루프 효용 9사이클 실증** — M8이 저비용 3종, M9가 최장기 기능 1종을 소진. retro가
   미반영을 부각 → 다음 milestone이 집어가는 구동이 일관 작동했다. 이제 그 루프의 출력이
   "실증하라"로 바뀌었으니, 회고가 도그푸딩 부채를 가장 큰 글씨로 들고 있어야 한다.

### 반복된 문제·이슈 군집

  M8에서도 재현: 가드 한국어 메시지가 활성 캐시(구 영문)라 release+재설치 전엔 실호출에

- **release 운영·도구 함정** (등장: M3·M4·M8, **신규 군집화**) — M3·M4의 마켓플레이스
  임시경로 복원에 이어, M8 release에서 둘이 새로 발생: (a) `phase=release && git ...`를
  한 명령에 넣자 가드가 **명령 실행 전** phase를 읽어 `idle`로 차단(→ phase 기록을 git과
  별도 호출로 분리해 해결), (b) Bash 도구에 PowerShell here-string `@'...'@`를 오용해 커밋
  메시지에 `@` 줄 오염(→ 푸시 전 `--amend -m`로 정리). 처리: 즉시 수정, 운영 노트화 가치.
- **문서 ↔ 실동작 동기화 누수** (등장: M2·M3·M4·M6·M7 → M8에서 **완화**) — M8이 사이트
  `conventions`·`changelog`를 원본 단일 인클루드로 바꿔 "원본↔사이트" 축의 이중 갱신
  부채를 제거했다. 잔존: README↔CHANGELOG 동일 노트 중복(규약상 의도된 이중화).
- **단일 원본 vs 사본의 긴장** (등장: M4·M7·M8) — M8이 M7의 사본을 `pymdownx.snippets`
  인클루드로 전환해 긴장을 해소(부분). 새 잔가지: snippet `base_path: ["."]`의 빌드 cwd
  의존(루트 빌드 전제, `check_paths:true` fail-fast로 완화).
- **Windows/도구 환경 가정** (등장: M1·M2·M7·M8) — M8에서 ps1 한글을 위한 **BOM 인코딩
  규약**(sh=no-BOM / ps1=BOM)을 새로 확정. 환경 가정이 사이클마다 소소히 재등장 — 모두
  규약화/우회로 수렴.
