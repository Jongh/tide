# tide 회고 (retro)

> 누적 마일스톤·보고서를 가로질러 본 회고. 회고 시점마다 이 문서 **최상단에** 새 섹션을
> 쌓는다(기존 섹션 보존). `/tide:retro`가 생성·갱신하는 읽기 전용 산출물.

## 2026-06-11 (v0.8.0 시점) — M6·M7 반영, M1~M7 누적

### 집계 범위

- 마일스톤: M1~M7 (전부 완료·릴리즈). 본 회고는 직전 v0.6.0 시점 회고에 M6·M7을 더한다.
- 보고서: impl 7건(M1~M7) + review 7건(M1~M7). 자기 자신 `retro.md`는 입력 제외.
- 릴리즈: v0.2.0 ~ v0.8.0 (7사이클).

### 반복된 문제·이슈 군집

- **release/배포-후 실증의 구조적 연기** (등장: M2·M3·M4·M5·M6·M7) — 가장 끈질긴 반복.
  M2~M6은 "플러그인 캐시가 재설치 전까지 구 스킬을 써서 실호출 검증을 release 후로
  미룸"이었고, M7에서 축이 하나 더 늘었다: 사이트는 GitHub Actions 배포라 플러그인
  캐시와 무관하지만 Mermaid 렌더·검색·다크모드 같은 **클라이언트 런타임은 정적
  `--strict` 빌드로 못 잡아** 배포 후로 미뤄진다. 처리 추이: impl을 정적/행위 검증으로
  대체하고 release/배포 후 도그푸딩 — 이번 회고 실행 자체가 M6 retro 스킬의 release-후
  실증(M6-impl#1)에 해당.
- **문서 ↔ 실동작 동기화 누수** (등장: M2·M3·M4·M6·M7) — 버전 파일 목록(M2)·README
  CHANGELOG(M3)·kickoff description(M4)에 더해, M6은 스킬 7→8종 카운트를 3곳에서 수동
  갱신했고, **M7은 사이트용 `conventions`·`changelog`를 원본의 사본으로 만들어 새로운
  동기화 축(원본↔사이트)을 추가**했다. 사용자 대면 표면이 늘 때마다 재현되는 누수.
- **단일 원본 vs 사본의 긴장** (등장: M4·M7) — M4는 템플릿을 중앙→스킬 동봉으로 옮겨
  단일 원본을 지켰으나, M7은 단순성·톤 독립(porpoise 제거)을 위해 의도적으로 사본을
  택했다. 위 동기화 누수의 한 갈래로, 빌드 시 인클루드 단일화가 미반영 후속으로 남음.
- **Windows 실행 전제** (등장: M1·M2·M7) — hook의 sh 의존(M1·M2)에 더해, M7 빌드 검증에서
  전역 Python이 파일 잠금(WinError 2)으로 실패해 격리 venv로 우회. 환경 가정이 사이클마다
  소소하게 재등장 — 모두 우회/문서화로 수렴.

   루틴화.
3. **새 표면 = 새 동기화 부채** — M7이 원본 문서의 사본을 만들며 "문서-실동작 동기화

   부채가 누적되기 전에 끊을 수 있다. 사용자 대면 표면(커맨드 표·버전 카운트·이제 사이트)은
   릴리즈 체크리스트로 동기화 강제할 가치가 커졌다.

### 반복된 문제·이슈 군집

- **설치 캐시 ↔ 원본 괴리: 실호출 검증의 release-후 연기** (등장: M2·M3·M4·M5) —
  편집 대상은 저장소 원본 `skills/`인데 설치된 플러그인 캐시는 release+재설치 전까지 구
  스킬을 쓴다. 그래서 "재설치한 새 세션에서 실제 호출 검증"이 매 사이클 release 후
  도그푸딩으로 미뤄지는 **구조적 반복**. 처리 추이: 자기적용·정적 검증으로 impl 단계를
  대체하고 release 후 실증 — M5에서 자동 발견(매니페스트 무수정)까지 실증돼 패턴이 안정화.
- **문서 ↔ 실동작 동기화 누수** (등장: M2·M3·M4) — 버전 파일 목록 누락(M2), README
  CHANGELOG 구 표기(M3), kickoff `description`이 구 동작만 서술(M4). 처리: 발견 즉시 수정
  또는 "이력 보존" 명시. frontmatter·표 같은 사용자 대면 표면에서 반복 누수.
- **마켓플레이스가 임시 워크트리 경로를 가리킴** (등장: M2·M3) — 도그푸딩 설치 source가
  임시 워크트리 절대경로라 release 후 `remove → add Jongh/tide → install` 복원 필요.
  처리: 운영 절차로 각 release 후 권장에 편입, GitHub 기준 복원은 v0.4.0 후 반영.
- **Windows hook 실행 전제** (등장: M1·M2) — hook 등록 방식의 조용한 무력화(M1, 상대경로로
  수정), ps1 인코딩(M1, 수용), sh 없는 환경(M2, README 전제 명시). 처리: 상대경로 픽스 +
  문서화로 수렴.
