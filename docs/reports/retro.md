# tide 회고 (retro)

> 누적 마일스톤·보고서를 가로질러 본 회고. 회고 시점마다 이 문서 **최상단에** 새 섹션을
> 쌓는다(기존 섹션 보존). `/tide:retro`가 생성·갱신하는 읽기 전용 산출물.

## 2026-07-29 (v2.10.0 시점) — M29~M32 반영, M1~M32 누적; 메모: 회고가 5사이클 관찰만 하던 *"권장은 리뷰에서 직접 수정"* 패턴이 마침내 **구조적 결함으로 진단돼 규약이 됐다**(M32 반증 시도 승격) — 회고→마일스톤 되먹임의 첫 명시 사례. 대신 **문서를 설명하는 문서 층**(수기 카운트·역할 서술)이 새 최대 미반영 군집으로 올라섰다

> M28(가드 읽기/쓰기 구분) 위에 **M29~M32** 네 사이클을 더한다. 성격이 뚜렷하게 둘로 갈린다 —
> **M29·M30은 사용자 신호·도그푸딩 피드백**(발견 우선 작업 진입점 `/tide:debug`, 그 첫 라이브 세션이
> 되돌려준 규약 구멍 3건), **M31·M32는 예측 기반 선제 사이클**(브랜치 간 협업 무결성 구멍, 그리고
> 루프 자신의 판정 신호 소실). 특히 M32는 **회고가 반복 기록한 패턴을 배경으로 인용해 만들어진 첫
> 마일스톤**이다 — tide가 자기 회고를 실제로 되먹인 사이클이다.

### 집계 범위

- 마일스톤: **M29~M32 (4사이클, 전부 완료·릴리즈)**. 직전 회고(M1~M28)에 더한다.
- 보고서: 누적 impl **32**건 + review **32**건(이번 +4/+4). 이 레포의 `docs/reports/debug-*.md`는
  **0건**(debug 도그푸딩은 외부 사용자 프로젝트에서 일어났고 그 산출물은 여기 없다). 자기 자신
  `retro.md`·`retro-archive.md`는 입력 제외.
- 릴리즈: **v2.7.0(M29) · v2.8.0(M30) · v2.9.0(M31) · v2.10.0(M32) — 4연속 minor**. 실측 태그
  **33개**(v0.1.0~v2.10.0); 1.0 이후로만 세면 **major 2 + patch 3 + minor 16 = 21**.
  - *각주(측정 정정)*: 직전 회고는 v2.6.0 시점을 "2 major + 3 patch + 11 minor(전 16릴리즈)"로 적었으나
    같은 기준의 실측은 **minor 12 · 전 17**이다. 아래 **군집 4**(수기 카운트 드리프트)의 또 하나의
    사례이며, **회고 문서 자신도 그 층에 속한다**.

### 반복된 문제·이슈 군집

- **(종결·되먹임) "권장은 리뷰에서 직접 수정" 9사이클 연속 → *구조적 결함*으로 승격**(등장: M24~M32) —
  회고가 M24~M28에서 5사이클 연속 기록한 이 패턴을 M32가 **판정자=실행자 구조**로 진단했다: 리뷰 판정
  31/31 전부 `가능`, 통산 차단 이슈는 M1의 1건뿐 → release 프리플라이트 게이트 ①(판정 "가능")이 **항상
  참인 조건**이고 실질 게이트는 ②테스트·③워킹트리 둘뿐이었다. 처리: **규약화** — 적대 검증을 재량에서
  *모든 리뷰의 기본 경로*(반증 시도)로 승격하고, 판정 계측 한 줄과 재작업 라운드를 더했다. **회고가
  관찰만 하던 패턴이 마일스톤 배경으로 인용돼 규약이 된 첫 사례**다. 다만 M32 자신도 판정 `가능`·
  in-review 수정 13건이라 **패턴 자체는 아직 깨지지 않았다** — 깨지는지는 v2.10.0 설치본 기준 다음
  사이클에서만 관측된다.
- **(지속) 프롬프트 자산은 하니스로 집행 불가 — 라이브 도그푸딩으로만 닫힌다**(등장: M29·M30·M31·M32
  **전부**, 계보 M22~) — 네 사이클 모두 impl이 "선언 정합만 집행, 런타임 발화는 미실증"을 정직 유보로
  남겼다. 처리 추이: **M29의 잔여 3건은 M30의 실제 도그푸딩**(외부 프로젝트 `debug-1`, 2026-07-15)이
  전부 닫았고, **M32는 리뷰 자신이 라이브 실증**했다(반증 서브에이전트가 실제로 디스패치돼 성립 8건).
  반면 **M31의 두 advisory는 여전히 런타임 미실증**이다. 패턴이 안정적이다 — *정직 유보 → 다음 도그푸딩에서
  닫힘(지연 1~2사이클)*. 이 레포에서 하니스가 집행할 수 있는 것은 언제나 **선언**뿐이다.
- **(지속·심화) 선언 정합 가드의 *공허 통과* — 두 번 수용한 한계가 세 번째에 물었다**(등장: M30 사소5 →
  M31 사소6 → **M32 이슈2·3**) — M30은 "네 값 존재 + 가짜 값 부재의 **일방향성**"을 Part B 선례 동형이라
  수용했고, M31은 "범용 git 토큰 앵커의 **brittleness**"를 드문 경로라 수용했다. M32에서 실제로 터졌다 —
  ① 토큰 **존재만** 검사해 이번 구현에서 실제로 난 계측 줄 **이형 드리프트**를 통과시켰고(사람이 손으로
  잡았을 뿐 가드는 무력), ② `in-review` 토큰이 계측 줄과 재검증 절에 **이중 용도**라 세 파일에서 재검증
  절을 **통째로 지워도 45/45 그린**이었다(반증자가 실증). 처리: **fix** — E4(골격 **형식** 정합) + E5(전용
  병기어 `re-verify`)를 더하고, 규약을 "메커니즘마다 **전용** 토큰이 있어야 한다"로 정정. 교훈: 존재 기반
  통제의 일방향성은 수용 가능하지만 **토큰 이중 용도는 수용 불가**다.
- **(신규·최대 미반영) 문서를 설명하는 문서 층에는 가드가 없다 — 수기 카운트와 역할 서술**(등장: M30
  사소6 → **M32 이슈12·13 + 비차단 후속**) — M30은 계획 문서가 인용한 하니스 기준선이 **틀린 수**였음을
  적발했다(14/14 인용, 실측 19/19 — `tests/discover/README.md`가 M22 이후 드리프트한 채 굳음). M32는 같은
  층에서 세 건을 더 냈다: ① 한 사이클에 PASS 수를 **29→41→45→48로 세 번** 고쳤고(M31 가산은 한 사이클
  내내 미반영이었다), ② `README.md`·사이트의 **역할 서술**이 캐노니컬 카탈로그와 갈렸으며, ③
  `docs/orchestration.md`가 **"11종"으로 낡은 채 사이트 본문으로 인클루드돼 공개 페이지에 나가고 있었다**
  (v2.7.0 debug 가산 이후 잔존, B1 카운트 가드가 그 파일을 보지 않았다). 처리: **파일 하나만 가드에
  편입(fix)**, **뿌리(수기 카운트 자체·역할 문구)는 미반영**. 위 집계 범위 각주가 보이듯 **이 회고 문서도
  같은 층에서 드리프트했다**.
- **(지속) 규약↔스킬 단일 원본 이탈 — 뿌리는 conventions 단조 증가**(등장: M30 권장2 → M32 이슈4) —
  M30은 신설 정오표 절이 기존 "재실행 시 보고서 갱신" 절과 **정면 모순**임을 적발했고, M32는 `rework`
  기록 규칙이 **규약(무조건 +1)과 impl 스킬(`불가` 이후에만 +1)로 갈린** 것을 적발했다 — 하필 "스킬은
  인용하고 재정의하지 않는다"고 못박은 같은 절에서. 처리: 둘 다 in-review fix(규범을 conventions로 회수).
  뿌리는 **규약 단조 증가**다(현재 **863줄 · 18개 `##` 절**, 9 minor 동안 증가만) — M32가 절 분할·사문화
  규약 집계를 **명시적 범위 밖 후속**으로 남겼다.
- **(지속) advisory 가산의 minor 판정이 4사이클 연속 *동형***(M29~M32) — 판정 근거가 매번 "사용자 관찰
  가능한 가산 + 계약 표면 불변(커맨드 12종 · `.tide/phase` · tide-guard · 프리플라이트 게이트 집합 ·
  2.0 stable 11종)"으로 같은 형태다. 버전 판정이 안정됐다는 신호이자, **M29 이후 네 사이클 동안 가드를
  한 줄도 고치지 않았다**는 신호다(M28의 가드 정련 이후 무수정 연속).
- **(지속) debug 계열의 대칭 배선 누락**(등장: M29-impl 4 → M31 사소5) — `debug-{N}` 독립 수열에는 번호
  사전경고 대칭이 없고, **열린 debug 세션이 있는 자식 레포를 `fleet-cycle`이 어떻게 다룰지**도 미정의다.
  둘 다 **수용·이월** — 전자는 저비용(같은 `git log --all --diff-filter=A` 배선), 후자는 오케스트레이션
  stable 계약을 건드려 별도 사이클.

### 수용된 트레이드오프

- **debug 경로의 자기 판정**(축약 review 게이트 부재) (출처: M29-review 사소1 → M30-impl 4) — 사용자가
  결정 3에서 명시적으로 택했다("가벼운 수정에 리뷰 한 단계가 다시 붙으면 원래 무게 문제가 재발"). 재검토
  트리거는 **회귀**인데, 도그푸딩에서 나온 것은 회귀가 아니라 **문서-코드 불일치**였다 — **근거 1건 ·
  트리거 미충족**이고, M30의 정오표 경로가 그 증상의 처치다.
- **커버리지 매칭의 경로 부분일치 위양성·위음성** (출처: M31-review 사소4 / M31-impl 2) — advisory·비차단이
  목적에 부합한다(`fleet-verify` git-verb 가드라일과 동형). 소음이 잦으면 표 파싱 강화가 후보.
- **존재 기반 통제의 일방향성 · 범용 토큰 brittleness** (출처: M30 사소5 · M31 사소6) — 레포 선례 동형이고
  실제 드리프트 양상(한 곳만 고쳐 빠뜨림)은 덮는다. **단, 군집 3대로 M32에서 부분적으로 대가를 치렀다.**
- **기준선 문구의 완전 동일성 미집행** (출처: M30-impl 1 / M30 사소4) — 세 템플릿의 단계 이름이 달라
  literal 동일이 **원리상 불가능**하다. 가드는 토큰 존재만 본다.
- **`skills/cycle/SKILL.md`의 `refutation`·`rework` 서술이 Part E 앵커 밖** (출처: M32) — 마일스톤 설계
  그대로. cycle 쪽 드리프트는 도그푸딩 영역으로 남는다.
- **Part E는 *선언*만 집행한다** (출처: M32) — 반증 패스의 런타임 디스패치·계측 값의 정확성은 프롬프트
  규율이다(Part C·D와 같은 분담).
- **카탈로그와 스킬의 인자 표기 축약 불일치** (출처: M29 사소2) — 마크다운 표 셀의 `|` 제약 때문이며 기존
  커맨드도 같은 축약을 쓴다(카탈로그는 요약, 스킬이 원본).
- **감싼 쓰기(`sh -c`/`eval`) 표적 탐지** (출처: M28 권장2, 이월) — 닫으려면 셸 전체 파싱 → 옛 false-positive
  회귀. 여전히 수용·트리거 대기.
- **mkdocs `--strict` 실렌더** (출처: M22~ 환경-이월) — 로컬 사각지대는 `tests/site-includes`가 덮고, 실제
  렌더는 CI 잔존.

### 수용된 트레이드오프

- **감싼/우회·plumbing 쓰기 비대상**(출처: M28-review 권장2) — `sh -c`·`eval`로 감싼 git 쓰기, `commit-tree`
  같은 ref 비이동 plumbing은 차단하지 않는다. 수용 사유: 닫으려면 셸 전체 파싱이 필요하고 그러면 `echo 'git
  push'`·`--grep=push`까지 오차단하던 **옛 부분일치로 회귀**한다(M28이 푼 바로 그 FP). 우발 방지 백스톱에

  후속. 현재 알려진 읽기 옵션은 전부 커버(검증됨).
- **추출 실패 시 레거시 부분일치 폴백**(사소) — `tool_input.command` 추출 실패(파싱 불가 입력)면 보수적으로
