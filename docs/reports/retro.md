> 쌓는다(기존 섹션 보존). `/tide:retro`가 생성·갱신하는 읽기 전용 산출물.

## 2026-06-15 (v2.2.1 시점) — M23 반영, M1~M23 누적; 메모: 정리 사이클 2연속 — 참조 구현 이중성을 *공유 라이브러리화로 축소*, 교훈 #2가 테스트 밖(회고 문서)까지 확장돼 헤더 누락 적발

### 반복된 문제·이슈 군집

- **(축소·진전) 참조 구현 이중성 — 가드판을 거쳐 *공유 라이브러리화*로 표면적 축소**(등장: M14~M20 군집 …
  M22 "가드의 단언 정밀도" 변형 … **M23 축소**) — 프롬프트 스킬(fleet 계열)을 `tests/`가 재구현하던 이중성을,
  M23이 4중(× 2셸) 복제된 `is_tide_repo`/`discover`/`toposort`를 `tests/lib/` 공유 단일 원본으로 추출해
  **표면적을 4→1로 줄였다**. 구조적 한계(프롬프트 스킬은 실행 바이너리 없음)로 *닫지는* 못하고 `read_deps`
  등 잔존하나, 드리프트 발생면을 축소. 실제 드리프트(주석·포맷 분기)를 정본으로 화해했고, fleet-cycle이
  정본 `toposort`로 통과해 **두 구현의 로직 동등성을 실증**(우연한 분기가 아니었음).
- **(지속·교훈 #2) 자동 테스트가 *닿지 않는* 산출물의 무결성 — 3사이클 연속 적발**(등장: M20 참조 구현
  우연한 green · M22 가드 B3 substring · **M23 회고 문서 v2.1.0 헤더 누락**) — 교훈 #2("테스트 통과≠정합")가
  세 사이클 연속 실제 결함을 잡았다. M23은 ②에서 *섀도잉=우연한 green* 가능성을 직접 배제(하니스 로컬 정의
  **0** 확인 — dedup이 실제로 일어났음)했고, ③에서 *하니스가 못 덮는* 회고 문서의 v2.1.0 `## ` 헤더 누락을
  적발·복원했다. 패턴: **테스트가 닿지 않는 산출물(프롬프트 스킬 출력·문서)일수록 직접 눈 검증이 유일한 그물.**
- **(positive·지속) 검증 깊이를 사이클 성격에 맞춤 — 3사이클째**(등장: M21·M22·M23) — M23도 정리 patch라
  단일 집중 비판 리뷰로 가볍게 가져가되, 핵심 위험(섀도잉·바이트 보존·문서 무결성)은 직접 확인했다. 검증
  스케일링이 3사이클 연속 비용을 아끼면서 결함을 놓치지 않음을 입증.

### 회고 메모

1. **못 닫는 군집은 *표면적을 줄여라*** — 참조 구현 이중성은 프롬프트 스킬의 구조적 한계라 닫히지 않는다.
   M23은 "관리(수용)"를 넘어 공유 라이브러리화로 **복제 표면적을 4→1로 축소**해 드리프트 발생면을 줄였다.
   닫을 수 없는 반복 군집은 *완전 종결*이 아니라 *표면적 축소*가 현실적 진전이다(잔존 `read_deps`는 관리).
2. **교훈 #2의 적용면이 테스트 밖으로 확장** — M20(참조 구현)·M22(가드)·M23(회고 문서)로 3사이클 연속,
   "테스트 통과≠정합"이 *자동 테스트가 닿지 않는 산출물*에서 결함을 잡았다. 리팩터에선 **섀도잉=우연한
   green을 직접 배제**(로컬 정의 0 확인)하고, 프롬프트 스킬·문서는 **직접 눈 검증**이 유일한 그물임을 패턴화.
3. **정리 사이클이 정리 백로그를 비우고 잔챙이만 남김** — M22가 연 ②③을 M23이 한 사이클에 모두 반영(사용자
   "둘 다 묶어"). M6부터 최장수 이월(회고 비대화)까지 종결돼 정리 백로그는 0에 수렴 — 남은 건 저위험
   `read_deps`·환경 mkdocs뿐. 다음 사이클은 다시 **사용자 신호 기반**(M21 회고의 결론으로 회귀).
4. **(메타) 아카이브가 회고 자신의 비용을 낮춤 — 이 회고가 ③의 첫 수혜이자 라이브 확인** — 본 섹션은
   1060→320행으로 줄어든 `retro.md` 위에 쓰였고, `/tide:retro`가 분할된 문서에 정상 prepend됨을 이 실행이
   곧 실증했다(릴리즈 후 라이브 확인 = 다음 회고라던 분석대로). 정리가 도구 자신의 운용 비용을 줄인 사례.

   페이지(`commands.md`·`getting-started.md`)만 커맨드 수가 표류했다. 발견성(M21) 작업 시 이 페이지들도
   가능한 한 단일 원본으로 끌어오는 것을 함께 검토한다.
4. **다음(에픽 닫힘 이후)** — 미반영 후속이 0에 수렴. 유일 후보는 **오케스트레이션 발견성(M21)**:

### 반복된 문제·이슈 군집

- **(positive·NEW) 적대적 검증이 안전 주장 결함을 적발** (등장: M18·M19 — **2사이클 연속**) — M18·M19
  리뷰는 ultracode 적대 검증(반증 시도 + 정합·완전성 감사)으로 수행했고, 두 사이클 모두 **"그럴듯하지만
  부정확한 안전 주장"을 적발**했다: M18 = release-exclusion의 "2층 기계 백스톱" 과대 서술 + stale phase=release
  누수 + 동어반복 테스트; M19 = verification-only 백스톱 미정밀 + 통합 훅의 stale-release 사각. **전부
  리뷰에서 수정**(정밀 서술·사전 점검·SKILL 아티팩트 결합 테스트). 단순 자기 검토로는 놓쳤을 결함 — 이번
  구간 품질의 핵심이자, 안전-critical 불변을 다루는 사이클의 새 방법론 패턴.
- **참조 구현 ↔ 스킬 프롬프트 이중성** (등장: M14~M19 — **6사이클 연속**, M18 사소·M19 사소4) — 여전히
  유일하게 살아있는 *부정* 반복 군집. fleet-cycle·fleet-verify도 프롬프트 스킬이라 tests/가 처리 순서·계약·
  훅 파싱 로직을 재구현. M18·M19는 여기에 **SKILL 산문 결합 검증**(금지 목록·verification-only 산문을 grep)
  을 더해 동어반복 테스트를 아티팩트 결합으로 격상 — 이중성은 잔존하나 회귀 방어가 강해졌다(저위험 수용).
- **(positive 지속) 3-way 병렬 디스패치 도그푸딩** (등장: M15~M19) — M18·M19도 규약·스킬·테스트를
  T01∥T02∥T03 3-way 병렬 산출. 회고·리뷰도 워크플로(M18 4-agent 적대, M19 단일 적대)로 — 자기 병렬·
  오케스트레이션 기능을 자기 개발·검토에 계속 도그푸딩.
- **(theme) 부수효과 분리 불변이 전 계층 보존** — fleet(advisory)·fleet-cycle(milestone→review·release 제외)·
  fleet-verify(verification-only) 모두 git·release 자동화 없음. 적대 검증이 그 **보장 메커니즘을 정확히
  서술**하게 만들었다(가드=release 차단기 아닌 phase 잠금, 사전 점검으로 stale-release 사각 차단).

### 수용된 트레이드오프

- **참조 구현 이중성** (M14~M19, 6연속) — 프롬프트 스킬을 스크립트로 덮는 유일한 현실적 방법. M18·M19는
  SKILL 산문 결합 grep으로 회귀 방어 보강.
- **release 제외·verification-only의 실제 보장 = 프롬프트 규율 + 사전 점검** (M18·M19 적대 검증) — tide-guard는
  백스톱(release 차단기가 아닌 phase 잠금)일 뿐이라, stale phase=release 자식은 사전 점검으로 제외하고
  통합 훅엔 cross-repo git을 두지 않는다. 정밀 서술로 수용.
- **통합 훅 git-verb 사전 차단 미구현** (M19-review 사소2) — 훅 실행 전 git 동사 grep 차단은 훅 의미를
  바꾸므로(검증 훅에 git이 합법적으로 필요한 변형 가능) major-safe하게 advisory로 유지.
- **통합 훅 parent-level** (`.tide-fleet/integration`) — 통합은 단일 레포가 소유하지 않는 cross-repo 개념이라
  레포별 `.tide/deps`와 달리 부모 레벨. 숨김이라 발견 무시.
