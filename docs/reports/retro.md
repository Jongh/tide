# tide 회고 (retro)

> 누적 마일스톤·보고서를 가로질러 본 회고. 회고 시점마다 이 문서 **최상단에** 새 섹션을
> 쌓는다(기존 섹션 보존). `/tide:retro`가 생성·갱신하는 읽기 전용 산출물.

## 2026-06-12 (v2.1.0 시점) — M21 반영, M1~M21 누적; 메모: 에픽 후속 마감(발견성) — "검증을 사이클에 맞춘다"(가산 minor=단일 비판 리뷰) 첫 적용, 문서↔실동작 군집을 기계 가드로 종결

> v2.0.0(에픽 마감·안정 재기준) 위에 M21이 **오케스트레이션 발견성**(status·kickoff 멀티 레포 감지 힌트
> + 커맨드 수 드리프트 가드)을 올렸다. v2.0.0 회고가 꼽은 **유일 미반영 후속(발견성)을 반영**해 미반영
> 후속이 0이 됐다.

### 수용된 트레이드오프

- **커맨드 수 가드의 `CONTAINS "N종"` 의미**(출처: M21-review sn1) — 정확 일치가 아니라 포함 검사라,
  한 파일이 `11종`과 모순되는 옛 수를 *동시에* 담으면 통과 가능. 수용 사유: 1차 드리프트(캐노니컬 수
  미선언, 곧 M20 #6 케이스)는 확실히 잡으며, 그게 가드의 의도. 모순 동시 표기까지 잡는 정확 파싱은
  coupling 테스트엔 과함.
- **드리프트 음성 통제가 `N+1종` 기준**(sn2) — 임의적이나 grep이 다른 수를 구별함을 입증하는 목적엔 충분.
- **힌트가 단일 레포에서도 발견 스캔 수행**(sn3) — 출력 바이트 동일·디렉터리 읽기는 읽기 전용이라 status의
  "완전 읽기 전용"·출력 불변 계약 유지. 수용.

### 회고 메모

1. **검증 스케일링이 실전에서 작동** — v2.0.0 회고가 세운 규칙("계약 동결 사이클만 적대 검증, 가산은 단일
   검증")을 M21에서 처음 적용해, 과한 비용 없이 핵심 위험(임계값·가드의 의도 정합)만 직접 확인했다. 이
   기준(사이클 성격 → 검증 깊이)을 앞으로의 기본 운영 규칙으로 둔다.
2. **문서↔실동작 군집을 *가드*로 졸업** — 오래 반복되던 "수기 페이지 표류"를 수정-반복이 아니라 기계
   가드(coupling 테스트)로 닫았다. 반복 이슈는 가능하면 **개별 수정이 아니라 회귀 고정 장치**로 종결하는
   것이 누적 부채를 줄인다(SKILL-coupling → 문서 수 정합으로 확장한 선례).
3. **백로그가 비었다 — 다음은 사용자 신호 기반** — 오케스트레이션 에픽(1~4층)·정리·견고화·발견성이 모두
   종결되고 미반영 후속 0. 다음 사이클은 내부 백로그가 아니라 **새 사용자 요구·운영 중 발견**에서 출발한다.
   후보 예: fleet 계열의 실제 멀티 레포 세션 도그푸딩에서 나오는 개선, 또는 jq 환경-이월 항목의 환경 갖춰질
   때 재실행.

  M8에서도 재현: 가드 한국어 메시지가 활성 캐시(구 영문)라 release+재설치 전엔 실호출에
  안 뜨고, ps1 런타임은 미검증으로 남았다. 다만 M8은 **편집본 sh를 파일 입력으로 직접
  실행**(트리거 토큰 분리)해 활성 가드를 우회하고 한국어 차단을 실증 — "사후로만 가능"의
  예외 경로를 처음 보였다. 처리 추이: 정적/우회 실증 확대 + 잔여는 release 후 도그푸딩.
- **release 운영·도구 함정** (등장: M3·M4·M8, **신규 군집화**) — M3·M4의 마켓플레이스
  임시경로 복원에 이어, M8 release에서 둘이 새로 발생: (a) `phase=release && git ...`를
  한 명령에 넣자 가드가 **명령 실행 전** phase를 읽어 `idle`로 차단(→ phase 기록을 git과
  별도 호출로 분리해 해결), (b) Bash 도구에 PowerShell here-string `@'...'@`를 오용해 커밋
  메시지에 `@` 줄 오염(→ 푸시 전 `--amend -m`로 정리). 처리: 즉시 수정, 운영 노트화 가치.
- **문서 ↔ 실동작 동기화 누수** (등장: M2·M3·M4·M6·M7 → M8에서 **완화**) — M8이 사이트
  `conventions`·`changelog`를 원본 단일 인클루드로 바꿔 "원본↔사이트" 축의 이중 갱신
  부채를 제거했다. 잔존: README↔CHANGELOG 동일 노트 중복(규약상 의도된 이중화).
- **단일 원본 vs 사본의 긴장** (등장: M4·M7·M8) — M8이 M7의 사본을 `pymdownx.snippets`
  인클루드로 전환해 긴장을 해소(부분). 새 잔가지: snippet `base_path: ["."]`의 빌드 cwd
  의존(루트 빌드 전제, `check_paths:true` fail-fast로 완화).
- **Windows/도구 환경 가정** (등장: M1·M2·M7·M8) — M8에서 ps1 한글을 위한 **BOM 인코딩
  규약**(sh=no-BOM / ps1=BOM)을 새로 확정. 환경 가정이 사이클마다 소소히 재등장 — 모두
  규약화/우회로 수렴.

2. **release/배포-후 실증 패턴이 번졌다** — M2~M6은 "플러그인 재설치", M7은 "사이트 배포"로
   같은 구조(impl은 정적 검증, 실동작은 사후 도그푸딩)가 재현. 도그푸딩 절차를 사이클에
   더 내장하자는 v0.6.0 회고 메모가 여전히 유효 — 특히 배포형 산출물에 대한 사후 확인
   루틴화.
3. **새 표면 = 새 동기화 부채** — M7이 원본 문서의 사본을 만들며 "문서-실동작 동기화
   누수"에 원본↔사이트 축을 더했다. 단일 원본화(빌드 인클루드)를 다음 사이클이 집으면
   부채가 누적되기 전에 끊을 수 있다. 사용자 대면 표면(커맨드 표·버전 카운트·이제 사이트)은
   릴리즈 체크리스트로 동기화 강제할 가치가 커졌다.

  편집 대상은 저장소 원본 `skills/`인데 설치된 플러그인 캐시는 release+재설치 전까지 구

  또는 "이력 보존" 명시. frontmatter·표 같은 사용자 대면 표면에서 반복 누수.
- **마켓플레이스가 임시 워크트리 경로를 가리킴** (등장: M2·M3) — 도그푸딩 설치 source가
  임시 워크트리 절대경로라 release 후 `remove → add Jongh/tide → install` 복원 필요.
