# tide 회고 (retro)

> 누적 마일스톤·보고서를 가로질러 본 회고. 회고 시점마다 이 문서 **최상단에** 새 섹션을
> 쌓는다(기존 섹션 보존). `/tide:retro`가 생성·갱신하는 읽기 전용 산출물.

## 2026-06-11 (v0.9.0 시점) — M8 반영, M1~M8 누적; 메모: 회고가 미반영 후속을 실제 소진

### 집계 범위

### 반복된 문제·이슈 군집

- **release/배포-후 실증의 구조적 연기** (등장: M2~M8, 7사이클) — 여전히 최장수 반복.
  M8에서도 재현: 가드 한국어 메시지가 활성 캐시(구 영문)라 release+재설치 전엔 실호출에
  안 뜨고, ps1 런타임은 미검증으로 남았다. 다만 M8은 **편집본 sh를 파일 입력으로 직접
  실행**(트리거 토큰 분리)해 활성 가드를 우회하고 한국어 차단을 실증 — "사후로만 가능"의
  예외 경로를 처음 보였다. 처리 추이: 정적/우회 실증 확대 + 잔여는 release 후 도그푸딩.
- **release 운영·도구 함정** (등장: M3·M4·M8, **신규 군집화**) — M3·M4의 마켓플레이스
  임시경로 복원에 이어, M8 release에서 둘이 새로 발생: (a) `phase=release && git ...`를
  한 명령에 넣자 가드가 **명령 실행 전** phase를 읽어 `idle`로 차단(→ phase 기록을 git과
  별도 호출로 분리해 해결), (b) Bash 도구에 PowerShell here-string `@'...'@`를 오용해 커밋
  메시지에 `@` 줄 오염(→ 푸시 전 `--amend -m`로 정리). 처리: 즉시 수정, 운영 노트화 가치.
- **문서 ↔ 실동작 동기화 누수** (등장: M2·M3·M4·M6·M7 → M8에서 **완화**) — M8이 사이트
  `conventions`·`changelog`를 원본 단일 인클루드로 바꿔 "원본↔사이트" 축의 이중 갱신
  부채를 제거했다. 잔존: README↔CHANGELOG 동일 노트 중복(규약상 의도된 이중화).
- **단일 원본 vs 사본의 긴장** (등장: M4·M7·M8) — M8이 M7의 사본을 `pymdownx.snippets`
  인클루드로 전환해 긴장을 해소(부분). 새 잔가지: snippet `base_path: ["."]`의 빌드 cwd
  의존(루트 빌드 전제, `check_paths:true` fail-fast로 완화).
- **Windows/도구 환경 가정** (등장: M1·M2·M7·M8) — M8에서 ps1 한글을 위한 **BOM 인코딩
  규약**(sh=no-BOM / ps1=BOM)을 새로 확정. 환경 가정이 사이클마다 소소히 재등장 — 모두
  규약화/우회로 수렴.

### 회고 메모

1. **회고 루프의 효용 실증** — M8이 오래 미반영이던 저비용 후속 **3종(한국어화·사이트
   단일화·패키지 위생)을 한 사이클에 소진**했다. "retro가 미반영을 부각 → 다음 milestone이
   집어감"이 실제로 돌았다. 남은 저비용은 거의 없다.
2. **미반영 최상위는 이제 명확히 하나** — **진짜 병렬 실행 수단**(8사이클째, cycle의
   "병렬"이 아직 규칙 해석일 뿐). 저비용 잔무가 비어 다음 마일스톤의 자연스러운 1순위.
3. **release 운영을 스킬에 내장할 때** — M8에서 가드 자기 차단(phase 기록↔git 분리)·셸
   here-string 오용이 새로 드러났다. release 스킬/규약에 "phase=release는 git과 별도 명령으로
   먼저 기록", "커밋 메시지는 도구별 멀티라인 문법 주의"를 운영 노트로 박아두면 반복 비용을
   끊는다(신규 군집 "release 운영·도구 함정").
4. **도그푸딩 부채가 누적 중** — M7의 Pages 소스 전환·배포 확인이 2사이클째 미수행. 배포형
   산출물(사이트)·환경 의존 산출물(ps1 가드)의 사후 확인을 한 번은 실제로 밟아야 "사후
   실증" 군집이 영원히 미결로 남지 않는다.

## 2026-06-11 (v0.8.0 시점) — M6·M7 반영, M1~M7 누적

### 집계 범위

- 마일스톤: M1~M7 (전부 완료·릴리즈). 본 회고는 직전 v0.6.0 시점 회고에 M6·M7을 더한다.
- 보고서: impl 7건(M1~M7) + review 7건(M1~M7). 자기 자신 `retro.md`는 입력 제외.
- 릴리즈: v0.2.0 ~ v0.8.0 (7사이클).

### 반복된 문제·이슈 군집

- **release/배포-후 실증의 구조적 연기** (등장: M2·M3·M4·M5·M6·M7) — 가장 끈질긴 반복.
  M2~M6은 "플러그인 캐시가 재설치 전까지 구 스킬을 써서 실호출 검증을 release 후로
  미룸"이었고, M7에서 축이 하나 더 늘었다: 사이트는 GitHub Actions 배포라 플러그인
  캐시와 무관하지만 Mermaid 렌더·검색·다크모드 같은 **클라이언트 런타임은 정적
  `--strict` 빌드로 못 잡아** 배포 후로 미뤄진다. 처리 추이: impl을 정적/행위 검증으로
  대체하고 release/배포 후 도그푸딩 — 이번 회고 실행 자체가 M6 retro 스킬의 release-후
  실증(M6-impl#1)에 해당.
- **문서 ↔ 실동작 동기화 누수** (등장: M2·M3·M4·M6·M7) — 버전 파일 목록(M2)·README
  CHANGELOG(M3)·kickoff description(M4)에 더해, M6은 스킬 7→8종 카운트를 3곳에서 수동
  갱신했고, **M7은 사이트용 `conventions`·`changelog`를 원본의 사본으로 만들어 새로운
  동기화 축(원본↔사이트)을 추가**했다. 사용자 대면 표면이 늘 때마다 재현되는 누수.
- **단일 원본 vs 사본의 긴장** (등장: M4·M7) — M4는 템플릿을 중앙→스킬 동봉으로 옮겨
  단일 원본을 지켰으나, M7은 단순성·톤 독립(porpoise 제거)을 위해 의도적으로 사본을
  택했다. 위 동기화 누수의 한 갈래로, 빌드 시 인클루드 단일화가 미반영 후속으로 남음.
- **Windows 실행 전제** (등장: M1·M2·M7) — hook의 sh 의존(M1·M2)에 더해, M7 빌드 검증에서
  전역 Python이 파일 잠금(WinError 2)으로 실패해 격리 venv로 우회. 환경 가정이 사이클마다
  소소하게 재등장 — 모두 우회/문서화로 수렴.

  편집 대상은 저장소 원본 `skills/`인데 설치된 플러그인 캐시는 release+재설치 전까지 구

  도그푸딩으로 미뤄지는 **구조적 반복**. 처리 추이: 자기적용·정적 검증으로 impl 단계를
  대체하고 release 후 실증 — M5에서 자동 발견(매니페스트 무수정)까지 실증돼 패턴이 안정화.

  또는 "이력 보존" 명시. frontmatter·표 같은 사용자 대면 표면에서 반복 누수.
- **마켓플레이스가 임시 워크트리 경로를 가리킴** (등장: M2·M3) — 도그푸딩 설치 source가
  임시 워크트리 절대경로라 release 후 `remove → add Jongh/tide → install` 복원 필요.
