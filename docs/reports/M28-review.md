# M28 리뷰보고서 (review)

## 개요

M28(tide-guard 읽기/쓰기 구분)을 리뷰했다. 이 사이클은 tide-guard의 **차단/통과 판정 자체를 바꾸는**
변경(읽기 통과로 완화)이라, 회고 교훈(M20: 계약·안전 핵심 사이클은 적대 검증을 표준 게이트로)에 따라
**보호 불변을 반증 시도로** 검증했다 — 즉 "차단되던 *쓰기*가 통과로 새지 않는지"를 우회·감싼 형태로 공격하고,
"풀린 *읽기*가 다른 형태에서 다시 막히지 않는지"를 함께 봤다. 그 적대 검증이 **읽기 오차단 1건**(리뷰에서
직접 수정)과 **보호 범위의 솔직한 한계 1건**(수용·문서화)을 드러냈다. **차단 결함 0.**

## 비판점

### 차단 (0건)

없음. 직접 git 쓰기는 모든 변형에서 차단이 보존된다(아래 검증).

### 권장 (2건)

1. **`git tag > 파일` 읽기 오차단(리다이렉트 토큰을 태그명으로 오인) — 리뷰에서 수정** — 태그 인자 분류기가
   쉘 리다이렉트 토큰(`>`·`>>`·`<`·`2>`·`&>`)을 *위치 인자*로 세어, 목록 옵션 없는 `git tag > tags.txt`
   (태그 목록을 파일로 덤프 = 읽기)를 **생성으로 오판해 차단**했다. M28의 목표(읽기를 막지 않는다)에 정면으로
   어긋나는 false-positive. **영향**: 읽기 오차단(쓰기 누수 아님 — 안전 측이나 의도 위반). **수정**: 양 셸
   태그 분류 루프가 리다이렉트 토큰에서 **정지**하도록 고쳤다(그 뒤는 태그 인자가 아니라 리다이렉트). 수정 후
   `git tag > /tmp/t.txt` 통과, `git tag v1 > log`(생성+리다이렉트)는 여전히 차단. `tests/multi-repo`에 회귀
   케이스 추가(양 셸 24/24).

2. **감싼/우회 실행의 git 쓰기는 더는 잡지 않음(`sh -c 'git push'`·`eval`) — 수용·범위 문서화** — 옛 부분일치
   가드는 명령 문자열에 `git ... push`가 substring으로 있으면 무엇이든 차단해, `sh -c 'git push'`·`eval 'git
   push'` 같은 **감싼 실행**도 (부수적으로) 잡았다. M28의 서브커맨드-앵커링 토큰 스캔은 `'git`처럼 따옴표에
   붙은 git을 런처로 보지 않아 이들을 통과시킨다. 즉 **직접 git 호출의 차단은 100% 보존**되지만, 감싼/우회
   실행은 비대상이 됐다(plumbing `commit-tree`도 동근으로 비대상). **수용 사유(코드 수정 대신 문서화)**: ①
   이를 다시 잡으려면 셸 전체를 파싱해야 하고, 그러면 `echo 'git push'`·`git log --grep=push`·`HEAD:src/tag.rs`
   같은 무해한 문자열까지 오차단하던 **옛 부분일치로 회귀**한다(M28이 푼 바로 그 false-positive). ② 완전성을
   좇아도 `eval $(printf ...)`·base64 등으로 우회 가능 — *우발 방지 백스톱*에 *의도적 회피 방어*를 요구하는
   것은 범위 착오다. ③ tide의 설계상 "impl·review는 git 금지"의 **실제 보장은 단계 규율**이고 가드는 백스톱
   (M18·M19 적대 검증이 못박은 결론). **처리**: `docs/conventions.md` tide-guard 절에 "가드는 직접 git 호출을
   본다 — 감싼/우회 실행·plumbing은 비대상, 백스톱이지 샌드박스 아님" 범위 항목을 단일 원본으로 명시. 따라서
   완료 기준 #2(보호 불변)는 **직접 git 호출 한정으로 성립**하며, 감싼 형태의 부수적 커버리지 축소는 옛
   substring의 우연한 잔재였지 설계된 보장이 아니었음을 기록한다.

### 사소 (2건)

- **태그 읽기-옵션 화이트리스트의 보수성** — `tag` 읽기 옵션 목록(`-l`·`--contains`·`--points-at`·`--sort`·
  `--format`·`-v` 등)에 없는 *미래 git 읽기 옵션*이 생기고 그 호출이 위치 인자를 동반하면 생성으로 오판해
  **차단될 수 있다**(안전 측 — 읽기만 막고 쓰기는 흘리지 않음). git이 새 tag 읽기 옵션을 추가할 때 목록을
  갱신하는 것이 후속. 현재 알려진 읽기 옵션은 전부 커버됨(검증됨).
- **추출 실패 시 레거시 부분일치 폴백의 거칠음** — `tool_input.command` 추출이 실패하면(파싱 불가 입력)
  보수적으로 옛 부분일치 규칙으로 폴백해 과소 차단을 막는다. 이 드문 경로에선 옛 읽기 오차단이 그 입력
  한정으로 재현될 수 있다(정상 입력에선 미발생). 더 견고한 폴백은 저위험 후속 후보.

## 수정 내용

- **권장 2 (감싼 실행 범위)**: 코드 무수정(수용). `docs/conventions.md` tide-guard 절에 "범위(백스톱이지
  샌드박스 아님)" 항목을 추가해 직접 호출 한정·감싼/우회·plumbing 비대상·실제 보장=단계 규율을 단일 원본으로
  명시.

## 검증

**적대 검증 — 보호 불변(직접 쓰기 차단 보존)**: 우회·감싼·전역옵션 변형으로 쓰기 누수를 반증 시도 —
`GIT_DIR=/x git push`·`git -c k=v tag -a`·`git -c u=x -C dir commit`·`git push --force-with-lease`·
`git tag -am v1 msg`·`true; git push`가 **전부 BLOCK**(직접 호출의 모든 변형에서 차단 보존). 감싼 형태
(`sh -c`·`eval`·`commit-tree`)만 ALLOW이며 이는 권장2로 수용·문서화.

**적대 검증 — 읽기 통과(오차단 없음)**: `git tag -l`·`-l 'v2.*'`·`--contains`·`--points-at`·`--merged`·
`git tag > 파일`·`git log --grep=commit`·`git show HEAD:src/tag.rs`·`git cat-file commit`·`git commit-graph
verify`·`git verify-tag`가 **전부 ALLOW**. 권장1 수정으로 리다이렉트 읽기까지 통과.

**영구 하니스(양 셸, 네이티브 실행)**:

| 하니스 | sh | ps1 |
|---|---|---|
| multi-repo (읽기/쓰기 구분 +12, 리다이렉트 회귀 포함) | **24 / FAIL 0** | **24 / FAIL 0** |
| discover · fleet · fleet-cycle · fleet-verify · site-includes | 19·41·23·29·28 / FAIL 0 | (M27 baseline 동일) |

- multi-repo 12→24(시나리오 10 신설). 음성 통제 충족 — 같은 `impl` phase에서 읽기 통과 + 쓰기 차단을 함께
  단언해 "가드가 살아 있으면서 읽기만 통과"임을 고정. 나머지 5개 하니스 M27 baseline 동일(가드 변경이
  `tests/lib`·오케스트레이션에 무영향).

**게이팅 불변(M27 견고화 보존)**: phase 없으면 무차단·`release`면 전부 통과·BOM 입력 내성·cwd→root→phase
해석·repo-root 격리·폴백 — multi-repo 시나리오 1~9가 전부 PASS로 보존(변경은 verb 매칭부에 한정).

**인코딩 규율**: `tide-guard.sh` 선두 `23 21 2f`(`#!/`, no-BOM 유지), `tide-guard.ps1` 선두 `EF BB BF`
(BOM 보존). 양 셸 한글 메시지 정상 출력(테스트 로그 확인).

**완료 기준 7개**: ① 읽기 통과(검증 표 좌열 전부 ALLOW + 리다이렉트 추가) ② 직접 쓰기 차단 보존(우열 + 우회
변형 전부 BLOCK; 감싼 실행은 권장2 수용·문서화로 직접-호출 한정 성립) ③ 서브커맨드 앵커링(옵션 값·경로·
복합 이름 부분일치 무시) ④ tag 읽기/쓰기 구분 ⑤ 양 셸 동일 판정·24/24·M27 baseline 보존 ⑥ 게이팅 불변
⑦ 2.0 stable 계약 불변·새 커맨드/토큰 0·가드 양 사본 동기화·적대 검증 수행.

**잔여 리스크(솔직)**: (권장2) 감싼/우회·plumbing 쓰기 비대상 — 수용·문서화, 실제 보장은 단계 규율.
(사소) 미래 tag 읽기 옵션의 보수적 오차단 여지·추출 실패 폴백 거칠음 — 둘 다 안전 측(읽기만 막고 쓰기는

## 릴리즈 판정

**가능** — 추천 버전: **v2.6.0 (minor)**

- **근거**: 차단 0. 권장 2건 중 1건(리다이렉트 읽기 오차단)은 **리뷰에서 직접 수정**, 1건(감싼 실행 범위)은
  **수용·문서화**(코드 수정이 옛 false-positive로 회귀하므로 부적절 — 백스톱 철학에 부합). 사소 2건은 모두
  안전 측·저위험 후속. 완료 기준 7개 충족.
- **버전(minor 재판정)**: M28은 tide-guard의 **통과 판정을 사용자 관찰 가능하게 완화**한다(비-release에서
  git 읽기가 통과). **호환 파괴 아님** — 통과하던 것이 새로 차단되지 않고, 차단하던 **직접 쓰기는 그대로
  차단**(보호 보존). 2.0 stable 가드 계약의 *보호 경계*(직접 git 쓰기 차단)는 불변이고, 그 위에서 오차단을
  걷어낸 정련이라 patch보다 크고 major(계약 재기준·호환 파괴)보다 작다 → **minor**. M27 가드 견고화가 minor
  (v2.5.0 동반)였던 선례와 같은 결이되, 이번은 판정이 *관찰 가능하게* 바뀌므로 명시적 minor.
