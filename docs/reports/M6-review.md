# M6 리뷰보고서 (review)

> 이 리뷰는 `/tide:cycle`을 수동 실행(도그푸딩)하는 흐름의 review 단계로 수행됐다.
> 대상은 방금 impl을 마친 M6(최대 번호 마일스톤이자 impl 보고서 존재 → 전제조건 충족).

## 비판점

### 차단 (0건)

없음. M6 완료 기준 중 코드/문서로 검증 가능한 항목(2·3·5)은 충족했고, 미검증 항목(1·4의
실호출 측면)은 재설치가 필요한 이 프로젝트의 구조적 제약이다.

### 권장 (0건)

없음.

### 사소 (3건 — 수용)

1. **"읽기 전용"이라는 표현이 회고 문서 1개를 쓰는 동작과 엄밀히는 불일치** —
   `skills/retro/SKILL.md`·conventions가 retro를 "`/tide:status`와 같은 읽기 전용"으로 부르지만
   실제로는 `docs/reports/retro.md` 하나를 생성/갱신한다. 다만 두 문서 모두 곧바로 "회고 문서
   하나만 생성/갱신, 그 외 무수정"으로 한정하고 M6 마일스톤 자체가 이 프레이밍을 택했으므로
   오해 소지는 낮다. 의도 명확성 우선으로 수용(status=완전 무기록, retro=단일 산출물만).
2. **완료 기준 4(읽기 전용 보장)는 프롬프트 강제뿐** — tide-guard 같은 기계적 가드가 없고
   "회고 문서 외 미수정·phase 미변경·git 금지"는 프롬프트 지시에 의존한다. status와 동일한
   성격이며 git은 어차피 hook이 막으므로(idle phase) 실질 위험은 낮아 수용.
3. **누적되는 `retro.md`의 입력 비용** — 회고가 쌓이면 다음 회고 시 자기 문서가 입력으로
   커진다. 규칙에 "자기 자신 제외"가 있고 파일명(`retro.md`)이 `M*` 글롭에 안 잡혀 자연
   배제되지만, 장기적으로 "직전 회고 메모만 참조" 최적화가 차기 후보(impl 메모 #2와 동일).

## 수정 내용

- 없음 — 리뷰 중 추가 결함을 발견하지 못했다. impl 단계에서 자동 발견 확인(매니페스트
  무수정), 집계 규칙의 실보고서 적용 검증, 문서 8종 카운트 동기화를 이미 끝냈다.

## 검증

- **완료 기준 대조**: ① 노출·호출 — 재설치 필요로 미검증(낮은 위험: 자동 발견 실증 +
  동형 frontmatter). ② 회고 문서 생성 — `docs/reports/retro.md`가 실제로 생성됨(실증).
  ③ 내용 정확성 — 반복 군집·수용 트레이드오프·후속 추적(반영 7/미반영 3)·버전 추이가
  M1~M5 실보고서와 대조해 합치(예: M1 hook 셀프설치→M2 반영, 차단 메시지 한국어화→미반영,
  cycle 시작점 공백→M5 수정). ④ 읽기 전용 — retro 로직이 retro.md 외 파일을 만들지 않음을
  확인(이번 드라이런에서 생성된 비-보고서 파일 없음). ⑤ conventions·README 반영 — 보고서
  절·금지 표·커맨드 표·8종 카운트 갱신 확인. **2·3·4·5 충족, 1은 release 후 실증.**
- **구조 일관성**: retro 스킬이 status의 읽기 전용 골격 + milestone/impl/review의 템플릿
  동봉 패턴을 그대로 따름. frontmatter 동형.
- **부수효과 분리**: 리뷰 중 git 작업 없음. phase는 cycle 흐름상 review로 기록(retro 스킬
  자체는 phase를 건드리지 않도록 명시됨 — 구분 유지).
- **미검증 잔여 리스크**: 완료 기준 1·4의 실호출 측면은 재설치+새 세션 도그푸딩에서 확인.
  M1~M5와 동일한 검증 리듬.
