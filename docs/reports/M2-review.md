## 비판점

### 권장 (3건 — 2건 수정, 1건 후속)

1. **구버전 커맨드 사본이 플러그인 커맨드를 가림 (섀도잉)** — 프로젝트(또는 상위
   디렉터리) `.claude/commands/`의 같은 이름 커맨드가 플러그인 커맨드보다 우선한다.
   이 워크트리가 본 저장소 안에 중첩돼 있고 본 저장소 체크아웃이 아직 v0.1이라,
   리뷰 중 새 세션 검증에서 v0.1 커맨드가 로드되는 현상으로 발견했다. 저장소 자체의
   결함이 아니라 **모든 구버전 수동 설치 사용자가 겪을 마이그레이션 함정**이다.
2. **버전 파일 목록 불일치** — `.claude-plugin/plugin.json`을 release 커맨드에만
   추가하고 status·kickoff의 버전 파일 목록에는 누락했다.
3. **플러그인 패키지에 불필요 파일 포함** — 로컬 경로 설치 캐시에 `.claude/`(스냅샷
   시점의 구 settings.json·hooks 사본), `docs/` 전체가 들어간다. 플러그인 로더는
   패키지 안의 `.claude/`를 읽지 않으므로 동작에는 무해하나 패키지 위생 문제.
   GitHub 설치는 git 기반이라 gitignore된 `.tide/`는 빠지지만 커밋된 `.claude/`는
   포함된다. (후속 — 패키징 제외 수단이 공식 지원되면 적용)

### 사소 (2건 — 수용)

4. **치환 경로의 이중 슬래시** — `${CLAUDE_PLUGIN_ROOT}` 치환 결과가
   `...3c063f//templates/...`로 나타나나 파일 접근에는 영향 없음.
5. **검증 1차 시도의 오판** — 첫 드라이런 세션이 "치환 안 됨"으로 보고했으나 실제로는
   섀도잉된 구 커맨드를 보고 있었다(이슈 1의 증상). verbatim 에코 + 네임스페이스
   호출(`/tide:tide-milestone`)로 교차 검증해 바로잡음. 단일 세션 보고를 그대로 믿지
   말 것 — 검증 절차 교훈으로 기록.

## 검증

- **플러그인 hook**: 구 설치물 제거 후 새 세션에서 phase=impl 커밋 시도 →
  `sh "${CLAUDE_PLUGIN_ROOT}/hooks/tide-guard.sh"` 엔트리가 차단 (Windows에서 단일
  sh 등록 동작 실증). `git status`는 통과.
- **커맨드 노출**: 새 세션에서 `/tide-*` 6종 확인.
- **템플릿 치환**: 네임스페이스 호출 + verbatim 에코로 커맨드 본문의
  `${CLAUDE_PLUGIN_ROOT}`가 절대경로로 치환되고 템플릿 첫 줄이 읽힘을 확인.
  (읽기 전용 `--allowedTools Read` 드라이런 — 부수효과 없음)
- 잔여 리스크: 실제 템플릿 기반 문서 생성은 다음 사이클(M3 마일스톤 작성)에서
  자연 검증된다. 섀도잉(이슈 1)은 v0.3.0 릴리즈로 `.claude/commands/` 삭제가 main에
  반영되고 사용자가 pull하면 이 저장소에서는 자연 해소된다.
