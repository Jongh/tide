# M31 리뷰보고서 (review)

## 비판점

### 차단 (0건)

없음.

### 권장 (1건 — 리뷰에서 직접 수정)

1. **커버리지 근거 집합이 impl 보고서를 제외해 정상 사이클을 오경고한다** — T01의 커버 판정이
   대상 보고서를 "리뷰보고서 + 미릴리즈 debug — **판정 근거 집합과 동일 대상**"으로 잡았다. 그런데
   변경 파일을 실제로 나열하는 `변경 파일 요약` 표는 **impl 보고서**에 있다. 정상 사이클에서 impl이
   바꾼 파일은 `M{N}-impl.md`에만 실리고 리뷰보고서는 자기 `수정 내용`의 파일만 언급하므로, 커버리지
   집합에서 impl을 빼면 **매 사이클 impl 변경 전부가 '미상'으로 오경고**된다 — 새 advisory가 편승
   커밋(드문 경로)을 잡기는커녕 **정상 경로(흔한 경로)에서 늑대소년**이 돼 무시당하고, 그러면 진짜
   편승이 소음에 묻힌다. M31이 닫으려던 "무결성 노출"의 가치가 스스로 무력화되는 설계 결함이다.
   판정 근거 집합(판정 섹션을 가진 review·debug)과 **커버리지 근거 집합**(변경을 설명하는 모든 보고서)을
   혼동한 것이 원인이다.

### 사소 (5건 — 2건 수정, 3건 수용·기록)

2. **첫 릴리즈(브라운필드)에서 전체 트리가 미상으로 뜬다** — 태그가 없으면 기준선이 HEAD 트리 전체라,
   tide 이전 코드가 어느 보고서에도 없어 대량 미상 경고가 난다. 첫 릴리즈 1회성 특성이나 규약이 그
   사실을 적지 않았다. **수정함**(caveat 명시).
3. **"4번째 advisory 가산"이 잘못된 서수였다** — release SKILL 프리플라이트는 이미 4단계(①판정
   ②테스트 ③워킹트리 ④사이트 용어)라 커버리지 체크는 **5번째**다. 규약이 "4번째"라 적어 SKILL 번호와
   어긋났다. **수정함**(서수 대신 "게이트 아닌 advisory 단계"로 기술).
4. **경로 부분일치 매칭의 위양성·위음성** — 보고서가 파일을 변경 파일 요약에 안 적었을 뿐인데 미상으로
   경고하거나, 경로 substring이 우연히 걸려 커버로 오판할 수 있다. **수용**(advisory·비차단이 목적에
   부합 — impl 보고서도 이 한계를 명시했고, fleet-verify git-verb 가드라일과 동형).
5. **`debug-{N}` 번호 충돌은 사전경고 대칭이 없다** — 번호 사전경고는 `/tide:milestone`(M번호)만
   다루고 `debug-{N}` 독립 수열의 같은 브랜치 간 충돌은 다루지 않는다. **수용·기록**(impl 후속 메모에
   이미 저비용 후속 후보로 남김 — `/tide:debug`에 같은 `git log --all --diff-filter=A` 배선이면 대칭).
6. **Part D 교차 통제가 범용 git 토큰에 의존해 다소 brittle하다** — "milestone SKILL에 커버리지 토큰
   없음" 류 통제는 미래에 그 스킬이 무관한 이유로 `git diff --name-only`를 쓰면 오탐한다. **수용**
   (드문 경로이고, 그때 편집자에게 정합을 다시 보게 하는 nudge라 방향이 안전 측. Part B/C의 존재 기반
   통제와 동일 성격).

## 수정 내용

- **이슈 1(권장)**: 커버리지 근거 집합을 **미릴리즈 보고서 전부**(`M{N}-impl.md` + `M{N}-review.md` +
  미릴리즈 `debug-{N}.md`)로 넓혔다 — `docs/conventions.md` "릴리즈 커버리지 체크"의 커버 판정 항목에
  **"커버리지 근거 집합 ≠ 판정 근거 집합"** 소절을 명시(판정은 판정 섹션 보유 보고서, 커버리지는 변경을
  설명하는 impl 보고서 포함)하고, `skills/release/SKILL.md` step 5도 "impl + 리뷰 + 미릴리즈 debug —
  판정 근거보다 넓다"로 정정했다. 이로써 정상 사이클 impl 변경의 오경고가 사라진다.
- **이슈 2(사소)**: `대상 범위 산정` 항목에 첫 릴리즈 대량 미상이 1회성 특성이며 advisory·비차단으로
  수용됨을 한 줄로 명시했다.
- **이슈 3(사소)**: `하위 호환` 항목의 "4번째 advisory 가산"을 제거하고, 기존 게이트(판정·테스트·
  워킹트리·사이트 용어)의 순서·판정은 불변이며 커버리지는 그 뒤 **게이트 아닌 advisory 단계**임을
  명확히 했다.

권장 1건을 수용이 아니라 **직접 수정**한 이유: 트레이드오프가 아니라 **기능이 정상 경로에서 무용해지는
설계 결함**이었다. advisory라 릴리즈를 막진 않지만, 늑대소년이 된 검사는 무시되고 그러면 M31의 목적
자체가 증발한다 — 릴리즈 전에 닫는 것이 옳다.

- **수정이 오경고를 실제로 닫는지** — M31 자신의 변경 파일 7개(conventions·release SKILL·milestone
  SKILL·discover ×2·commands·project-context)가 `M31-impl.md`의 변경 파일 요약에 **전부 경로로**
  실려 있음을 확인했다. 커버리지 집합에 impl을 포함하면 이 릴리즈의 커버리지 미상은 0이다 — 새 규칙의
  **첫 자기적용이 깨끗**하다(수정 전 규칙이었다면 7개가 전부 오경고됐을 것이다).
- **Part D 토큰 온전성** — 이슈 1의 정정이 토큰을 다시 가르지 않았는지 확인: `git diff --name-only`
  (release SKILL step 5)·`git log --all`(milestone SKILL)이 연속 유지되고, 교차 통제(반대 스킬 부재)·
  음성 통제(가짜 토큰 부재)가 양 셸 통과. (impl 중 최초 실행에서 이 토큰이 줄바꿈으로 갈라져 D1이
  FAIL한 이력이 있어 — 가드가 실제로 드리프트를 잡는다는 방증 — 이번 정정에서 재차 확인했다.)
- **가드 무수정** — `hooks/tide-guard.{sh,ps1}`는 이번 사이클에 **한 줄도 손대지 않았다**. 두 검사는
  git **읽기**(`git tag`·`git diff`·`git log`)만 쓰므로 phase≠release에서도 통과하며, `tests/multi-repo`
  30/30이 읽기 통과·쓰기 차단 계약 불변을 뒷받침한다.
- **계약 불변 확인** — 커맨드 **12종**(discover N=12), `.tide/phase` 의미, 프리플라이트 게이트 집합,
  2.0 stable 11종이 전부 무변경. 사이트 제외 용어 0건.

**완료 기준 7개 — 전부 충족**: ① 커버리지 경고 발화/조용/비차단/첫 릴리즈 전체 트리(caveat 추가) ②
bookkeeping 제외 ③ 번호 사전경고 발화/조용/번호 자동변경 없음 ④ 둘 다 읽기 전용·가드 무수정 ⑤
conventions 단일 원본 + 스킬 배선 + Part D 선언 정합 양 셸 동수(36/36) ⑥ 하위 호환(12종·phase·가드·
게이트·11 stable 불변) ⑦ 프롬프트 자산 한계 정직 명시(규약·impl·리뷰 3중).

**잔여 리스크(솔직)**:

- **런타임 발화는 미실증이다** — 두 검사가 실제로 올바른 상황에서 경고를 내는지는 **프롬프트 규율**이라
  Part D는 선언 정합만 집행한다. M29/M30이 프롬프트 자산 한계를 남긴 것과 **정확히 같은 성격**이다.
- **이번 릴리즈에는 커버리지 체크가 실제로 돌지 않는다** — 실행되는 release 스킬은 **설치본(2.8.0)**이라
  step 5가 없다. 새 검사는 **v2.9.0 설치 후 다음 릴리즈부터** 라이브가 된다(스킬 편집의 통상 도그푸딩
  지연 — 가드·규약 편집이 재설치 후 적용되는 것과 동일). 따라서 이 검사의 첫 실증은 v2.9.0 이후 사이클이다.
- **휴리스틱 매칭 소음**과 **다인 팀 미실증**은 라이브 영역으로 남는다.

## 릴리즈 판정

**가능** — 추천 버전: **v2.9.0 (minor)**

- **차단 0.** 권장 1건은 **리뷰에서 직접 수정**(기능을 정상 경로에서 무용하게 만드는 설계 결함 — 수용
  대상이 아니었다). 사소 5건 중 2건 수정(첫 릴리즈 caveat·잘못된 서수), 3건 수용·기록(휴리스틱 한계·
  `debug-{N}` 대칭 부재·Part D 통제 brittleness). 완료 기준 7개 전부 충족, 못 덮은 것은 **라이브
  도그푸딩 영역**으로 정직히 남긴다.
- **버전(minor 확정)**: `/tide:release`의 커버리지 경고와 `/tide:milestone`의 번호 경고가 **사용자
  관찰 가능하게 더해진다** → patch보다 크다(버그 수정·정리가 아니라 사용자가 볼 수 있는 새 동작).
  **호환 파괴 아님** — 두 검사 모두 **비차단·읽기 전용**이고 번호를 자동 변경하지 않으며, 12종 커맨드의
  호출명·역할·산출물, `.tide/phase`·tide-guard 계약, 프리플라이트 **게이트 집합**(판정·테스트·워킹트리·
  사이트 용어)이 그대로다 — 더해진 것은 **advisory 단계 하나와 advisory 경고 하나**뿐이라 기존 릴리즈·
  마일스톤 흐름이 전부 유효하다. 가드는 이번에도 **무수정** → major 아님. 2.0 안정성 절의 "minor·patch는
  가산·정리·견고화에 한한다"에 부합하며, M30이 v2.8.0을 minor로 판정한 근거("관찰 가능한 가산")와 동형이다.
