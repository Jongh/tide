# M69 리뷰보고서 (review)

**라운드 3 리뷰다.** 리뷰 라운드 2는 차단 1 · 권장 3 · 사소 2를 반환했고, impl 라운드 3이 그 반환을
처리했다. 이 보고서는 그 결과를 대상으로 새로 썼다. 재작업 라운드가 **3**(2 초과)이라 종료 조건이 열린다.

## 비판점

### 차단 (1건 — 잔여 위험 수용으로 처분 · 리뷰는 고치지 않았다)

1. **다음 마일스톤을 직전 마일스톤의 태그보다 먼저 세우면 Part O가 붉어 그 릴리즈를 막는다.**
   - **증상 ⑴ `O23`** — stale 판정은 「미릴리즈 = 최대 번호 하나」를 전제로 최대 번호만 뺀다.
     - `skills/cycle/SKILL.md`는 impl·review 보고서가 다 있으면 **릴리즈 여부를 묻지 않고** 새 마일스톤
       단계부터 시작한다. 그래서 M69 미릴리즈 상태에서 `M70.md`가 생기면, 아직 회고가 옮길 수 없는 M69의
       `rf-02`가 대상에 들어가 붉는다.
     - **실측**: 스크래치 사본, CHANGELOG 불변 + 기반 `v2.34.0`인 `M70.md` → `pwsh -Part O` · `sh run.sh O`
       모두 `O23` 붉음(39/1).
   - **증상 ⑵ `O18`**(반증이 연 같은 뿌리) — 버전 파일·CHANGELOG는 올랐는데 **태그 전에** 다음 마일스톤을
     세우면, 그 기반 버전이 CHANGELOG 첫째와 같아져 백스톱이 「회고를 건너뛰었다」로 읽는다.
     - 도달 경로: `pr` 모드의 머지 뒤 마무리 전, 또는 `autonomy=continuous`의 커밋 앞 정지 뒤 새 사이클.
     - **실측**(반증): CHANGELOG `v2.35.0` + 기반 `v2.35.0`인 `M70.md` → 두 사본 모두 `O18`·`O23` 붉음(38/2).
   - **결과** — 두 붉음 모두 release 프리플라이트 2(테스트)를 막는다.
   - **등급** — 트리거는 제품이 제공하는 정상 경로라 `reachability-weighting`이 내리지 않는다. **차단**이다.
   - **처분** — 결함의 자리는 `tests/discover`와 규약 서술뿐이다. `skills/cycle`·`skills/release`의 지시
     자체는 틀리지 않았고, 사용자 저장소에는 이 하니스가 없다. 그래서 아래 판정의 **잔여 위험 수용** 대상이다.

### 권장 (3건 — 전부 리뷰 중 수정)

2. **「기반 버전 줄이 없으면 막지 않는다」가 거짓이었다.** impl 라운드 3의 규약·README·기대는 주장 표 ⑼는
   그 갈래를 「막지 않는 쪽」으로 적었다. 그러나 `O39`(기반 버전 추출 positive-control)가 최대 번호 문서에서
   값이 비면 따로 붉는다.
   - **실측**: 기반 버전 줄 없는 `M70.md` 사본 → 두 사본 모두 `O39` 붉음.
   - 집행을 **사실보다 좁게** 적은 문서 부정확이라 `vacuous-pass`(넓게 주장) 부류는 아니다.
3. **stale 대상 경계(차단 1 ⑴)가 규약에 없었다.** 규약은 *"최대 번호(진행 중인 사이클)는 대상이 아니다 —
   아직 릴리즈되지 않아"* 로 **미릴리즈가 하나뿐이라고** 적어, 기대는 절차(`/tide:cycle`의 시작점 판단)의
   거짓 갈래를 빠뜨렸다(`lean-branches-stated`).
4. **백스톱 갈래 ⑵·⑶의 서술이 차단 1 ⑵와 충돌했다.**
   - ⑵는 *"최대 번호 마일스톤이 초안인지는 묻지 않는다"* 라고 적었지만, 태그 전 초안은 붉는다.
   - ⑶은 그 상태를 무조건 「회고를 건너뛴 것」으로 읽었다.

### 사소 (2건)

5. **(리뷰 중 수정) 회고 스킬 절차의 공백 셋** — `skills/retro/SKILL.md` 「행 키 발급과 섹션 제목의 형태」.
   - 키 도입 전 표의 행에 키를 발급하는 절차가 없었다.
   - 절차 5(집었으나 닫지 못한 행 → `미결`)가 **릴리즈 뒤**에 판단한다는 시점을 적지 않았다. 그래서 수동
     회고가 진행 중인 마일스톤의 행을 일찍 옮길 수 있었다.
   - *"하니스가 그 둘을 대조한다"* 는 사용자 저장소에서는 사실이 아니다.
6. **자동 회고에 옵트아웃이 없다**(반증 — 설계 기록) — 회고를 쓰지 않던 저장소도 첫 릴리즈 뒤
   `docs/reports/retro.md`가 생긴다. 그 뒤로는 `/tide:milestone`의 소음 0 경로(회고 문서 없음)가 그 저장소에서
   끝난다.
   - **막지 않는 이유**: 릴리즈 쪽은 안전하다 — 산출물이 `bk-reports` 범위이고, 회고 실패는 릴리즈를 실패로
     만들지 않는다.
   - 의도된 확장인지 다음 사이클이 판단한다(아래 다음 단계).

## 릴리즈 판정

**가능** — 추천 버전: **v2.35.0 (minor)**

계측: in-review 수정 차단 0/권장 3/사소 1 · 반증 시도 수행 성립 3건 · 연속 폴백(fallback-streak) 0 · 부인 기록(precedent-waiver) 0건 · 연속 부인(waiver-streak) 0 · 재작업 라운드(rework) 3

- **판정 근거**
  - 라운드 2의 차단(리뷰 없는 릴리즈 커밋)은 닫혔다.
  - 릴리즈 경로 전부(리뷰 · debug · 강행 · `pr` 마무리)에서 백스톱이 초록이다.
  - 회고 건너뜀(새 마일스톤 · debug 릴리즈 둘 다)에서는 붉다.
  - 남은 차단 하나는 아래 수용 블록으로 처분했다.
  - 완료 기준은 impl 대조와 같다. 기준 5만 `부분`이고, 그 사유(최대 번호의 설계된 제외)는 이번 차단과 같은
    자리다.
- **잔여 위험 수용**(`residual-risk-acceptance`) — 재작업 라운드 3(2 초과)에서 연 선택이다.
  - ⑴ **무엇을 수용했는가** — 차단 1이다. 직전 마일스톤의 **태그보다 먼저** 다음 마일스톤 문서를 세우면,
    `tests/discover` Part O의 `O23`(미릴리즈 직전 마일스톤이 stale 대상에 듦)과 `O18`(태그 전 기반 버전)이
    붉어 이 저장소의 릴리즈 프리플라이트 2와 CI를 막는다. 트리거는 `/tide:cycle`의 시작점 판단, `pr` 모드의
    머지 뒤 마무리 전 초안, `autonomy=continuous` 뒤 새 사이클이다.
  - ⑵ **왜 배포 가능한가**
    - 결함의 자리는 **기여자 인프라**(`tests/discover`)와 그것을 서술한 규약뿐이다. 하니스는 참조 구현 저장소
      안에서만 돌고 사용자 저장소에는 없다.
    - 이 결함을 고칠 자리는 `skills/`·`hooks/`가 아니다. 이 사이클이 고친 스킬 문면(release·milestone·retro)은
