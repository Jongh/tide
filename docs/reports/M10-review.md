# M10 리뷰보고서 (review)

> `/tide:cycle`의 review 단계로 수행. 대상은 방금 impl을 마친 M10(최대 번호 마일스톤 +
> impl 보고서 존재 → 전제조건 충족). impl은 **T01·T02·T03을 3개 서브에이전트로 실제
> 병렬 디스패치**해 수행됨(M9 병렬 메커니즘의 첫 런타임 실증).

## 비판점

### 차단 (0건)

없음. 완료 기준 6개 충족 — 특히 ⑥ 병렬 실증이 합산 아닌 벽시계 시간(~45s = 최댓값)으로
동시성을 보였고, 빌드 출력 제외 용어 0건으로 ④⑤도 실증. 세 서브에이전트가 격리된
컨텍스트에서 각자 정확한 파일만 편집해 디스패치 계약(전달 컨텍스트·반환·부수효과 분리
상속)이 작동함을 확인.

### 권장 (1건)

1. **릴리즈 빌드 출력 검증이 conventions(T03)엔 있으나 release 스킬(T01) 프리플라이트엔
   미반영** — T03이 `docs/conventions.md`에 "release 프리플라이트에서 빌드 출력 기준 제외
   용어 0건 확인"을 규약으로 넣었지만, `skills/release/SKILL.md`의 실제 프리플라이트
   3단계(판정·테스트·워킹트리)에는 이 스캔이 추가되지 않았다(T01은 "운영 주의" 노트만
   추가). 즉 **규약은 있는데 실행 스킬이 그 단계를 지시하지 않는다** — 회고가 반복 지목한
   "문서↔실동작 동기화" 패턴의 재현. 차단은 아니다(conventions를 읽는 release 수행자가
   따를 수 있고, 같은 단계를 두 태스크가 나눠 가져 비중첩을 지킨 결과이기도 하다). 다음에
   `skills/release/SKILL.md` 프리플라이트에 "사이트 빌드 출력 제외 용어 0건" 한 줄을
   더해 규약과 실행을 일치시키길 권장.

### 사소 (3건 — 수용)

2. **병렬 폴백 경로 미실증**(impl 후속 #1) — 이번은 "비중첩 → 폴백 없는 병렬" 정상 경로만
   탔다. 겹침 부분 순차 폴백·서브에이전트 부분 실패·워크트리 격리는 여전히 미실증. 일부러
   겹치거나 실패하는 픽스처가 필요 — 차기 후보로 수용.
3. **"변경 파일" 권장 필드의 강제력 없음**(impl 후속 #2) — 채우지 않으면 겹침 감지가 다시
   휴리스틱. 필수화는 하위 호환을 깨므로 보류, 후속 마일스톤들이 실제로 채우는지 관찰로
   수용.
4. **T04 예상 변경 파일 언더슈팅**(impl 후속 #3) — README가 예상에 있었으나 실제 불필요.
   예측 필드는 예측일 뿐이며 과대 예측은 무해(병렬 안전엔 과소 예측만 위험)함을 보여줌,
   수용.

## 수정 내용

- 없음 — 리뷰 중 추가 결함을 발견하지 못했다. 세 서브에이전트 산출물(release 운영 주의
  3종·템플릿 "변경 파일" 필드·conventions 두 규약)을 재확인했고, strict 빌드·사이트 반영·
  제외 용어 0건·매니페스트 무수정을 impl 단계에서 이미 실증했다. 권장1은 차단이 아니라
  후속으로 남긴다(scope 확장 회피).

## 검증

- **완료 기준 대조**:
  ① `skills/release/SKILL.md`에 운영 주의 3종 추가, 기존 절차 무변경(실증).
  ② `skills/milestone/template.md`에 태스크별 "변경 파일" 권장 필드(필수 아님)(실증).
  ③ `docs/conventions.md`에 메타 용어 누수 방지 + 릴리즈 빌드 출력 검증 규약, snippets로
     사이트 반영(빌드 출력에서 두 제목 확인)(실증).
  ④ `mkdocs build --strict` exit 0 + 사이트 빌드 출력 제외 용어 0건(실증).
  ⑤ project-context 일관 반영, 매니페스트 무수정. README는 불필요로 미변경(일관성 유지).
  ⑥ **병렬 실증**: T01·T02·T03이 한 메시지 3개 동시 Agent 호출, 비중첩으로 폴백 없음,
     벽시계 ~45s(합산 아님) — M9 병렬 디스패치의 런타임 동작 확인(실증).
- **부수효과 분리**: impl(서브에이전트 포함)·review 통틀어 git 없음. 서브에이전트는
  phase=impl에서 동작 — 가드가 git을 차단하는 정합이 병렬에서도 유지됨(설계대로).
- **디스패치 계약 건전성**: 세 서브에이전트가 격리 컨텍스트에서 마일스톤·project-context를
  읽고 **각자 지정 파일만** 편집(타 파일 무수정), 구조화 반환을 메인이 병합 — 계약이
  의도대로 작동.
- **미검증 잔여 리스크**: 폴백·부분 실패 경로(사소2), 권장1의 규약↔실행 간극. 다음
  도그푸딩/마일스톤에서 다룸.
