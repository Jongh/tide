# M55 리뷰보고서 (review)

## 비판점

### 차단 (0건)

없다. 아래 넷은 전부 `vacuous-pass` 부류로 분류했으나 **도달 가능성 가중**(`reachability-weighting`)을
적용해 `권장`·`사소`로 매겼다 — 부인 기록은 「다음 단계」에 있다.

### 권장 (2건 — 문면은 in-review 수정, 코드 층은 impl 반환)

1. **`P15`의 집행 범위를 하니스 README가 넓게 적었다.** 그 서술은 *"선언된 판정 값이 한 번이라도
   등장하면 붉는다"* 였으나 실제로 세는 토큰은 **첫 값 하나**다. 셋째 값은 보지 않으며, 그 낱말은
   한국어 산문의 흔한 낱말이라 **같은 스킬에 이미 네 번** 다른 뜻으로 들어 있는 채로 하니스가
   **269/0 초록**이다(`skills/impl/SKILL.md` 46·58·64·94행). 남는 구멍은 *"첫 두 값을 한 번도 쓰지
   않으면서 셋째 값으로 집합을 재열거하는 편집"* 하나다.
   - **반대 방향이 더 도달 가능하다** — 첫 값이 둘째 값의 부분 문자열이라, 스킬이 산문에서 둘째 값을
     **한 번만 써도** `P15`가 붉는다. 그런 문장은 마일스톤이 **템플릿에 두라고 요구한 안내문**과 같은
     문장이고(`skills/impl/template.md:26`), 그것을 스킬로 옮기는 것은 평범한 다음 편집이다.
     **같은 문장이 어느 파일에 있느냐로 판정이 갈린다.**
   - **뿌리는 통제의 빈자리다.** 마일스톤 T03은 오탐 방향 통제를 *"새 파트에는 처음부터 적용한다"* 고
     적었는데, Part P의 오탐 방향 통제(`P12`)는 **보고서 표 계열에만** 있고 **소비자 배선 계열
     (`P13`~`P15`)에는 없다.** 그래서 위 과대 집행 방향이 한 번도 실측되지 않았다.

2. **빈 선언 기본값의 못이 「파생 토큰」에만 박혔다.** impl이 관측 ⒟로 닫았다고 적은 자리인데,
   집합 소속을 판정하는 자리는 여전히 **선언 원문**을 읽고 거기엔 못이 없다. 실측(트리 무변이):

   ```
   dash -c 'CRITV=""; _ct=""; case " $CRITV " in *" $_ct "*) echo IN;; *) echo OUT;; esac'  → IN
   pwsh -NoProfile -c '$s=@(); if ($s -notcontains "") { "OUT" }'                            → OUT
   ```

   선언이 빈 채로 **판정 칸까지 비면** `sh`는 빈 값을 **집합 안**으로, `ps1`은 **집합 밖**으로 센다 —
   `P9`가 `sh` 10 · `ps1` 11로 **다른 수를 세고 같은 색**을 낸다. 교란 ⑴이 264/5로 일치한 것은
   **그 자리 케이스가 어차피 전부 붉기 때문**이지 못이 박혀서가 아니다. 문서 둘이 *"두 사본 다 …
   받아 닫았다"* 고 적은 것이 실제보다 넓다.

### 사소 (2건)

3. **Part P의 창 열기가 CR에 깨지는 형태다.** 세 자리가 `$0 == "## …"` **줄 전체 일치**로 창을 연다
   (`tests/discover/run.sh` 2878·2887·2947). `.gitattributes`는 `*.sh`만 LF로 고정하고 `.md`는
   워크트리에서 **CRLF**다(`git ls-files --eol docs/conventions.md` → `i/lf w/crlf`).
   - **선언된 네 환경에서는 발화하지 않는다** — 윈도우 gawk가 줄 끝 CR을 **선벗기고**, 우분투 레그는
     LF로 체크아웃한다. 발화하려면 CR을 레코드에 남기는 awk로 윈도우 워크트리를 읽어야 한다.
   - **신규 이탈은 아니다** — 같은 부류의 정확 일치(`$0 == ""`)가 `run.sh`에 이미 둘 있다(2609·2647).
     다만 이 저장소는 CRLF를 살아 있는 축으로 다루고 M42 차단이 CR 처리에서 나왔으므로 기록해 둔다.
   - 부수: `sh`의 대상 선별에는 `ps1`이 가진 `^[0-9]+$` 가드에 해당하는 것이 없어 `M55-draft.md` 같은
     이름에서 stderr 잡음이 난다. **수는 갈리지 않는다**(정수 비교가 실패해 그 항목이 건너뛰어진다).

4. **`docs/epics/E2.md`가 impl의 `수정` 칸에 있다.** 그 파일을 바꾼 것은 **마일스톤 단계**이고,
   같은 처지의 `docs/milestones/M55.md`는 표에서 빼고 고지로만 처리했다 — 두 파일을 다르게 다뤘다.
   - **다만 표에서 빼는 것이 옳은 처방이 아니다.** 에픽 문서는 릴리즈 커버리지의 **bookkeeping 제외
     대상이 아니고**, 커버리지가 읽는 것은 impl·review 보고서뿐이라 빼면 그 파일이 **커버리지 미상**이
     된다. 그래서 **행을 남기고 왜 남기는지를 명시**하는 쪽으로 고쳤다.

## 수정 내용

- **이슈 1**: `tests/discover/README.md`의 `P15` 문단을 **무는 범위 그대로**로 고쳤다 — 보는 파일이
  하나이고 세는 토큰이 첫 값 하나라는 것, **셋째 값은 보지 않으며 넓히면 M49 부류의 오탐이 된다**는
  것, **템플릿을 대상에서 뺀 것이 의도**라는 것을 고지로 적었다. **코드는 손대지 않았다** — 통제
  추가는 반환 항목이다(impl 보고서의 되돌림 표가 «마지막 편집 뒤 한 판본»이므로 리뷰가 하니스 코드를
  고치면 그 표가 조용히 낡는다).
- **이슈 2**: `tests/discover/README.md`와 `docs/reports/M55-impl.md`의 *"두 사본 다 … 닫았다"* 를
  **파생 토큰까지**로 좁히고, 집합 소속 자리에 못이 없다는 것과 `P9`의 `sh` 10 · `ps1` 11 실측을
  고지로 남겼다. **코드 못박기는 반환 항목이다**(같은 사유).
- **이슈 4**: `docs/reports/M55-impl.md`의 기준선 고지에 **왜 `E2.md` 행을 남기는가**(귀속이 아니라
  커버리지)를 한 줄로 적었다.
- **이슈 3은 고치지 않았다** — 사소이고, 고치려면 하니스 코드를 만져야 해 위와 같은 사유로 반환한다.

## 검증

**재검증 결과 (re-verify)** — in-review 수정 3건 뒤에 다시 실행했다. 고친 파일 둘
(`tests/discover/README.md` · `docs/reports/M55-impl.md`)은 **둘 다 `discover`의 입력**이다.

| 명령 | 결과 |
|---|---|
| `dash tests/discover/run.sh` | **PASS=269 FAIL=0** |
| `bash tests/discover/run.sh` | **PASS=269 FAIL=0** |
| `powershell -File tests/discover/run.ps1` (5.1) | **PASS=269 FAIL=0** |
| `pwsh tests/discover/run.ps1` (7) | **PASS=269 FAIL=0** |

- **나머지 여섯 하니스는 입력이 바뀌지 않았다** — `multi-repo`·`fleet`·`fleet-cycle`·`fleet-verify`·
  `site-includes`는 이 두 파일을 읽지 않는다. **`mutation`만 `discover`를 통째로 돌리므로** 전이
  영향을 받아 재실행했다 — `dash` **7/0** · `bash` **7/0**(비용이 몰리는 두 칸을 골랐다. `ps1` 두 칸은
  같은 `discover` 사본을 도는데 그 넷이 위 표에서 이미 269/0이다).
- **리뷰 보고서 자신은 하니스 입력이 아니다** — `docs/reports/`는 러너의 살아 있는 문서 스캔에서
  빠지고(`roster_scan_files`), 이름으로 읽히는 것은 `retro.md`와 `M{N}-impl.md`뿐이다. 그래서 이
  보고서를 쓴 뒤 다시 돌릴 것이 없다.
- **impl이 낸 28칸은 이 수정 이전 판본의 값이다.** 다시 잰 것은 여섯 칸(`discover` 넷 +
  `mutation` 둘)이고 **전건 같은 수**이므로 28칸 표는 그대로 유효하다.
- **미검증 잔여 리스크 없음.**
