# M85 리뷰보고서 (review)

## 비판점

### 차단 (0건)

차단 등급 이슈는 없다. 아래 권장 · 사소는 리뷰 중에 고쳤거나 경계로 기록했다.

### 권장 (6건)

1. **status가 새로 읽는 값을 상태 확인 항목 표가 수집하지 않았다**(반증) — `skills/status/SKILL.md`의 판정 `불가` 갈래는 impl 보고서 개요와 리뷰 계측 줄의 재작업 라운드를 읽는다. 그런데 규약 "상태 확인 항목과 시작점 판단 (선언)" 절의 「무엇을 읽는가」 표는 `impl-report`를 존재 여부만, `review-report`를 판정 · 추천 버전만 읽었다. 같은 절은 「읽는 법도 여기 있다 — 소비자는 이 표를 가리킨다」 · 「수집을 빠뜨리면 판단 규칙이 데이터 없이 조용히 발화하지 못한다」(M52-T01)고 적는다. 그런데 fleet 분류 줄은 이미 그 갈래를 약속하고 있었다. 정상 흐름(M82 꼴 상태의 자식 레포를 fleet이 볼 때)에서 도달한다. **수정** — 두 행에 재작업 라운드 값을 읽는 법을 더했다.
2. **규약 "보고서" 절의 회고 섹션 목록이 여섯으로 남았다**(반증) — retro 스킬 폴백 목록과 템플릿은 「관측 지표」를 넣어 일곱이 됐는데, 재서술처인 규약 목록은 그대로였다(CLAUDE.md 「규칙을 고치면 재서술한 자리를 같은 편집에서」). **수정**.
3. **`O98`이 행 전체에서 `review-due`를 찾았다 — 다음 회고에서 거짓으로 붉을 자리**(반증) — 릴리즈 뒤 회고는 `rf-103`을 `반영`으로 옮기며 반영 위치 셀에 M85의 일을 적는다. 그때 「재심 표지 `review-due`」 같은 산문 언급만으로 `O98`이 붉는다. 반영 위치 셀로 좁히는 것만으로는 막히지 않는다(산문도 그 셀에 들어간다). **수정** — 표지를 **백틱 없는 맨 토큰**으로 정의하고(규약 정의 · retro 스킬 · 템플릿을 같은 편집에서), 두 러너가 반영 위치 셀 안에서 백틱 바로 뒤가 아닌 `review-due`만 센다. 통제 `O99`에 칸 둘(반영 행의 백틱 언급 0 · 항목 셀의 맨 토큰 0)을 더했다(케이스 수 불변). 되돌림 `rev-prose-done`(반영 행에 「재심 표지 `review-due`」 산문)이 초록, `rev-unquote-sh` · `rev-unquote-ps1`(백틱 검사를 지운 러너)이 각자 `O99`를 붉힌다. 기존 `review-done`(반영 행에 맨 토큰)은 여전히 두 러너 `O98`.
4. **`retro-gate-since:` rf-105가 대상 레포로 폴백하면 관문이 사실상 꺼진다**(반증 · impl 후속 3) — 설치본 규약을 읽는 대상 레포는 키가 105에 닿을 때까지 `next:` · `kin:`을 요구받지 않는다. 같은 사이클이 막 병합한 `rf-61`과 같은 부류다. impl은 공개했지만 「해는 작다」로 낮게 잡았다. **수정** — `rt-issue-gate` 정의에 「그 값은 이 저장소의 키 번호다. 선언을 갖지 않은 대상 레포는 물려받지 않고, 이 규칙을 처음 따르는 회고가 새로 발급하는 행 전부에 요구한다」를 적었다. retro 스킬 · 템플릿의 포인터 두 자리에 「대상 레포에서의 경계도 그 절」을 같은 편집에서 더했다.
5. **규약이 「`fleet` · `cycle`이 status 규칙을 그대로 적용한다」고 적은 채 cycle이 갈라졌다**(리뷰) — T05는 마일스톤 지시대로 status만 고쳤다. 하지만 같은 절 머리 문장은 그대로였고, `skills/cycle/SKILL.md` 설명 줄의 「status는 `불가`에 재실행과 후속 계획을 둘 다 허용」도 새 갈래를 모른다. **수정** — 규약 문장 뒤에 「예외 하나가 남아 있다 — 라운드 대조 갈래는 status에만 있다(후속)」를 적었다. cycle 스킬은 완료 기준 10(`skills/` 변경은 네 스킬뿐)이 막아 고치지 않았다(다음 단계 ⑴).
6. **`rf-38`의 몫이 `rf-103`과 함께 조용히 닫힐 경로에 있다**(반증) — T01이 `rf-38`(선언되지 않은 행의 통째 삭제를 Part O가 보지 못한다)을 `rf-103`에 병합했다. `rf-103`은 이 사이클이 집은 행이라 릴리즈 뒤 회고가 `반영`으로 옮긴다. 그런데 M85는 행 삭제 탐지를 범위 밖에 두었다. **기록** — impl 보고서 후속 5와 아래 다음 단계 ⑵. 고칠 것은 다음 회고의 몫이라 이 리뷰가 표를 고치지 않았다.

### 사소 (6건)

7. **`O97` wide 꼴이 「문자열로는 앞」이라는 서술이 틀렸다**(반증) — `"1050"`은 사전순으로 `"105"` 뒤다(awk · pwsh 실측). wide는 비교의 종류를 가르지 못하고, 가르는 것은 below 꼴 하나다. 기준 4 ⑻은 below로 충족된다. **수정** — README Part O · 두 러너 머리 주석 · impl 보고서 T08.
8. **`/tide:review M{N}`에 정의되지 않은 인자가 붙었다**(반증) — 커맨드 카탈로그의 `/tide:review`는 인자가 없고, 같은 스킬의 다른 갈래도 `→ /tide:review`다. 마일스톤 T05의 문면을 따른 것이지만, 「라벨과 인자까지 포함한 커맨드」를 정하는 fleet 분류 절과 어긋난다. **수정** — status 스킬 · 규약 fleet 분류 줄을 `/tide:review`로.
9. **기준 1 근거의 「각각 정확히 1회」가 셈 단위를 적지 않았다**(반증) — 병합 원장 줄은 키를 항목 셀과 처분 셀에 두 번 적는다. **수정** — impl 보고서에 「항목 셀에서」를 적었다.
10. **생명주기 상태표가 ⑼를 B(회고 전 트리)에 묶었고, 판정별 격자 ③의 부류 축이 왜 하나로 접히는지를 적지 않았다**(리뷰) — ⑼는 ⑸ 위의 debug 릴리즈라 회고가 쌓인 트리(C)다. 그리고 이 판정들은 마일스톤 문서 · 보고서를 읽지 않아 부류 일곱이 ⓑ로 묶인다. **수정** — impl 보고서 상태표 두 행과 「그 입력을 바꾸는 전이」 항목.
11. **통제가 비는 방향과 잔재 판정의 훑기 범위가 「묻지 않는 것」에 없었다**(반증 · 리뷰) — 관문의 `미반영` 필터를 지우는 편집, 재심 표지 판정의 `미결` 수용과 `처분` 거부, 시작 키 선언 줄을 지운 픽스처(실물은 `O88` · `O94`가 막는다), 커맨드 카탈로그 · README의 rt- 토큰. 셋 다 러너 자기 코드를 고쳐야 닿는다(도달 가능성 가중 — 경계 기록). **수정** — 규약 「묻지 않는 것」과 README Part O에 경계로 적었다. 통제를 더하는 일은 다음 단계 ⑶.
12. **마일스톤 T05의 「무는 판정이 없으면 재서술처 공존 정도만 T08에 얹는다」를 하지 않았다**(반증) — impl은 후속 2로 공개했다. 완료 기준에는 없다. **기록**만 했다(다음 단계 ⑴과 함께 다룬다).
