## 비판점

### 차단 (0건)

없습니다. 라운드 1 차단 1(번호 대장 밖 라벨의 무선언 삭제가 초록인데 문서는 한정 없이 붉는다고 적음)은 리뷰가 낸 길 ⑵로 닫혔습니다 — 규약 「기계가 묻지 않는 것」이 경계 넷(가장 큰 번호 · 빈 번호 줄로 덮기 · 공유 ID에서 하나를 남긴 삭제 · 번호 없는 라벨)을 적고, E2 완료 신호 4 하위 항목 · 하니스 README 머리 단락 · Part V 불릿 · 두 러너 주석이 같은 크기로 좁혀졌습니다. 대장 밖 수(러너마다 소스 줄 87 · 실행 98)는 반증자가 다시 세어 맞았고, 사이클마다 변하는 수라 문서에 박지 않고 impl 보고서를 가리킨 것은 CLAUDE.md 「케이스 수를 여러 곳에 적지 않는다」와 맞습니다.

### 권장 (2건)

1. **`retire-subsumed`의 정의 문장이 넓어진 판정보다 느슨했습니다** — 라운드 2가 `V58`에 「은퇴 ID가 붉은 근거 행이 하나 이상」을 더하고 규약 「기계가 묻는 것」 ⑷는 고쳤지만, 같은 절의 갈래 정의(`docs/conventions.md`의 "케이스 은퇴 (거두는 규칙 — 기계가 사유를 묻는다)" 절 `retire-subsumed` 항목)와 `docs/epics/E2.md`의 두 재서술(「무엇을 하지 않는가」의 조건 ⑵ · 「회수 규칙을 쓸 때의 함정」 불릿)은 「붉은 행마다」만 적어 붉은 행 0을 허용했습니다. 규칙의 단일 원본이 기계보다 느슨한 방향이라 공허 통과는 아니지만, 규칙을 재서술한 자리를 같은 편집에서 고치지 않은 자리입니다(CLAUDE.md). 리뷰 중 고쳤습니다.
2. **번호 대장의 「선언 없는 삭제가 붉는다」 문장 몇 곳이 경계 ⑴(파트의 가장 큰 번호)을 문장 안에서 제외하지 않았습니다**(반증 성립) — 대장은 파트마다 (살아 있음 ∪ 은퇴 ∪ 빈 번호)의 가장 큰 번호까지만 보므로(`rt_audit`의 `mx[p]` · `RtAudit`의 `$mx`), 가장 최근 케이스(예: `V71`)를 지우고 `cases:` · 파트 내역을 맞추면 초록입니다. 규약 「번호 대장」 항목(「그 밖의 삭제는 … 경계다」가 번호 단 ID 삭제 전부를 잡는다고 읽힘) · README Part V 불릿 · E2 완료 신호 4 하위 항목 · `V61` 라벨(두 러너 — 「선언 없는 삭제 0」) · impl 보고서 개요가 한정 없이 적었습니다. 같은 문서의 같은 절 · 단락에 경계 ⑴이 적혀 있어(라벨과 impl 개요는 예외) 고지가 주장의 크기를 따라가므로 차단이 아니라 권장으로 두고(아래 부인 기록) 리뷰 중 고쳤습니다.

### 사소 (2건)
