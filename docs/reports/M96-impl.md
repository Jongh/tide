# M96 완료보고서 (impl)

## 개요

M96 태스크 넷(T01~T04)을 구현했습니다.
- 선언 꼬리를 읽는 공용 함수(`decl_tail` · `DeclTail`)가 탭 · VT · FF · CR이 든 공백 연속을 공백 하나로 바꾸게 했습니다. 키 바로 뒤와 두 토큰 사이 모두입니다. 그래서 선언 줄 어디에 탭이 있어도 두 러너의 소비자가 같은 토큰을 받습니다(`rf-125`). 통제는 `F60`입니다.
- `O126` 소실 통제의 셋째 칸은 이제 「직전 섹션에서 `반영`이고 최상단 표에도 있는 키」를 지웁니다. 그런 키가 없으면 합성 반영 행을 더한 사본을 기준으로 쓰고, 그래도 없으면 `0` 대신 `none`을 냅니다(`rf-119`). 통제는 `O128`입니다.
- 하니스 README Part F · O와 규약 「회고 후속 항목의 소비」 절의 경계 서술을 맞췄습니다.

재작업 라운드(rework): 0

## 미해결·후속 메모

1. **탭 · VT · FF · CR 밖의 공백 문자는 정규화하지 않는다.** NBSP · U+3000 같은 유니코드 공백이 줄 가운데에 오면 두 러너의 소비자 분할(sh 바이트 분할 · ps1 `-split '\s+'`)이 다를 수 있습니다. 금지 구분자 판정은 그 문자도 원문에서 붉힙니다(`sep-cps:` 집합). 그때 두 러너의 붉은 집합이 같은지는 재지 않았습니다 — 하니스 README Part F 「묻지 않는 것」에 적었습니다.
2. **소비자 분할 꼴은 그대로 넷이다.** 공용 읽기가 탭을 공백으로 바꾸므로 지금 입력에서는 갈리지 않습니다. 다만 공용 읽기를 거치지 않는 새 선언 읽기를 더하면 같은 갈림이 다시 날 수 있습니다. 전 선언 사본(가운데 · 머리 · 끝)을 두 러너에 먹이는 실측이 그 자리를 잡는 방법입니다(이 보고서의 드라이버 꼴).
3. **합성 반영 행의 키는 `rf-0`이다.** 실제 행 키는 `rf-01`부터라 겹치지 않습니다. 회고 표가 `rf-0`을 쓰게 되면 합성 행이 실제 행과 같은 키를 갖습니다 — 번호는 재사용하지 않고 「최대 + 1」로 발급하므로 정상 흐름에서는 닿지 않습니다.
