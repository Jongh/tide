# debug-1 세션 보고서 (debug)

## 개요

**v2.15.0 릴리즈 PR(#17)의 CI가 붉어서 열린 세션이다**(2026-08-11, 한 턴). M42 사이클은 리뷰 판정
`가능`을 받아 릴리즈 브랜치까지 나갔는데, 그 PR의 CI에서 **`posix (macos-latest)` 잡 하나만** 실패했다
— 나머지 다섯 잡(ubuntu · windows · pwsh · powershell 5.1 · pairing)과 로컬 네 환경은 전부 통과했다.

**발견 1건 · 수정 1건 · 미해결 0건.** 원인은 **one-true-awk(BSD awk)가 `-v` 값의 생 개행을 거부**하는
것이었고, `tests/discover`의 Part I가 표지 목록을 그렇게 넘기고 있었다. CI 잡의 stderr(`awk: newline
in string 미집행`)를 직접 읽어 기전을 확정하고, 전송을 공백으로 바꿔 닫았다. 이 결함은 **GNU awk와
mawk가 받아 주는 입력이라 개발 기계와 우분투 CI에서는 영원히 초록**이며, M42 리뷰가 *"macOS/BSD 레그는
이 세션에서 돌리지 못했다 — CI의 `posix` 잡이 낸다"* 로 남긴 미검증 잔여 리스크가 **그대로 발화한
자리**다. `Part I`는 M42 신설이라 이번이 그 코드의 첫 BSD 실행이었다.

세션 범위는 이 한 항목이다 — 릴리즈를 막고 있는 CI 실패만 닫았고, 같은 부류의 재발을 막을 **집행
신설은 후속으로 넘겼다**(그 판단의 근거는 `## 미해결·후속` 1번에 적었다).

## 항목별 기록

### 1. macOS CI 레그에서만 `discover`가 144/2 — BSD awk가 `-v` 값의 생 개행을 거부해 Part I의 축 추출이 통째로 죽는다 — **수정함**

- **증상**: v2.15.0 릴리즈 PR(#17)의 CI에서 **`posix (macos-latest)` 잡 하나만** 실패했다.
  `tests/discover`가 **144 / 2**이고 붉은 것은 둘이다 —
  `FAIL I1b: 집행 칸이 살아 있는 축 추출 positive-control(>0) (got no, want ok)` ·
  `FAIL I3: 음성 통제 — 주입한 축 상태 모순을 잡는다 (got 0, want 1)`.
  같은 커밋에서 **ubuntu-latest · windows-latest · pwsh · powershell(5.1) · pairing 다섯 잡은 전부
  통과**했고, 로컬 네 환경(dash · bash · pwsh 7.6.4 · PS 5.1)도 전부 146 / 0이었다.
  `I1b`가 `no`라는 것은 `POS_AXES`가 **완전히 비었다**는 뜻이고, `I3`는 그 파생이다(POS가 없으면
  주입한 모순을 견줄 대상이 없다).

- **재현**: 로컬에 BSD awk가 없어 **이 기계에서는 재현하지 못했다.** 대신 CI 잡의 **stderr**를 읽어
  기전을 직접 확인했다 — `gh run view 31466601563 --job 93700676848 --log`:

  ```
  awk: newline in string 미집행 ...
  awk: newline in string 이던 ...
  ```

  `미집행`은 `state-neg:` 선언의 **첫 표지**, `이던`은 `state-past:` 선언의 **첫 표지**다. 즉
  awk가 표지 목록을 받다가 죽었고, 이 메시지는 one-true-awk(BWK awk — macOS `/usr/bin/awk`)의
  것이다. 메시지가 **매 호출마다** 반복되는 것도 `live_axes`·`contra_of`가 케이스마다 불리는 구조와
  일치한다.

- **원인**: `tests/discover/run.sh`의 `live_axes()`(`-v NEG="$NEG_MARKS"`)와
  `contra_of()`(`-v NEG="$NEG_MARKS" -v PAST="$PAST_MARKS"`)가 표지 목록을 **개행으로 구분한 채**
  awk에 넘기고 `split(NEG, NG, "\n")`으로 받았다. **one-true-awk는 `-v` 값에 생 개행이 있으면
  `newline in string`으로 죽는다**(값을 문자열 리터럴로 렉싱하므로 raw newline이 문법 오류다).
  GNU awk와 mawk는 이것을 받아 주므로 **개발 기계도, 우분투 CI(mawk)도, Git Bash(gawk)도 초록**이고
  **macOS(BSD awk)에서만 붉다** — 이것이 축 표가 `external-tool`(GNU ↔ BSD)로 선언해 둔 축이고,
  M40이 macOS 레그를 붙인 이유 그대로다. `Part I`는 M42 신설이라 **이번이 그 코드의 첫 BSD 실행**이다.

  범위는 **그 두 자리로 격리된다**. 근거는 실측이다 — ⑴ `I1`(표지 추출 positive-control)은 macOS에서
  **통과**했으므로 `markers_of`·`decl_lines`의 awk는 BSD에서 정상이다(그쪽 `-v k=` 값은 단일 토큰이라
  개행이 없다) ⑵ Part H의 `table_axis_tokens`(`run.sh:850`)는 **같은 `axis:[a-z][a-z-]*` 토큰**을
  `grep -o`로 뽑는데 macOS에서 **통과**한다 — 정규식·토큰 형태는 무죄다 ⑶ 나머지 `awk -v` 값
  (`SELFREF_JEOL`·`SKEL_UI`는 **한 글자**, `k`는 단일 토큰, `cr`은 CR 한 글자, `BASES`는 경로)은
  개행을 담을 수 없고, 해당 파트들도 macOS에서 통과했다.

  **부수 관찰**: 같은 고장에서 `I2`(살아 있는 문서 모순 0건)는 **초록이었다** — `contra_of`가 빈
  출력을 내면 "모순 0건"이 되어 `0 == 0`으로 공허 통과한다. 붉힌 것은 **추출 positive-control(`I1b`)과
  음성 통제(`I3`)** 둘뿐이다. 이 레포가 파트마다 그 둘을 붙여 온 규율이 **BSD에서 실제로 값을 했다**.

- **수정**: 표지 전송을 **개행에서 공백으로** 바꿨다(`run.sh`).
  `NEG_MARKS_SP`·`PAST_MARKS_SP`를 한 번 만들어 두 awk 호출에 넘기고, 받는 쪽을
  `split(…, " ")`으로 맞췄다.
  - **무손실인 근거**: 표지는 `markers_of`가 `tr ' ' '\n'`으로 **공백에서 쪼개** 만든다 — 즉
    **표지에는 공백이 들어갈 수 없다**(선언 형식이 그것을 보장한다). 그래서 개행 대신 공백으로 실어도
    집합이 변하지 않는다. 추정이 아니라 구성상 그렇다.
  - **새 기전을 들이지 않았다**: 같은 `contra_of`의 `AX`(`POS_AXES`)가 **이미 공백 전송 +
    `split(AX, A, " ")`** 을 쓰고 있고 **BSD에서 그 자리는 죽지 않았다**(stderr에 `AX` 값으로 인한
    오류가 없다). 이미 통과하는 전송에 나머지 둘을 맞춘 것이다.
  - `split(s, a, " ")`은 awk의 기본 필드 분할 규칙이라 앞뒤 공백·연속 공백을 알아서 흡수한다 —
    `tr`이 남기는 꼬리 공백이 빈 원소를 만들지 않는다(기존 `NG[i] != ""` 가드도 그대로 뒀다).
  - **ps1 사본은 손대지 않았다** — `run.ps1`에는 awk가 없고 표지를 .NET 배열로 다룬다. 이 결함은
    sh 사본의 전송 방식에만 있었으므로 양 사본의 **의미**는 처음부터 같았다.

- **검증**:
  - **전송값 직접 계측**(사본에 계측을 심어 실행): 수정 **전** `-v`로 가던 값에 **생 개행 2개**,
    수정 **후** `neg_nl=0 past_nl=0`이고 내용은 그대로다 —
    `neg=[미집행 미배선 가드밖]`(3) · `past=[이던 이었 였 떠났다 붙었다 얻었다]`(6). 규약 선언과 일치한다.
    **BSD awk가 거부한 바로 그 입력이 사라졌고 실려 가는 내용은 변하지 않았다.**
  - **로컬 전수**: 하니스 6종 × dash · bash — 전부 FAIL 0(**314 / 0**), `run.ps1` 6종 × pwsh 7.6.4 —
    전부 FAIL 0, discover는 PS 5.1에서도 146 / 0. **회귀 0**이다.
  - **미검증(정직 표기)**: **BSD awk에서의 통과는 이 기계에서 확인할 수 없다** — 로컬에 BSD awk가
    없고, 이 결함은 정의상 그 구현에서만 발화한다. 따라서 이 수정의 최종 확인 자리는
    **PR #17의 `posix (macos-latest)` 레그**다. 위 계측은 *"거부당한 입력이 제거됐다"* 까지를
    증명하고, *"BSD awk가 이제 통과한다"* 는 CI가 낸다.

## 미해결·후속

1. **`awk -v` 생 개행 금지가 어디에도 집행돼 있지 않다.** 이번 결함은 규약에도 하니스에도 그런
   규율이 **없어서** 생겼다 — 사람이 개행으로 쪼갠 목록을 `-v`로 넘기는 것이 GNU/mawk에서 아무
   문제가 없기 때문이다. 같은 부류가 다시 들어올 통로가 그대로 열려 있다. 처분 후보는 **표지에
   공백이 없다**는 불변을 양 사본이 함께 단언하는 케이스다(sh는 전송값에 개행이 0인지, ps1은 표지
   배열 원소에 공백류가 없는지 — 같은 불변의 양쪽 표현이라 케이스 집합의 동형이 유지된다).
   **이번 세션에서 하지 않은 이유**: 새 케이스는 케이스 수 선언·README·양 러너를 함께 바꾸고
   네 환경 재검증을 요구하는데, **BSD 검증은 어차피 CI 왕복으로만 가능**하다. 막힌 릴리즈 위에서
   수정과 새 집행을 한 번에 밀면 새 케이스 자신의 BSD 특성 때문에 왕복이 한 번 더 늘 수 있다.
   **다음 사이클(M43)의 항목**으로 넘긴다 — 마침 M43은 규칙 개정 사이클이다.
2. **`I2`가 이 고장에서 공허 통과했다.** 붉힌 것은 `I1b`·`I3`뿐이다. 설계대로 통제가 작동한
   결과라 결함은 아니지만, *"모순 0건"* 을 단언하는 케이스는 **추출이 죽어도 같은 답을 낸다**는
   사실이 실측으로 확인됐다. 같은 형태(0건 단언)가 다른 파트에도 있는지는 이 세션에서 세지 않았다.
3. **BSD awk 실측은 여전히 로컬 사각지대다.** 이번 수정의 확인이 CI에 있는 것처럼, `external-tool`
   축의 모든 후속 변경은 같은 왕복을 진다. `docs/project-context.md`의 실행 환경 축 항목이 이미
   그 사실을 적고 있으므로 새 고지를 더하지는 않았다.

## 릴리즈 판정

**가능** — 추천 버전: **v2.15.0 (minor)**

- **판정 근거**: 미해결 **차단급 항목이 없다**. 발견 1건은 원인을 **CI stderr로 직접 확인**해
  수정했고, 로컬 네 환경에서 **회귀 0**(314 / 0)이며, 전송값 계측으로 *"BSD awk가 거부한 입력이
  제거됐고 실려 가는 내용은 불변"* 까지 증명했다. 후속 셋은 전부 **집행 신설·측정 확대**로 다음
  사이클의 몫이지 이번 배포를 막는 항목이 아니다.
- **버전을 올리지 않는다** — 이 수정은 **M42 사이클의 회귀를 그 사이클의 릴리즈 전에 닫는 것**이라
  별도 patch 번호를 만들지 않고 **v2.15.0에 합류**한다. 고친 대상이 기여자 하니스(`tests/`)라
  사용자 관찰 가능한 동작 변화도 없다. `M42-review.md`의 판정(**가능** · v2.15.0)과 이 보고서의
  판정이 **같은 버전을 가리키므로** 프리플라이트의 근거 집합이 일관된다.
- **다음**: 이 수정을 `release/v2.15.0` 브랜치에 실어 **PR #17의 macOS 레그가 초록인지 확인**한 뒤
  머지하고, `/tide:release v2.15.0`으로 마무리(태그 · `gh release` · 브랜치 정리)한다.
  **macOS 레그가 이 수정의 최종 검증 자리**이므로 그 결과를 보기 전에는 머지하지 않는다.
