# M35 완료보고서 (impl)

## 개요

M35의 다섯 태스크(T01~T05)를 전부 구현했다. `docs/conventions.md`의 `### 상호참조 무결성`을 **규약
문서 집합**(본체 + `docs/conventions-{주제}.md` 조각, 발견 글롭 `docs/conventions*.md`) 전제로 확장하고(T01),
`tests/discover` Part G가 **파일별 앵커 집합**으로 대조하도록 일반화한 뒤(T02), `## 릴리즈 게시 (gh)`
127줄을 `docs/conventions-release.md`로 **문장 무수정 이동**하고 인용을 갱신했으며(T03), 사이트 셸·nav를
배선했다(T04). 마지막으로 집행력을 두 변형으로 실증하고 전 하니스 6종을 양 셸로 재실행했다(T05, FAIL 0).
오케스트레이션 절 분할과 인용 규약의 문서 일반 확대는 계획대로 범위 밖이다.

**계획의 "인용 4건"은 실제로 5건이었고, 그것을 사람이 아니라 이번에 만든 가드가 잡았다** — 상세는 T03.

재작업 라운드(rework): 0

## 태스크별 수행 내용

- **M35-T01** — `### 상호참조 무결성`(문서 자기서술 정합 절의 세 번째 규약)을 새 `##` 절을 만들지 않고
  확장했다. 더한 것: **규약 문서 집합**(본체 + 조각, 주제 토큰은 소문자 ASCII, 발견 글롭
  `docs/conventions*.md` — 목록 하드코딩 금지가 요점) · **인용은 앵커가 실제로 사는 파일을 가리킨다**
  (조각↔본체 사이의 상호참조도 파일을 건너뛰므로 같은 골격을 쓰고 그 순간 가드 사정권에 든다) ·
  **조각 파일 요건 셋**(마커 + 도입 문단은 마커 밖 / 사이트 셸·nav를 같은 사이클에 / 본체에 포인터 한 줄).
  기존 두 항목은 제자리 개정했다 — **이름 유일성의 범위를 "문서 안" → "집합 전체"** 로, **집행**을
  "파일별 앵커 집합 대조"로. 같은 규칙을 두 곳에 적으면 두 번째 선언처가 생기므로 새 항목을 추가하지
  않고 기존 문장을 고친 것이 설계 결정이다.
  - 골격 예시의 **중괄호 자리표**(`{앵커 이름}`)를 유지했다 — M34가 넣은 제외 규칙이 없으면 규약을
    적는 행위 자체가 그 규약을 FAIL시킨다(Part G 통과로 실증).
- **M35-T02** — Part G의 **내부 구현만** 일반화했다(Part A~F 무접촉).
  - **집합 발견**: 양 셸이 글롭 `docs/conventions*.md`로 목록을 만들고 정렬해 **같은 순서**로 훑는다
    (`run.sh`는 quoted-glob + `LC_ALL=C sort`, `run.ps1`은 ordinal `StartsWith`/`EndsWith` 필터 +
    `List[string].Sort([StringComparer]::Ordinal)`). `run.ps1`에서 `-Filter '*.md'`를 쓰지 않은 이유는
    Windows 8.3 단축명 때문에 `.mdx` 류를 물 수 있어서다.
  - **앵커를 파일별로 묶되 키는 파일명이 아니라 인덱스**로 했다 — sh가 레코드를 `<인덱스목록> <인용>`
    텍스트 줄로 나르는데 파일명에 공백이 들면 레코드가 깨진다. sh는 `anchors.<i>.txt` + 통제용 합본,
    ps1은 `$gAnchorSets[i]`(ordinal `HashSet`) + 평면 리스트.
  - **인용의 파일 귀속**: 후보 줄 판정을 `grep 'conventions\.md'` → `grep -F -f <파일명 목록>`으로
    바꿨고(단일 파일 상태에서 동치), 줄마다 등장한 파일명들의 인덱스를 각 따옴표 구획과 함께 저장한다.
    miss 판정은 **귀속된 집합 중 하나라도 맞으면 통과**(안전 측 — 오탐을 만들지 않는다).
  - **이름 유일성·가짜 이름 통제는 합본(집합 전체) 기준**이 됐다. 제외 규칙 3종(`8<--`·`{}`·빈 구획)과
    M34 리뷰가 넣은 방어(`grep -qxF -- … </dev/null`)는 그대로 유지했다.
  - **케이스 수는 6 유지**(리팩터이므로). `Chk`/`chk` 설명 문자열을 한 글자도 바꾸지 않아 출력이
    before/after 바이트 동일이다.
- **M35-T03** — `docs/conventions.md` **714–840행(127줄)** 을 `docs/conventions-release.md`로 옮겼다.
  본문 문장은 **고쳐 쓰지 않았다** — 이동과 축약을 섞으면 리뷰가 diff에서 둘을 가려낼 수 없다(M34에서
  신설·승격·축약이 한 파일에 섞여 절별 증감 검증에 품이 들었던 교훈).
  - **파일을 건너뛰게 된 자기참조 3건만** 인용 골격으로 바꿨다(규약이 요구하는 최소 변경):
    `(위 "상태 파일 (.tide/phase)" 절)` · `(위 "버전·CHANGELOG"의 …)` · `(위 "tide-guard hook"·"2.0 안정성" 절)`
    → 각각 `` `docs/conventions.md`의 … `` 형태. 조각 **안에서** 조각을 가리키는 참조
    (`"원격 불가 처리"` 2건)는 파일을 건너뛰지 않으므로 그대로 뒀다.
  - 본체에는 **제목 없는 포인터 블록쿼트 2줄**을 남겼다. 제목을 남기면 조각과 이름이 겹쳐 **집합 전체
    이름 유일성 통제가 FAIL**한다(T02가 임시 조각으로 미리 실측해 경고한 사항).
  - **인용 갱신은 4건이 아니라 5건이었다.** 마일스톤은 `"릴리즈 게시 (gh)"` 문자열 검색으로 4곳을
    셌지만, `docs/project-context.md:151`이 **소절**을 `` `docs/conventions.md`의 "`pr` 모드" 절 `` 로
    따로 인용하고 있었다. 4건만 고친 상태에서 하니스를 돌리자 `G1 (got 1, want 0)`이 떴고, 진단해
    5번째를 찾아 고쳤다 — **계획의 수동 집계가 놓친 인용을 이번 사이클이 만든 가드가 잡은 것**이다.
- **M35-T04** — `site/docs/conventions-release.md`를 `site/docs/conventions.md`와 같은 형태의 셸로
  만들고(사이트 전용 도입부 + 저장소 원본 링크 + 인클루드 한 줄) `site/mkdocs.yml`의 `nav`에 `규약`
  바로 아래로 항목을 더했다. **러너·CI는 한 줄도 고치지 않았다** — `tests/site-includes`가 셸을
  발견하고(shells 4 → 5, PASS 28 → 34), `deploy-pages.yml`은 paths 필터가 없어 새 루트 파일이 트리거에서

- **M35-T05** — 집행력 실증 2종(아래 테스트 결과), 전 하니스 6종 양 셸 재실행, 계약 표면 불변 확인,

### 부수효과 분리

이 단계에서 git commit·tag·push를 **하지 않았다**(`.tide/phase=impl`로 tide-guard가 백스톱). git은
**읽기만** 사용했다(`git status`·`git diff`). 병렬 서브에이전트 둘에도 같은 금지를 상속시켰다.

### 병렬 디스패치

**레벨 0의 T01·T02를 서브에이전트로 동시 실행했다** — 마일스톤이 변경 파일을 비중첩으로 설계하고
(T01 = `docs/conventions.md`, T02 = `tests/discover/*`) 명명 규칙·발견 글롭을 본문에서 미리 고정해
두었으므로 폴백 없이 병렬이 성립했다. 나머지 레벨(T03 → T04 → T05)은 각 1개씩이라 메인이 순차로
수행했다. M34가 전 구간 순차 폴백이었던 사유(같은 레벨 두 태스크가 같은 파일을 고친다)를 이번엔
설계로 없앤 결과다.
