# M4 완료보고서 (impl)

## 개요

M4 "브라운필드 킥오프 + 프로젝트 구조 문서화"의 5개 태스크를 전부 구현했다.
`/tide:kickoff` 스킬에 신규/진행-중 프로젝트 판별과 `docs/project-context.md` 생성
단계를 추가하고, `/tide:milestone`·`/tide:impl`이 그 문서를 조건부로 참조하도록
연결했다. conventions·README에 새 산출물과 동작을 반영하고, 이 저장소(자체가 브라운필드)
에 새 로직을 자기적용해 `docs/project-context.md`를 실제로 생성·검증했다.

## 태스크별 수행 내용

- **M4-T01** — `skills/kickoff/SKILL.md` 앞부분에 신규/진행-중 판별 단계를 추가했다.
  판별 신호(git 커밋 이력, `docs/milestones/`·`docs/reports/` 기존 산출물, 소스·버전
  파일 규모)와 결과 한 줄 보고를 명시. 기존 "덮어쓰지 말고 누락만 보강" 원칙은 유지.
- **M4-T02** — 같은 스킬에 단계 7을 추가했다. **진행 중**으로 판별된 경우에만
  `docs/project-context.md`를 생성(스택·의존성 / 디렉터리 구조와 역할 / 진입점·빌드·
  테스트 / 핵심 도메인 개념). 불확실 항목은 "확인 필요" 표기, 구조 파악이 어려우면 최소
  골격+사유 보고, 신규 프로젝트면 단계 생략+사유 보고로 폴백을 명문화. **설계 결정**:
  형식이 단순하고 kickoff 한 곳에서만 쓰여 별도 `skills/kickoff/template.md`를 동봉하지
  않고 스킬 본문 인라인 형식으로 두었다(M4-T02 상세의 "동봉 여부 판단"에 따름).
- **M4-T03** — `skills/milestone/SKILL.md`와 `skills/impl/SKILL.md`에 "`docs/project-context.md`가
  있으면 먼저 읽어 기존 구조를 파악한 뒤 진행(없으면 평소대로)"를 **조건부**로 추가했다.
  필수 전제조건으로 만들지 않아 기존 동작과 하위 호환된다.
- **M4-T04** — `docs/conventions.md`에 "## 프로젝트 컨텍스트" 절을 신설(생성 조건·내용·
  신규/진행-중 차이·milestone/impl의 조건부 참조)하고, `README.md`의 커맨드 표 kickoff
  행 산출물에 `docs/project-context.md`를 추가, 역할 문구를 "(+ 진행 중 프로젝트면 구조
  문서화)"로 보강, 저장소 구조 docs/ 설명에 "프로젝트 컨텍스트"를 추가했다.
- **M4-T05** — 새 로직을 이 저장소에 자기적용해 검증했다. 이 저장소는 커밋 4개 +
  기존 스킬/hook 소스 + M1~M6 마일스톤 보유로 **진행 중 프로젝트**로 감지되며, 그에 따라
  `docs/project-context.md`를 실제로 생성했다(스택·구조·진입점·도메인 개념 채움).
  전 저장소 grep으로 6개 파일(생성처 kickoff, 소비처 milestone·impl, 문서 conventions·
  README, 산출물 자체)이 일관되게 연결됨을 확인했다.

## 테스트 결과

자동화된 테스트 러너가 없는 프로젝트다(해석형 마크다운/셸 hook). 대체 검증:

1. **자기적용 드라이런(T05)** — 새 kickoff 판별 로직대로 이 저장소를 평가해 "진행 중
   프로젝트" 판정이 정확함을 확인(커밋 4 + 기존 소스/산출물). 그 분기에서
   `docs/project-context.md`를 실제 생성 → 생성 경로 동작 확인.
2. **신규 프로젝트 분기** — 스킬 본문상 빈 프로젝트면 단계 7을 생략하도록 조건 분기가
   명시됨을 검토로 확인(기존 골격 생성 동작 보존, 완료 기준 2).
3. **연결 일관성** — `project-context` grep으로 생성처·소비처·문서·산출물 6개 파일이
   빠짐없이 연결됨을 확인(완료 기준 3).

실패 없음. 구현 중 발견·수정한 별도 이슈 없음.

## 미해결·후속 메모

1. **설치 캐시 미반영 — 새 세션 재설치 검증은 release 후로 연기**: 편집 대상은 저장소
   원본 `skills/`이고, 현재 설치된 플러그인 캐시(`...\plugins\cache\tide\0.4.0\`)는
   release+재설치 전까지 구 스킬을 쓴다. 따라서 "재설치한 새 세션에서 실제 `/tide:kickoff`
   호출"로의 검증은 이번 단계에서 불가하며 release 후 도그푸딩으로 수행해야 한다(M3와
   동일 패턴). 본 단계는 새 로직의 자기적용으로 동작을 실증해 대체했다.
2. **판별 임계값이 휴리스틱**: "진행 중" 판별이 커밋/산출물/소스 규모의 정성 신호에
   의존한다. 커밋 1~2개·소스 거의 없는 경계 사례에서 신규/진행-중 오판 가능 — 리뷰에서
   경계 동작 점검 권장.
3. **자기적용 산출물의 커밋 여부**: `docs/project-context.md`는 런타임 산출물이지만 이
   저장소에선 실제 문서로 커밋 대상이 된다. release 시 포함 여부를 판단할 것.
