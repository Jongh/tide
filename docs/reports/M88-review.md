### 권장 (5건)

1. **impl 보고서가 돌리지 않은 검색을 범위로 적었다** — T01의 「손 상수 기대값」 범위는 패턴 둘을 적었지만 impl은 그 검색을 돌리지 않고 C3 · C4 자리만 읽었다. 완료 기준 1 근거 칸의 Grep 패턴은 깨진 문자열(`hk "K(7\|…`)이었다. T07의 Grep은 대상에 `docs/reports`가 없는데 「히트는 옛 리뷰 보고서뿐」이라고 적었다(반증 성립 — 메인 발견과 겹침). `scope-same-search` 위반이다. 리뷰가 실제로 돌려 보니 결론은 같았다 — sh 히트 10 · ps1 11 가운데 문서 목록 크기 뜻인 것은 없고, `V29`의 `2` · `G8a`의 `40`은 러너가 스스로 든 목록 크기다. 보고서의 주장이 실측보다 넓었던 것이지 판정이 공허한 것은 아니라 권장이다.
2. **C3 파생을 케이스 자신이 아니라 복제한 논리가 지킨다 · 기준 3의 재해석을 밝히지 않았다** — 통제는 grow 사본에서 `roster_count`와 `decl_n`이 맞는지만 본다. 개수 케이스 여섯의 기대값을 손 숫자 `"6"` · `"11"`로 되돌려도 오늘 트리에서는 값이 같아 전부 초록이다. 마일스톤이 막으려던 `rf-97` 회귀를 무엇도 잡지 않는다. 또 기준 3은 「이름 하나를 더한 사본에서 초록」인데 구현은 「이름과 수를 함께」로 바꿔 읽었고, 보고서는 그것을 충족으로만 적었다(반증 성립). 규약 · 문서가 집행을 사실보다 넓게 적은 `vacuous-pass` 부류다. 다만 트리거는 하니스 자기 검사 코드(케이스 줄의 기대값 자리)를 고치는 편집뿐이다. 그래서 `reachability-weighting`으로 권장 + 경계 기록으로 내렸다(부인 기록 — 다음 단계).
3. **파생원 셋 가운데 하나만 비워 보았다** — grow/drop 통제와 되돌림 세 행이 기록 명단 접두만 건드렸다. 비기록(「**나머지 」) · stable(「**커맨드 」) 접두를 비운 사본은 재지 않았다. 일반어 접두라 앞 절에 다른 뜻의 「접두 + 숫자 + 종」이 생기면 그것이 파생원이 된다는 취약도 적혀 있지 않았다(반증 성립).
4. **하니스 README 등록표 문단이 낡은 근거를 현재형으로 적었다** — 「Part N의 선언 케이스는 등록표에 두지 않는다 — `case_ids`가 `chk "N…:` 줄을 읽어 …」. M88이 그 근거를 두 러너 주석과 규약 `case-exists`에서 고쳤는데 README 사본은 빠졌다. `CLAUDE.md`의 「규칙을 고치면 재서술한 자리를 같은 편집에서」를 어겼다(반증 성립).
5. **impl 보고서 T05가 코드와 다르다** — 「선언만 맞바꿈 세 자리」라고 적었지만 `O119`는 선언 사본을 합성 창 하나에 건다(같은 보고서의 발견 ⑸가 그 이유를 적는다). 마일스톤 T05의 「세 자리 모두에서 붉다」를 하지 않았다는 사실도 밝히지 않았다(반증 성립).

### 사소 (3건)

6. **생명주기 상태표 ⑿가 새 헬퍼 전부를 파트 가드 밖이라고 적었다** — `ms_order_bad` · `ms_order_fixture` · `ms_frag_root`(ps1 `MsOrderBad` 등)는 Part O 가드 안이다. 해는 없다(Part O만 쓴다)(반증 성립).
7. **`/tide:debug` 승격에 러너를 함께 고친다는 문장 셋이 낡았다** — `run.sh` · `run.ps1` 주석과 README Part C. M88 뒤 기대값은 규약 문장에서 읽으므로 러너는 고치지 않는다(반증 성립).
8. **규약 「회고 후속 항목의 소비」 절의 닫힌 목록이 M88의 차례 판정을 빠뜨렸다** — 「무는 것은 …까지다(M87)」 바로 뒤에 「차례는 M88부터 묻는다」가 와서 닫힌 목록이 실제보다 좁았다(반증 성립).
