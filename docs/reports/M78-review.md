# M78 리뷰보고서 (review)

> 이 보고서는 **라운드 1**이다. 라운드 0(판정 `불가`)의 비판점은 차단 2(규약의 구분자 집행 주장 · impl 완료 기준 4 · 7 대조) · 권장 2 · 사소 5였고,
> 반증 성립은 8건이었다. 라운드 1 impl(재작업 라운드 1)이 아홉 항목을 처리했고, 이 리뷰가 그것을 트리에서 하나씩 확인했다(아래 `## 검증`).

## 비판점

### 차단 (0건)

라운드 0의 차단 둘은 닫혔다.
- 차단 1: `N35`가 `floor-mark-map:`까지 네 줄을 문다. 되돌림 `n35-mapsep`에서 두 사본 모두 `N35`만 붉다.
- 차단 2: 빠진 방향 여섯이 되돌림 표에 행으로 있고 리뷰가 재현했다. 재서술 검색이 영어 패턴으로 다시 돌았고, 낡은 머리 주석 두 줄이 고쳐졌다.

### 권장 (1건)

1. **규약 「기계가 묻는 것」의 배선 주장이 사실보다 넓었다** — `docs/conventions.md` 「안전 바닥」 항목은 「러너가 이름을 선언에서 읽는가(배선)를 묻는다」고 적었다.
   그러나 배선 통제는 칸 판정(`N45` — `fl_class` · `FlClass`)과 순서 판정(`N40` — 합성 규약)뿐이다.
   - 반증 패스의 실측(sh 사본): `fl_def_bad` · `fl_name_dup`이 박아 둔 이름 목록을 읽게 고쳐도 Part N이 **45/0 초록**이다. 그러면 `N36` · `N37`이 공허해진다.
   - README 검증 블록은 「`N45` 배선(… 칸 출력이 따라 바뀐다)」로 정확히 적고 있다.
   - **등급**: 판례 부류 `vacuous-pass`(규약이 집행력을 사실보다 넓게 주장)에 해당한다. 그러나 트리거는 **러너 소스에 이름을 박는 자기 검사 코드의 편집**이다 —
     `reachability-weighting`의 「자기 훼손으로만 도달」이라 `권장`이다. 그 편집은 완료 기준 3이 금지하고 diff에 드러난다. 해로운 상태 대부분은
     선언을 읽는 `N38` · `N41`이 여전히 붉힌다.
   - **경계 기록**: 이름 유일성(`N36`) · 정의 대조(`N37` · `N38`)는 러너가 선언을 읽는다는 것을 기계로 확인하지 않는다. 러너 소스에 이름 리터럴이 생기는 편집은
     diff와 리뷰가 본다. 이 경계를 규약 문장에 적었다(아래 수정 내용).

### 사소 (5건)

2. **규약 ⒝와 README ⒝가 어긋났다** — README는 「바닥 선언들과 정의 항목, `autonomy-lines:` · `floor-marks:`」인데, 규약 ⒝는 라운드 1에서 `autonomy-lines:`가 빠졌다.
   안전 측(집행을 덜 주장)이지만 두 문서를 맞춘다.
3. **`run.ps1` `FloorMarks` 머리 주석이 넓다** — 「the floor name checks read fixtures through it」라고 적었다. 그러나 `FloorMarks`에 파일을 넘기는 호출자는 픽스처가 아니다
   (`FlMarkMissing` · `FlMarkExtra`가 받은 인자를 그대로 넘길 뿐이고 표지 픽스처는 없다). sh 쪽 주석은 정확하다.
4. **impl 보고서 기준 8의 근거 명령이 재현되지 않는다** — `LC_ALL=C grep -c '[\200-\377]'`를 Git Bash에서 그대로 돌리면 5332가 나온다. 작은따옴표 안 8진이
   펼쳐지지 않아 숫자 · 역슬래시와 맞기 때문이다. 주장(비-ASCII 0)은 참이다(`printf`로 펼친 명령 → 0 · `F5` 초록).
5. **impl 보고서가 잰 적 없는 방향 셋을 「충족」 칸에 기대고 있었다**
   - 정의 복제: 보고서가 「재지 않았다」로 둔 방향이다.
   - `N34`의 대응 쪽 절반: 대응 꼬리를 비우는 방향이다.
   - 규약이 새로 적은 「대응 → 표지 없음 이동은 초록」: 드라이버에 행은 있었지만 보고서에 값이 없었다.
   - 셋 다 주장은 참이었다. 리뷰와 반증 패스가 각각 쟀다 — 정의 복제 `N37`만, 대응 비움 `N34`;`N41`;`N43`, 이동은 초록.
6. **`docs/epics/E2.md` 331행 「그 목록을 규약이 열거한다」가 현재형이다** — 기준 7의 패턴(「규약이 열거」)이 잡지 못한 형태다. 다만 그 문단은 M52 계획의
   역사 서술(「`skills/` 변경 0이다. 안전 바닥은 …」)이라 고치지 않는다 — 에픽 본문의 과거 계획을 소급해 바꾸지 않는다.

## 수정 내용

- **이슈 1**: `docs/conventions.md` 「기계가 묻는 것」의 배선 구절을 「칸 판정과 순서 판정이 이름을 선언에서 읽는가(배선 — 칸 출력과 합성 규약의 순서 위반으로
  잰다)」로 좁혔다. 이어 「나머지 판정(이름 유일성 · 정의 대조)에는 따로 배선 통제가 없다 — 러너 소스에 이름을 박는 편집은 기계가 아니라 diff와 리뷰가 본다」를 더했다.
- **이슈 2**: 규약 ⒝에 `autonomy-lines:`를 넣어 README ⒝와 맞췄다.
- **이슈 3**: `tests/discover/run.ps1` `FloorMarks` 머리 주석을 「Accepts an optional conventions file (… empty means $CONV)」로 고쳤다(ASCII).
- **이슈 4 · 5**: `docs/reports/M78-impl.md`에서 고친 것:
  - 기준 8의 명령을 재현 가능한 형태(`"$(printf '[\200-\377]')"`)로 바꿨다.
  - 되돌림 표에 `n37-defdup` · `n34-mapempty` 두 행을 더했고, 리뷰가 잰 값이다.
  - 표 밖 행에 `open-map-to-unmarked`(초록)를 더했다.
  - 기준 4 칸의 「복제는 행을 따로 두지 않았다」를 새 행으로 바꿨다.
  - 더한 행과 값마다 「리뷰 라운드 1이 잼」을 적어 impl의 측정과 구분했다.
- 이슈 6은 고치지 않았다(위 사유).

  - 반증 패스가 셋을 다시 돌려 같은 값을 얻었다 — 기준 1 동그라미 다섯 줄, 기준 3 여덟 이름 0/0 · `publish` HEAD와 같은 수, 기준 7 80개 파일 · 고유 히트 열 줄.
  - 기준 7의 범위에는 빠짐이 하나 있다 — 위 이슈 6의 「규약이 열거」 형태다(`scope-exhaustive`). 처분은 역사 서술이라 고치지 않는 것이다. 그래서 기준 7은
    「현재형 재서술 0」이 아니라 「패턴에 걸린 것은 처분했다」로 읽는다.
- **불가 주장 대조**(`infeasible-evidenced`) — impl 표 밖 행 `adv-remove-all`의 「닫을 수 없다」는 세 요소(형태 · 까닭 · 반례 탐색 — 라운드 1에서 여섯으로 늘었다)를
