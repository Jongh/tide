# M11 리뷰보고서 (review)

> `/tide:cycle`의 review 단계로 수행. 대상은 방금 impl을 마친 M11. impl은 T01을 메인에서
> (네트워크·판단), T02·T03·T04를 **3개 서브에이전트로 병렬 디스패치**해 수행 — M9 병렬
> 메커니즘의 2회째 런타임 사용(이번엔 T03이 폴백 규약 자체를 개선).

## 비판점

### 차단 (0건)

없음. 완료 기준 충족 — T01 게시 확인 + **배포 고착 결함 적발·근본 수정**, T02 ps1 한국어
출력 런타임 실증, T03 폴백 워크스루+규약 보강, T04 release 배선(규약↔실행 일치). 도그푸딩
라운드가 목적(숨은 부채를 실제로 드러냄)을 정확히 달성했다.

### 권장 (1건)

1. **배포 트리거 `paths` 허용목록은 단일 원본 인클루드에 대해 구조적으로 취약** — 이번
   수정은 현재 단일 원본화된 루트 파일 2개(`CHANGELOG.md`·`docs/conventions.md`)를 paths에
   추가했다. 옳은 즉효 수정이나, **앞으로 사이트가 더 많은 루트 파일을 snippets로 인클루드하면
   paths 목록이 또 조용히 낡아** 같은 종류의 고착이 재발한다(이번 결함과 동일 클래스).
   더 견고한 대안: ① `paths` 필터를 제거하고 `main` 푸시마다 빌드(사이트가 가벼워 비용
   낮음), 또는 ② "사이트가 인클루드하는 루트 파일을 새로 만들면 반드시 paths에 추가"를
   `docs/conventions.md`·워크플로우 주석에 규칙으로 박기. 차단은 아니며(현 결함은 해소됨)
   차기 후보로 권장.

### 사소 (3건 — 수용)

2. **라이브 재교정은 release 후로 미완**(impl 후속 #1) — 현재 라이브는 아직 v0.9.0 고착
   상태. 배포 path 수정 + M11 릴리즈(CHANGELOG 변경)로 재트리거되면 v0.11.0·porpoise 0으로
   갱신된다(현재 main 빌드 산출물로 입증). release 후 라이브 재확인이 T01의 마지막 1마일 —
   수용(자기 치유 경로 존재).
3. **클라이언트 런타임·폴백 종단 실행 미실증**(impl 후속 #2·#3) — Mermaid·검색·다크모드는
   정적 fetch 한계로 미확인, 병렬 폴백은 워크스루+보강이지 실제 분기 실행 실증은 아니다.
   둘 다 저위험·자연 발생 시 사후 실증으로 수용.
4. **`site_url` 대소문자 불일치**(impl 후속 #4) — `mkdocs.yml`은 `Jongh`, 라이브는 소문자
   `jongh`가 200. GitHub 정규화로 동작 무문제, 정확성용 소문자 정렬은 선택적 후속으로 수용.

## 수정 내용

- **T01 배포 결함(impl 중 수정)**: `deploy-pages.yml` 트리거 `paths`에 단일 원본 인클루드
  대상 `CHANGELOG.md`·`docs/conventions.md`를 추가(주석으로 이유 명시). 리뷰에서 완전성
  확인 — 사이트가 외부 인클루드하는 루트 파일은 이 둘뿐(나머지 site 페이지는 자족적)이라
  현 시점 누락 없음.
- 그 외 리뷰 중 추가 결함 없음. T03 보강(impl/SKILL.md)이 기존 메커니즘과 모순 없고
  명확화에 한정됨을 확인. T04 배선이 conventions 규약과 정합함을 확인.

## 검증

- **완료 기준 대조**:
  ① Pages: 라이브 HTTP 200 + 홈·규약 정상 렌더·인클루드·porpoise 0(실증). 변경 이력 고착은
     결함으로 적발·수정, 라이브 재교정만 release 후로 보류(명확히 기록).
  ② ps1: PowerShell 5.1에서 한국어 차단 메시지 무깨짐·exit 2·비-git exit 0·BOM 확인(실증).
  ③ 병렬 폴백: 겹침→순차·부분 실패→보존+1회 재시도→중단 워크스루 확인 + 규약 모호함 2건
     보강(실증·보강).
  ④ release 배선: 프리플라이트 4번(사이트 조건부 빌드 출력 검증) 추가, conventions 정합(실증).
  ⑤ 매니페스트 무수정, strict 빌드 exit 0, 보고서에 실증/대기/수정 상태 정직 기록(실증).
- **부수효과 분리**: impl(서브에이전트 3개 포함)·review 통틀어 git 없음. 서브에이전트
  phase=impl → 가드가 git 차단(T02가 그 동작을 직접 실증한 것이기도 함).
- **병렬 디스패치 건전성**: T02·T03·T04 비중첩 동시 디스패치, 폴백 없음, 벽시계 ≈ 최댓값.
  특히 **T03이 자기가 검증하던 폴백 규약을 보강**한 메타적 사례 — 디스패치 계약이 분석형
  태스크에도 작동.
- **배포 수정 완전성**: 현 단일 원본 루트 파일 2개를 모두 커버. 미래 확장 취약성은 권장1로
  분리.
