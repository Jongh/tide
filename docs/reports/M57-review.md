# M57 리뷰보고서 (review)

## 비판점

### 차단 (0건)

없다. 아래 넷은 **전부 차단 아래로 매겼고**, 그중 셋에 대해 「다음 단계」에 부인 기록을 남겼다.

**차단이 아니라고 본 근거를 먼저 적는다** — 이 사이클이 만든 새 게이트(CI 산출물 스캔)는 **실제 빌드
산출물에 누수를 심어 배포가 막히는 것까지 실측**됐고(impl 보고서의 3단계 표), 워크플로가 GitHub에서
파싱되는 것도 확인됐다. 하니스는 네 실행 환경 28칸 FAIL 0이고 되돌림 17행이 양 사본에서 같은 판정을
낸다. **집행이 없는데 있다고 적힌 자리**는 이 리뷰가 찾은 범위에서 남아 있지 않다.

### 권장 (1건 — in-review 수정 완료)

1. **`-eq` 표면 실측치가 최종 트리에서 재현되지 않았다 — 완료 기준 6의 「충족」이 성립하지 않았다**
   impl 보고서가 적은 규칙(«`tests/*/run.ps1` 일곱과 `hooks/tide-guard.ps1`의 **주석이 아닌 줄**에 있는
   `-eq` **출현 하나하나**»)을 최종 워킹트리에 그대로 적용하면 **186**이 나오는데, 보고서·규약·
   `tests/discover/README.md` 셋이 **183**을 적고 있었다.
   - 어긋난 칸은 하나다 — `tests/site-includes/run.ps1`이 표에서 **11**(⒜5·⒝0·⒞6), 실측 **14**
     (⒜7·⒝0·⒞7). 차이 **3**은 이 사이클이 **나중에 더한 `wf-yaml` 블록**의 `-eq`다. 측정이 그 블록
     **이전**에 이뤄졌는데 보고서는 *"이 사이클의 최종 트리 기준"* 이라고 적었다.
   - **완료 기준 6의 문면이 「같은 방법으로 다시 재면 같은 수가 나온다」**이므로 그 「충족」이 사실이
     아니었다. 그리고 이것은 impl 스스로 「이 사이클이 스스로 연 결함」 3번으로 적은 것
     (*"`tests/discover/README.md`가 재현되지 않는 수 204를 적고 있었다"*)과 **동형의 결함을 같은
     편집에서 재도입**한 것이다.
   - **도달 가능성**: 가설이 아니라 현재 트리에서 이미 성립했다. 게다가 이 값은 사이클 중 변하는
     수라 케이스를 하나만 더해도 다시 어긋난다.

### 사소 (3건 — 2건 in-review 수정, 1건 반환)

2. **신설 `tests/lib/excluded-terms.sh`가 공백 든 레포 경로에서 도출 0건이 됐다(in-review 수정)**
   `excluded_terms()`·`excluded_masthead()`가 `for _et_src in $(_exterm_sources "$1")`로 명령 치환을
   **인용 없이 기본 IFS로 단어 분할**했다. 이 사이클이 지운 `tests/site-includes/run.sh`의 옛 구현은
   경로를 인용해 두어 **공백 안전**이었으므로 **라이브러리로 모으면서 생긴 회귀**다.
   - 실측: `README.md`·`docs/conventions.md`만 `/tmp/tide space test/`에 복사하고
     `excluded_terms "/tmp/tide space test"` → **빈 출력**(같은 트리의 무공백 경로는 `porpoise`).
   - 여파: `TERMS`가 비면 본문 스캔 `for term in $TERMS`가 **0회** 돌아 용어 케이스가 전부 공허하게
     0이 된다. 다만 마스트헤드 positive-control이 붉어 하니스는 **fail-loud**이고, CI 쪽은 도출 0건을
     명시적으로 실패로 받으므로 **`vacuous-pass`까지 가지 않는다** — 그래서 사소다.
   - **도달 가능성은 높다.** 이 저장소는 *"레포 경로에 공백이 하나 있으면 sh 쪽 검사가 절대 실패할 수
     없었다"* 를 **도달 가능한 트리거의 실례로 이미 등록**해 두었다(M42 실측).

3. **배선 검사가 「참조 줄은 남기고 검출 루프만 주석 처리」를 물지 못한다(in-review 고지, 집행은 반환)**
   `ci-scan` 여섯의 판정은 «`tests/lib/excluded-terms.sh`를 참조하는 비-주석 줄이
   `upload-pages-artifact`보다 앞인가»뿐이다. 실측: 워크플로의 `rc=0` 이후 검출 루프와 `exit $rc`만
   주석 처리하고 참조 줄을 남기면 **`tests/site-includes` 45/0 초록**이다. 그 상태의 스텝은 용어를
   도출해 개수만 찍고 `rc=0`으로 끝나므로 **누수가 그대로 배포된다**.
   - **과대주장은 아니다** — README와 규약이 둘 다 *"무는 것은 **배선**"* 으로 범위를 좁혀 적는다.
     그래서 부류로는 성립하되 등급은 사소이고, **빠진 것은 경계의 고지**였다. 형제 절 둘
     (블록 스칼라 무결성 · Part Q)은 「묻지 않는 것」을 갖는데 이 절만 없었다.
   - 적대 축 `adv-scan-commented`가 닫은 것은 **참조 줄 자체**를 주석 처리한 형태 하나이고, 바로 옆
     형태가 열린 채다.

4. **완료 기준 13에 방전 주체가 없다 — `Deploy docs site` 런을 확인하는 절차가 어디에도 없다(반환)**
   판정 근거가 «13은 release의 일이다»인데 **release 절차가 그것을 하지 않는다.**
   - `.github/workflows/deploy-pages.yml`은 `on: push: branches: [main]`뿐이라 **릴리즈 PR의 체크에
     나타나지 않는다**. 반면 `docs/conventions-release.md`의 "PR CI 확인" 항목은 머지된 PR의 체크를
     **보고**할 뿐이고 스스로 *"게이트가 아니다"* 라고 적는다. 즉 이 사이클이 새로 세운 게이트 ④가
     GitHub에서 **적재·완주하는지를 아무 단계도 자기 완료 조건으로 갖지 않는다.**
   - `.github/workflows/tests.yml`의 머리말이 같은 축을 이미 적어 두었다 —
     *"Local YAML validity is not GitHub workflow validity; only a real push proves this file."*
     그리고 **이 사이클 자신이 파싱되지 않는 워크플로를 한 번 트리에 넣었고**, `wf-yaml`은 스스로
     *"파서가 아니라 프록시"* 라고 고지한다. 남은 층이 실재한다.
   - **고치지 않은 이유**: 릴리즈 절차에 완료 조건을 더하는 것은 **집행 추가**라 리뷰의 자리가 아니다
     (규약의 수정 권한 제한). 대신 **이번 릴리즈의 핸드오프로 명시**하고 다음 사이클에 반환한다.

## 수정 내용

- **이슈 1**: 값을 **최종 트리 기준으로 정정**하고(총 **186** = ⒜ **75** · ⒝ **30** · ⒞ **81**, 헬퍼
  표면 **74**) **선언처를 하나로 모았다**. `docs/reports/M57-impl.md`의 "-eq 표면 실측" 절이 규칙과

  그 자리를 가리킨다**. 정정 자체보다 **셋에 박아 둔 구조**가 원인이므로 구조를 고쳤다 —
  `CLAUDE.md`의 *"사이클 중 변하는 수는 문서에 박지 말고 선언처를 가리킨다"* 와 같은 처방이다.
  impl 대조표의 6번 근거 칸에 **처음 값이 왜 어긋났는지**를 남겨 이력이 지워지지 않게 했다.
- **이슈 2**: `tests/lib/excluded-terms.sh`의 두 함수가 소스 목록을 **개행으로만** 분할하도록 고쳤다

  구현을 라이브러리로 모으면서 잃었다는 것 — 을 그 자리 주석에 남겼다.
- **이슈 3**: `tests/site-includes/README.md`의 CI 배선 절에 **「묻지 않는 것(정직 고지)」**을 세웠다.
  실측(45/0 초록)과 **왜 지금 닫지 않는지**(집행 추가는 리뷰의 자리가 아니다), 그리고 반환처를 적었다.
- **이슈 4**: 고치지 않았다 — 「다음 단계」의 반환 항목과 릴리즈 핸드오프로 넘겼다.

**미검증 잔여 리스크 (2건 — 둘 다 push 이후에만 관측된다)**

1. **`Deploy docs site` 워크플로가 GitHub에서 실제로 적재·완주하는지**는 확인하지 못했다. 로컬에서
   확인한 것은 ⑴ YAML 파서가 파일을 읽고 스텝 순서가 스캔 → 업로드라는 것 ⑵ 스텝 본문을 Ubuntu의
   `sh` 방언(`dash`)으로 그대로 돌려 완주한다는 것 ⑶ 실제 빌드 산출물에 누수를 심으면 `rc=1`과 누수
   경로가 나온다는 것이다. **워크플로 문법의 GitHub 판정은 그 셋으로 대신할 수 없다** —

2. **이번에 세운 `sh` 코드가 BSD 도구에서 도는지** 확인하지 못했다. `tests.yml`의 `posix` 잡은
   **ubuntu·macOS·windows** 세 다리이고, 신설 `tests/lib/excluded-terms.sh`와 `wf-yaml` 블록은 이
   기계의 GNU 도구(Git Bash)에서만 돌았다. 후속 확인은 릴리즈 후 `tests` 워크플로의 macOS 다리다.

    없다는 점에서 부류에 닿는다. 다만 **④는 실재하고 로컬에서 완주가 확인됐으며**, 남은 것은 «GitHub이
    이 워크플로를 어떻게 판정하는가»라는 **impl·review 어느 단계도 관측할 수 없는 층**이다. 판정을
    막는 대신 **릴리즈 핸드오프와 반환 항목으로 방전**했다.
