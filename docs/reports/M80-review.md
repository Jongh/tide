# M80 리뷰보고서 (review)

## 비판점

### 차단 (0건)

- 차단 등급으로 매긴 이슈는 없다. 다시 쓴 문장 넷의 사실 · 토큰 · 링크 · 숫자 · 제목은 HEAD와 같고(보존 대조 · 반증 패스의 독립 대조), 하니스가 무는 자리는 그대로 문다.

### 권장 (4건)

1. **impl 보고서가 네 파일을 읽는 하니스 자리를 넷(`B1` · `C3` · `C4` · `F2`)으로만 적었다** — T01 ⑶은 「`tests/discover/run.sh`를 읽어 확정」이라고 적었는데,
   파일 전체를 훑는 판정(Part G `living_docs` · Part L · `tests/site-includes`)이 빠졌다. 열거가 빠짐없는가(`scope-exhaustive`)를 리뷰가 다시 훑어 셋을 더 찾았다.
   그 과정에서 `index.md`에 새로 들어간 수 낱말 「아래 네 가지입니다」를 Part L이 묻지 않는다는 것도 쟀다(「다섯 가지」로 바꿔도 sh Part L 13/0 — 파일은 백업으로 되돌리고 `cmp`로 확인).
2. **`getting-started.md` 「단축 경로」에 새로 넣은 목적 문장이 사실과 맞지 않았다** — 「사이클을 단계별로 호출하지 않을 때 쓰는 커맨드는 아래와 같습니다」는 넷 중 `/tide:cycle`에만 맞는다
   (`/tide:status`는 언제든 · `/tide:retro`는 사이클이 쌓인 뒤 · `/tide:debug`는 사이클 밖). 마일스톤이 금지한 사실 추가이고, 보존 대조는 토큰만 보아 이 문장을 잡지 못한다.
3. **되돌림 표의 목록 줄(`B1 C3 C4 F2`)이 규약 정의 밖인데 그 사실이 적혀 있지 않았다** — 규약 "되돌림 표의 선언 형식 (기계가 읽는다)" 절은 목록 줄을 「새로 세운 본 검사」의 자리로
   정의하고, 비우면 침묵 판정이 붉다. 새 케이스 없는 사이클이 따를 형태가 규약에 없다. impl의 선택(기존 본 검사를 고친 문장에 대고 되돌림)은 실측으로 뜻이 있다.
4. **`CLAUDE.md`의 어투 항목이 규약 「진입점 문서」 항목의 「담는 것」 밖이다** — 어투는 「모르면 조용히 깨지는 이 저장소 고유의 자리」라기보다 문체 방향이고, 기준표는 마일스톤 문서(사이클 이력)에 있다.
   커밋 메시지 어투는 release 스킬의 커밋 형식에 속하는데 기준 7이 `skills/` 변경을 막아 이 자리로 왔다. 상한(40줄)을 지키려고 줄 하나를 합쳤다(내용 손실 없음 · 141자).
   **사용자 요청으로 더한 항목이라 고치지 않고 경계를 기록한다** — 자리 옮기기는 `docs/epics/E2.md` 「M80 계획 중 드러난 것」 소절의 「어투 항목의 자리」가 받는다.

### 사소 (7건)

5. **`index.md`의 새 수 낱말 「아래 네 가지입니다」** — 이슈 1이 잰 대로 묻는 기계가 없는 새 재서술이다(`rf-81` 부류). 지웠다.
6. **하드 규칙의 「절대」가 README · `index.md`에서 빠졌다** — 기준표는 「규칙은 그대로 단정한다」인데 「`impl`·`review`는 절대 git 작업을 하지 않고」가 「…는 git 작업을 하지 않고」가 됐다. 되살렸다.
7. **`index.md`의 「오직」이 빠지고 「~도록 되어 있습니다」로 약해졌다** — 「git commit/tag/push는 오직 `release`에서만 일어납니다」로 되돌렸다(README · `concepts.md`와 같은 표현).
8. **`index.md`의 가능 서술이 자동 적용으로, 없던 읽기 순서가 새로** — 「그대로 적용할 수 있습니다」가 「그대로 적용됩니다」가 됐고, 「처음 쓰시는 경우 아래 순서로 읽으시면 됩니다」가 원문에 없던 순서를 주장했다. 둘 다 고쳤다.
9. **impl 보고서가 새로 넣은 굵게를 「남긴 굵게」로 적었다** — README 「오직 `release`에서만」과 `index.md` 「상태 파일이 아직 없는 구간…」은 HEAD에서 굵게가 아니었다. 「새로 넣었다」로 고쳐 적었다.
10. **마일스톤 파일 변경 요약에 `docs/epics/E2.md`가 없었다** — impl 보고서는 적었다. 마일스톤 표에 더했다(릴리즈 커버리지 체크의 역방향 대조가 읽는 자리다).
11. **기준 2는 「부분」이다** — 남은 줄표 둘이 제목 줄 「### 수동 복사 (비권장 — 가드 hook 미포함)」(README · `getting-started.md`)에 있고, 기준 1이 제목을 고정한다.
    두 기준이 같은 자리를 다르게 요구한 마일스톤 작성의 충돌이다. 고치지 않고 받아들인다 — 제목을 바꾸려면 사이트 앵커를 가리키는 링크부터 훑어야 하며 impl 후속 1이 받는다.

이 밖에 `getting-started.md` 워크스루 5번의 「CHANGELOG/README 갱신」(release는 README를 고치지 않는다)은 이 사이클 **이전부터** 있던 부정확함이라 비판점에 넣지 않고 impl 후속 6으로 둔다.

sh 전수는 규약 `measure-axis:`대로 CI가 판정한다(릴리즈 PR 체크). 되돌림 네 행은 다시 재지 않았다 — 리뷰 수정은 되돌림 행의 앵커 문장(README 「총 12종」 · stable 명단 줄 · `verification-only` · `concepts.md` 명단 줄)을 건드리지 않았다.

**검증 범위 선언**(`scope-declared`)

- **하니스 읽기 자리 훑기(이슈 1)**
  - 패턴: `site/docs|README\.md|\$README|SITE_GS|CONCEPTS|INDEX`(주석 줄 · `tests/*/README` · `cases:` 줄 제외)
  - 대상: `tests/discover/run.sh` · `tests/site-includes/run.sh`
  - 대조 항목: 「네 파일을 입력으로 읽는 판정」
  - 루트: 저장소
  - 결과: `B1` · `C3` · `C4` · `F2` · Part G(`living_docs`) · Part L(같은 목록) · `tests/site-includes`(`site/docs/*.md` 전부 · README)
  - `run.ps1` 사본은 두 사본 계약(F1)으로 같은 판정을 가지므로 따로 훑지 않았다. 이것은 「일부를 보았다」에 해당한다.
- **의미 변화 읽기(이슈 2 · 6~8)**
  - 대상: `git diff --word-diff=plain`의 네 파일
  - 대조 항목: 「조건 · 범위(만 · 항상 · ~면) · 가능/의무 · 버전과 커맨드의 짝 · 하드 규칙의 단정이 바뀌었는가」
  - 리뷰와 반증 패스가 각각 읽었다.
- **새 수 낱말 훑기(이슈 5)**
  - 패턴: `(한|두|세|네|다섯|여섯) ?(가지|개|곳|줄|단계)|[0-9]+ ?(가지|개|곳)|둘|셋|넷`
  - 대상: 네 파일 diff의 더한 줄
  - 대조 항목: 「원문에 없던 수 선언」
  - 결과: 「아래 네 가지입니다」 하나. 「두 단계는」은 바로 앞의 `impl`·`review`를 가리켜 둔다.

**기대는 주장 대조**(`lean-branches-stated`)

- impl 보고서의 「되돌림 행을 다시 재지 않아도 된다」(이 보고서의 주장)는 리뷰 수정이 앵커 문장을 건드리지 않았다는 사실에 기댄다.
- 갈래는 넷(행마다 앵커)이고, 넷 다 리뷰 수정 diff에 없다.
