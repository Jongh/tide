# M14 리뷰보고서 (review)

## 비판점

리뷰 결과 **차단 0건**. M14 네 태스크는 완료 기준을 충족하고 라이브 하니스가 양 셸에서
재현된다. 리뷰 중 발견한 파생 문서 정합 갭 1건은 **리뷰에서 직접 수정**했다.

### 차단 (0건)

없음. 오케스트레이션 1층(읽기 전용 fleet)·규약/로드맵·project-context 드리프트 차단이
모두 가산이고, 부수효과 분리 불변(cross-repo git 비자동화)이 규약·스킬에 명문화됐으며,
단일 레포 동작·커맨드 8종 안정 계약을 깨지 않는다.

### 권장 (1건 — 리뷰에서 수정 완료)

1. **파생 문서의 커맨드 수 미동기화** — T02가 `conventions.md`에 `/tide:fleet`을 올바르게
   등록(8종 stable + fleet 가산)했으나, T03이 9번째 커맨드를 추가하면서 **파생 표면이 미갱신**으로
   남았다: `docs/project-context.md`의 스킬 인벤토리("스킬 8종" + 8개 목록)와 `README.md`의 "8종"
   카운트 3곳(설치·구조·자동완성) + 커맨드 표에 fleet 행 부재 + 1.0 안정성 절에 fleet 미언급.
   "규약↔실행/인프라 동기화" 메타 규칙상 신규 커맨드의 사용자 표면은 **같은 사이클에** 손봐야
   한다. → **리뷰에서 수정**(아래 "수정 내용").

### 사소 (3건)

2. **테스트 참조 구현 이중성** (M14-impl#1) — fleet은 프롬프트 스킬이라 실행 바이너리가 없어,
   T04 하니스가 발견·분류 로직을 러너에 **재구현**해 규약의 결정적 동작을 회귀로 고정한다. 스킬
   프롬프트(단일 원본)와 하니스(참조)가 같은 규칙을 각자 표현하므로 규약 변경 시 양쪽 동기화가
   필요하다. 프롬프트 스킬을 스크립트로 덮는 유일한 현실적 방법이고 README가 이 한계를 명시하므로
   **수용**(M13의 "가드는 실제 .sh 실증, fleet은 참조 실증"이라는 차이를 정직하게 기록).
3. **fleet 세션 레벨 실동작 미실증** (M14-impl#2) — 발견·분류·강등은 스크립트로 덮었으나 실제
   `/tide:fleet` 호출의 출력 형식·advisory 서술·읽기 전용 준수는 수동 확인 영역(README 절차).
   멀티 레포 실투입 전 상위 폴더 단일 세션에서 1회 확인 권장(비차단 — M13 앵커링 수동 절차와 동일
   성격, 그때도 릴리즈 후 in-session에 닫았다).
4. **하니스 픽스처 단자리 마일스톤만** (M14-impl#3) — 참조 분류 픽스처가 M1뿐이라 `sort -V`/
   `Sort-Object Name`으로 충분. 실제 M10+ 다중 자리 정렬은 fleet이 status 규칙을 그대로 따르므로
   동일하나 하니스는 단자리만 덮는다. 저위험, 후속 시 픽스처 보강 가능.

## 수정 내용

- **이슈 1 (파생 문서 동기화)** — `conventions.md`의 framing("v1.0 stable 8종 + fleet v1.2.0 가산")에
  정합되게 사용자 표면을 갱신:
  - `README.md`: 커맨드 표에 `/tide:fleet` 행 추가, 사이클 다이어그램에 fleet(읽기 전용) 한 줄,
    "8종" 카운트 3곳 → "9종"(설치·구조·자동완성), 1.0 안정성 절에 "위 8종은 안정 그대로 +
    `/tide:fleet`은 v1.2.0 가산" 노트 추가(stable-8 claim 보존).
  - `docs/project-context.md`: 스킬 인벤토리를 "스킬 9종 — {…,fleet}"로 갱신(fleet=읽기 전용 멀티
    레포 개요 표기).
  - 역사 문서(과거 마일스톤·보고서의 "8종" 언급)와 1.0 안정성 개념의 stable-8 참조(project-context
    :79·README 1.0 절·conventions:251)는 **의도적으로 보존** — "8종"은 v1.0 안정 계약의 동결 집합이고
    fleet은 그 위 가산이므로, stable-8 + 가산 1 = 총 9의 framing이 정확하다(8을 9로 덮어쓰지 않는다).

## 검증

- **라이브 하니스 재실행**: `sh tests/fleet/run.sh` → **PASS=5 / FAIL=0 (exit 0)**,
  `tests\fleet\run.ps1` → **PASS=5 / FAIL=0 (exit 0)**. 회귀: `sh tests/multi-repo/run.sh` → exit 0
  (M13 가드 하니스 무영향). 이슈 1 수정은 문서 전용이라 셸 테스트와 무관(재실행 불필요하나 회귀
  무영향 재확인).
- **검증 시나리오**: 발견 = tide 레포만(비-git `plain`·tide 산출물 없는 git `notide` 제외, 직속 1단계),
  분류 정확(release-ready/review-pending/impl-inprogress), tide 레포 0 → graceful 강등.
- **fleet 등록 3곳 정합**: 사이클 다이어그램(읽기 전용 보조)·"단계별 금지 행위" 표(파일·phase·git
  금지)·"1.0 안정성"(8종 불변 + fleet v1.2.0 가산) — conventions·README 모두 일치 확인.
- **부수효과 분리 불변**: fleet 스킬·규약 모두 "advisory만, cross-repo git 비자동화, release 레포별
  수동"을 명시. fleet은 읽기 전용(파일·phase·git 금지) — status·retro와 동일 강제 문구.
- **제외 용어 누수**: M14가 추가한 텍스트(conventions 오케스트레이션 절·fleet 스킬·README 신규 행·
  project-context 갱신)에 제외 용어(외부 저장소명) literal 없음. 기존 `README.md:3`·`conventions.md:3`
  1건씩은 사이트 인클루드 영역 밖(설계대로)이며 건드리지 않았다. **권위 있는 빌드 출력 스캔은 release
  프리플라이트/CI에서** 수행(현 환경 mkdocs 미설치는 release가 처리).

**검증하지 못한 잔여 리스크**: fleet의 **세션 레벨 실동작**(사소 3)은 스크립트 강제 밖 — README
수동 절차로 다음 단계에 1회 확인 권장. 참조 구현 이중성(사소 2)은 규약 변경 시 양쪽 동기화 부담을
남긴다(저위험).
