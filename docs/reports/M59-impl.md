# M59 완료보고서 — 게시할 수 없는 환경에서 릴리즈가 종료 상태를 갖는다

## 개요

- 마일스톤: `docs/milestones/M59.md`
- epic: `E3` (첫 등재)
- 기반 버전: v2.24.0
- 재작업 라운드(rework): 0
- 태스크: T01~T04 전부 완료. deps 그래프 T01 → {T02, T03} → T04, 순환·미존재 ID 0

`/tide:release`가 원격에 닿지 못하는 환경에서 **실패가 아니라 명명된 성공 종료**로 끝나게 했다.
세운 것은 이름 둘이다 — **`push-availability`**(게시 축에서 갈라낸 push 축)와
**`unpublished-release`**(그 축이 불통과일 때의 종료 상태). 집행은 `tests/discover` **Part S 7케이스**이며
**278 → 292 → 299**로 늘었고 지운 것은 없다.

## 무엇을 왜 이렇게 했는가

**「릴리즈 = 로컬 태그」가 이미 사실이었다.** 프리플라이트가 릴리즈 여부를 가르는 두 자리
(`docs/conventions.md`의 "debug 세션" 절 · 같은 문서의 "릴리즈 커버리지 체크" 절)는 `git tag`·
`git ls-tree`·`git diff`만 쓰고 **원격을 한 번도 보지 않는다.** 그래서 원격 불가 환경에서 실제로
벌어지던 일은 `add → commit → tag`가 **전부 성공한 뒤** push만 실패하는 것이었고, 트리는 정상인데
보고만 실패로 끝났다. 이 사이클이 한 것은 **없는 기능을 만든 것이 아니라 이미 도달하는 종료 상태에
이름과 보고를 준 것**이다.

**축을 가른 근거는 규약 안에 이미 있었다.** 종전 검증 ④는 *"gh가 다룰 GitHub인가"* 를 물으면서
*"push가 되는가"* 를 겸했는데, 같은 절이 실패 사유로 **비-GitHub 호스트(GitLab 등)** 를 열거하고
있었다 — 그 경우 ④는 실패하지만 push는 정상 동작한다. **겸직이 성립하지 않는 반례가 규약 자신의
문면에 적혀 있었다.**

**모드 축을 늘리지 않았다.** `local`을 넷째 모드로 만들면 `.tide/release-mode`에 저장될 수 있고,
그러면 원격이 나중에 생겨도 저장값이 그것을 모른 채 살아남는다(「선언이 사실보다 오래 산다」).
가르는 선을 규약이 적었다 — **모드는 사용자의 *의도*, 게시 가용성은 환경의 *사실*.** 이 저장소는 같은
분리를 이미 한다(`.tide/autonomy`는 파일로 저장하고 `gh` 가용성은 매번 잰다).
`.tide/release-mode`의 값 집합은 **불변**이다.

**B를 미리 재지 않기로 한 것은 정한 것이지 빠뜨린 것이 아니다.** `git ls-remote` 같은 도달성 측정은
오프라인에서 수십 초 매달리고 그 값이 push 시점에도 참이라는 보장이 없다. 게이트는 **A(원격
미설정)만** 즉시·확실하게 재고, **B(닿지 않음)는 push의 결과로** 갈린다. 두 경우가 도달하는 종료
상태는 같고 **보고 문면만 다르다** — 앞은 구조적이고 뒤는 일시적이라 사용자가 취할 행동이 다르기
때문이다. 이 결정과 근거를 규약이 적는다.

**D(git 레포 아님)를 열지 않은 이유도 규약에 남겼다.** 미릴리즈 판정의 *"태그가 하나도 없으면 전부
미릴리즈"* 폴백은 **첫 릴리즈 1회성**으로 수용된 것이지 영구 상태가 아니다. 태그가 영영 없으면 그
폴백이 매 사이클 걸려 커버리지 체크가 **영구히 아무것도 세지 않는다**(`vacuous-pass`). 근거는
「집행이 뜻을 잃는다」이지 「구현이 어렵다」가 아니다.

## 태스크별 결과

### T01 — 규약에 게시 가용성 축을 세우고 게시 불가 종료 상태를 명명

`docs/conventions-release.md`에 넷을 세웠다.

- **검증 게이트 축 분리**: ①~④를 **게시 축**으로 묶고 그 앞에 **push 축**을 세웠다. 선언은
  `` `push-availability:` remote-configured `` 한 줄이다.
- **종료 상태 명명**: `` `terminal-state:` unpublished-release `` 한 줄 + **보고 의무 셋**(일어난 것 ·
  남은 push 두 줄 · **A와 B를 구분한** 사유).
- **「명시 의도 비폴백」 상속**: 새 규칙을 쓰지 않고 **새 축이 기존 순서를 상속**한다고만 적었다 —
  모드를 명시했는데 push 축이 불통과면 `commit`·`tag` **앞에서** 중단한다.
- **D 미지원 경계**: 별도 절(`### 지원하지 않는 것 — git 레포가 아닌 대상`)로 근거와 함께.

`docs/conventions.md`는 조각을 가리키는 자리 한 곳만 정정했다(목록을 두 곳에 적지 않는다).

### T02 — release 스킬 배선

`skills/release/SKILL.md`에서 **push-only를 두 단계로 쪼갰다** — ⑴ `add → commit → tag`(항상 돈다)
⑵ push(push 축 통과 시). ⑴이 끝난 시점이 릴리즈가 성립한 시점이다. `release` 모드는 push가 없으면
릴리즈 객체도 만들지 않고, `pr` 모드는 push 없이 성립하지 않으므로 **모드 해석 단계에서 중단**되어
이 종료 상태로 오지 않는다. 머리말(`description`·`argument-hint`)도 함께 고쳤다.

### T03 — 재서술처 전파

착수 시점에 **다시 실측**했다(계획 시점 15군데는 T01·T02가 문면을 바꾸며 움직였다). 남은 소비자는
`docs/commands.md`와 `tests/multi-repo/README.md` 둘이었고 둘 다 고쳤다. 발견 방법은
`push-only`·`commit→tag→push` 토큰 글롭이며, 수를 문서에 박지 않는다.

`docs/commands.md`에서 **기존 드리프트 하나를 함께 발견했다** — `- **동작**` 줄이
*"`CHANGELOG.md`·`README.md` 갱신"* 이라 적는데 규약과 스킬은 **README를 건드리지 않는다**고
정한다(`docs/conventions.md`의 "버전 · CHANGELOG" 절). 같은 줄을 고치는 김에 `README.md`를
지웠다 — 이 사이클이 만든 것이 아니라 **드러난** 것이다(아래 후속 1).

### T04 — 선언 정합 집행 (Part S, 7케이스)

`tests/discover`에 **Part S**를 세웠다. `run.sh`·`run.ps1` 동형이고 `run.ps1`의 **byte>127 = 0**을
유지했다(실측 0).

| 케이스 | 무는 것 |
|---|---|
| `S1`·`S2` | 두 선언 줄이 **각각 정확히 하나** |
| `S3` | 두 꼬리 **추출 positive-control**(비면 아래가 빈 토큰으로 공허하게 갈린다) |
| `S4`·`S5` | **본 검사** — 종료 상태 이름이 소비자 둘(릴리즈 스킬 · 커맨드 카탈로그)에 실재 |
| `S6` | **배선** — 릴리즈 스킬이 **축 이름**을 가리킨다 |
| `S7` | **픽스처 통제** — 이름이 빠진 사본을 실제 판정이 잡는다 |

**`S6`가 없으면 반쪽이다** — 종료 상태만 물으면 축 이름이 사라져도 초록인데, 축이 그 종료 상태의
**트리거**다(`R5`가 「가리키는가」를 더한 것과 같은 형태).

**`S7`의 빈 토큰 처리를 양 사본에서 맞췄다** — 토큰이 비면 치환이 무동작이 되어 통제가 **공허하게
초록**이 된다. 그래서 빈 토큰이면 사본을 **건드리지 않아 `S7`이 붉게** 두었고, 원인은 `S3`이 지목한다.
`s3-emptytail` 되돌림이 **S3·S7을 함께** 붉히는 것이 그 설계의 실측이다.

### 이 사이클의 편집이 하니스에 잡힌 것 둘

**둘 다 내 편집의 결함이고 하니스가 잡았다.**

1. **`S6`가 처음부터 붉었다** — 검사가 선언 **키**(`push-availability:`)를 물었는데 스킬은
   **병기어**(콜론 없는 `push-availability`)를 들고 있었다. 재서술되는 것은 병기어이므로 **검사 쪽을**
   고쳤다(키의 꼬리 콜론을 벗겨 결합).
2. **`G8b`가 붉었다** — 두 번 각각 다른 원인이다. ⒜ 스킬에 쓴 *"두 **절**이다. ⑴"* 의 낱말 「절」이
   절 표지로 읽혔다 → *"두 **단계**다"* 로. ⒝ `docs/conventions.md`에 넣은 문장이 기존 `⑵` 항목과
   **같은 줄에 붙어** 인용 줄에 열거 번호가 생겼다 → 문장을 `⑶` 항목으로 독립시켰다.

⒝는 CLAUDE.md가 경고한 *"인용은 한 줄 안에 쓴다"* 의 **인접 부류**다 — 인용을 한 줄에 쓰는 것만으로는
부족하고, **그 줄에 다른 열거 번호가 들어오지 않아야** 한다.

## 리뷰가 연 것 둘 (in-review 수정)

**둘 다 impl 시점에는 초록이었고, 실행 환경을 넓히자 드러났다.**

**⑴ `run.sh`가 CRLF로 바뀌어 dash에서 즉시 죽었다(차단).** 이 저장소의 `.gitattributes`는
`*.sh text eol=lf`로 sh 스크립트의 개행을 **못박고 있다**(주석: *"CRLF면 sh 실행이 깨진다"*). 그런데
impl의 편집 스크립트가 Windows 기본 개행 변환을 타 `tests/discover/run.sh`를 **LF → CRLF**로 바꿨고,
dash가 `set: Illegal option -`으로 **0초 만에 exit 2** 했다.

- **bash는 통과시켰다** — 그래서 `run.sh` @ bash에서 299/0이 나왔고 **양 사본 동일**로 읽혔다.
  `run.ps1` 두 환경도 무관하다. **네 환경 중 dash 하나만 이것을 본다.**
- **어떤 케이스도 이것을 묻지 않는다.** Part J는 `$이름` 뒤 다중바이트를 보고, `F1`은 두 사본의
  **총계**를 보며, 공통 통제 대조(Part K)는 토큰의 **존재**를 본다 — **러너 소스 자신의 개행**을 무는
  자리가 없다. 이 저장소가 `run.ps1`의 byte>127을 세는 것과 **대칭인 통제가 sh 쪽에 없다.**
- **고침**: `run.sh`를 LF로 복원하고, **추적되는 `*.sh` 전수**를 훑어 다른 오염이 0건임을 확인했다.
  `.md`·`.ps1`은 `.gitattributes`가 고정하지 않으며 `core.autocrlf=true` 아래 CRLF가 **정상 체크아웃
  상태**라 손대지 않았다(diff가 국소적임을 `git diff --stat`으로 대조 — 전체 재작성 0).
- **남긴 것**: 이 부류를 무는 케이스는 **세우지 않았다**. 후속 5가 그 자리를 적는다.

**⑵ 완료 기준 대조 표가 선언된 판정 값 집합 밖이었다(차단).** 규약이 `` `criteria-verdict:` 충족
미충족 부분 `` 셋을 선언하는데 표가 `충족(문면)`·`부분 — …` 같은 값을 썼고, **표 자체가 4열**
(`번호|기준|판정|근거`)이라 파서가 보는 셋째 칸이 **기준 문장**이었다. `P5`가 **12/12 전부 집합 밖**으로
붉었다.

- **impl 시점에 초록이던 이유는 순서다** — bash·pwsh 실행이 **보고서를 쓰기 전**이었다. 보고서를 쓴 뒤
  처음 돈 것이 dash였고 거기서 드러났다.
- **고침**: 표를 규약이 정한 **3열**(`번호|판정|근거`)로 바꾸고 판정 칸을 선언 집합의 값 하나로 좁혔다.
  한정어(「문면 층까지」 등)는 **근거 칸으로** 옮겼다 — 판정 칸에 두면 집합 밖이 된다.

## 후속

1. **`docs/commands.md`의 `README.md` 갱신 주장을 지웠다** — 규약·스킬은 README를 건드리지 않는데
   카탈로그만 갱신한다고 적고 있었다. 이 사이클이 만든 드리프트가 아니라 **드러난** 것이고, **어떤
   기계도 이 부류를 물지 않는다**(카탈로그의 「동작」 서술 ↔ 스킬 절차의 정합). Part B는 커맨드 수·
   이름·역할 앵커를 물지 **동작 문장**을 묻지 않는다. 세우려면 창을 정의해야 하고 그것은 M58이
   「재서술 대 정당한 언급」에서 걷은 부류와 같은 위험을 갖는다 — **후보로 남긴다.**
2. **행동 층의 픽스처를 세우지 않았다** — 샌드박스 레포에 원격 없는 상태를 만들어 종료 상태를
   실측하는 층은 `tests/multi-repo` 방식으로 가능하다. 세우지 않은 이유는 그 하니스가 **가드 계약**을
   무는 자리이고 이 사이클은 게시 분기 안쪽을 건드렸기 때문이다. **빠뜨린 것이 아니라 정한 것**이며,
   다음 사이클이 이 축을 이어받을지는 리뷰·회고의 판단이다.
3. **보고 문면이 A와 B를 실제로 구분하는지는 무가드다** — 규약은 「구분해 적는다」를 요구하는데 그것을
   정적으로 판정하려면 산문의 의미를 재야 한다. `S4`·`S5`가 무는 것은 **이름의 실재**까지다.
4. **러너 소스 자신의 개행을 무는 자리가 없다** — 리뷰가 연 차단 ⑴이 그 실측이다. `.gitattributes`가
   `*.sh text eol=lf`로 못박은 것을 **어떤 케이스도 확인하지 않으며**, sh 러너가 CRLF가 되면 **dash
   하나만** 죽고 나머지 세 환경은 초록이다. `run.ps1`의 byte>127을 세는 통제와 **대칭인 자리가 sh 쪽에
   비어 있다.** 세우기는 쉬워 보이지만(추적되는 `*.sh`의 `
` 수 == 0) **이 사이클에서 세우지
   않았다** — 리뷰가 연 자리를 그 리뷰가 곧바로 집행까지 세우면 그 집행 자체는 다음 라운드의 검증을
   받지 못한다. **후보로 남기고 근거를 여기 적는다.**
5. **넷째 면(절차의 환경 전제)을 `E3`의 축으로 승격할지 미정이다** — `docs/epics/E3.md`가 *"실례
   하나로 축을 세우면 `E2`에서 축이 흐려진 방식을 반복한다"* 며 실측이 쌓인 뒤로 미뤘다. 재검토
   조건을 적어 두는 것이 원장의 규율이므로, **같은 부류의 자리가 한 건 더 나오면** 승격을 판단한다.
