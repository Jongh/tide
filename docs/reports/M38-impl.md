# M38 완료보고서 (impl)

## 개요

M38의 여섯 태스크를 전부 구현했다 — 러너가 **덜 돌면 스스로 붉어지는** 케이스 수 대조를 하니스
6종에 배선하고(T01), CI가 `run.sh`↔`run.ps1` **짝**을 교차 검사하게 하고(T02), `tests/discover/run.ps1`의
문화권 기반 `StartsWith`를 전부 `Ordinal`로 닫고(T03), Part B의 셸 발산을 **의미 통일**로 해소하고(T04),
`tests/multi-repo`의 기동 맥락 의존을 **진단해 (b) 명시+집행**으로 처분하고(T05), `docs/conventions.md`에
**실행 환경 축**을 이름·두 극·집행처로 선언하며 `tests/discover` **Part H**로 그 선언을 집행했다(T06).
집행력은 코드 대조가 아니라 **레포 밖 사본에서 실제로 돌려** 확인했다 — 6종 각각에서 케이스 하나를
건너뛰게 만들면 양 셸이 **같은 단언에서** FAIL하고, 소프트 하이픈·점 디렉터리 픽스처에서 수정 전
발산과 수정 후 일치를 실측했다.

**재작업 라운드 1에서 닫은 것**: M38 리뷰가 `불가`로 반환한 차단 1건 — 규약이 Part H의 집행 범위를
**사실보다 넓게 주장**한 것(`vacuous-pass`) — 을 **주장 축소와 집행 가산을 함께** 써서 닫았다.
리뷰가 실측으로 반증한 자리(`posix` 잡을 통째로 지우고 표를 그대로 둬도 양 셸 90/0 초록)에
**H6~H9 4케이스**를 넣어 이제 그 조작이 양 셸에서 FAIL하고, 그래도 기계가 묻지 **못하는** 층
(CI 잡이 아닌 집행 칸의 진실성)은 규약·README·러너 주석에 **"묻지 않는다"고 명시**했다. 함께
권장 2·3(확인 지점의 누가·언제)과 사소 4(양 셸 첫 매치/마지막 매치 발산)를 닫았다.

**재작업 라운드 2에서 닫은 것**: 라운드 1의 수정이 **새로 쓴 두 문장**이 같은 부류로 반환됐다 —
⑴ 규약이 `/tide:release`에 없는 확인을 있다고 적은 것 ⑵ 새 CI 잡 가드의 커버리지 경계를 적지 않은
것. ⑴은 **사실로 좁혔다**(그 확인은 사람이 하며 스킬 미배선 — 배선은 M39, 근거는 완료 기준 10의
프리플라이트 동결). ⑵는 **닫고 또 고지했다** — 축 행이 적은 CI 잡의 매핑 등재를 집행하는
**H10·H11**을 더하고, 그래도 남는 층(실재하지 않는 이름을 잡인 것처럼 적은 산문)을 "기계가 묻지
않는 것"에 **세 번째 항목으로 명시**했다.

재작업 라운드(rework): 2

- **M38-T05** — **먼저 진단했다.** 실패 케이스는 시나리오 9의
  `A(impl) blocks commit [BOM input -> cwd, not CPD]` 한 건이고, 원인은 **콘솔 입력 코드페이지**다 —
  BOM 자체도 `$OutputEncoding`도 아니다. 가드는 `[Console]::In`으로 stdin을 읽고 그 디코딩은
  `[Console]::InputEncoding`(= 콘솔 입력 CP)을 따르며, **자식 프로세스는 그것을 띄운 호스트에서
  물려받는다**. 같은 기계 실측:

  | 기동 호스트 | 자식 콘솔 입력 CP | 선두 BOM 3바이트가 되는 것 | 결과 |
  |---|---|---|---|
  | 네이티브 PowerShell/pwsh | **65001**(UTF-8) | 디코더가 **흡수**(가드는 깨끗한 `{`를 본다) | 30/0 |
  | Git Bash | **949**(ANSI) | `EF BB` → **U+7664**(한 글자), `BF` → U+003F | 29/1 |

  가드가 strip하는 형태는 `U+FEFF`와 `U+00EF U+00BB U+00BF` 둘인데 CP949 결과는 **그 어느 것도
  아니라** `ConvertFrom-Json`이 throw하고, `cwd`가 비어 `CLAUDE_PROJECT_DIR`(phase 없음)로 폴백해
  **통과**해 버린다 — 그래서 차단을 기대한 케이스만 뒤집혔다.
  - **처분은 (b) 명시 + 집행**이다. (a)를 택하려면 ⑴ 가드의 BOM strip을 넓히거나 ⑵ 러너가 **공유
    콘솔의 코드페이지를 고쳐 쓰거나** 여야 한다. ⑴은 이 사이클의 불변(**훅 무접촉** — 완료 기준 10)이고
    ⑵는 사용자 터미널에 대한 부수효과이면서 **가드의 실제 취약성을 가린다**(그 자체가 `vacuous-pass`
    방향이다). 그래서 지원 기동 맥락을 `tests/multi-repo/README.md`에 선언하고, 러너가 **첫 단언 전에
    자기 채널을 탐침**해 지원 밖이면 케이스를 하나도 돌리지 않고
    `# UNSUPPORTED LAUNCH CONTEXT …` + 코드페이지 진단을 찍고 **exit 1**한다. 조용히 다른 판정을 내지
    않는다.
  - 탐침은 **행위 기반**이다 — 같은 `Start-Process` stdin 경로로 `EF BB BF` + `{}`를 보내 선두가 가드가
    아는 형태로 도착하는지 본다. `65001`을 하드코딩하지 않은 이유: 오늘 정당하게 초록인 CI 레그를
    코드페이지 숫자로 붉게 만들 수 있다. 탐침 스크립트는 **코드포인트 비교**라 `run.ps1`의 ASCII 전용
    규율(비-ASCII 0바이트)을 지킨다.
  - `run.sh`는 **손대지 않았다** — POSIX 가드는 stdin을 바이트로 읽어 코드페이지 축이 없다.
  - 남은 가드 측 견고성 구멍(비-UTF-8 콘솔 페이지가 뭉갠 BOM)은 고치지 않고 **이월로 기록**했다
    (아래 후속 1).

### 재작업 라운드 1 — M38 리뷰 `불가` 반환분

- **차단 1 (규약이 Part H의 집행 범위를 사실보다 넓게 주장)** — 반환 태스크의 (a)·(b) 중 **둘 다**
  했다. (b)만 하면 새 집행이 닿지 않는 칸에 같은 과대 주장이 남고, (a)만 하면 리뷰가 실측으로 연
  구멍을 문서로 덮는 것이 되기 때문이다.
  - **(b) 집행 가산**: 축 → CI 잡 매핑의 단일 원본으로 규약에
    `<!-- env-axis-ci-jobs: posix-shell=posix powershell-runtime=powershell -->` 선언 줄을 두고,
    `tests/discover` **Part H에 4케이스(H6~H9)** 를 더했다 — **H6** 매핑 추출 positive-control
    (0건이면 FAIL — 루프가 통째로 공허 통과하는 것을 차단) · **H7** 매핑된 잡이
    `.github/workflows/tests.yml`의 **잡 키로 실재** · **H8** 그 잡 이름이 **해당 축의 표 행**에 실재
    (매핑만 고치고 표를 두는 **반대 방향** 드리프트 차단) · **H9** 가짜 잡 이름(`bogus-job`) 부재
    음성 통제. 잡 이름 집합은 워크플로의 `jobs:` 블록에서 **발견**한다(하드코딩 금지) — `on:` 아래의
    `push`·`pull_request`·`workflow_dispatch`가 잡으로 오인되지 않도록 **`jobs:` 블록 안의 2칸
    들여쓰기 키**로 범위를 좁혔고, 양 셸이 같은 규칙을 쓴다(sh는 `awk` 상태 플래그, ps1은 같은 논리의
    루프).
  - **(a) 주장 축소**: 문제의 문장("표가 러너·CI의 실제 구성과 어긋나는 것을 기계가 문다")을 지우고,
    규약에 **"기계가 묻지 않는 것(정직 고지)"** 항목을 새로 뒀다 — CI 잡이 **아닌** 집행처
    (`launch-context`의 러너 자기 탐침 · `workflow-syntax`의 "실제 푸시 뿐" · `external-tool`의
    "미집행")의 진실성은 **사람의 리뷰 영역**임을 명시하고, 그 경계를 뭉뚱그리는 것 자체가
    `vacuous-pass`임을 반증 실측과 함께 적었다. 같은 넓이로 `tests/discover/README.md` Part H 절과
    `tests/discover/run.sh`·`run.ps1`의 Part H 서두 주석을 고쳤다(리뷰가 지적한 "러너·문서와
    어긋나지 않게 문다" / "pins that declaration against the runner/docs" 두 문구가 그 자리다).
  - **케이스 수**: `discover` 90 → **94**(Part H 5 → 9). `tests/discover/README.md`의 `cases:` 선언과
    파트별 내역을 함께 갱신했다 — F1·F1b가 그것을 문다.
  - **두 번째 선언처를 만들지 않았다**: 매핑 선언은 **규약에만** 두고 `tests/discover/README.md`에는
    사본 대신 산문 설명만 뒀다. 축 이름은 두 파일 집합 일치(H3)로 묶여 있지만, 매핑까지 양쪽에 두면
    집합 일치 대조가 하나 더 필요해지고 선언처가 늘어난다.
- **권장 2 (완료 기준 3·9의 확인 지점이 비어 있음)** — 규약 "실행 환경 축" 절에
  **`workflow-syntax` 축의 확인 지점(누가·언제)** 항목을 추가했다: `/tide:release`가 미는
  `release/vX.Y.Z` 브랜치의 **PR CI**가 그 자리이고 릴리즈는 **머지 전에** 확인해 결과를 릴리즈 근거에
  남긴다(v2.11.0에서 실제로 두 번 붉은 뒤 초록이 된 자리다). **짝 없는 하니스로 `pairing`이 실제로

"못 읽어서 통과"하는 경로가 없다.

### T02 검증 상태 (완료 기준 3·9 — **미완**, 릴리즈 전 확인 필요)

- 로컬에서 한 것: 워크플로 **YAML 파싱**(3개 잡 `powershell`·`posix`·`pairing` 생성 · `shell:`에

  `tests/lib`는 미보고).

  이므로 이 두 기준은 **미충족으로 남긴다**. 아래 후속 2가 처분 경로다.
- **확인 지점의 누가·언제(재작업 1에서 채우고 재작업 2에서 정정했다)**: 기준 9가 닫히는 자리는
  `pr` 모드로 릴리즈했을 때 생기는 `release/vX.Y.Z` 브랜치의 PR CI다 — v2.11.0이 그 자리에서 두 번
  붉은 뒤 초록이 됐다(`gh run list` 실측). **그러나 그 확인은 `/tide:release` 절차에 배선돼 있지

  `gh` 없으면 push-only로 강등). 그래서 규약은 이것을 **"사람이 하는 확인 · 미배선"** 으로 적고

## 미해결·후속 메모

1. **가드 측 BOM 견고성(신규 이월, 우선순위 있음)** — `hooks/tide-guard.{ps1,sh}`의 BOM strip은
   `U+FEFF`와 `U+00EF U+00BB U+00BF` 두 형태만 안다. 콘솔 입력 코드페이지가 UTF-8이 아닌 세션
   (예: 한국어 로케일의 CP949)에서는 **선두 BOM이 제3의 형태로 디코드돼 훅 입력 파싱이 throw하고
   가드가 폴백 통과**한다 — T05이 실측한 그 경로다. 이번에 고치지 않은 이유는 완료 기준 10의
   **훅 무접촉** 불변이다. 처분 선택지는 ⑴ strip을 코드페이지 무관하게(바이트 레벨 stdin 읽기)
   넓히거나 ⑵ 실제 Claude Code 세션의 훅 입력 채널이 항상 UTF-8인지 실증해 "발화하지 않는 축"으로
   수용하거나다. `tests/multi-repo`가 지금은 그 맥락을 **거부**하므로 이 구멍이 하니스에 잡히지 않는다는
   점을 함께 봐야 한다(거부는 조용함을 없앴을 뿐 구멍을 닫지 않았다).
2. **T02의 실제 푸시 검증** — 완료 기준 3·9는 로컬에서 충족할 수 없다. 리뷰 또는 릴리즈 단계에서
   ① 현재 브랜치를 밀어 4개 레그 + `pairing` 잡이 **전부 초록**인지 ② 짝 없는 하니스를 둔 브랜치에서
   `pairing`이 **실제로 붉고 이름을 보고**하는지 확인해야 한다. 이 두 확인 전에는 T02를 "배선했다"까지만
   주장할 수 있다.
3. **`external-tool` 축 미집행(M39 이월, 규약에 기록됨)** — `tests/lib/encoding.sh`의 `strip_bom`이
   `sed '1s/^\xEF\xBB\xBF//'`로 GNU sed에 기댄다. 사유 3가지(오늘 발화하지 않음 · 실패해도 조용하지
   않음 · v2.11.0에서 막 고친 경로라 연속 변경 위험)와 함께 규약 표에 **"미집행"으로 적혀 있다**.
   M39가 이것을 집으면 축 행의 집행 칸을 같은 사이클에 갱신해야 한다. 이 축은 CI 잡을 지목하지
   않으므로 **H7·H8의 대상이 아니고**, "미집행"이 사실인지는 사람의 리뷰가 본다(아래 4).
4. **Part H의 집행 경계(고지 — 재작업 1·2에서 두 번 좁혀졌다)** — 이제 기계가 묻는 것은
   다섯이다: 축 이름의 표 행 실재(H2) · 축 이름 집합 일치(H3) · **매핑된 CI 잡의 워크플로
   실재(H7)** · **그 잡 이름의 해당 축 표 행 실재(H8)** · **축 행이 적은 실재 잡의 매핑 등재(H11)**.
   여전히 묻지 **않는** 것은 셋이며 규약의 "기계가 묻지 않는 것"이 단일 원본이다 — ⑴ CI 잡을
   지목하지 않는 집행 칸의 사실성 ⑵ 잡을 지목한 칸의 나머지 서술("2 OS" 등) ⑶ **실재하지 않는
   이름을 잡인 것처럼 적은 산문**(커버리지가 실재 잡 방향으로만 돌기 때문 — 기계는 임의 백틱
   토큰이 잡 지목인지 구별할 수 없다). **M39 후보**: 집행 칸의 참조를 `job:<이름>` 같은 **해소
   가능한 표기**로 강제하면 ⑶까지 닫히고 매핑 선언 줄이 표 안으로 흡수돼 선언처가 하나로 준다.
   비용은 표기 규칙 하나를 더 세우는 것이라 이번 라운드에서는 하지 않았다.
5. **`tests/multi-repo`의 지원 맥락 축소 부작용** — 이제 Git Bash 호스트에서 이 하니스의 `run.ps1`을
   돌릴 수 없다(`run.sh`는 영향 없음). 로컬 개발자가 Git Bash만 쓰는 경우 ps1 사본의 회귀를 직접
   돌릴 수 없으므로 CI의 PowerShell 잡이 그 유일한 집행이 된다 — 지원 맥락을 넓히려면 후속 1의
   ⑴ 경로가 선행이다.
6. **`site-includes`의 완주 플래그 부재(선존, 완화됨)** — 6종 중 이 러너만 `try/finally` + 완주
   플래그가 없다(감쌀 정리 대상이 없어서다). T01의 케이스 수 대조가 "죽지 않고 덜 도는" 경로를
   덮으므로 실질 위험은 줄었지만, **중간에 죽는** 경로는 여전히 `trap` 하나에 의존한다. M38 리뷰가
   사소로 매기고 **이월 유지**로 판단했다.
7. **재작업 라운드 1·2의 dash 레그 미재현(고지)** — 두 라운드의 세션 환경에 dash가 없어
   `run.sh @ dash`를 다시 돌리지 못했다(설치된 WSL 배포판이 busybox 기반 `docker-desktop`뿐이다).
   두 라운드가 `run.sh`에서 바꾼 것은 `awk` 상태 플래그 추출 · `grep -o` 첫 매치 추출 · 커버리지
   `while read`+`case` 루프이고 전부 POSIX 범위이며, 라운드 2 리뷰가 `awk`의 `[ \011:]`를 GNU
   Awk·busybox awk 둘 다 탭으로 해석함을 실측했다(우분투 기본 `mawk`는 미확인). 그래도 **미검증은
   미검증이다.** 확인 지점은 CI `posix` 잡의 ubuntu 레그이며 위 2와 **같은 푸시**에서 함께 닫힌다.
8. **집행 칸의 표기 문법(M39 후보, 위 4의 처분 경로)** — 집행 칸의 참조를 `job:<이름>` 같은 **해소
   가능한 표기**로 강제하면 "실재하지 않는 이름을 잡인 것처럼 적은 산문"까지 기계가 문다. 그때
   `env-axis-ci-jobs:` 선언 줄은 표 행으로 흡수돼 **선언처가 하나 준다**. 이번에 하지 않은 이유는
   표기 규칙을 새로 세우는 변경이고, 라운드 2의 반환분은 **닫을 수 있는 층을 닫고 남는 층을 적는
   것**까지였기 때문이다.
