     초록"이라는 더 나쁜 공허 통과를 새로 만들 수 있기 때문이다. 음성 통제로 양 셸에서 발화 확인.

     않았으므로 규약 `:657-659`가 요구하는 **`precedent-waiver`를 아래 `다음 단계`에 남긴다.**

  결과 줄 직전에 넣고 5.1에서 실행): 여섯 전부 성공 배너 없이 `# ABORTED at line N: …` +
  **exit 1**. 구조가 넷으로 갈리는데(try/finally · 중첩 try + finally · try 없음) 전부 물었다.
  반증 패스가 **독립적으로** 세 러너에 대해 재현했고, 나아가 ⑴ trap 선언 줄 **이전**의 오류
  ⑵ **함수 내부**의 오류 ⑶ **`finally` 블록 안**의 오류까지 전부 exit 1로 잡히는 것을 실측했다.
  러너·공용 lib 전체에 `catch`가 **0개**라 오류를 삼킬 경로가 없다는 것도 확인됐다.

**CI가 실제로 도는지 — 로컬에서 GitHub 조건을 재현**(`$ErrorActionPreference='stop'` 주입 + `&` 호출):
양 런타임에서 `discovered 6: discover, fleet, fleet-cycle, fleet-verify, multi-repo, site-includes`
→ 6종 전부 exit 0 → `all 6 harnesses passed`(잡 exit 0). bash 잡도 6종 발견·전부 통과. **음성 통제
둘 다 발화**한다 — 실패하는 하니스를 넣으면 `FAILED: … (exit 3)` + exit 1, 하니스 0개면
`no run.ps1 harness discovered … refusing to pass` + exit 1. 반증 패스가 GitHub의 실제 래퍼
(`-Command ". 'step.ps1'"` + 끝에 붙는 `exit $LASTEXITCODE`)까지 흉내 내 같은 결과를 얻었고,
YAML 파싱·`shell: powershell`=5.1 · `&` 호출의 `$LASTEXITCODE` 전파도 실측했다.

**미검증 잔여 리스크**

- **CI의 `ubuntu-latest` 레그**: 이 개발 환경에 Linux가 없어 **실측하지 못했다.** 근거는 보강됐다 —
  `.gitattributes`가 `*.sh text eol=lf`를 고정하고(`git ls-files --eol`로 전부 `i/lf` 확인),
  `run.sh` 6종 + `tests/lib/*.sh` + 훅에 **bashism이 0건**이며(`[[`·배열·`local`·`echo -e`·`+=`·
  `<<<`·`source`·`&>` 전무) 쓰는 것은 `sort -V`·`grep -o`뿐이라 dash에서도 문제없다. 그래도
  **실행하지 않았다.** 첫 CI 실행에서 이 레그가 붉으면 환경 조정 사항이지 제품 회귀가 아니다.
- **가드는 *중단*을 잡지 실행 부족을 잡지 않는다**: 6종 중 5종이 `-ErrorAction SilentlyContinue`를
  쓰고, 실행된 케이스 수를 선언값과 대조하는 것은 `discover`의 Part F뿐이다. 직전 리뷰가 준 두
  선택지 중 impl이 `catch`/trap 쪽을 택했으므로 **반환 범위 안**이지만, 나머지 절반은 M38 몫이다.
- **완주 플래그는 발화를 실증하지 못했다**: trap이 먼저 잡기 때문에 플래그만 걸리는 경로를
  **구성할 수 없었다**(반증 패스도 실패했다). 방어적 이중화로는 유효하나, "플래그가 무는 것을
  보였다"고 적지 않는다 — 무는 것은 trap이다.
- **사이트 실제 렌더**: `mkdocs` 로컬 부재로 `--strict` 미실행 — CI 몫이다.
