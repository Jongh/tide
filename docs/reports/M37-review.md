## 비판점

### 차단 (0건)

없다. 릴리즈 시도가 드러낸 **두 결함**(워크플로 미컴파일 · dash 비호환)이 모두 닫혔고, 이번 라운드가

### 권장 (2건 — 둘 다 in-review 수정, 재검증 완료)

1. **릴리즈 델타에 들어간 워크플로 재설계가 어느 문서에도 선언되지 않았다**

   릴리즈 시도는 결함을 **둘** 드러냈는데 이 라운드는 **하나만** 선언하고 닫았다. 첫 푸시에서
   `.github/workflows/tests.yml`이 **컴파일되지 않았다** — GitHub이 `shell: ${{ matrix.shell }}`을
   거부해 **잡이 0개** 생성됐고 실행 기록에는 "workflow file issue"만 남았다. 그 수정(`env: PS_EXE` +
   리터럴 `shell: pwsh` + 하니스를 **자식 프로세스**로 기동)은 커밋 `2ebc99d`으로 트리에 들어갔으나,
   `docs/milestones/M37.md`의 T07에도 `docs/reports/M37-impl.md`에도 없었다. 오히려 impl 보고서
   T07 (d)는 **폐기된 설계**("매 호출 전 절대 경로로 복귀한다")를 계속 서술하고 있었다.

   - **등급 근거 — 판례 부류가 아니다**: 집행은 **실재하고 실측으로 초록**이다(3개 레그 통과, CI 로그
     확인). 문서가 집행력을 **사실보다 넓게 주장**한 것이 아니라 **다른 설계를 서술**하고 있었다.
     `vacuous-pass`는 "결함이 있는데 green"인데 여기서는 결함이 없다. 따라서 `precedent-waiver`가
     필요한 하향이 아니며, 고쳐서 **선언과 집행을 같은 넓이로** 되돌리면 사안이 소멸한다.
   - **수정**: 마일스톤에 **T07 (d-2)**를, impl 보고서에 같은 번호의 항목을 넣어 미컴파일 사실·원인·
     자식 프로세스 설계의 세 가지 이유(ⓐ `multi-repo`의 Git Bash 호스트 실패 ⓑ `fleet-verify`의
     `Set-Location` 누수 ⓒ 주입된 `$ErrorActionPreference`)를 적고, 초안 서술이 대체됐음을 명시했다.

2. **`CHANGELOG.md`의 v2.11.0 노트가 이미 거짓이 된 주장을 **사용자에게** 싣고 있었다**

   "전 하니스를 **세 실행 환경**에서 재실행해 **18회** 전부 FAIL 0 … 남은 미실측은 CI의 ubuntu 레그
   하나이며 **이 릴리즈가 푸시돼야 처음 돈다**" — 세 문장 모두 틀렸다. 워크플로는 이미 두 번 돌았고,
   ubuntu 레그는 이미 돌아 **이 라운드가 고친 결함을 냈으며**, 이 라운드의 실측은 **네 실행 환경 24회**다.
   같은 릴리즈 안에서 impl 보고서는 그 항목을 "닫혔다(부분)"로 적고 있어 **한 릴리즈가 자기와 모순**이었다.

   - **무게**: `CHANGELOG.md`는 `site/docs/changelog.md`가 스니펫으로 인클루드하는 **발행 콘텐츠**다
     (`tests/site-includes`가 그 인클루드를 해석한다). 그리고 **`/tide:release` 재실행은 이미 존재하는
     `### [v2.11.0]` 항목을 다시 쓰지 않는다** — 태그 전에 고치지 않으면 그대로 게시된다.
   - **수정**: 네 실행 환경·24회로 고치고, **CI가 릴리즈 도중 두 번 값을 한 사실**(미컴파일 → dash 결함)을
     한 항목으로 추가했다.

   `tests/fleet-verify/run.sh`·`tests/site-includes/run.sh`가 없었다. 마일스톤 쪽은 이번에 갱신됐고

5. **`tests/discover/README.md`가 아직 "세 실행 환경"이고 `run.sh`를 하나로 뭉쳤다** — 완료 기준 9는
   이제 **네** 환경을 선언하고 `run.sh` @ dash와 @ bash를 **일부러 나눈다**(같은 환경이 아니기 때문에).
   실행 예시도 "두 런타임을 다 돌린다"로 `.ps1`만 말하고, CI 서술은 bash 레그가 **두 OS**에서 돌아
   `sh`가 서로 다르다는 사실을 감췄다. "런타임 축이 문장 안에 숨는다"가 한 층 아래에서 반복된 것이고,
   T07 (e)가 지정한 바로 그 파일이다. → 네 환경 표기, `dash` 실행 예시 추가, **ubuntu 레그의 `sh`가
   dash**임을 명시.
6. **"CI 첫 실행"이 부정확했다** — 첫 실행(`30788018160`)은 잡을 하나도 만들지 못했고, ubuntu 결함은
   **두 번째 실행**(`30788456063`)이 냈다. 워크플로 주석은 이 구분을 적고 있어 레포가 자기와 어긋났다.
   → 두 실행을 나눠 적었다(전자는 CI가 **자기 자신에 대해** 낸 결함이다).

### 사소 (4건 — 미수정, M38으로 이월)

7. **CI의 발견이 셸별로 독립이라 짝 없는 하니스가 조용히 빠진다**(직전 라운드에서 이월) — `run.ps1`
   집합과 `run.sh` 집합이 같은지 아무도 묻지 않는다. **직전 라운드의 부인 기록이 계속 적용된다.**
8. **`tests/lib/encoding.sh`의 `strip_bom`이 GNU sed에 기댄다** — `sed '1s/^\xEF\xBB\xBF//'`의 `\x`는
   GNU 확장이다. 이번에 **바꾸지 않은 것은 옳다**: 셸이 아니라 sed가 해석하는 자리라 이번 부류
   (`printf`의 `\xHH`)와 **메커니즘이 다르고**, 반증 패스가 GNU sed 4.9 · `C`/`C.UTF-8`/`en_US.UTF-8`/
   `ko_KR.UTF-8`에서 실제 BOM을 벗기는 것을 실측했으며, 실패하면 `fleet-verify` 4단언이 곧바로 붉다
   (조용하지 않다). 비-GNU sed(BSD/macOS)를 쓰는 CI 레그는 없다.
9. **`run.ps1`의 점 필터가 문화권 기반 비교를 쓴다**(이월) · 10. **(선존) Part B의 셸 발산**(이월).

## 검증

in-review 수정이 **6건**이라 재검증(re-verify)이 발동했다. 아래는 **수정 후** 결과다.

**재검증 결과 (re-verify)** — 전 하니스 6종 × **네 실행 환경** = **24회 전부 FAIL 0 · exit 0**:

| 하니스 | `run.sh` @ **dash** | `run.sh` @ **bash** | `run.ps1` @ **5.1** | `run.ps1` @ **pwsh 7** |
|---|---|---|---|---|
| `tests/discover` | 85 / 0 | 85 / 0 | 85 / 0 | 85 / 0 |
| `tests/fleet` | 41 / 0 | 41 / 0 | 41 / 0 | 41 / 0 |
| `tests/fleet-cycle` | 23 / 0 | 23 / 0 | 23 / 0 | 23 / 0 |
| `tests/fleet-verify` | **29 / 0** | 29 / 0 | 29 / 0 | 29 / 0 |
| `tests/multi-repo` | 30 / 0 | 30 / 0 | 30 / 0 | 30 / 0 |
| `tests/site-includes` | 34 / 0 | 34 / 0 | 34 / 0 | 34 / 0 |

**dash 열이 이 사이클에서 처음 생겼고, 그것이 이번 수정의 근거다.** 수정 전 같은 열의
`fleet-verify`는 **25 / 4 · exit 1**이었고 이는 CI 우분투 레그가 낸 수치와 **정확히 같다**.

**팔진 변환이 바이트 동일하다**(실측): 원본 `bash printf '\xec…'`와 새 `dash printf '\354…'`를
`cmp`로 대조해 **동일**, 유효 UTF-8. 픽스처 BOM도 `sh`·`dash` 양쪽에서 `ef bb bf`로 같다(수정 전
dash는 글자 12개였다). 셸 파일에 남은 `printf`의 `\xHH`는 **0건**이다.

**반증 패스가 내가 하지 않은 검증을 했다 — 그리고 판정을 강화했다.** CI 로그를 직접 당겨
(`gh run view --job 91606816540`) **우분투 레그가 6종을 전부 실행**했음을 확인했다: `discover` 85/0 ·
`fleet` 41/0 · `fleet-cycle` 23/0 · `multi-repo` 30/0 · `site-includes` 34/0 `terms=[porpoise]` ·
`fleet-verify` **25/4**. 즉 우분투의 coreutils·awk·로케일 축까지 **한 번은 실제 러너에서 돌았고**,
"다른 POSIX 지뢰가 남아 있다"는 공격선이 grep이 아니라 **실측으로** 무너졌다. 실패 단언 4개의 이름도
로컬 dash 재현본과 바이트 일치했다. 반증 패스는 또 `strip_bom`이 네 로케일에서 실제 BOM을 벗기는 것,
`site-includes`의 파생 통제가 **여전히 문다는 것**(용어를 본문에 주입하면 FAIL · 마스트헤드에서
치우면 양성 통제 FAIL)을 변형으로 확인했다.

**계약 표면 불변**(실측): 커맨드 **12종** · `.tide/phase` 값 집합 · **훅 이번 라운드 무접촉** ·
프리플라이트 게이트 · 보고서 필수 섹션 · 판정 표기·계측 줄 형식 · `docs/conventions.md` **1035줄** ·
`cases: 85` · `run.ps1` 6종 **비-ASCII 0바이트** · 수정한 두 `run.sh` **무BOM · `i/lf w/lf`**.

**발행 산출물**: `mkdocs build --strict` 성공, **빌드 산출물 제외 용어 누수 0건**, v2.11.0 노트가
사이트 2개 파일에 렌더된다(고친 CHANGELOG 기준).

**완료 기준 12개**: 전부 충족한다. **기준 9**는 이번에 "세 실행 환경" → **"네 실행 환경(dash·bash·
5.1·7)"**으로 넓어졌고 위 24회가 그것을 만족한다.

**미검증 잔여 리스크**

- **고친 트리의 CI는 아직 돌지 않았다** — 리뷰는 push하지 않는다. CI가 검증한 트리와의 델타는
  **`printf` 형식 문자열 2개 + 산문**뿐이고, `\ddd`는 **POSIX가 규정한** 팔진 이스케이프이며 우분투가
  싣는 dash와 같은 소스다. 나머지 5종은 이미 실제 러너에서 초록이었다. 위험은 작지만 **0이 아니다** —
  릴리즈 후 첫 확인 항목이다.
- **로컬 `dash` ≠ 우분투 `dash` + 우분투 coreutils/로케일**: 방언 축은 재현 가능해졌을 뿐 동일하지 않다.
- **비-GNU sed**(위 사소 8) · **`run.ps1`의 침묵 실패 잔여 절반**(실행 케이스 수 대조는 `discover`의
  Part F뿐) — 둘 다 M38.

계측: in-review 수정 차단 0/권장 2/사소 4 · 반증 시도 수행 성립 6건 · 재작업 라운드(rework) 4

  워크플로는 3개 레그가 실제 GitHub에서 초록이고, dash 결함은 로컬 dash가 CI와 같은 수치를 재현한 뒤
  29/0으로 돌아섰다. 완료 기준 12개 전부 충족, 계약 표면 불변, 24회 그린이다. 이번에 발견된 것은
  **전부 문서**였고 차단 등급이 하나도 없었다.
- **차단 이슈 처리 상태**: **0건**. 권장 2·사소 4는 in-review로 닫고 재검증했다(위 24회 + 사이트 빌드).
  사소 7~10은 M38으로 이월한다.
- **재작업 라운드**: impl 보고서 개요의 값 **4**를 그대로 옮겼다. 직전 판정이 `가능`이었으므로 규약
  (`불가` 이후의 재실행에서만 증가)대로 **올리지 않았다** — 반증 패스도 이 독법이 규약 문면 그대로임을
  확인했다. 수렴 조건(`>2`)은 이미 발동 중이라 아래에 재분해 권고를 유지한다.
- **반증 시도: 수행 — 성립 6건.** 성립한 지적은 위 비판점에 편입했다. 이번 패스는 판정을 **유지시키면서**
  근거 하나를 **더 강하게** 만들었다 — 내가 하지 않은 CI 로그 실측으로 우분투 환경 축 전체가 이미
  한 번 돌았음을 보였다.
- **부인 기록 (`precedent-waiver`)**: 이번 라운드 **신규 0건**. 권장 1은 판례 부류가 아니라고 판단했고
  그 근거를 항목에 적었다(집행이 실재하고 초록이며, 문서가 집행력을 과장한 것이 아니라 낡은 설계를
  서술한 것이다). 직전 라운드가 남긴 부인 기록은 **사소 7에 대해 계속 유효하다**.
- **리뷰어 독립성 고지**: 이번 라운드도 **구현자와 리뷰어가 같다.** 반증 패스가 그 보정 장치이고,
  반증자가 제기한 6건을 **하나도 기각하지 않았다**.
- **minor 근거**: 직전 라운드와 같다 — 리뷰 절차 변경과 `kickoff`의 `.gitignore` 가산이 사용자 관찰
  가능하고, 동결 집합을 깨지 않는다. 이번 라운드 변경은 **테스트 하니스와 문서뿐**이라 등급을 올리지 않는다.
