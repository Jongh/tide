# M28 완료보고서 (impl)

## 개요

M28(tide-guard 읽기/쓰기 구분)의 4개 태스크를 모두 구현했다. tide-guard가 git 명령을 **서브커맨드
위치에서** 판정하도록 바꿔, 비-release phase에서도 git **읽기**(커밋 읽기·태그 목록·메시지 검색·이력
파일 읽기)는 통과하고 **쓰기**(`commit`·태그 *생성/삭제*·`push`)만 차단한다. 차단되던 쓰기 집합은 한
건도 줄지 않고(보호 불변), 부분 문자열 매칭이 만들어 온 읽기 오차단(태그 목록·`--grep`·이력 경로·
`cat-file commit`·`commit-graph`)만 해소했다. 규약(conventions)·hook 양 셸·가드 하니스(`tests/multi-repo`)·
도메인 문서를 한 결로 갱신했다. deps가 T01→T02→T03→T04로 완전 선형이라 메인이 순차 구현했다(같은 레벨
독립 태스크 2개 이상 없음 — 병렬 디스패치 비해당).

## 태스크별 수행 내용

- **M28-T01** — `docs/conventions.md` "tide-guard hook" 절의 동작 규약을 읽기/쓰기 구분으로 정련했다.
  차단 대상을 git **쓰기 서브커맨드**(`commit`·`push`·태그 생성/삭제)로 명시하고, git 읽기는 phase와
  무관하게 통과함을 단일 원본으로 기술했다. "서브커맨드 위치 판정" 항목을 추가해 verb를 전역 옵션(인자
  소비형 포함)을 건너뛴 첫 비-옵션 토큰으로 보고, 옵션 값·경로·복합 서브커맨드 이름의 부분일치는 무시함을
  규정했다. `tag`의 읽기/쓰기 구분 기준(읽기 옵션만/인자 없음=목록, 쓰기 옵션이나 목록 옵션 없는 위치
  인자=생성/삭제)과 새 안내 메시지 문안을 같은 절에 두었다. `idle` 차단 설명도 "쓰기만 차단(읽기는 통과)"로
  정합했다. **설계 결정**: 차단/통과 케이스의 단일 원본을 conventions 절 + `tests/multi-repo` 집행으로 두고
  마일스톤 문서를 살아있는 원본으로 만들지 않았다(마일스톤은 이력).

- **M28-T02** — `hooks/tide-guard.sh`·`hooks/tide-guard.ps1`의 verb 매칭부를 판정 계약대로 교체했다.
  **게이팅 로직(입력 읽기·BOM strip·cwd→root→phase 해석·`phase=release` 조기 exit, M27 견고화)은 한 줄도
  바꾸지 않고** 그 뒤 차단 결정부만 교체했다. **설계 결정**: 권장 경로(확장 정규식)는 `git cat-file commit`
  (인자 `commit`이 서브커맨드가 아님)·`commit-graph`를 정규식만으로 깨끗이 가르기 어려워, **폴백 경로 B
  (최소 토큰 스캔)** 를 채택했다 — 명령을 `&|;`로 세그먼트 분할 후 각 세그먼트에서 git 런처 토큰을 찾고,
  전역 옵션(`-C`·`-c`·`--git-dir` 등 인자 소비형은 그 인자까지)을 건너뛴 첫 비-옵션 토큰=서브커맨드를 얻어
  `commit`/`push`면 차단, `tag`면 쓰기 옵션·목록 옵션·위치 인자를 보고 분기한다. 양 셸 동일 판정.
  실제 셸 명령은 hook 입력 JSON의 `tool_input.command`에서 추출(sh는 jq, 없으면 sed 폴백; ps1은
  `ConvertFrom-Json`)하고, **추출 실패 시 보수적으로 기존 부분일치 규칙으로 폴백**해 파싱 불가 입력에서
  과소 차단을 막았다. sh 구현 중 발견·수정한 버그는 "테스트 결과"에 기록.

- **M28-T03** — `tests/multi-repo/run.sh`·`run.ps1`에 "시나리오 10: 읽기/쓰기 구분"을 양 셸 동일 케이스로
  추가했다. 같은 `impl` phase에서 **읽기 7건 통과**(`git tag -l`·`-l 'v2.*'`·`--contains`·`log --grep=commit`·
  `show HEAD:src/tag.rs`·`cat-file commit`·`commit-graph verify`) + **쓰기 4건 차단**(`tag v2.6.0` 생성·
  `tag -d` 삭제·`push --tags`·`-C ../other commit`)을 함께 단언해 "가드가 살아 있으면서 읽기만 통과"임을
  고정했다(음성 통제). 기존 시나리오 1~9(repo-root 인식·격리·폴백·BOM 회귀)는 보존, PASS 카운트만 12→23
  증가. 양 셸 동수.

- **M28-T04** — `docs/project-context.md`의 도메인 개념 `tide-guard` 항목을 읽기/쓰기 구분·서브커맨드 위치
  판정으로 갱신하고, "이월 항목 처분 원장"에 M28 fix 행(사용자 요구 출처)을 추가, 결산 프로즈에 "M28은
  백로그가 아닌 사용자 신호로 git 읽기 오차단을 닫음"을 명시했다. 안내 메시지 문안 정합은 T02에서 hook
  양 사본에 새 문안을 직접 넣어 충족했고, conventions 메시지 예시는 T01에서 같은 문안으로 맞췄다.

**구현 중 발견·수정한 이슈**: sh `seg_is_write`가 처음엔 모든 쓰기를 통과시켰다(34/51 FAIL). 원인은 세그먼트
순회 루프가 `IFS=개행`으로 설정된 상태에서 함수 내부 `set -- $1`이 공백이 아닌 개행으로 토큰화돼 명령이
한 덩어리로 남은 것. 함수 진입 시 `unset IFS`(기본 공백/탭/개행 분리)로 토큰화 후 IFS 복원하도록 고쳐
51/51 통과. ps1은 `-split '\s+'`로 명시 분리해 동일 버그 없음(검증으로 확인).

## 미해결·후속 메모

1. **선행 시연**: M28은 가드 *판정을 변경*(읽기 통과로 완화)하는 변경이라, 리뷰는 **적대 검증**으로
   "차단되던 *쓰기*가 통과로 새지 않는지"(보호 불변)를 반증 시도로 확인하는 것이 권장된다(M20 회고: 계약·
   안전 핵심 사이클의 표준 게이트). 본 impl은 검증 표 우열(쓰기) 17+4건이 전부 BLOCK 유지됨을 양 셸로
   고정했으나, 리뷰가 추가 쓰기 변형(예: `git -c k=v tag -a`, 인자 소비 전역 옵션의 변형, 환경변수 접두
   `GIT_DIR=x git push`)으로 보호 불변을 추가 반증해 볼 여지가 있다.
2. **추출 실패 폴백의 거칠음**: `tool_input.command` 추출이 실패하면 기존 부분일치 규칙으로 폴백한다(과소
   차단 방지). 이 경로는 드물지만(파싱 불가 입력) 옛 읽기 오차단이 그 입력 한정으로 재현될 수 있다 — 정상
   입력에선 발생하지 않으며, 더 견고한 폴백은 저위험 후속 후보.
3. **태그 옵션 화이트리스트의 보수성**: `tag` 읽기 옵션 목록(`-l`·`--contains`·`--points-at`·`--sort`·
   `--format`·`-v` 등)에 없는 *미래 git 읽기 옵션*이 생기고 그 호출이 위치 인자를 동반하면 생성으로 오판해
   차단될 수 있다(안전 측 — 읽기를 막을 뿐 쓰기를 흘리지 않음). 트레이드오프로 수용하되, git 옵션 추가 시
   목록 갱신이 후속.
4. **버전 영향도**: 마일스톤은 목표 v2.6.0(minor)로 기록했다. 가드 판정이 사용자 관찰 가능하게 바뀌므로
   patch보다 minor라는 판단이며, **리뷰가 영향도 재판정**한다(호환 파괴 아님 — 통과하던 것이 차단되지 않고
   차단하던 쓰기는 그대로).
