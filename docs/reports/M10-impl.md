# M10 완료보고서 (impl)

## 개요

M10 "안정화 라운드(병렬 디스패치 실증 겸용)"의 4개 태스크를 구현했다. 핵심 성과는
**M9 병렬 디스패치의 런타임 실증** — 상호 무의존·파일 비중첩인 T01·T02·T03을 **한
메시지에서 3개 서브에이전트로 동시 디스패치**해 폴백 없이 병렬 처리했고, 셋에 의존하는
T04를 레벨 배리어 뒤에서 통합·검증했다. 함께 회고 백로그 셋(release 운영 노트·마일스톤
템플릿 "변경 파일" 필드·메타 용어 누수 규약)이 해소됐다.

## 태스크별 수행 내용

- **M10-T01** (서브에이전트 #1, `skills/release/SKILL.md`) — 기존 release 절차는 무변경,
  "운영 주의" 절을 덧붙여 함정 3종 규약화: ① `.tide/phase`=`release` 기록을 git과 별도
  단계로 먼저(가드가 명령 전 phase를 읽으므로 합치면 차단), ② 멀티라인 커밋 메시지는
  실행 환경 문법에 맞춤(`-m` 반복/here-doc, 셸 불일치 시 토큰 오염), ③ CHANGELOG/README에
  제외 용어 literal 회피(snippets로 사이트 유입). 반환: 변경 1파일, 검증 통과.
- **M10-T02** (서브에이전트 #2, `skills/milestone/template.md`) — "태스크 상세" 블록 각
  태스크에 `- **변경 파일**: {…}` **권장 필드** 추가(필수 아님·생략 가능 명시 → 하위
  호환). 목적: 병렬 겹침 감지를 마일스톤 단위 표 추정에서 **태스크별 결정적**으로. 반환:
  변경 1파일, `{…}` 관례 준수 확인.
- **M10-T03** (서브에이전트 #3, `docs/conventions.md`) — "버전·CHANGELOG" 절(본문 마커
  안쪽)에 두 규약 추가: ① 메타 용어 누수 방지(제외 용어를 검증 서술 메타 문장에서도
  literal로 쓰지 않음 — 실제 단어 대신 "제외 용어"·"외부 저장소명" 일반 표현), ② 릴리즈
  빌드 출력 검증(release 프리플라이트에서 빌드 산출물 기준 제외 용어 0건 확인). 반환:
  변경 1파일, 마커 무손상·제외 용어 literal 미사용 확인.
- **M10-T04** (메인, 레벨 배리어 뒤; deps T01·T02·T03) — `docs/project-context.md`에 병렬
  겹침 감지의 템플릿 필드 연결·릴리즈 위생 개념 반영. strict 빌드 + 사이트 반영·제외
  용어 0건 검증(아래). **README.md는 실제 변경 불필요**로 판단(커맨드 표 정확, conventions
  변경은 snippets로 자동 반영) — T04 예상 변경 파일(README+project-context) 중 README는
  언더슈팅(무해).

## 테스트 결과

자동 테스트 러너 없는 프롬프트·규약 플러그인. 정적/빌드/행위 검증:

- **★ 병렬 디스패치 런타임 실증(완료 기준 6)** — T01·T02·T03을 **하나의 메시지에서 3개
  Agent(서브에이전트) 동시 호출**로 디스패치했다. 변경 파일이 비중첩(`release/SKILL.md`·
  `milestone/template.md`·`conventions.md`)이라 **겹침 폴백 없이 병렬 유지**. 동시성 증거:
  각 서브에이전트 소요 ~35s/~32s/~45s가 **합산(~112s)이 아니라 벽시계 ~45s(최댓값)** 로
  완료 — 실제 동시 실행. 각자 독립 반환을 메인이 이 보고서로 병합. **M9-impl#1의 사후
  실증 항목을 충족.**
- **strict 빌드** — venv(mkdocs 1.6.1)에서 `mkdocs build -f site/mkdocs.yml --strict`
  exit 0. T03이 conventions에 더한 "메타 용어 누수 방지"·"릴리즈 빌드 출력 검증"이
  사이트 `conventions`에 반영됨 확인.
- **빌드 출력 제외 용어 0건** — `grep -rli porpoise site/_build` → 0건. T03 서브에이전트가
  규약 문구에 제외 용어 literal을 쓰지 않아(일반 표현 사용) 새 누수 없음 — 이번에 추가한
  규약이 스스로를 위반하지 않음.
- **매니페스트 무수정·하위 호환** — 신규 파일 없이 기존 스킬/문서/템플릿만 수정. 템플릿
  "변경 파일" 필드는 권장(필수 아님)이라 기존 마일스톤과 호환.

## 미해결·후속 메모

1. **병렬 폴백 경로는 이번에 미실증** — 이번은 "비중첩 → 폴백 없이 병렬"의 정상 경로만
   탔다. "겹침 → 부분 순차 폴백", "서브에이전트 부분 실패 → 보존+재시도", 워크트리 격리는
   여전히 런타임 미실증. 일부러 겹치거나 실패하는 픽스처가 필요(차기 후보).
2. **"변경 파일" 권장 필드의 강제력 없음** — 템플릿에 필드를 넣었으나 마일스톤 작성 시
   채우지 않으면 겹침 감지는 다시 휴리스틱이 된다. 강제(필수화)는 하위 호환을 깨므로
   보류 — 다음 마일스톤들이 실제로 이 필드를 채우는지 관찰이 후속.
3. **T04 예상 변경 파일 언더슈팅** — README가 예상에 있었으나 실제 불필요했다. "변경 파일"
   예측은 어디까지나 예측이며 실제와 다를 수 있음을 보여줌(과대 예측은 무해 — 병렬 안전엔
   과소 예측만 위험). 겹침 감지가 보수적으로 동작하면 충분.
4. **누적 도그푸딩 잔여** — 이번에 병렬 런타임은 실증했으나, M7 Pages 소스 전환·배포 후
   렌더 확인, ps1 가드 한국어 출력은 여전히 미수행(회고 추적). 다음 도그푸딩 묶음 후보.
