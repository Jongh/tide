M36의 다섯 태스크를 전부 구현했다. `docs/conventions.md`의 `## 리뷰 검증 규율`에 다섯 번째 소절

### 재작업 1 — T04의 창 정의를 사실에 맞춤 (리뷰 차단 #1)

초회 T04는 창을 `clone 후 **첫 tide 커맨드 이전**까지 — 각 커맨드가 시작 시 자기 단계명을 기록하므로
**첫 커맨드가 창을 닫는다**`로 적었다. **12종 중 6종은 이 레포의 phase를 쓰지 않는다** — 실측:

| 구분 | 커맨드 | 근거 |
|---|---|---|
| **쓴다 (6종)** | `milestone`·`impl`·`review`·`release`·`debug`·`cycle` | 각 SKILL 시작 절차 |
| 안 쓴다 | `kickoff` | `.gitignore`에 `.tide/phase` 항목만 추가(`skills/kickoff/SKILL.md:25-26`) |
| 안 쓴다 | `status`·`fleet` | 읽기 전용 — `단계별 금지 행위 요약`이 phase 변경을 금지 |
| 안 쓴다 | `retro` | 회고 문서 외 파일 생성·수정 금지 |
| 안 쓴다 | `fleet-verify` | verification-only — 어떤 레포 phase도 쓰지 않는다 |
| 안 쓴다(이 레포) | `fleet-cycle` | **자식 레포의** phase만 쓴다(`skills/fleet-cycle/SKILL.md:48,50`) — 부모·세션 레포의 창은 그대로다 |

**`fleet-cycle`은 리뷰의 보완 지시조차 틀렸던 지점이다.** 리뷰 `다음 단계`는 phase를 쓰는 커맨드로
`fleet-cycle`을 포함해 7종을 열거했는데, 실측하면 그것이 쓰는 것은 **자식 레포의** phase다. 지시를
그대로 옮겼다면 같은 부류(범위 과대 주장)를 재생산했을 것이므로, 재실행에서 **6종**으로 확정했다.

수행한 것 넷:
1. **창 정의를 좁혔다** — "**단계 커맨드 6종 중 하나를 처음 부를 때** 닫힌다"로 바꾸고, **첫 커맨드가
   닫아 준다는 보장이 없음**을 명시했다(fresh clone 후 가장 자연스러운 `kickoff`·`status`가 둘 다
   phase를 쓰지 않아 창이 그대로 열려 있고, `kickoff`만 돌린 신규 레포는 계속 열린 상태다).
2. **`결론 = 수용`의 근거 문장을 다시 적었다** — "창이 좁고(첫 커맨드가 닫는다)" → "창은 **좁지만
   자동으로 닫히지 않는다**(단계 커맨드를 불러야 닫힌다). 그래도 앞당겨 닫으려면 …". 수용 자체는
   넓은 창에서도 성립하므로 결론은 유지하고 근거만 사실에 맞췄다.
3. **선존 문장도 고쳤다(범위 판단)** — `## 상태 파일 (.tide/phase)`의 "각 커맨드는 시작 시 자기
   단계명을 기록하고 … (`/tide:status`는 읽기 전용이라 변경하지 않음)"이 status만 예외로 적어
   같은 부류의 과대 주장이었다. **창 항목이 그 문장을 근거로 인용**하므로(`위 "상태 파일 (.tide/phase)"
   절`) 근거가 틀린 채로 두면 차단을 온전히 닫지 못한다 — **차단을 닫는 데 필요한 최소 수정으로
   판단해 고쳤다**(범위 확대가 아니며, 리뷰의 "넓히면 명시하라"에 따라 이 문단으로 명시한다).
   새 문장은 6종을 열거하고 나머지 6종이 왜 쓰지 않는지 한 줄로 적는다.
4. **훅 두 사본 주석을 같은 취지로 고쳤다** — 6종 열거 + `fleet-cycle`이 자식 레포 phase만 쓴다는
   단서 + 첫 커맨드 보장 없음. **주석 전용이며 실행 코드는 여전히 한 줄도 바뀌지 않았다**
   (`numstat` 각 `+9 −1`, 비주석 변경 **0줄**). `.sh` 무BOM·`.ps1` BOM 포함 UTF-8 유지.

### 재작업 2 — 창이 닫히는 **시점**을 사실에 맞춤 (리뷰 차단 #1, 2라운드)

재작업 1은 창의 **주체**(6종)를 바로잡았으나 시점을 `6종 중 하나를 **처음 부를 때**`로 적었다.
**호출만으로는 닫히지 않는다** — 실측:

| 커맨드 | 기록 시점 | 근거 |
|---|---|---|
| `milestone` | 시작 시 무조건 | `skills/milestone/SKILL.md:12` |
| `debug`(세션 열기) | 시작 시 무조건 | `skills/debug/SKILL.md:33` |
| `impl` | **대상 문서 검사 통과 후** | `:15` 중단 → `:17` "검사를 통과하면 … 기록해줘" |
| `review` | **impl 보고서 검사 통과 후** | `:13` 중단 → `:15` 동일 |
| `release` | **프리플라이트 통과 후** | `:63` "프리플라이트 통과 후 … 기록하고" |
| `cycle` | **시작점 단계의 전제조건을 그대로 검사** | `:33,40,43` |
| `debug done` | **열린 세션이 없으면 아무것도 하지 않고 중단** | `:71-72` |

검사에서 중단되면 phase 파일이 생기지 않아 창은 그대로다. 살아 있는 반례가 이 사이클 안에 있었다 —
직전 리뷰 판정이 `불가`였으므로 그 시점에 `/tide:release`를 불렀다면 게이트 ①에서 중단되고 phase를
**쓰지 않았을 것**이다.

수행한 것 셋:
1. **창 정의를 "실제로 기록할 때"로 고쳤다** — `호출만으로는 닫히지 않는다`를 명시하고, 이유를 두
   갈래로 나눴다(① 쓰지 않는 6종 ② 쓰기 전에 중단되는 경로). **시점 목록을 규약에 복제하지 않았다** —
   "어느 커맨드가 어느 시점에 쓰는지는 **각 스킬의 절차가 정한다**"로 위임하고 규약은 *기록될 때

2. **`결론 = 수용` 문구**를 "phase가 **실제로 기록돼야** 닫힌다"로 맞췄다.
3. **훅 두 사본 주석과 `site/docs/concepts.md`의 창 고지**를 같은 조건으로 맞췄다(훅은 주석 전용

   `불가`로 끝난다. 그것이 정상 동작이다.
4. **복제 선언 +5는 M37이 갚는다**(위 자기 부채 계측). M37은 `12종` 6곳 → 캐노니컬 1곳과 지표
   "복제 선언 수"의 규약화가 범위다. **`docs/conventions.md`·`docs/orchestration.md`는 raw로 읽히는
   파일이라 snippets로는 풀 수 없다** — 선언을 지우고 캐노니컬을 가리키는 방식이어야 한다.
5. **3.0 마커는 등재만 했다.** 구현 시 제약 두 개(차단 메시지 자기서술 · `rev-parse` 루트 앵커)를
   반드시 함께 설계해야 한다. 적대 검토에서 나온 오탐 넷 중 **"영구 차단·순환"은 성립하지 않는다** —
   가드가 워킹트리 `[ -f ]` 검사라 마커를 `rm` 하면 즉시 해제된다(커밋 불요). 남는 것은 상속 레포 UX와
   모노레포 범위 초과이고 둘 다 위 제약으로 다룰 수 있다.
6. **`docs/conventions.md`가 995줄로 늘었다**(M35 종료 시 927줄, **+68** — 초회 +53, 재작업 1 +7,
   리뷰 in-review +1, 재작업 2 +7).
   신설 소절과 가드 창 고지가 더해진 결과다. M35 impl 보고서가 남긴 **분할 종료 조건** 후속이 아직
   정해지지 않았고, 규약이 다시 증가 추세로 돌아섰으므로 M37 또는 그 다음에서 판단해야 한다.
7. **재작업 1이 남긴 관찰(D′의 첫 실사용 기록)** — 리뷰의 **보완 지시 자체가 부정확**했다
   (`fleet-cycle`을 phase 기록 커맨드로 열거했으나 실제로는 자식 레포 phase만 쓴다). impl이 지시를
   재해석 없이 옮기지 않고 **실측 후 6종으로 확정**한 것이 같은 부류의 재생산을 막았다. 이는 D′가
   의도한 효과의 부수 확인이다 — 차단을 반환하면 impl이 그 지점을 **다시 실측**하게 되고, 리뷰가
   in-review로 고쳤다면 리뷰의 부정확한 이해가 그대로 트리에 들어갔을 것이다. 다음 회고가 볼 값이다.
8. **같은 축에서 두 번 반환됐다 — 서술 정밀도가 이 사이클의 실질 난점이었다.** 차단 1(주체)과
   차단 2(시점)는 같은 문장의 서로 다른 축이었고, 두 번 다 "범위를 사실보다 넓게 적음"이었다.
   재작업 2가 택한 대응은 **더 정확한 목록을 적는 것이 아니라 목록을 규약에서 빼는 것**이다 —
   전수 단정을 넣을수록 틀릴 표면이 늘어나므로, 규칙만 정하고 시점은 각 스킬 절차에 위임했다.
   이것이 세 번째 반환을 막는 구조적 선택인지는 다음 리뷰가 판정한다. **라운드 2는 수렴 조건
   (`>2`)의 경계**이므로, 같은 축에서 또 차단이 나오면 재분해가 타당하다.
9. **선존 문장을 함께 고친 판단의 경계** — 이번 재작업은 차단 범위를 넘지 않기 위해
   `## 상태 파일 (.tide/phase)`의 한 문장만 고쳤다. 같은 부류로 의심되는 서술이 다른 절에 더 있는지는
   **전수 조사하지 않았다**(범위 확대를 피했다). 규약 전반의 "각/모든 …이 X한다" 류 단정을 훑는 작업은
   별도 사이클 후보이며, M37의 복제 선언 제거와 성격이 가깝다.
