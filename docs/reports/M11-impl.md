# M11 완료보고서 (impl)

## 개요

M11 "도그푸딩 라운드"의 4개 태스크를 수행했다. 검증 위주 라운드로, T01(Pages 게시
실증)에서 **실제 배포 결함을 적발·수정**했고 — 이 라운드의 핵심 성과 — T02(ps1 한국어
출력)·T03(병렬 폴백)·T04(release 빌드검증 배선)는 **3개 서브에이전트로 동시 디스패치**해
수행했다(M9 병렬 메커니즘 재사용, 벽시계 ≈ 최댓값). 누적 도그푸딩 부채 중 Pages·ps1·
병렬 폴백·규약↔실행 배선이 상환됐고, 코드 외 수동 부채(Pages Source 전환)는 사용자가
이미 완료해 게시가 확인됐다.

## 태스크별 수행 내용

- **M11-T01** (메인, Pages 게시 실증) — 사용자가 Settings→Pages→Source를 GitHub Actions로
  전환 완료. 라이브 사이트(`https://jongh.github.io/tide/`) **HTTP 200**, 홈(정의·6페이지
  내비·Mermaid·porpoise 0)·규약(단일 원본 인클루드 렌더·porpoise 0·귀속 없는 도입부)
  정상 확인. **그러나 변경 이력 페이지가 v0.9.0까지만 + "porpoise" 1건 노출**을 발견 —
  사이트가 v0.9.0 시점 빌드로 고착돼 있었다.
  - **근본 원인**: `.github/workflows/deploy-pages.yml`의 트리거 `paths`가 `site/**`만
    감시하는데, 사이트는 `CHANGELOG.md`·`docs/conventions.md`(루트)를 snippets로 단일
    원본 인클루드한다. 그래서 그 루트 파일만 바뀐 릴리즈(M9·M10·M11)는 재배포를 트리거
    못 해 changelog/conventions 페이지가 낡았다 — 회고의 "배포-후 실증 연기"가 2릴리즈간
    조용히 누적된 실체.
  - **수정**: 트리거 `paths`에 `CHANGELOG.md`·`docs/conventions.md`를 추가(주석으로 이유
    명시). 현재 main 빌드 산출물은 v0.11.0까지 포함·porpoise 0건임을 확인 — **재배포되면
    라이브가 교정됨**(M11 릴리즈가 CHANGELOG를 건드리므로 자동 트리거; 사용자가 워크플로우
    수동 재실행 시 즉시 교정).
- **M11-T02** (서브에이전트 #1, ps1 실증) — PowerShell 5.1에서 저장소 원본
  `hooks/tide-guard.ps1`을 직접 실행(임시 `CLAUDE_PROJECT_DIR`+`.tide/phase=impl`, 트리거
  토큰 분리로 활성 가드 자기 차단 회피, JSON stdin 주입). **결과: 한국어 차단 메시지가
  깨짐 없이 출력**(`'impl' 단계에서는 git commit/tag/push가 차단됩니다. …`), **exit 2**,
  비-git exit 0, 파일 앞 3바이트 `EF BB BF`(UTF-8 BOM) 확인. M8의 BOM 저장이 런타임에서
  정상 동작함이 실증됨. 변경 파일 없음(깨짐 없어 수정 불필요).
- **M11-T03** (서브에이전트 #2, 병렬 폴백 실증) — 통제된 워크스루로 ① 겹침 폴백(두
  태스크가 같은 파일 대상 → 교집합 ≠ ∅ → 겹치는 것만 순차, 비겹침 제3태스크는 병렬
  유지)과 ② 부분 실패(다른 결과 보존+메인 재시도→재시도 실패 시 중단·보고)가 규약대로임을
  확인. 검증 중 **규약 모호함 2건**(겹침 판정 입력의 정규화·빈/조건부 집합 처리, "실패"
  탐지 기준) 발견 → `skills/impl/SKILL.md` "병렬 디스패치" 절을 **명확화 보강**(메커니즘
  불변, 문장만 추가): 겹침=정규화 경로 교집합·빈/조건부 집합은 잠재 겹침으로 순차, 실패
  정의(오류 종료 또는 반환 계약 미충족)+재시도 1회.
- **M11-T04** (서브에이전트 #3, release 배선) — `skills/release/SKILL.md` 프리플라이트에
  4번 항목 "사이트 빌드 출력 제외 용어 0건 확인"을 추가(기존 3종 보존). **사이트 있는
  프로젝트 한정**(`site/mkdocs.yml` 존재 시) 조건 + 사이트 없는 일반 프로젝트 면제를
  양방향 명시. conventions의 "릴리즈 빌드 출력 검증" 규약과 정합 — **M10 권장1(규약↔실행
  간극) 해소**. 제외 용어 literal 미사용. README/project-context는 불필요로 미수정(규약은
  이미 conventions에 있고 프리플라이트 배선만 누락이었음).

## 테스트 결과

검증 위주 라운드 — 1차 산출물은 실증 기록. 결과:

- **★ T01 Pages 실증** — 라이브 HTTP 200, 홈·규약 페이지 정상 렌더·인클루드·porpoise 0.
  변경 이력 고착(v0.9.0+porpoise) **결함 적발 → 배포 path 결함 수정**. 현재 main 빌드
  산출물은 v0.11.0까지·porpoise 0건(재배포 시 교정 입증).
- **★ T02 ps1 한국어 출력** — PowerShell 5.1 런타임 실증 성공(한글 무깨짐·exit 2·BOM).
  M8 이후 미상환이던 항목 상환.
- **★ T03 병렬 폴백** — 겹침→순차, 부분 실패→보존+1회 재시도→중단이 규약대로임을 워크스루로
  확인 + 규약 모호함 2건 보강.
- **T04 release 배선** — 프리플라이트 4번 추가, conventions 규약과 일치. strict 빌드
  exit 0.
- **병렬 디스패치 재실증** — T02·T03·T04를 한 메시지 3개 동시 Agent 호출(비중첩, 폴백
  없음), 벽시계 ≈ 최댓값(~106s, 합산 ~247s 아님). M10에 이은 2회째 — 이번엔 **폴백 규약
  자체를 개선(T03)** 하는 메타적 사용.
- **매니페스트 무수정** — 기존 파일만 수정, 자동 발견 유지.

## 미해결·후속 메모

1. **라이브 사이트 재배포 확인은 M11 릴리즈 후** — 배포 path 수정 + M11 릴리즈(CHANGELOG
   변경)로 워크플로우가 재트리거돼 변경 이력이 v0.11.0까지·porpoise 0으로 갱신되는지는
   release 후 라이브 재확인이 필요(또는 사용자 워크플로우 수동 재실행). T01의 마지막 1마일.
2. **Mermaid·검색·다크모드 런타임 미실증** — 정적 fetch로는 클라이언트 렌더를 끝까지 못
   본다. 브라우저 확인이 후속(저위험 — HTML/스크립트 포함은 확인됨).
3. **병렬 폴백의 종단 실행 실증은 여전히 미완** — T03은 규약 워크스루+보강이지, 실제
   N≥2 비겹침 레벨에서 폴백 분기가 코드로 실행되는 실증은 아니다. 자연 발생하는 겹침/실패
   레벨이 나오면 그 사이클 보고서에 실행 실증을 남기는 게 후속.
4. **`site_url` 실값 확인됨** — `https://jongh.github.io/tide/`(소문자)가 200. `mkdocs.yml`의
   `site_url`(`https://Jongh.github.io/tide/`)은 GitHub이 대소문자를 정규화하므로 동작에
   문제없으나, 정확성을 위해 소문자로 맞추는 것은 선택적 후속.
