# M5 리뷰보고서 (review)

> 대상 선정 메모: `docs/milestones/`의 최대 번호는 M6이지만 M6은 계획 문서만 있고 구현·
> impl 보고서가 없다. 방금 구현되어 impl 보고서가 존재하는 마일스톤은 **M5**이므로, "최근
> 구현된 작업 리뷰"라는 review 단계의 취지에 따라 M5를 대상으로 한다(M5-impl.md 존재 →
> 전제조건 충족). M5·M6이 독립이라 진행 순서가 무관한 데서 비롯된 정상 상황이다.

## 비판점

### 차단 (0건)

없음. M5 완료 기준 중 코드/문서로 검증 가능한 항목은 모두 충족했고, 미검증 항목은
이 프로젝트 구조상 불가피한 "재설치 후 드라이런"뿐이다(아래 검증·다음 단계).

### 권장 (1건 — 처리 완료)

1. **무인자 시작점 판단의 공백** — `skills/cycle/SKILL.md`의 "시작점 판단"이 무인자 호출 시
   "가장 큰 번호 마일스톤이 impl 보고서까지 완료됨 → 새 milestone부터"로만 분기해, **impl
   보고서는 있으나 review 보고서가 없는 상태**(지금 M5가 정확히 그 상태)를 만나면 진행 중
   사이클의 review로 이어가지 않고 새 마일스톤을 만들어버린다. 사이클 이어하기 의도와
   어긋난다. 리뷰 중 직접 수정함(아래 수정 내용).

### 사소 (2건)

2. **"병렬 착수"는 규칙상 해석일 뿐 실제 동시 실행은 아님** — cycle 본문은 독립 태스크를
   "병렬 묶음"으로 기술하지만 현재 impl 단계는 단일 실행자라 실제 동시성은 없다. 본문
   괄호주석("실제 병렬 실행 수단은 구현 판단에 맡긴다")과 impl 보고서 메모 #2가 이를 이미
   명시하므로 오해 소지는 낮다. 완료 기준 3은 *해석의 명시*만 요구하므로 충족. 진짜 병렬이
   필요해지면 별도 마일스톤 후보.

3. **conventions 전제조건·프리플라이트 표에 cycle 행 없음** — cycle의 전제조건은 각 하위
   단계(impl=마일스톤 문서, review=impl 보고서)를 그대로 상속하며, 이는 "수동 vs 자동"
   산문 단락에 이미 서술돼 있다. 표에까지 중복 기재하지 않은 것은 의도적 — 표는 단계
   고유 전제조건의 단일 원본이고 cycle은 상속자이기 때문. 수정 불요.

## 수정 내용

- **이슈 1**: `skills/cycle/SKILL.md`의 "시작점 판단"을 무인자 호출 시 최대 번호 마일스톤의
  **보고서 상태로 3분기**하도록 재작성 — (a) impl 보고서 없음 → impl부터, (b) impl만 있고
  review 없음 → **review부터(이어하기)**, (c) impl·review 모두 있음 → milestone부터(새
  마일스톤). 인자 분기(번호=impl부터 / 주제=milestone부터)도 함께 명확화. 이로써 진행 중
  사이클을 건너뛰고 새 마일스톤을 만드는 공백이 제거된다.

## 검증

- **수정 재검토** — 재작성한 "시작점 판단"을 현재 저장소 상태에 트레이스: 무인자 호출 시
  최대 번호 M6은 impl 보고서 없음 → 분기 (a) impl부터. M5를 인자로 주면 impl부터(재실행).
  M5가 review까지 끝난 뒤 무인자 호출하면 M6 분기 (a)로 자연 진행. 공백 케이스(impl만 있고
  review 없음)는 분기 (b)로 review 이어하기 — 의도대로 해석됨.
- **deps 스케줄링 재확인** — impl 단계에서 검증한 두 형태(M5/M4 단일 루트 팬, M1 다중 루트)
  트레이스가 유효. 순환·미존재 ID 폴백 조건도 본문에 명시.
- **부수효과 분리/tide-guard 비충돌** — cycle은 phase를 milestone/impl/review/idle로만 두고
  `release`로 두지 않으므로 체이닝 구간 전체에서 tide-guard가 git을 차단한다(의도된 동작,
  충돌 없음). 리뷰 단계에서 git 명령은 일절 실행하지 않았다.
- **문서 일관성** — conventions(다이어그램·산문·금지 표)·README(다이어그램·설명·커맨드
  표·6→7종 3곳)·project-context(스킬 7종) 갱신 확인. 잔여 "6종"은 전부 과거 기록으로 보존 정당.

**미검증 잔여 리스크**: 완료 기준 1(재설치 후 새 세션에서 `/tide:cycle` 실제 노출·호출)과
2의 엔드투엔드 자동 진행은 플러그인 재설치+새 세션이 있어야 실증 가능하며 이 단계에서
불가하다. 단 (a) 매니페스트에 `skills` 배열이 없어도 기존 6종이 노출되는 사실로 자동 발견이
이미 실증돼 있고, (b) 신규 frontmatter가 기존 스킬과 동형이므로 노출 실패 가능성은 낮다.
릴리즈 직후 새 세션에서 1회 도그푸딩 권장(M2·M3·M4와 동일한 검증 리듬).
