# M34 완료보고서 (impl)

## 개요

M34의 여섯 태스크(T01~T06)를 전부 구현했다. 규약의 절·소절별 크기와 **레포 안에서 실제로 인용되는
횟수**를 실측해 인벤토리로 남기고(T01), `docs/conventions.md`에 `### 상호참조 무결성` 규약을 신설한 뒤
(T02) 끊긴 인용·표기 흔들림·중복 앵커 이름을 전부 해소했으며(T03), `tests/discover`에 **Part G**를
신설해 인용→앵커 대조를 양 셸 FAIL로 집행하고(T04), 인용 0 + 미집행 서술을 축약해 규약을 **9 minor
만에 처음으로 줄였다**(T05, 1066 → 1022줄). 마지막으로 분할 판단 근거와 계약 표면 불변을 확인하고 전
하니스 6종을 양 셸로 재실행했다(T06, FAIL 0). 파일 분할은 계획대로 범위 밖이다.

**계획의 기준선 수치가 틀렸다는 점을 먼저 밝힌다.** 마일스톤은 계획 시점 실측을 "922줄 / `##` 19 /
`###` 29"로 적었으나, 같은 트리(`v2.10.1`, 워킹트리 클린)의 실측은 **1066줄 / `##` 19 / `###` 28**이다
(`git show v2.10.1:docs/conventions.md | wc -l` = 1066으로 교차 확인). 따라서 완료 기준 6의 문자
그대로의 조건("922줄보다 줄었다")은 **충족되지 않았다** — 그 수를 맞추려면 기준선의 13.5%를 잘라야
하는데, 그것은 오기(誤記)가 만든 목표지 규약이 요구하는 목표가 아니다. 이 사이클은 기준을 **실측
기준선 1066줄 대비 감소**로 읽고 1022줄(**−44줄, −4.1%**)을 달성했다(상세·근거는 T05 항목).

## 태스크별 수행 내용

- **M34-T01** — `docs/conventions.md`의 `##`·`###` 앵커 **47개**(계획 시점)를 훑어 앵커별 줄 수와
  **살아 있는 문서에서의 인용 수·인용처**를 실측했다(아래 인벤토리 표). 인용처 조사 범위는
  `skills/**/*.md` · `docs/*.md` · `README.md` · `site/docs/*.md` · `tests/**/*.md`이고
  `docs/milestones/*`·`docs/reports/*`는 역사 기록이라 세지 않았다. **새 문서를 만들지 않고** 표를 이
  보고서 안에 뒀다(규약 부피를 줄이려는 사이클이 문서를 늘리지 않는다).
  - 계획이 예고한 3건 외에 **불일치를 3건 더 발견**했다 — 총 6건(아래 T03).
  - 사문화 후보(인용 0)는 17개였고, 그중 **"실제로 죽었다"는 판정은 1건**(`### 계층 로드맵`의
    "이번 마일스톤" 서사)뿐이었다. 나머지 16개는 전부 **"살아 있는데 인용 배선만 없다"** — 상위 절이
    인용되거나(gh 게시 8개 소절·리뷰 검증 규율 5개 소절), 하니스가 토큰으로 직접 앵커하고 있었다
    (Part E·F). 이 판정이 T05의 방향을 정했다: **절을 통째로 지우는 축약은 거의 불가능하고, 줄일 것은
    중복 서술·경위 서사·예시 나열이다.**

- **M34-T02** — `## 문서 자기서술 정합`에 **세 번째 규약** `### 상호참조 무결성`을 더했다(새 `##` 절을
  만들지 않았다 — ①카운트 단일 선언처 ②역할 앵커 전파 ③상호참조 무결성의 같은 계보). 정의한 것:
  **인용 골격**(`` `docs/conventions.md`의 "{앵커 이름}" 절 ``) · **인용 가능 앵커 = `##`·`###` 제목만**
  (볼드 항목은 소절 승격, 승격이 문맥을 해치면 인용 쪽을 고침) · **이름 유일성**(겹치면 상위 맥락을
  괄호로 붙여 유일화) · **공백만 제거하는 정규화** · **FAIL 집행**(추출 0건도 FAIL) · **대상 범위**
  (살아 있는 문서만, 역사 기록 제외).
  - **추출 제외 두 가지를 규약에 명시**했다 — 구현 중 실측으로 필요해진 것이다. ① **스니펫 인클루드
    지시어 줄**(`8<--`): `site/docs/conventions.md`의 인클루드 타깃 `"docs/conventions.md:body"`가
    따옴표 구획이라 인용으로 오추출된다. ② **중괄호가 든 따옴표**: 규약 자신이 적는 골격 예시
    `"{앵커 이름}"`이 오추출된다(규약을 적으면 그 규약이 FAIL하는 자기모순 차단). 둘 다 ASCII 규칙이라
    `run.ps1`의 한글 리터럴 금지와 정합한다.
  - 규약 문서 **안의** 자기참조(`위/아래 "X" 절`)는 골격에 파일명이 없어 가드 밖임을 **정직하게
    명시**했다(사람의 리뷰 영역 — Part B~F와 같은 분담). 그럼에도 이번 사이클에서 그 자기참조들도
    전부 실재 앵커로 맞췄다(T03).

### 부수효과 분리

이 단계에서 git commit·tag·push를 **하지 않았다**(`.tide/phase=impl`로 tide-guard가 백스톱). git은

### 구현 중 발견·수정한 이슈

1. **계획의 기준선 수치 오류**(위 개요) — 922줄/`###` 29는 실측 1066줄/`###` 28과 다르다. 릴리즈 태그
   트리로 교차 확인해 실측을 채택했다.
2. **불일치가 계획 예고보다 많았다** — 3건 예고, 실제 6건. 계획이 "인용 표면이 이미 새고 있다"고 본
   판단이 과소평가였던 셈이다.
3. **규약 자신이 자기 가드에 걸리는 자기모순** — 인용 골격을 규약에 적으면 그 예시(`"{앵커 이름}"`)가
   인용으로 추출돼 FAIL한다. 중괄호 자리표 제외 규칙으로 닫았다(규약·러너 양쪽에 명시).
4. **PowerShell 기본 비교가 대소문자 무시** — `-contains`/해시테이블 키를 그대로 썼다면 ASCII 앵커에서
   `grep -qxF`와 판정이 갈릴 수 있었다. `HashSet[string]`(ordinal)로 맞추고 README에 이유를 남겼다.
5. **편집 도구가 일부 파일의 줄끝을 CRLF → LF로 바꿨다** — git이 정규화해 커밋 내용은 불변이고

   전용 추출 규칙(한글 `절` 앵커 필요 → ps1 ASCII 규율과 충돌)을 만드는 두 경로가 있는데, 둘 다
   대가가 있어 **이번엔 정직 고지로 남겼다**.
4. **`### 통합 검증`·`### 교차 사이클 자동화` 제목에서 커맨드명을 걷어냈다** — 본문 첫 줄이 커맨드를
   밝히므로 정보 손실은 없으나, 목차만 훑는 독자에게는 어느 커맨드 절인지 한 단계 덜 명확해졌다.
   리뷰가 과했다고 보면 제목을 되돌리고 인용 6곳을 긴 이름으로 되돌리면 된다(양방향 비용 동일).
5. **병렬 디스패치는 발동하지 않았다(폴백 — 전 구간 순차)** — deps 위상은 L0={T01} / L1={T02, T05} /
   L2={T03} / L3={T04} / L4={T06}인데, 유일하게 2개가 같은 레벨인 **T02·T05가 둘 다
   `docs/conventions.md`를 고쳐 예상 변경 파일이 완전히 겹친다**. impl 스킬의 파일 충돌 안전장치대로
   그 레벨을 순차로 내렸고, 나머지 레벨은 태스크가 1개씩이라 애초에 병렬 대상이 아니다. 규약 문서
   하나를 다루는 마일스톤의 구조적 특성이며, 다음 사이클에서 **파일 분할이 이뤄지면 이 겹침도 자연히
   풀린다**(분할의 부수 이득으로 기록해 둔다).
