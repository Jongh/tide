# M86 리뷰보고서 (review)

## 비판점

### 차단 (0건)

차단 등급 이슈는 없다. 라운드 0의 차단 1(키 여럿 입력에서 정의 창이 좁아진 것)은 impl 라운드 1이 닫았다.
- **창 대조**: 키 여럿 갈래의 `dn_defs` · `DnDefs`를 HEAD의 `sp_defs` · `SpDefs`와 견줬다. 창 시작(블록 술어 선언 줄 다음) · CR 처리 · 빈 줄 · 탭 들여쓰기 · 두 선언 줄 사이의 줄 · 0열 `#`에서 같다(리뷰어 대조 · 반증 대조).
- **되돌림**: 라운드 0 리뷰의 교란 둘(`indent-orphan` · `indent-dup`)이 두 러너에서 HEAD와 같은 케이스(`W160` · `W158` `W162`)로 붉다.
- **통제**: 새 통제 `W164`는 같은 깊이 창으로 되돌리면 붉다(`dn-depth-*`).

### 권장 (0건)

권장 등급 이슈는 없다. 라운드 0의 권장 둘은 이렇게 처리됐다.
- **권장 2**: `W164`로 닫았다.
- **권장 3**: T03 배선 통제를 등록표로 옮기지 않은 결정과 사유가 impl 보고서에 기록됐다. 반증이 사유를 대조했다 — 픽스처 함수 여섯과 케이스 모양의 차이가 사실이다.

### 사소 (1건)

1. **impl 보고서 T06의 러너 주석 훑기 서술이 실제 검색과 맞지 않았다**(반증 · `scope-same-search`)
   - **출처를 잘못 적었다**: 라운드 1 문장은 히트 10줄 가운데 `mutation-axes:` 값 재서술 두 자리를 찾아 고쳤다고 적었다. 그러나 두 줄에는 선언 키가 없어 적힌 패턴에 걸리지 않는다 — 라운드 0 리뷰가 짚은 자리였다.
   - **조건 하나가 빠졌다**: 적힌 패턴에는 실제 검색이 건 「한글 수사 뒤 비한글 문자」 조건이 없었다. 적힌 대로 돌리면 히트가 19줄이다(반증 실측).
   - **찾지 못한 자리**: 키 없이 값만 다시 적은 자리는 이 패턴으로 찾지 못한다. 반증이 그런 자리로 `run.sh` M48 블록 「`epic-status:`(열림/닫힘 값 집합)」과 ps1 사본 「the open/done value set」을 찾았다.
   - **고친 것**: 출처 · 패턴 · 한계를 바로 적고, 두 자리를 후속 2에 기록했다(리뷰 중 수정).
   - **등급**: 사람이 돌린 훑기의 서술이고 기계 판정의 집행력 주장이 아니므로 `vacuous-pass` 부류로 보지 않는다. 범위 네 축은 그 자리에 있었고, 어긋난 것은 출처와 조건 하나다.
