## 비판점

### 차단 (0건)

없음.

### 권장 (1건 — 리뷰에서 수정 완료)

1. **`tests/site-includes/run.ps1`가 LF→CRLF로 줄바꿈이 뒤집힘(T02 서브에이전트 산출)** — HEAD는
   LF-only(`CR=0 LF=153`)인데 작업 트리가 CRLF(`CR=179 LF=179`)로 바뀌어 있었다. 형제 파일
   (`tests/multi-repo/run.ps1`)·repo HEAD가 일관되게 LF인 **저장소 LF 규약**에서 이탈했다. git
   `autocrlf` 정규화로 **커밋 diff 자체는 깨끗**(34줄만, 전 파일 플립 아님)하고 PowerShell은 CRLF/LF
   둘 다 정상 실행하므로 **기능 무영향**이나, "왜 이 파일만 CRLF?" 드리프트를 남긴다(M26 권장1의 BOM
   일관성 결함과 동형 — 규율 일관성). **영향**: 기능 무영향·일관성 결함. **수정**: `sed -i 's/\r$//'`로
   LF로 되돌렸다(`CR=0` 확인). 수정 후 no-BOM·ASCII-only 유지, `run.ps1` 재실행 **PASS=28 FAIL=0** 보존.

### 사소 (3건)

- **[sn1] positive-control은 "위치 드리프트/조작"은 잡되 "마스트헤드의 엉뚱한 실단어"는 못 잡는다** —
  추가된 단언은 추출 토큰이 **마스트헤드(3행)에 literal로 실재**하는지 본다. 추출기는 파일 전체에서
  **가장 이른** KO-방법론 패턴 매치를 취하고(3행이 본문보다 앞서 우선됨), 단언은 그 토큰이 3행에 있는지
  확인한다 — 즉 추출이 **3행 밖(본문 등)으로 드리프트**하거나 캡처가 **조작된 빈/부분 토큰**을 내면
  FAIL한다(sn1이 요구한 "스캐너가 진짜 문자열을 다루는지" 보장 — 충족). 다만 3행이 리워딩돼 **실재하지만
  의미상 틀린 단어**를 뽑는 경우는 그 단어가 3행에 있으니 통과한다. **수용 사유**: ① sn1이 명시 요구한
  범위가 "추출 토큰의 마스트헤드 실재"였고 그대로 구현됨, ② 제외 용어 누수 방어는 여전히 **3중**(release
  프리플라이트 수기 스캔 · CI `--strict` · 이 로컬 가드)이라 단일 실패점 아님, ③ "의미상 옳은 단어"까지
  강제하려면 용어를 하드코딩해야 해(그 자체가 누수·드리프트) 트레이드오프가 역전된다. **후속(비차단)**:
  용어를 비-인클루드 데이터 파일로 분리하는 대안의 트레이드오프를 차기 정리 사이클에서 판단.
- **[sn2] BOM 회귀(시나리오 9)는 순수 PowerShell 콘솔에서 비판별적** — 실험으로 strip 없는 가드 사본도
  순수 PS에서 BOM 입력에 정상 판정(exit 2)을 냄을 확인했다(`[Console]::In`이 BOM 흡수). 즉 시나리오 9는
  **Git Bash/MSYS 실행에서만 판별적**(no-strip이면 cwd 추출 실패→폴백→판정 뒤집힘)이고 순수 PS에선
  동일-판정 계약을 고정한다. impl 보고서가 이 환경 의존성을 정직히 기록했고, 가드 BOM strip의 실질 가치는
  **jq 경로(jq는 BOM에서 throw)와 MSYS 실행**을 위한 방어적 견고화임이 맞다(실 hook 입력은 BOM 없는
  UTF-8이라 production 동작은 애초 불변). **수용**: 회귀가 닫는 sn2의 실근원은 **하니스 fixture BOM**
  이었고 이를 no-BOM으로 닫았다 — 시나리오 9는 그 위에 계약 고정 + MSYS 판별을 더한 정당한 가드.
- **[T01] conventions finalize ⑤가 "건너뛴다" 종결 괄호 뒤에 콤마로 이어져 가독성이 약간 낮음** — "...
  재편집 금지), ⑤ **릴리즈 브랜치 정리**..." 구조라 ④의 마무리 문장과 ⑤가 한 문장에 붙는다. 의미는
  명확하고 "멱등·안전" 목록의 전용 항목이 상세를 담당하므로 **기능·정합 무영향**. 차기 문서 정리 시 ⑤를
  독립 문장/번호로 떼면 더 읽기 쉽다(비차단).

## 검증

**정적 직접 검토(교훈 #2 직접 적용)**:
- **가드 BOM strip 정합**: `tide-guard.sh`는 `bom=$(printf '\357\273\277'); input=${input#"$bom"}`
  (POSIX 파라미터 확장 — GNU `\x` 의존 없음), `tide-guard.ps1`은 `-replace '^(﻿|ï»¿)'`
  (UTF-8 디코드 BOM U+FEFF와 오디코드 3바이트 둘 다 방어). 양 escape가 실제 strip함을 단위 확인(U+FEFF·
  3바이트·no-BOM 입력 모두 기대 결과). `tide-guard.ps1` **파일 BOM 보존**(`EF BB BF`, 규약대로)·삽입 줄은
  ASCII. `tide-guard.sh` no-BOM 유지.
- **판정 계약 불변 실증**: 판별 셋업(cwd=차단 레포 / CPD=phase 없는 폴백)으로 strip 사본 vs no-strip
  사본을 비교 — 순수 PS에선 둘 다 동일 판정, **차단/통과·메시지·exit 2 불변** 확인. sed 앵커링
  `[{,[:space:]]"cwd"`은 표준 hook JSON(`{`·`,`·공백이 키 앞에 옴)을 모두 커버하며 multi-repo의 **sed
  폴백 경로(jq 부재)** 12/12 통과로 회귀 없음 입증.
- **finalize 브랜치 정리 규약 안전성**: ⑤가 ②~④ 성공 후에만·태그/릴리즈와 **독립 멱등**으로 수행되고,
  **현재 브랜치 안전**(기본 브랜치 체크아웃 선행), **로컬**(`branch -d` 우선 — squash/rebase 머지로 `-d`가
  거부되는 흔한 경우 **gh 머지 확인 전제 하에서만** `-D`, 미머지 강제삭제 금지), **원격**(`--delete`·
  없으면 무오류), **실패 비차단**(릴리즈 무효화 안 함)임을 정적 확인. squash-merge에서 `-d`가 거부되는
  현실 경로를 `-D` 폴백이 정확히 덮는 설계가 강점. 스킬은 규약 재서술 없이 포인터만 둠.
- **site-includes positive-control 실효성**: 추출은 파일 전체 최이른 매치(3행 우선), 단언은 그 토큰의
  3행 실재 확인 — 위치 드리프트·캡처 조작을 잡음(sn1 충족, 한계는 사소[sn1]에 명시). 양 셸 동일 의미·
  동수(+1). stale "BOM present" 주석 정정 확인.
- **인코딩·줄바꿈 규율**: `tide-guard.sh`/테스트 `.sh` no-BOM, 테스트 `.ps1` 2종 no-BOM·**ASCII-only
  (비-ASCII 0)**, `tide-guard.ps1` BOM 보존. 수정 후 테스트 `.ps1` 전부 LF 일관. `git diff --stat`로 의도
  변경만(줄바꿈 전 파일 플립 없음).
- **문서 결산 정합**: project-context 이월 원장 3행(sn1·sn2·raw-`$input` grep = fix/M27) + "남는 미반영"이
  **코드 잔여 0 / 라이브 도그푸딩만**으로 갱신. 도메인 개념(tide-guard 입력 내성·릴리즈 위생 finalize 정리)·
  하니스 인벤토리(site-includes positive-control·multi-repo 12/12) 반영. 버전 숫자 비복제 유지.

## 릴리즈 판정

**가능** — 추천 **v2.5.0 (minor)**.

근거: 차단 0. 권장 1건(줄바꿈 일관성)은 **리뷰에서 직접 수정**, 사소 3건은 수용(모두 비차단·후속 후보).
M27의 주 변경은 **`pr` 모드 finalize에 사용자 대면 가산 동작**(머지 후 다 쓴 릴리즈 브랜치 자동 정리)을
더한 것이다 — 새 동작 가산이므로 **minor**가 맞다(M24 sn2 "finalize 머지 후 마무리 자동화" = v2.4.0
minor 선례와 동형; M23 테스트 참조 구현 단일 원본화 같은 순수 내부 정리=patch와 달리 사용자 대면 능력을
더하므로 patch 아님). 동반된 sn1·sn2·가드 견고화는 내부 정리/견고화로, 모두 **판정 계약·메시지·exit 2를
바꾸지 않는다**(2.0 stable: minor=가산·정리·견고화). 2.0 stable 계약·M22 드리프트 가드(B1/B2/B3)·tide-guard
비확장 전부 불변(`git diff`로 hook 차단/통과 로직 무변경 확인 — strip은 파싱 전 입력 정규화일 뿐). M26
리뷰의 비차단 후속(sn1·sn2)과 오래 수용돼 온 raw-`$input` grep 거칠음을 **모두 fix로 종결**해, 코드로
