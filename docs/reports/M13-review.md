# M13 리뷰보고서 (review)

## 비판점

리뷰 결과 **차단 이슈 0건**. M13의 네 태스크는 완료 기준을 충족하고, 라이브 실증이
양 셸에서 재현된다. 아래는 비차단 권장·사소 항목이다.

### 차단 (0건)

없음. 가드 로직·인코딩 규약·격리·폴백이 sh·ps1 양쪽에서 실증되었고, 단일 레포 회귀가
동일하며, 1.0 안정 계약(커맨드 8종 호출명·역할, `.tide/phase`/guard 차단 규칙·메시지·exit 2,
보고서·마일스톤 형식)을 깨지 않는다. 모든 변경이 가산(additive)임을 확인했다.

### 권장 (2건)

1. **완료 기준 4(d)(산출물 앵커링)는 자동화로 미실증 — 수동 절차로 남음** — M13 완료 기준
   4의 (a)비-release 차단·(b)release 통과·(c)레포별 격리·(e)단일 레포 회귀는 라이브 하니스가
   exit 코드로 **기계 검증**한다. 그러나 (d)"tide 산출물이 각 자식 레포 안에만 생기고 상위
   폴더에는 생기지 않는다"는 **에이전트 행위 규약**(스킬 프롬프트의 대상 레포 앵커링)이라
   스크립트로 강제·검증되지 않는다. `tests/multi-repo/README.md`의 "세션 레벨 수동 절차"에
   재현 단계가 명시돼 있다. 비차단 사유: ① 기계적으로 강제되는 핵심(가드의 레포별 격리)은
   실증됨, ② 앵커링은 tide가 이미 전반에서 의존하는 프롬프트 규약과 같은 종류의 보장이다.
   다만 멀티 레포를 실사용에 투입하기 전 상위 폴더 단일 세션에서 `/tide:milestone→impl→
   release`를 자식 레포 대상으로 1회 수동 확인할 것을 권장한다(다음 사이클 후보).

2. **`.sh`의 jq 추출 분기 미실증(sed 폴백만 실증)** — 이 환경에 jq가 없어 `jq -r '.cwd'`
   경로는 정적 검토만 했고, sed 폴백 경로로 10/10 통과를 확보했다. jq 설치 환경에서 한 번
   더 돌려 동일 결과를 확인하면 좋다(동작 동일 기대 — jq는 JSON 이스케이프를 자동 처리하므로
   sed 분기보다 견고). 저위험.

### 사소 (4건)

3. **`.sh` 가드는 raw `$input`을, `.ps1`은 추출된 command를 검사하는 비대칭** — `.sh`는
   POSIX에서 명령 문자열의 따옴표·이스케이프를 견고하게 파싱하기 어려워 **의도적으로** 입력
   JSON 전체를 차단 정규식으로 grep한다(`.ps1`은 `ConvertFrom-Json`으로 command만 추출).
   부작용: 입력 JSON에 포함된 `cwd` 경로에 `git-commit`·`git/tag`·`git_push` 같은 부분
   문자열이 있으면 비-release 단계에서 **안전 명령까지 거짓 차단**될 수 있다. 단 방향이
   안전 측(과차단이지 누수 아님)이고 그런 레포 경로명은 드물다. **이 비대칭은 라우드-그렙을
   택한 의도적 트레이드오프**이며, `.sh`에서 command만 추출하도록 바꾸면 POSIX 명령 파싱
   취약성이 되살아난다 → **수정하지 않는다**. 기록만 남긴다(필요 시 정규식을 cwd 값 밖으로
   한정하는 후속 검토 가능).

4. **`docs/project-context.md`의 버전 표기 stale (0.7.0)** — 실제는 v1.0.0(릴리즈 이력 기준).
   M13 범위 밖의 **기존 드리프트**다(릴리즈 절차가 `plugin.json`만 범프하고 project-context는
   갱신 대상이 아니라 누적됨). M13 리뷰 diff를 깨끗이 유지하려 이번엔 고치지 않았다. 다음
   `/tide:kickoff`(브라운필드 갱신) 또는 별도 정리 태스크로 동기화 권장.

5. **마일스톤 문서의 잠정 파일명(setup.sh/setup.ps1)과 실제(run.sh/run.ps1) 불일치** — impl이
   러너 의미(setup+실증+teardown 통합)에 맞춰 `run.*`로 변경하고 완료보고서에 기록했다.
   `run.*`가 더 정확하다. 마일스톤 문서는 역사적 산출물이므로 사후 수정하지 않고 impl 보고서가
   기록으로 정합을 잡는다. 비고만.

6. **`tests/` 디렉터리가 플러그인 패키지에 포함됨** — 설치는 추적 트리를 미러링하므로 `tests/`도
   설치 캐시에 들어간다. project-context "배포 위생"의 수용 기조(런타임 무관 파일은 용량 외
   비용 없음 → 수용)와 일치한다. 도그푸딩 재현성에 유용하므로 **수용**. 공식 파일 한정 수단이
   생기면 `docs/`·`site/`와 함께 재검토.

## 수정 내용

- 리뷰 중 **코드/문서 수정 없음**. 차단 이슈가 없고, 권장·사소 항목은 모두 (a)의도적
  트레이드오프(이슈 3), (b)M13 범위 밖 기존 드리프트(이슈 4), (c)수동 검증 영역(이슈 1),
  (d)저위험 후속(이슈 2), (e)수용된 배포 위생(이슈 5·6)이라 이번 리뷰에서 손대면 M13의
  변경 footprint만 흐려진다. 모두 후속으로 명시한다.

## 검증

리뷰 시점에 라이브 하니스를 **직접 재실행**해 impl 보고서의 결과를 독립 재현했다.

- `sh tests/multi-repo/run.sh` → **PASS=10 / FAIL=0 (exit 0)** (sed 폴백 경로).
- `tests/multi-repo/run.ps1` → **PASS=10 / FAIL=0 (exit 0)**.
- 검증 시나리오(양 셸): 비-release 차단(commit·tag) → release 통과 → **레포별 격리**
  (A=release 시점에 B(impl) 차단) → 하위 디렉터리 cwd→레포 루트 해석 → 안전 명령(`git status`)
  통과 → cwd 부재 시 `CLAUDE_PROJECT_DIR` 폴백 차단 → non-repo+phase 부재 무차단 → 단일 레포
  회귀(루트 cwd impl 차단/release 통과).
- **인코딩 규약 재확인**: `tide-guard.sh` 선두 3바이트 `23 21 2f`(BOM 없음, `#!/`),
  `tide-guard.ps1` 선두 3바이트 `ef bb bf`(UTF-8 BOM). 규약 유지.
- **메타 용어 누수 0건**: M13가 추가한 conventions "멀티 레포 / 대상 레포" 절·project-context
  반영 줄에 제외 용어(외부 저장소명) literal 없음. 기존 1건은 snippet 마커(`[start:body]`) 밖
  도입 문단에 있어 사이트 인클루드 대상이 아님(설계대로).
- **1.0 계약 정합**: 가드 차단 규칙·메시지·exit 2 불변, `.tide/phase` 의미 불변, 커맨드 8종
  호출명·역할·argument-hint 보존(대상 레포 인자는 선택·가산), 단일 레포 동작 회귀 동일.

**검증하지 못한 잔여 리스크**: 산출물 앵커링·cwd 규율의 **세션 레벨 실동작**(권장 1)은
스크립트로 강제되지 않아 이번 리뷰에서도 자동 검증 대상이 아니다. README의 수동 절차로
다음 사이클에 한 번 눈으로 확인할 것을 권장한다. jq 추출 분기(권장 2)도 정적 검토에 그친다.

## 릴리즈 판정

**가능** — 추천 버전: **v1.1.0 (minor)**

- **완료 기준 충족**: 가드 repo-root 인식·폴백·인코딩(기준 1), conventions 단일 원본·계약 갱신·
  project-context 반영(기준 2), 스킬 8종 앵커링·release push 일반화·단일 레포 가산(기준 3),
  라이브 실증 (a)(b)(c)(e) 기계 검증(기준 4 — (d)앵커링은 수동 절차로 분리, 권장 1), 전부
  가산·1.0 계약 불파괴(기준 5) 모두 충족.
- **차단 이슈 처리 상태**: 차단 0건. 남은 항목은 전부 비차단(권장 2 / 사소 4)이며 안전 측·후속
  성격이라 릴리즈를 막지 않는다.
- **버전 근거**: 멀티 레포 위치별 격리라는 **신규 능력 가산** + 단일 레포 동작 불변·하위 호환
  일반화 + 커맨드 8종·phase/guard 계약 의미 유지 → SemVer **minor**가 정확하다(major 파괴 아님,
  patch보다 큼). 마일스톤 메타데이터의 목표 버전 v1.1.0과 일치.
