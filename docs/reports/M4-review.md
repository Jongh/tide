# M4 리뷰보고서 (review)

## 비판점

### 차단 (0건)

없음.

### 권장 (1건 — 리뷰 중 수정 완료)

1. **kickoff 스킬의 frontmatter `description`이 구 동작만 서술** — 본문에는 진행-중
   프로젝트 감지 + 구조 문서화(M4의 핵심)가 추가됐는데, 스킬 선택기·자동완성에 노출되는
   `description`은 여전히 "새 프로젝트에 … 골격 생성"이었다. README 커맨드 표는 갱신됐으나
   스킬 자기 설명이 그와 모순되고, 완료 기준 4("새 산출물·브라운필드 동작 기록")의 사용자
   대면 표면에 구멍이 있었다. 영향: 기능 손실은 없으나 발견성·문서 일관성 저하.

### 사소 (3건 — 수용)

2. **진행/신규 판별이 정성 휴리스틱** — 판별이 커밋·산출물·소스 "규모"의 정성 신호에
   의존해 경계 사례(커밋 1~2개, 소스 거의 없음)에서 오판 여지가 있다. 다만 양방향 모두
   실패가 완만하다 — 신규를 진행-중으로 오판하면 얇은 project-context.md가 생기고,
   진행-중을 신규로 오판하면 문서가 생략될 뿐(재실행으로 복구). 프롬프트 구동 판별의
   합리적 트레이드오프로 수용.
3. **새 세션 재설치 검증은 release 후로 연기** — 편집 대상은 저장소 원본 `skills/`이고
   설치된 플러그인 캐시는 release+재설치 전까지 구 스킬을 쓴다. 실제 `/tide:kickoff` 호출
   검증은 release 후 도그푸딩에서 수행한다(M3와 동일 패턴). 이번엔 새 로직의 자기적용으로
   동작을 실증했고, 변경이 순수 프롬프트 텍스트 추가라 메커니즘 리스크가 낮아 수용.
4. **`docs/project-context.md`의 release 포함 여부** — 런타임 산출물이지만 이 저장소에선
   tide 자신을 기술하는 실제 문서다. release 커밋에 포함하는 것이 자연스러우나, 최종
   결정은 release 단계에 맡긴다.

## 수정 내용

  진행 중 프로젝트면 구조 문서화 (…)"로 갱신. 더불어 README 설치 절의 "새 프로젝트에서
  시작하세요" 문구를 "프로젝트에서 시작하세요 (신규·진행 중 모두 지원)"로 보정.
  저장소 전체 `새 프로젝트` grep으로 잔존 구 표현이 없음을 재확인(마일스톤 이력 제외).

  — 스킬 본문의 "신규면 단계 7 생략" 분기로 충족. ③ milestone·impl의 조건부 참조 —
  두 SKILL.md에 "있으면 먼저 읽고, 없으면 평소대로" 명시 확인. ④ conventions·README 반영
  — "프로젝트 컨텍스트" 절 + 커맨드 표/저장소 구조 갱신 확인. **4개 기준 전부 충족.**
- **연결 일관성**: `project-context` grep으로 생성처(kickoff)·소비처(milestone·impl)·
  문서(conventions·README)·산출물 6개 파일이 빠짐없이 연결됨을 확인.
- **부수효과 분리 준수**: 리뷰 중 수정은 문서/프롬프트 텍스트뿐, git 작업 없음.
  워킹트리는 예상 변경(수정 5 + 신규 M4~M6·project-context·M4-impl)만 포함.

  release 후 도그푸딩에서 자연 확인된다.
