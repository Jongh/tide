# M28 — tide-guard 읽기/쓰기 구분: git 읽기 명령 오차단 해소(서브커맨드 앵커링 + `tag` 목록 허용)

## 목표

이 마일스톤이 끝나면 **tide-guard가 git *읽기* 작업과 *쓰기* 작업을 구분**한다 — `release`가 아닌
phase에서도 맥락 파악용 git 읽기(커밋 내용 읽기, **현재 태그 목록 읽기**, 메시지 검색, 이력 파일
읽기)는 통과하고, 실제 저장소/원격을 바꾸는 쓰기(`commit`·태그 *생성/삭제*·`push`)만 차단한다.
가드의 **보호 경계(쓰기 차단)는 그대로 보존**하면서, 부분 문자열 매칭이 만들어 온 읽기 오차단을
제거한다. 차단되던 *쓰기* 집합은 한 건도 줄지 않고(보호 불변), 오차단되던 *읽기* 집합만 풀린다.

## 배경

- **출처**: 사용자 요구 — "git 커밋 내용 읽기·현재 태그 읽기 같은 읽기 작업은 release 이외 상황에서도
  작업 맥락 파악에 필요한데 가드가 막는다. 해당 명령을 정리하고 작업 제어를 조정해 달라."
- **현 동작(`hooks/tide-guard.{sh,ps1}`)**: phase가 존재하고 `release`가 아닐 때, 명령 문자열에
  정규식 `git[^&|;]*[^a-zA-Z](commit|tag|push)([^a-zA-Z]|$)`가 걸리면 exit 2로 차단한다. 이는 verb를
  git **서브커맨드 위치**로 앵커링하지 않고 **부분 문자열로 어디서든** 찾기 때문에, 다음 *읽기* 명령을
  오차단한다(현행 가드 정규식에 실측):
  - **태그 목록(읽기)**: `git tag` · `git tag -l` · `git tag --list` · `git tag -n5` · `git tag --sort=…`
    · `git tag --contains <c>` — `tag`가 *목록(읽기)*과 *생성(쓰기)* 양면이라 verb 한 단어로 구분 못 함.
  - **메시지 검색(읽기)**: `git log --grep=commit` · `--grep=tag` · `--grep=push` — verb 글자가 옵션 값에 들어감.
  - **이력 파일 읽기**: `git show HEAD:src/tag.rs` · `git show HEAD:internal/commit/parser.go` ·
    `git log -- path/push.md` — verb 글자가 경로(pathspec)에 들어감.
  - **유지보수 읽기(니치)**: `git cat-file commit HEAD` · `git commit-graph verify` — verb 글자가
    오브젝트 타입/다른 서브커맨드 이름에 들어감.
- **이미 통과(보존 대상)**: `git log` · `git show` · `git diff` · `git status` · `git blame` ·
  `git rev-parse` · `git rev-list`, 그리고 태그 읽기 대안 `git describe --tags` · `git for-each-ref refs/tags`
  · `git ls-remote --tags` · `git show-ref --tags`, 전역 옵션 접두 `git -C <dir> …` · `git -c k=v …`.
- **두 뿌리**: ① **부분 문자열 매칭** — verb가 서브커맨드가 아니라 옵션 값/경로/다른 서브커맨드 이름에
  들어가도 매칭. ② **`tag`의 양면성** — `commit`·`push`는 항상 쓰기라 문제없으나 `git tag`는 목록(읽기)과
  생성/삭제(쓰기)가 한 verb. 이 둘을 닫는다.
- **기준 계약**: 2.0 stable 계약(커맨드 11종·오케스트레이션 규약·`.tide/phase`/tide-guard·보고서/마일스톤
  형식). 본 변경은 tide-guard의 **판정을 정련**한다 — 가드가 내리던 **차단(쓰기) 판정은 불변**이고
  **오차단되던 읽기만 통과로 바뀐다**. 호환 파괴 아님(통과하던 것이 차단되지 않으며, 차단하던 쓰기는
  그대로 차단). 새 `/tide` 커맨드·토큰·phase 의미 변경 0. 가드 게이팅(phase 해석·BOM strip·cwd 추출,
  M27 견고화)은 불변 — 이번엔 **verb 매칭부**만 바꾼다.

## 판정 계약 (구현·테스트의 단일 원본)

가드는 명령을 `&`/`|`/`;`로 구분되는 각 git 호출 단위로 보고, 그 호출의 **서브커맨드**(= `git` 뒤
전역 옵션을 건너뛴 첫 비-옵션 토큰; `-C <dir>`·`-c <kv>`·`--git-dir`·`--work-tree`·`--namespace`·
`--super-prefix`·`--exec-path` 등 인자 소비 전역 옵션은 그 인자까지 건너뜀)를 본다. phase가 존재하고
`release`가 아닐 때:

- 서브커맨드가 정확히 `commit` 또는 정확히 `push` → **차단**(항상 쓰기).
- 서브커맨드가 `tag`:
  - **읽기 형태 → 통과**: 뒤에 아무 인자 없거나, *읽기 옵션만* 있을 때 —
    `-l`/`--list`, `-n[N]`, `--contains`/`--no-contains`, `--points-at`, `--merged`/`--no-merged`,
    `--sort[=…]`, `--column`/`--no-column`, `--format[=…]`, `-i`/`--ignore-case`, `-v`/`--verify`
    (목록 옵션이 있으면 그 뒤 위치 인자는 *패턴*이므로 읽기).
  - **쓰기 형태 → 차단**: 쓰기 옵션이 있거나(`-a`/`--annotate`·`-s`/`--sign`·`-u`/`--local-user`·
    `-m`/`--message`·`-F`/`--file`·`-e`/`--edit`·`-f`/`--force`·`-d`/`--delete`·`--create-reflog`),
    *목록 옵션 없이* 위치 인자(태그명)가 올 때(= 생성).
- 그 외 서브커맨드(`log`·`show`·`diff`·`status`·`cat-file`·`commit-graph`·`describe`·`for-each-ref`
  ·`ls-remote`·`show-ref` 등) → **통과**. verb 글자가 옵션 값(`--grep=commit`)·경로(`HEAD:src/tag.rs`)·
  복합 서브커맨드 이름(`commit-graph`)에 들어가도 서브커맨드가 아니므로 매칭하지 않는다.

**검증 표(이 표가 곧 T03 테스트 케이스다)**

| 반드시 통과(읽기) | 반드시 차단(쓰기) |
|---|---|
| `git tag` · `git tag -l` · `git tag --list` · `git tag -l 'v2.*'` · `git tag -n5` · `git tag --sort=-creatordate` · `git tag --contains HEAD` · `git tag --points-at HEAD` · `git tag -v v2.5.0` | `git tag v1.2.3` · `git tag -a v1 -m m` · `git tag -s v1` · `git tag -f v1` · `git tag -d v1` · `git tag --delete v1` |
| `git log --grep=commit` · `git log --grep=tag` · `git log --grep=push` | `git commit` · `git commit -m msg` · `git commit --amend` |
| `git show HEAD:src/tag.rs` · `git show HEAD:internal/commit/parser.go` · `git log -- path/push.md` | `git push` · `git push origin main` · `git push --tags` · `git push -f` |
| `git cat-file commit HEAD` · `git commit-graph verify` | `git -C ../other commit -m x` · `git -c k=v push` |
| `git log` · `git show HEAD` · `git diff` · `git status` · `git describe --tags` · `git for-each-ref refs/tags` · `git ls-remote --tags` · `git show-ref --tags` · `git -C ../x log` · `git -c k=v log` | (위 쓰기 집합은 현행과 동일 — 차단 축소 0) |

phase가 `release`면 위와 무관하게 전부 통과(불변). phase 파일 없으면 무차단(불변).

### M28-T01: 판정 계약을 `docs/conventions.md` tide-guard 절에 단일 원본으로 정의

- **변경 파일**: `docs/conventions.md`
- tide-guard 절(현 "동작: `.tide/phase`가 `release`가 아닌 동안 git commit/tag/push … 차단")을 **읽기/쓰기
  구분**으로 정련한다 — 위 "판정 계약" 절의 내용을 규약 단일 원본으로 기술한다: ① 차단 대상은 git
  **쓰기 서브커맨드**(`commit`·`push`·태그 *생성/삭제*)이고, ② git **읽기**(커밋 읽기·태그 목록·메시지
  검색·이력 파일 읽기)는 phase와 무관하게 통과하며, ③ 판정은 verb를 **서브커맨드 위치에서** 본다(부분
  문자열 아님), ④ `tag`의 읽기/쓰기 형태 구분 기준(읽기 옵션 목록 + "목록 옵션 없는 위치 인자 = 생성").
- 안내 메시지의 의미가 바뀌므로(이제 "쓰기"만 차단) 메시지 문안 정합은 T04에서 hook과 함께 맞춘다(여기선
  규약 텍스트만).
- **불변 명시**: phase 게이팅·BOM strip·cwd 추출(M27 견고화)·"phase 없으면 무차단"·"`release`에서 전부
  통과"·"`idle` 포함 비-release에서 *쓰기* 차단"은 불변. `release`에서 가드 해제(phase 삭제)로 모든 git
  허용도 불변.

### M28-T02: hook verb 매칭부 교체 (양 셸 동기화) (deps: M28-T01)

- **변경 파일**: `hooks/tide-guard.sh`, `hooks/tide-guard.ps1`
- 현 단일 차단 정규식(`git[^&|;]*[^a-zA-Z](commit|tag|push)([^a-zA-Z]|$)`)을 판정 계약대로 교체한다.
  **게이팅 로직(입력 읽기·BOM strip·cwd→root→phase 해석·`phase=release`면 exit 0)은 한 줄도 바꾸지
  않고**, 그 뒤 "차단 여부" 결정부만 교체한다.
- **권장 경로 (A) — 확장 정규식 2분기**: (i) 항상-쓰기 verb를 서브커맨드로 앵커링한 차단 패턴
  (`commit`·`push`가 git 호출의 서브커맨드 토큰이고 뒤가 단어 경계 — `commit-graph`·`--grep=commit`·
  경로 제외), (ii) `tag` 쓰기 형태 차단 패턴(읽기-형태 화이트리스트에 **해당하지 않는** `git … tag`).
  읽기-형태 화이트리스트는 위 계약의 읽기 옵션 alternation을 단일 문자열로 양 셸에 **동일하게** 둔다.
  전역 옵션 접두(`-C <dir>`·`-c <kv>` 등)는 서브커맨드 토큰 탐색 시 건너뛴다.
- **폴백 경로 (B) — 최소 토큰 스캔**: 정규식이 비대해지면, 각 git 호출(`&|;`로 분할)에서 토큰을 훑어
  전역 옵션(+인자 소비형)을 건너뛰고 첫 서브커맨드를 얻은 뒤, `commit`/`push`면 차단·`tag`면 나머지
  인자에서 쓰기 신호를 보고 분기한다. sh는 `case`/`set --`, ps1은 `-split`로 자기완결 구현(외부 source
  금지 — hook 단독 실행). **어느 경로든 관찰 가능한 판정(검증 표)은 동일**해야 한다.
- **양 셸 동기화 불변(필수)**: `.sh`(원본)·`.ps1`(보조 사본)을 **함께** 갱신하고 동일 판정을 내린다
  (project-context "가드 스크립트 수정 시 두 사본 함께"). 이 레포의 #1 반복 문제가 sh↔ps1 드리프트이므로,
  두 사본이 검증 표 전 케이스에서 **동일 결과**임을 T03이 양 셸로 고정한다.
- **인코딩 규율**: `tide-guard.sh` no-BOM, `tide-guard.ps1` BOM 포함 UTF-8·삽입 줄 ASCII(conventions 인코딩 절).

### M28-T03: `tests/multi-repo` 가드 하니스에 검증 표 케이스 추가 (양 셸) (deps: M28-T02)

- **변경 파일**: `tests/multi-repo/run.sh`, `tests/multi-repo/run.ps1`
- 현 하니스는 실제 `hooks/tide-guard.{sh,ps1}`에 hook 입력 JSON을 넣어 phase별 block/allow를 `chk`로
  단언한다(repo-root 인식·BOM 회귀 등). 여기에 **phase=비-release(`impl`/`idle`)에서**:
  - **읽기-통과 케이스**: 검증 표 좌열(태그 목록 전 형태·`--grep=commit/tag/push`·이력 경로 `HEAD:…tag.rs`·
    `cat-file commit`·`commit-graph verify`)이 **통과(exit 0)** 함을 단언한다. 이들이 현행 가드에선
    *차단*되므로, 이 케이스는 T02 이전엔 실패하고 이후엔 통과해 정련을 증명한다.
  - **쓰기-차단 보존 케이스**: 검증 표 우열(`git commit`·`git tag v1`·`-a`·`-d`·`git push`·`--tags`·
    전역 옵션 접두 `git -C … commit`/`-c k=v push`)이 **여전히 차단(exit 2)** 됨을 단언한다(보호 불변 —
    차단 축소 0의 회귀 가드).
  - **release 불변**: phase=`release`에서 위 쓰기 케이스가 모두 통과함을 단언(기존 시나리오 보존).
- 양 셸 **동일 케이스·동일 판정**(카운트 정합). 기존 시나리오(repo-root 인식·폴백·BOM 회귀)는 보존하고
  카운트만 증가시킨다. 이 스크립트를 호출하는 명령줄 자체엔 차단 패턴이 없어야 한다(활성 가드 자가 차단
  방지 — 헤더 주석 규율 유지; 픽스처 명령 문자열은 데이터 파일/변수로 다뤄 호출줄에 노출하지 않는다).
- **음성 통제**: 읽기-통과 단언이 *틀린 이유로* green이 되지 않도록(예: 가드가 통째로 무차단이 돼버림),
  같은 phase에서 쓰기 케이스가 차단됨을 같은 셋업으로 함께 단언해 "가드가 살아 있으면서 읽기만 통과"임을
  고정한다.

  차단, 읽기는 통과)함을 한 줄 반영(규약 단일 원본 포인터 유지).

## 완료 기준

1. **읽기 통과**: phase가 비-release(`impl`/`idle`)여도 검증 표 좌열 git 읽기 명령(태그 목록 전 형태·
   `--grep=commit/tag/push`·이력 경로 `HEAD:…tag.rs`/`…commit/…`·`cat-file commit`·`commit-graph verify`·
   기존 통과 명령)이 양 셸 가드에서 **통과(exit 0)** 한다.
2. **쓰기 차단 보존(보호 불변)**: 동일 phase에서 검증 표 우열(`git commit`·`git tag <name>`/`-a`/`-s`/`-f`/
   `-d`/`--delete`·`git push`/`--tags`/`-f`·전역 옵션 접두 `git -C … commit`/`-c k=v push`)이 **여전히
   차단(exit 2)** 된다 — 차단되던 쓰기 집합은 한 건도 줄지 않는다.
3. **서브커맨드 앵커링**: verb(`commit`·`tag`·`push`)가 옵션 값·경로·복합 서브커맨드 이름(`commit-graph`)에
   글자로 들어가는 경우는 차단하지 않는다(서브커맨드일 때만 판정).
4. **`tag` 읽기/쓰기 구분**: `git tag` 목록/조회 형태는 통과, 생성/삭제 형태는 차단(검증 표대로).
5. **양 셸 동기화**: `tide-guard.sh`·`tide-guard.ps1`이 검증 표 전 케이스에서 **동일 판정**을 내리고,
   `tests/multi-repo`가 양 셸 동일 케이스·카운트로 이를 고정한다. 기존 시나리오(repo-root 인식·폴백·BOM
   회귀, M27)는 보존되고 PASS 카운트만 증가, 전 하니스 exit 0(M27 baseline 동작 보존).
6. **게이팅 불변**: phase 없으면 무차단, `release`면 전부 통과, BOM strip·cwd→root→phase 해석(M27 견고화)
   불변. 변경은 verb 매칭부에 한정.
7. **2.0 stable 계약**: 커맨드 11종·오케스트레이션 규약·`.tide/phase` 의미·보고서/마일스톤 형식 불변,
   새 `/tide` 커맨드·토큰 0, 가드 양 사본 함께 갱신, 인코딩 규율 준수. 부수효과 분리 유지(impl은 git
   무변경). **가드 판정 변경 사이클이므로 리뷰는 적대 검증으로 수행**(M20 회고: 계약·안전 핵심 사이클의
   표준 게이트) — 특히 "차단되던 쓰기가 통과로 새지 않는지"(보호 불변)를 반증 시도로 확인.
