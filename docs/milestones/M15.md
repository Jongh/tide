# M15 — fleet 출력 결정성·정합: 분류 taxonomy 단일화 + advisory 인자 명시 + 숨김 디렉터리 규약

## 목표

이 마일스톤이 끝나면 **`/tide:fleet`의 advisory 출력이 결정적이고 스킬·규약·테스트 레퍼런스가
한 분류 체계로 일치한다.** 구체적으로 (1) 교차 요약 버킷이 레포 사이클 위치(position)와 1:1로
대응하는 **정규 taxonomy**로 통일되고(스킬이 임의로 합산/분리하지 않음), (2) advisory 다음 커맨드가
`/tide:status` 규칙대로 **정확한 인자**를 포함하며(impl→`/tide:impl M{N}`, release→`/tide:release v{추천}`),
(3) 발견 규약이 **숨김(dot) 디렉터리를 무시**함을 명문화한다. 이 셋이 `skills/fleet/SKILL.md`·
`docs/conventions.md`·`tests/fleet/`에서 동일하게 표현돼, fleet 실행 결과가 레퍼런스(`tests/fleet/`)와
일치한다. fleet의 호출명·역할·읽기 전용·부수효과 분리 불변은 그대로다.

## 배경

M14 릴리즈(v1.2.0) 후 사용자가 `/tide:fleet`을 멀티 레포 샌드박스에서 실제 실행해 검증하던 중,
스킬 출력과 테스트 레퍼런스(`tests/fleet/`·`expect.ps1`) 사이의 **표기 불일치 3건**을 발견했다
(의사결정 영향은 없는 cosmetic이지만 결정성·정합 결함):

- **(b, 핵심)** 교차 요약 버킷 불일치 — `skills/fleet/SKILL.md`는 "release 가능 / review 대기 /
  **impl·milestone 진행(합산)**"의 3버킷으로 서술하나, `tests/fleet/`·`expect.ps1`은 release-ready /
  review-pending / impl-inprogress / milestone-needed의 4분류를 쓴다. **스펙↔레퍼런스가 애초에 어긋나**
  어느 쪽으로 출력되든 한쪽과 불일치한다.
- **(a)** advisory 인자 변동 — impl 진행 레포 권고가 `/tide:impl`로도, `/tide:impl M{N}`로도 나온다
  (프롬프트가 인자 포함을 명시하지 않아 run-to-run 변동).
- **(c)** 숨김 디렉터리 — 세션 폴더에 `.claude` 등 dot 디렉터리가 있으면 올바르게 제외되나, 발견
  규약이 "숨김 무시"를 명문화하지 않아 제외 표기가 들쭉날쭉하다(동작은 정상).

원인은 fleet이 프롬프트 스킬이라 출력 형식이 산문으로만 규정돼 결정성이 약한 데 있다. 해법은 **정규
분류 taxonomy를 단일 원본으로 못박고** 스킬·규약·테스트가 모두 그것을 인용하는 것 — "규약↔실행/
인프라 동기화" 메타 규칙대로 세 표면을 같은 사이클에 정렬한다. 기능 추가가 아니라 정합·견고화이므로
**patch**다.

## 정규 분류 taxonomy (이 마일스톤의 단일 기준 — T01·T02·T03이 모두 이를 인용)

각 자식 레포의 **position**은 `/tide:status` 다음 커맨드 판단 규칙을 그대로 적용해 정확히 하나로
분류한다. 교차 요약은 이 position들을 1:1로 집계한다(합산·분리 금지).

| position | 조건 (최신 마일스톤 M{N} 기준) | advisory 다음 커맨드 |
|---|---|---|
| `milestone 필요` | `docs/milestones/M*.md` 없음 | `/tide:milestone` |
| `impl 진행` | M{N} 있고 `M{N}-impl.md` 없음 | `/tide:impl M{N}` |
| `review 대기` | `M{N}-impl.md` 있고 `M{N}-review.md` 없음 | `/tide:review` |
| `보완 필요` | `M{N}-review.md` 판정 "불가" | 보완 후 `/tide:impl M{N}` |
| `release 가능` | `M{N}-review.md` 판정 "가능" | `/tide:release v{추천}` |

교차 요약 형식(고정): `release 가능 N / review 대기 N / impl 진행 N / milestone 필요 N / 보완 필요 N`
(해당 0건 버킷도 표기하거나 0으로 명시 — 임의 합산하지 않는다).

발견 규약 보강: 대상 부모의 직속 하위 중 **숨김(이름이 `.`으로 시작하는) 디렉터리는 무시**한다
(`.git`·`.claude` 등). 그 외 git 레포 AND tide 산출물 조건은 그대로.

## 태스크 상세

### M15-T01: fleet 스킬 — 정규 taxonomy 반영

- **변경 파일**: `skills/fleet/SKILL.md`
- "출력" 절의 **교차 요약**을 위 정규 5버킷 형식으로 교체("impl·milestone 진행 합산" 서술 제거 —
  position과 1:1, 합산 금지).
- **advisory 다음 행동 계획**에 position→커맨드 매핑을 위 표대로 **인자 포함**해 명시:
  impl 진행→`/tide:impl M{N}`(반드시 마일스톤 번호 포함), release 가능→`/tide:release v{추천}`,
  review 대기→`/tide:review`, milestone 필요→`/tide:milestone`, 보완 필요→보완 후 `/tide:impl M{N}`.
- **자식 tide 레포 발견** 절에 "이름이 `.`으로 시작하는 **숨김 디렉터리는 무시**한다(`.git`·`.claude`
  등)" 한 줄 추가.
- 읽기 전용·부수효과 분리·"의존성 정렬 미지원(2층 전)" 서술은 그대로 유지.

## 완료 기준

1. `skills/fleet/SKILL.md`의 교차 요약이 정규 5버킷(release 가능/review 대기/impl 진행/milestone 필요/
   보완 필요)과 1:1이고 합산 서술이 없으며, advisory 권고가 인자를 포함(impl→`/tide:impl M{N}`,
   release→`/tide:release v{추천}`)하고, 발견 규약에 숨김 디렉터리 무시가 명시된다.
2. `docs/conventions.md` "멀티 레포 오케스트레이션" 절의 advisory 계획 규칙·발견 규약이 같은 taxonomy로
   정합되어, 스킬과 규약이 동일한 분류·요약·인자·숨김 규칙을 서술한다(스펙↔스킬 불일치 해소).
3. `tests/fleet/run.sh`·`run.ps1`이 T01 taxonomy 라벨·요약에 정합하고, 숨김 디렉터리 제외·`보완 필요`
   (불가) 분류 시나리오가 추가되어 Git Bash `sh`·PowerShell 양쪽에서 전부 통과한다(README 갱신).
4. 이 변경이 전부 정합·견고화(기능 추가 없음, fleet 호출명·역할·읽기 전용·부수효과 분리 불변, 커맨드
   9종·1.0 안정 계약 무관)이며 **patch**임이 확인된다.
