# M26 — 잔여 후속 결산: 참조 구현 BOM 헬퍼 단일 원본화 + 사이트 스니펫 인클루드 자기완결 검증(환경-이월 종결)

## 목표

이 마일스톤이 끝나면 **코드로 손볼 수 있는 마지막 잔여 후속 두 건이 결정적으로 닫힌다**. 첫째,
참조 구현의 BOM 제거 헬퍼(`strip_bom`/`StripBom`)가 트리 전체에 **정의 1개씩**만 남아(현재 `tests/lib`
공유본 + `tests/fleet-verify` 로컬 복제의 이중 정의), 참조 구현 이중성 군집의 마지막 코드성 복제면이
사라진다. 둘째, M22부터 매 사이클 "환경-이월"로 미뤄온 **사이트 스니펫 인클루드 검증**이 mkdocs
없이도 돌아가는 자기완결 하니스로 **로컬에서 결정적으로** 검증되어, 인클루드 타깃·섹션 마커·제외 용어
누수의 로컬 사각지대가 닫힌다(실제 `--strict` 렌더는 CI 몫으로 명시 유지). 사용자 대면·계약 변경은 없다.

## 배경

M26 scoping sweep(전 `docs/reports/M*-review.md` 25건 + 코드 + 회고 교차 조사)로 확인한 바, tide의 내부
백로그는 M20 "이월 항목 처분 원장" 이후 매우 엄격히 추적·소진되어 **코드/스크립트로 손볼 진짜 열린 잔여는
두 건뿐**이며 둘 다 저위험이다.

- **참조 구현 BOM 헬퍼 미추출 (M24-review sn3 → M25-review sn3, 2사이클 연속 "잔존")**: M23이
  `discover`/`toposort`를, M24가 `read_deps`(+`strip_bom`/`dep_name`)를 `tests/lib`로 추출해 복제
  표면적을 4→1로 축소했으나, `tests/fleet-verify`는 `.tide-fleet/integration` 훅을 파싱하느라 `deps`가
  아닌 `discover`만 source한다. 그래서 `strip_bom`/`StripBom` **로컬 복제본**을 그대로 들고 있다
  (`tests/lib/deps.{sh,ps1}`의 공유본과 **바이트 동일**). "저위험 정리 후보"로 두 사이클 명시 이월된,
  참조 구현 이중성 군집의 마지막 코드성 잔여다.
- **사이트 빌드 출력 검증의 로컬 사각지대 (M22-review sn1 → M23·M24·M25 다음 단계, 연속 "환경-이월")**:
  `docs/conventions.md`의 "릴리즈 빌드 출력 검증"은 **빌드된** 사이트 출력에서 제외 용어 0건을 요구하지만,
  이를 강제하는 수단이 갈라져 있다 — (a) `mkdocs build --strict`(스니펫 `check_paths:true`)는 **CI에서만**
  (`.github/workflows/deploy-pages.yml`), (b) 제외 용어 0건 스캔은 release 스킬의 **수기 LLM 단계**,
  (c) `tests/discover` B2는 사이트 페이지가 "스니펫 셸"인지만 정적 확인할 뿐 **인클루드 타깃·섹션 마커를
  해석하지 않는다**. 로컬에 mkdocs가 없어 실제 스니펫 해석·출력 스캔은 매 사이클 CI/배포로만 회수돼 왔다.
  이는 mkdocs 풀빌드 없이도 **결정적 자기완결 하니스**로 로컬에서 닫을 수 있다(아래 T02). repo가 이미
  신뢰하는 드리프트 가드 계열(`tests/discover`·`tests/lib` 단일 원본화)과 conventions의 "규약↔실행을
  같은 사이클에 배선" 원칙에 정확히 부합한다.

회고 교차 결론도 같다: 안정 계약을 깨는 부채는 없고 정리 백로그는 0으로 수렴 중이며, 위 두 건이 닫히면
남는 미반영은 **의도적 수용**(예: `tide-guard.sh`의 raw-`$input` grep 거칠음 — M13 사소3→M18 사소6,
POSIX 명령 파싱 취약성을 피하려는 "수정하지 않는다"로 명기된 트레이드오프)과 **라이브 도그푸딩 영역**
(gh 게시/`pr` finalize 라이브 실증 — 다음 `pr` 도그푸딩 회수 예정)뿐이다. **이 둘은 M26 범위 밖**이다
(전자는 안전 핵심 가드의 의도적 수용 항목이라 가산 정리 사이클에 끼우지 않고, 후자는 코드 부채가 아닌
실증 회수다). 따라서 M26은 코드성 잔여 두 건만 결산하는 **저위험 내부 정리 사이클**이다(M23 정리 patch
선례와 동형).

## 태스크 상세

### M26-T01: 참조 구현 BOM 헬퍼(`strip_bom`/`StripBom`) 단일 원본화

- **변경 파일**: `tests/lib/deps.sh`, `tests/lib/deps.ps1`, `tests/fleet-verify/run.sh`,
  `tests/fleet-verify/run.ps1` (+ 채택 경로에 따라 신규 `tests/lib/encoding.{sh,ps1}` **또는** 기존
  `tests/lib/discover.{sh,ps1}`)
- **현재 상태(sweep 확인)**: 언어별로 **독립 정의 2개**가 존재한다.
  - sh: `tests/lib/deps.sh:19`(공유본 — `read_deps`가 사용, fleet·fleet-cycle이 source) + `tests/fleet-verify/run.sh:33`(로컬 복제, `read_hook`가 사용). 두 본문은 바이트 동일(`strip_bom() { sed '1s/^\xEF\xBB\xBF//'; }`).
  - ps1: `tests/lib/deps.ps1:21`(공유본) + `tests/fleet-verify/run.ps1:37`(로컬 복제). 두 본문 동일(`if ($null -ne $s -and $s.Length -gt 0 -and [int]$s[0] -eq 0xFEFF) { return $s.Substring(1) }`).
  - source 순서는 `discover → deps → toposort`(deps는 `read_deps`가 `strip_bom`을 쓰므로 자기 BOM 헬퍼 홈 뒤에, toposort는 deps 뒤에 와야 함). fleet-verify는 `.tide-fleet/integration`을 파싱하느라 **`discover`만** source하고 `deps`를 안 써서 사본을 들고 있다.
- **목표 상태**: `strip_bom`/`StripBom` 정의가 **언어별로 정확히 1개**. 모든 소비자(deps의 `read_deps`,
  fleet, fleet-cycle, **그리고 fleet-verify의 `read_hook`/`ReadHook`**)가 그 단일 정의를 source해서 쓰고,
  `tests/fleet-verify/run.{sh,ps1}`의 로컬 정의는 삭제된다.
- **권장 경로 (A)**: BOM 헬퍼는 deps 파싱 전용이 아니라 **범용 인코딩 헬퍼**이므로, 단일 책임의 신규
  `tests/lib/encoding.{sh,ps1}`로 승격해 네 하니스 모두 체인 **맨 앞**에서 source한다
  (`encoding → discover → deps → toposort`). `deps.{sh,ps1}`는 로컬 정의를 지우고 "`strip_bom`은 앞서
  source된 `encoding`에서 온다"로 주석 갱신. fleet-verify는 `encoding` source 한 줄을 추가하고 로컬 정의 삭제.
- **폴백 경로 (B)**: 신규 파일을 피하려면 `strip_bom`/`StripBom`을 이미 모두가 첫 번째로 source하는
  `tests/lib/discover.{sh,ps1}`로 이동한다(fleet-verify도 discover를 이미 source하므로 무료 획득). deps·fleet-verify
  로컬 정의 삭제 + 주석 갱신. 단점: 인코딩 헬퍼를 discover 책임에 섞음 — 그래서 A를 권장하되, 신규 파일
  없이 끝내야 하면 B를 쓴다. **어느 경로든 관찰 가능한 종료 상태(정의 1개·전 하니스 green)는 동일**.
- **엣지/주의**: ① 동작 **바이트 동일** 유지(헬퍼 본문 변경 금지, 단순 이동·재배선). ② source 순서 불변식
  보존(BOM 헬퍼 홈 → discover → deps → toposort; deps가 standalone으로 source되는 경로가 있으면 그 경로도
  BOM 헬퍼를 먼저 source하도록 보장). ③ 인코딩 규율: `.sh`는 BOM 없음, `.ps1`은 BOM 있음·소스 ASCII-only
  (`docs/conventions.md` 인코딩 절). ④ `deps.{sh,ps1}`의 "`read_deps`와 직접 헬퍼 `strip_bom`/`dep_name`은
  단일 deps-parse 규칙" 류 주석을 새 홈을 가리키도록 정합. ⑤ `tests/fleet-verify/run.ps1:112`의
  `$bom = [char]0xFEFF`는 **BOM 픽스처 작성용**(헬퍼 정의 아님)이라 건드리지 않는다.
- **검증**: `tests/fleet`·`tests/fleet-cycle`·`tests/fleet-verify`·`tests/multi-repo`의 `run.sh`+`run.ps1`이
  양 셸에서 exit 0, **M25 baseline과 PASS 수 동일**. `grep`로 `strip_bom`(sh)·`StripBom`(ps1) **정의가 각
  1개**만 남고 fleet-verify 로컬 복제가 사라졌음을 확인.

### M26-T02: 사이트 스니펫 인클루드 자기완결 검증 하니스 `tests/site-includes/run.{sh,ps1}` 신설

- **변경 파일**: 신규 `tests/site-includes/run.sh`, `tests/site-includes/run.ps1`
  (+ 디렉터리 컨벤션에 맞춰 짧은 `tests/site-includes/README.md` 선택)
- **무엇을**: mkdocs **설치 없이** 사이트 스니펫 셸의 인클루드가 실제로 해석되는지 결정적으로 검증한다.
  기존 `tests/discover/run.{sh,ps1}` 패턴을 그대로 미러링한다(스크립트 위치에서 ROOT 산출, `chk`/`Chk`
  카운터, PASS/FAIL 집계, exit 0/1, BOM 규율).
- **검사 항목**(sweep로 확인한 현 구조 — 4개 스니펫 셸):
  1. `site/docs/*.md`에서 인클루드 지시 `--8<-- "<target>:<section>"`를 열거한다. 현재 4건:
     `changelog.md → CHANGELOG.md:notes`, `commands.md → docs/commands.md:body`,
     `conventions.md → docs/conventions.md:body`, `orchestration.md → docs/orchestration.md:body`.
  2. 각 `<target>` 파일이 존재하고, 그 안에 **균형 잡힌 섹션 마커 쌍이 정확히 1쌍** 있는지 확인한다.
     마커는 HTML 주석으로 감싼 형태: `<!-- --8<-- [start:<section>] -->` … `<!-- --8<-- [end:<section>] -->`
     (예: `CHANGELOG.md`는 `[start:notes]`/`[end:notes]`, 나머지 3개는 `[start:body]`/`[end:body]`).
  3. 각 캐노니컬 본문 파일이 참조된 섹션에 대해 start/end **각 1개**(중복·고아 마커 없음)인지 확인한다.
  4. **제외 용어 0건 정적 스캔**: 마커로 구획된 본문 영역(실제 사이트 콘텐츠가 되는 부분)에서
     `docs/conventions.md` "릴리즈 빌드 출력 검증"이 정한 제외 용어가 0건임을 확인한다 — release
     프리플라이트 수기 스캔의 **정적 대체 프록시**. (제외 용어 목록은 conventions의 "메타 용어 누수 방지"
     절을 단일 원본으로 참조 — 하니스에 용어를 재복제하지 말 것.)
- **스코프 경계(중요)**: 이 하니스는 `mkdocs build --strict`의 **대체가 아니다**. 인클루드 타깃 해석 +
  섹션 마커 균형 + 제외 용어 정적 가드까지만 하고, 실제 렌더·nav/link 깨짐·mkdocs 설정 회귀는 **CI
  (`deploy-pages.yml`)의 몫으로 남긴다**. 이 분담을 하니스 상단 주석과 (T03의) 문서에 명시한다 —
  "자기완결 가드 ≠ 빌드 대체". 또한 `tests/discover` B2가 이미 하는 "사이트 페이지가 스니펫 셸인가"
  검사와 **중복하지 않는다**: T02는 그 너머의 타깃·마커 해석 + 용어 스캔을 한다(경계 주석으로 명시).
- **엣지**: ① 어떤 `site/docs/*.md`가 스니펫 셸이 **아니거나** 인클루드 0건이면 시끄럽게 FAIL(그게 막으려는
  드리프트). ② 마커 쌍 불균형(start만/end만/2쌍)·타깃 파일 부재·섹션 불일치를 각각 FAIL로 검출. ③ 양 셸
  동작 동등(같은 PASS/FAIL 집합). ④ BOM 규율 준수(.sh no-BOM / .ps1 BOM·ASCII-only).
- **검증**: `tests/site-includes/run.sh`·`run.ps1`이 현 트리에서 exit 0(4 셸 전부 PASS). **음성 케이스**로
  타깃의 `[end:body]` 마커를 일시 제거하면 FAIL=1로 검출됨을 확인(검증이 실제로 무는지). 기존 하니스
  baseline 불변(T02는 신규 디렉터리만 추가).

### M26-T03: 문서 결산 — 이월 처분 원장·규약↔실행 동기화·테스트 인벤토리 갱신 (deps: M26-T01, M26-T02)

  (+ tests 인벤토리 언급 시 `README.md`의 테스트 항목)
- **무엇을**:
  - `docs/project-context.md` "이월 항목 처분 원장" 표에 두 행을 결산으로 추가/갱신 — **sn3
    (`strip_bom`/`StripBom` 단일 원본화)** = `fix`(M26-T01, 참조 구현 이중성 마지막 코드 복제면 제거),
    **mkdocs 빌드 출력 검증(환경-이월)** = `fix(부분)`(M26-T02 자기완결 가드로 로컬 사각지대 종결, 실제
    `--strict` 렌더는 CI 잔존 명시).
  - `docs/project-context.md` "진입점·빌드/테스트"의 하니스 목록에 **`tests/site-includes`**(사이트 스니펫
    인클루드 자기완결 검증) 추가. 디렉터리 구조 표의 `tests/` 역할 줄도 필요 시 정합.
  - `docs/conventions.md` "릴리즈 빌드 출력 검증"·"규약↔실행/인프라 동기화" 절에 **자기완결 인클루드/용어
    가드가 배선됐음**을 기록(수기 release 스캔 + CI `--strict` + 로컬 결정적 가드의 3분담 명시).
- **주의**: 버전 숫자는 문서에 복제하지 않는다(project-context 규약 — 버전 원본은 `plugin.json`). T01·T02의
  **실제 종료 상태**를 반영(가산 표현이 아니라 결산 기록). 새 커맨드·토큰을 더하지 않으므로 `commands.md`
  11종·드리프트 가드 B1/B2/B3 불변.
- **검증**: 원장 두 행과 하니스 인벤토리 항목이 T01·T02 산출물과 일치. conventions 3분담 서술이 실제
  배선(수기·CI·로컬 가드)과 정합.
