# M31 — 브랜치 간 협업 안전: 릴리즈 커버리지 체크 · 마일스톤 번호 사전경고

## 목표

이 마일스톤이 끝나면 **브랜치를 오가는 협업에서 두 가지가 조용히 새지 않는다** — ① `/tide:release`
프리플라이트가 마지막 태그 이후 변경된 실질 파일 중 **어떤 미릴리즈 보고서도 설명하지 않는 것**을
advisory로 드러내(비-tide·미커버 커밋이 리뷰·CHANGELOG 없이 태그에 편승하는 무결성 구멍을 릴리즈
시점에 노출), ② `/tide:milestone`이 정한 다음 번호 `M{N}`이 **다른 ref에 이미 존재하면** advisory로
경고한다(병렬 브랜치 번호 충돌을 파일 생성 전에 드러내 머지 시 재할당 캐스케이드를 예방). 둘 다
**읽기 전용·advisory**다 — 릴리즈를 차단하지도, 번호를 자동 변경하지도, 가드를 건드리지도 않는다.

## 배경

2026-07-27 대화에서 브랜치 간 협업 충돌을 검토했다 — (1) 둘 다 tide를 쓸 때의 **M번호 충돌**과
(2) **tide 미사용자와 협업 시 마일스톤 없는 변경**. 분석의 핵심 반전은 다음이다:

- **경로 충돌은 git이 이미 loud하게 잡는다.** 번호가 파일명에 박혀 있어(`M{N}.md`·`M{N}-*.md`·
  `debug-{N}.md`·버전 파일 같은 줄) 두 브랜치가 같은 번호를 쓰면 머지에서 add/add·같은 줄 충돌로
  막힌다. 조용한 손상은 거의 없다 — 남는 건 **번호 재할당 캐스케이드**(N이 파일명 + 리포트 본문 +
  CHANGELOG + 커밋 메시지에 박혀 손 교정이 번짐).
- **비-tide 협업의 진짜 위험은 번호가 아니라 "릴리즈 편승"이다.** release는 commit→tag→push이고
  **태그는 트리 전체**를 담는데, 릴리즈 판정 근거·CHANGELOG는 **미릴리즈 보고서의 합집합**만 본다.
  대응 보고서가 없는 비-tide 커밋은 **배포엔 실리나 미검토·미기록**으로 새 나간다 — "무엇을 배포했는가
  = 무엇을 검토·문서화했는가"라는 tide 존재 이유(부수효과 분리·판정 근거·CHANGELOG 단일 원본)에
  뚫린 구멍이다. 반면 리포트 귀속(변경 파일 기준선 설계)·가드 마찰(phase 파일 없으면 무마찰)·
  "마일스톤 없음"(kickoff 정상 경로)은 **이미 설계로 닫혀 있어** 손댈 것이 없다.

두 검사는 모두 tide의 **advisory 선례**(fleet-verify의 git-verb 가드라일 — 훅 실행 전 토큰 점검·경고,
차단 아님)와 동형이며, 게이트가 아니라 노출 수단이다.

**정직한 실증 유보**: 아직 **다인·혼성 팀의 라이브 도그푸딩 근거는 없다**(debug·`확인함`이 실사례에서
나온 것과 다르다). 다만 (2d) 릴리즈 편승은 예측 가능한 **무결성** 구멍이라 실증 전에도 닫을 가치가
있다는 판단으로 진행한다 — 이 유보는 완료 기준 #7과 "미해결·후속"에 남긴다.

## 태스크 상세

### M31-T01: 릴리즈 커버리지 체크 (advisory)

- **변경 파일**: `docs/conventions.md`, `skills/release/SKILL.md`
- **규약(conventions 단일 원본)**: "전제조건·프리플라이트" 절 아래(또는 "debug 세션 → 릴리즈 경로"
  인접)에 **### 릴리즈 커버리지 체크** 절을 신설한다. 정의:
  - **대상 범위 산정**: 마지막 릴리즈 태그를 찾는다(`git tag` 읽기 — **기존 "릴리즈 여부 = 태그-트리
    포함" 기준을 재사용**, 새 기준 만들지 않음). 변경 파일 = `git diff --name-only <lasttag>..HEAD`.
    **태그가 하나도 없으면(첫 릴리즈)** HEAD 트리의 커밋된 추적 파일 전체를 대상으로 같은 판정.
  - **bookkeeping 제외**: `docs/reports/*`·`docs/milestones/*`·`CHANGELOG.md`·버전 파일·`.tide/*`는
    tide 자체 산출물이라 커버리지 대상에서 뺀다(자기 자신으로 경고를 만들지 않게).
  - **커버 판정(휴리스틱·advisory)**: 남은 실질 변경 파일 각각이 **미릴리즈 보고서**(리뷰
    `M{N}-review.md` + 미릴리즈 debug `debug-{N}.md` — 릴리즈 경로의 "근거 집합"과 동일 대상)의
    본문(특히 변경 파일 요약)에 **경로로 언급되는지** 확인한다. 언급 0인 파일 = **커버리지 미상**.
  - **경고(차단 아님)**: 미상 파일이 있으면 한 블록으로 advisory 경고 —
    `⚠ 커버리지 미상: 다음 N개 파일이 {태그} 이후 변경됐으나 어떤 미릴리즈 보고서에도 없음 — 태그엔
    실리나 리뷰·CHANGELOG에서 누락될 수 있음: {목록}`. **release를 차단하지 않는다**(기존 3검사와
    별개의 advisory) — 사용자가 강행/보완을 판단한다.
  - **불변 명시**: git **읽기만** 사용(가드는 phase 무관하게 읽기 통과 — 파서 이중화·새 기준 없음).
    매칭이 경로 부분일치 휴리스틱이라 **위양성**(보고서가 파일을 안 적었을 뿐)·**위음성** 여지를
    수용한다(fleet-verify git-verb 가드라일과 동형 — 정밀 게이트가 아니라 "편승 변경을 드러냄"이 목적).
- **스킬 배선(release SKILL 절차)**: 프리플라이트 ①판정 "가능" ②테스트 통과 ③워킹트리 확인 **뒤에**
  이 커버리지 체크를 **advisory 4번째 단계**로 잇는다(기존 3검사·게이트 로직 불변 — 순수 가산).
  conventions 절을 **참조**한다(스킬은 절차, 규약은 conventions — 기존 분담 유지).

### M31-T02: 마일스톤 번호 사전경고 (advisory)

- **변경 파일**: `docs/conventions.md`, `skills/milestone/SKILL.md`
- **규약(conventions 단일 원본)**: "마일스톤 문서" 절에 **번호 사전경고**를 명시한다. 정의:
  - `/tide:milestone`이 다음 번호 `M{N}` = `max(로컬 M*.md)+1`을 정한 **직후, `M{N}.md`를 만들기
    전에** 읽기 전용으로 다른 ref에 그 번호가 이미 도입됐는지 확인한다 —
    `git log --all --diff-filter=A -- "docs/milestones/M{N}.md"`(리포트 경로도 선택 확인). 결과가
    있으면 그 ref/커밋을 밝혀 **advisory 경고**:
    `⚠ M{N}이 이미 다른 ref({branch})에 도입됨 — 병렬 브랜치 번호 충돌 가능. 조정 후 진행하거나
    다음 번호를 쓰세요(충돌 시 머지에서 파일·본문·CHANGELOG 재할당 캐스케이드 발생).`
  - **불변**: 경고는 **번호를 자동 변경하지 않는다**(놀라운 재할당 금지 — 사용자가 판단). 원격
    브랜치를 보려면 **최신 fetch가 전제**임을 경고 문구에 한 줄로 밝힌다. git **읽기만** 사용.
  - **하위 호환·소음 0**: 충돌이 없으면(단일 레포·단일 브랜치 통상) 경고를 내지 않아 출력이 현행과
    동일하다.
- **스킬 배선(milestone SKILL)**: 번호 결정 단계와 문서 생성 단계 **사이**에 이 사전경고를 둔다
  (기존 생성 로직 불변 — 경고 후에도 종전대로 `M{N}.md` 생성으로 진행). conventions 절을 참조한다.

## 완료 기준

1. release 프리플라이트에서, 마지막 태그 이후 변경된 **실질 파일 중 미릴리즈 보고서가 언급하지 않는
   것**이 있으면 **advisory 경고**가 뜨고 없으면 조용하다. 경고는 release를 **차단하지 않는다**(게이트
   아님). 태그가 하나도 없으면(첫 릴리즈) 전체 추적 파일 기준으로 같은 판정을 낸다.
2. bookkeeping 파일(`docs/reports/*`·`docs/milestones/*`·`CHANGELOG.md`·버전 파일·`.tide/*`)은
   커버리지 대상에서 제외돼 **자기 자신으로 경고를 만들지 않는다**.
3. `/tide:milestone`이 다음 번호 `M{N}`을 정한 뒤, 그 `M{N}.md`가 **다른 ref에 이미 있으면**
   advisory 경고를 내고, 없으면 현행과 동일하게 조용히 진행한다(소음 0). 경고는 **번호를 자동 변경하지
   않는다**.
4. 두 검사 모두 git **읽기만** 사용해 phase와 무관하게 통과하며(가드 무수정), 어떤 **파일·git·phase도
   바꾸지 않는다**(순수 advisory).
5. conventions가 두 규약의 **단일 원본**이고 release·milestone 스킬이 이를 배선하며, `tests/discover`
   정적 단언이 **conventions↔스킬 선언 정합**을 양 셸 동수로 집행한다(케이스 수 양 셸 동일).
6. **하위 호환**: 단일 레포·단일 브랜치·커버리지 완전한 통상 릴리즈에서 두 스킬 출력은 현행과 동일하다.
   커맨드 **12종·`.tide/phase`·tide-guard·프리플라이트 3검사·2.0 stable 11종** 계약이 전부 불변(순수
   advisory 가산).
7. **(정직) 프롬프트 자산 한계 명시**: 두 검사의 **런타임 발화 정확성**은 프롬프트 규율이라 하니스로
   완전 집행되지 않는다 — `tests/discover`는 **선언 정합만** 집행하고, 실제 경고가 올바른 상황에서
   뜨는지(및 다인 팀 실증)는 **라이브 도그푸딩 영역**으로 남긴다(M29/M30이 프롬프트 자산 한계를 정직히
   남긴 것과 동형).
