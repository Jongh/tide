# M1 — 부수효과 분리의 메커니즘화 + 사이클 상태 인식

## 목표

tide의 핵심 원칙인 "impl/review는 git 작업 금지"를 프롬프트 문장이 아닌 **시스템 차원의
차단 장치(hook)**로 강제하고, 사이클의 현재 위치를 파악·검증하는 **상태 인식 능력**
(`/tide-status`, 단계별 전제조건 검사, release 프리플라이트)을 추가한다.

## 배경

v0.1.0의 커맨드 5종은 부수효과 분리를 "다음은 절대 수행하지 마: git commit…"라는
프롬프트 지시로만 막는다. 컨텍스트가 길어지거나 모델이 "이왕 고친 김에 커밋까지"라고
판단하면 원칙이 뚫릴 수 있다. 또한 각 커맨드는 자기 단계만 알고 사이클 어디에 있는지
모르기 때문에, 마일스톤 없이 impl을 돌리거나 리뷰 판정 "불가" 상태에서 release를
실행하는 사고를 막을 수 없다. 이 마일스톤은 두 약점을 구조적으로 해소한다.

## 태스크 목록

- M1-T01: tide-guard hook 스크립트 작성 (단계 상태 기반 git 변이 명령 차단)
- M1-T02: 단계 상태 파일 규약 정의 및 각 커맨드에 상태 기록 지시 추가 (deps: M1-T01)
- M1-T03: kickoff 확장 — hook 스크립트·설정을 대상 프로젝트에 설치 (deps: M1-T01)
- M1-T04: /tide-status 커맨드 신설
- M1-T05: impl/review 커맨드에 전제조건 검사 추가
- M1-T06: release 커맨드에 프리플라이트 검사 추가
- M1-T07: /tide-impl 인자 확장 — 마일스톤 번호 지정 실행
- M1-T08: 규약 문서·README 갱신 (deps: M1-T01, M1-T02, M1-T03, M1-T04, M1-T05, M1-T06, M1-T07)

## 태스크 상세

### M1-T01: tide-guard hook 스크립트 작성

PreToolUse(Bash 매처) hook 스크립트를 작성한다.

- 위치: `hooks/tide-guard.ps1` (Windows/PowerShell), `hooks/tide-guard.sh` (POSIX) — 동일 로직 2종
- 동작: Bash 도구 호출의 command에 `git commit` / `git tag` / `git push` 패턴이 포함되면,
  단계 상태 파일(M1-T02)의 현재 단계가 `release`가 아닌 한 차단(exit 2 + 사유 메시지)
- 상태 파일이 없으면 통과(tide 미사용 프로젝트에 영향 없음)
- 차단 메시지에 "git 작업은 /tide-release에서만 허용됩니다" 안내 포함

### M1-T02: 단계 상태 파일 규약 정의 및 커맨드 반영 (deps: M1-T01)

- 상태 파일: `.tide/phase` — 내용은 단계명 한 줄 (`milestone` / `impl` / `review` / `release` / `idle`)
- 각 커맨드 프롬프트에 "시작 시 `.tide/phase`를 자기 단계명으로 갱신, 종료 보고 직전
  `idle`로 되돌림" 지시 추가
- `.tide/`를 kickoff의 `.gitignore` 보강 항목에 추가 (상태 파일은 커밋 대상 아님)
- conventions.md에 상태 파일 규약 절 신설은 M1-T08에서 수행

### M1-T03: kickoff 확장 — hook 설치 (deps: M1-T01)

`/tide-kickoff` 프롬프트를 확장한다.

- `hooks/tide-guard.*` 스크립트를 대상 프로젝트 `.claude/hooks/`로 복사(또는 생성)
- 대상 프로젝트 `.claude/settings.json`에 PreToolUse hook 설정을 병합
  (기존 설정 덮어쓰지 않고 누락분만 추가 — kickoff의 기존 원칙과 동일)
- 플랫폼 감지: Windows면 ps1, 그 외 sh를 hook command로 등록

### M1-T04: /tide-status 커맨드 신설

`.claude/commands/tide-status.md`를 추가한다. 읽기 전용 커맨드.

- 보고 항목: 최신 마일스톤 번호·제목, impl 보고서 유무, review 보고서 유무와 릴리즈
  판정 결과(가능/불가 + 추천 버전), 버전 파일의 현재 버전, `.tide/phase` 현재 값
- 마지막 줄에 "다음 권장 커맨드"를 구체 인자까지 포함해 한 줄로 제시
  (예: `/tide-release v0.2.0`)
- 금지: 파일 생성·수정 / git 작업

### M1-T05: impl/review 전제조건 검사

- `/tide-impl`: 시작 전 `docs/milestones/M*.md` 존재 확인 — 없으면 구현하지 않고
  `/tide-milestone` 먼저 실행하라고 안내 후 중단
- `/tide-review`: 대상 마일스톤의 `docs/reports/M{N}-impl.md` 존재 확인 — 없으면
  `/tide-impl` 먼저 실행하라고 안내 후 중단

### M1-T06: release 프리플라이트

`/tide-release` 프롬프트 앞부분에 검사 단계를 추가한다. 하나라도 실패하면 git 작업
없이 중단하고 사유를 보고한다.

1. `docs/reports/M{N}-review.md`의 릴리즈 판정이 "가능"인지 확인
   (불가이거나 보고서가 없으면 중단; 사용자가 버전 인자와 함께 강행 의사를 명시한
   경우에만 경고 후 진행)
2. 프로젝트 테스트 명령 실행 — 실패 시 중단
3. 워킹트리 상태 확인 — 추적되지 않은 의도 불명 변경이 있으면 목록을 보여주고 확인 요청

### M1-T07: /tide-impl 인자 확장

- frontmatter에 `argument-hint: "[M번호 (선택, 예: M3)]"` 추가
- 인자로 마일스톤 번호가 오면 해당 문서를 대상으로 실행 (재실행·이어하기 용도)
- 인자가 없으면 기존대로 최대 번호 문서 대상
- 재실행 시 기존 `M{N}-impl.md` 보고서는 갱신 (conventions의 기존 규약과 일치)

### M1-T08: 규약 문서·README 갱신 (deps: M1-T01~T07)

- `docs/conventions.md`: 상태 파일(`.tide/phase`) 규약 절, hook 차단 동작 설명,
  단계별 금지 행위 표에 "강제 수단(hook)" 열 추가, 전제조건·프리플라이트 규칙 반영
- `README.md`: 커맨드 표에 `/tide-status` 추가, 사이클 다이어그램 갱신, 설치 절에
  hook 파일 복사 안내 추가

## 완료 기준

1. `.tide/phase`가 `impl` 또는 `review`인 상태에서 `git commit`을 시도하면 hook이
   차단하고 안내 메시지를 출력한다 (ps1·sh 모두 수동 검증)
2. 상태 파일이 없는 프로젝트에서는 hook이 어떤 git 명령도 차단하지 않는다
3. `/tide-status`가 마일스톤·보고서·판정·버전을 정확히 읽어 다음 커맨드를 제시한다
4. 마일스톤 문서가 없는 상태에서 `/tide-impl` 실행 시 구현 없이 안내 후 중단한다
5. review 판정 "불가" 상태에서 `/tide-release` 실행 시 git 작업 없이 중단한다
6. `/tide-impl M1`처럼 번호 지정 실행이 동작한다
7. README·conventions가 변경된 동작과 일치한다
