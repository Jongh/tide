# M4 — 브라운필드 킥오프 + 프로젝트 구조 문서화

## 목표

이미 코드가 어느 정도 쌓인 기존 프로젝트에 `/tide:kickoff`를 실행하면, 빈 골격만
세우는 데 그치지 않고 현재 코드베이스의 스택·디렉터리 구조·진입점을 조사해 프로젝트
컨텍스트 문서로 남긴다. 그 결과 이후 `/tide:milestone`·`/tide:impl`이 기존 구조를
매번 처음부터 재조사하지 않고 그 문서를 참조해 더 정확하게 착수할 수 있는 상태가 된다.

## 배경

현 kickoff 스킬은 신규 프로젝트를 가정하고 디렉터리·CHANGELOG·conventions·`.gitignore`·
버전 감지 골격만 세운다(`skills/kickoff/SKILL.md`). 이미 진행 중인 프로젝트(기존
소스·git 이력 보유)에 적용하면 진행 상태를 인지하지 못한 채 골격만 덧붙고, 기존 구조에
대한 기록이 남지 않아 이후 모든 단계가 코드베이스를 매번 새로 파악해야 한다.

출처: 사용자 요청 — "이미 어느 정도 진행된 프로젝트에 대한 킥오프가 잘 동작하는지
검토하고, 킥오프 시 파일 구조 등을 문서화해 작업을 잘 수행시킬 수 있는 내용을 추가".
M5(`/tide:cycle`)·M6(`/tide:retro`)와 독립이라 어느 순서로 진행해도 무방하다.

## 태스크 목록

- M4-T01: 기존-진행 프로젝트 감지 로직을 kickoff 스킬에 추가
- M4-T02: 프로젝트 컨텍스트 문서(`docs/project-context.md`) 생성 단계 추가 (deps: M4-T01)
- M4-T03: milestone·impl 스킬이 `docs/project-context.md`를 참조하도록 연결 (deps: M4-T02)
- M4-T04: conventions·README에 새 산출물·브라운필드 동작 반영 (deps: M4-T02)
- M4-T05: 기존 진행 프로젝트 대상 드라이런 검증 (deps: M4-T01, M4-T02, M4-T03, M4-T04)

## 태스크 상세

### M4-T01: 기존-진행 프로젝트 감지 로직 추가

`skills/kickoff/SKILL.md` 본문에 "대상 저장소가 신규인지 진행 중인지" 판별 단계를
추가한다. 판별 신호: git 커밋 이력 존재 여부, `docs/milestones/`·`docs/reports/`에
기존 산출물 유무, 소스 파일/버전 파일의 존재 규모. 신규로 판단되면 기존 동작(골격만
세우고 보고)을 그대로 따르고, 진행 중으로 판단되면 T02의 문서화 단계로 진입한다.
판별 결과를 사용자에게 한 줄로 보고하도록 한다. 기존 파일은 덮어쓰지 않는다는 현
원칙은 유지한다.

### M4-T02: 프로젝트 컨텍스트 문서 생성 단계 추가 (deps: M4-T01)

진행 중 프로젝트로 판별된 경우, 코드베이스를 조사해 `docs/project-context.md`를
생성한다(이미 있으면 덮어쓰지 말고 누락 항목만 보강). 포함 항목:
- 스택·언어·주요 의존성(버전 파일·매니페스트 기준)
- 최상위 디렉터리 구조와 각 디렉터리의 역할 한 줄
- 진입점·빌드/테스트 실행 방법(감지 가능한 범위)
- 핵심 도메인 개념·용어(소스/README에서 확인 가능한 수준)

조사가 불확실한 항목은 단정하지 말고 "확인 필요"로 표기한다. **폴백**: 구조를
신뢰 있게 파악하기 어려우면(예: 비표준 레이아웃) 최소 골격(디렉터리 트리 + 확인 필요
표기)만 남기고 그 사유를 보고한다. 형식이 반복 사용될 가치가 있다면
`skills/kickoff/template.md` 동봉 여부를 함께 판단한다(없으면 본문 인라인 형식).

### M4-T03: milestone·impl 스킬의 컨텍스트 문서 참조 연결 (deps: M4-T02)

`skills/milestone/SKILL.md`와 `skills/impl/SKILL.md` 본문에 "`docs/project-context.md`가
있으면 먼저 읽어 기존 구조를 파악한 뒤 작업하라"는 지시를 추가한다. 파일이 없으면
기존 동작을 그대로 따르도록(필수 전제조건으로 만들지 않음) 조건부로 기술한다.

### M4-T04: conventions·README 반영 (deps: M4-T02)

- `docs/conventions.md`: kickoff 절(또는 산출물 목록)에 `docs/project-context.md`를
  새 산출물로 추가하고, 신규/진행 중 프로젝트에서의 동작 차이를 한 줄로 명시
- `README.md`: kickoff 설명·저장소 구조 설명에 브라운필드 동작과 새 산출물을 반영

### M4-T05: 드라이런 검증 (deps: M4-T01~T04)

기존 소스·커밋이 있는 프로젝트(이 저장소 자체로 자기적용 가능)에서 `/tide:kickoff`를
실행해 다음을 확인한다:
1. 진행 중 프로젝트로 감지했음을 보고
2. `docs/project-context.md`가 생성되고 구조·스택·진입점이 채워짐(또는 폴백 사유 보고)
3. 신규(빈) 임시 디렉터리에서는 기존 동작이 유지됨
4. `/tide:milestone` 호출 시 컨텍스트 문서를 참조하는 동작이 확인됨

## 파일 변경 요약

| 구분 | 파일 |
|---|---|
| 수정 | `skills/kickoff/SKILL.md` (감지 + 컨텍스트 문서화 단계) |
| 수정 | `skills/milestone/SKILL.md`, `skills/impl/SKILL.md` (컨텍스트 문서 참조) |
| 수정 | `docs/conventions.md`, `README.md` |
| 추가 | `docs/project-context.md` (대상 프로젝트 런타임 산출물 — 자기적용 시 이 저장소에도 생성) |
| 추가 | (선택) `skills/kickoff/template.md` (T02에서 형식 동봉을 택한 경우) |

## 완료 기준

1. 기존 소스/커밋이 있는 프로젝트에서 `/tide:kickoff` 실행 시, 진행 중 프로젝트로
   감지했음을 보고하고 `docs/project-context.md`를 생성한다(또는 폴백 사유를 보고)
2. 신규(빈) 프로젝트에서는 기존 골격 생성 동작이 그대로 유지된다
3. `docs/project-context.md`가 있으면 `/tide:milestone`·`/tide:impl`이 이를 참조한다
   (스킬 본문에 조건부로 명시되어 있다)
4. `docs/conventions.md`·`README.md`에 새 산출물과 브라운필드 동작이 기록된다
