# M99 — 판별을 절차로 세우고, GitHub에서 계획을 읽는 어댑터 표를 둘째 구현으로 세운다

## 목표

스킬이 계획을 읽기 전에 「이 레포의 트래커가 무엇이고 닿는가」를 계약의 판별 갈래대로 정하고, 그 결론에 따라 읽기 항목을 로컬 문서 또는 GitHub 이슈에서 읽는다. 연결을 켜지 않은 레포의 동작과 산출물은 이 사이클 전과 같고, 출력에 로컬 문서 모드임을 밝히는 한 줄이 더해진다. 연결을 명시한 GitHub 레포에서는 읽기 항목 넷이 이슈에서 읽힌다. 쓰기는 아직 로컬 문서에만 한다 — 이 사이클이 끝나도 연결된 레포에서 사이클 하나를 끝까지 돌 수는 없고, 그것은 다음 사이클(쓰기와 유입)이 선 뒤다.

## 배경

- **E5 사이클 배분의 셋째(GitHub 어댑터와 유입)를 둘로 나눈 앞쪽**이다(사용자 결정 2026-11-26). 한 사이클에 읽기 · 쓰기 · 대응 기록 · 유입이 다 들어 있었고, M97이 재작업 2 · M98이 재작업 1이었다. 두 사이클의 차단은 모두 「문서가 집행을 사실보다 넓게 적는다」였고 범위가 넓을수록 그 틈이 커진다. 쓰기와 유입은 실제 이슈를 만들고 닫는 일이라 따로 두는 편이 되돌리기 쉽다.
- **M98이 넘긴 것이 넷이다**(`docs/reports/M98-impl.md`의 후속 메모 · `docs/epics/E5.md`의 「M98 결과」).
  - 경로 없이 계획을 읽는 스킬 자리가 이름으로 옮겨지지 않았다. `cycle`의 의존 표기 읽기와 시작점 갈래, `impl`의 시작 전 검사, `retro`의 릴리즈 표지 읽기, `status`의 다음 커맨드 판단, `milestone`의 최대 번호 읽기다. 이 목록은 두 낱말(`마일스톤 문서` · `열린 에픽`) 검색으로 낸 것이라 더 없는지는 재지 않았다.
  - 판별과 「로컬 문서 모드」 알림 한 줄을 넣지 않았다. 어댑터가 하나뿐인 동안 그 알림은 소음이었다.
  - `tracker-phase-writes:`의 단계 이름을 스킬 디렉터리 이름과만 대조한다. 커맨드 명단과의 대조는 세우지 않았다.
  - 행 추출이 조각 전체를 본다. 같은 이름의 행을 든 둘째 어댑터 표를 세우면 `F92`가 붉다.
- **판별 갈래는 M97이 이름으로 세웠고 소비자가 없다**(`docs/conventions-tracker.md`의 `tracker-detect-steps:`). GitHub 쪽 실측 기록은 `docs/reports/M97-recordings/`에 있다.
- **외부 응답을 저장소에 보관하는 절차가 손으로만 서 있다**(회고 행 `rf-127`). M97에서 정제 스캔이 값 패턴만 보아 응답이 스스로 싣는 비밀 필드가 두 라운드 동안 보관본에 남았다. 이 사이클은 GitHub 응답을 다시 보관하므로 그 절차를 처음부터 쓴다.
- **쓰기가 서기 전에 읽기만 트래커로 가면 계획이 두 벌로 갈린다.** 읽기는 이슈에서, 쓰기는 로컬 문서에 하게 되기 때문이다. 그래서 이 사이클의 연결은 **명시 설정으로만** 켠다(아래 T02). `origin`이 GitHub이고 `gh`가 인증돼 있다는 사실만으로 읽기가 바뀌면, 이미 tide를 쓰는 GitHub 레포 전부가 이 릴리즈에서 빈 트래커를 읽게 된다.

**이 사이클이 하지 않는 것**

- **쓰기(`to-write`) · 대응 기록(`to-map`) · 유입 선별을 구현하지 않는다.** 다음 사이클의 몫이다. `tracker-path-sites:`의 `write` 자리는 그대로 둔다.
- **GitLab 어댑터를 세우지 않는다.** 판별의 GitLab 갈래는 정의만 두고 절차 표에 「아직 없음 — 로컬 문서 모드」로 적는다.
- **실행되는 어댑터 스크립트를 세우지 않는다.** 판별과 읽기는 스킬이 조각의 표를 따라 `gh`를 도는 절차다(release 스킬이 `gh`를 쓰는 꼴과 같다). E5 완료 신호가 요구하는 「가짜 어댑터로 네트워크 없이 무는」 집행은 무엇이 실행 단위인지부터 정해야 하므로, T01이 선택지를 적고 결정은 사용자에게 받는다.
- **이 저장소의 계획 원본을 바꾸지 않는다.** 이 저장소는 로컬 강제 설정으로 남고 하니스가 `docs/milestones/`를 읽는 자리도 그대로다(E5 「사용자 판단」).
- **소개 문서의 경로 서술은 그대로 둔다.** 다만 알림 한 줄과 설정 파일은 사용자가 보는 표면이라 `docs/commands.md`에 한 줄씩 적는다(T07).

## 태스크 상세

### M99-T01: 조사 — 읽기 자리 · 판별 자리 · 읽을 꼴 · 실행 단위

- **변경 파일**: 없음(결과는 impl 보고서의 표).
- **남은 읽기 자리.** 검색 루트는 `skills/` 전체(모든 `.md`)다. 검색 낱말은 M98이 쓴 둘에 더해 `마일스톤` · `태스크` · `에픽` · `완료 기준` · `released` · `deps`다. 줄마다 「파일 · 원문 요지 · 분류 · 처분」을 적는다. 분류는 읽기 · 쓰기 · 계획이 아닌 것 셋이다. 읽기로 분류한 줄마다 「이미 있는 읽기 항목 넷 가운데 어느 것이 돌려주는가」를 적고, 넷으로 덮이지 않는 것이 있으면 새 항목의 후보로 적는다.
- **판별을 부를 자리.** 읽기 항목을 소비하는 스킬마다 「실행 한 번에 판별을 어디서 한 번 하는가」를 적는다. 기본안은 스킬이 처음 읽기 항목에 닿는 자리 앞이다. `cycle`처럼 다른 스킬을 이어 부르는 스킬은 알림이 한 실행에 여러 번 뜨지 않는 자리를 고른다.
- **이슈 본문에서 읽을 꼴.** `docs/reports/M97-recordings/`의 GitHub 기록(에픽 이슈 · 사이클 체크리스트 이슈 · sub-issue 응답)에서 읽기 항목 넷이 돌려줘야 하는 것(번호와 제목 · 목표 · 태스크와 의존 · 완료 기준 · 메타데이터 · 에픽 본문 · 속한 사이클)이 어느 필드 · 본문의 어느 구획에 있는지 적는다. 기록에 없는 것(M97은 사이클 이슈 본문을 계획 전체로 채우지 않았다)은 「T03이 꼴을 정한다」로 적는다.
- **가짜 어댑터의 실행 단위.** 선택지와 비용을 표로 적는다. 후보는 셋이다 — 절차 표에 머문다(하니스는 표와 선언만 묻는다) · 판별만 두 셸 스크립트로 세운다 · 읽기까지 스크립트로 세운다. 이 사이클은 첫째로 진행하고, 표는 사용자가 다음 사이클 전에 고를 근거다.
- 이 표들이 T02 · T03 · T05의 대상 목록이다. 표에 없는 스킬 자리를 T05가 고치지 않는다.

### M99-T02: 연결 설정 · 연결 조건 · 판별 절차 표 · 알림 (deps: M99-T01)

- **변경 파일**: `docs/conventions-tracker.md`
- **연결 설정**(`td-explicit`이 읽는 것). 자리는 `.tide/` 아래 파일 하나이고 한 줄 값이다. 값의 집합은 선언으로 둔다 — 기본안은 `local`(로컬 강제) · `github`(이 레포의 `origin`이 가리키는 GitHub 저장소)다. 호스트 · 프로젝트를 따로 적는 꼴은 GitLab 사이클이 더한다. 파일이 `.gitignore`에 드는지(레포 단위 설정인지 사용자 단위 설정인지)를 정해 적는다 — 기본안은 레포에 커밋하는 설정이다(같은 레포를 쓰는 사람이 같은 원본을 읽어야 한다).
- **연결 조건.** 값 선언 한 줄로 둔다. 기본안은 이름 `tracker-connect:` · 값 `explicit`이고, 뜻은 「연결 설정이 플랫폼을 적은 레포만 트래커에서 읽는다」다. 설정이 없으면 `td-remote` · `td-reach`가 무엇을 내든 읽기는 로컬 문서다. 쓰기가 서는 사이클이 이 값을 다시 정한다. `td-local`의 정의 문장(「앞의 갈래 가운데 하나라도 결론을 내지 못하면」)을 이 조건과 어긋나지 않게 고치고, 재서술처를 같은 편집에서 맞춘다.
- **판별 절차 표.** 갈래 이름마다 행이 하나다. 열은 「갈래 · 확인하는 법 · 결론을 내는 조건 · 실패 사유의 꼴」이다. `td-remote`의 GitHub 판정과 `td-reach`의 인증 · 읽기 권한 확인은 release 스킬이 이미 쓰는 게시 축 검증과 같은 명령을 쓴다 — 단일 원본을 가리키고 다시 적지 않는다(`docs/conventions-release.md`의 "검증 게이트" 절). GitLab 행은 「이 사이클에 없음」으로 적는다.
- **알림 문구.** `td-local`의 한 줄을 사유별로 고정한다. 사유는 판별 절차 표의 실패 사유와 같은 집합이고 선언으로 둔다(기본안: 설정 없음 · 로컬 강제 · 미인증 · 권한 없음 · 응답 없음 · 플랫폼 미지원). 「설정 없음」은 tide를 쓰는 레포 대부분이 볼 문구라 가장 짧게 쓴다.
- **불확실성** — 알림이 모든 로컬 레포의 모든 실행에 뜬다. 한 줄로 끝나는지, 스킬마다가 아니라 실행마다 한 번인지를 T05의 대조표가 확인한다. 소음이 크다고 판단되면 「설정 없음」 사유에서는 `status`와 `milestone`만 알리는 안으로 좁히고 그 결정을 조각에 적는다.

### M99-T03: GitHub 어댑터 표와 이슈 본문의 읽기 꼴 (deps: M99-T01)

- **변경 파일**: `docs/conventions-tracker.md`
- 「읽기 항목」 소절에 **GitHub 어댑터** 표를 둘째 표로 세운다. 행은 항목 이름마다 하나이고 열은 「항목 · GitHub에서 읽는 법」이다. 읽는 법은 `gh` 명령과 고르는 규칙이다(예: `rd-cycle-latest` — 라벨 `tide:cycle`인 이슈를 열림 · 닫힘 모두 읽어 제목 머리의 `M{N}`이 가장 큰 것). 라벨 이름은 `tracker-labels:` 선언의 것을 쓴다.
- **표를 가르는 표지.** 두 표가 같은 이름의 행을 들므로, 표마다 머리에 ASCII 표지 한 줄을 둔다(기본안: 어댑터 이름 선언 `tracker-adapters:` local github, 표 바로 위의 굵은 머리가 그 이름을 백틱으로 든다). T06의 표 단위 행 추출이 이 표지로 표를 가른다.
- **이슈 본문의 읽기 꼴.** `rd-cycle-doc`이 돌려주는 것(목표 · 태스크와 의존 · 완료 기준 · 메타데이터)을 사이클 이슈 본문의 어느 구획에서 읽는지 정한다. 기본안은 로컬 마일스톤 문서와 같은 제목의 구획이다 — 변환(뒤 사이클)이 문서를 그대로 올릴 수 있고 읽는 규칙이 하나로 남는다. 태스크의 완료 상태는 체크리스트의 체크로 읽는다. 릴리즈 표지(`released`)를 본문의 메타데이터 줄로 읽을지 이슈의 닫힘으로 읽을지를 정해 적는다 — 기본안은 메타데이터 줄이다(닫힘은 사람이 손으로 할 수 있어 릴리즈와 같지 않다).
- `rd-epic-open`의 「속한 사이클」은 sub-issue 목록으로 읽고, sub-issue가 없으면 본문 체크리스트의 이슈 참조로 읽는다(M97 실측의 두 꼴).
- **읽지 못할 때.** 본문이 이 꼴이 아니면 「없음」으로 조용히 넘기지 않고 어느 구획을 찾지 못했는지 알리고 멈춘다. 이 문장을 표 아래에 적는다.
- 쓰기가 이 꼴을 만드는 것은 다음 사이클이다. 그 사실과 「이 사이클의 읽기는 손으로 만든 이슈로만 재진다」를 조각 「묻지 않는 것」에 적는다.

### M99-T04: 실측과 응답 보관 (deps: M99-T02, M99-T03)

- **변경 파일**: `docs/reports/M99-recordings/`(새 디렉터리 — 기록과 `README.md`) · `docs/conventions-tracker.md`(보관 절차 소절과 「정의의 근거」 표)
- **대상.** 비공개 GitHub 시험 저장소다. 저장소 이름은 impl이 사용자에게 받는다(M97의 시험 저장소가 남아 있으면 그것을 쓴다). 이 저장소(`Jongh/tide`)에는 이슈를 만들지 않는다.
- **준비.** T03의 본문 꼴로 에픽 이슈 하나와 사이클 이슈 둘(하나는 열림 · 하나는 닫힘, 하나는 에픽의 sub-issue)을 손으로 만든다. 이 쓰기는 실측 준비이고 스킬의 쓰기가 아니다.
- **잰다.**
  - 읽기 항목 넷을 T03 표의 명령 그대로 돌려, 돌려준 값이 손으로 만든 이슈의 내용과 같은지 대조한다.
  - 판별 갈래마다 한 번씩 결론을 내게 한다 — 설정 `local` · 설정 `github` · 설정 없음(GitHub `origin`) · 미인증(토큰을 뺀 환경) · 권한 없는 저장소 · 없는 저장소 · `origin` 없음. 갈래마다 T02 표가 적은 사유가 나오는지 적는다. 재지 못한 칸은 「재지 않음」과 까닭을 적는다.
  - 본문 꼴이 어긋난 이슈(구획 하나를 지운 것)에서 T03의 「읽지 못할 때」가 그대로 나오는지 본다.
