# M70 — 「미릴리즈」를 최대 번호가 아니라 상태로 가리고, 새 판정은 생명주기 상태표를 통과해야 선다

## 목표

**다음 마일스톤을 언제 세우든 Part O가 거짓으로 붉지 않게 한다.** 지금은 「미릴리즈 마일스톤 = 최대 번호 하나」라는
전제 때문에, 직전 마일스톤의 태그보다 먼저 다음 마일스톤 문서가 생기면 `O23`·`O18`이 붉어 그 릴리즈가 막힌다
(v2.35.0 리뷰가 수용한 잔여 위험). 이 마일스톤이 끝나면 stale 판정과 백스톱은 **마일스톤의 릴리즈 상태**를 신호로
삼고, 그 신호는 **릴리즈 커밋 트리에서도** 같은 답을 낸다. 함께, **새 판정을 세우는 사이클은 제품의 생명주기 상태
목록을 사본으로 만들어 그 판정에 먹인 표**를 impl 보고서에 남겨야 한다 — M69가 리뷰 네 번으로 치른 비용을 impl 쪽으로
옮긴다.

## 배경

**출처는 전부 이 저장소의 산출물이다.**

- `docs/reports/retro.md` 최상단 섹션(2026-09-17, v2.35.0 시점)의 후속 표
  - **1순위 `rf-54`** — 태그 전에 세운 다음 마일스톤이 Part O(`O23`·`O18`)를 거짓으로 붉혀 릴리즈를 막는다.
  - **2순위 `rf-59`** — 새 판정이 제품의 생명주기 상태 전부에서 초록인지 묻는 절차가 없다.
- `docs/reports/M69-review.md`(라운드 3) — 차단 1의 **잔여 위험 수용 블록**이 이 마일스톤을 「넘긴 곳」으로 지정했다.
  재현은 두 갈래다.
  - M69 미릴리즈 + 기반 `v2.34.0`인 `M70.md` → `O23` 붉음.
  - CHANGELOG `v2.35.0` + 기반 `v2.35.0`인 `M70.md` → `O18`·`O23` 붉음.
- `docs/conventions.md`의 "회고 후속 항목의 소비" 절 — 「경계(수용된 잔여 위험)」 문단이 우회(태그 뒤에 새 마일스톤)와
  **고치지 않은 사유**를 적는다. 사유는 *"릴리즈 커밋 트리에서도 같은 답을 내는 신호의 설계가 범위를 넘는다"* 이다.
- `skills/cycle/SKILL.md`의 시작점 판단 — impl·review 보고서가 다 있으면 **릴리즈 여부를 묻지 않고** 새 마일스톤
  단계부터 시작한다. 이것이 `rf-54`를 **제품의 정상 경로**로 만든다.

**M69가 남긴 설계 제약 — 두 번 실측으로 좁혀졌다.**

1. 신호는 **릴리즈 커밋 트리**(CHANGELOG는 올랐고 회고는 태그 뒤에 돈다)에서 초록이어야 한다 — 라운드 1 차단.
2. 신호는 **리뷰 보고서 유무에 기대면 안 된다** — debug 릴리즈와 강행 릴리즈가 리뷰 없이 릴리즈 커밋을 만든다. 라운드 2 차단.
3. **하니스는 git을 읽지 않는다**(M69 라운드 1이 택하지 않은 안 ⒝의 사유) — CI 체크아웃에 태그가 없을 수 있다.
   그래서 「태그 전 초안」과 「태그 뒤 회고 건너뜀」은 **트리만으로는 구별되지 않는다**(라운드 3 반증 실측 — 두 트리가
   바이트 단위로 같다).

제약 3 때문에 **신호만 바꿔서는 닫히지 않을 수 있다.** 대안은 **순서 규칙**이다 — 「새 마일스톤은 최상단 회고가
CHANGELOG 첫째를 따라잡은 뒤에 세운다」를 규약으로 두고, `/tide:milestone`이 advisory로 알리며(`rf-02`의 원래 처방
후보), 그 규칙 위에서는 태그 전 초안의 `O18` 붉음이 **거짓이 아니라 참**이 된다. 어느 쪽인지 T01이 실측으로 정한다.

**왜 지금인가** — v2.35.0이 태그됐으므로 지금 M70을 세우는 것은 안전하다. 그러나 이 마일스톤 **안에서**
`/tide:cycle`이 M71을 태그 전에 세우면 같은 막음이 재발한다. 수용은 한 번의 릴리즈를 위한 것이었다.

## 태스크 상세

### M70-T01: 생명주기 상태표와 신호 후보를 실측으로 정한다

- **변경 파일**: (없음 — 결과는 impl 보고서에 적는다)

규칙의 형태를 정하기 **전에** 읽기 전용으로 잰다.

- **생명주기 상태 목록을 열거한다.** 최소 목록은 아래와 같다.
  - ⑴ 사이클 중(최대 번호 마일스톤 미리뷰)
  - ⑵ 리뷰 뒤 릴리즈 전
  - ⑶ 릴리즈 커밋(CHANGELOG·버전 파일만 오름)
  - ⑷ 태그 뒤 회고 전
  - ⑸ 태그 뒤 회고 후
  - ⑹ ⑵ 상태에서 다음 마일스톤 초안(`/tide:cycle` 시작점)
  - ⑺ ⑶ 상태에서 다음 마일스톤 초안(`pr` 머지 뒤 마무리 전 · `autonomy=continuous` 커밋 앞 정지 뒤)
  - ⑻ ⑷ 상태에서 다음 마일스톤 초안(회고 건너뜀)
  - ⑼ debug 릴리즈 커밋(회고 최신)
  - ⑽ 회고를 건너뛴 뒤 debug 릴리즈 커밋
  - ⑾ 강행 릴리즈 커밋

  빠진 상태가 있으면 더한다. 목록 자체가 `lean-branches-stated`의 「기대는 절차의 갈래」다 — 기대는 절차는
  `skills/cycle`·`skills/release`·`skills/debug`의 흐름이다.
- **현행 판정표를 잰다** — 각 상태를 스크래치패드 사본에 만들어 현행 Part O(`O18`·`O21`·`O23`)를 두 사본으로 돌리고,
  「기대(붉어야 하나)」와 「실제」를 표로 적는다. M69 라운드 3 리뷰의 시나리오 표가 출발점이다.
- **신호 후보를 비교한다.** 각 후보는 위 표 **전체**에 대해 기대와 맞는지로 평가하고, 표에서 틀리는 상태를 이름으로 적는다.
  - ⒜ **릴리즈 기록형** — 릴리즈가 그 커밋에 「이 마일스톤이 이 버전으로 나갔다」를 ASCII로 남긴다. 기록 자리의 후보는
    마일스톤 메타데이터 한 줄 또는 CHANGELOG 노트의 선언 줄이다. stale 대상은 「기록된 버전 ≤ 최상단 회고 버전」인
    마일스톤이다. release 스킬(사용자 실행 표면)이 바뀐다.
  - ⒝ **순서 규칙형** — 「새 마일스톤은 최상단 회고가 CHANGELOG 첫째를 따라잡은 뒤에 세운다」를 규약으로 두고
    `/tide:milestone`이 advisory로 알린다. ⑺의 `O18` 붉음은 규칙 위반의 참 신호가 된다. **복구 경로**(태그 전에
    `/tide:retro`를 돌려도 되는가 · 그때 섹션 제목의 버전은 무엇인가)를 함께 정한다.
  - ⒞ ⒜와 ⒝의 결합.
  - ⒟ 그 밖에 T01이 찾은 안.
- **제약 3의 사실을 다시 잰다** — ⑺과 ⑻이 트리 기준으로 구별되는지를 사본으로 확인한다. 구별되지 않으면 그 사실을
  `infeasible-evidenced`의 세 요소로 적는다. 구별된다면 무엇이 그 둘을 가르는지 적는다.
- **「못 한다」 주장이 나오면** 세 요소를 따른다. 규약의 단일 원본은 `docs/conventions.md`의
  "구조적 불가 주장의 근거" 절이다.

### M70-T02: 새 판정의 생명주기 상태표 요구를 규약·impl 스킬에 선언한다 (deps: M70-T01)

- **변경 파일**: `docs/conventions.md` · `skills/impl/SKILL.md` · `skills/impl/template.md`

- **규칙** — 기계 판정(하니스 케이스)을 **새로 세우거나 판정 조건을 바꾸는** 사이클의 impl 보고서가 **생명주기 상태표**를
  갖게 한다. 표의 열은 셋이다: 상태 · 사본에서 만든 방법 · 기대와 실제.
- **자리** — `docs/conventions.md`의 "다른 절차에 기대는 주장의 분기" 소절 옆(또는 T01이 정하는 자리)에 둔다.
  병기어 선언 줄은 기존 형식을 따른다(ASCII 키 · 백틱 · 꼬리 구분자 금지 · 키마다 하나).
- **적용 범위를 적는다**
  - 대상 레포 일반의 규율인가, 이 저장소(하니스가 있는 참조 구현)의 규율인가를 적는다.
  - 상태 목록의 **단일 선언처**를 한 곳에 둔다 — 목록을 여러 자리에 복제하지 않는다.
- **기계가 무는 것과 사람의 영역** — 무는 것은 병기어의 공존까지다. **상태 목록이 빠짐없는가**와 **실측이 정말
  돌았는가**는 리뷰의 영역이다(`scope-exhaustive`와 같은 층). 이 경계를 적지 않으면 `vacuous-pass` 판례에 걸린다.
- 재서술처(`skills/impl/SKILL.md` · `skills/impl/template.md`)를 **같은 편집에서** 고친다. 사용자 스킬에는 이 저장소의
  실행 환경 축 이름을 적지 않는다(규약 "완료 기준 대조 (impl)" 절의 적용 범위).

### M70-T03: 「미릴리즈」 신호와 회고·마일스톤 순서 규칙을 규약에 선언한다 (deps: M70-T01)

- **변경 파일**: `docs/conventions.md`

- `docs/conventions.md`의 "회고 후속 항목의 소비" 절에서 T01이 택한 안으로 **stale 판정 대상**과 **백스톱 갈래**를
  다시 쓴다. 「최대 번호(진행 중인 사이클)는 대상이 아니다」는 문장을 **상태 기준**으로 바꾸고, 「경계(수용된 잔여
  위험)」 문단은 닫힌 만큼 걷거나 좁힌다.
- ⒝(순서 규칙)를 택하면 다음을 규약에 적는다.
  - 순서 규칙과 그 **복구 경로**(태그 전 회고가 허용되는가, 허용되면 섹션 제목의 버전).
  - 규칙이 `/tide:cycle`의 시작점 판단과 어떻게 맞물리는가 — 막는가, 알리는가.
- ⒜(릴리즈 기록)를 택하면 다음을 규약에 적는다.
  - 기록의 형식 · 기록 주체(release) · 기록이 없는 기존 마일스톤(M1~M69)의 해석.
  - **소급 경계** — 기존 문서를 고치지 않는다.
- 새 병기어가 생기면 기존 선언 줄 형식을 따르고, 선언 줄은 **키마다 하나**다.
- **갈래 표를 규약에 싣는다** — T01의 상태 목록 각각에서 판정이 무엇인지를 적는다(`lean-branches-stated`).

### M70-T04: 스킬이 새 규칙을 따른다 (deps: M70-T03)

- **변경 파일**: T01·T03의 결정에 따라 `skills/milestone/SKILL.md` · `skills/release/SKILL.md` · `skills/cycle/SKILL.md` ·
  `skills/retro/SKILL.md` · `docs/commands.md` 중 해당하는 것

- ⒝이면 `/tide:milestone`이 최상단 회고의 기준 버전과 CHANGELOG 첫째를 대조해 **advisory 한 줄**을 낸다.
  - 막지 않는다 — 번호 사전경고와 같은 성격이다.
  - **소음 0 계약을 유지한다** — 회고 문서가 없는 저장소에서는 아무것도 내지 않는다.
- ⒜이면 `/tide:release`가 기록을 남기는 단계를 **게시 분기 앞(버전 파일·CHANGELOG 편집과 같은 자리)** 에 둔다.
  `pr` 모드 마무리 분기에서는 재편집하지 않는다(기존 규약).
- `/tide:cycle`의 시작점 판단에 **릴리즈 상태**가 관여하는지를 T03의 결정대로 적는다.
- `docs/commands.md` 카탈로그를 같은 편집에서 고친다. 카탈로그가 역할·산출물·금지의 단일 원본이기 때문이다.

### M70-T05: Part O를 새 신호로 다시 세우고 상태표를 사본 실측한다 (deps: M70-T03, M70-T04)

- **변경 파일**: `tests/discover/run.sh` · `tests/discover/run.ps1` · `tests/discover/README.md`

- **Part O의 기존 헬퍼를 고친다**(새 파트를 만들지 않는다) — `claim_stale`/`ClaimStale`의 대상 선택과
  `backstop_verdict`/`BackstopVerdict`의 넷째 인자(또는 T01이 정한 신호)를 새 신호로 바꾼다. 기존 판정 중
  바뀌지 않는 것(`O1`~`O17` · `O19`~`O22` · `O24`~`O35`)의 결과가 전후로 같음을 기준선으로 적는다.
- **통제는 회귀 방향마다 둔다**(`rf-01`의 관행). 최소 방향은 다음과 같다.
  - 신호 추출을 죽임
  - 신호를 상수로 고정
  - 신호를 무시하고 옛 「최대 번호」로 되돌림
  - 대상 선택을 전부 포함 · 전부 제외로 고정
- **생명주기 상태표를 사본 실측한다** — T01의 목록 **전부**를 스크래치패드 사본에 만들어 두 사본으로 돌리고, 상태마다
  기대와 실제가 같음을 표로 적는다. 이 표가 T02 규칙의 **첫 적용**이다.
- `.ps1`에는 비-ASCII를 넣지 않는다(한글 키는 `Uni`로 만든다). 정렬·비교는 로케일/ordinal로 고정한다.
- `cases:` 선언 · 파트 내역 · Part O 머리글·블록을 **같은 편집에서** 고친다. 수는 README가 단일 선언처이고 이 문서에
  옮겨 적지 않는다.
- 되돌림 표에서 빼는 케이스의 사유는 `infeasible-evidenced`의 세 요소를 따른다.

### M70-T06: Part W가 생명주기 상태표 병기어의 정합을 문다 (deps: M70-T02)

- **변경 파일**: `tests/discover/run.sh` · `tests/discover/run.ps1` · `tests/discover/README.md`

- T02가 선언한 병기어를 Part W의 기존 형태(`W49`~`W57` · `W58`~`W66`)로 문다.

## 완료 기준

1. impl 보고서가 T01 실측을 적는다.
   - 생명주기 상태 목록(최소 열하나)
   - 상태마다 현행 Part O의 기대·실제(두 사본)
   - 신호 후보별로 표에서 틀리는 상태의 이름
   - 택한 안과 사유
   - ⑺·⑻ 구별 가능성의 실측(불가라면 세 요소)
2. 규약이 새 판정의 **생명주기 상태표 요구**를 병기어로 선언하고, 재서술처(`skills/impl/SKILL.md` ·
   `skills/impl/template.md`)가 그것을 가리킨다. 상태 목록의 단일 선언처가 한 곳이며, 「기계가 무는 것과 사람의 영역」이
   같은 자리에 있다.
3. 규약의 stale 대상·백스톱 갈래가 T01이 택한 신호로 다시 쓰이고, 갈래 표가 T01 목록의 모든 상태를 덮는다.
   「최대 번호(진행 중인 사이클)는 대상이 아니다」라는 문장과 「경계(수용된 잔여 위험)」 문단이 새 사실에 맞게 바뀌었다.
4. 아래 사본 상태 각각에서 두 사본의 Part O가 **기대대로** 나온다.
   - ⑹ ⑵ 상태에서 다음 마일스톤 초안(M69 미릴리즈 + `M70.md` 형태) → 붉지 않는다.
   - ⑶ 릴리즈 커밋 → 붉지 않는다.
   - ⑼ debug 릴리즈 커밋(회고 최신) → 붉지 않는다.
   - ⑻ 회고 건너뜀 + 다음 마일스톤 → 붉는다.
   - ⑽ 회고 건너뜀 + debug 릴리즈 커밋 → 붉는다.
   - ⑺ 릴리즈 커밋 상태에서 다음 마일스톤 초안 → T03이 규약에 적은 기대대로 나온다(⒝면 붉는다 · ⒜면 T01이 적은 대로).
5. 아래 교란 각각에서 `tests/discover`가 붉는다(두 사본).
   - 새 신호 추출을 죽인다.

   - 대상 선택을 옛 「최대 번호」 방식으로 되돌린다.
   - 대상 선택을 「전부 포함」으로 고정한다.
