# M10 — 안정화 라운드 (병렬 디스패치 실증 겸용)

## 목표

이 마일스톤이 끝나면 회고가 추적해 온 운영·규약 부채 셋이 해소되고, **동시에 M9의
병렬 디스패치가 실제로 작동함이 실증**된다. M10은 의도적으로 **의존 없고 변경 파일이
겹치지 않는 태스크 3개(T01·T02·T03)** 를 같은 위상 레벨에 두어, `/tide:impl`·`/tide:cycle`이
이 레벨을 **동시 서브에이전트로 디스패치**하도록 강제하는 실증 도구를 겸한다. 통합·검증은
이 셋에 의존하는 T04가 레벨 배리어 뒤에서 수행한다.

## 배경

v0.10.0 회고(`docs/reports/retro.md`)가 "백로그가 신규 기능→출시분 실증으로 전환됐다"며
다음 1순위로 **안정화 라운드**를, 그 안에서 **병렬 디스패치 런타임 실증**을 지목했다.
사용자가 `marketplace update`로 설치 캐시를 v0.10.0(병렬 디스패치 절 포함)으로 갱신해
**실증 창이 열렸다** — 이제 활성 스킬이 병렬 경로 지침을 갖는다.

선정된 백로그 항목은 모두 **서로 다른 파일**을 건드려 병렬 실증의 깨끗한 픽스처가 된다:

- release 운영·도구 함정의 노트화 (M9 회고 군집 "release 운영·도구 함정"이 "학습됨"으로
  이동 — 영구화 가치) → `skills/release/SKILL.md`
- 마일스톤 템플릿에 태스크별 "변경 파일" 필드 (M9-review 권장1 — 병렬 겹침 감지를
  휴리스틱에서 결정적으로) → `skills/milestone/template.md`
- 메타 용어 누수 방지 규약 + 빌드 출력 검증의 릴리즈 체크리스트화 (M9-impl#2 — v0.9.0류
  회귀를 release 시점에 잡기) → `docs/conventions.md`

> **이 마일스톤은 그 자체가 M9 병렬 디스패치의 도그푸딩 시나리오다**(M9-impl#1).

## 태스크 목록

- M10-T01: release 운영 노트를 release 스킬에 추가
- M10-T02: 마일스톤 템플릿에 태스크별 "변경 파일" 필드 추가
- M10-T03: 메타 용어 누수 방지 + 릴리즈 빌드 출력 검증 규약 (conventions)
- M10-T04: 문서 반영·일관성 + strict 빌드/병렬 실증 기록 (deps: M10-T01, M10-T02, M10-T03)

> T01·T02·T03은 **상호 무의존 + 변경 파일 비중첩** — 같은 위상 레벨이므로 impl이 동시
> 서브에이전트로 디스패치한다. T04만 셋에 의존(레벨 배리어 뒤 통합).

## 태스크 상세

### M10-T01: release 운영 노트를 release 스킬에 추가

- **변경 파일**: `skills/release/SKILL.md`
- `skills/release/SKILL.md`에 "운영 주의" 절을 추가해 최근 release에서 반복된 함정을
  규약화한다:
  1. **`.tide/phase`=`release` 기록은 git 명령과 별도 단계로 먼저** 실행한다 — tide-guard는
     명령 실행 *전* phase를 읽으므로 `phase 기록 && git ...`를 한 명령에 넣으면 직전 phase로
     차단된다.
  2. **커밋 메시지는 실행 환경의 멀티라인 문법에 맞춘다** — 여러 줄이면 `-m`을 반복하거나
     환경에 맞는 here-doc/here-string을 쓴다(셸 불일치 시 메시지에 토큰이 오염될 수 있음).
  3. **CHANGELOG/README 릴리즈 노트에 제외 대상 용어(외부 저장소명 등)를 literal로 쓰지
     않는다** — 단일 원본화로 사이트에 유입될 수 있다(M10-T03과 정합).
- 기존 release 단계 절차(프리플라이트·버전 범프·commit/tag/push)는 변경하지 않고 주의
  절만 덧붙인다.

### M10-T02: 마일스톤 템플릿에 태스크별 "변경 파일" 필드 추가

- **변경 파일**: `skills/milestone/template.md`
- `skills/milestone/template.md`의 "태스크 상세" 블록에 각 태스크가 **건드릴 파일을 한
  줄로 적는 권장 필드**를 추가한다(예: `- 변경 파일: {경로들}`). 목적: impl의 병렬 겹침
  감지가 마일스톤 단위 표에서 추정하던 것을 **태스크별로 결정적**으로 만든다(M9-review
  권장1).
- 필수가 아니라 권장 필드로 둔다(기존 마일스톤과 하위 호환). conventions의 마일스톤 문서
  규약과 모순되지 않게 — 문구는 "가능하면 태스크별 변경 파일을 명시(병렬 안전·겹침 감지에
  쓰임)" 수준.

### M10-T03: 메타 용어 누수 방지 + 릴리즈 빌드 출력 검증 규약 (conventions)

- **변경 파일**: `docs/conventions.md`
- `docs/conventions.md`에 두 규칙을 추가한다(본문 마커 안쪽 → 사이트 자동 반영):
  1. **메타 용어 누수 방지**: 사이트에서 제외하기로 한 용어(외부 저장소명 등)는 CHANGELOG·
     conventions의 **검증을 서술하는 메타 문장에서도 쓰지 않는다** — 단일 원본화(snippets)로
     사이트 콘텐츠가 되기 때문(v0.9.0 회귀 근거).
  2. **릴리즈 빌드 출력 검증**: release 시 사이트를 빌드한 산출물 기준으로 제외 용어 0건을
     확인하는 절차를 "버전·CHANGELOG" 또는 프리플라이트 항목에 한 줄 추가 — 회귀를 release
     시점에 잡도록(현재는 다음 사이클이 잡음).
- `docs/conventions.md`만 수정한다(T01의 release 스킬·T02의 템플릿과 파일 비중첩 유지).

### M10-T04: 문서 반영·일관성 + strict 빌드/병렬 실증 기록 (deps: M10-T01, M10-T02, M10-T03)

- **변경 파일**: `README.md`, `docs/project-context.md`
- T01~T03 완료 후, 변경이 사용자 대면 문서와 일관되게 반영됐는지 확인하고 필요한 한 줄을
  `README.md`·`docs/project-context.md`에 반영한다(예: 마일스톤 "변경 파일" 권장 필드,
  릴리즈 체크리스트 언급). **conventions·release 스킬·템플릿 본문은 재수정하지 않는다**
  (T01~T03 소관 — 파일 비중첩 유지).
- 격리 venv에서 `mkdocs build -f site/mkdocs.yml --strict` 통과 + 사이트 제외 용어 0건
  재확인(T03이 conventions에 더한 내용이 사이트에 정상 반영되는지).
- **병렬 실증 기록(핵심)**: 이 마일스톤을 impl할 때 T01·T02·T03이 **실제로 동시
  서브에이전트로 디스패치됐는지**(같은 메시지에서 병렬 Agent 호출, 파일 비중첩으로 폴백
  없이 병렬 유지)를 완료보고서에 기록한다. 폴백이 발생했다면 그 사유도.

## 파일 변경 요약

| 구분 | 파일 |
|---|---|
| 추가 | (없음) |
| 수정 | `skills/release/SKILL.md`(T01), `skills/milestone/template.md`(T02), `docs/conventions.md`(T03), `README.md`·`docs/project-context.md`(T04) |
| 삭제 | (없음) |

> T01·T02·T03의 변경 파일이 서로 겹치지 않음을 위 표로 확인 가능 — 병렬 픽스처의 전제.

## 완료 기준

1. `skills/release/SKILL.md`에 운영 주의 3종(phase↔git 분리·멀티라인 메시지·제외 용어
   literal 회피)이 추가되고, 기존 release 절차는 무변경이다.
2. `skills/milestone/template.md`에 태스크별 "변경 파일" 권장 필드가 추가되고 하위 호환
   (필수 아님)이다.
3. `docs/conventions.md`에 메타 용어 누수 방지 + 릴리즈 빌드 출력 검증 규약이 추가되고,
   snippets로 사이트 conventions에 반영된다.
4. `mkdocs build -f site/mkdocs.yml --strict` 통과 + 사이트 빌드 출력 제외 용어 0건.
5. README·project-context가 변경과 일관되고, 매니페스트는 무수정이다.
6. **병렬 실증**: 완료보고서에 T01·T02·T03이 동시 서브에이전트로 디스패치됐는지(또는
   폴백 사유)가 기록돼, M9 병렬 디스패치의 런타임 동작이 확인된다.
