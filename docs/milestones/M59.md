# M59 — 게시할 수 없는 환경에서 릴리즈가 종료 상태를 갖는다

## 목표

`/tide:release`가 **원격에 닿지 못하는 환경**에서 실패가 아니라 **명명된 종료 상태**로 끝난다. 릴리즈
판정 기계가 이미 로컬 태그만 보고 있다는 사실을 절차가 따라잡아, `commit`·`tag`까지 끝난 트리를
「실패」로 보고하던 자리가 닫힌다. 사용자는 무엇이 일어났고 무엇이 남았는지를 **보고에서 바로** 읽고,
남은 것이 push 두 줄뿐임을 안다. 그리고 검증 게이트가 겸하고 있던 두 물음 — *"gh가 다룰 GitHub인가"*
와 *"push가 되는가"* — 이 갈려서, 한쪽이 실패해도 다른 쪽이 잘못 끌려가지 않는다.

## 배경

**사용자 요구(2026-09-02)**: *"릴리즈 단계에서 git과 연결되지 않는 로컬 환경에서 진행하도록 하는 부분이
있으면 좋겠다."* 우선순위는 **B 조건**(원격은 설정돼 있으나 닿지 않는 상태)으로 지정됐다.

**실측으로 가른 상태 넷** (v2.24.0 트리 기준):

| 상태 | 지금 어떻게 되는가 | 이번 범위 |
|---|---|---|
| **A. git 레포인데 원격이 없다** | 검증 ④ 실패 → 「gh 게시 불가」 → push-only → `git push`에서 죽는다 | **받는다**(B의 게이트에 얹힘) |
| **B. 원격은 있는데 닿지 않는다**(오프라인·에어갭·VPN 밖) | 같은 자리에서 죽는다 | **1순위** |
| **C. 원격이 GitHub가 아니다**(GitLab·Gitea) | 검증 ④는 실패하나 push는 **정상 동작** | **이미 처리됨 — 건드리지 않는다** |
| **D. git 레포가 아니다** | `commit`·`tag` 자체가 불가 | **열지 않는다**(사유는 T01) |

**핵심 관찰 — 로컬 릴리즈는 이미 일어나고 있다. 이름이 없을 뿐이다.** tide가 *"릴리즈됐다"* 를
판정하는 기계는 전부 로컬이다: 프리플라이트 1b는 `git tag` + `git ls-tree <태그> docs/reports/` 로,
프리플라이트 5⑴은 `git tag` + `git diff --name-only <태그>..HEAD` 로 판정하며 **원격을 한 번도 보지
않는다.** 즉 이 저장소의 정의로 **릴리즈 = 로컬 태그이고 push는 게시**다. A·B에서 실제로 벌어지는
일은 `add → commit → tag` 가 **전부 성공한 뒤** push만 실패하는 것이며, 트리는 정상이고 다음 사이클의
판정·커버리지도 정상 동작한다. **결과물은 옳은데 보고만 실패로 끝난다.** 그러므로 이 사이클은 없는
기능을 만드는 것이 아니라 **이미 도달하는 종료 상태에 이름과 보고를 주는** 것이다.

**C가 축 분리의 증거다.** `docs/conventions-release.md`의 "검증 게이트" 절 ④는 *"대상 원격이 gh가
다룰 수 있는 GitHub 레포인지"* 를 물으면서 *"push가 되는가"* 를 겸하고 있다. 이 둘은 별개이고,
GitLab 원격이면 ④는 실패하지만 push는 된다 — 겸직이 성립하지 않는 실례가 이미 규약 안에 적혀 있다.

**이 줄기가 `E3`의 첫 등재인 이유.** `E3`는 *"참조 구현 저장소 밖에서 같은 규칙과 같은 집행에
닿는다"* 를 노리고 축 셋(규칙 텍스트의 도달 · 산출물의 오염 · 집행의 국소성)을 열어 두었다. 이
마일스톤이 여는 것은 그 셋과 나란한 **넷째 면 — 절차의 환경 전제**다: 규칙 텍스트도 집행도 아니라
**절차 자체가 「닿는 원격이 있다」를 전제**하고 있었고, 그 전제는 이 저장소에서만 참이다. `E3`의
「속한 마일스톤」이 *"첫 등재는 이 줄기를 실제로 겨냥하는 다음 마일스톤이 한다"* 로 비어 있던 자리에
이것이 들어간다.

## 태스크 상세

### M59-T01: 규약에 게시 가용성 축을 세우고 게시 불가 종료 상태를 명명한다

- **변경 파일**: `docs/conventions-release.md` · `docs/conventions.md`

`docs/conventions-release.md`의 "릴리즈 게시 (gh)" 절이 게시 규약의 단일 원본이므로 여기서 축을
가른다. 넷을 한다.

**⑴ 검증 게이트를 두 축으로 가른다.** 현재 ①~④가 한 줄로 서 있고 ④가 두 물음을 겸한다. 이것을
**게시 축**(gh)과 **push 축**(git 원격)으로 나눈다. ASCII 병기어 **`push-availability`** 를 push 축에
붙인다 — 규칙이 스킬·카탈로그에 재서술되므로 병기어가 없으면 Part E·새 집행이 결합할 대상이 없다
(규약의 *"이 절에 규칙을 더하면 ASCII 병기어를 함께 붙인다"*).
- **push 축이 묻는 것은 A뿐이다**: `git remote`가 비었는가. 네트워크를 건드리지 않고 즉시·확실하게
  판정된다.
- **B를 미리 재지 않는다는 것을 규약이 명시한다.** `git ls-remote`는 오프라인에서 수십 초 매달리므로
  사전 측정을 **금지**하고, B는 **push를 시도한 결과로** 갈린다고 적는다. 사전 측정보다 싸고, 어차피
  push가 진짜 답이라 위양성이 없다. 이 「재지 않기로 한 결정」은 근거와 함께 남긴다 — 근거 없는 부재는
  다음 사이클이 「빠뜨린 것」으로 읽는다.

**⑵ 종료 상태를 명명한다.** ASCII 병기어 **`unpublished-release`**. 정의: *"릴리즈는 성립했고(로컬
태그) 게시만 일어나지 않은 상태."* 이 이름이 「릴리즈 = 로컬 태그 / push = 게시」라는 위 배경의 관찰을
문서에 고정한다. **실패가 아니라 성공 종료**임을 명시하고, 보고 의무를 규약이 요구한다 — ⒜ 무엇이
일어났는가(add·commit·tag 완료) ⒝ 무엇이 남았는가(`git push {remote} {기본 브랜치}` + `git push
{remote} v{버전}` 둘) ⒞ **왜 못 했는가를 A와 B로 구분**해서. A는 구조적 부재(원격 미설정)이고 B는
일시적 단절(닿지 않음)이라 사용자가 취할 행동이 다르다 — 같은 문면으로 보고하면 *"설정을 안 했나"* 와
*"네트워크가 죽었나"* 를 구분할 수 없다.

**⑶ 「명시 의도 비폴백」의 순서를 고정한다.** 규약의 "명시 의도 비폴백"·"원격 불가 처리" 절이 *"모드를
명시했는데 검증 실패면 중단하고 사유 보고(조용한 강등 금지)"* 를 **이미** 요구한다. **새 규칙을 쓰지
않는다** — 그 중단이 `commit`·`tag` **앞**에서 일어나는지 순서만 확인해 못박는다. push 축이 새로
생겼으므로 이 축의 실패도 같은 대우를 받는다는 한 줄만 더한다.

**⑷ D를 열지 않는 이유를 규약이 적는다.** 프리플라이트 1b가 「마지막 릴리즈 태그의 트리」로 미릴리즈를
가르는데, 태그가 영영 없으면 *"태그가 하나도 없으면 전부 미릴리즈"* 폴백이 **매 사이클** 걸린다. 그
폴백은 규약이 **첫 릴리즈 1회성**으로 명시·수용한 것이지 영구 상태가 아니며, D를 지원하면 커버리지
체크가 영구히 무의미해진다(`vacuous-pass`). 이 경계를 근거와 함께 남긴다.

**모드 축은 늘리지 않는다.** `local`을 `release`/`pr` 옆의 넷째 모드로 만들지 **않는다**. 모드로
만들면 `.tide/release-mode`에 저장될 수 있고, 그러면 나중에 원격이 생겨도 조용히 로컬에 머문다 —
「선언이 사실보다 오래 산다」 부류를 스스로 만드는 것이다. 가르는 선을 규약이 적는다: **모드는
사용자의 *의도*, 게시 가용성은 환경의 *사실*.** tide는 이 분리를 이미 한다(`.tide/autonomy`는 의도라
저장하고, `gh` 가용성은 사실이라 매번 잰다). `.tide/release-mode`의 값 집합은 **불변**이다.

`docs/conventions.md` 쪽은 조각을 가리키는 자리(1844~1845행 부근의 push-only 서술)만 새 축에 맞춰
정정한다 — 목록을 두 곳에 적지 않는다.

### M59-T02: release 스킬 절차를 그 축에 배선한다 (deps: M59-T01)

- **변경 파일**: `skills/release/SKILL.md`

스킬은 **절차**이고 규약이 **사유·상세**이므로, T01이 세운 것을 재서술하지 않고 **결정 지점만** 적는다.

- **게시 분기의 push-only를 둘로 쪼갠다**: 「`git add` → `commit` → `git tag`」(항상 돈다) + 「push」
  (push 축 통과 시에만 돈다). 앞 절이 끝난 시점이 **릴리즈가 성립한 시점**이다.
- **push 축 불통과 시** `unpublished-release`로 **성공 종료**하고 T01이 정한 보고 셋(⒜⒝⒞)을 낸다.
- **push를 시도했는데 실패한 경우**(B)도 같은 종료 상태로 수렴하되 보고 문면이 A와 갈린다.
- **`release` 모드**는 push-only 위에 얹히므로 push가 없으면 `gh release create`도 없다 — 게시가
  일어나지 않았음을 보고에 명시한다. **`pr` 모드**는 애초에 push 없이 성립하지 않으므로 push 축
  불통과면 **모드 해석 단계에서 중단**된다(T01 ⑶의 순서 — 파일 편집 전).
- 스킬 머리말(`description`·`argument-hint`)이 push-only를 말하는 자리도 함께 본다.

**`.tide/phase` 계약·tide-guard·커맨드 12종·프리플라이트 3게이트는 불변이다.** 이 사이클은 게시
분기 안쪽만 건드린다.

### M59-T03: 재서술처 전파 — push-only를 말하는 나머지 자리 (deps: M59-T01)

- **변경 파일**: `docs/commands.md` · `tests/multi-repo/README.md` · (실측으로 발견되는 나머지)

`push-only`/`commit→tag→push`를 말하는 자리는 **실측 6파일 15군데**다(v2.24.0 트리): 
`docs/conventions-release.md`(5) · `skills/release/SKILL.md`(4) · `docs/conventions.md`(2) ·
`docs/commands.md`(1) · `tests/multi-repo/README.md`(1) 외. 앞 셋은 T01·T02가 가져가고 **이 태스크가
나머지를 받는다.** CLAUDE.md의 *"규칙을 고치면 그 규칙을 재서술한 자리를 같은 편집에서 고친다"* 가
정확히 걸리는 넓이이며, M58이 회고 쓰기 범위에서 여덟 자리를 함께 고친 것과 같은 크기다.

**착수 전에 목록을 다시 실측한다** — 위 수는 계획 시점 값이고, T01·T02가 문면을 바꾸면 움직인다.
수를 문서에 박지 않고 **발견 방법**(`push-only`·`commit→tag→push` 토큰 글롭)을 적는다.

### M59-T04: 선언 정합 집행을 세운다 (deps: M59-T01, M59-T02, M59-T03)

- **변경 파일**: `tests/discover/run.sh` · `tests/discover/run.ps1` · `tests/discover/README.md`

무는 것은 **선언 정합**이다 — 새 축과 종료 상태의 이름이 규약↔스킬↔카탈로그에서 **같은 집합**인가.
Part D(브랜치 협업 안전 선언 정합)·Part E(리뷰 규율 선언 정합)와 같은 부류이며, 새 Part로 세울지
기존 Part에 얹을지는 구현이 정한다.

- **양성 통제 필수**: 추출이 0건이면 **FAIL**이다(`vacuous-pass` 방지 — 규약의 새 검사 체크리스트).
- **선언 줄 유일성**: 병기어 선언이 규약에서 **정확히 한 줄**임을 단언한다.
- **되돌림 실측**: 세운 케이스마다 선언 토큰을 깨면 **그 케이스가** 붉는지 실측하고 결과를 impl
  보고서에 적는다.
- **음성 통제**: 축이 늘지 않은 문서를 붉히지 않는다.
- **양 사본 동형** — `run.sh`·`run.ps1` 총계 일치(F1)와 `run.ps1`의 byte>127=0 규율을 지킨다.
- `tests/discover/README.md`의 `cases:` 선언을 **같은 편집에서** 갱신한다(러너가 실측과 대조한다).

**픽스처 레벨은 이번에 세우지 않는다** — 「원격 없는 레포에서 실제로 로컬 태그가 달리는가」는
`tests/multi-repo`가 샌드박스 레포를 만드는 방식으로 덮을 수 있으나, 그 하니스는 **가드 계약**을 무는
자리이고 이 사이클은 게시 분기 안쪽을 건드린다. 세우지 않기로 한 이 결정과 **그 근거**를 impl 보고서와
아래 완료 기준 6이 적는다 — 적지 않으면 다음 사이클이 「빠뜨린 것」으로 읽는다.

## 완료 기준

1. **A 상태**(`git remote`가 비어 있음)에서 모드 미지정으로 release를 돌리면 `add`·`commit`·`tag`가
   끝나고 **성공으로 종료**하며, 보고에 ⒜ 완료된 것 ⒝ 남은 push 두 줄 ⒞ 사유가 **A로** 적힌다.
2. **B 상태**(원격은 설정됐고 push가 실패)에서 같은 종료 상태에 수렴하며, 보고의 사유가 **B로** 적혀
   A와 구분된다.
3. **C 상태**(GitHub 아닌 원격)의 동작이 v2.24.0과 **바이트 동일**하다 — push가 정상 수행되고
   `unpublished-release`에 들어가지 않는다.
4. 모드를 **명시**(`pr`/`release`)했는데 push 축이 불통과면 **버전 파일·CHANGELOG를 건드리기 전에**
   중단하고 사유를 보고한다(작업 트리 무변경).
5. `.tide/release-mode`가 가질 수 있는 값의 집합이 v2.24.0과 **같다** — `local` 등이 늘지 않았다.
6. **경계가 문서에 적혀 있다**: ⑴ D를 열지 않는 이유 ⑵ B를 사전 측정하지 않는 이유 ⑶ 픽스처 레벨을
