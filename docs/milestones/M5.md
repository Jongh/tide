# M5 — /tide:cycle 오케스트레이션 (단계 자동 체이닝 + deps 기반 실행)

## 목표

한 번의 호출로 `milestone → impl → review`를 자동으로 이어 실행하고, 마일스톤 내
태스크의 `(deps:)` 표기를 읽어 독립 태스크는 병렬로, 의존 태스크는 순서대로 진행하는
`/tide:cycle` 스킬이 생긴다. 사용자가 단계마다 수동 호출하지 않아도 한 사이클을 끝까지
(릴리즈 직전까지) 자동 진행할 수 있는 상태가 된다.

## 배경

다른 세션에서 정리된 백로그: "M4 후보인 `/tide:cycle` 오케스트레이션 — 마일스톤→구현→
리뷰 자동 체이닝, deps 기반 병렬". 현재는 각 단계를 사용자가 수동으로 호출해야 한다
(`docs/conventions.md` 사이클 다이어그램). `release`만은 유일하게 git 작업을 하는
단계이므로 자동 체이닝에서 제외하고 사용자에게 넘기는 것이 **부수효과 분리 원칙**
(conventions)과 tide-guard 동작에 그대로 부합한다.

M4(브라운필드 킥오프)·M6(`/tide:retro`)와 독립이며, 어느 순서로 진행해도 무방하다.

## 태스크 목록

- M5-T01: `/tide:cycle` 스킬 골격 + phase 기록/복원 + 단계 체이닝(milestone→impl→review)
- M5-T02: 마일스톤 `(deps:)` 파싱 → 독립 태스크 병렬 / 의존 태스크 순차 실행 규칙 (deps: M5-T01)
- M5-T03: release 제외 + 각 단계 전제조건·실패 시 중단 처리 (deps: M5-T01)
- M5-T04: conventions·README에 cycle 단계 반영 (deps: M5-T01)
- M5-T05: 드라이런·도그푸딩 검증 (deps: M5-T01, M5-T02, M5-T03, M5-T04)

## 태스크 상세

### M5-T01: cycle 스킬 골격 + 단계 체이닝

`skills/cycle/SKILL.md`를 신설한다. frontmatter는 기존 스킬과 동일 형식
(`description`·`argument-hint`). 본문은 milestone → impl → review를 순서대로 호출·진행
하도록 기술하되, 각 단계 진입 시 `.tide/phase`에 해당 단계명을 기록하고 사이클 종료 시
`idle`로 되돌린다. **불확실성**: 플러그인이 `skills/` 하위를 자동 발견하는지(신규 스킬
등록에 `.claude-plugin/plugin.json` 수정이 필요한지)를 먼저 확인하고, 필요하면 등록을
포함한다 — M3에서 쓴 재설치+새 세션 노출 확인 절차를 재사용한다.

### M5-T02: deps 기반 병렬/순차 실행 규칙 (deps: M5-T01)

impl 단계에서 마일스톤 문서의 태스크 목록을 읽어 `(deps: …)` 표기를 파싱한다.
의존이 없는 태스크는 병렬 착수 가능으로, 의존이 있는 태스크는 선행 완료 후 착수로
스케줄링하는 규칙을 스킬 본문에 명시한다. 순환 의존·미존재 의존 ID 같은 이상 표기는
감지해 보고하고 보수적으로 순차 진행하도록 폴백을 정해둔다. (실제 병렬 실행 수단은
구현 단계에서 결정 — 규칙·표기 해석을 이 태스크에서 확정한다.)

### M5-T03: release 제외 + 전제조건/중단 처리 (deps: M5-T01)

`release`는 자동 체이닝에 포함하지 않는다 — review가 "가능" 판정을 내면 사이클을
종료하고 사용자에게 `/tide:release vX.Y.Z`를 안내한다. 각 단계의 기존 전제조건
(conventions 표: impl=마일스톤 문서, review=impl 보고서)을 사이클 안에서도 그대로
검사하고, 한 단계가 전제조건 미충족·실패로 멈추면 사이클 전체를 중단하고 어느 단계에서
왜 멈췄는지 보고한다. tide-guard가 비-release 단계의 git을 막는 동작과 충돌하지 않음을
확인한다(체이닝 구간에 git 작업이 없어야 한다).

### M5-T04: conventions·README 반영 (deps: M5-T01)

- `docs/conventions.md`: 사이클 다이어그램·금지 행위 표에 `cycle`을 추가하고, "수동
  단계별 호출 vs cycle 자동 체이닝(release 제외)" 관계를 명시
- `README.md`: 커맨드 표·사이클 설명에 `/tide:cycle` 추가

### M5-T05: 드라이런·도그푸딩 검증 (deps: M5-T01~T04)

재설치 후 새 세션에서: `/tide:cycle`이 노출되고, 마일스톤 문서가 있는 상태에서 호출 시
impl→review까지 진행한 뒤 release 직전에 멈추고 안내하는지, deps 표기가 다른 두
마일스톤(독립/의존 혼재)으로 스케줄링 규칙이 의도대로 해석되는지 확인한다.

## 완료 기준

1. 재설치 후 새 세션에서 `/tide:cycle`이 노출되고 호출된다
2. 마일스톤 문서가 있는 상태에서 `/tide:cycle` 실행 시 milestone(필요 시)→impl→review가
   순서대로 진행되고, review "가능" 판정 후 release 직전에 멈춰 `/tide:release`를 안내한다
3. 마일스톤의 `(deps:)` 표기가 독립=병렬·의존=순차 규칙으로 해석된다(스킬 본문에 명시,
   드라이런으로 해석 확인)
4. 한 단계 전제조건 미충족·실패 시 사이클이 중단되고 중단 지점·사유가 보고된다
5. `docs/conventions.md`·`README.md`에 `/tide:cycle`이 반영된다
