# M12 — 1.0 준비: 잔여 정리·견고화 + 안정 선언

## 목표

이 마일스톤이 끝나면 tide가 **v1.0.0(안정 선언)** 으로 릴리즈할 준비가 된다 — 11사이클간
쌓인 잔여 정리(README↔CHANGELOG 중복 제거)·견고화(배포 트리거)·메타 규칙(규약↔실행
동기화)이 처리되고, 커맨드 8종·규약·`.tide/phase`/tide-guard 계약이 **안정(stable)** 으로
문서에 선언된다. 백로그에 큰 기능도 실증 부채도 남지 않은, 회고가 확인한 "1.0 전제 충족"
상태를 실제 1.0으로 확정한다.

## 배경

v0.12.0 회고(`docs/reports/retro.md`)의 결론: "백로그가 신규기능(M5~M9) → 실증/안정화
(M10~M11) → **견고화·정리·cosmetic**으로 또 한 단계 내려갔다. 11사이클 연속 '가능', 전부
minor, 차단은 M1 1건뿐. **1.0 논의의 전제가 실제로 갖춰졌다**." 사용자가 다음 라운드를
**v1.0.0 안정 선언**으로 끊기로 결정했다.

회고가 남긴 잔여·메타 항목:
- **배포 트리거 견고화** (M11-review 권장1): `paths` 허용목록이 단일 원본 인클루드 확장에
  취약 — 루트 파일이 늘면 또 낡는다.
- **README↔CHANGELOG 단일화** (M8·M9 이후 미반영): 규약상 동일 노트를 두 곳에 둬 이중
  갱신.
- **"규약↔실행/인프라 동기화" 메타 규칙** (회고 메모 4): 개별 픽스로 안 닫히는 군집 —
  "규약/단일 원본을 더하면 그것을 강제·반영할 실행/CI/스킬도 같은 사이클에" 를 규칙화.
- **`site_url` 대소문자** (M11-impl#4, cosmetic).

## 태스크 목록

- M12-T01: 배포 트리거 견고화 (main 푸시마다 빌드)
- M12-T02: 1.0 규약·문서 정리 (안정 선언 + 메타 규칙 + README↔CHANGELOG 단일화)
- M12-T03: 사이트 cosmetic 정리 + 홈 안정성 반영
- M12-T04: 1.0 종합 검증·일관성 점검 (deps: M12-T01, M12-T02, M12-T03)

> T01·T02·T03은 상호 무의존 + 변경 파일 비중첩 → 같은 레벨로 동시 디스패치. T04만 셋에
> 의존(배리어 뒤 통합·검증).

## 태스크 상세

### M12-T01: 배포 트리거 견고화 (main 푸시마다 빌드)

- **변경 파일**: `.github/workflows/deploy-pages.yml`
- M11 권장1: `paths` 허용목록은 단일 원본 인클루드가 늘면 또 낡는다(구조적 취약). 가장
  견고한 해결로 **`push` 트리거의 `paths` 필터를 제거하고 `main` 푸시마다 빌드·배포**한다
  (사이트 빌드가 ~1초로 가벼워 비용 무시 가능). `workflow_dispatch`는 유지.
  - `concurrency`로 동시 배포 방지는 그대로.
  - 워크플로우 주석에 "사이트가 단일 원본 인클루드하는 루트 파일이 늘어도 누락 위험이
    없도록 main 전체를 트리거로 둔다"는 이유를 남긴다.
- 대체 경로(견고성↔효율 트레이드오프를 효율 쪽으로 두고 싶으면): paths 유지 + "인클루드
  루트 파일을 추가하면 paths에도 추가" 규칙을 T02 메타 규칙에 편입. **기본은 paths 제거**
  (M11이 보인 누락 위험 > 빌드 비용).

### M12-T02: 1.0 규약·문서 정리 (안정 선언 + 메타 규칙 + README↔CHANGELOG 단일화)

- **변경 파일**: `docs/conventions.md`, `README.md`, `skills/release/SKILL.md`, `docs/project-context.md`
- **(a) 안정 선언**: `docs/conventions.md`와 `README.md`에 "1.0 안정성" 절을 추가 — **커맨드
  8종의 호출명·역할, 단계별 규약, `.tide/phase`/tide-guard 계약, 보고서/마일스톤 형식이
  1.0부터 안정(stable)** 임을 선언. 하위 호환을 깨는 변경은 다음 major에서만.
- **(b) "규약↔실행/인프라 동기화" 메타 규칙**: `docs/conventions.md`에 규칙 추가 — **규약·
  단일 원본을 새로 더하면, 그것을 강제·반영할 실행 수단(스킬 프리플라이트·hook·CI 트리거·
  빌드)도 같은 사이클에 함께 손본다.** (근거: 빌드검증 규약↔release 배선 간극, 단일 원본
  인클루드↔배포 트리거 간극이 반복됨.)
- **(c) README↔CHANGELOG 단일화**: `README.md`의 `## CHANGELOG` 섹션의 **중복 노트를 제거**
  하고 `CHANGELOG.md`로 가는 **포인터**(예: "릴리즈 노트는 [CHANGELOG.md] 참조")로 대체.
  이에 맞춰 `docs/conventions.md`의 "버전·CHANGELOG" 규칙에서 "README에도 동일 노트"를
  **"CHANGELOG.md가 단일 원본, README는 포인터"** 로 수정하고, `skills/release/SKILL.md`의
  릴리즈 절차 중 "README CHANGELOG 섹션에 동일 내용 추가" 단계를 **제거**한다(불일치 방지).
  - 주의: 이 변경 이후 release는 CHANGELOG.md만 갱신한다. 사이트 changelog는 이미
    `CHANGELOG.md`를 단일 원본으로 인클루드하므로 영향 없음.
- **(d)** `docs/project-context.md`에 1.0 안정 선언·메타 규칙을 한 줄 반영.
- 메타 용어 누수 방지 규약 준수(제외 용어 literal 미사용).

### M12-T03: 사이트 cosmetic 정리 + 홈 안정성 반영

- **변경 파일**: `site/mkdocs.yml`, `site/docs/index.md`
- `site/mkdocs.yml`의 `site_url`을 라이브 실제 호스트에 맞춰 **소문자**(`https://jongh.github.io/tide/`)
  로 정렬(M11-impl#4 — GitHub 정규화로 동작엔 무문제이나 정확성).
- `site/docs/index.md`(홈)에 1.0 안정성 한 줄을 자연스럽게 반영(예: "커맨드·규약이 1.0부터
  안정"). 과한 추가는 피하고 기존 톤 유지.
- `docs/conventions.md`·`README.md`(T02 소관)는 건드리지 않는다 — 파일 비중첩 유지.

### M12-T04: 1.0 종합 검증·일관성 점검 (deps: M12-T01, M12-T02, M12-T03)

- **변경 파일**: (없음 — 검증. 불일치 발견 시 해당 파일 최소 수정)
- T01~T03 완료 후 통합 점검:
  - **일관성**: 안정 선언·메타 규칙·README 포인터·release 절차(README 단계 제거)가 서로
    모순 없는지. conventions·README·project-context·release 스킬 간 정합.
  - **strict 빌드 + 빌드 출력 제외 용어 0건**: 격리 venv에서 `mkdocs build -f site/mkdocs.yml

  - **매니페스트**: 버전 범프는 release에서 1.0.0으로 하되, 자동 발견(매니페스트 구조

    파괴 변경이 이 라운드에 없는지(전부 가산·정리) 확인.

## 완료 기준

1. `deploy-pages.yml`이 `main` 푸시마다 빌드·배포하도록 견고화되고(`paths` 필터 제거,
   `workflow_dispatch` 유지), 이유가 주석에 남는다.
2. `README.md`의 CHANGELOG 중복 노트가 제거되고 `CHANGELOG.md` 포인터로 대체되며,
   `docs/conventions.md` 버전 규칙과 `skills/release/SKILL.md` 절차가 "CHANGELOG 단일 원본·
   README 포인터"로 정합한다(release가 README CHANGELOG를 더는 안 건드림).
3. `docs/conventions.md`·`README.md`에 1.0 안정성 선언(커맨드 8종·규약·phase/guard 계약)과
   "규약↔실행/인프라 동기화" 메타 규칙이 명시된다.
4. `site/mkdocs.yml` `site_url`이 소문자로 정렬되고, 홈에 안정성이 반영되며,
   `mkdocs build --strict` 통과 + 사이트 출력 제외 용어 0건이다.
5. 매니페스트 구조 무수정(자동 발견), 문서 전반이 1.0 선언과 일관되고, 이 라운드에 하위
   호환을 깨는 변경이 없다(전부 정리·가산).
