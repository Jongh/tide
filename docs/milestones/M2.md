# M2 — 플러그인 패키징 + 템플릿 파일화

## 목표

tide를 Claude Code **플러그인** 구조로 재편해 설치·업데이트를 `/plugin` 한 번으로
만들고, hook을 플러그인이 직접 제공하게 하여 **kickoff 내장 스크립트와 `hooks/`
원본의 이중 관리를 제거**한다. 아울러 마일스톤·보고서 형식을 산문 규약이 아닌
**실물 템플릿 파일**로 옮겨 형식 드리프트를 차단한다.

## 배경

v0.2.0의 두 가지 구조적 부채가 남아 있다 (M1 리뷰보고서 후속 메모):

1. **이중 관리** — tide-guard 스크립트가 `hooks/` 원본과 kickoff 커맨드 내장본
   두 곳에 존재해 수정 시 항상 동기화해야 한다. 전역 설치(`cp`) 시에도 자급자족하려던
   설계인데, 플러그인은 커맨드·hook·부속 파일을 한 패키지로 배포하므로 내장이
   필요 없어진다. hook 경로도 `${CLAUDE_PLUGIN_ROOT}` 기준으로 등록되어 kickoff의
   프로젝트별 hook 설치 절차 자체가 사라진다.
2. **형식 드리프트** — 마일스톤 7개 섹션·보고서 형식이 커맨드/규약 문서의 설명문으로만
   존재해, 실행할 때마다 모델이 형식을 재해석한다. 템플릿 실물 파일을 두고 "복사해서
   채워라"로 바꾸면 형식이 고정되고 커맨드 프롬프트도 짧아진다.

## 태스크 목록

- M2-T01: 플러그인 골격 생성 — `.claude-plugin/plugin.json` + 커맨드를 `commands/`로 이동
- M2-T02: hook을 플러그인 제공으로 전환 — `hooks/hooks.json` + `${CLAUDE_PLUGIN_ROOT}` 경로 (deps: M2-T01)
- M2-T03: kickoff 다이어트 — 내장 스크립트·hook 설치 절차 제거, 골격 생성만 유지 (deps: M2-T02)
- M2-T04: 템플릿 파일 작성 — `templates/` 에 마일스톤·완료보고서·리뷰보고서 3종
- M2-T05: milestone/impl/review 커맨드가 템플릿을 참조하도록 수정 (deps: M2-T04)
- M2-T06: 마켓플레이스 매니페스트 — `.claude-plugin/marketplace.json` (deps: M2-T01)
- M2-T07: 도그푸딩 전환 — 이 저장소에서 플러그인 로컬 설치 검증, 구 설치물 정리 (deps: M2-T02, M2-T03)
- M2-T08: README·conventions 갱신 — 플러그인 설치 절차, 이중 관리 제거 반영 (deps: M2-T01~T07)

## 태스크 상세

### M2-T01: 플러그인 골격 생성

- `.claude-plugin/plugin.json` 작성: `name: "tide"`, `description`, `version`(현재 버전),
  `author` 등 최소 필드
- `.claude/commands/tide-*.md` 6종을 플러그인 표준 위치 `commands/`로 **이동**
  (이동 후 단일 원본 — `.claude/commands/`에 사본을 남기지 않는다, 도그푸딩은 T07에서
  플러그인 설치로 해결)
- 커맨드 동작·frontmatter는 변경하지 않음 (이동만)

### M2-T02: hook을 플러그인 제공으로 전환 (deps: M2-T01)

- `hooks/hooks.json` 작성 — PreToolUse(`Bash|PowerShell` 매처)에 tide-guard 등록.
  스크립트 경로는 `${CLAUDE_PLUGIN_ROOT}/hooks/tide-guard.*`
- 플랫폼 분기: 단일 등록으로 양 플랫폼을 처리할 방법을 우선 조사
  (예: sh 래퍼 하나로 통일하거나, hooks.json에서 OS별 command 분기가 가능한지 확인).
  불가하면 ps1·sh 중 런타임에 자기 OS가 아니면 즉시 exit 0 하는 상호 가드 추가
- 기존 `hooks/tide-guard.sh`·`.ps1`은 위치 유지 (플러그인 루트 기준 `hooks/`)
- 검증: 스크립트 단독 실행 시나리오(차단/통과)가 기존과 동일해야 함

### M2-T03: kickoff 다이어트 (deps: M2-T02)

- kickoff에서 hook 스크립트 내장본·`.claude/hooks/` 생성·`settings.json` 병합 절차
  **전부 제거** — 플러그인이 hook을 제공하므로 프로젝트별 설치가 불필요
- 남기는 것: 디렉터리/CHANGELOG/README 섹션/conventions/`.gitignore`(`.tide/`)/버전 보고
  + 템플릿 복사(T05와 연동)
- 수동 복사(`cp`) 설치 경로는 README에서 "가드 hook이 빠지는 비권장 경로"로 명시 (T08)

### M2-T04: 템플릿 파일 작성

`templates/` 디렉터리에 3종 생성. 각 파일은 섹션 골격 + 빈 칸 채움 안내 주석으로 구성:

- `templates/milestone.md` — 7개 섹션(목표/배경/태스크 목록/태스크 상세/파일 변경
  요약/완료 기준/메타데이터), 태스크 ID·(deps:) 표기 예시 포함
- `templates/impl-report.md` — 개요/태스크별 수행 내용/변경 파일 요약/테스트 결과/미해결·후속 메모
- `templates/review-report.md` — 비판점(차단/권장/사소)/수정 내용/검증/릴리즈 판정/다음 단계

기존 M1 문서·보고서의 실제 구조를 추출해 템플릿화한다 (규약과 어긋나지 않게).

### M2-T05: 커맨드의 템플릿 참조 전환 (deps: M2-T04)

- milestone/impl/review 커맨드에서 형식을 산문으로 나열하는 부분을
  "`${CLAUDE_PLUGIN_ROOT}/templates/<파일>` 템플릿을 읽어 그 구조대로 작성"으로 교체.
  커맨드 프롬프트에서 `${CLAUDE_PLUGIN_ROOT}` 참조가 동작하는지 확인하고, 안 되면
  kickoff가 `docs/templates/`로 복사해 두고 커맨드는 프로젝트 사본을 읽는 방식으로 대체
- 템플릿을 찾지 못한 경우의 폴백(기존 산문 형식 한 줄 요약)을 남겨 강건성 유지

### M2-T06: 마켓플레이스 매니페스트 (deps: M2-T01)

- `.claude-plugin/marketplace.json` 작성 — 이 저장소를 마켓플레이스로 등록 가능하게
  (`/plugin marketplace add <repo>` → `/plugin install tide`)
- plugin.json과 버전·메타데이터 일관성 확인

### M2-T07: 도그푸딩 전환 (deps: M2-T02, M2-T03)

- 이 저장소에서 플러그인을 로컬 설치(`/plugin marketplace add` 로컬 경로 또는 동등
  수단)하고 커맨드 6종·hook이 플러그인 경유로 동작하는지 검증
- 검증 후 구 설치물 정리: `.claude/commands/`의 사본(T01에서 이동 완료 확인),
  `.claude/hooks/`·`.claude/settings.json`의 tide-guard 등록 (플러그인 hook과 중복 차단
  방지 — 단, 플러그인 hook 동작이 확인되기 전에는 제거하지 않는다)
- 가드 실증: idle 상태에서 git commit 시도가 플러그인 hook으로 차단되는지 확인

### M2-T08: README·conventions 갱신 (deps: M2-T01~T07)

- README: 설치 절을 플러그인 우선으로 개편(마켓플레이스 추가 → install), 수동 복사는
  비권장 경로로 격하, 저장소 구조(commands/·hooks/·templates/·.claude-plugin/) 설명
- conventions: hook 제공 주체가 "kickoff 설치"에서 "플러그인 내장"으로 바뀐 것 반영,
  템플릿 파일 규약 절 신설(템플릿이 형식의 단일 원본임을 명시)

## 파일 변경 요약

| 구분 | 파일 |
|---|---|
| 추가 | `.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json` |
| 추가 | `hooks/hooks.json` |
| 추가 | `templates/milestone.md`, `templates/impl-report.md`, `templates/review-report.md` |
| 이동 | `.claude/commands/tide-*.md` 6종 → `commands/` |
| 수정 | `commands/tide-kickoff.md` (hook 설치 절차 제거), `tide-milestone.md`·`tide-impl.md`·`tide-review.md` (템플릿 참조) |
| 삭제 | `.claude/hooks/tide-guard.*`, `.claude/settings.json`의 tide-guard 등록 (T07 검증 후) |
| 수정 | `README.md`, `docs/conventions.md` |

## 완료 기준

1. `/plugin` 경유 설치만으로 커맨드 6종과 tide-guard hook이 함께 활성화된다
   (프로젝트별 hook 설치 절차 없이)
2. tide-guard 스크립트의 원본이 `hooks/` **한 곳**에만 존재한다 (kickoff 내장본 제거)
3. hook 차단/통과 시나리오가 기존과 동일하게 동작한다 (idle/impl/review 차단, release/파일
   없음 통과)
4. milestone/impl/review가 템플릿 파일 구조대로 문서를 생성하고, 템플릿 부재 시에도
   동작한다 (폴백)
5. 이 저장소가 플러그인 설치 방식으로 도그푸딩되며, 구 설치물(.claude/hooks 등)이
   정리되어 hook 중복 실행이 없다
6. README 설치 안내가 플러그인 절차와 일치하고, conventions가 새 구조를 반영한다
