# M6 — /tide:retro 회고 (누적 사이클 가로지르기)

## 목표

여러 사이클이 쌓인 뒤, 누적된 마일스톤·보고서를 가로질러 읽어 반복된 문제, 수용된
트레이드오프, 미반영된 후속 항목을 회고 문서로 정리하는 `/tide:retro` 스킬이 생긴다.
`status`와 동일하게 읽기 전용으로 동작하며 회고 산출물만 남긴다.

## 배경

다른 세션 백로그: "사이클이 더 쌓인 뒤의 `/tide:retro` 회고". `/tide:status`가 현재
위치(현 마일스톤/보고서/판정/phase)만 보는 반면, retro는 과거 사이클 전체를 가로질러
패턴을 뽑는다는 점에서 역할이 다르다. 사이클 수가 적으면 이득이 작으므로 M4·M5 이후
진행을 권장하지만, 산출물·동작 면에서는 두 마일스톤과 독립이다.

이미 M1~M3 보고서에 "수용(사소)"·"후속" 항목이 흩어져 있어(예: tide-guard 보수적
차단의 false positive, 수동 복사 설치의 일반명 충돌) 검증용 입력이 확보돼 있다.

## 태스크 목록

- M6-T01: `/tide:retro` 스킬 골격 + 읽기 전용 보장(status와 동일 원칙)
- M6-T02: 마일스톤·보고서 누적 수집·집계 규칙 정의 (deps: M6-T01)
- M6-T03: 회고 문서 산출물 위치·형식 정의 (+ 템플릿 동봉 여부) (deps: M6-T02)
- M6-T04: conventions·README 반영 (deps: M6-T01)
- M6-T05: 기존 M1~M3 보고서로 드라이런 검증 (deps: M6-T01, M6-T02, M6-T03, M6-T04)

## 태스크 상세

### M6-T01: retro 스킬 골격 + 읽기 전용 보장

`skills/retro/SKILL.md`를 신설한다(frontmatter 형식은 기존 스킬과 동일). status와 같은
원칙 — 파일 생성·수정과 git 작업 외에는 손대지 않되, retro는 회고 문서 **하나**만
생성/갱신하도록 허용한다(그 외 코드·문서 수정 금지, git 금지). `.tide/phase`는 변경하지
않는다(status와 동일하게 읽기 전용 단계로 취급). 신규 스킬 등록 필요 여부는 M5-T01과
동일한 방식으로 확인한다.

### M6-T02: 누적 수집·집계 규칙 (deps: M6-T01)

`docs/milestones/M*.md`와 `docs/reports/M*-impl.md`·`M*-review.md`를 모두 읽어 다음을
집계하는 규칙을 본문에 정의한다:
- 반복적으로 나타난 문제·차단/권장 이슈의 주제 군집
- 수용된 트레이드오프(사소·수용 항목) 목록과 그 사유
- "후속"으로 표기됐으나 이후 마일스톤에서 반영됐는지 미반영인지 추적
- 릴리즈 판정·버전 추이 요약

### M6-T03: 회고 문서 산출물 형식 정의 (deps: M6-T02)

산출물 위치를 정한다 — 후보: `docs/reports/retro.md`(갱신형 단일) 또는
`docs/retro/{기준일}.md`(시점별). 권장: 갱신형 단일 `docs/reports/retro.md`로 시작해
회고 시점마다 최상단에 누적(보고서 디렉터리 일관성 + 이력 보존). 형식이 반복 사용될
가치가 있으면 `skills/retro/template.md`를 동봉하고, 아니면 본문 인라인 형식으로 둔다
(milestone/impl/review 템플릿 패턴 재사용).

### M6-T04: conventions·README 반영 (deps: M6-T01)

- `docs/conventions.md`: 보고서 절에 회고 산출물 추가, 금지 행위 표에 `retro`(읽기 전용 +
  회고 문서만 생성) 추가
- `README.md`: 커맨드 표에 `/tide:retro` 추가

### M6-T05: 드라이런 검증 (deps: M6-T01~T04)

재설치 후 새 세션에서 `/tide:retro`를 호출해 기존 M1~M3 보고서로부터 회고 문서가
생성되는지, 반복 문제·수용 트레이드오프·미반영 후속이 실제 보고서 내용과 맞게
집계되는지, 회고 외 파일·git에 손대지 않는지 확인한다.

| 수정 | `docs/conventions.md`, `README.md` |

## 완료 기준

1. 재설치 후 새 세션에서 `/tide:retro`가 노출되고 호출된다
2. 호출 시 누적 마일스톤·보고서를 읽어 회고 문서(`docs/reports/retro.md` 등)를 생성한다
3. 회고 문서가 반복 문제·수용 트레이드오프·미반영 후속을 실제 보고서 내용과 맞게 담는다
4. retro 실행이 회고 문서 외 파일이나 git에 손대지 않는다(읽기 전용 원칙)
5. `docs/conventions.md`·`README.md`에 `/tide:retro`가 반영된다
