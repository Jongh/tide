# M74 — 에픽·회고 문서를 릴리즈 밖에서 커밋하는 경로를 연다

## 목표

**릴리즈가 아닐 때도 에픽과 회고 문서를 `/tide:release docs` 한 번으로 커밋할 수 있다.** 경로를 쓸 수 있는 조건은 phase `idle` · 열린 debug 세션 없음 ·
**화이트리스트 밖 미커밋 변경 0**이다. 그래서 하니스가 잰 작업 트리와 커밋되는 트리가 같다. `pr` 모드면 PR을 거치고, 그 밖의 모드면
기본 브랜치에 커밋하고 push한다. 버전 · CHANGELOG · 태그 · 릴리즈 표지 · 회고는 건드리지 않는다. 화이트리스트는 규약의 선언 한 줄이 들고,
그 밖의 경로가 섞이면 **중단**한다. 커맨드 12종 · `.tide/phase` 값 집합 · tide-guard 계약은 바뀌지 않는다 — 가드는 지금처럼
`release` phase에서만 git 쓰기를 통과시키고, 이 경로는 그 phase 안에서만 git을 쓴다.

## 배경

**출처는 이 저장소의 운영 실측과 2026-10-13 세션의 사용자 결정이다.**

- **릴리즈 뒤 자동 회고는 태그 뒤에 돌아 늘 미커밋으로 남는다** — `retro-after-release`의 단일 원본
  (`docs/conventions.md`의 "회고 후속 항목의 소비" 절)은 회고가 낸 변경을 「이번 태그에 실리지 않는다 — 다음 사이클의 커밋 범위」로 적는다. v2.39.0 마무리 직후에도
  `docs/reports/retro.md`가 미커밋으로 남았다. 그 문서는 다음 릴리즈까지 **한 사이클 내내** 작업 트리에만 있고, 그동안 다른 세션 ·
  다른 머신은 최신 회고를 보지 못한다. E1 축 ⑵(「지나간 사이클이 남긴 것이 다음 사이클에 닿는가」)의 빈자리다.
- **에픽 문서는 사이클 밖에서 고쳐지는 것이 정상이다** — E1 축 ⑶(「줄기가 생기거나 바뀌어야 한다는 사실」)은 방향이 사이클 밖에서
  정해진다고 적는다. 그런데 커밋 경로는 `/tide:release` 하나뿐이라, 사이클 사이에 고친 에픽도 다음 릴리즈를 기다린다.
- **지금의 우회는 가드를 손으로 여는 것뿐이다** — tide-guard는 `.tide/phase`가 `release`가 아니면 git 쓰기를 막는다(`hooks/tide-guard.sh`).
  릴리즈가 아닌데 phase를 `release`로 손수 쓰면 「git 쓰기는 release 단계에서만」의 뜻이 절차 없이 흐려진다.
- **세션 분석(2026-10-13)이 정한 형태** — 새 커맨드는 커맨드 12종 선언(B1 · 카탈로그 · 「2.0 안정성」 명단 C-4)을 흔들고, 새 phase 값은
  가드 계약(2.0 동결)을 약하게 바꾸는 쪽이라 3.0 사안이다. **release 스킬의 모드로 넣으면** phase는 `release` 그대로이고 커맨드 수 · phase
  값 집합 · 가드 판정이 불변이라 가산(minor)이다. 같은 분석이 조용히 깨지는 자리 넷을 짚었다.
  1. **에픽만 커밋하면 커밋된 트리가 Part M에서 붉다** — `/tide:milestone`이 에픽의 「속한 마일스톤」에 번호를 더하는데(`skills/milestone/SKILL.md`),
     그 마일스톤 문서가 미커밋이면 커밋된 트리에서는 등재가 **고아**다. 로컬 하니스는 작업 트리를 재므로 초록이다.
  2. **부분 스테이징은 잰 트리와 내보낸 트리를 가른다** — 사용자는 (가) 「화이트리스트 밖 미커밋 변경 0일 때만」을 골랐다. 사이클 도중에는
     쓸 수 없고, 그 대가로 작업 트리 = 커밋이 성립한다.
  3. **phase 복원** — (가)의 전제가 `idle`이라 끝나면 `idle`로 돌아가는 것이 원래 값이다.
  4. **재서술처** — `retro-after-release`의 「돌지 않는 분기(전수 열거)」, 「git 쓰기는 release 단계에서만」을 다시 적은 자리.
- **사용자 결정** — (가)로 간다. `pr` 모드면 PR을 거친다(`deploy-pages.yml`이 main push마다 배포하므로 기본 브랜치 직접 push를 피한다).

**이 마일스톤이 닫지 않는 것(먼저 못박는다)**

- **사이클 도중의 문서 커밋**((나) 확장안 — 인덱스 트리를 작업 트리 밖에 풀어 재는 경로)은 범위 밖이다.
- **`.tide/NEXT-SESSION.md`**(`rf-48`)는 화이트리스트에 넣지 않는다 — 사용자가 고른 범위가 에픽 · 회고다.
- **릴리즈 커버리지 체크는 바꾸지 않는다** — `docs/epics/*`는 `coverage-bookkeeping:` 밖이라, 문서 커밋으로 나간 에픽 변경은 다음 릴리즈의
  범위 ⑴(`<태그>..HEAD`)에 들어가 보고서에 언급이 없으면 advisory가 뜬다. 사이클 밖에서 바뀐 방향을 다음 릴리즈가 드러내는 것은 의도에
  맞으므로 그대로 두고, 그 경계를 규약에 적는다.

## 태스크 상세

### M74-T01: 경로의 형태 · 선언 · 상태 분기 · 회귀 방향 확정 (읽기 전용)

- **변경 파일**: 없음(산출은 `docs/reports/M74-impl.md`)
- **⑴ 인자 해석** — `/tide:release docs`의 `docs`는 **동작 토큰**이고 게시 모드(`pr`/`release`)와 다른 축이다. 버전 토큰(`v…`)과 함께
  오면 중단한다(두 동작을 한 실행에 섞지 않는다). 게시 모드는 기존 우선순위(명시 인자 > `.tide/release-mode` > 질문)를 그대로 쓰되,
  `release` 모드는 GitHub 릴리즈 객체를 만들지 않으므로 이 경로에서는 push-only와 같게 동작한다 — 이것을 판정해 적는다.
- **⑵ 화이트리스트 선언의 형태** — 후보는 `docs-commit-paths:` 한 줄이다. 값은 `docs/reports/retro.md` · `docs/epics/*` · `docs/project-context.md`이고,
  `docs/project-context.md`는 **같은 실행에 `docs/reports/retro.md` 변경이 있을 때만** 허용한다(회고가 처분 행을 쓰는 유일한 경우). 조건을
  선언에 어떻게 싣는지(예: `docs/project-context.md@retro`) 정해 적는다. 글롭은 `*` 하나만 허용하고 디렉터리 하나 깊이에서만 맞춘다 —
  `docs/epics/*`가 `docs/epics/sub/x.md`를 덮지 않는다.
- **⑶ 전제 셋과 중단 조건** — ① phase가 `idle`(파일이 없으면 `idle`과 같다) ② `.tide/debug-session` 없음 ③ `git status --porcelain`의 **모든**
  경로가 화이트리스트 안이고 하나 이상이다(0이면 「커밋할 것 없음」으로 끝낸다). 미추적 파일도 같은 규칙을 받는다. 셋 중 하나라도
  어기면 git 작업 없이 중단하고 어긴 경로를 목록으로 보인다. **자율 수준과 무관하다**(advisory가 아니다).
- **⑷ 에픽 등재 동반 규칙** — 에픽 diff의 `epic-milestones` 마커 블록 안에서 **더해지거나 빠진** `M{N}`이 있으면, 그 `docs/milestones/M{N}.md`가
  커밋되는 트리에 있어야 한다. 그 마일스톤 문서가 미커밋이면 ⑶의 ③에 걸린다(화이트리스트 밖) — 즉 **(가)에서는 이 규칙이 ③으로 이미
  닫히는지** 판정해 적는다. 닫힌다면 별도 검사를 세우지 않고 그 근거를 적는다(`lean-branches-stated`).
- **⑸ 프리플라이트** — 하니스 전수(pr 모드면 측정 배당대로 `sh` 전수는 CI) · 사이트 빌드 출력 스캔(`scan-same-form-control` 그대로)을 돌린다.
  판정 근거 보고서(프리플라이트 1) · 커버리지 체크(프리플라이트 5)는 돌지 않는다 — 그 사유를 적는다.
- **⑹ `pr` 모드의 상태 분기** — 브랜치 이름 `docs/{YYYY-MM-DD}`(같은 날 둘째면 `-2`) · PR 제목 `Docs: {요약}`. 열린 `docs/*` PR이 **이미 있으면 대기**
  (새 PR을 쌓지 않는다). 머지됐으면 기본 브랜치 최신화 · 로컬 브랜치 정리 후 끝낸다(태그 없음). 미머지로 닫혔으면 중단. 생성 뒤 작업 트리는
  `docs/*` 브랜치에 머문다 — 다음 사이클을 그 브랜치 위에서 시작하지 않도록 안내 한 줄을 정한다.
- **⑺ 생명주기** — 이 경로가 `lifecycle-transitions:`의 새 전이인지 판정한다. 작업 트리의 판정 입력을 바꾸지 않고 git만 쓰면 전이가 아니다.
  `pr` 모드의 브랜치 전환은 작업 트리를 바꾸므로 `tr-pr-create`와 같은 부류인지 따진다(`rf-67`의 소비자).
- **⑻ 회귀 방향을 먼저 적는다** — 최소한 다음을 포함한다.
  - 화이트리스트 선언의 소실 · 중복 · 빈 값 · 금지 구분자 · 값에 `docs/conventions.md`를 더함
  - 스킬이 선언을 가리키지 않고 경로를 직접 열거함(재서술)
  - `retro-after-release` 「돌지 않는 분기」에서 `docs` 모드가 빠짐
  - 재서술처(`CLAUDE.md` · 규약 tide-guard 절 · 「단계별 금지 행위 요약」 표 · `docs/commands.md`) 중 하나만 고침
  - 자율 조건을 이 경로의 `git push` · `gh pr create` 바닥 게이트에 닮(`floor-marks:` · `N20`)
  - **오탐 방향**: 화이트리스트 안 경로만 바뀐 정상 상태 — 초록이어야 한다

### M74-T02: 규약에 화이트리스트 선언과 문서 커밋 경로를 적는다 (deps: M74-T01)

- **변경 파일**: `docs/conventions.md` · `docs/conventions-release.md` · `docs/commands.md` · `CLAUDE.md`
- `docs/conventions-release.md`의 "릴리즈 게시 (gh)" 절 곁에 **문서 커밋 경로** 소절을 둔다 — T01 ⑴~⑹의 결정과 `docs-commit-paths:` 선언 줄.
  선언을 이 파일에 둘지 `docs/conventions.md`에 둘지 T01이 정한다(선언 줄을 읽는 러너의 기존 위치를 따른다).
- **재서술처를 같은 편집에서 고친다**(`CLAUDE.md`의 「규칙을 고치면 재서술한 자리를 같은 편집에서 고친다」).
  - `docs/conventions.md`의 tide-guard 절 · 「단계별 금지 행위 요약」 표의 release 행 — release 단계가 문서 커밋을 포함함
  - `docs/conventions.md`의 "회고 후속 항목의 소비" 절 — 문서 커밋은 태그를 달지 않으므로 회고가 돌지 않음
  - `docs/commands.md`의 `/tide:release` 행 — 인자 `docs` 추가
  - `CLAUDE.md`의 「git 쓰기는 `/tide:release` 단계에서만」 줄 — 문서 커밋 경로도 그 단계 안이라는 한 구절
- **커버리지 체크의 경계를 적는다** — 문서 커밋으로 나간 `docs/epics/*`는 다음 릴리즈의 범위 ⑴에 들어 advisory가 뜰 수 있다(배경의 「닫지
  않는 것」).
- **새 병기어를 세우면 체크리스트 여섯을 함께 붙인다**(`docs/conventions.md`의 "새 검사를 세울 때 함께 붙일 것 (체크리스트 — 판단이 아니다)" 절).

### M74-T03: release 스킬에 `docs` 모드를 더한다 (deps: M74-T01)

- **변경 파일**: `skills/release/SKILL.md`
- 인자 해석에 `docs` 동작 토큰을 더하고, **기존 릴리즈 절차와 섞이지 않는 독립 절**로 둔다 — 전제 셋(T01 ⑶) → 프리플라이트(T01 ⑸) →
  게시 모드 해석 → phase `release` 기록(**git 명령과 별도 단계** — 운영 주의 1) → 스테이징 → 커밋(`Docs: {요약}`) → push 또는 PR → phase `idle`.
- **스테이징 범위**: 기존의 「스테이징 범위 (세 모드 공통 — 여기서만 정의한다)」는 그대로 두고, 문서 커밋은 **`git status --porcelain`의 경로
  전부**(전제 ③이 그것이 전부 화이트리스트 안임을 보장한다)라고 그 절에 한 줄로 잇는다 — 정의처를 둘로 만들지 않는다.
- 화이트리스트는 **선언을 가리키고 다시 열거하지 않는다**.
- **「릴리즈 뒤 회고 자동 실행」의 돌지 않는 분기 열거에 `docs` 모드를 더한다** — 태그가 달리지 않는다.
- `autonomy` 토큰이 이 절에 들어가지 않게 한다(`autonomy-lines: release=3`이 줄 수를 문다). 바닥 게이트(`git push` · `gh pr create`)는
  자율과 무관하다.

### M74-T04: 두 러너에 선언 · 결합 검사를 세우고 되돌림을 잰다 (deps: M74-T02, M74-T03)

  ⑶ 값이 화이트리스트 **허용 집합 밖**(예: `docs/conventions.md` · `skills/` · `tests/`)을 담지 않는다 — 허용 집합의 근거는 T01이 정한다
  ⑷ `skills/release/SKILL.md`가 선언을 가리키는 병기어를 갖고, 경로를 다시 열거하지 않는다 ⑸ 회고 자동 실행의 돌지 않는 분기 열거 창에
  `docs` 모드 토큰이 있다(M68의 단계 앵커 창 형태).
- 파트는 T01이 정한다(후보: 회고 · 릴리즈 순서를 무는 Part O). 새 파트를 만들지 않는 것이 기본이다.
- **두 사본의 동형** — `run.ps1`에는 비-ASCII를 넣지 않는다(코드포인트로 지칭 · 집행 `tests/discover` F5). 비교는 **ordinal**이다.
- **되돌림 실측** — T01 ⑻의 방향 하나하나를 **두 사본에서** 되돌려 붉는 케이스를 표에 적는다. 오탐 방향은 초록인지 잰다.
- 케이스 수는 `tests/discover/README.md`의 `cases:` 한 줄에서만 선언한다 — 이 문서에 수를 적지 않는다.

3. **회고 자동 실행이 돌지 않는다** — 「돌지 않는 분기」 열거에 `docs` 모드가 있고, 두 러너가 그 창을 문다.
