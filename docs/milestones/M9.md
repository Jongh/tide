# M9 — 진짜 병렬 실행: 독립 태스크 서브에이전트 디스패치

## 목표

이 마일스톤이 끝나면 `/tide:impl`과 `/tide:cycle`의 impl 단계가 deps 위상에서 **독립인
태스크들을 실제로 동시에** 실행한다 — 지금처럼 "순서 해석만 하고 순차로 처리"하는 게
아니라, 같은 위상 레벨의 무의존 태스크를 Claude의 Agent(서브에이전트) 도구로 병렬
디스패치하고 결과를 모아 단일 완료보고서로 합친다. 파일 충돌·서브에이전트 실패에는
보수적 순차 폴백이 작동하고, 부수효과 분리(서브에이전트도 git 금지)와 tide-guard 정합이
유지된다.

## 배경

회고(`docs/reports/retro.md`)가 8사이클째 **최상위 미반영 후속**으로 "진짜 병렬 실행
수단"을 지목했다. `/tide:cycle`(M5)·conventions는 "독립 태스크 = 병렬 착수 가능"이라
규정하면서도 그 끝에 *"실제 병렬 실행 수단은 구현 판단에 맡긴다 … 순차로 처리하더라도
deps 위상 순서는 지킨다"*고 명시해, **병렬은 스케줄링 해석일 뿐 실제 동시성은 없었다**
(M5-review 사소2가 짚고 회고가 반복 부각). M8에서 저비용 후속(한국어화·문서 단일화·
패키지 위생)이 거의 소진돼, 이제 이 항목이 다음 마일스톤의 자연스러운 1순위다.

핵심 현실 인식: tide는 코드 런타임이 없는 **프롬프트·규약 플러그인**이다. 따라서 "병렬
실행 수단"은 별도 동시성 엔진이 아니라, impl 단계를 수행하는 Claude에게 **Agent 도구로
독립 태스크를 동시 서브에이전트에 위임하라는 규약**을 스킬 본문에 명문화하는 것이다.
서브에이전트는 컨텍스트가 격리되고 공유 워킹트리에서 파일 경쟁이 생길 수 있으므로,
충돌 안전장치와 폴백이 메커니즘의 필수 일부다.

## 태스크 상세

### M9-T01: impl 스킬에 독립 태스크 서브에이전트 병렬 디스패치 규약 정의

`skills/impl/SKILL.md`(병렬 실행의 단일 원본)에 "병렬 디스패치" 절을 추가한다.

- **디스패치 단위**: deps 위상에서 선행이 모두 끝난 **같은 레벨의 무의존 태스크가 2개
  이상**이면, 각 태스크를 **하나의 메시지에서 동시에** Agent 도구로 서브에이전트에 위임한다
  (한 메시지에 복수 Agent 호출 = 동시 실행). 레벨 간에는 배리어 — 다음 레벨은 현재
  레벨의 모든 서브에이전트가 끝난 뒤.
- **서브에이전트 전달 컨텍스트**(재해석 없이 착수 가능하도록): 대상 마일스톤 문서 경로,
  `docs/project-context.md`(있으면), 맡은 **태스크 ID·상세·해당 완료 기준**, 그리고
  **부수효과 분리 상속** — "코드·테스트만, git commit/tag/push 금지, 코드 리뷰 금지,
  완료보고서는 메인이 쓴다".
- **반환 계약**: 각 서브에이전트는 구조화된 요약을 반환한다 — 수행 내용, **실제 변경
  파일 목록**, 테스트/검증 결과, 미해결·이슈. (메인이 T03에서 집계)
- 레벨에 태스크가 1개뿐이거나 Agent 도구를 쓸 수 없으면 메인이 직접 순차 구현(폴백).
- 기존 deps 파싱·이상 표기 폴백(순환·미존재 ID → 전체 순차)은 그대로 유지하고, 그
  위에 병렬 디스패치를 얹는다.

### M9-T02: 파일 충돌 안전장치 + 워크트리 격리(선택) (deps: M9-T01)

공유 워킹트리에서 병렬 서브에이전트가 같은 파일을 동시에 고치면 경쟁이 난다. 안전장치를
같은 절에 정의한다.

- **사전 겹침 감지**: 한 레벨을 병렬 디스패치하기 전, 각 태스크의 마일스톤 "파일 변경
  요약"·상세로 **예상 변경 파일 집합**을 추정한다. 두 독립 태스크의 예상 집합이 겹치면
  그 **겹치는 태스크들만 순차**로 내리고(부분 폴백), 나머지 비겹침 태스크는 병렬 유지한다.
- **설계 권장 연결**: conventions가 이미 "태스크를 가능한 한 독립적으로(파일 비중첩)"를
  권하므로, 겹침이 잦으면 그건 마일스톤 분해 신호다 — 폴백은 안전망이지 정상 경로가
  아니다.
- **워크트리 격리(선택·고급)**: 파일 경쟁이 불가피한데 병렬 이득이 큰 경우, 서브에이전트를
  격리된 git worktree에서 실행하는 옵션을 **명시하되 기본 비활성**으로 둔다 — 병합 비용·
  복잡도가 있어 기본은 "공유 트리 + 비겹침" 경로. (불확실성: 워크트리 병합을 프롬프트로
  안전히 기술하기 어려움 → 기본안에서 제외, 향후 후보로 기록)

### M9-T03: 결과 병합·부분 실패 처리 규약 (deps: M9-T01)

병렬 서브에이전트 결과를 메인이 모아 **단일** `docs/reports/M{N}-impl.md`로 집계하는
규약을 정의한다.

- **병합**: 각 서브에이전트 반환(수행 내용·변경 파일·테스트·이슈)을 태스크별 절로
  합치고, 변경 파일 요약·테스트 결과를 통합한다. 보고서 형식은 기존 `impl/template.md`
  그대로(병렬이라고 형식이 바뀌지 않는다).
- **부분 실패**: 한 서브에이전트가 실패/중단되면 — ① 같은 레벨의 다른 병렬 결과는
  보존하고, ② 실패 태스크는 메인이 순차로 재시도하거나, 재시도도 실패면 cycle "중단
  처리" 규칙대로 **중단하고 어느 태스크에서 왜 멈췄는지 보고**한다.
- **tide-guard 정합**: 서브에이전트는 phase=`impl`에서 동작하므로 그 안에서 git을
  시도하면 가드가 차단한다(부수효과 분리가 병렬에서도 기계적으로 강제됨) — 이 정합을
  명시한다.

### M9-T04: cycle 스킬 정합 — deps 절을 병렬 메커니즘 참조로 교체 (deps: M9-T01)

`skills/cycle/SKILL.md`의 "deps 기반 병렬/순차" 절을 갱신한다.

- 절 끝의 *"실제 병렬 실행 수단은 구현 판단에 맡긴다 … 순차로 처리하더라도 …"* 문장을
  **삭제·교체**하고, "impl 단계는 `/tide:impl`과 동일하게 **독립 태스크를 서브에이전트로
  병렬 디스패치**한다(메커니즘·충돌 안전장치·병합은 impl 스킬 절 참조)"로 바꾼다.
- 사이클 안에서도 같은 폴백·tide-guard 정합이 적용됨을 한 줄 명시. 중복 서술을 피하고
  impl 스킬을 단일 원본으로 가리킨다(M8의 단일 원본화 기조 계승).

### M9-T05: conventions·README·project-context 반영 (deps: M9-T01, M9-T02, M9-T03, M9-T04)

- `docs/conventions.md`: "deps 기반 병렬/순차"에 해당하는 서술(사이클 절·태스크 표기
  설명)에서 "병렬은 해석일 뿐"이라는 뉘앙스를 **실제 병렬 디스패치**로 갱신하고,
  파일 비중첩 권장이 병렬 안전과 직결됨을 한 줄 추가. (이 변경은 snippets로 사이트
  conventions에 자동 반영 — 별도 사이트 편집 불필요)
- `README.md`: `/tide:cycle`·`/tide:impl` 설명에 "독립 태스크 서브에이전트 병렬 실행"을
  반영(커맨드 표·사이클 설명 문구). CHANGELOG 절은 release에서 추가.
- `docs/project-context.md`: 핵심 도메인 개념의 "태스크 표기"·cycle 항목에 병렬 디스패치
  한 줄 반영.

### M9-T06: 검증 — 자동 발견·정적 일관성·strict 빌드 + 도그푸딩 시나리오 정의 (deps: M9-T05)

- **자동 발견**: 신규 파일 없이 기존 `skills/*/SKILL.md`만 수정하므로 매니페스트
  (`plugin.json`·`marketplace.json`) 무수정 확인(M5~M8과 동일).
- **정적 일관성**: impl·cycle·conventions·README·project-context의 병렬 서술이 서로
  모순 없는지, impl 스킬이 단일 원본이고 나머지는 참조인지 확인.
- **strict 빌드**: conventions 변경이 snippets로 사이트에 반영되므로 격리 venv에서
  `mkdocs build -f site/mkdocs.yml --strict` 통과·porpoise 0건 재확인.
- **도그푸딩 시나리오(정직한 한계)**: 이 M9 자체는 대부분 단일 SKILL 편집이라 병렬 이득을
  자기적용으로 보이긴 어렵다. 따라서 "독립 태스크 2개 이상을 가진 다음 마일스톤을
  `/tide:cycle`로 돌릴 때 같은 레벨이 동시 서브에이전트로 디스패치되는지"를 **release 후
  도그푸딩 시나리오로 정의**해 완료보고서에 적는다(실행 가능한 첫 대상은 M9 이후 첫
  병렬형 마일스톤). 활성 가드/스킬 캐시 제약상 실호출은 release+재설치 후 — 구조적 반복.

## 완료 기준

1. `skills/impl/SKILL.md`가 독립 태스크의 **서브에이전트 동시 디스패치**(같은 레벨 ≥2개를
   한 메시지에서 병렬), 전달 컨텍스트·반환 계약, 레벨 간 배리어를 명시한다.
2. 파일 겹침 사전 감지 → 겹치는 태스크만 순차 폴백, 워크트리 격리는 선택·기본 비활성으로
   기술돼 있다. Agent 도구 부재/레벨 단일 태스크면 순차 폴백한다.
3. 병렬 결과를 단일 impl 보고서로 병합하는 규약과 부분 실패(보존+재시도/중단) 처리,
   서브에이전트의 git 금지가 tide-guard로 강제됨이 명시돼 있다.
4. `skills/cycle/SKILL.md`에서 "실제 병렬 실행 수단은 구현 판단에 맡긴다 …" 문장이
   제거되고 impl 스킬의 병렬 메커니즘을 참조하도록 바뀌었다.
5. conventions·README·project-context의 병렬 서술이 impl 스킬과 모순 없이 일치하고,
   매니페스트는 무수정이다.
6. `mkdocs build -f site/mkdocs.yml --strict`가 통과하고 사이트 출력 porpoise 0건이며,
   완료보고서에 release-후 병렬 도그푸딩 시나리오가 정의돼 있다.
