# M97 — 두 트래커에서 대응표를 손으로 재현하고, 그 결과로 트래커 계약을 규약 선언으로 세운다

## 목표

GitHub과 자체 호스팅 GitLab 14.9의 실물에서 E5 대응표(에픽 = 추적 이슈 · 사이클 = 이슈 · 태스크 = 체크리스트 · 유입 라벨)를 한 줄씩 손으로 재현한다. 재현된 것과 안 되는 것, 그리고 대체 경로가 근거와 함께 기록된다. 그 실측을 근거로 트래커 계약을 규약 조각의 선언으로 세운다. 계약은 연산 이름, 판별 순서, 라벨, 단계별 쓰기 범위, 유입 선별 갈래이고, 하니스가 그 선언의 위생을 묻는다. 스킬 · 훅의 동작은 바뀌지 않는다. 다음 사이클(읽기 경로 모으기)이 기댈 이름과 사실이 저장소에 선다.

## 배경

- **E5 사이클 배분 1**(`docs/epics/E5.md`의 「사이클 배분」)이다. 2026-11-23 사용자 논의로 대응이 확정됐다(E5 「사용자 판단」 · 「개념 대응」 · 「유입」). 사용자가 이 줄기를 다음 마일스톤의 최우선 후보로 정했다. 회고 1순위 후보(`rf-81`)보다 앞이다.
- E5가 「계획 시점 지식」으로 남긴 판정 셋을 이 사이클이 실물로 확인한다. GitLab 14.9 Free에 sub-issue · 에픽 · 범위 라벨이 없는가, 체크리스트 안의 이슈 참조가 닫힘 상태를 보여 주는가, 판별 순서(명시 설정 → 원격 추론 → 닿는가 → 로컬)가 실물에서 성립하는가다.
- GitLab은 tide 세션이 직접 접근한다(사용자 결정). 토큰은 환경변수로만 받고 파일에 쓰지 않는다. 호스트 · 시험 프로젝트는 impl 시작 때 사용자에게 받는다.
- CI는 사내 GitLab에 닿지 않는다(E5 「못 무는 것」). 실물 대조는 이 사이클의 수동 실측이다. 그래서 다음 사이클들의 가짜 어댑터가 쓸 수 있도록 응답을 정제해 남긴다.

## 태스크 목록

- M97-T01: GitHub 실측 — 대응표 · 유입 흐름을 시험 저장소에서 손으로 재현하고 응답을 기록한다
- M97-T02: GitLab 14.9 실측 — 같은 재현과 버전 · 등급 기능 유무 확인
- M97-T03: 실측 기록의 정제와 보관 — 내부 호스트 · 사용자 식별자를 지우고 저장소에 남긴다 (deps: M97-T01, M97-T02)
- M97-T04: 트래커 계약을 규약 조각의 선언으로 세운다 (deps: M97-T01, M97-T02)
- M97-T05: 새 선언을 하니스 등록표에 올리고 위생 · 통제 케이스를 붙인다 (deps: M97-T04)
- M97-T06: E5에 실측 결과를 반영하고 재서술처를 맞춘다 (deps: M97-T03, M97-T04)

## 태스크 상세

### M97-T01: GitHub 실측

- **변경 파일**: 없음(트래커 쓰기 · 기록은 작업 트리 밖 scratchpad). 결과는 T03 · T06 · impl 보고서로 간다.
- **대상 저장소**: impl 시작 때 사용자에게 고르게 한다. 기본 제안은 실측 전용 **비공개 시험 저장소**다. 대안은 `Jongh/tide`이고, 이 경우 만든 항목을 실측 뒤 닫고 `tide:` 라벨은 남기거나 지운다. 트래커 쓰기는 외부 부수효과라 쓰기 전에 만들 항목 목록을 보이고 승인을 받는다(E5 「변환」의 원칙을 실측에도 적용).
- 재현할 줄(E5 「개념 대응」 · 「유입」 표 순서):
  1. 라벨 `tide:epic` · `tide:cycle` · `tide:backlog` 만들기
  2. 에픽 추적 이슈(`E{N} — …`, 본문 요지 · 링크 · 체크리스트)
  3. 사이클 이슈를 그 에픽의 sub-issue로(`gh issue create --parent`). REST `sub_issues` 응답과 부모 이슈의 `sub_issues_summary`를 기록한다
  4. 사이클 이슈 본문의 태스크 체크리스트 상태 바꾸기(본문 편집)
  5. 에픽 본문 체크리스트의 `- [ ] #{사이클}` 참조가 사이클 이슈를 닫은 뒤 어떻게 보이는가(렌더된 HTML · API `body_html`)
  6. 닫힘 경로 둘 — PR 본문 `Closes #N` 머지, 기본 브랜치 push 커밋 메시지 `Closes #N`(push-only 모드의 대체 경로 후보)
  7. 유입: `tide:` 라벨 없는 외부 이슈를 라벨 필터로 읽는 질의(`gh issue list --search "-label:tide:epic -label:tide:cycle -label:tide:backlog"` 또는 API 필터)와 흡수 댓글 한 줄 · `tide:backlog` 붙이기
- 각 줄에 「명령 · 응답 요지 · 재현됨/안 됨 · 안 되면 대체」를 적는다. 쓰기 명령마다 원 응답 JSON을 scratchpad에 저장한다.
- **불확실성**: 개인 저장소는 이슈 타입(`--type`)이 없다(E5 실측표). 쓰지 않는다. PR 머지가 필요한 6의 앞 갈래는 시험 저장소에서 빈 커밋 PR로 잰다.

### M97-T02: GitLab 14.9 실측

- **변경 파일**: 없음(scratchpad). 결과는 T03 · T06 · impl 보고서로 간다.
- 접근: 환경변수 `GITLAB_HOST` · `GITLAB_TOKEN`(api 범위). 이름은 impl에서 사용자와 맞춘다. 토큰 값은 명령 출력 · 기록 · 보고서 어디에도 남기지 않는다. 자체 서명 인증서면 사용자 환경 설정으로 넘기고, 우회 플래그(`-k`)는 쓰지 않는다.
- 확인할 사실:
  1. `GET /api/v4/version`의 버전 · 리비전
  2. 등급 기능 유무 — 그룹 에픽 엔드포인트, 이슈 링크 `link_type=blocks`, 범위 라벨(`a::b`)의 상호 배타 동작, 이슈 하위 작업(Task work item)의 유무. 응답 코드로 판정하고, 문서 지식으로 갈음하지 않는다
  3. T01의 1~7과 같은 줄을 REST v4로 재현한다. sub-issue 줄은 「없음」이 예상이고, 그때 대체(체크리스트 + `relates_to` 링크)를 재현한다. 닫힘 경로는 MR 설명 `Closes #N` 머지와 기본 브랜치 push 커밋 메시지 둘이다
  4. 판별 순서의 실물 — `origin` URL에서 호스트를 읽고 `/api/v4/version` 응답으로 GitLab임을 가르는 것, 토큰 없을 때 · 잘못된 토큰일 때 · 권한 없는 프로젝트일 때의 응답 코드
- 시험 프로젝트에 만든 항목은 실측 뒤 닫는다. 지울지 남길지는 사용자가 정한다.
- **불확실성**: 호스트가 tide 세션에서 닿지 않으면(사내망 · VPN), 그 사실을 기록하고 사용자에게 접근 방법을 묻는다. 끝내 닿지 않으면 T02를 「사용자 실측 결과 전달」 경로로 바꾼다. 재현 절차를 명령 목록으로 적어 사용자에게 넘기고, 그 결과를 받는다. 완료 기준 2는 어느 경로였는지를 함께 적는다.

### M97-T03: 실측 기록의 정제와 보관 (deps: M97-T01, M97-T02)

- **변경 파일**: `docs/reports/M97-recordings/` 아래 정제된 응답 파일(`github-*.json` · `gitlab-*.json`)과 그 목록 `README.md`(파일마다 어느 줄 · 어느 명령의 응답인지)
- 정제 규칙: 내부 호스트명은 `gitlab.example`로, 사용자 이름 · 이메일 · 아바타 URL · 노드 ID는 고정 자리표시자로 바꾼다. 토큰 · 쿠키 헤더는 기록하지 않았는지 확인한다. 정제 뒤 실제 호스트 문자열 · 사용자 이메일로 파일 전체를 스캔해 0건이어야 한다. 빈 스캔을 믿기 전에 정제 전 원본에서 같은 스캔이 1건 이상 잡는지 먼저 본다(양성 통제 — `docs/conventions.md`의 "릴리즈 빌드 출력 검증" 절 `scan-same-form-control`과 같은 꼴).
- 보관 자리가 하니스나 사이트 빌드를 붉히면(보고서 디렉터리를 읽는 파트가 하위 폴더 · JSON을 문제 삼으면) 대체 자리를 쓴다. 대체는 impl 보고서 부록에 정제된 발췌만 넣는 것이고, 그 사실과 사유를 보고서에 적는다.

### M97-T04: 트래커 계약을 규약 조각의 선언으로 세운다 (deps: M97-T01, M97-T02)

- **변경 파일**: `docs/conventions-tracker.md`(새 규약 조각 — 규약은 글롭으로 발견되므로 목록을 고치지 않는다)
- 절 하나(「트래커 계약」)에 선언과 이름별 정의 항목을 둔다. 이름 꼴은 기존 선언(`release-preflights:` · `mark-since-steps:`)을 따른다.
  - `tracker-ops:` — 연산 이름(판별 · 읽기 · 쓰기 · 대응 기록에 대응하는 ASCII 이름)
  - `tracker-detect-steps:` — 판별 순서의 갈래 이름(명시 설정 · 원격 추론 · 닿는가 · 로컬 대체). 이름의 순서가 적용 순서다
  - `tracker-labels:` — `tide:epic` `tide:cycle` `tide:backlog`
  - `tracker-phase-writes:` — 단계 → 쓸 수 있는 연산(E5 「부수효과의 자리」)
  - `tracker-intake-verdicts:` — 유입 선별 갈래 다섯(흡수 · 승격 · 보류 · debug · 닫음)
- 각 정의 항목에 T01 · T02 실측의 근거 줄을 가리킨다(보고서 · 기록 파일 이름). 실측이 대응을 바꾸면(예: GitLab 닫힘 경로가 MR에서만 된다) 선언이 실측을 따른다. E5와 다르면 T06이 E5를 고친다.
- **이 절은 아직 아무 스킬도 소비하지 않는다** — 그 사실을 절 머리에 적는다(소비는 E5 사이클 배분 2부터). 「선언 · 소비자 없음」이 공허한 주장으로 읽히지 않게, 하니스가 묻는 것(T05)과 묻지 않는 것을 같은 절에 적는다.

### M97-T05: 새 선언을 하니스 등록표에 올린다 (deps: M97-T04)

- **변경 파일**: `tests/discover/run.sh` · `tests/discover/run.ps1`(등록표 `decl_reg` · `$DECL_REG` 행) · `tests/discover/README.md`(`cases:` 한 줄 · 해당 파트 서술)
- 규약 문서 집합의 선언 줄은 등록표 키 집합과 대칭차가 0이어야 한다(Part F `F24`~`F28`). 그래서 T04의 선언 다섯에 등록표 행을 두 러너에 같은 꼴로 더한다. 판정 종류(이름 목록 · 값 · 금지 구분자 등)는 기존 행에서 같은 꼴을 고른다.
- 이름 선언(`tracker-ops:` · `tracker-detect-steps:` · `tracker-intake-verdicts:`)은 이름별 정의 항목의 대응을 묻는 기존 판정 꼴(`dn_*` · `Dn*`)을 쓴다. 차례가 뜻인 `tracker-detect-steps:`는 정의 항목 차례도 묻는다.
- 통제: 새 행마다 「선언에서 한 칸을 뺀 사본」에서 그 행이 붉는지 되돌림으로 잰다. 두 러너가 각자 단독으로 붉어야 한다.
- `tests/**/*.ps1`에는 비-ASCII를 넣지 않는다(`tide:` 라벨과 ASCII 이름만 쓴다).

### M97-T06: E5 반영과 재서술처 맞추기 (deps: M97-T03, M97-T04)

- **변경 파일**: `docs/epics/E5.md`, 필요 시 `docs/project-context.md`(개념 블록이 트래커를 말하게 되면)
- E5에 「M97 실측」 소절을 더한다. 줄마다 재현됨 · 안 됨 · 대체를 적고, 확인된 GitLab 14.9 등급 사실을 적는다. E5의 「계획 시점 지식」 문장들이 실측과 다르면 고친다(예: Free에 없다고 적은 기능이 실제로 있었다).
- E5 「개념 대응」 · 「유입」 · 「계약」 서술이 T04 선언과 같은 이름을 쓰게 한다. 선언과 같은 것을 다시 열거하지 않고 선언을 가리킨다(규약 단일 원본 원칙).
- 「속한 마일스톤」 블록에는 이미 M97이 있다(이 마일스톤 생성이 넣었다).

## 완료 기준

1. **GitHub 재현표** — T01의 줄 1~7마다 impl 보고서에 「명령 · 응답 요지 · 재현됨/안 됨 · 대체」가 있다. 줄 5(체크리스트 참조의 닫힘 표시)와 줄 6(닫힘 경로 둘)은 관측한 값 그대로 적는다(「될 것이다」가 아니다).
2. **GitLab 재현표** — T02의 1~4마다 같은 꼴의 줄이 있다. 버전 문자열과 등급 기능 넷(그룹 에픽 · `blocks` 링크 · 범위 라벨 배타 · Task work item)의 유무는 응답 코드 · 응답 본문으로 적는다. 접근 경로(tide 직접 · 사용자 전달)를 함께 적는다.
3. **정제** — 보관한 기록 파일 전체에서 실제 내부 호스트 문자열 · 사용자 이메일 스캔이 0건이다. 같은 스캔이 정제 전 원본에서 1건 이상이었다(양성 통제). 토큰 문자열은 어느 파일에도 없다.
4. **계약 선언** — `docs/conventions-tracker.md`에 선언 다섯과 이름별 정의 항목이 있고, 정의마다 실측 근거를 가리킨다.
5. **하니스** — `tests/discover`가 네 실행 환경에서 FAIL 0이고 총계가 일치한다. 총계는 `tests/discover/README.md`의 `cases:` 선언이다. sh 축은 측정 배당대로 CI `posix` 레그가 판정한다. 새 등록표 행마다 한 칸 뺀 사본에서 그 행이 두 러너 각각 단독으로 붉는다(되돌림 표).
6. **동작 불변** — `git diff` 기준 `skills/` · `hooks/` 변경이 0이다.
7. **E5 반영** — E5에 M97 실측 소절이 있다. 「계획 시점 지식」으로 적었던 판정 셋(Free 기능 유무 · 체크리스트 닫힘 표시 · 판별 순서)이 실측 값으로 바뀌었거나, 같았음을 적었다.
8. **트래커 정리** — 시험 저장소 · 시험 프로젝트에 만든 항목의 처분(닫음 · 지움 · 남김과 사유)이 impl 보고서에 있다.
