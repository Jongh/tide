# M20 — 에픽 마감: 계약 연산자 확장 + 자산 정리·견고화 + 2.0 안정 계약 재기준

## 목표

이 마일스톤이 끝나면 **오케스트레이션 에픽이 정리·견고화와 함께 닫히고 tide가 v2.0.0 안정 계약으로
재기준된다.** 구체적으로 (1) `.tide/deps` 계약 버전 비교가 `>=`만이 아니라 **`>`·`>=`·`=`·`<=`·`<`
전체 연산자**를 지원하고(가산), (2) 회고 백로그의 이월·견고화 항목(다중 자리 픽스처·gitignore 노트·
통합 훅 git-verb 가드라일·참조 버전 파일/pre-release 명시·그 외 저위험 이월)이 **각각 fix·수용·환경-
이월로 명시 종결**되며, (3) "1.0 안정성" 계약이 **"2.0 안정성"으로 재기준**돼 11종 커맨드 + 오케스트
레이션 규약(부수효과 분리 불변·`.tide/deps`·계약 비교·`.tide-fleet/integration`)이 stable로 동결된다.
**동작은 깨지지 않는다** — 2.0은 v1.0.0이 "안정 선언" major였던 것과 동일 성격의 **계약 재기준**이고,
연산자 확장·정리·견고화는 전부 하위 호환 가산이다. 단일 레포·미선언·기존 커맨드 11종 동작 불변.

## 배경

v1.6.0(M19)로 오케스트레이션 로드맵 1~4층이 완성됐다. v1.6.0 회고가 남긴 **잔여 후속**은 (a)연산자
확장(M17 권장1 — 최대 잔여 후보)과 (b)저위험 이월·견고화 군집(다중 자리 픽스처·gitignore 노트·통합 훅
가드라일·jq 분기·워크트리 병합·사이트 cosmetic)뿐이며, **로드맵 항목 미반영은 0**이다. 에픽이 닫힌
지금이 백로그를 비우고 안정 계약을 재기준할 자연스러운 시점이다.

**2.0 = 안정 계약 재기준(사용자 확정)**: 남은 작업은 전부 가산/정리라 그 자체로는 minor지만, 에픽 완성
surface(11종 커맨드 + 오케스트레이션 규약)를 **2.0 stable로 동결 선언**하는 것을 major의 근거로 삼는다
(실제 호환 파괴 없음 — v1.0.0의 "안정 선언" major와 동형). 정리 범위는 **전체**(이월 포함)로, 각 항목을
fix하거나 수용/환경-이월로 명시 종결해 백로그를 실제로 비운다.

메타 규칙("규약↔실행/인프라 동기화"): 연산자 규약을 확장하면 그 강제·검증인 라이브 실증을 같은
사이클에 넣는다(연산자 시나리오 + 다중 자리 픽스처 하니스).

## 정규 spec (이 마일스톤의 단일 기준 — 모든 태스크가 인용)

### 계약 버전 비교 — 연산자 확장

- `.tide/deps` 의존 줄의 버전 제약 형식을 `<형제명>[ <op> <버전>]`으로 확장한다. **지원 연산자**:
  `>=`·`>`·`=`(또는 `==`)·`<=`·`<`. (연산자 없으면 이름 의존만 — M16 그대로.)
- **비교**: 의존 대상의 현재 버전(상태 조회)과 요구 버전을 `vX.Y.Z`(선행 `v` 선택) major.minor.patch
  숫자로 비교해 연산자 만족 여부를 판정한다 — 만족이면 무표기, **불만족이면 `⚠ contract` 경고**를
  의존 레포 줄에 표기한다(형식 단일 원본은 conventions "계약 비교 규칙" — 예:
  `svc-orders → ⚠ contract svc-auth 0.2.0 < 요구 >= 0.3.0 (upstream behind — svc-auth를 먼저 올릴 것)`).
  위반 시 메시지에 연산자·요구·현재를 함께 적는다.
- **알 수 없는 연산자·비표준/파싱 불가 버전**: 무시하고 **경고**(차단·위반으로 단정하지 않음 — 안전 측,
  M17 기조 유지).
- **위상정렬 순서·의존 그래프는 버전 제약과 무관하게 불변**(M16·M17 그대로) — 경고는 줄 표기일 뿐.
- 하위 호환: `>=`만 쓰던 기존 deps·미선언 deps는 동작 불변(연산자 확장은 순수 가산).

### 통합 훅 git-verb 가드라일 (견고화, advisory)

- `/tide:fleet-verify`는 통합 훅을 실행하기 **전에** 훅 명령에 git commit/tag/push·release 토큰이 있는지
  점검해, 있으면 **경고**한다(예: `⚠ 통합 훅에 git/release로 보이는 토큰 — fleet-verify는 verification-only`).
  훅 실행을 강제 차단하진 않되(검증 훅에 git이 합법적으로 필요한 변형 가능 — major-safe), 사용자가
  cross-repo git 누수를 인지하게 한다. M19 적대 검증이 짚은 훅 공격 표면을 advisory 가드라일로 좁힌다.

### 2.0 안정 계약 재기준

- `docs/conventions.md`·`README.md`의 "1.0 안정성" 절을 **"2.0 안정성"**으로 재선언한다:
  - **커맨드 11종**(기존 8종 + `/tide:fleet`·`/tide:fleet-cycle`·`/tide:fleet-verify`)의 호출명·역할을
    **2.0 stable**로 동결. "8종 + 가산" 서술을 "11종 stable"로 승격하되, 1.0부터의 안정 이력을 보존 서술.
  - **오케스트레이션 규약**을 stable 계약에 추가: 부수효과 분리 불변(fleet advisory·fleet-cycle release
    제외·fleet-verify verification-only), `.tide/deps`(의존 선언·계약 비교)·`.tide-fleet/integration`(통합 훅)
    포맷, tide-guard 백스톱 정밀(phase 잠금≠release 차단기)·사전 점검.
  - **`.tide/phase`·tide-guard·보고서·마일스톤 형식** 계약은 1.0 그대로 유지(불변).
  - 하위 호환 약속을 갱신: "2.0부터 위 11종·오케스트레이션 규약을 안정 계약으로 선언, 깨는 변경은
    다음 major(3.0)에서만". v1.x 가산 이력(fleet v1.2.0 등)은 보존 표기.
