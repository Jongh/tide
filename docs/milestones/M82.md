# M82 — 회고 순서 판정의 갈래를 이름으로 선언하고 러너가 갈래 이름을 낸다

## 목표

**`docs/conventions.md` "회고 후속 항목의 소비" 절의 순서 판정 갈래(산문 ⑴~⑷)가 이름 선언과 이름별 정의 항목으로 서고, 두 러너는 그 판정을 갈래 이름으로 낸다.**
갈래마다 판정 값(받는다 · 붉다)도 선언이 들고, 러너는 이름과 값을 선언에서 읽는다. 갈래를 하나 더하거나 지우거나 값을 바꾸는 편집이 선언 · 정의 · 러너 사이에서 어긋나면 붉다.
함께, M79가 남긴 경계 비교 필터 자리(`N58`이 접미 ID를 숫자 부분으로 견주는 변환)에 통제를 둔다. 기존 `O18` · `O36`~`O40`의 판정 결과는 바뀌지 않는다.

## 배경

- **회고 1순위 `rf-86`(v2.45.2 시점 회고 · 세 회차 연속 1순위)** — `rf-83`의 나머지 무리가 산문이다. M76 재고 조사 표 B 행이 든 후보 가운데 순서 판정 갈래 넷은
  「판정 갈래의 유일한 원본이 산문이고 러너가 그것을 구현한다(Part O). 수는 Part L이 문다. 선언화 후보: 갈래 이름 선언과 러너의 `이름=값` 출력(M75 형태)」로 적혀 있다.
  케이스가 한 파트(Part O)에 몰려 있어 M79 회고 메모 1이 먼저 집으라고 한 조건에 맞는다. 판정 함수도 하나(`backstop_verdict` · `BackstopVerdict`)다.
- **회고 `rf-87`** — `N58`(`fa_case_unmapped` · `FaCaseUnmapped`)의 경계 비교 필터는 접미 ID의 숫자 부분을 `floor-ask-from:`과 견준다. 두 러너의 필터를 함께 「접미 ID → 0」으로 고치면 대응 없는 접미 케이스가 다시 판정을 피해 간다(M79 리뷰 라운드 1 반증 실측: Part N 63/0). 처방은 접미 ID를 든 합성 러너를 먹이는 통제 하나다.
- **회고 `rf-88`(규칙 후보)** — 새 판정이 입력을 바꾸는 변환(파서 · 필터 · 정규화)을 거치면 변환마다 통제를 둔다. M78 라운드 1 · M79 라운드 0 · 1의 반환이 전부 그 자리에서 났다. 이 마일스톤의 새 판정에 그대로 적용한다.
- 사용자 선택(2026-10-28 세션) — 회고 권장 순서(M82 `rf-86`+`rf-87` → `rf-89`+`rf-90` → `rf-93`)의 첫 자리다.

## 태스크 상세

### M82-T01: 순서 판정 갈래를 선언으로 올린다

- **변경 파일**: `docs/conventions.md`
- "회고 후속 항목의 소비" 절에서 「갈래는 넷이다」 뒤의 ⑴~⑷ 산문을 다음으로 바꾼다.
  - 이름 선언 한 줄 — 키 `retro-order-branches:`, 값 예시 `ro-first ro-release-commit ro-ahead ro-behind`. 이름은 ASCII이고, 선언의 이름 순서가 러너가 갈래를 시험하는 순서다.
  - 값 선언 한 줄 — 키 `retro-order-verdict:`, 값 예시 `ro-first=ok ro-release-commit=ok ro-ahead=no ro-behind=no`. 값 집합은 `ok` · `no` 둘이다.
  - 이름별 정의 항목 — 선언 줄 아래에 이름마다 굵은 백틱 이름으로 시작하는 항목 하나(M75 · M79 형태). 지금 ⑴~⑷ 문단의 사실(조건 · 실측 근거 · M69 · M70 판례 · ⓐ ⓑ 두 경로 · 복구)은 그대로 각 항목으로 옮긴다 — 문장의 뜻을 바꾸지 않는다.
- 같은 절에서 갈래를 번호로 가리키던 자리(「위 ⑶의 정의다」 · 「⑶이 붉으면」 등)를 이름으로 바꾼다. 「갈래는 넷이다」처럼 수를 적은 문장은 수를 빼고 선언을 가리킨다(Part L이 이 수를 묻는지 impl이 확인한다 — `CLAUDE.md` 「케이스 수를 여러 곳에 적지 않는다」와 같은 까닭).
- 「기계가 묻는 것」을 이 절에 적는다 — 무엇을 묻고 무엇을 묻지 않는지(정의 문장의 뜻 · 조건과 러너 계산의 같음은 리뷰의 자리)를 M75 · M79 형태로 적는다. 고지가 주장하는 판정은 T02의 케이스와 1:1로 대조할 수 있게 쓴다.
- 이 규칙을 재서술한 자리를 훑어 같은 편집에서 고친다 — 스킬(`skills/retro/SKILL.md` · `skills/milestone/SKILL.md` · `skills/release/SKILL.md`) · 템플릿 안내문 · `docs/project-context.md` 개념 블록 · `docs/conventions-release.md`. 검색의 네 축을 보고서에 적는다. 계획 시점에는 번호로 가리키는 자리가 이 절 안에만 있다.

### M82-T02: 러너가 갈래 이름을 낸다 (deps: M82-T01)

- **변경 파일**: `tests/discover/run.sh` · `tests/discover/run.ps1`
- 판정 함수를 갈래 이름을 내는 함수(예: `ro_branch` · `RoBranch` — 회고 버전 · CHANGELOG 첫째 · 둘째 · 최대 번호 마일스톤의 기반 버전을 받아 이름 하나)와, 그 이름의 값을 `retro-order-verdict:`에서 읽는 자리로 가른다. 이름은 `retro-order-branches:`의 위치로 읽고 러너 소스에 박지 않는다. 선언을 읽는 자리는 M79의 공용 헬퍼(`dn_names` · `dn_pairs` · `DnNames` · `DnPairs`)를 쓴다.
- `O18`과 `O36`~`O40`은 지금과 같은 `ok` · `no`를 낸다(출력 동일). 판정이 읽는 넓이(무는 범위)가 바뀌는 자리가 있으면 보고서에 적는다(M79 회고 메모 3 — 출력 동일과 무는 범위 동일을 나눠 적는다).
- Part O에 케이스를 더한다(번호는 `O59` 다음부터).
  - 선언 정합: 두 선언 줄의 유일성 · 이름 추출이 비지 않음 · 금지 구분자 · 이름 유일성 · 정의 항목 양방향(이름마다 정확히 하나 · 고아 0) · 정의 순서 = 선언 순서 · 값 선언의 키 집합 = 이름 집합 · 값이 `ok` · `no` 안에 있음.
  - 갈래 고정: 갈래마다 그 갈래로 떨어지는 입력 한 벌을 먹여 이름이 나오는지(넷 각각).
  - **변환마다 통제(`rf-88`)**: 선언을 읽는 자리(이름 위치 · 값 쌍 파싱)마다 「선언을 바꾸면 출력이 따라 바뀐다」 통제를 둔다 — 예: 값 선언에서 한 갈래의 값을 뒤집은 합성 규약에서 그 갈래의 판정이 뒤집힌다 · 이름을 바꾼 합성 규약에서 정의 판정이 붉는다. 버전 추출(`FirstVer` · `NthVer` · `doc_base`)은 기존 positive-control이 있으면 그것을 인용하고, 없으면 같은 형태로 더한다.
- 「기계가 묻는 것」 고지(T01)가 든 판정마다 케이스가 하나 이상 있다(1:1 대조표를 보고서에 둔다).
- 되돌림은 「새 케이스 × 회귀 방향」으로 펼친다(M79 회고 메모 4). 입력 꼴 쪽 방향(빈 기반 버전 · 접두 `v` 없는 버전 · 선언 줄 앞 들여쓰기)도 판정 쪽과 같이 펼친다(`rf-01`).
- 이 판정은 판정 조건을 바꾸므로 `lifecycle-state-table`이 걸린다. 규약 "새 판정의 생명주기 상태표" 소절의 상태 목록 전부와 판정별 격자를 사본으로 재고 `## 테스트 결과`에 적는다.

### M82-T03: `N58` 경계 비교 필터의 통제 (deps: M82-T02)

- **변경 파일**: `tests/discover/run.sh` · `tests/discover/run.ps1` · `docs/conventions.md`(`floor-ask-cases:` 한 토큰)
- 접미 ID 케이스 하나만 든 합성 러너 두 벌(sh · ps1 형태)을 `fa_case_unmapped` · `FaCaseUnmapped`에 먹여, 대응 없는 접미 케이스가 1로 세어지는지 묻는 통제를 Part N에 더한다(번호는 `N62` 다음).
  두 러너의 필터를 함께 「접미 ID → 0」으로 바꾼 사본에서 이 통제가 두 사본 모두 붉는지 되돌림으로 잰다(M79 리뷰 라운드 1 반증과 같은 편집).
- Part N은 `floor-ask-from:` 이상의 케이스가 전부 대응에 있어야 한다(`case-mapped`). 새 케이스를 `floor-ask-cases:`에 `case-mapped`의 케이스로 더한다.
- T02와 같은 두 러너 파일을 고치므로 T02 뒤에 순차로 한다.

## 완료 기준

1. 규약 "회고 후속 항목의 소비" 절에 갈래 이름 선언 · 값 선언 한 줄씩과 이름별 정의 항목이 있고, 그 절 안에 갈래를 번호(⑴~⑷)로 가리키는 자리가 0이다.
2. 두 러너의 순서 판정이 갈래 이름을 내고, 이름과 판정 값을 선언에서 읽는다 — 러너 소스에 갈래 이름 문자열이 박혀 있지 않다(`grep`으로 확인하고 패턴 · 대상 · 대조 항목 · 루트를 적는다).
3. `O18` · `O36`~`O40`의 출력이 HEAD와 같다(두 러너 · 기준선 대조).
4. 아래 교란마다 두 사본에서 해당 케이스가 붉고, 결과가 되돌림 표에 있다 —
   ⑴ 이름 선언에서 이름 하나를 지움 ⑵ 이름 하나를 복제 ⑶ 정의 항목 하나를 지움 ⑷ 선언에 없는 정의 항목을 더함 ⑸ 정의 항목 둘의 순서를 바꿈
   ⑹ 값 선언에서 한 갈래의 값을 뒤집음 ⑺ 값 선언에서 한 갈래를 지움 ⑻ 값에 `ok` · `no` 밖의 값을 넣음 ⑼ 러너의 갈래 시험 순서를 바꿈
   ⑽ 두 러너의 `N58` 필터를 함께 「접미 ID → 0」으로 바꿈.
5. 「기계가 묻는 것」 고지(T01)의 판정마다 T02 · T03의 케이스가 하나 이상 대응하고, 그 대조표가 impl 보고서에 있다.
6. 생명주기 상태표가 impl 보고서 `## 테스트 결과`에 있다 — 규약 상태 목록의 모든 상태와 판정별 격자가 낸 상태가 한 행씩이고, 해당 없는 상태는 사유가 붙어 있다.
7. `pwsh` 7 · Windows PowerShell 5.1의 `tests/discover` 전수가 FAIL 0이고 나머지 `run.ps1` 하니스 여섯도 두 PowerShell에서 FAIL 0이다(수는 `tests/discover/README.md`의 `cases:` 선언처를 가리킨다). sh 축은 규약 `measure-axis:`대로 CI가 판정한다.
8. `skills/` · `hooks/` 변경이 0이거나, 바뀐 자리가 T01 훑기가 찾은 재서술처뿐이다(`git diff --name-only`).
