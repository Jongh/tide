# M39 — 검사가 보는 집합을 태그에 실리는 집합에 맞춘다

## 목표

이 마일스톤이 끝나면 **릴리즈 커버리지 체크가 자기가 막겠다고 선언한 것을 실제로 볼 수 있다.**
지금 이 검사는 커밋된 diff만 보는데 release 자신은 워킹트리를 쓸어담아 태그에 싣는다 — 검사 집합과
태그 집합이 갈라져 있고, 정상 tide 사이클에서는 검사 범위가 **항상 공집합**이다. 이 사이클이
끝나면 범위는 "태그에 실릴 것"으로 정의되고, 스테이징 범위는 스킬이 명시하며, 규약↔스킬 정합을
하니스가 문다. 동시에 **갓 태어난 프로젝트도 리뷰 검증 규율을 담은 규약으로 출발한다** — 지금은
kickoff 산출 규약에 그 절이 없어 신규 프로젝트가 두 사이클 뒤 스스로 채워 넣어야 했다.

## 배경

**출처는 외부 사용자 프로젝트의 실측 회수 리포트**(`nipa3_cctv_checker`, 2026-08-04~05, 사이클 2회,
tide 2.11.0→2.12.0)다. 그 프로젝트는 빈 레포에서 kickoff로 출발해 두 사이클을 돌았고, tide의
"라이브 도그푸딩 영역"(하니스로 집행 못 하고 실제 세션에서만 관측되는 항목) 미실측 목록을 대조해
확인 4 / 반증 0 / 측정 불가 3을 회수했다. 버전 게이트를 세션 로그의 스킬 base directory 경로로
확정했고(2.11.0 35회·타버전 0회 / 2.12.0 10회·타버전 0회), 미발화를 반증으로 승격하지 않았다.

그 리포트가 **판정 밖에서** 기록한 관측 두 건이 이 마일스톤의 근거다.

1. **커버리지 체크의 범위는 tide 정상 흐름에서 구조적으로 비어 있다.** release는 프리플라이트
   **후에** 커밋하므로 사이클 산출물은 검사 시점에 전부 미커밋이고, 직전 릴리즈 이후 HEAD가
   움직이지 않았으면 `git diff <태그>..HEAD`는 공집합이다(다운스트림 v0.2.0에서 실제로 공집합).
   더 중요한 것은 **실제 편승이 검사 밖에서 일어났다는 사실**이다 — v0.1.0 릴리즈의 `git add -A`가
   `.claude/settings.local.json.tmp.13580.…`를 스테이징했고, 되돌린 주체는 커버리지 체크가 아니라
   `git status`를 읽은 에이전트였다. 규약(`docs/conventions.md` "릴리즈 커버리지 체크")은 목적을
   "편승을 릴리즈 시점에 노출"이라 적지만 집행은 커밋된 diff만 본다 — **집행력을 사실보다 넓게
   주장**하는 형태이고, 이는 M36이 못박고 M38이 세 라운드에 걸쳐 인용한 `vacuous-pass` 부류다.
   `skills/release/SKILL.md`의 게시 절차가 스테이징 범위를 `git add`로만 적어 범위를 정하지 않은
   것도 같은 구멍의 절반이다.
2. **kickoff 산출 규약에 리뷰 검증 규율·차단 등급 판례가 없다.** `skills/kickoff/SKILL.md`의 4번
   항목이 요구하는 것은 단계별 금지행위·상태 파일·태스크 ID·버전 파일·템플릿 단일 원본 다섯이고,
   "리뷰 검증 규율"·"차단 등급 판례" 문자열은 0건이다. 다운스트림에서 M1 리뷰는 레포 규약에 근거가
   0줄인 상태에서 **설치본만으로** 반증 패스를 강제했고(M32 항목의 실증 — 이 사이클로 닫힌다),
   결손을 M2 리뷰가 스스로 이슈로 잡아 채웠다. 스펙 위반은 아니지만 배선 갭이다.

여기에 **M38 리뷰가 M39 이월 원장 ①로 남긴 항목**(집행 칸 참조의 해소 가능한 표기 `job:<이름>`)을
합류시킨다 — M38 리뷰 자신이 "표기를 구조화하면 사람이 산문으로 주장할 여지가 사라진다"며 같은
`vacuous-pass` 재발 표면을 줄이는 수단으로 지목했다. 이 마일스톤의 두 축(검사 범위 정정 · 표기
구조화)이 같은 부류를 양쪽에서 좁힌다.

이월 원장의 나머지(② `workflow-syntax` 확인의 스킬 배선 ③ `external-tool` 축 집행 ④ 가드 측 BOM
견고성 ⑤ `site-includes` 완주 플래그)는 **이번에 집지 않는다** — ②는 프리플라이트 표면을 건드리는데
이 사이클이 이미 같은 표면(T01·T03)을 고치므로 한 사이클에 두 겹으로 얹으면 M37이 다섯 라운드를
쓴 그 형태가 된다. M40으로 넘긴다.

또한 실측 회수로 **원장 자체가 갱신 대상**이 됐다 — M32 항목은 닫혔고, M31 두 advisory는 "검사 실행·
분기 선택·규약 순서 도달"까지 부분 회수됐으며, 실행 환경 축(M38)은 애초에 tide 자신의 기여자 규율이라
**사용자 프로젝트 라이브 도그푸딩 항목이 아니다**(분류 오류). 새 미실측 두 건(반증 패스의 서브에이전트
디스패치 경로 — 2회 모두 폴백 / 가드의 차단 경로 — 시도 사례 없음)도 원장에 올린다.

## 태스크 상세

### M39-T01: 릴리즈 커버리지 체크의 대상 범위를 "태그에 실릴 집합"으로 정정

- **변경 파일**: `docs/conventions.md` ("릴리즈 커버리지 체크" 절)
- **대상 범위 산정** 항목을 다음으로 바꾼다 — 범위 = ⑴ `git diff --name-only <태그>..HEAD`(커밋 편승)
  **∪** ⑵ `git status --porcelain`이 보고하는 **미커밋 변경**(추적 파일 수정·삭제 + 미추적 파일).
  ⑵의 근거를 한 줄로 적는다: **release가 커밋 전에 스테이징하므로 미커밋 변경도 태그 트리에 실린다.**
  `git status --porcelain`은 `.gitignore`를 존중하므로 `.tide/phase`·`.tide/debug-session` 같은 로컬
  상태 파일은 자동으로 빠진다(별도 제외 규칙을 새로 만들지 않는다 — 기존 bookkeeping 제외는 그대로).
- **정직 표기**: 이 절이 "커밋된 것만 본다"였던 동안 **정상 tide 사이클에서 범위가 항상 공집합**이었다는
  사실과 그 근거(release가 프리플라이트 후에 커밋한다)를 절 안에 한 줄로 남긴다. 집행 부재를 감추지
  않는 것이 이 레포가 `external-tool` 축에 쓴 것과 같은 형식이다.
- **하위 호환 서술 갱신**: 범위가 넓어지면 정상 사이클의 미커밋 impl 산출물이 범위에 들어온다 — 그러나
  그것들은 impl 보고서 본문에 경로로 언급되므로 **커버 판정을 통과해 경고가 없다**(소음 0 유지). 기존
  "소음 0" 문장을 이 근거로 다시 쓴다. 반대로 보고서 어디에도 없는 미추적 파일(예: 편집기 임시 파일)은
  이제 **경고에 뜬다** — 이것이 이 정정의 목적이고, advisory·비차단이라 릴리즈를 막지 않는다.
- **불변**: 프리플라이트 게이트 ①②③의 순서·판정 로직, 이 검사가 advisory(비차단)라는 성격, git
  **읽기만** 쓴다는 성질(`git status`도 읽기 — 가드 무수정) 전부 그대로. 첫 릴리즈(태그 없음) 분기는
  HEAD 트리 전체 ∪ ⑵로 같은 방식으로 확장한다.

### M39-T02: 실행 환경 축 표의 집행 칸을 `job:<이름>` 해소 가능 표기로 구조화 (deps: M39-T01)

- **변경 파일**: `docs/conventions.md` ("실행 환경 축" 절 — T01과 같은 파일이라 순서를 deps로 고정)
- 지금 집행 칸은 산문("CI `posix` 잡 2 OS")이고 축↔잡 매핑은 별도 선언 줄
  `<!-- env-axis-ci-jobs: … -->`에 따로 있다. **선언처가 둘**이라 갈라질 수 있고, M38 리뷰가 "묻지 않는
  것"으로 남긴 ⑶⑷가 정확히 그 틈이다. 집행 칸에 `job:<잡이름>` 토큰을 **표 안에** 넣어 매핑을 표로
  흡수하고, 별도 매핑 선언 줄은 제거하거나 표에서 파생되는 것임을 명시한다.
- 잡을 지목하지 않는 축(`workflow-syntax` = 사람·스킬 미배선, `external-tool` = 미집행)은 **토큰 없이**
  현행 정직 표기를 유지한다 — 집행 없는 축을 집행되는 것처럼 적는 것이 `vacuous-pass`다. 토큰 부재가
  곧 "기계 집행 없음"의 표시가 되게 한다.
- 표기 문법을 절 안에 한 줄로 정의한다(`job:<이름>` — ASCII, 한 칸에 여러 개 가능). 하니스가 이 토큰을
  추출하므로 **문법이 단일 원본**임을 명시한다.

### M39-T03: release 스킬의 스테이징 범위 명시 + 커버리지 절차 동기화 (deps: M39-T01)

- **변경 파일**: `skills/release/SKILL.md`
- 프리플라이트 5번(커버리지 체크) 절차를 T01의 범위 정의와 같게 고친다 — `git diff --name-only`에
  더해 `git status --porcelain`으로 미커밋 변경을 함께 모은다는 문장을 넣는다(규약↔실행 동기화:
  규약과 스킬을 **같은 사이클에** 손본다).
- 게시 분기의 스테이징을 **명시한다**: 지금 `git add`로만 적혀 범위가 미정이고, 그래서 다운스트림
  에이전트가 `git add -A`를 골라 임시 파일을 태그에 실었다. 스테이징 범위를 명시적으로 적고(대상 레포
  루트 기준 전체 스테이징), **커버리지 체크가 보는 집합이 이 스테이징 집합과 같다**는 것을 한 줄로
  연결한다. push-only·`release`·`pr` 세 모드 모두 같은 문장을 참조하게 한다(세 곳에 복제하지 않는다).
- **불변**: 게시 모드 분기 로직·PR 상태 분기·태그 생성 순서는 손대지 않는다. 커버리지는 여전히
  비차단 advisory다.

### M39-T04: kickoff 산출 규약에 리뷰 검증 규율·차단 등급 판례 배선

- **변경 파일**: `skills/kickoff/SKILL.md`
- 생성/확인 4번(`docs/conventions.md` 골격) 항목에 **리뷰 검증 규율**과 **차단 등급 판례**를 더한다 —
  신규 프로젝트의 규약이 그 둘을 담은 채 출발하게 한다. 지금 요구 항목은 단계별 금지행위·상태 파일·
  태스크 ID·버전 파일·템플릿 단일 원본 다섯이고, 여기에 두 항목을 가산한다(기존 다섯은 불변).
- 담을 내용은 **요지 수준**으로 한정한다 — tide 레포의 해당 절 전문을 복제하면 문서 복제 드리프트를
  새로 만든다. 신규 프로젝트가 알아야 할 것은 ⑴ 리뷰가 판정 후보를 스스로 공격하는 절차를 밟는다는
  것 ⑵ 가드·검증이 공허하게 통과하거나 문서가 집행력을 사실보다 넓게 주장하면 차단 등급이라는 것,
  둘이다. 상세 규약의 단일 원본은 설치본 스킬임을 명시한다.
- **엣지케이스(반드시 확인)**: `tests/discover` Part E는 리뷰 검증 규율 토큰의 **교차·음성 통제**를
  갖는다(반증 시도 토큰이 impl 템플릿에 없어야 하는 식). kickoff SKILL에 토큰이 등장하면 그 통제
  케이스와 간섭할 수 있으니, 편집 후 Part E를 양 셸로 돌려 확인한다. 간섭하면 통제의 대상 파일 목록을
  좁히는 쪽으로 조정하고(토큰을 빼는 방향이 아니라), 그 판단 근거를 impl 보고서에 적는다.

### M39-T05: 하니스 — Part D 확장 + Part H 재배선 + 케이스 수 선언 1회 갱신 (deps: M39-T01, M39-T02, M39-T03)

  F1이 이 값을 실제 케이스 수와 대조하므로 중간 상태로 두면 양 셸이 FAIL한다. 이 파일은 회고가 반복해
  지적한 수기 카운트 드리프트 핫스폿이니 **러너를 실제로 돌려 나온 수**를 적는다(추정 금지).
- `.sh`·`.ps1` 두 사본을 함께 갱신하고 **양 셸 케이스 수·종료 코드가 같은지** 확인한다.

## 완료 기준

1. `docs/conventions.md`의 "릴리즈 커버리지 체크" 절이 범위를 **커밋 diff ∪ 미커밋 변경**으로 정의하고,
   그 근거(release가 프리플라이트 후에 커밋하므로 미커밋 변경도 태그에 실린다)와 정정 전 공집합
   사실을 함께 적는다.
2. `skills/release/SKILL.md`가 ⑴ 커버리지 절차에서 미커밋 변경을 함께 모으고 ⑵ 스테이징 범위를
   명시하며 ⑶ 그 둘이 같은 집합임을 한 줄로 연결한다. 세 게시 모드가 같은 문장을 참조한다(복제 없음).
3. 워킹트리에 **어떤 보고서에도 없는 미추적 파일**을 하나 두고 커버리지 판정을 수행하면 그 파일이
   미상 목록에 뜬다. 같은 상태에서 그 파일을 지우면 경고가 없다(구별력 — 판정 규칙을 규약대로 적용한
   결과로 보인다).
4. `skills/kickoff/SKILL.md`의 conventions 골격 요구 항목이 기존 다섯 + **리뷰 검증 규율 · 차단 등급
   판례** = 일곱이고, 각 항목의 상세 단일 원본이 설치본 스킬임을 명시한다.
5. `tests/discover`가 새 토큰 `git status --porcelain`의 규약↔release 스킬 정합을 집행하고, 어느 한
   쪽에서 그 토큰을 지우면 **양 셸이 FAIL한다**(구별력 실측으로 확인).
6. Part H가 축↔잡 매핑을 **표의 `job:<이름>` 토큰**에서 추출하고, 기존 검사 성질(잡 실재·축 행 실재·
   매핑 커버리지)이 유지되며, 토큰 없는 축(`workflow-syntax`·`external-tool`)이 그 때문에 FAIL하지
   않는다.
7. `tests/discover/README.md`의 `cases:` 선언·Part별 내역·러너 요약 줄이 **러너를 실제로 돌려 나온
   수**와 일치하고, `.sh`·`.ps1` 양 셸이 같은 케이스 수·같은 종료 코드를 낸다.
8. `docs/project-context.md`의 라이브 도그푸딩 현황이 M32 닫힘 · M31 부분 회수 · 실행 환경 축 분류
   정정 · 신규 미실측 2건을 출처(외부 프로젝트·기간·tide 버전)와 함께 담고, 이월 원장 표에 M39 행이
