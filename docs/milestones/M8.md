# M8 — 누적 후속 정리: 차단 메시지 한국어화·패키지 위생·문서 단일화

## 목표

이 마일스톤이 끝나면, 회고가 장기 미반영으로 추적해 온 저비용 후속 세 가지가 해소된
상태가 된다. tide-guard가 git을 막을 때 **한국어 메시지**로 안내하고(sh·ps1 동일,
Windows에서 한글 깨짐 없음), 플러그인 배포의 **패키지 위생**에 대한 현재 가능한 수단이
재조사·결정·문서화되며, 사이트의 `conventions`·`changelog`가 저장소 원본을 **단일
원본으로 인클루드**해 이중 갱신 부채가 사라진다(사이트 출력의 외부 귀속은 여전히 0건).

## 배경

v0.8.0 시점 회고(`docs/reports/retro.md`)가 미반영 후속의 우선순위를 정리했고, 사용자가
그중 비용 대비 효과가 큰 세 항목을 이번 마일스톤 범위로 지정했다(최장기 항목인 "진짜
병렬 실행 수단"은 이번 범위에서 제외 — 별도 마일스톤).

- **차단 메시지 한국어화** (M1-impl#3, 6사이클째 미반영) — `hooks/tide-guard.sh`·`.ps1`의
  차단 문구가 영어다(`"... is blocked during phase ... allowed only in /tide:release."`).
  저비용·사용자 대면인데도 ps1 한글 인코딩(BOM) 규약 미도입으로 계속 미뤄졌다.
- **패키지 위생** (M2-review#3·M3, 수용 종결) — 플러그인 배포가 `docs/`·`site/`·`.github/`
  등 런타임 무관 파일을 포함한다. M3에서 "공식 제외 수단 부재"로 수용 종결했으나, 회고가
  "수단 생기면 재검토"로 남겼고 M7로 `site/`가 늘며 재조사 가치가 커졌다.
- **사이트 conventions/changelog 단일화** (M7-impl#2·M7-review 사소2) — M7이 porpoise 제거를
  위해 원본의 사본을 만들면서 "원본↔사이트" 동기화 축이 새로 생겼다. 회고가 "새 표면 =
  새 동기화 부채"로 부각했고, 빌드 시 인클루드로 끊을 수 있다.

## 태스크 목록

- M8-T01: tide-guard 차단 메시지 한국어화 (sh·ps1) + ps1 한글 인코딩 규약
- M8-T02: 패키지 위생 재조사 + 결정·문서화

- M8-T05: 규약·README 반영 + `--strict` 재빌드·porpoise 재검증 (deps: M8-T01, M8-T03, M8-T04)

## 태스크 상세

### M8-T01: tide-guard 차단 메시지 한국어화 (sh·ps1) + ps1 한글 인코딩 규약

`hooks/tide-guard.sh`(원본)와 `hooks/tide-guard.ps1`(보조 사본)의 차단 메시지를
한국어로 바꾼다. 두 사본의 문구를 **동일하게** 유지한다(규약: 로직·문구 수정 시 함께 갱신).

- 현재 문구: `tide-guard: git commit/tag/push is blocked during phase '$phase'. Git
  operations are allowed only in /tide:release.`
- 한국어 예시: `tide-guard: '$phase' 단계에서는 git commit/tag/push가 차단됩니다. git
  작업은 /tide:release 단계에서만 허용됩니다.` (변수 보간 위치 유지 — sh `$phase`,
  ps1 `$phase`)
- **인코딩 처리(핵심 불확실성)**: `tide-guard.ps1`은 Windows PowerShell 5.1이 한글을
  깨뜨리지 않도록 **UTF-8(BOM 포함)** 로 저장한다 — 5.1은 BOM 없는 UTF-8을 ANSI로 오인해
  한글이 깨질 수 있다. `tide-guard.sh`는 UTF-8(BOM 없음)로 둔다(sh/Git Bash는 BOM이 있으면
  첫 줄 shebang 처리에 문제가 생길 수 있으므로 BOM 금지). 즉 **두 파일의 인코딩 규약이
  다르다** — 이를 conventions에 명시한다.
- 검증: `.tide/phase`를 `impl` 등으로 둔 상태에서 `git commit` 류를 시도해 한국어 메시지가
  깨짐 없이 출력되고 exit 2가 되는지 확인(sh 경로 필수, ps1 경로는 가능 환경에서).
- 로직(정규식·exit 코드·phase 판정)은 변경하지 않는다 — 문구·인코딩만.

### M8-T02: 패키지 위생 재조사 + 결정·문서화

플러그인 배포에 런타임 무관 파일이 포함되는 문제를 현재 시점 기준으로 재조사하고
결정을 문서화한다. **조사 태스크**이므로 불확실성을 명시하고 대체 경로를 정한다.

- 조사 대상: Claude Code 플러그인/마켓플레이스가 배포 파일을 제한하는 공식 수단이
  생겼는지 — `plugin.json`·`marketplace.json`의 `files`/`include`/`ignore` 류 필드,
  `.claudeignore`/`.gitattributes export-ignore` 적용 여부, `source` 하위 경로 지정 등.
- **수단이 있으면**: 런타임에 불필요한 `docs/`·`site/`·`.github/`·드라이런 산출물을
  배포에서 제외하도록 최소 적용한다(런타임 필수인 `skills/`·`hooks/`·`.claude-plugin/`은
  보존). 적용 후 재설치 드라이런으로 노출·가드 동작이 유지되는지 확인.
- **수단이 없으면**: M3의 "수용 종결"을 현재 근거로 갱신해 재확정하고, `docs/conventions.md`
  또는 `docs/project-context.md`에 "배포 포함 파일 = 저장소 전체, 공식 제외 수단 부재"를
  한 줄로 남긴다(다음 재검토 트리거 포함).
- 산출물은 코드 변경이 아니라 **결정 기록**일 수 있음을 전제한다(완료 기준은 "결정이
  문서화됨").

### M8-T03: pymdownx.snippets 도입 + 사이트 conventions 단일 원본 인클루드

사이트의 규약 페이지가 저장소 원본 `docs/conventions.md`를 단일 원본으로 인용하게 한다.

- `site/mkdocs.yml`의 `markdown_extensions`에 `pymdownx.snippets`를 추가하고
  `base_path`를 저장소 루트(`mkdocs.yml` 기준 `..`)로 설정해, 사이트 밖 `docs/`·루트
  파일을 인클루드할 수 있게 한다.
- **porpoise 재유입 방지(핵심 제약)**: 원본 `docs/conventions.md:3`에는 외부 귀속 문장이
  있으므로 파일 전체를 인클루드하면 사이트에 porpoise가 되살아난다. 따라서:
  - 원본 `docs/conventions.md`의 **본문(도입 문단 제외)** 을 snippet 섹션 마커
    HTML 주석으로 감싼다: `<!-- --8<-- [start:body] -->` … `<!-- --8<-- [end:body] -->`.
    이는 의미 내용·porpoise 문장을 건드리지 않는 **마커 주석만의 최소 수정**이다.
  - `site/docs/conventions.md`는 사이트 전용·porpoise-free 도입 문단을 그대로 두고, 그
    아래를 `--8<-- "docs/conventions.md:body"` 인클루드로 대체한다.
- 대체 경로(마커가 어려우면): 원본에서 porpoise 귀속 문장 자체를 tide 자체 정의로
  리워딩해 원본을 순수 단일 원본으로 만들고 site는 파일 전체를 인클루드 — 단 이 경로는
  원본의 콘텐츠를 바꾸므로 기본안(마커)보다 후순위.
- 검증은 T05에서 `--strict` 빌드로.

### M8-T04: 사이트 changelog 단일 원본 인클루드 (deps: M8-T03)

사이트의 변경 이력 페이지가 `CHANGELOG.md`를 단일 원본으로 인용하게 한다(T03이 도입한
`pymdownx.snippets` 설정 재사용).

- `CHANGELOG.md`는 외부 귀속이 없어 본문 인클루드가 안전하다. 다만 파일 상단의
  `# CHANGELOG (Older Releases)` 제목과 README 안내 줄은 사이트 페이지에 부적절하므로,
  릴리즈 노트 블록을 snippet 섹션 마커로 감싼다(`[start:notes]`…`[end:notes]`).
- `site/docs/changelog.md`는 사이트 전용 도입 문단 + 원본 링크를 두고, 릴리즈 노트
  부분을 `--8<-- "CHANGELOG.md:notes"` 인클루드로 대체한다.
- 주의: `CHANGELOG.md`와 README의 CHANGELOG 절은 규약상 동일 노트를 둔다(별개의 기존
  중복) — 이 태스크 범위가 아니다. 여기서는 사이트↔`CHANGELOG.md` 축만 단일화한다.

### M8-T05: 규약·README 반영 + `--strict` 재빌드·porpoise 재검증 (deps: M8-T01, M8-T03, M8-T04)

- `docs/conventions.md`: tide-guard 절의 차단 메시지 예시를 한국어로 갱신하고, sh=BOM
  없는 UTF-8 / ps1=BOM 포함 UTF-8 **인코딩 규약**을 한 줄 명시(T01). 단일 원본 인클루드
  도입 사실도 필요 시 한 줄.
- 격리된 가상환경에서 `mkdocs build -f site/mkdocs.yml --strict`가 인클루드(snippet)
  정상 해석으로 경고·깨진 링크 없이 통과하는지 확인.
- 빌드 출력(`site/_build`) 기준으로 **porpoise 0건**(`grep -ri porpoise site/_build`)을
  재확인 — 인클루드가 원본 본문만 가져와 도입부 귀속이 새지 않았음을 실증. 검증 후
  임시 venv·`_build` 정리.
- T02가 코드 변경을 낳았다면 재설치 드라이런 결과도 보고서에 포함.

## 완료 기준

1. `.tide/phase`가 `release`가 아닌 상태에서 git commit/tag/push를 시도하면 tide-guard가
   **한국어** 메시지로 차단(exit 2)하며, sh 경로에서 한글이 깨지지 않는다. sh·ps1 두
   사본의 문구가 동일하고, ps1은 UTF-8(BOM)·sh는 UTF-8(BOM 없음)로 저장돼 있다.
2. 패키지 위생에 대한 현재 시점 조사 결과와 결정(적용 또는 수용 재확정)이 문서로 남는다.
   적용 가능한 공식 수단이 있으면 런타임 무관 파일이 배포에서 제외되고 재설치 드라이런이
   통과한다.
3. `site/docs/conventions.md`가 `docs/conventions.md`를 snippet 인클루드로 단일 원본화하고,
   `site/docs/changelog.md`가 `CHANGELOG.md`를 단일 원본화한다(사본 본문 중복 제거).
4. `mkdocs build -f site/mkdocs.yml --strict`가 인클루드 정상 해석으로 경고 없이 통과한다.
5. 빌드 출력(`site/_build`)에 "porpoise"가 0건 — 단일 원본화가 외부 귀속을 재유입하지
   않았다.
6. `docs/conventions.md`의 tide-guard 절이 한국어 차단 메시지·인코딩 규약을 반영하고,
   원본 conventions의 **의미 내용은 무변경**(섹션 마커 주석·예시 문구 갱신 외).
