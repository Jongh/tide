# M21 — 오케스트레이션 발견성: 멀티 레포 맥락 감지 힌트 + 커맨드 수 드리프트 가드

## 목표

이 마일스톤이 끝나면 **사용자가 멀티 레포 맥락에 들어선 바로 그 순간 fleet 입구를 안내받는다.**
구체적으로 `/tide:status`와 `/tide:kickoff`가 정상 동작 끝에 — 상위 폴더에서 실행돼 **직속 자식 tide
레포가 2개 이상** 발견되면 — `여러 자식 tide 레포 N개 감지 — 교차 개요는 /tide:fleet` 한 줄을
advisory로 덧붙인다(발견 로직은 fleet 규약 재사용). 자식 tide 레포가 2개 미만(단일 레포 세션 포함)이면
**아무 것도 덧붙이지 않는다**(소음 0). 또한 M20 리뷰가 적발한 "사이트 커맨드 수 표류(8종↔11종)"가 다시
생기지 않도록, **커맨드 스킬 실제 개수와 문서·사이트의 선언 개수가 어긋나면 실패하는 가드**를 둔다.
전부 읽기 전용·하위 호환 가산 — 단일 레포 세션의 status/kickoff 동작은 불변이다.

## 배경

v2.0.0(M20)으로 오케스트레이션 에픽이 닫히고 백로그가 비었다. v2.0.0 회고가 남긴 **유일한 미반영
후속**이자 본 세션 논의에서 새로 제안된 항목이 **오케스트레이션 발견성**이다 — fleet 3종은 강력하나
적용 맥락(상위 폴더 + 자식 tide 레포 2개 이상)이 좁아 사용자가 그 존재·시점을 알기 어렵다. 가장 ROI 큰
한 수는 이미 있는 **발견 로직을 재사용**해, 사용자가 멀티 레포 맥락에 있을 때 읽기 전용 보조 커맨드
(`status`·`kickoff`)가 fleet 입구를 한 줄로 가리키는 것이다(M21 후보로 v2.0.0 회고에 기록됨).

함께, M20 리뷰의 major #6(`site/docs`가 v1.2.0·2.0 갱신을 놓쳐 "8종"으로 표류, 같은 nav의 가이드와 모순)이
드러낸 교훈 — **단일 원본화가 닿지 않는 수기 페이지가 드리프트 핫스폿** — 을 기계적 가드로 닫는다.
회고 메모 #3("수기 사이트 페이지를 가능한 단일 원본으로 — M21에서 함께 검토")의 이행이다.

메타 규칙("규약↔실행/인프라 동기화"): 발견성 규약을 더하면 그 강제·검증인 라이브 실증을 같은 사이클에
넣는다(감지 임계값 + 커맨드 수 일치 가드 하니스).

## 정규 spec (이 마일스톤의 단일 기준 — 모든 태스크가 인용)

### 멀티 레포 맥락 감지 힌트 (status·kickoff, advisory)

- **트리거**: `/tide:status`·`/tide:kickoff`가 자기 본래 작업을 마친 뒤, **현재 세션 위치(cwd)의 직속
  1단계 하위 디렉터리** 중 **자식 tide 레포**(fleet 발견 규약 그대로: git 레포 AND tide 산출물 보유,
  이름이 `.`으로 시작하는 숨김 디렉터리 제외)를 센다.
- **출력 조건**: 발견된 자식 tide 레포가 **2개 이상**이면 출력 **맨 끝에** 한 줄을 advisory로 덧붙인다 —
  예: `여러 자식 tide 레포 N개 감지 — 교차 개요는 /tide:fleet`(N=발견 수). **2개 미만(0·1개)이면 아무
  것도 덧붙이지 않는다.** 단일 레포 루트에서 실행한 일반 경우엔 자식이 tide 레포가 아니므로 힌트가 안
  나온다(소음 0).
- **불변**: 힌트는 **읽기 전용·advisory**다 — status는 종전대로 완전 읽기 전용(파일·git·phase 무변경),
  kickoff는 골격 생성 외 동작 불변이며, 힌트가 fleet/cycle을 자동 실행하지 않는다. 발견 규약의 단일
  원본은 `docs/conventions.md`의 "멀티 레포 오케스트레이션"(발견) 절이고, 힌트는 그것을 인용한다.
- **하위 호환**: 자식 tide 레포 2개 미만인 모든 세션(단일 레포 포함)에서 status·kickoff 출력은 현행과
  바이트 동일하다(순수 가산).

### 커맨드 수 드리프트 가드

- **불변식**: `skills/*/SKILL.md`로 존재하는 **커맨드 스킬의 실제 개수**(현재 11)와, 문서·사이트가
  선언하는 "커맨드 N종" 수가 **일치**해야 한다.
- **검증 대상(단일 원본 결합)**: 캐노니컬 선언 위치 — `README.md`(설치·명명 규약), `docs/conventions.md`
  ("2.0 안정성"), `site/docs/commands.md`·`site/docs/getting-started.md` — 의 선언 수가 실제 스킬 개수와
  같은지 라이브 하니스가 grep으로 결합 검증한다(M18~M20의 SKILL-artifact-coupling 패턴 — 수기 페이지가
  표류하면 테스트가 실패). 커맨드를 더/빼면서 선언 수를 안 고치면 가드가 잡는다.
- 이 가드는 M20 리뷰 #6(사이트 8종↔11종 표류)의 회귀 고정이다.

## 태스크 상세

### M21-T01: status 멀티 레포 감지 힌트

- **변경 파일**: `skills/status/SKILL.md`
- status가 본래 보고(현재 상태 + 다음 권장 커맨드)를 마친 **맨 끝에**, 정규 spec의 트리거·출력 조건대로
  자식 tide 레포 ≥2 감지 시 한 줄 advisory(`여러 자식 tide 레포 N개 감지 — 교차 개요는 /tide:fleet`)를
  덧붙인다. 2개 미만이면 덧붙이지 않는다. **완전 읽기 전용 불변 유지**(파일·git·phase 무변경) 명시.
  발견 규약은 `docs/conventions.md` "멀티 레포 오케스트레이션" 발견 절을 인용(중복 정의 금지).

### M21-T02: kickoff 멀티 레포 감지 힌트

- **변경 파일**: `skills/kickoff/SKILL.md`
- kickoff가 골격 생성(및 진행 중 프로젝트 문서화)을 마친 **맨 끝에**, 동일 트리거·출력 조건으로 ≥2 감지
  시 같은 한 줄 advisory를 덧붙인다. 2개 미만이면 덧붙이지 않는다. kickoff의 기존 동작(골격·`.gitignore`·
  project-context 생성)은 불변이며 힌트는 그 위에 가산. 발견 규약은 conventions 인용.

### M21-T03: 발견성 규약(단일 원본) + README 언급

- **변경 파일**: `docs/conventions.md`, `README.md`
- `docs/conventions.md` "멀티 레포 오케스트레이션" 절에 **"발견성(discoverability) 힌트"** 항목을 추가 —
  트리거(세션 cwd 직속 자식 tide 레포 ≥2), 출력 조건(맨 끝 한 줄 advisory, <2면 무출력), 읽기 전용·
  advisory 불변, status·kickoff 공통 적용을 정규 spec대로 규정한다(이 규약이 두 스킬의 단일 원본).
  발견 규약 자체는 기존 발견 절을 재사용(재정의 금지).
- `README.md`: 멀티 레포(MSA) 안내나 커맨드 표 인근에 "단일 세션이 멀티 레포 맥락이면 `status`·`kickoff`가
  `/tide:fleet`을 한 줄로 안내한다"는 사용자 대면 언급 한 줄. 기존 2.0 안정성·커맨드 표는 건드리지 않는다.

### M21-T04: 라이브 실증 — 감지 임계값 + 커맨드 수 가드 (deps: 정규 spec)

- **변경 파일**: `tests/discover/run.sh`·`run.ps1`·`README.md`(신규)
- **감지 임계값 하니스**: fleet 발견 참조 구현(직속 1단계·git+tide 산출물·숨김 제외)을 재사용해, 부모
  픽스처별로 **감지 결과 = hint|none**을 검증한다 — 자식 tide 레포 2개 → **hint**(N=2), 1개 → **none**,
  0개 → **none**, 단일 레포 루트(자식이 `src/`·비-tide) → **none**, 숨김 자식(`.hidden`)은 카운트 제외.
- **커맨드 수 드리프트 가드**: `skills/*/SKILL.md` 실제 개수를 세고, 캐노니컬 선언 위치(`README.md`·
  `docs/conventions.md`·`site/docs/commands.md`·`site/docs/getting-started.md`)가 같은 수("N종")를
  선언하는지 grep 결합 검증한다(불일치면 FAIL). 실제 스킬 디렉터리를 세므로 커맨드 증감 시 자동 갱신
  요구가 강제된다.
- `run.ps1` ASCII 소스(한글 토큰은 코드포인트)·`run.sh` 무BOM·활성 가드 규율(러너에 git 차단 동사 없음)
  유지. 양 셸 전부 통과. `README.md`에 시나리오 표·실행법 기재.

## 완료 기준

1. 상위 폴더(자식 tide 레포 2개 이상)에서 `/tide:status`·`/tide:kickoff`를 실행하면 출력 맨 끝에
   `여러 자식 tide 레포 N개 감지 — 교차 개요는 /tide:fleet` 한 줄이 advisory로 붙고, 자식 tide 레포가
   2개 미만(단일 레포 세션 포함)이면 **그 줄이 붙지 않는다**(소음 0). status는 완전 읽기 전용, kickoff는
   골격 생성 외 동작 불변.
2. `docs/conventions.md`가 발견성 힌트 규약(트리거·출력 조건·읽기 전용 advisory 불변·status/kickoff 공통)을
   단일 원본으로 규정하고, 발견 규약 자체는 기존 발견 절을 재사용한다. `README.md`에 사용자 대면 언급 한 줄.
3. `tests/discover`가 감지 임계값(2개→hint·<2→none·단일 레포→none·숨김 제외)과 커맨드 수 드리프트
   가드(실제 스킬 수 == 캐노니컬 선언 수)를 양 셸에서 전부 통과한다(run.ps1 ASCII·run.sh 무BOM). 선언 수를
   실제와 어긋나게 만들면 가드가 FAIL한다.
4. 이 변경이 전부 하위 호환 가산(자식 tide 레포 2개 미만 세션의 status·kickoff 출력 불변)이며, 발견성·
   가드 추가가 부수효과 분리·읽기 전용 불변을 깨지 않음이 규약·테스트로 확인된다.
