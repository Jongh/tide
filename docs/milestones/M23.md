# M23 — 정리 사이클: 참조 구현 공유 라이브러리화 + 회고 문서 아카이브

## 목표

이 마일스톤이 끝나면 **테스트 하니스의 발견·위상정렬 로직이 한 곳에서만 정의되고, 회고 문서는
다시 읽을 만한 크기로 돌아온다.** `tests/{discover,fleet,fleet-cycle,fleet-verify}`에 4중(× 2셸)으로
복제돼 있던 `is_tide_repo`/`discover`/`toposort` 참조 구현을 `tests/lib/`의 공유 라이브러리로 추출해
각 하니스가 source하고, 규약 변경 시 한 곳만 고치면 된다. 1060행으로 비대해진 `docs/reports/retro.md`는
최근 사이클(v2.x)만 남기고 과거를 `retro-archive.md`로 분리해 입력·열람 비용을 줄인다. 동작·계약은
전부 불변 — 모든 하니스가 그대로 통과하고, `/tide:retro`는 종전대로 동작한다.

## 배경

- **출처**: M22(v2.2.0) 회고가 남긴 **정리 후속 2건**과 사용자 지시("둘 다 묶어 한 사이클", 2026-06-15).
  M22 회고 메모 #3·#4가 다음 정리축으로 ②참조 구현 이중성 축소·③retro 자기 입력비용을 부각했다.
- **② 참조 구현 이중성(M14~M20 군집 + M22 변형)**: fleet 계열은 프롬프트 스킬이라 실행 바이너리가
  없어 `tests/`가 발견·분류·위상정렬을 재구현한다. 이 재구현이 **4개 하니스 × 2셸로 복제**돼 있고,
  실제로 **드리프트가 시작됐다** — 코드 조사 결과: `is_tide_repo`/`discover`는 discover·fleet·fleet-cycle에서
  바이트 동일하나 **fleet-verify가 주석 한 줄만 다르고**(`.tide-fleet 포함` 첨언), `toposort`는 fleet(상세·
  주석)과 fleet-cycle(압축형)이 **포맷이 갈라졌다**(로직 동일 추정이나 미검증). M22 회고가 지적한 "가드를
  더할수록 단언 정밀도가 새 검증 대상"의 뿌리 = 이 복제. 단일 원본화로 닫는다(M22가 사이트 문서에 한 것을
  테스트 참조 구현에 적용).
- **③ retro 자기 입력비용(M6-impl#2, 최장수 이월)**: `docs/reports/retro.md`가 1060행(이번 v2.2.0
  섹션 추가 후)으로, 회고 시점마다 누적돼 열람·문맥 비용이 단조 증가한다. **중요 사실 확인**: `/tide:retro`
  스킬은 "자기 자신 `retro.md`는 입력에서 제외"하므로(skills/retro/SKILL.md), 과거 섹션을 별도 파일로
  옮겨도 **집계 동작에 영향이 없다** — 순수 문서 재배치다. 섹션 경계(`## ` 헤더)는 line 320(v1.4.0)이
  깔끔한 분할점이라, v2.x(v2.2.0·v2.1.0·v2.0.0)만 남기고 v1.4.0 이하를 아카이브한다.
- **비파괴(정리 patch)**: 새 커맨드·능력·계약 변화 없음. 테스트 참조 구현은 추출 후에도 **모든 하니스가
  동일하게 통과**(동작 보존), retro 분할은 문서 재배치이고 `/tide:retro` 동작 불변. 2.0 stable 계약
  (11종 커맨드·오케스트레이션 규약·`.tide/phase`/tide-guard·보고서·마일스톤 형식) 전부 불변.
- **수용 트레이드오프(설계 결정)**: 하니스의 "자기완결형"(project-context line 23·36) 성격이 약해진다 —
  이제 `tests/lib/`를 source해야 돈다. 같은 `tests/` 트리 안의 상대경로 source라 `sh tests/X/run.sh`로는
  여전히 실행되며, 단일 원본화 이득(규약 변경 시 1곳만 수정)이 자기완결성보다 크다고 본다.

## 태스크 상세

### M23-T01: `tests/lib/` 공유 참조 라이브러리 신설 (discover + toposort, 양 셸, 정본 화해)

- **변경 파일**: `tests/lib/discover.sh`(신규), `tests/lib/discover.ps1`(신규), `tests/lib/toposort.sh`(신규),
  `tests/lib/toposort.ps1`(신규)
- `tests/lib/discover.sh`: `is_tide_repo`(git 레포 AND tide 산출물, 발견 규약)와 `discover`(직속 1단계·
  숨김 제외·정렬)를 정의한다 — discover·fleet·fleet-cycle의 **바이트 동일** 버전을 정본으로 삼고,
  fleet-verify의 주석 첨언(`.tide-fleet 포함`)을 정본 주석에 통합(로직 동일이므로 주석만 흡수).
- `tests/lib/toposort.sh`: `toposort`(Kahn 변형, 피의존 먼저, `CYCLE` 반환)를 정의한다 — **정본 화해**:
  fleet의 상세·주석 버전을 정본으로 채택(가독성·완전성 우위). fleet-cycle의 압축형과 **로직 동등성**은
  T02/T03에서 두 하니스가 그대로 통과함으로 검증된다(불일치 시 하니스가 FAIL해 드러난다).
- `tests/lib/discover.ps1`·`toposort.ps1`: 위 sh와 동작 동형인 PowerShell 함수(`IsTideRepo`/`Discover`/
  `TopoSort`)를 정의한다. **ASCII 소스 규율**(비ASCII 바이트 0, 한글 필요 시 코드포인트)·**무BOM** 유지.
- 라이브러리는 함수 정의만 담고 부수효과(픽스처 생성·실행)는 없다 — 하니스가 source 후 호출한다.
- **엣지**: source 경로는 호출 하니스 기준 상대(`. "$ROOT/tests/lib/discover.sh"` 또는 스크립트 위치에서
  해석). ps1은 dot-source(`. (Join-Path $PSScriptRoot '..\lib\discover.ps1')`).

### M23-T02: discover·fleet 하니스를 공유 라이브러리 source로 전환 (deps: M23-T01)

- **변경 파일**: `tests/discover/run.sh`, `tests/discover/run.ps1`, `tests/fleet/run.sh`, `tests/fleet/run.ps1`
- 각 하니스의 로컬 `is_tide_repo`/`discover`(fleet은 추가로 `toposort`) 정의를 제거하고, 스크립트 상단
  (ROOT 해석 직후)에서 `tests/lib/discover.sh`(fleet은 `toposort.sh`도) 를 source한다. ps1도 동형으로
  dot-source. 하니스의 픽스처·시나리오·`chk`/`Chk` 단언은 **그대로 유지**.
- **검증**: 전환 후 `sh tests/discover/run.sh`·`tests/discover/run.ps1`·`tests/fleet/run.sh`·`run.ps1`이
  **전환 전과 동일한 PASS 수**로 통과해야 한다(동작 보존). discover의 M22 가드(B1/B2/B3)·fleet의 전체
  연산자 계약 비교 등 기존 단언 불변.

### M23-T03: fleet-cycle·fleet-verify 하니스를 공유 라이브러리 source로 전환 (deps: M23-T01)

- **변경 파일**: `tests/fleet-cycle/run.sh`, `tests/fleet-cycle/run.ps1`, `tests/fleet-verify/run.sh`,
  `tests/fleet-verify/run.ps1`
- fleet-cycle: 로컬 `is_tide_repo`/`discover`/`toposort`를 제거하고 `discover.sh`+`toposort.sh`를 source.
  fleet-verify: 로컬 `is_tide_repo`/`discover`를 제거하고 `discover.sh`를 source(주석 첨언은 정본에
  흡수됐으므로 손실 없음). ps1도 동형. 픽스처·단언 유지.
- **검증**: 전환 후 네 러너가 전환 전과 동일 PASS 수로 통과. 특히 fleet-cycle의 release 제외·downstream-skip,
  fleet-verify의 verification-only·git-verb 가드라일 단언 불변. **fleet-cycle의 toposort가 정본(fleet판)으로
  바뀌고도 통과**하면 두 구현의 로직 동등성이 실증된다(T01의 미검증 가정 해소).

### M23-T04: 회고 문서 아카이브 분리 (`retro.md` v2.x 유지 + `retro-archive.md` 신설 + 스킬 노트)

  스킬 동작은 불변, 아카이브 존재만 알린다("기존 섹션 보존" 지시가 분할과 모순되지 않음을 명시).
- **엣지**: v2.0.0·v1.6.0 섹션은 `## ` 헤더 없이 블록쿼트로 이어진 형태이므로(문서 구조 불일치), 분할
  경계는 **v1.4.0 `## ` 헤더 직전**으로 잡아 v2.x(블록쿼트 연속 포함)를 한 덩어리로 남긴다. `/tide:retro`
  집계는 retro.md를 입력 제외하므로 분할이 다음 회고에 영향 없음(behavior-neutral).

## 완료 기준

1. `tests/lib/`에 `discover.{sh,ps1}`·`toposort.{sh,ps1}`가 존재하고 발견·위상정렬 참조 구현을 **단일
   정의**한다. 4개 하니스(× 2셸)의 로컬 `is_tide_repo`/`discover`/`toposort` 중복 정의가 제거되고 source로 대체된다.
2. `sh tests/X/run.sh`와 `tests/X/run.ps1`(X ∈ discover·fleet·fleet-cycle·fleet-verify) + `tests/multi-repo`가
   **모두 전환 전과 동일한 PASS 수로 통과**(exit 0) — 동작 보존. fleet-cycle이 정본 toposort로 통과해
   두 구현의 로직 동등성이 실증된다.
3. `tests/lib/*.ps1` 비ASCII 바이트 **0**, 신규/수정 셸·라이브러리 파일 **BOM 없음**.
4. `docs/reports/retro-archive.md`가 v1.4.0 이하 회고를 바이트 보존으로 담고, `docs/reports/retro.md`는
   v2.x만 + 아카이브 포인터로 축소된다(과거 섹션 보존·열람 비용 감소). `/tide:retro` 동작 불변(retro.md
   입력 제외·최상단 누적).
5. `skills/retro/SKILL.md`·`docs/conventions.md`·`docs/project-context.md`가 새 단일 원본(tests/lib)과
   아카이브 관례를 기록한다(버전 숫자 미복제).
6. **비파괴 확인**: 새 커맨드·능력·계약 변화 0. 2.0 stable 계약(11종 커맨드·오케스트레이션 규약·
   `.tide/phase`/tide-guard·보고서·마일스톤 형식) 불변. M22 가드(discover B1/B2/B3) 단언 불변.
