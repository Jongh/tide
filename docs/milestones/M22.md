# M22 — 사이트 단일 원본화: 커맨드 카탈로그를 캐노니컬 `docs/`로 끌어오고 가드로 동결

## 목표

이 마일스톤이 끝나면 **공개 사이트의 커맨드 카탈로그가 더는 표류할 수 없다.** 지금까지 수기로
복제돼 있던 `site/docs/commands.md`의 커맨드 표·역할 설명이 새 캐노니컬 문서 `docs/commands.md`
한 곳에서 스니펫으로 인클루드되고(기존 conventions·orchestration·changelog와 동형), 드리프트
가드가 "개수"를 넘어 "각 커맨드 이름이 캐노니컬 카탈로그에 선언됐는지"와 "사이트 페이지가 실제
스니펫 셸인지(재복제 아님)"까지 검증한다. 회고가 M11~M20 내내 지목하고 M21이 *증상(개수)만*
가드로 고정했던 "문서↔실동작 표류" 군집의 **잔존 뿌리(수기 카탈로그 복제)를 단일 원본화로 닫는다.**

## 배경

- **출처**: 본 세션의 내부 정리 분석(2026-06-15) — `/tide:status`(M21 릴리즈 완료·phase idle) 후
  "현재 마일스톤으로 가능한 내부 정리 사항" 분석에서 **사이트 단일 원본화**가 ROI 최상 후보로 도출됨.
  사용자 지시: "사이트 단일 원본화를 핵심으로 정리 사이클 진행".
- **회고 근거**: v2.0.0 회고 메모 #3 "수기 사이트 페이지가 표류 핫스폿 — 발견성(M21) 작업 시 이
  페이지들도 가능한 한 단일 원본으로 끌어오는 것을 함께 검토", 그리고 M21 회고 "수기 사이트 페이지
  추가 단일 원본화 — 수용(가드로 갈음), 필요 시 cosmetic". M21은 개수 가드로 *증상*만 고정했고
  단일 원본화 자체는 미해결로 남겼다.
- **현황 확인(코드 직접 조사)**:
  - 단일 원본 메커니즘이 이미 정착 — `site/docs/conventions.md`·`orchestration.md`는 사이트 전용
    도입부 + `--8<-- "docs/<파일>:body"`, `changelog.md`는 `--8<-- "CHANGELOG.md:notes"`. mkdocs
    `pymdownx.snippets`(`base_path: ["."]`, `check_paths: true`)가 **레포 루트** 기준으로 해석한다.
  - 반면 `site/docs/commands.md`는 **전부 수기** — "한눈에 보기" 표 + 11개 커맨드 절이 SKILL 역할을
    복제하고 `11종`을 하드코딩한다. 이 카탈로그의 **캐노니컬 `docs/` 원본이 존재하지 않는다**.
  - `getting-started.md`(설치·5분 워크스루)·`concepts.md`("왜")·`index.md`(랜딩)는 카탈로그가 아닌
    튜토리얼/설계-원칙 산문 → 강제 단일화 대상이 아님(별도 경계 확정 필요).
- **2.0 메타 규칙 적용**: project-context "2.0 안정성" 절 — "규약·단일 원본을 새로 더하면 그것을
  강제·반영할 실행 수단도 같은 사이클에 함께 손본다". 새 캐노니컬 `docs/commands.md`를 더하므로
  드리프트 가드 확장(강제 수단)을 **같은 사이클**에 넣는다.
- **불변(비파괴)**: 커맨드 11종 이름·역할은 2.0 stable 동결 계약이라 **변경하지 않는다**. 카탈로그
  본문을 그대로 옮길 뿐이라 렌더된 사이트 출력은 변경 전과 동일하다(가산·리팩터).

## 태스크 상세

### M22-T01: 캐노니컬 `docs/commands.md` 신설 + `site/docs/commands.md` 스니펫 셸 전환

- **변경 파일**: `docs/commands.md`(신규), `site/docs/commands.md`
- 새 캐노니컬 문서 `docs/commands.md`를 만든다. 현재 `site/docs/commands.md`의 카탈로그 본문
  ("한눈에 보기" 표 + `## /tide:kickoff` … `## /tide:fleet-verify`까지 11개 절 + 멀티 레포 도입
  문단)을 **바이트 보존**으로 옮긴다. 본문을 `pymdownx.snippets` 마커로 감싼다 —
  본문 시작 직전 줄에 `--8<-- [start:body]`, 본문 끝 직후 줄에 `--8<-- [end:body]`
  (conventions.md의 `:body` 마커와 동형; 정확 마커 형식은 `docs/conventions.md` 원본을 열어 그대로 따른다).
- `docs/commands.md`는 GitHub에서도 단독으로 읽히는 정규 레퍼런스 문서가 되도록 최상단에 제목
  `# 커맨드 레퍼런스`와 한 줄 설명을 둔다(이 제목/도입은 마커 **밖** — 사이트 셸이 자체 제목을 가지므로
  중복 렌더 방지).
- `site/docs/commands.md`를 셸로 축소한다 — `site/docs/conventions.md`와 **동일 패턴**:
  사이트 전용 제목 + 도입부 + "저장소 원본 `docs/commands.md`를 단일 원본으로 인클루드" 안내(GitHub
  소스 링크) + `--8<-- "docs/commands.md:body"`. `11종` 카운트와 카탈로그는 더 이상 셸에 직접 두지 않는다.
- **엣지**: ① snippet 경로 `docs/commands.md`는 레포 루트 기준(기존 작동 스니펫과 동일 규칙) —
  새 경로가 맞는지 mkdocs `check_paths: true`가 빌드 시 검증한다. ② 본문 내 상대 링크
  (`orchestration.md`)는 사이트(`site/docs/`)·GitHub(`docs/`) 양쪽에서 형제 파일로 해석되므로
  그대로 둔다. ③ 카탈로그 표의 역할/산출물 문구는 SKILL.md와 정합해야 하나 이번엔 **이동만**
  하고 내용 변경 없음(역할 문구 갱신은 범위 밖 — 표류 시 T03 가드가 이름 누락을 잡는다).

### M22-T02: 잔여 수기 사이트 페이지 단일 원본 경계 확정 (getting-started·concepts·index)

- **변경 파일**: `site/docs/getting-started.md`, `site/docs/concepts.md`, `site/docs/index.md`
- 세 페이지를 훑어 **커맨드 카탈로그(역할·인자·산출물)를 재서술하는 지점**이 있으면 카탈로그를
  복제하는 대신 `commands.md`로의 교차 링크로 바꾼다. 반대로 튜토리얼/"왜" 산문(5분 워크스루의
  단계 설명, 설계 원칙 해설)은 **수기로 유지**하되, 그 페이지가 카탈로그의 단일 원본이 아님을
  분명히 한다(이미 getting-started 말미는 "각 커맨드의 인자와 산출물은 커맨드 레퍼런스를 참고"로
  링크함 — 이 경계를 나머지 페이지에도 일관 적용).
- `11종` 같은 카운트 토큰: getting-started의 "커맨드 11종과 tide-guard hook이 함께 활성화"는
  튜토리얼 산문이라 유지하되 T03 가드의 검사 대상에 남긴다(카운트 표류 시 적발). index가 카운트를
  하드코딩하면 동일 처리.
- **목표 상태**: 어떤 수기 페이지도 커맨드 카탈로그를 **재복제하지 않는다** — 카탈로그 세부는
  전부 `commands.md`(→ `docs/commands.md`) 한 곳을 가리킨다. 렌더 의미 변화는 중복 제거뿐.
- (T01과 독립 — 다른 파일. 교차 링크 대상 `commands.md` 페이지는 이미 존재하므로 하드 의존 없음.)

### M22-T03: 드리프트 가드 확장 — 개수→카탈로그 완전성 + 셸 검증 (deps: M22-T01)

- **변경 파일**: `tests/discover/run.sh`, `tests/discover/run.ps1`
- 가드의 캐노니컬 카운트 대상을 `site/docs/commands.md` → **`docs/commands.md`**(새 단일 원본)로
  바꾼다. T01 이후 사이트 셸엔 `11종`이 없으므로, 이를 갱신하지 않으면 기존 Part B가 곧바로 FAIL한다
  (이 결합이 단일 원본화를 강제한다).
- 검사 두 가지를 추가한다:
  1. **셸 검증(재복제 방지)** — `site/docs/commands.md`가 스니펫 셸인지 확인한다:
     `--8<-- "docs/commands.md:body"`를 **포함**하고, `${N}종`·카탈로그 표(`| 커맨드 |` 등)를
     **재선언하지 않는다**. 사이트 페이지가 다시 수기 카탈로그로 회귀하면 FAIL.
  2. **카탈로그 완전성(개수→이름)** — 실제 커맨드 이름(`skills/*/SKILL.md`의 디렉터리 basename,
     예 `kickoff`·`fleet-verify`) **각각**이 캐노니컬 `docs/commands.md`에 `/tide:<name>` 형태로
     등장하는지 검사한다. 개수만 맞고 이름이 빠지거나 바뀐 표류(개수 가드가 못 잡던 것)를 적발.
- 음성 통제 갱신: 존재하지 않는 가짜 커맨드 이름은 카탈로그에 없어야 한다(이름 검사가 실제로
  구별함을 입증). `${N}종` 개수 음성 통제(`N+1종` 부재)는 캐노니컬을 `docs/commands.md`로 옮겨 유지.
- **규율**: `run.sh`·`run.ps1` 두 셸을 함께 갱신, `run.ps1`은 ASCII 소스(한글은 코드포인트)·무BOM,
  기존 Part A(감지 임계값)·다른 하니스 불변. 러너 호출 명령줄에 git 차단 동사 없음(활성 tide-guard).
- deps: M22-T01(새 `docs/commands.md`를 대상으로 하므로).

### M22-T04: 단일 원본 도달 범위 문서 동기화 (conventions·project-context) (deps: M22-T01, M22-T03)

- **변경 파일**: `docs/conventions.md`, `docs/project-context.md`
- `docs/conventions.md` "규약↔실행/인프라 동기화"(또는 버전·CHANGELOG 인접) 절: 커맨드 카탈로그가
  이제 `docs/commands.md` 단일 원본이고 사이트는 스니펫 셸이며, 드리프트 가드(`tests/discover`)가
  개수+이름+셸을 강제함을 기록한다 — 2.0 메타 규칙(새 단일 원본 → 같은 사이클 강제 수단)의 적용 사례로.
- `docs/project-context.md`: ① 디렉터리 구조 표/단일 원본 목록에 `docs/commands.md`(캐노니컬 커맨드
  카탈로그)를 추가하고, `site/docs/{conventions,orchestration,changelog,commands}.md`가 스니펫 셸임을
  명시. ② 버전 숫자는 복제하지 않는다(드리프트 방지 기조 유지).
- 산문 동기화이므로 T01·T03이 만든 최종 상태를 정확히 서술하기 위해 deps로 둔다(파일은 비중첩이라
  병렬 안전하나 내용 정합 위해 순서 의존).

## 완료 기준

1. `docs/commands.md`가 캐노니컬 카탈로그로 존재하고(`--8<-- [start:body]`/`[end:body]` 마커 포함),
   `site/docs/commands.md`는 사이트 전용 도입부 + `--8<-- "docs/commands.md:body"` 셸로 축소된다 —
   카탈로그 본문은 이동만 되어 **렌더된 사이트 커맨드 페이지 내용이 변경 전과 동일**하다.
2. `11종` 카운트와 11개 커맨드 절은 카탈로그에 대해 **`docs/commands.md` 한 곳에만** 존재한다
   (사이트 셸·다른 수기 페이지는 카탈로그를 재선언하지 않는다).
3. 어떤 수기 사이트 페이지도 커맨드 카탈로그(역할·인자·산출물)를 재복제하지 않는다 — 세부는
   전부 `commands.md`로 교차 링크된다(튜토리얼/"왜" 산문은 유지).
4. `sh tests/discover/run.sh`와 `tests/discover/run.ps1`이 **둘 다 PASS(exit 0)**: 가드가
   `docs/commands.md`에서 개수(`${N}종`)와 **각 커맨드 이름**을 검사하고, `site/docs/commands.md`가
   스니펫 셸(재복제 아님)임을 검증한다. `run.ps1` 비ASCII 0·무BOM, Part A·타 하니스 불변.
5. `docs/conventions.md`·`docs/project-context.md`가 새 단일 원본(`docs/commands.md`)과 가드 강제를
   기록한다(버전 숫자 미복제).
6. **비파괴 확인**: 커맨드 11종 이름·역할 불변(2.0 stable 계약 유지), `.tide/phase`/tide-guard·보고서·
   마일스톤 형식 불변. mkdocs `check_paths`가 새 스니펫 경로를 통과(빌드 가능 상태).
