# M7 — tide 소개 GitHub Pages 사이트

## 목표

tide 저장소를 처음 접하는 사람이 웹에서 "무엇인지 → 어떻게 설치·시작하는지 → 각
커맨드가 무엇을 하는지"를 순서대로 읽고 바로 도입할 수 있는 한국어 문서 사이트가
GitHub Pages로 공개된다. 소스는 tide 자신의 사이클 기록(`docs/`)과 격리된 별도
폴더에 두고, `main`에 푸시하면 GitHub Actions가 자동으로 빌드·배포한다. 사이트
콘텐츠는 tide를 독립적인 워크플로우로 서술하며 외부 저장소(porpoise) 귀속 표현을
포함하지 않는다.

## 배경

v0.7.0까지 tide는 README·conventions·CHANGELOG로 충분히 문서화돼 있으나, 외부에
공개·소개할 수 있는 진입 페이지가 없다. 사용자가 "다음 버전으로 가기 전에 tide를
소개하는 GitHub 페이지를 만들고 싶다"고 요청했고, 사전 분석에서 다음이 확정됐다:

- **`docs/` 폴더 충돌**: GitHub Pages 네이티브(Jekyll, `/docs` 또는 루트) 방식은
  부적합하다 — `docs/`는 이미 마일스톤·impl/review·회고 보고서로 점유돼 있어, 여기를
  소스로 쓰면 내부 산출물이 전부 공개되고 빌드 충돌이 난다. 루트에는 플러그인
  매니페스트·스킬이 있어 역시 부적합. → **GitHub Actions로 별도 소스 폴더를 빌드해
  배포**하는 방식으로 결정.
- **SSG**: MkDocs Material(검색·내비·다크모드 내장, 한국어 지원 양호)로 결정.
- **porpoise 제외**: 저장소 전체에서 "porpoise" 언급은 2곳(`README.md:3`,
  `docs/conventions.md:3`)뿐이며 모두 *"tide는 porpoise의 방법론을 옮긴 것"*이라는
  출처 귀속이다. 사이트 콘텐츠에서는 이 귀속을 빼고 tide 자체 정의로 서술한다.
  **원본 저장소 파일(README·conventions)은 이 마일스톤에서 수정하지 않는다.**
- **진행 방식**: tide 자신의 M7 사이클로 도그푸딩한다.

## 태스크 상세

### M7-T01: MkDocs Material 프로젝트 골격 + GitHub Actions 배포 워크플로우

사이트 소스를 담을 별도 디렉터리를 만들고 MkDocs 프로젝트를 초기화한다.

- **레이아웃** (tide `docs/`와 충돌 회피):
  - `site/mkdocs.yml` — MkDocs 설정. `docs_dir: docs`(→ `site/docs/`), 빌드 출력은
    `site_dir: _build`로 **명시**해 MkDocs 기본 출력 폴더명(`site`)이 프로젝트 폴더명
    `site`와 겹치는 혼동을 제거한다.
  - `site/docs/` — 마크다운 소스가 들어갈 곳 (T02~T07이 채움). 이번 태스크에서는
    빌드가 통과하도록 `index.md` 자리표시자만 둔다.
  - `site/requirements.txt` — `mkdocs-material` 핀 (예: `mkdocs-material>=9,<10`).
- **mkdocs.yml 핵심 설정**:
  - `site_name: tide`, `site_description`, `theme: name: material`,
    `language: ko`(검색·UI 한국어), `palette`(라이트/다크 토글), `features`
    (navigation.sections, navigation.top, content.code.copy, search.suggest 등).
  - `repo_url: https://github.com/Jongh/tide`, `repo_name: Jongh/tide`.
  - `nav:`는 T08에서 최종 확정하되, 이번 태스크에서 6페이지 골격 경로를 미리 잡아둔다
    (홈·시작하기·개념·커맨드·규약·변경 이력). 자리표시자 단계라 일부 항목은 T08까지
    placeholder를 가리킬 수 있다.
- **배포 워크플로우** `.github/workflows/deploy-pages.yml`:
  - 트리거: `push`(branch `main`, `paths: ['site/**', '.github/workflows/deploy-pages.yml']`)
    + `workflow_dispatch`.
  - 권한: `pages: write`, `id-token: write`, `contents: read`.
  - 잡: `actions/checkout` → `actions/setup-python` → `pip install -r site/requirements.txt`
    → `mkdocs build -f site/mkdocs.yml` → `actions/upload-pages-artifact`(path `site/_build`)
    → `actions/deploy-pages`. 표준 GitHub Pages Actions 배포 패턴을 따른다.
  - `concurrency` 그룹으로 동시 배포 방지.
- **gitignore**: `site/_build/`(MkDocs 빌드 출력)를 `.gitignore`에 추가해 산출물을
  커밋하지 않는다.
- **불확실성/대체 경로**: GitHub Pages 소스를 "GitHub Actions"로 전환하는 것은 저장소
  설정(Settings → Pages)에서 한 번 해야 하며 코드로는 안 된다 → 이 수동 단계는
  완료보고서·릴리즈 안내에 "사용자가 1회 수행"으로 명시한다(코드 외 작업).

### M7-T02: 홈/개요 페이지 (deps: M7-T01)

`site/docs/index.md`. tide가 무엇인지 한 화면에 전달한다.

- 한 줄 정의: **"마일스톤 → 구현 → 리뷰 → 릴리즈 개발 사이클을 프로젝트 독립적인
  Claude Code 슬래시 커맨드로 구현한 워크플로우"** — porpoise 귀속 없이 tide 자체로
  서술(README.md:3·conventions.md:3의 "porpoise의 방법론을 옮긴" 표현을 쓰지 않는다).
- 사이클 다이어그램: README의 ASCII 다이어그램을 **Mermaid flowchart**로 재구성
  (kickoff→milestone→impl→review→release, cycle 묶음, status 읽기 전용). Material는
  Mermaid를 `pymdownx.superfences`로 지원하므로 mkdocs.yml에 해당 확장을 켠다(T01에서
  포함하거나 이 태스크에서 추가).
- 핵심 가치 3~4개 불릿(부수효과 분리, hook 강제, 프로젝트 독립성, 문서화 규율) +
  "시작하기/커맨드"로 이어지는 링크.

### M7-T03: 시작하기 페이지 — 설치 + 5분 워크스루 (deps: M7-T01)

`site/docs/getting-started.md`. README의 설치 절을 정제해 옮긴다.

- 설치: 플러그인(권장) `/plugin marketplace add Jongh/tide` → `/plugin install tide@tide`,
  Windows의 `sh`/Git for Windows 주의, 수동 복사(비권장·가드 미포함) 경고.
- 5분 워크스루: `/tide:kickoff` → `/tide:milestone` → `/tide:impl` → `/tide:review`
  → `/tide:release vX.Y.Z`를 짧은 예시 흐름으로. `/tide:status`로 위치 확인,
  `/tide:cycle`로 한 번에 체이닝하는 단축 경로도 소개.
- 마이그레이션 노트(≤v0.2.0, v0.3.0→v0.4.0)는 README에서 가져오되 접이식(admonition)로.

### M7-T04: 개념 페이지 (deps: M7-T01)

`site/docs/concepts.md`. conventions.md에서 "왜"에 해당하는 부분을 산문으로 정제.

- **부수효과 분리**: impl·review는 git 금지(코드·보고서만), commit/tag/push는 release만.
- **상태 파일 `.tide/phase`**: 단계명 한 줄, 각 스킬이 시작 시 기록·종료 시 idle 복원.
- **tide-guard hook**: release가 아니면 git commit/tag/push 차단(exit 2), 상태 파일
  없으면 무간섭, idle에서도 차단(의도된 동작) — 우회는 `.tide/phase` 삭제.
- **전제조건·프리플라이트** 표(conventions의 표 재사용).
- 규약 세부는 "규약" 페이지로 링크.

### M7-T05: 커맨드 레퍼런스 페이지 — 8종 (deps: M7-T01)

`site/docs/commands.md`. 각 커맨드의 역할·인자·산출물·전제조건을 표/소절로 정리.

- 출처: README 커맨드 표 + 각 `skills/{단계}/SKILL.md`의 frontmatter(description)와 본문
  요지. 8종: kickoff, milestone, impl, review, cycle, release, retro, status.
- 커맨드별: 한 줄 역할 / 인자(예: `/tide:impl [M번호]`, `/tide:release vX.Y.Z`) /
  산출물 / 전제조건·금지 행위 / 읽기 전용 여부.

### M7-T06: 규약 페이지 (deps: M7-T01)

`site/docs/conventions.md`. `docs/conventions.md`를 사이트용으로 옮긴다.

- **porpoise 귀속 제거**: conventions.md:3의 도입 문장을 tide 자체 정의로 리워딩.
- 마일스톤/보고서 형식, 버전·CHANGELOG 규칙, 단계별 금지 행위 표를 포함.
- 원본 `docs/conventions.md`는 수정하지 않고, 사이트용 사본을 만든다(내용 분기 시
  추후 단일화는 별도 후속으로 남긴다 — 미해결 메모 후보).

### M7-T07: 변경 이력 페이지 (deps: M7-T01)

`site/docs/changelog.md`. `CHANGELOG.md`(또는 README의 CHANGELOG 절) 내용을 옮긴다.
v0.1.0~v0.7.0 릴리즈 노트를 그대로 게시. 빌드 시 자동 동기화는 이번 범위에서 제외하고
수동 복사로 둔다(후속 메모 후보: CHANGELOG 자동 인클루드).

### M7-T08: 내비게이션 통합·로컬 빌드 검증·porpoise 잔재 최종 점검 (deps: M7-T01, M7-T02, M7-T03, M7-T04, M7-T05, M7-T06, M7-T07)

- `site/mkdocs.yml`의 `nav:`를 6페이지(홈·시작하기·개념·커맨드·규약·변경 이력)로
  최종 확정하고 자리표시자를 제거한다.
- 로컬 검증: `mkdocs build -f site/mkdocs.yml --strict`가 경고/깨진 링크 없이 통과하는지
  확인한다(완료보고서에 결과 기록). `--strict`로 내부 링크·nav 누락을 잡는다.
- **porpoise 잔재 점검**: `site/` 전체에 "porpoise"가 한 번도 등장하지 않음을 확인
  (`rg -i porpoise site/`가 0건). 원본 README·conventions는 변경되지 않았음도 확인.

## 완료 기준

1. `mkdocs build -f site/mkdocs.yml --strict`가 경고·깨진 링크 없이 성공한다.
2. 빌드된 사이트에 6개 페이지(홈·시작하기·개념·커맨드 레퍼런스·규약·변경 이력)가
   내비게이션에 모두 노출되고 상호 링크가 동작한다.
3. `site/` 트리 전체에서 "porpoise"가 0건이며(`rg -i porpoise site/`), 홈/규약 페이지의
   도입부가 tide 자체 정의로 서술돼 있다.
4. 원본 `README.md`·`docs/conventions.md`가 이 마일스톤에서 변경되지 않았다(git diff 무).
5. `.github/workflows/deploy-pages.yml`이 `main` 푸시(`site/**` 경로) 시 MkDocs를 빌드해
   `actions/deploy-pages`로 배포하도록 구성돼 있고, `site/_build/`가 `.gitignore`에 있다.
6. 완료보고서에 "GitHub 저장소 Settings → Pages 소스를 GitHub Actions로 1회 전환"이
   코드 외 수동 단계로 명시돼 있다.
