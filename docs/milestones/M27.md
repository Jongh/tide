# M27 — `pr` 모드 finalize 브랜치 정리 + M26 비차단 후속(sn1·sn2) 종결

## 목표

이 마일스톤이 끝나면 **`pr` 게시 모드의 머지 후 마무리(finalize)가 릴리즈 브랜치까지 스스로
정리**한다 — 머지된 기본 브랜치를 가져온 뒤 다 쓴 `release/v{버전}` 브랜치(로컬·원격)를 멱등·안전하게
거둬, 사이클마다 죽은 릴리즈 브랜치가 쌓이지 않는다. 동시에 M26 리뷰가 비차단 후속으로 남긴 두 건
(sn1 `site-includes` 용어 추출의 오추출-공허 green 여지, sn2 `multi-repo` fixture-BOM 취약성)과 그와
한 결인 **tide-guard 입력 견고화**(BOM 내성 + raw-`$input` grep)를 함께 닫아, 코드로 손볼 잔여
후속 백로그를 다시 0으로 되돌린다.

## 배경

- **출처(주 기능)**: 사용자 요구 — "`pr` 모드 종결 후 main 브랜치 가져올 때 기존 브랜치 정리". 현재
  `pr` 모드 finalize(`docs/conventions.md` "`pr` 모드" 절 / `skills/release/SKILL.md`)는 머지 결과로
  기본 브랜치를 최신화(`git fetch`→checkout/`pull`)하고 태그·릴리즈만 만든 뒤 **`release/v{버전}`
  브랜치를 그대로 남긴다**. PR 머지는 사람 몫이라 GitHub 측 원격 브랜치도 (auto-delete 미설정 시)
  남을 수 있어, 사이클을 거듭하면 죽은 릴리즈 브랜치가 누적된다.
- **출처(후속)**: `docs/reports/M26-review.md` "다음 단계" — 모두 비차단·차기 정리 사이클 후보로 명시:
  - **sn1**: `tests/site-includes`가 제외 용어를 마스트헤드에서 **런타임 추출**하는데, 마스트헤드
    표현이 바뀌어 엉뚱한 토큰을 뽑으면 그 토큰은 당연히 본문에 없어 스캔이 **공허하게 통과**한다
    (틀린 이유의 green). 추출 토큰이 마스트헤드에 **실재**함을 재확인하는 positive-control 한 줄로
    차단한다.
  - **sn2**: `tests/multi-repo/run.ps1`을 비-PowerShell 셸에서 돌리면 fixture JSON을
    `Set-Content -Encoding utf8`로 써 **BOM이 붙고**, PS 5.1 `ConvertFrom-Json`이 선두 BOM에서 throw해
    가드가 폴백→일부 시나리오가 뒤집힌다(제품 결함 아님·기존·M26 무관). 리뷰 권장은 **가드가 입력
    선두 BOM에 내성**을 갖도록(BOM strip 후 파싱)이며, 이는 기존 수용 항목 **tide-guard 입력 견고화**
    (M13 사소3→M18 사소6의 raw-`$input` grep 거칠음)와 같은 가드-하드닝 테마라 한 사이클로 묶는다.
- **기준 계약**: 2.0 stable 계약(커맨드 11종·오케스트레이션 규약·`.tide/phase`/tide-guard·보고서/
  마일스톤 형식)은 불변. 이번 변경은 `pr` 모드에 **국한된 가산**(finalize 정리 단계)과 가드 입력
  **견고화**(차단/통과 판정 계약 자체는 불변 — 단지 BOM 섞인 입력에서도 동일 판정을 내림)이다.
  새 `/tide` 커맨드·토큰은 더하지 않는다.

## 태스크 상세

### M27-T01: `pr` 모드 finalize에 릴리즈 브랜치 정리 단계 추가

- **변경 파일**: `docs/conventions.md`, `skills/release/SKILL.md`
- `docs/conventions.md` "`pr` 모드 (분기·상태 인지)" 절의 **merged → 마무리(finalize)** 항목에
  기존 ①최신화 ②버전 sanity ③태그 ④`gh release create` 뒤에 **⑤ 릴리즈 브랜치 정리**를 추가한다.
  finalize의 단일 원본은 이 절이므로 여기서 규약을 정의하고, 스킬은 이를 따른다.
- **정리 규약(멱등·안전 — 외부 대면이라 보수적으로)**:
  - **선행 조건**: ⑤는 ②~④가 성공해 finalize가 실제로 완료된 경우에만 수행한다(태그·릴리즈가
    이미 존재해 "보고만" 한 멱등 경로에서도 브랜치가 남아 있으면 정리 대상에 포함 — 정리는 태그/
    릴리즈 생성과 **독립 멱등**이다).
  - **현재 브랜치 안전**: 정리 전 이미 기본 브랜치(①에서 checkout)에 있어야 한다 — 삭제하려는
    `release/v{버전}`에 체크아웃된 상태면 삭제 불가하므로 기본 브랜치 체크아웃을 선행 보장한다.
  - **로컬**: `release/v{버전}` 로컬 브랜치가 존재하면 삭제한다. 머지가 기본 브랜치 머지 커밋으로
    확인됐으므로 `git branch -d`(머지 확인 삭제)를 먼저 시도하고, 머지 추적이 어긋나 `-d`가 거부되면
    **머지를 이미 `gh`로 확인했다는 전제**에서만 `-D`로 강제 삭제한다(미머지 강제삭제 금지 — 머지
    미확인이면 정리하지 말고 남긴다). 브랜치가 없으면 조용히 건너뛴다(멱등).
  - **원격**: 원격에 같은 브랜치가 있으면 `git push {remote} --delete release/v{버전}`로 지운다.
    이미 없으면(예: GitHub PR auto-delete) 건너뛴다 — "없음"을 오류로 보지 않는다(멱등).
  - **실패 비차단**: 브랜치 정리 실패(권한·보호 브랜치 등)는 **릴리즈 성공을 무르지 않는다** —
    태그·릴리즈는 이미 완료됐으므로, 정리 실패는 경고로 보고하고 수동 삭제를 안내한다(부분 실패가
    릴리즈를 되돌리지 않음).
- `skills/release/SKILL.md`의 `pr` 모드 finalize 서술(현 `git push {remote} v{버전}` →
  `gh release create` 뒤)에 "⑤ 릴리즈 브랜치 정리(규약 단일 원본 = conventions `pr` 모드 절)"를
  한 줄 가산하고, 멱등·비차단·현재 브랜치 안전 불변을 짧게 명시한다(규약 재서술이 아니라 포인터).
- **불변 유지**: 이 가산은 `pr` 모드 finalize에 **한정**된다 — `release` 모드·push-only·`gh` 부재
  경로, 생성/대기/중단 분기, tide-guard 계약은 불변. 정리는 phase=`release` 동안 수행(`git
  branch/push --delete`도 git 작업이므로 가드 계약 안에서 동작).

### M27-T02: sn1 — `site-includes` 용어 추출 positive-control 추가

- **변경 파일**: `tests/site-includes/run.sh`, `tests/site-includes/run.ps1`
- 현 하니스는 제외 용어를 마스트헤드(`README.md:3`·`docs/conventions.md:3`, 본문 마커 **밖**)에서
  런타임 추출하고 "추출 0개면 FAIL" 가드로 빈 스캔만 막는다. 여기에 **positive-control 단언**을
  추가한다: **추출한 토큰이 그 마스트헤드 영역(추출에 쓴 바로 그 줄/범위)에 literal로 실제 존재**
  하는지 재확인한다. 존재하지 않으면(= 추출 로직이 엉뚱한 토큰을 만들어냄) FAIL.
- 이로써 "마스트헤드 표현 변경 → 오추출 → 본문에 없어 공허하게 통과"(틀린 이유의 green) 모드를
  차단한다 — 스캐너가 **진짜 문자열**을 다룸을 보장.
- 양 셸(`run.sh`·`run.ps1`)에 **동일 의미**의 단언을 추가하고, PASS 카운트 증가를 헤더 주석/요약에
  반영한다. 인코딩 규율 유지(no-BOM·ASCII-only `.ps1`/`.sh`, 비-ASCII 소스 0 — KO 구절 필요 시
  코드포인트/바이트 구성).
- **엣지케이스**: 추출이 다중 토큰을 낼 수 있으면 각 토큰 모두에 대해 실재를 확인한다(현재는 정확히
  1개 추출이나, 단언은 1개 가정에 묶지 않는다).

### M27-T03: tide-guard 입력 견고화 — 선두 BOM 내성 + raw-`$input` grep 거칠음 해소

- **변경 파일**: `hooks/tide-guard.sh`, `hooks/tide-guard.ps1`, `docs/conventions.md`
- **BOM 내성**: 가드가 hook 입력(JSON)을 파싱하기 전에 **선두 UTF-8 BOM(`EF BB BF`)을 제거**한다.
  - `tide-guard.ps1`: `ConvertFrom-Json`(또는 현 추출 로직) **이전에** 입력 문자열 선두 BOM/제로폭을
    strip한다(PS 5.1 `ConvertFrom-Json`이 선두 BOM에서 throw하는 문제를 근본 차단). 기존
    `StripBom`(`tests/lib/encoding.ps1`)은 테스트 참조 구현이고 hook은 자기완결이어야 하므로, hook
    내부에 동등한 최소 strip을 직접 둔다(외부 source 금지 — hook은 단독 실행).
  - `tide-guard.sh`: 입력 선두 BOM에 동일하게 내성을 갖도록 strip(jq/grep 분기 양쪽에서 일관).
- **raw-`$input` grep 거칠음(M13 사소3→M18 사소6)**: jq 부재 시 fallback로 raw 입력을 grep해
  `cwd`/`tool_name`/phase를 추출하는 경로의 거칠음(따옴표·이스케이프·키 부분일치 오인 여지)을
  점검해 **오인 추출을 줄이도록** 패턴을 견고화한다(키 경계 앵커링 등). 단, **차단/통과 판정 계약
  자체는 불변** — 동일 입력에 동일 판정을 유지하면서 BOM·따옴표 변형에 견디게만 한다.
- **양 셸 동기화 불변**: `tide-guard.sh`(원본)·`tide-guard.ps1`(보조 사본)을 **함께** 갱신한다
  (project-context "가드 스크립트 수정 시 두 사본 함께").
- **규약 반영**: `docs/conventions.md`에 가드 입력 견고화 규약(선두 BOM strip·키 앵커링)을 단일
  원본으로 한 항목 추가하고, "규약↔실행/인프라 동기화" 원칙대로 같은 사이클에서 hook 양 사본이
  이를 반영함을 적는다. (이 절은 T01의 "`pr` 모드" 절과 **다른 절**이지만 같은 파일 —
  `conventions.md` 동시 편집이므로 T01과 병렬 시 겹침 폴백 대상.)
- **검증 포인트(impl이 충족)**: 선두 BOM이 붙은 입력에서도 `cwd`가 정상 추출되고 phase 판정이
  BOM 없는 입력과 **동일**함을 보인다(회귀 단언은 T04에서 multi-repo 하니스에 둔다).

### M27-T04: sn2 — `multi-repo` 하니스 fixture no-BOM 쓰기 + 가드 BOM-내성 회귀 단언 (deps: M27-T03)

- **변경 파일**: `tests/multi-repo/run.ps1`
- **fixture no-BOM**: `tests/multi-repo/run.ps1`이 가드 입력 fixture JSON을 쓸 때 PS 5.1
  `Set-Content -Encoding utf8`가 붙이는 BOM을 없앤다 — `[IO.File]::WriteAllText`(UTF8 no-BOM
  인코더) 또는 `-Encoding ascii`(fixture가 ASCII 전용이면)로 교체. 이로써 비-PS 셸에서 돌려도
  fixture에 BOM이 끼지 않아 하니스가 셸에 무관하게 견고해진다.
- **BOM-내성 회귀 단언**: T03의 가드 BOM 내성을 고정하는 회귀 케이스를 추가한다 — **선두 BOM이
  붙은** hook 입력 fixture를 일부러 만들어 가드에 넣고, BOM 없는 동일 입력과 **동일 판정**(차단/
  통과 + `cwd` 추출 동일)이 나오는지 단언한다. 이 케이스가 T03 이전엔 실패하고 이후엔 통과함으로써
  견고화를 증명한다.
- **양 셸 정합**: 의도된 실행(PowerShell)에서 multi-repo가 10/10을 유지하고, 신규 회귀 단언만큼
  카운트가 증가한다. `run.sh`도 같은 회귀 의미가 필요하면 동등 단언을 추가하되(셸 간 카운트 정합),
  sh 측은 BOM 입력 재현이 셸 특성상 다를 수 있으니 **가드 BOM strip의 셸-중립 동작**을 단언하는
  형태로 맞춘다(불가능하면 ps1 전용임을 헤더 주석에 명시).
- T03 완료 후 회귀 단언이 green이어야 하므로 deps.

1. **finalize 브랜치 정리**: `pr` 모드 finalize가 머지 확인·태그·릴리즈 후 `release/v{버전}` 로컬·

   경고로 보고한다. 현재 브랜치가 기본 브랜치임을 보장한 뒤 삭제하고, 미머지 강제삭제는 하지 않는다.
   규약 단일 원본은 conventions "`pr` 모드" 절이고 스킬은 포인터로 따른다. `release`/push-only/생성·
   대기·중단 분기는 불변.
2. **sn1**: `tests/site-includes`가 추출한 제외 용어가 마스트헤드 추출 영역에 literal로 실재함을
   양 셸에서 단언한다 — 추출이 엉뚱한 토큰을 내면 FAIL(오추출-공허 green 차단). PASS 카운트가 그만큼
   증가하고 양 셸 exit 0.
3. **가드 견고화**: 선두 UTF-8 BOM이 붙은 hook 입력에서도 가드가 `cwd`/phase를 정상 추출해 BOM 없는
   입력과 **동일 판정**을 내린다(`tide-guard.sh`·`tide-guard.ps1` 둘 다). raw-`$input` grep 경로의
   키 추출이 앵커링으로 견고해지되 판정 계약은 불변. 규약 단일 원본 한 항목 추가 + 양 사본 동기화.
4. **sn2**: `tests/multi-repo/run.ps1`이 fixture를 no-BOM으로 쓰고, 선두 BOM 입력에 대한 가드 BOM-내성
   회귀 단언이 추가돼 — T03 이전엔 실패하고 이후엔 통과한다. 의도된 PS 실행에서 multi-repo가 (신규
   단언 포함) 전부 통과, 양 셸 카운트 정합.
5. **문서 결산**: project-context 이월 원장에 sn1·sn2·가드 견고화 3행(처분=fix/M27)이 추가되고
