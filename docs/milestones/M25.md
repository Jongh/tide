# M25 — `pr` 모드 머지 후 마무리 자동화: 상태 인지 release로 태그·GitHub 릴리즈 핸드오프 종결

## 목표

이 마일스톤이 끝나면 **`pr` 모드 릴리즈가 PR 머지 후의 태그·GitHub 릴리즈까지 한 커맨드로 마무리**된다.
M24에서 `pr` 모드는 "PR 열림"까지만 하고 머지 후 태그/릴리즈를 사람이 수동으로 했는데, M25는 `pr` 모드를
**상태 인지**로 만들어 같은 `/tide:release v{버전} pr`를 머지 후 다시 실행하면 — 릴리즈 PR이 머지됐음을
감지해 **머지 커밋에 태그를 달고 push한 뒤 `gh release create`로 릴리즈를 생성**한다(버전 범프·CHANGELOG는
이미 머지됐으므로 건너뜀). PR이 아직 열려 있으면 부수효과 없이 "머지 후 다시 실행"을 안내하고, 릴리즈 PR이
없으면 종전대로 새 PR을 연다. 태그·릴리즈가 이미 있으면 중복 생성하지 않는다(멱등).

## 배경

- **출처**: M24(v2.3.0) 리뷰 비차단 후속 **sn2** + 사용자 지시("pr 머지 후 태그/릴리즈 핸드오프 자동화",
  2026-06-17). M24-review "다음 단계"가 `pr` 머지 후 마무리 자동화를 차기 후보로 명시했다.
- **현재 갭(M24)**: `docs/conventions.md` "릴리즈 게시 (gh)"의 `pr` 모드는 릴리즈 브랜치 commit→push→
  `gh pr create`로 **"PR 열림"까지만** 하고, "**태그·GitHub 릴리즈는 PR 머지 후로 미룬다(PR 머지는 사람
  몫)**"고 핸드오프한다. 그래서 머지 후 사용자가 직접 `git tag`·`git push tag`·`gh release create`를 해야
  하는데, 이 마무리 단계가 자동화되지 않아 `release` 모드 대비 한 번에 끝나지 않는다.
- **해결 방향 — 상태 인지 `pr` 모드(같은 토큰, PR 상태로 분기)**: 새 커맨드·토큰을 늘리지 않고 `pr` 모드를
  **재실행 가능한 상태 인지**로 만든다. `gh`로 릴리즈 PR(브랜치 `release/v{버전}` 또는 제목 `Release
  v{버전}`)의 상태를 조회해:
  - **merged** → **마무리(finalize)**: 기본 브랜치를 최신화하고 머지 결과에 태그·push·`gh release create`.
  - **open** → 부수효과 없이 PR URL·"머지 후 다시 실행" 안내(대기).
  - **closed(미머지)** → 보고하고 중단(임의 진행 금지).
  - **없음** → 종전 M24 동작(릴리즈 브랜치 + 새 PR 생성).
  이 분기는 **버전 범프·CHANGELOG 편집 전**(M24 "검증을 부수효과 전에" 원칙)에 결정해, finalize 경로가
  이미 머지된 버전 파일·CHANGELOG를 다시 건드리지 않게 한다.
- **멱등·안전이 핵심**: 머지 후 마무리는 외부 대면(태그 push·릴리즈 공개)이라, ① 머지 사실을 `gh`로 확인한
  뒤에만 태그를 달고(미머지 PR에 태그 금지), ② 태그 `v{버전}`·릴리즈가 이미 있으면 중복 생성하지 않고
  보고하며(M24 수동 핸드오프로 이미 마친 경우 안전), ③ 머지된 기본 브랜치의 버전 파일이 `v{버전}`과
  일치하는지 sanity 확인한다(엉뚱한 머지에 태그 방지).
- **비파괴·하위호환**: `pr` 모드만 영향받는 옵트인 가산이다. `release` 모드·push-only·`gh` 부재 경로는
  **전부 불변**(특히 `gh` 부재 시 바이트 동일). 2.0 stable 계약(11종 커맨드 호출명·역할·오케스트레이션
  규약·`.tide/phase`/tide-guard·보고서·마일스톤 형식)·M22 드리프트 가드(discover B1/B2/B3)·M24 검증
  게이트·tide-guard 비확장(가드는 git 토큰만 차단, `gh` 비게이트) 전부 불변. 커맨드 수 11종 유지
  (`/tide:release` 안의 `pr` 모드 동작 확장일 뿐 새 커맨드·토큰 아님).
- **검증 한계(사전 인지)**: `pr` finalize는 `gh`·실제 머지 상태에 의존하는 프롬프트 스킬 로직이라 자기완결형
  라이브 하니스로 덮을 수 없다(M24 sn1과 동질). 검증은 정적 검토(conventions↔SKILL 정합·상태 분기·멱등)
  + 다음 `pr` 모드 도그푸딩 라이브 회수로 한다.

## 태스크 상세

### M25-T01: `pr` 모드 상태 인지 + 마무리(finalize) 규약 (단일 원본)

- **변경 파일**: `docs/conventions.md`
- "릴리즈 게시 (gh)"의 `### `pr` 모드 (분기)` 절을 확장한다. `pr` 모드는 **재실행 가능한 상태 인지**임을
  명시하고, 진입 시 (M24 검증 게이트 통과 후, **버전 범프·CHANGELOG 편집 전에**) 릴리즈 PR 상태를
  `gh`로 조회해 분기함을 규정한다:
  - **PR 식별**: 브랜치 `release/v{버전}`(또는 제목 `Release v{버전}`)의 PR을 `gh pr view`/`gh pr list`로
    조회한다. 버전은 인자로 받는다(머지 후 finalize는 `/tide:release v{버전} pr`로 명시 호출).
  - **merged → 마무리(finalize)**: ① 기본 브랜치를 원격 머지 결과로 최신화(`git fetch` 후 기본 브랜치
    checkout·`git pull` 또는 fast-forward), ② **sanity**: 머지된 기본 브랜치의 버전 파일이 `v{버전}`과
    일치하는지 확인(불일치면 중단·보고 — 엉뚱한 머지에 태그 방지), ③ 태그 `v{버전}`을 머지된 tip에 달고
    `git push {remote} v{버전}`, ④ `gh release create v{버전}`(노트 = CHANGELOG 발췌, 제외 용어 규약 준수).
  - **open → 대기**: 부수효과 없이 PR URL과 "머지 후 같은 명령을 다시 실행하면 태그·릴리즈로 마무리"를
    안내한다(태그·릴리즈·push 없음).
  - **closed(미머지) → 중단**: PR이 머지 없이 닫혔음을 보고하고 중단한다(임의 재생성·태그 금지).
  - **없음 → 생성**: 종전 M24 동작(릴리즈 브랜치 commit→push→`gh pr create`). 기존 "릴리즈 브랜치 충돌"
    규칙 유지.
- **멱등·안전 규정**: ① **미머지 PR에 태그 금지**(merged 확인 후에만 태그). ② 태그 `v{버전}` 또는 릴리즈가
  **이미 존재하면 중복 생성하지 않고 보고**(M24 수동 핸드오프로 마친 경우 안전 — `git tag`/`gh release view`로
  선확인). ③ finalize는 **버전 범프·CHANGELOG를 건너뛴다**(머지로 이미 기본 브랜치에 반영됨 — 재편집 금지).
- **불변 명시**: 이 확장은 `pr` 모드에 한정되며 `release` 모드·push-only·`gh` 부재 경로는 불변. tide-guard
  비확장·"게시는 release에서만"(phase=release) 불변 유지.

### M25-T02: `skills/release/SKILL.md` `pr` 모드 상태 인지 구현 (deps: M25-T01)

- **변경 파일**: `skills/release/SKILL.md`
- M24의 게시 분기 중 **`pr` 모드** 항목을 상태 인지로 교체한다. 절차는 재서술하지 말고 `docs/conventions.md`
  "릴리즈 게시 (gh)"의 확장된 `pr` 모드 절을 참조한다(스킬=절차, 규약=conventions 분담 유지). 요지를 단계로:
  - mode=`pr` 해석·M24 검증 게이트 통과 후, **버전 범프·CHANGELOG(2·3단계) 전에** 릴리즈 PR 상태를 조회한다.
  - **merged**: 기본 브랜치 최신화 → 버전 파일 sanity(`v{버전}` 일치) → 태그·push tag → `gh release create`.
    태그·릴리즈 기존재 시 중복 생성 없이 보고. **이 경로는 버전 범프·CHANGELOG 단계를 건너뛴다.**
  - **open**: PR URL·"머지 후 재실행" 안내 후 부수효과 없이 종료(태그/릴리즈/push 없음).
  - **closed(미머지)**: 보고 후 중단.
  - **없음**: 버전 범프(2)·CHANGELOG(3)·릴리즈 브랜치 commit→push→`gh pr create`(M24 생성 경로 그대로).
- **운영 주의 보강**: 기존 gh 항목(5번)에 한 줄 — `pr` finalize의 태그·`gh release create`도 phase=release
  에서만 실행하고, 머지 확인(`gh pr` merged) 전에는 태그를 달지 않는다(미머지 태그 금지·멱등 보고).
- **엣지**: 버전 인자가 없을 때 — 열린/머지된 릴리즈 PR이 유일하면 그 버전으로 추론하되, 모호하면(여러 후보)
  버전 명시를 요청하고 중단(임의 선택 금지).

## 완료 기준

1. `pr` 모드 릴리즈 PR이 **머지된 뒤** `/tide:release v{버전} pr`를 다시 실행하면 — 기본 브랜치를 최신화하고
   머지된 tip에 태그 `v{버전}`을 달아 push한 뒤 `gh release create v{버전}`으로 릴리즈를 생성한다(버전 범프·
   CHANGELOG는 건너뜀). 한 커맨드로 `pr` 릴리즈가 종결된다.
2. **상태 분기**: 릴리즈 PR이 **open이면** 부수효과 없이 PR URL·"머지 후 재실행" 안내, **closed(미머지)면**
   보고 후 중단, **없으면** 종전 M24 동작(새 릴리즈 브랜치+PR 생성)으로 동작한다.
3. **멱등·안전**: 미머지 PR에는 태그를 달지 않고, 태그 `v{버전}`·릴리즈가 이미 있으면 중복 생성 없이 보고하며,
   머지된 기본 브랜치의 버전 파일이 `v{버전}`과 다르면 태그 없이 중단한다(엉뚱한 머지 방지).
4. `docs/conventions.md` "릴리즈 게시 (gh)"의 `pr` 모드 절이 상태 인지(merged/open/closed/none)·finalize·
   멱등을 **단일 원본**으로 규정하고, `skills/release/SKILL.md`는 그 절을 참조해 절차로 구현한다(재서술 아님).
5. **불변 확인**: `release` 모드·push-only·`gh` 부재 경로는 불변(특히 `gh` 부재 시 바이트 동일). M24 검증
   게이트·tide-guard 비확장(`gh` 비게이트)·"게시는 release에서만" 유지. finalize의 태그·`gh` 호출은
   phase=release에서만.
6. `docs/commands.md`가 `pr` 모드 마무리를 반영하되 **커맨드 11종·셸·이름 가드(B1/B2/B3) 불변**,
   `docs/project-context.md`가 `pr` 상태 인지 마무리를 기록한다(버전 숫자 미복제). `tests/discover`·`tests/fleet`
   계열 라이브 하니스 동일 통과(19·41·23·29·10, FAIL 0).
7. **비파괴 확인**: 2.0 stable 계약(11종 커맨드 호출명·역할·오케스트레이션 규약·`.tide/phase`/tide-guard·
   보고서·마일스톤 형식) 불변. `pr` 모드 마무리는 옵트인 가산.
