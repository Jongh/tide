# discover 라이브 실증 (tests/discover)

M21 **오케스트레이션 발견성**의 **결정적 핵심**과, 그와 같은 부류인 **선언 드리프트**를 재현 가능하게
검증하는 하니스다 — ① status·kickoff의 **멀티 레포 맥락 감지 힌트**(임계값 ≥2 → hint|none),
② **커맨드 수 드리프트 가드**(`skills/*/SKILL.md` 실제 개수 == 캐노니컬 문서·사이트의 "N종" 선언),
③ **선언 정합 드리프트 가드**(M30 — debug 항목 상태값 집합 · 변경 파일 요약 기준선),
④ **브랜치 간 협업 안전 선언 정합**(M31 — 릴리즈 커버리지 체크 · 마일스톤 번호 사전경고),
⑤ **리뷰 검증 규율 선언 정합**(M32 — 반증 시도 · 판정 계측 · 재작업 라운드 · 재검증),
⑥ **문서 자기서술 정합**(M33 — 이 파일의 케이스 수 선언 · 커맨드 역할 앵커 전파),
⑦ **상호참조 무결성**(M34 · M35 — 살아 있는 문서의 인용이 **그 줄이 가리킨 규약 파일**의 실재 앵커를
가리키는지, 규약 문서 **집합** 기준).

**현재 케이스 수 (cases: 68)** — Part A 7 + Part B 14 + Part C 10 + Part D 7 + Part E 10 + Part F 14 + Part G 6.
`.sh`·`.ps1` 동일, FAIL 0.

> 이 한 줄이 **케이스 수의 유일한 선언처**다(규약: `docs/conventions.md`의 "문서 자기서술 정합").
> 러너가 `cases` 토큰으로 이 값을 **추출해 자기 실제 케이스 수와 대조**하므로(Part F의 F1),
> 케이스를 더하거나 빼고 이 줄을 안 고치면 **양 셸이 FAIL한다**. 다른 문서는 이 수를 옮겨 적지
> 않는다 — 옮겨 적는 순간 두 번째 선언처가 생긴다.

## 무엇을 검증하나 (그리고 왜 참조 구현인가)

감지 힌트는 status·kickoff **프롬프트 스킬**의 행위라 실행 바이너리가 없다(직접 호출할 `.sh`가
없다). 따라서 이 러너는 그 스킬이 인용하는 **결정적 규약**(fleet **발견** 규약 재사용 + 감지
**임계값** ≥2 판정)을 **동일 로직의 참조 셸 절차**로 재현해 픽스처에 대해 검증한다. 단일 원본은
`docs/conventions.md`의 "멀티 레포 오케스트레이션"(발견) 절 + 발견성 힌트 항목이며, 이 러너는
그 결정적 동작을 **회귀로 고정**한다.

> 스킬 프롬프트의 LLM 서술(advisory 한 줄 문구 등)은 스크립트로 100% 강제되지 않는다 —
> **결정적 핵심**(발견·임계값)만 스크립트로 덮고, **advisory 서술 품질**은 아래 세션 레벨 수동
> 절차로 분리한다(tests/fleet와 동일 분리).

### Part A — 감지 임계값 (sh·ps1 동일, 7 케이스)

fleet 발견 참조 구현(직속 1단계·git 레포 AND tide 산출물·숨김 `.`-디렉터리 제외)을 재사용한
`detect_hint`/`DetectHint`가 자식 tide 레포 수를 세어 **≥2면 `hint N=<count>`**, **<2면 `none`**을
낸다. 픽스처별 기대:

| 부모 픽스처 | 구성 | 기대 감지 |
|---|---|---|
| `parent2` | 자식 tide 레포 **2개**(`svc-auth`·`svc-orders`) | **hint** (N=2) |
| `parent1` | 자식 tide 레포 **1개**(`only-svc`) | **none** |
| `parent0` | 자식 tide 레포 **0개**(비-tide 폴더만) | **none** |
| `single-repo` | **단일 레포 루트** — 직속 자식이 `src/`·`docs/` 등 비-tide | **none** (일반 단일 레포 세션) |
| `parenthidden` | 자식 tide 레포 **2개**(`svc-a`·`svc-b`) + **숨김** tide 자식 `.hidden-svc` | **hint** (N=2 — 숨김 미카운트) |

검증: ① 2개→hint N=2, ② 1개→none, ③ 0개→none, ④ 단일 레포 루트→none(소음 0), ⑤ 숨김
자식이 있어도 카운트에서 제외돼 hint N=2, ⑥ 숨김 자식 미발견, ⑦ 발견 집합은 `svc-a,svc-b`.

### Part B — 커맨드 수 드리프트 가드 (sh·ps1 동일, 14 케이스)

실제 커맨드 스킬 개수 `N = skills/*/SKILL.md 파일 수`(현재 12)를 세고, 캐노니컬 선언 위치가 같은
수 **"N종"**(예: `12종`)을 선언하는지 grep 결합 검증한다(불일치면 FAIL — M18~M20 SKILL-artifact
결합 패턴). 레포 루트는 스크립트 위치(`$(dirname "$0")/../..`)에서 해석한다.

| 캐노니컬 선언 위치 | 검증 |
|---|---|
| `docs/commands.md` | `${N}종` 선언 존재 (캐노니컬 카탈로그) · 모든 `/tide:<이름>` 등장 |
| `README.md` | `${N}종` 선언 존재 |
| `docs/conventions.md` | `${N}종` 선언 존재 |
| `site/docs/getting-started.md` | `${N}종` 선언 존재 |
| `docs/orchestration.md` | `${N}종` 선언 존재 (M32에서 편입 — 사이트 본문으로 인클루드되는데 `11종`으로 낡아 있었다) |
| `site/docs/commands.md` | **스니펫 셸** — 인클루드 보유 AND 카운트·카탈로그 표 미재선언 |

검증: 실제 스킬 수 측정(>0) 1 + **B1** 카운트 선언 5 + **B2** 사이트 셸 1 + **B3** 카탈로그
완전성 1 + **B3 이름 통제**(`/tide:bogus` 부재) 1 + **B1 드리프트 음성 통제** 5(실제와 다른 수
`${N+1}종`이 어느 캐노니컬 파일에도 없음) = **14**. 이 가드는 M20 리뷰 #6(사이트 8종↔11종 표류)의
회귀 고정이다 — 커맨드를 더/빼면서 선언 수를 안 고치면 양 셸 모두 실패한다. M22에서 카탈로그가
`docs/commands.md` 단일 원본으로 옮겨져 `site/docs/commands.md`는 **카운트 선언처가 아니라 셸**이다.

### Part C — 선언 정합 드리프트 가드 (sh·ps1 동일, 10 케이스)

Part B가 집행하는 것은 결국 **"같은 사실을 여러 문서가 선언할 때의 드리프트"**(커맨드 수)다. 아래
둘은 정확히 같은 부류라 같은 하니스에 둔다 — 여러 파일이 같은 사실을 선언하고, **한 곳만 고치면
조용히 갈라진다**.
단일 원본은 `docs/conventions.md`의 "debug 세션"(항목 상태값)·"변경 파일 요약 기준선" 절이며,
이 러너는 **선언의 존재**를 결합 조건으로 고정한다(문구 품질이 아니다).

**C-1. debug 항목 상태값 집합** — 네 값(`수정함`·`미해결`·`원인만 규명`·`확인함`)이 **세 파일 전부**에
등장한다(M30에서 `확인함`이 가산되며 갈라질 위험이 실재했다).

| 선언 위치 | 검증 |
|---|---|
| `docs/conventions.md` | 네 상태값 전부 등장 · `보류함` **부재** |
| `skills/debug/SKILL.md` | 네 상태값 전부 등장 · `보류함` **부재** |
| `skills/debug/template.md` | 네 상태값 전부 등장 · `보류함` **부재** |

**C-2. 변경 파일 요약 기준선** — 같은 추가/수정/삭제 표를 쓰는 **세 템플릿 전부**가 기준선을
명시한다(한 템플릿만 고치면 표의 의미가 파일마다 갈라진다 — 그 자체가 드리프트).

| 템플릿 | 검증 |
|---|---|
| `skills/milestone/template.md` | `기준선` 선언 존재 |
| `skills/impl/template.md` | `기준선` 선언 존재 |
| `skills/debug/template.md` | `기준선` 선언 존재 |

검증: **C1 양성** 4(네 상태값 × 세 파일 결합) + **C1 음성 통제** 3(존재하지 않는 상태값 `보류함`이
세 파일 **어디에도** 없음) + **C2** 3(기준선 × 세 템플릿) = **10**. 음성 통제는 Part B의 `${N+1}종`
부재 통제와 **동일 취지**다 — 통제가 없으면 grep이 죽어도 green이 된다(가드의 구별력 입증).

### Part D — 브랜치 간 협업 안전 선언 정합 (M31, sh·ps1 동일, 7 케이스)

Part C와 같은 부류를 **규약↔스킬** 축으로 집행한다. 두 검사(릴리즈 커버리지 체크·마일스톤 번호
사전경고)의 **런타임 발화**는 프롬프트 규율이라 하니스로 못 덮지만, **선언 정합**은 결정적으로
고정된다. 앵커는 ASCII 메커니즘 토큰(git 읽기 명령)이라 ps1의 ASCII-only 원본 규율과 정합한다.

| 검사 | 앵커 토큰 | 결합 |
|---|---|---|
| D1 릴리즈 커버리지 체크 | `git diff --name-only` | `docs/conventions.md` ↔ `skills/release/SKILL.md` |
| D2 마일스톤 번호 사전경고 | `git log --all` | `docs/conventions.md` ↔ `skills/milestone/SKILL.md` |

검증: D1 2 + D2 2 + **교차 통제** 2(각 토큰이 반대 스킬에 **없음**) + **음성 통제** 1(가짜 토큰
`git diff --bogus-only` 부재) = **7**.

### Part E — 리뷰 검증 규율 선언 정합 (M32, sh·ps1 동일, 10 케이스)

`/tide:review`가 판정을 만들어내는 절차(단일 원본: conventions "리뷰 검증 규율")를 **규약↔스킬↔
템플릿** 3축으로 결합한다. 토큰은 전부 **ASCII 병기어**다.

| 검사 | 앵커 | 결합 |
|---|---|---|
| E1 반증 시도 | `refutation` | conventions ↔ review SKILL |
| E2 판정 계측 | `in-review` | conventions ↔ review SKILL ↔ review 템플릿 |
| E3 재작업 라운드 | `rework` | conventions ↔ review 템플릿 ↔ impl 템플릿 |
| E4 계측 줄 **형식** | `in-review` … `(rework)` **같은 한 줄** | 세 파일 각각 |
| E5 재검증 선언 | `re-verify` | conventions ↔ review SKILL ↔ review 템플릿 |

검증: E1 1 + E2 1 + E3 1 + E4 3 + E5 1 + **교차 통제** 2(impl 템플릿에 반증 토큰·계측 줄 골격
부재) + **음성 통제** 1 = **10**. E4·E5는 M32 리뷰가 적발한 **공허 통과**를 닫은 단언이다 —
토큰 존재만 보던 E1~E3는 계측 줄 이형(`(rework)` 병기 누락)을 통과시켰고, `in-review`가 계측 줄과
재검증 절에 **이중 용도**라 재검증 절을 통째로 지워도 green이었다.

### Part F — 문서 자기서술 정합 (M33, sh·ps1 동일, 14 케이스)

Part B~E가 **여러 문서가 같은 사실을 선언할 때**의 드리프트를 집행한다면, Part F는 문서가
**자기 자신에 대해 하는 서술**을 집행한다.
단일 원본은 `docs/conventions.md`의 "문서 자기서술 정합" 절.

**F-2. 역할 앵커 전파** — 캐노니컬 `docs/commands.md`의 주석 한 줄
`<!-- role-anchors: name=token … -->`에서 앵커를 **추출**해, ① 그 커맨드의 **캐노니컬 표 행**에
앵커가 실재하는지 ② 소비자 문서(`README.md`·`site/docs/getting-started.md`)가 그 커맨드를
**언급하면** 앵커도 있는지 검사한다. 언급하지 않는 문서는 대상이 아니다(소음 0). 스크립트에 한글
리터럴을 두지 않는 **데이터 기반** 검사라 ps1 ASCII-only 규율과 정합한다(`tests/site-includes`의
용어 추출과 동형). 앵커는 **영문·하이픈 경계**로 찾는다 — 짧은 앵커(`gh`)가 다른 단어 안에 우연히
걸리지 않도록.

**F-3. 통제** — 추출 0건이면 **FAIL**(positive-control: 루프가 통째로 공허 통과하는 것을 차단),
앵커 맵의 이름이 전부 실제 커맨드 스킬인지, 가짜 앵커(`bogusanchor`) 부재.

**F-1. 케이스 수 자기 정합** — 이 README 맨 위 `cases` 선언과 러너의 **실제 케이스 수**를
대조한다. F1 자신도 한 케이스라 계수가 순환하므로 **F1을 마지막 케이스로 두고 `누계 + 1`과
비교**하는 경로를 택했다(러너 주석에도 같은 문장이 있다). 추출 실패(선언 부재·골격 이형)는 조용한
skip이 아니라 **FAIL**이다.

**F-1b. 파트별 내역 합 정합** — F1은 **총계**만 본다. 총계를 고치면서 같은 줄의 파트별 내역을 안
고치면 한 겹 아래에서 조용히 갈라지므로, 내역의 합이 총계 선언과 같은지 함께 확인한다(내역도 ASCII
골격이라 양 셸이 같은 방식으로 합산한다). 합산 범위는 **선언 줄 한 줄**이다 — 파일 전체를 훑으면
이 문서 산문에 인용된 같은 골격까지 더해진다(리뷰 중 실제로 그렇게 걸렸다).

검증: F2 3(앵커 수) × 3(캐노니컬 행 + 소비자 2) = 9 + F3 3 + F1b 1 + F1 1 = **14**.

### Part G — 상호참조 무결성 (M34 · M35에서 파일 집합으로 일반화, sh·ps1 동일, 6 케이스)

Part F가 문서의 **자기서술**을 집행한다면 Part G는 문서 **사이를 잇는 참조**를 집행한다. 단일 원본은
`docs/conventions.md`의 "상호참조 무결성" 절.

**G-0. 규약 문서 집합 발견** — 규약은 한 파일이 아니라 **문서 집합**이다(본체 + `docs/conventions-{주제}.md`
조각). 그래서 대조 대상을 글롭 `docs/conventions*.md`로 **발견**한다 — 러너에 목록을 하드코딩하지
않으므로 조각을 더해도 러너를 고칠 일이 없다(하드코딩 금지가 이 규약의 요점이다). 순회 순서는 양 셸이
같도록 고정한다(sh는 `LC_ALL=C sort`, ps1은 ordinal 정렬). 조각이 하나도 없으면 집합은 본체 하나뿐이라
일반화 **이전과 같은 판정**이 나온다(M35 회귀 고정).

**G-1. 인용 → 앵커 실재(파일별 대조)** — 살아 있는 문서(`skills/*/*.md`·`docs/*.md`·`README.md`·
`site/docs/*.md`·`tests/*/README.md`)에서 **인용 골격**(규약 파일명이 든 줄의 따옴표 구획)을 **추출**해,
**그 줄에 등장한 규약 파일**의 `##`·`###` 제목 집합에 **전부 실재**하는지 단언한다. 앵커는 **파일별로**
묶여 있으므로, 절이 조각으로 옮겨 가면 인용도 **그 조각의 파일명**을 가리켜야 통과한다 — 파일을 옮기고
인용을 안 고치면 잡힌다(이 일반화의 핵심 가치). 한 줄에 규약 파일명이 둘이면 **어느 쪽 앵커 집합에든
있으면 통과**로 본다(안전 측 — 오탐을 만들지 않는다). 대조 전 **공백만 제거**해 정규화한다
(`버전·CHANGELOG` ≡ `버전 · CHANGELOG`). 두 가지는 인용이 아니라 제외한다 — **스니펫 인클루드
지시어 줄**(`8<--`)과 **중괄호가 든 따옴표**(골격 예시의 자리표). `docs/milestones/*`·`docs/reports/*`는
역사 기록이라 대상이 아니다(`docs/*.md` 글롭이 하위 디렉터리를 잡지 않아 자연히 제외된다).

**G-2. 통제** — 인용 추출 0건·앵커 추출 0건이면 **FAIL**(루프가 통째로 공허 통과하는 것을 차단,
F3·M27 positive-control 선례), 가짜 이름(`bogus-section`)이 **집합 어디에도** 없음, `##`·`###` 제목이
정규화 후 **집합 전체에서 유일**(중복 0 — 파일이 갈려도 같은 이름을 두 곳에 두지 않는다. 겹친 이름을
가리키는 인용은 어느 쪽인지 결정할 수 없다).

스크립트에 한글 리터럴을 두지 않는 **데이터 기반** 검사라 ps1의 ASCII-only 규율과 정합한다.
PowerShell의 `-contains`·해시테이블 키는 기본이 **대소문자 무시**라 `grep -x`와 갈리므로,
`HashSet[string]`(ordinal)로 맞춰 양 셸이 같은 판정을 내리게 했다 — 파일별 앵커 집합도 파일마다
`HashSet[string]` 하나씩(sh는 파일별 앵커 파일 하나씩)이고, 파일 키는 **인덱스**다(파일명에 공백이
들어도 레코드가 깨지지 않도록).

**G-3. 줄바꿈 인용 통제** — 후보 줄의 따옴표가 **미종결**(홀수)이면 인용이 다음 줄로 넘어간 것이고,
줄 단위 추출에서 **조용히 빠진다**. 그런 줄이 0이어야 통과한다(= 인용은 **한 줄 안에** 쓴다).

> **알려진 잔여 한계**: G3는 줄바꿈이 **따옴표 구획 안**에서 일어난 경우만 잡는다. 파일명은 앞 줄에,
> 따옴표 구획은 **통째로 다음 줄**에 오는 형태는 후보 줄의 따옴표 수가 짝수(0)라 잡히지 않는다 —
> 파일명만 언급하는 정상 줄과 구별할 수 없기 때문이다(그런 줄을 FAIL로 두면 경로를 언급하는 모든
> 문장이 걸린다). 인용을 한 줄에 쓰는 규율이 1차이고 G3는 그 백스톱이다.

검증: G1 1 + G2 4(인용 추출·앵커 추출 positive-control, 가짜 이름 부재, **집합 전체** 이름 유일성) +
G3 1 = **6**. M35의 일반화는 Part G **내부 구현**만 바꾼 것이라 케이스 수는 그대로다.

## 실행

```sh
sh tests/discover/run.sh       # POSIX / Git Bash
```
```powershell
& tests\discover\run.ps1       # Windows PowerShell (.ps1 사본)
```

각 러너는 전부 통과 시 exit 0, 하나라도 실패 시 exit 1(양 셸 동일 판정, FAIL 0). 케이스 수는
맨 위 `cases` 선언 **한 곳**에만 적는다 — 여기 다시 적으면 같은 파일 안에 두 번째 선언처가
생기고, F1이 집행하는 것은 그 첫 선언이다.
픽스처 자식 레포는 `git init`만 하면 되고 **commit은 불필요**하다(발견은 디렉터리·산출물 존재만 본다).

> **활성 가드 주의**: git 차단 동사(commit/tag/push)는 이 러너에 등장하지 않는다(셋업은 init만
> 사용). 러너를 호출하는 명령줄에도 차단 패턴이 없어야 활성 tide-guard가 막지 않는다.
> `run.ps1`은 ASCII 소스 + 한글 토큰을 **코드포인트로 구성**해 BOM 의존을 없앤다(인코딩 규약) —
> 카운터 `종`(U+C885)에 더해 Part C의 상태값·`기준선` 토큰도 `Uni` 헬퍼로 조립한다. 헬퍼 이름이
> `Cp`가 **아닌** 이유: `Cp`는 `Copy-Item`의 빌트인 별칭이고 PowerShell은 별칭을 함수보다 먼저
> 해석해 토큰이 조용히 빈 문자열이 된다(공허 green). `run.sh`는 무BOM이다.

## 자동화로 못 덮는 부분 — 세션 레벨 수동 절차

감지 힌트의 **서술**(advisory 한 줄 `여러 자식 tide 레포 N개 감지 — 교차 개요는 /tide:fleet`을
status·kickoff 출력 맨 끝에 붙이는 LLM 행위)은 스크립트로 강제되지 않는다. 상위 폴더 단일
세션에서 다음을 수동 확인한다:

1. 자식 tide 레포 2개 이상을 둔 상위 폴더에서 세션을 띄우고 `/tide:status`(또는 `/tide:kickoff`)를
   호출한다.
2. 본래 보고 끝에 `여러 자식 tide 레포 N개 감지 — 교차 개요는 /tide:fleet` 한 줄이 advisory로
   붙고, status는 **완전 읽기 전용**(파일·git·phase 무변경), kickoff는 골격 생성 외 동작 불변임을
   확인한다.
3. 자식 tide 레포가 2개 미만(단일 레포 세션 포함)인 폴더에서 호출하면 **그 줄이 붙지 않음**(소음 0,
   기존 출력 바이트 동일)을 확인한다.

상세 규약은 `docs/conventions.md`의 "멀티 레포 오케스트레이션"(발견) 절 + 발견성 힌트 항목이
단일 원본이다.
