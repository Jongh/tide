# discover 라이브 실증 (tests/discover)

M21 **오케스트레이션 발견성**의 **결정적 핵심**과, 그와 같은 부류인 **선언 드리프트**를 재현 가능하게
검증하는 하니스다 — ① status·kickoff의 **멀티 레포 맥락 감지 힌트**(임계값 ≥2 → hint|none),
② **커맨드 수 드리프트 가드**(`skills/*/SKILL.md` 실제 개수 == 캐노니컬 문서·사이트의 "N종" 선언),
③ **선언 정합 드리프트 가드**(M30 — debug 항목 상태값 집합 · 변경 파일 요약 기준선),
④ **브랜치 간 협업 안전 선언 정합**(M31 — 릴리즈 커버리지 체크 · 마일스톤 번호 사전경고),
⑤ **리뷰 검증 규율 선언 정합**(M32 · M36 · M44 — 반증 시도 · 판정 계측 · 재작업 라운드 · 재검증 ·
차단 등급 판례 · 부인 기록 · 종료 조건 · 도달 가능성 가중),
⑥ **문서 자기서술 정합**(M33 — 이 파일의 케이스 수 선언 · 커맨드 역할 앵커 전파),
⑦ **상호참조 무결성**(M34 · M35 · M44 — 살아 있는 문서의 인용이 **그 줄이 가리킨 규약 파일**의 실재
앵커를 가리키는지, 규약 문서 **집합** 기준 + 절 안의 항목을 **열거 번호로 가리키지 않는지**),
⑧ **실행 환경 축 선언 정합**(M38 — 규약이 이름 붙인 실행 환경 축의 집합이 표·이 README와 일치하는지),
⑨ **축 상태 주장 정합**(M42 — 표가 집행된다고 적은 축을 산문이 반대로 적는 자리),
⑩ **러너 소스의 변수 이름 경계**(M48 — `$이름` 뒤에 다중바이트가 오면 쉘 구현마다 이름 경계가 갈린다),
⑪ **하니스 공통 통제 보유 대조**(M48 — 새 하니스가 기존 하니스의 공통 통제를 빠뜨렸는지).

**현재 케이스 수 (cases: 212)** — Part A 7 + Part B 14 + Part C 30 + Part D 20 + Part E 20 + Part F 28 + Part G 16 + Part H 18 + Part I 20 + Part J 6 + Part K 6 + Part L 13 + Part M 14.
`run.sh` @ **dash**(우분투 `/bin/sh`) · `run.sh` @ **bash**(Git Bash) · `run.ps1` @ **Windows
PowerShell 5.1** · `run.ps1` @ **pwsh 7** — **네 실행 환경 모두** 같은 수, FAIL 0.
"양 셸 동일"로만 적지 않는다. 두 축이 그 표현 뒤에 숨어 있었다: ⑴ `.ps1`은 **런타임에 따라** 다르게
동작해 M37 재작업 3의 차단이 네 라운드를 머물렀고(5.1에서 34/85만 돌고 exit 0), ⑵ `.sh`는 **`sh`가
무엇이냐에 따라** 다르게 동작해 dash 결함이 일곱 라운드를 머물렀다(`\xHH`는 POSIX printf 확장이
아니라 dash가 글자 그대로 낸다 — 로컬 Git Bash는 `sh`가 bash라 보이지 않았다).

> 이 한 줄이 **케이스 수의 유일한 선언처**다(규약: `docs/conventions.md`의 "문서 자기서술 정합").
> 러너가 `cases` 토큰으로 이 값을 **추출해 자기 실제 케이스 수와 대조**하므로(Part F의 F1),
> 케이스를 더하거나 빼고 이 줄을 안 고치면 **양 셸이 FAIL한다**. 다른 문서는 이 수를 옮겨 적지
> 않는다 — 옮겨 적는 순간 두 번째 선언처가 생긴다.

## 무엇을 검증하나 (그리고 왜 참조 구현인가)

감지 힌트는 status·kickoff **프롬프트 스킬**의 행위라 실행 바이너리가 없다(직접 호출할 `.sh`가
없다). 따라서 이 러너는 그 스킬이 인용하는 **결정적 규약**(fleet **발견** 규약 재사용 + 감지
**임계값** ≥2 판정)을 **동일 로직의 참조 셸 절차**로 재현해 픽스처에 대해 검증한다. 단일 원본은
`docs/conventions.md`의 "멀티 레포 오케스트레이션"(발견) 절 + 발견성 힌트 항목이며, 이 러너는
그 결정적 동작을 **회귀로 고정**한다.

> 스킬 프롬프트의 LLM 서술(advisory 한 줄 문구 등)은 스크립트로 100% 강제되지 않는다 —
> **결정적 핵심**(발견·임계값)만 스크립트로 덮고, **advisory 서술 품질**은 아래 세션 레벨 수동
> 절차로 분리한다(tests/fleet와 동일 분리).

### Part A — 감지 임계값 (sh·ps1 동일, 7 케이스)

fleet 발견 참조 구현(직속 1단계·git 레포 AND tide 산출물·숨김 `.`-디렉터리 제외)을 재사용한
`detect_hint`/`DetectHint`가 자식 tide 레포 수를 세어 **≥2면 `hint N=<count>`**, **<2면 `none`**을
낸다. 픽스처별 기대:

| 부모 픽스처 | 구성 | 기대 감지 |
|---|---|---|
| `parent2` | 자식 tide 레포 **2개**(`svc-auth`·`svc-orders`) | **hint** (N=2) |
| `parent1` | 자식 tide 레포 **1개**(`only-svc`) | **none** |
| `parent0` | 자식 tide 레포 **0개**(비-tide 폴더만) | **none** |
| `single-repo` | **단일 레포 루트** — 직속 자식이 `src/`·`docs/` 등 비-tide | **none** (일반 단일 레포 세션) |
| `parenthidden` | 자식 tide 레포 **2개**(`svc-a`·`svc-b`) + **숨김** tide 자식 `.hidden-svc` | **hint** (N=2 — 숨김 미카운트) |

검증: ① 2개→hint N=2, ② 1개→none, ③ 0개→none, ④ 단일 레포 루트→none(소음 0), ⑤ 숨김
자식이 있어도 카운트에서 제외돼 hint N=2, ⑥ 숨김 자식 미발견, ⑦ 발견 집합은 `svc-a,svc-b`.

### Part B — 커맨드 수 드리프트 가드 (sh·ps1 동일, 14 케이스)

실제 커맨드 스킬 개수 `N = skills/*/SKILL.md 파일 수`(현재 12)를 세고, 캐노니컬 선언 위치가 같은
수 **"N종"**(예: `12종`)을 선언하는지 grep 결합 검증한다(불일치면 FAIL — M18~M20 SKILL-artifact
결합 패턴). 레포 루트는 스크립트 위치(`$(dirname "$0")/../..`)에서 해석한다.

| 캐노니컬 선언 위치 | 검증 |
|---|---|
| `docs/commands.md` | `${N}종` 선언 존재 (캐노니컬 카탈로그) · 모든 `/tide:<이름>` 등장 |
| `README.md` | `${N}종` 선언 존재 |
| `docs/conventions.md` | `${N}종` 선언 존재 |
| `site/docs/getting-started.md` | `${N}종` 선언 존재 |
| `docs/orchestration.md` | `${N}종` 선언 존재 (M32에서 편입 — 사이트 본문으로 인클루드되는데 `11종`으로 낡아 있었다) |
| `site/docs/commands.md` | **스니펫 셸** — 인클루드 보유 AND 카운트·카탈로그 표 미재선언 |

검증: 실제 스킬 수 측정(>0) 1 + **B1** 카운트 선언 5 + **B2** 사이트 셸 1 + **B3** 카탈로그
완전성 1 + **B3 이름 통제**(`/tide:bogus` 부재) 1 + **B1 드리프트 음성 통제** 5(실제와 다른 수
`${N+1}종`이 어느 캐노니컬 파일에도 없음) = **14**. 이 가드는 M20 리뷰 #6(사이트 8종↔11종 표류)의
회귀 고정이다 — 커맨드를 더/빼면서 선언 수를 안 고치면 양 셸 모두 실패한다. M22에서 카탈로그가
`docs/commands.md` 단일 원본으로 옮겨져 `site/docs/commands.md`는 **카운트 선언처가 아니라 셸**이다.

### Part C — 선언 정합 드리프트 가드 (M30 · M37 · M41, sh·ps1 동일, 30 케이스)

Part B가 집행하는 것은 결국 **"같은 사실을 여러 문서가 선언할 때의 드리프트"**(커맨드 수)다. 아래
둘은 정확히 같은 부류라 같은 하니스에 둔다 — 여러 파일이 같은 사실을 선언하고, **한 곳만 고치면
조용히 갈라진다**.
단일 원본은 `docs/conventions.md`의 "debug 세션"(항목 상태값)·"변경 파일 요약 기준선" 절이며,
이 러너는 **선언의 존재**를 결합 조건으로 고정한다(문구 품질이 아니다).

**C-1. debug 항목 상태값 집합** — 네 값(`수정함`·`미해결`·`원인만 규명`·`확인함`)이 **세 파일 전부**에
등장한다(M30에서 `확인함`이 가산되며 갈라질 위험이 실재했다).

| 선언 위치 | 검증 |
|---|---|
| `docs/conventions.md` | 네 상태값 전부 등장 · `보류함` **부재** |
| `skills/debug/SKILL.md` | 네 상태값 전부 등장 · `보류함` **부재** |
| `skills/debug/template.md` | 네 상태값 전부 등장 · `보류함` **부재** |

**C-2. 변경 파일 요약 기준선** — 같은 추가/수정/삭제 표를 쓰는 **세 템플릿 전부**가 기준선을
명시한다(한 템플릿만 고치면 표의 의미가 파일마다 갈라진다 — 그 자체가 드리프트).

**C-3. phase 기록 커맨드 명단**(M37) — 규약이 `## 상태 파일 (.tide/phase)` 절을 그 명단의 **유일한
열거처**로 정하고 발행 페이지 `site/docs/concepts.md` **하나만 예외**로 뒀다. 이 파트가 그 선언을
집행한다. M36이 이 사실을 **같은 축에서 세 번** 틀리게 적은 것이 배경이다 — 명단이 다섯 곳에
복제돼 매 라운드가 일부만 고쳤다.

규약의 선언이 **두 목록**(phase를 쓰는 6종 · 쓰지 않는 6종)을 함께 걸었으므로 이 파트도 **둘 다**
문다 — **선언 범위와 집행 범위를 같은 넓이**로 둔다(M37 리뷰 차단 #1: 집행이 절반만 덮으면 규약이
사실보다 넓게 주장하는 `vacuous-pass` 부류가 된다).

- **기록 명단 줄**의 정의: 여섯 커맨드 이름이 **한 줄에 모두** 있으면서 `phase` 문맥인 줄. 커맨드
  카탈로그 행(README의 커맨드 목록, `docs/project-context.md`의 `skills/` 디렉터리 행)은 phase
  문맥이 아니라 걸리지 않는다.
- **비기록 명단 창**의 정의: 비기록 6종은 두 파일 모두 **산문으로 풀어 써 여러 줄에 걸치므로**,
  여섯 이름이 모두 드는 **가장 짧은 연속 줄 묶음(창, 최대 4줄)** 을 뽑는다(실측 스팬 — 규약 2줄 ·
  발행 페이지 3줄). **상한을 넘으면 창을 찾지 못하고** 개수 케이스가 크게 FAIL한다 — 이 상한이
  **집행 경계**이며 양 셸이 같은 값을 쓴다. 창에 섞여 드는 무관한 백틱 토큰(`` `.gitignore` `` 등)을
  거르는 것은 창의 최소성이 아니라 **추출 정규식** `` `[a-z][a-z-]*` ``(양 셸 공통)다.
- **캐노니컬 이름은 러너가 탐침(needle)으로 갖는다** — 기록 6종은 `grep -F` 리터럴 연쇄(`run.sh`)·
  `$ROSTER_NEEDLES`(`run.ps1`), 비기록 6종은 awk `index` 리터럴·`$NONWRITER_NEEDLES`다. 드리프트
  표면은 **없어진 것이 아니라 러너로 옮겨졌다** — 커맨드 이름을 바꾸면 러너 두 사본도 함께 고쳐야
  한다. 다만 러너는 명단을 **선언**하지 않고 **탐침**만 하므로, 어긋나면 추출이 0이 되어 개수
  케이스가 **크게 FAIL**한다(조용한 공허 통과가 아니다). 규약의 복제 선언 수 지표도 `tests/`를
  집계에서 빼므로 지표와 정합한다.

| 검사 | 내용 |
|---|---|
| 개수 | 규약·발행 페이지의 **기록**·**비기록** 명단이 각각 **이름 6개** (4 케이스) |
| 집합 일치 | 두 파일에서 뽑은 이름 집합이 **문자열로 동일** — 기록·비기록 각각 (2). **양쪽이 다 비면 `no`** 로 떨어뜨려 자기 공허를 막는다 |
| 유일 열거처 | 살아 있는 문서를 훑어 명단을 가진 파일이 **그 둘뿐** — 기록 줄·비기록 창 각각 (2) |
| 서로소 | 한 파일 안에서 **기록 ∩ 비기록 = 공집합** (2). 추출기가 엉뚱한 쪽을 집으면 개수·집합 일치는 통과해도 여기서 걸린다 |
| 음성 통제 | 존재하지 않는 이름(`phantom-cmd`)이 네 명단 **어디에도 없음** (4) |

훑는 범위는 README·`docs/*.md`·`site/docs/*.md`·`skills/**/*.md`(재귀)·훅 두 사본이며 **두 명단이
같은 범위**를 훑는다 — `docs/milestones/`·`docs/reports/`는 **시점 기록물**이라 제외한다(규약의
복제 선언 수 세는 규칙과 같은 범위). 이 범위를 만드는 함수는 `roster_scan_files`/`RosterScanFiles`로
**Part G의 `living_docs`/`LivingDocs`와 이름이 다르다** — Part G판은 범위가 다르므로(`tests/*/README.md`
포함·훅 제외) 같은 이름을 쓰면 C-3의 범위가 **정의 실행 순서**에 달리게 된다.

범위의 의미는 **"재귀 + 점 제외 + 확장자 대소문자 구분"** 이고, 양 셸이 그것을 각자의 관용구로
구현한다. 아래 표의 축(점 이름 · 점 디렉터리 · 레포 **위쪽** 경로의 점 성분 · Hidden 속성 ·
확장자 대소문자)이 **실측으로 두 셸이 일치함을 확인한 전부**다 — 표에 없는 축은 확인하지 않았다:

| 가지 | `run.sh` | `run.ps1` |
|---|---|---|
| `docs/*.md` · `site/docs/*.md`(평면) | POSIX 글롭 — 점 이름 미매치 · Hidden 속성은 매치 · `*.md`는 **대소문자 구분** | `-Force` + **이름**이 `.`으로 시작하면 제외 + `EndsWith('.md', Ordinal)` |
| `skills/**/*.md`(재귀) | `find … -name '.*' -prune`(점 이름·점 디렉터리 제외) · `-name '*.md'`는 **대소문자 구분** | `-Force` + **레포 상대 경로**의 성분이 `.`으로 시작하면 제외 + `EndsWith('.md', Ordinal)` |
| **`skills/*/SKILL.md`(Part B — M38-T04)** | POSIX 글롭 `ls "$ROOT"/skills/*/SKILL.md` — 점 디렉터리 **미매치**(글롭이 의미를 공짜로 만족) | `Get-ChildItem -Directory` + **이름**이 `.`으로 시작하면 제외(`Ordinal`) — 필터 없이는 점 디렉터리를 **포함**한다 |

**Part B 가지의 의미**(M38-T04) — **"점으로 시작하는 디렉터리는 커맨드 스킬이 아니다"**. 이 러너의
다른 모든 스캔(위 두 가지 · Part G)과 같은 의미이고, 양 셸·양 파트가 그 하나의 의미에 맞춰져 있다.
이 선언이 없던 동안 `skills/.spare/SKILL.md` 하나로 **sh 85/0 exit 0 ↔ ps1 79/6 exit 1**로 갈렸다 —
**한 러너 안에서 파트끼리 규율이 달랐던 것**(Part G는 점 필터를 갖고 Part B는 갖지 않았다)이 원인이다.
`StartsWith`는 전부 `Ordinal`이다(M38-T03) — 문화권 비교는 무시 가능 문자를 건너뛰어 ps1만 **덜**
훑게 만든다.

`run.ps1`의 `-Filter '*.md'`는 Windows에서 **대소문자를 가리지 않는다** — 그래서 `EndsWith(… Ordinal)`을
덧붙여 글롭·`find`와 같은 집합이 되게 한다. 없으면 `X.MD`를 ps1만 훑어 판정이 갈린다(M37 재작업 3
리뷰의 in-review 수정).

`skills/` 가지에서 ps1이 **절대경로**를 보면 안 된다 — 레포가 점 디렉터리 아래에 체크아웃되면
(`~/.config/…`·`.worktrees/…`·CI 캐시) `skills/**`가 통째로 스캔에서 빠져 이 러너만 조용히 초록이
된다(M37 리뷰 차단의 실측 재현). 그래서 판정은 **`$ROOT`를 제거한 상대 경로**로만 한다.

**집행의 한계(고지)** — 아래는 이 파트가 **덮지 않는** 우회 표면이다. 규약의 "유일 열거처"는
규율이고, 하니스는 그중 아래 범위까지만 기계로 문다.

- **줄·창 단위 스코프**: 기록 명단을 **두 줄로 나눠** 제3의 파일에 적으면 걸리지 않는다(한 줄이면
  걸린다). 비기록 명단은 **5줄 이상으로 흩어 놓으면** 창(4줄)을 벗어난다. **이 경계는 양 셸이
  같다** — 경계 밖 변형(스팬 6줄)에서 두 러너가 같은 케이스·같은 종료 코드를 내는지는 실측으로
  확인한다(M37 재작업 2의 실증 표).
- **탐침 이름 의존**: 위 두 명단의 검출은 러너가 가진 이름 탐침에 걸린다 — 이름을 바꾸면 검출이
  0이 되어 FAIL로 드러나지만(조용하지 않다), 러너 두 사본을 함께 고쳐야 복구된다.
- **점 제외·대소문자 구분의 뒷면**: 위 범위 표대로 점으로 시작하는 파일·디렉터리, 그리고 `.MD`처럼
  **확장자 대소문자가 다른** 파일은 스캔 밖이다. 명단을 `skills/.internal/notes.md`·`docs/.notes.md`·
  `docs/NOTES.MD` 같은 자리에 적으면 **양 셸 모두 못 잡는다**. 판정이 갈리지는 않지만(두 러너가 같이
  못 잡는다) 제3 선언처가 들어올 통로다 — 점 경로와 이형 확장자를 살아 있는 문서로 쓰지 않는 것이
  규율 쪽 전제다.
- **경계 밖은 무관심**: 창 밖으로 흩어진 선언은 **위반이 아니라 미탐지**다. 이 파트는 "여기까지는
  기계가 문다"를 고정할 뿐, 그 밖을 규율로 막는 것은 규약의 몫이다.

| 템플릿 | 검증 |
|---|---|
| `skills/milestone/template.md` | `기준선` 선언 존재 |
| `skills/impl/template.md` | `기준선` 선언 존재 |
| `skills/debug/template.md` | `기준선` 선언 존재 |

**C-4. 2.0 stable 커맨드 명단**(M41) — 규약이 `## 2.0 안정성` 절에서 stable 11종의 **이름 명단**을
열거하는 곳을 **규약과 `README.md` 둘**로 정하고, 다른 살아 있는 문서는 명단을 다시 적지 않고 그 절을
가리키게 했다. 이 소절이 그 선언을 집행한다. C-3과 **같은 부류**(여러 파일이 같은 명단을 선언 →
하나만 고치면 조용히 갈라짐)라 새 파트를 만들지 않고 여기 둔다.

| 열거처 | 검증 |
|---|---|
| `docs/conventions.md` | stable 명단 이름 **11개** · 존재하지 않는 이름 부재 |
| `README.md` | stable 명단 이름 **11개** · 존재하지 않는 이름 부재 |

- **`12종`과 `11종`은 다른 사실이다** — 전자는 실제 `skills/*/SKILL.md` **파일 수**라 B1이 세어
  대조하고, 후자는 **동결 선언**이라 파일 시스템으로 셀 수 없어 **명단 대조로만** 집행된다. 그래서
  이 검사를 B1에 얹을 수 없고 별도 추출기를 둔다.
- **추출 단위 = 창(최대 4줄)** — 열한 이름이 모두 드는 가장 짧은 연속 줄 묶음. 실측 스팬은 **규약
  3줄 · `README.md` 1줄**이고 상한은 C-3과 **같은 4**다(집행 경계 — 양 셸 동일). 명단을 5줄 이상으로
  흩으면 창을 찾지 못해 개수 케이스가 크게 FAIL한다. 위 "집행의 한계" 고지가 그대로 적용된다.
- **탐침은 닫는 백틱까지 포함한다**(`` `/tide:fleet` ``) — 그러지 않으면 `` `/tide:fleet-cycle` ``
  안에 우연히 걸린다(B3의 경계 요구와 같은 이유).
- **`/tide:debug`는 동결 집합이 아니다** — 창에 섞여 들면 개수가 12가 되어 FAIL한다. 승격은 major
  사안이고, 그때 규약·README·러너 두 사본을 함께 고치는 것이 **의도된 비용**이다.
- **정렬은 ordinal로 고정한다** — C-4를 넣으며 `run.ps1`의 `Sort-Object -CaseSensitive`가 **문화권
  비교**라 `docs/…`를 `README.md`보다 앞에 두는 것이 드러났다(`LC_ALL=C sort`는 `README.md`가 앞).
  두 사본이 같은 의미를 내도록 ps1에 `OrdinalSortUnique` 헬퍼를 두고 이 파트의 모든 정렬을 거기로
  모았다 — M40이 BSD에서 `LC_ALL=C` 누락으로 물린 것과 **같은 부류**이며, 비교 대상이 대소문자
  머리글자를 섞기 전까지 **잠복해 있었다**.

검증: **C1 양성** 4(네 상태값 × 세 파일 결합) + **C1 음성 통제** 3(존재하지 않는 상태값 `보류함`이
세 파일 **어디에도** 없음) + **C2** 3(기준선 × 세 템플릿) + **C3** 14(개수 4 · 집합 일치 2 ·
유일 열거처 2 · 서로소 2 · 음성 통제 4) + **C4** 6(개수 2 · 집합 일치 1 · 유일 열거처 1 ·
음성 통제 2) = **30**. 음성 통제는 Part B의 `${N+1}종`
부재 통제와 **동일 취지**다 — 통제가 없으면 grep이 죽어도 green이 된다(가드의 구별력 입증).

### Part D — 브랜치 간 협업 안전 선언 정합 (M31 · M39 · M40 · M46, sh·ps1 동일, 20 케이스)

Part C와 같은 부류를 **규약↔스킬** 축으로 집행한다. 두 검사(릴리즈 커버리지 체크·마일스톤 번호
사전경고)의 **런타임 발화**는 프롬프트 규율이라 하니스로 못 덮지만, **선언 정합**은 결정적으로
고정된다. 앵커는 ASCII 메커니즘 토큰(git 읽기 명령)이라 ps1의 ASCII-only 원본 규율과 정합한다.

| 검사 | 앵커 토큰 | 결합 |
|---|---|---|
| D1 릴리즈 커버리지 체크 | `git diff --name-only` | `docs/conventions.md` ↔ `skills/release/SKILL.md` |
| D2 마일스톤 번호 사전경고 | `git log --all` | `docs/conventions.md` ↔ `skills/milestone/SKILL.md` |
| D3 커버리지의 **미커밋 범위**(M39) | `git status --porcelain` | `docs/conventions.md` ↔ `skills/release/SKILL.md` |
| D4 같은 범위의 **사용자 대면 선언**(M39 재작업 1) | `git status --porcelain` | `docs/commands.md`(캐노니컬 카탈로그 → 사이트 인클루드) |
| D5 `workflow-syntax` 축의 **확인 배선**(M40 리뷰 권장1) | `gh pr checks` | `docs/conventions-release.md`(규약 조각) ↔ `skills/release/SKILL.md` |
| D6 커버리지의 **중괄호 확장 정규화**(M46) | `brace-expansion` | `docs/conventions.md` ↔ `skills/release/SKILL.md` |
| D7 커버리지의 **역방향 선언 대조**(M46) | `declared-change-set` | `docs/conventions.md` ↔ `skills/release/SKILL.md` |

D3이 D1과 **별도 토큰**인 이유: 커버리지 범위는 두 절반(커밋 diff ∪ 미커밋 변경)인데 D1만 있으면
**미커밋 절반이 통째로 빠져도 통과**한다. 그 절반이 빠져 있던 동안 검사는 정상 사이클에서 아무것도
보지 못했고(release가 프리플라이트 **후에** 커밋하므로 범위가 늘 비었다), 정작 release 자신이
스테이징으로 태그에 싣는 편승은 검사 밖에 있었다 — M39의 출처다.

**D4가 왜 필요했나(M39 재작업 1)** — M39가 규약과 release 스킬만 고치고 **캐노니컬 카탈로그를 두는
바람에** 공개 페이지가 옛 범위("마지막 태그 이후 변경된 파일")로 남았다. D1·D3은 규약↔스킬 결합이라
그 드리프트를 **보지 못했다**. 소비자 문서를 결합에 넣어 **그 결합 구멍**을 닫는다(Part F의 역할 앵커
소비자 전파와 같은 취지).

> **D4가 무는 범위**: D1·D2·D3과 똑같이 **선언(토큰)의 존재**만 묶는다 — 카탈로그가 토큰을 지닌 채
> **서술을 틀리게** 적으면 이 파트는 초록이다(문구 품질은 Part D 전체가 묻지 않는 층이고, 사람의
> 리뷰가 본다). 실제로 일어난 드리프트는 "미커밋 범위를 **아예 언급하지 않음**"이었고 D4는 그것을 문다.

**D5가 왜 필요했나(M40 리뷰 권장1)** — M40이 `workflow-syntax` 축의 확인을 `pr` 마무리에 배선하면서
**결합 없이 문장만** 넣었다. 실측: release 스킬에서 그 배선을 통째로 지워도 **107/0 초록**이었다.
D1~D4와 같은 부류이고 기법도 같다 — 다른 것은 규약 쪽 단일 원본이 본체가 아니라 **조각**
(`docs/conventions-release.md`)이라는 점뿐이다(M35의 규약 문서 집합 분할 이후 첫 조각 결합).

**D6·D7이 왜 필요했나(M46)** — D1·D3은 커버리지가 **무엇을 모으는가**(커밋 diff · 미커밋 변경)를
앵커하지만 **모은 것을 어떻게 대조하는가**는 아무도 묶지 않았다. 그 층에서 두 결함이 실제로 났다.

- **D6(중괄호 확장)**: v2.18.0 릴리즈의 커버리지 대조에서 대상 17건 중 **미상 7건이 전부**
  `skills/{cycle,debug,…}/SKILL.md` 형태였다 — 보고서가 정당하게 선언한 것을 매칭이 못 읽어 낸
  **위양성 100%** 다. 펼친 뒤 미상은 **0건**이 된다. M42~M44 구간은 이 형태를 쓰지 않아 펼치기 전후가
  모두 미상 0이다(**음성 통제** — 확장 규칙이 다른 형태를 잘못 펼치지 않는다).
- **D7(역방향 선언 대조)**: `docs/reports/M45-review.md`가 `skills/review/template.md`를 변경 파일로
  적었으나 그 파일은 **v2.17.0 이후 무변경**이다. 등급 근거의 사실 오류가 릴리즈까지 갔고 어떤 검사도
  보지 않았다. 대조 범위를 **impl 보고서의 `변경 파일 요약` 표**로 한정하면 M42~M45 네 사이클에서
  **역방향 오탐 0 · 정방향 누락 0**이다. **산문 전역으로 넓히지 않는 이유**도 실측이다 — 실재 경로
  토큰 96개 중 플래그 10건인데 진짜 결함은 **하나**이고 나머지 아홉은 포인터·이력 서술·경로 축약이라
  **위양성 90%** 다. 그 경계는 규약이 적는다.

> **D6·D7이 무는 범위**: D1~D5와 똑같이 **선언(토큰)의 존재**만 묶는다 — 실제 매칭이 규약대로
> 동작하는지는 프롬프트 규율이라 이 파트가 묻지 않는다(라이브 도그푸딩 영역).

되돌림 실측(사본, 양 러너 동일): release 스킬에서 `brace-expansion`을 지우면 **164/1**, conventions에서
`declared-change-set`을 지우면 **164/1**, milestone 스킬에 두 토큰을 심으면 교차 통제가 물어 **163/2**.
복구하면 셋 다 165/0으로 돌아온다.

검증: D1 2 + D2 2 + D3 2 + D4 1 + D5 2 + D6 2 + D7 2 + **교차 통제** 6(커버리지·미커밋 범위·PR CI·
중괄호 확장·역방향 대조 토큰이 milestone 스킬에 **없음**, 번호경고 토큰이 release 스킬에 **없음**) +
**음성 통제** 1(가짜 토큰 `git diff --bogus-only` 부재) = **20**.

### Part E — 리뷰 검증 규율 선언 정합 (M32 · M36 · M44 · M46, sh·ps1 동일, 20 케이스)

`/tide:review`가 판정을 만들어내는 절차(단일 원본: conventions "리뷰 검증 규율")를 **규약↔스킬↔
템플릿** 3축으로 결합한다. 토큰은 전부 **ASCII 병기어**다.

| 검사 | 앵커 | 결합 |
|---|---|---|
| E1 반증 시도 | `refutation` | conventions ↔ review SKILL |
| E2 판정 계측 | `in-review` | conventions ↔ review SKILL ↔ review 템플릿 |
| E3 재작업 라운드 | `rework` | conventions ↔ review 템플릿 ↔ impl 템플릿 |
| E4 계측 줄 **형식** | `in-review` … `(rework)` **같은 한 줄** | 세 파일 각각 |
| E5 재검증 선언 | `re-verify` | conventions ↔ review SKILL ↔ review 템플릿 |
| E6 판례 부류 (M36) | `vacuous-pass` | conventions ↔ review SKILL |
| E7 부인 기록 (M36) | `precedent-waiver` | conventions ↔ review SKILL ↔ review 템플릿 |
| E8 종료 조건 (M44) | `residual-risk-acceptance` | conventions ↔ review SKILL ↔ review 템플릿 |
| E9 도달 가능성 가중 (M44) | `reachability-weighting` | conventions ↔ review SKILL |

검증: E1 1 + E2 1 + E3 1 + E4 3 + E5 1 + **E6** 1 + **E7** 1 + **E8** 1 + **E9** 1 + **교차 통제**
2(impl 템플릿에 반증 토큰·계측 줄 골격 부재) + **음성 통제** 3(가짜 `refutation-bogus`·가짜
`vacuous-pass-bogus`·가짜 `residual-risk-acceptance-bogus`가 conventions에 부재) = **16**. E4·E5는 M32 리뷰가 적발한 **공허 통과**를 닫은 단언이다 —
토큰 존재만 보던 E1~E3는 계측 줄 이형(`(rework)` 병기 누락)을 통과시켰고, `in-review`가 계측 줄과
재검증 절에 **이중 용도**라 재검증 절을 통째로 지워도 green이었다.

**E8·E9(M44 — M43이 더한 두 규칙)** 은 이 파트가 왜 M43 리뷰 이슈 1을 못 물었는지에 대한 처방이다.
그 두 규칙(**종료 조건** · **도달 가능성 가중**)에는 **ASCII 병기어가 없었고**, 결합할 토큰이 없으니
종료 조건을 **무조건으로 부정하는 재서술 세 자리**가 트리 그대로 초록이었다. 병기어를 붙이고 결합한다 —
`residual-risk-acceptance`는 보고서에 **수용 근거 블록**을 남기므로 3곳(E7과 같은 층위 — **M44 리뷰가
그 슬롯을 실제로 만들었다**: 규약은 블록 셋을 요구하는데 리뷰 템플릿에 자리가 없어 3곳 결합의 근거가
그만큼 약했다. 새 섹션이 아니라 기존 `## 릴리즈 판정` 절 안의 조건부 항목이다),
`reachability-weighting`은 등급 판단의 근거라 2곳(E6과 같은 층위)이다. **M44-T01이 이 파트의 경계도
실측했다**: 병기어가 **있는데도** 옆 산문이 규칙과 반대되는 사실을 말하는 경우는 여전히 못 문다
(토큰 존재는 대조되지만 문장의 의미는 대조되지 않는다 — 창 기반 모순 검출은 예외 문장이 **다음 줄**에
있어 줄 단위로 잡히지 않고, 표지가 한글이라 ps1 ASCII-only 규율과 충돌했다). 그 층은 사람의 리뷰
영역이며 규약이 같은 문장으로 적고 있다.

**E6·E7(M36 — 차단 등급 판례)** 은 같은 부류를 **판정 근거** 축으로 넓힌다. `vacuous-pass`는 판례
부류의 이름이라 **기준(규약)** 과 **절차(review SKILL)** 2곳 결합이고(E1 `refutation`과 같은 층위 —
보고서 템플릿엔 슬롯을 두지 않아 복제 선언을 늘리지 않는다), `precedent-waiver`는 **부인 기록이
실제로 남아야** 하므로 규약(의무)·스킬(절차)·템플릿(기록 슬롯) **3곳 결합**이다 — 템플릿에서만
지워도 E7이 문다. **음성 통제**는 가짜 토큰 `vacuous-pass-bogus`가 conventions에 **없음**을 단언해
가드의 구별력을 입증한다(기존 `refutation-bogus` 통제와 동형). `vacuous-pass`가 impl 템플릿에
없어야 한다는 **교차 통제는 새로 두지 않는다** — 기존 교차 통제 2건이 이미 review↔impl 경계를
고정하고 있고, 케이스를 늘리는 것 자체가 이 사이클이 지는 부채다.

### Part F — 문서 자기서술 정합 + 러너 소스 규율 (M33 · M43 · M45, sh·ps1 동일, 24 케이스)

Part B~E가 **여러 문서가 같은 사실을 선언할 때**의 드리프트를 집행한다면, Part F는 문서가
**자기 자신에 대해 하는 서술**을 집행한다.
단일 원본은 `docs/conventions.md`의 "문서 자기서술 정합" 절.

**F-2. 역할 앵커 전파** — 캐노니컬 `docs/commands.md`의 주석 한 줄
`<!-- role-anchors: name=token … -->`에서 앵커를 **추출**해, ① 그 커맨드의 **캐노니컬 표 행**에
앵커가 실재하는지 ② 소비자 문서(`README.md`·`site/docs/getting-started.md`)가 그 커맨드를
**언급하면** 앵커도 있는지 검사한다. 언급하지 않는 문서는 대상이 아니다(소음 0). 스크립트에 한글
리터럴을 두지 않는 **데이터 기반** 검사라 ps1 ASCII-only 규율과 정합한다(`tests/site-includes`의
용어 추출과 동형). 앵커는 **영문·하이픈 경계**로 찾는다 — 짧은 앵커(`gh`)가 다른 단어 안에 우연히
걸리지 않도록.

**F-3. 통제** — 추출 0건이면 **FAIL**(positive-control: 루프가 통째로 공허 통과하는 것을 차단),
앵커 맵의 이름이 전부 실제 커맨드 스킬인지, 가짜 앵커(`bogusanchor`) 부재.

**F-1. 케이스 수 자기 정합** — 이 README 맨 위 `cases` 선언과 러너의 **실제 케이스 수**를
대조한다. F1 자신도 한 케이스라 계수가 순환하므로 **F1을 마지막 케이스로 두고 `누계 + 1`과
비교**하는 경로를 택했다(러너 주석에도 같은 문장이 있다). 추출 실패(선언 부재·골격 이형)는 조용한
skip이 아니라 **FAIL**이다.

**F-1b. 파트별 내역 합 정합** — F1은 **총계**만 본다. 총계를 고치면서 같은 줄의 파트별 내역을 안
고치면 한 겹 아래에서 조용히 갈라지므로, 내역의 합이 총계 선언과 같은지 함께 확인한다(내역도 ASCII
골격이라 양 셸이 같은 방식으로 합산한다). 합산 범위는 **선언 줄 한 줄**이다 — 파일 전체를 훑으면
이 문서 산문에 인용된 같은 골격까지 더해진다(리뷰 중 실제로 그렇게 걸렸다).

**F-7. 발견 명세** (M42 재작업 5) — `F5`가 무는 파일 집합을 **명세로 고정하고 픽스처로 문다**.
명세는 셋이다 — ⑴ 확장자 비교는 **대소문자 구분**(`.PS1`은 발견 대상이 아니다) ⑵ **숨김 항목도
본다** ⑶ **디렉터리는 세지 않는다**. 실물 `tests/`에는 그런 파일이 없어 실물만 훑으면 명세가 아무리
틀려도 **영원히 초록**이므로, 샌드박스에 `a.ps1`·`b.PS1`·`.hidden.ps1`·`sub/c.ps1`과 미끼 디렉터리
`dir.ps1`을 만들어 **검사와 같은 함수**를 걸고 **정렬된 basename 목록**을 대조한다. 수가 아니라
이름을 보는 이유는 숨김을 빠뜨리고(-1) 대문자를 더하면(+1) **개수가 상쇄**돼 초록이 되기 때문이다 —
ps1 사본이 실제로 그 두 결함을 동시에 갖고 있었다. `Get-ChildItem -Filter`는 Windows에서 대소문자를
무시하고 `-Force` 없이 숨김을 건너뛰므로 **같은 트리에서 두 셸의 판정이 갈렸다**(M42 리뷰 차단 1:
비-ASCII가 든 `extra.PS1` → sh 145/0 초록 ↔ 양 PowerShell 144/1, 숨김 `hid.ps1` → sh 144/1 ↔ 양
PowerShell 145/0 초록). **정본은 sh다** — `find`가 셋을 그대로 하므로 ps1 사본이 `-Force`와 ordinal
`EndsWith`로 옮겨 왔다. 숨김의 표기는 플랫폼마다 다르므로(Windows=속성, POSIX=점 이름) 픽스처는 양쪽
모두에 점 이름으로 두고 ps1 사본이 **속성도 함께** 건다. sh 사본은 속성을 걸지 않는다 — `find`에는
숨김 개념 자체가 없어 걸 대상이 없고, **그 사실이 이 결함이 ps1 쪽 결함이었던 이유**다.

검증: F2 3(앵커 수) × 3(캐노니컬 행 + 소비자 2) = 9 + F3 3 + F1b 1 + F1 1 + **F4·F5** 2(러너 소스
규율 — 발견 positive-control + `tests/**/*.ps1` 비-ASCII 0줄) + **F6** 1(검사한 파일 수 == 발견한
파일 수 — 발견과 소비의 대조) + **F7** 1(발견 명세 — 대소문자·숨김·디렉터리) + **F8** 1(F7의
숨김 축 **전제조건** — 숨김 픽스처가 숨김 미포함 열거에서 감춰진다) + **F9~F13** 5(로케일 고정 —
미고정·미선언 0건 · **계열별** 추출 positive-control 둘 · **계열별** 주입 픽스처 검출 둘)
+ **F14~F16** 3(진입점 문서 줄 수 상한 — 상한 선언 추출·유일성 · 실제 판정 · **같은 판정 함수**에 먹인 초과 픽스처 통제) = **27**.

**F14~F16이 왜 생겼나(M46)** — 규약이 `CLAUDE.md`에 줄 수 상한을 적으면서 *"상한은 사람이 지키며
기계가 묻지 않는다"* 고 **함께 적고 있었다**. M46-T05가 닫을 수 있음을 실측했고 두 전제를 먼저 고쳤다.

- **선언 줄 유일성**: 상한 값이 규약과 `docs/project-context.md` **두 곳**에 있었다 — 값을 규약 한 줄로
  모으고 원장 쪽은 포인터로 바꿨다(체크리스트 ⑵).
- **세는 방법이 판정을 가른다**: `wc -l`은 개행 **개수**라 마지막 줄에 개행이 없으면 1 적게 센다.
  실측(개행 없는 3줄 파일): `wc -l` **2** · `grep -c ""` **3** · ps1 `ReadAllLines` **3**. 그래서 sh는
  `grep -c ""`, ps1은 `ReadAllLines`로 고정했다 — 이 선택이 없으면 같은 파일에서 두 러너가 갈린다.
- **ps1 쪽 한글**: 상한 선언 줄이 한글 산문이라 정규식을 **코드포인트로 조립**했다(F5의 ASCII-only
  원본 규율과 정합).

- **판정은 함수 하나에만 둔다**: `F15`(실물)와 `F16`(픽스처)이 **같은 판정 함수**를 부른다
  (`F12`·`F13`이 `locale_scan_in`을 픽스처에 돌리는 형태와 동형). 이 구조가 아니면 `F16`은 자기가
  통제한다고 적힌 것을 통제하지 못한다 — 아래 재작업 항목을 보라.

되돌림 실측(사본, 양 러너 동일): `CLAUDE.md`에 상한 초과가 되도록 줄을 더하면 **F15만 붉고**
(**171/1** · `over(43/40)`), **판정 함수를 항상 `ok`로 무력화하면 F16이 붉고**(**171/1** · `missed`),
규약의 상한 선언 줄을 지우면 **F14·F15·F16이 함께 붉다**(**169/3** — 추출 0이라 유일성이 깨지고
판정이 `nocap`이 되어 픽스처도 `over`를 잃는다). 복구하면 양 러너 172/0으로 돌아온다.

> **이 검사가 만든 사람을 두 번 세웠다.**
> ⑴ **첫 판본은 자기 훼손 경로에서 두 사본이 갈렸다** — 선언 줄을 지우면 **sh 169/3 · pwsh 170/2**로,
> sh의 `ENTRY_CAP`이 **빈 문자열**이 되어 산술 비교가 에러로 죽고 ps1은 정수 `0`이라 살아남았다.
> 빈 값을 **0으로 고정**해 닫았다.
> ⑵ **그렇게 고친 판본도 `F16`이 동어반복이었다**(M46 리뷰 차단 1 · 재작업 1에서 닫음) — 픽스처를
> 만든 뒤 *"그 픽스처의 줄 수가 상한보다 큰가"* 를 **인라인으로 재구현**해서 물었기 때문에 `F15`의
> 판정을 **한 번도 호출하지 않았다**. 실측: `F15`의 판정을 통째로 무력화해도 **양 사본 172/0 초록**.
> 판정을 함수로 뽑아 둘이 같은 것을 부르게 해서 닫았다. **픽스처 통제는 「픽스처가 조건을 만족하는가」가
> 아니라 「실제 판정이 픽스처를 잡는가」를 물어야 한다** — 이 구별이 이 파트의 교훈이다.

**F-8. `F7`의 전제조건** (M43) — `F7`이 *"숨김도 본다"*를 증명하려면 픽스처의 그 파일이 **실제로
숨김이어야** 한다. ps1 사본은 속성 설정을 `try/catch`로 감싸는데, 그 단계가 조용히 실패하면 **숨김
축이 통째로 사라지고 러너는 아무 말도 하지 않는다**(M42 리뷰 실측: 속성 단계만 무력화하면 `-Force`
결함을 그대로 두고도 양 PowerShell이 146/0 초록). 그래서 전제조건을 케이스로 승격했다 — **숨김을
포함하지 않는 열거에서 그 파일이 보이지 않아야 한다**. 이 판별은 두 플랫폼에서 **각자의 숨김 표기로**
성립한다(POSIX는 점 이름 — 글로브가 매치하지 않는다 / Windows는 숨김 속성 — `-Force` 없는 열거가
건너뛴다). **각 사본이 무는 것은 다르다**: sh는 **점 이름 규약**을(그 셸엔 속성 개념이 없다), ps1은
**속성 설정의 성공 여부**를 문다. 같은 불변의 양쪽 표현이며, `F7`의 숨김 축이 ps1 전용인 것과 같은
분담이다.

> **F5는 왜 여기 있나**(M42 재작업 3 — 자체 발의): 규약과 이 문서가 *"byte>127=0 규율이 유지된다"*고
> 적어 왔지만 **어느 케이스도 CI 잡도 그것을 물지 않았다**. 그 사이클의 재작업 중 `run.ps1` 주석에
> 한글이 한 줄 섞였는데 **138 케이스가 전부 초록**이었고 사람이 바이트를 세어서야 드러났다. 탐색은
> **`$ROOT` 기준**이다 — 상대경로로 두면 호출자의 cwd에 있는 다른 트리를 훑어 깨진 사본에도 초록이
> 된다(배선 중 실측으로 한 번 그렇게 갈렸다).

**F-9. 로케일 고정 규율** (M45) — `F5`(비-ASCII 0줄)와 같은 층위다: 문서가 아니라 **러너 소스**의
규율을 문다. 네 사이클 연속 같은 부류가 **사람 손에** 잡혔다(M41 `Sort-Object`·`StartsWith` 6곳 ·
M42 세 표면 전수 감사 + `tests/lib/discover.sh`의 누락 · **M44 리뷰 이슈 4** — 구현이 놓치고 리뷰가
잡았다). 이 부류는 **두 셸의 의미를 갈라 BSD에서만 터진 전례가 둘**이다.

- **무는 대상 집합의 명세**: `.sh`는 **명령 위치**의 `sort`·`uniq`만(줄 선두·파이프·`;`·`&`·`(`·`$(`
  뒤). 함수 이름 부분 문자열(`toposort`)과 주석은 대상이 아니다 — **M45-T01 실측: 원시 46줄 → 명령
  위치 22 사이트**. `.ps1`은 **인자 없는 `Sort-Object`** 만(키를 지정한 `Sort-Object { … }`는 문화권과
  무관하며 실측 2건, 광범위 API(`-eq`·`-match`·`IndexOf`)는 오탐이 폭발해 대상 밖이다).
- **고정으로 보는 형태는 `.sh`의 같은 줄 `LC_ALL=C` 하나다**(M45 재작업 1에서 좁혔다). 인자 없는
  `Sort-Object`에는 **고정 형태가 없다** — 헬퍼로 바꾸면 사이트가 아니게 되고, 남겨야 하면 **선언**한다.
  첫 판본은 같은 줄에 `Ordinal` **문자열**이 있으면 고정으로 봤고, 문서는 *"헬퍼 경유"*라 적어
  **구현이 문서보다 넓었다** — 주석의 단어 하나로 미고정 정렬이 통과했다(리뷰 차단 2, 실측).
- **예외는 선언한다**: 같은 줄 `locale-exempt: <사유>` 주석. 살아 있는 예외 셋 · 사유 둘 —
  `version-sort`(`sort -V` 두 곳 · M40이 *"macOS 레그 통과가 BSD 지원의 실측"*이라 유지 결정) ·
  `diagnostic-only`(진단 출력의 표시 순서라 판정에 쓰이지 않는다 · M41 후속 11이 같은 사실을 기록).
  여기에 **검사 자신의 픽스처 문자열**이 하나 더 붙었다 — 첫 실행에서 **검사가 자기 소스를 물었고**
  (`fixture-string`) 그것이 이 메커니즘의 첫 사용 사례다(`F5`·`G1`이 M44에서 같은 일을 했다).
- **사이트의 종결 문자도 명세에 든다**: 명령 뒤에 **공백·`)`·`;`·`|`·`#`가 오거나 줄이 끝나면** 사이트다.
  첫 판본은 공백·줄끝만 봐서 `$(cat x | sort)`·`$(sort)`·`| Sort-Object  # 주석`을 **검출하지 못했고**,
  그것이 리뷰 차단 2의 **실제 기전**이었다(`Ordinal` 탈출구와는 별개의 누락이다).
- **공백 집합을 양 사본이 같은 명세로 쓴다**: **ASCII 공백과 탭**뿐이다(`run.sh`는 `[[:blank:]]` @
  `LC_ALL=C`, `run.ps1`은 `[ 	]`). 첫 판본은 `[[:space:]]` ↔ `\s`로 갈려 있었는데 그 둘은 무는 폭이
  달라 **그 자체가 두 셸 갈림의 씨앗**이었다(리뷰 반환 2).
  - **M49-T02 이전까지 이 문장은 `run.ps1`에서 거짓이었다.** `sh`는 M48 재작업 1에서 `COMMENT_RE`
    하나로 통일됐으나 **ps1 사본은 술어 선언처가 둘**이었고, 이 파트가 쓰던 자리는 `IsCommentLine`이
    아니라 인라인 `TrimStart().StartsWith('#')`였다 — .NET의 인자 없는 `TrimStart()`는 **모든 유니코드
    공백**(U+00A0·U+3000 …)을 벗기므로 위 명세보다 **넓다**(M48 리뷰 이슈 2의 실측. 그때 살아 있는
    입력이 0건이라 어느 케이스도 붉지 않았다). M49-T02가 `IsCommentLine` 정의를 이 파트 **앞으로**
    옮기고 인라인 술어를 그 호출로 바꿔 **ps1 사본의 선언처를 하나로** 만들었다 — 좁은 쪽이 옳다
    (POSIX 셸에서 `#` 앞에 공백·탭이 아닌 바이트가 있으면 그 `#`은 주석 시작이 아니다).
  - **`F17`이 그 폭을 픽스처로 문다** — U+00A0으로 시작하는 주석 줄에 미고정 사이트를 심으면 양
    사본이 **똑같이 1건으로 잡는다**. 픽스처 바이트는 `run.sh`가 8진(`\302\240`), `run.ps1`이 같은
    코드포인트 인코딩으로 만든다(`F5`의 ASCII-only 규율 때문에 ps1 쪽은 리터럴을 쓸 수 없다).
- **판정은 줄 자체로 한다**: 첫 판본은 사이트를 `파일:줄번호:본문`으로 이어 붙인 뒤 콜론으로 다시
  쪼갰고, **경로에 드라이브 콜론이 있는 ps1 사본에서 그 쪼개기가 어긋나** 주석 제외가 죽었다
  (리뷰 차단 1 — 같은 트리에서 bash 158/0 · pwsh 157/1). 이제 파일별 스캔 안에서 **줄 자체를 보고**
  판정하고 경로는 보고용으로만 앞에 붙인다 — 콜론 파싱이 사라져 그 부류가 **구조적으로** 닫혔다.
- **오탐 표면**(규약이 같은 문장으로 적는다): 종결 문자에 `;`·`|`·`)`가 들어가므로 **따옴표 안 산문**이
  명령처럼 보이면 잡힌다(실측: `msg="pipe into | sort; then dedupe"` → 양 사본이 미고정으로 보고).
  셸 인용은 줄 단위로 배제할 수 없어 **정적으로 걸러내지 않는다** — 오탐은 즉시 붉어지므로 사람이
  문장을 바꾸거나 `locale-exempt:`로 결정을 남긴다.
- **경계**(규약이 같은 문장으로 적는다): 판정은 **줄 단위**라 `LC_ALL=C sort … | uniq`처럼 **파이프 뒤
  두 번째 명령의 개별 고정**은 묻지 않는다 · 변수 경유 호출·`eval`·다른 로케일 민감 도구(`join`·`comm`)는
  대상 밖 · `.ps1`의 광범위 비교 API는 위 명세의 이유로 대상 밖이다.
- **추출 통제와 픽스처 통제를 계열별로 둔다**(`F10`·`F11`·`F12`·`F13`) — 첫 판본은 사이트 수를 두 계열의
  **합**으로 세서 한쪽 추출이 망가져도 초록이었고(R5 실측) 픽스처도 `.sh`뿐이라 ps1 검출기의 비공허성에
  하니스 안 통제가 없었다(리뷰 권장). ps1 쪽 사이트가 0이 되면 `F11`이 붉어진다 — 전부 헬퍼로 바뀌는
  것은 개선이지만, 그때 검사가 조용히 공허해지는 대신 **사람이 명세를 다시 정하게** 한다.

### Part G — 상호참조 무결성 (M34 · M35에서 파일 집합으로 일반화 · M41에서 자기참조 편입 · M42에서 규약 집합 밖 대상 편입 · M44에서 하위 인덱스 금지, sh·ps1 동일, 16 케이스)

Part F가 문서의 **자기서술**을 집행한다면 Part G는 문서 **사이를 잇는 참조**를 집행한다. 단일 원본은
`docs/conventions.md`의 "상호참조 무결성" 절.

**G-0. 규약 문서 집합 발견** — 규약은 한 파일이 아니라 **문서 집합**이다(본체 + `docs/conventions-{주제}.md`
조각). 그래서 대조 대상을 글롭 `docs/conventions*.md`로 **발견**한다 — 러너에 목록을 하드코딩하지
않으므로 조각을 더해도 러너를 고칠 일이 없다(하드코딩 금지가 이 규약의 요점이다). 순회 순서는 양 셸이
같도록 고정한다(sh는 `LC_ALL=C sort`, ps1은 ordinal 정렬). 조각이 하나도 없으면 집합은 본체 하나뿐이라
일반화 **이전과 같은 판정**이 나온다(M35 회귀 고정).

**G-1. 인용 → 앵커 실재(파일별 대조)** — 살아 있는 문서(`skills/*/*.md`·`docs/*.md`·`README.md`·
`site/docs/*.md`·`tests/*/README.md`)에서 **인용 골격**(규약 파일명이 든 줄의 따옴표 구획)을 **추출**해,
**그 줄에 등장한 규약 파일**의 `##`·`###` 제목 집합에 **전부 실재**하는지 단언한다. 앵커는 **파일별로**
묶여 있으므로, 절이 조각으로 옮겨 가면 인용도 **그 조각의 파일명**을 가리켜야 통과한다 — 파일을 옮기고
인용을 안 고치면 잡힌다(이 일반화의 핵심 가치). 한 줄에 규약 파일명이 둘이면 **어느 쪽 앵커 집합에든
있으면 통과**로 본다(안전 측 — 오탐을 만들지 않는다). 대조 전 **공백만 제거**해 정규화한다
(`버전·CHANGELOG` ≡ `버전 · CHANGELOG`). 두 가지는 인용이 아니라 제외한다 — **스니펫 인클루드
지시어 줄**(`8<--`)과 **중괄호가 든 따옴표**(골격 예시의 자리표). `docs/milestones/*`·`docs/reports/*`는
역사 기록이라 대상이 아니다(`docs/*.md` 글롭이 하위 디렉터리를 잡지 않아 자연히 제외된다).

**G-2. 통제** — 인용 추출 0건·앵커 추출 0건이면 **FAIL**(루프가 통째로 공허 통과하는 것을 차단,
F3·M27 positive-control 선례), 가짜 이름(`bogus-section`)이 **집합 어디에도** 없음, `##`·`###` 제목이
정규화 후 **집합 전체에서 유일**(중복 0 — 파일이 갈려도 같은 이름을 두 곳에 두지 않는다. 겹친 이름을
가리키는 인용은 어느 쪽인지 결정할 수 없다).

스크립트에 한글 리터럴을 두지 않는 **데이터 기반** 검사라 ps1의 ASCII-only 규율과 정합한다.
PowerShell의 `-contains`·해시테이블 키는 기본이 **대소문자 무시**라 `grep -x`와 갈리므로,
`HashSet[string]`(ordinal)로 맞춰 양 셸이 같은 판정을 내리게 했다 — 파일별 앵커 집합도 파일마다
`HashSet[string]` 하나씩(sh는 파일별 앵커 파일 하나씩)이고, 파일 키는 **인덱스**다(파일명에 공백이
들어도 레코드가 깨지지 않도록).

**G-3. 줄바꿈 인용 통제** — 후보 줄의 따옴표가 **미종결**(홀수)이면 인용이 다음 줄로 넘어간 것이고,
줄 단위 추출에서 **조용히 빠진다**. 그런 줄이 0이어야 통과한다(= 인용은 **한 줄 안에** 쓴다).

> **알려진 잔여 한계**: G3는 줄바꿈이 **따옴표 구획 안**에서 일어난 경우만 잡는다. 파일명은 앞 줄에,
> 따옴표 구획은 **통째로 다음 줄**에 오는 형태는 후보 줄의 따옴표 수가 짝수(0)라 잡히지 않는다 —
> 파일명만 언급하는 정상 줄과 구별할 수 없기 때문이다(그런 줄을 FAIL로 두면 경로를 언급하는 모든
> 문장이 걸린다). 인용을 한 줄에 쓰는 규율이 1차이고 G3는 그 백스톱이다.

**G-4. 자기참조 해소**(M41) — 같은 파일 **안의** 자기참조(`위/아래 "{앵커 이름}" 절`)도 집행한다.
M34가 상호참조 무결성을 신설하며 *"골격에 파일명이 없어 가드 밖 — 사람의 리뷰 영역"*으로 남긴 층이고
**여섯 사이클** 동안 그대로였다.

- **범위는 `living_docs`다 — G1과 같다.** 규약 문서 집합만 보면 규약이 "닫혔다"고 적은 층이
  `skills/`·`README.md`·`tests/*/README.md`에서 **그대로 열려 있다**. 그 상태로 고지를 지웠다가
  **M41 라운드 1이 차단을 받았다**(규약 밖에 깨진 자기참조를 심어도 초록이었다).
- **대조는 그 파일 자신의 앵커 집합**이다. 자기참조는 정의상 같은 파일을 가리키므로 집합 전체와
  대조하면 **다른 파일의 절을 가리켜도 통과**한다 — 좁은 범위에서 안전 측이던 선택이 범위를 넓히면
  과대 허용으로 뒤집힌다(라운드 1 → 2에서 바꾼 것).

| 후보 좁히기 | 후보 | 오탐 | 판정 |
|---|---|---|---|
| `"{앵커 이름}" 절` + 백틱 경로 없음 + **줄·앞줄에 규약 파일명 없음** | **46** | **0** | 집행(현행) |
| 위에서 "줄에 규약 파일명 없음"을 뺌 | 50 | **4**(마크다운 링크 인용) | 오탐 |
| 위에서 "앞줄에 규약 파일명 없음"을 뺌 | 50 | **3**(줄바꿈 인용) | 오탐 |
| `절` 표지 없이 따옴표 구획 전부(규약 집합 기준) | 165 | **100+** | 집행 불가(평범한 산문) |

- **기계가 묻지 않는 것 넷**(규약이 양쪽에서 열거하는 저쪽): ① `절` 표지를 쓰지 않은 자기참조
  ② 백틱 파일 경로를 함께 언급하는 자기참조 ③ **규약이 아닌 파일로의 인용 중 골격을 쓰지 않은 것**
  (골격으로 **파일명을 명시한** 것은 M42가 `G5`~`G7`로 집행한다 — 회고의 *"인용 규약의 문서 일반
  확대"* 후속은 그때 닫혔다. 파일명이 없으면 대조할 파일을 정할 수 없어 남는다)
  ④ **파일명 없이 쓴 규약 인용 중 그 이름이 자기 파일에도 앵커로 있는 것**(아래).
- **자기참조와 파일명 없는 인용은 원리상 구별되지 않는다(④)** — 그 줄에 규약 파일명이 없으면 어느
  쪽인지 알 수 없다(구별 정보가 그 줄에 없다). 파일명이 없어지는 길은 **둘**이고 둘 다 같은 자리로
  떨어진다 — **㉮ 줄바꿈으로 떨어져 나간 경우**(G3가 사각으로 고지한 성질. 앞줄 검사는 한 줄만 보므로
  두 줄 이상 앞은 못 본다) · **㉯ 애초에 골격을 안 쓴 경우**(`규약의 "{앵커 이름}" 절` — **G1도 보지
  못한다**. G1의 후보 줄 조건이 파일명이다). 그때 이 파트는 그 구획을 자기참조로 취급해 **자기 파일
  앵커에 대조**하고, 결과는 **이름이 우연히 그 파일에도 있는가**로 갈린다 — 있으면 조용히 통과(④),
  없으면 FAIL.
  - **실측(둘 다)**: `site/docs/concepts.md`에서 그 파일이 **자기 앵커로 가진 이름**(`tide-guard hook`)을
    ㉮ 파일명을 두 줄 앞에 두고 끊어 쓰거나 ㉯ 한 줄로 파일명 없이 쓰면 **둘 다 초록**이고, 각각 그
    파일에 **없는 이름**으로 바꾸면 **둘 다 FAIL**이다. 발행 페이지가 규약 절 이름을 미러링하는 것은
    정상 형태이므로 **이 예외는 드물지 않다.**
  - **이 문단의 예시가 자리표 표기를 쓰는 이유**: 예시에 **실제 이름**을 그대로 적으면 이 파트가
    그것을 살아 있는 자기참조로 읽어 이 README가 붉어진다(리뷰 중 실측으로 걸렸다). 골격 예시는
    중괄호 자리표로 쓴다 — 규약의 인용 골격 항목이 정한 그대로다.
  - **㉯가 실재한다는 것은 이 사이클이 실증했다** — M41이 고친 두 결함(`skills/debug/SKILL.md`·
    `tests/multi-repo/README.md`)이 정확히 그 형태였다.
  - **창을 넓혀도 닫히지 않는다** — 앞줄 창 1 → 2 → 3에서 후보 46·미해소 0으로 **값이 동일하고**
    (실측), 창이 N이면 N+1줄 앞은 여전히 못 본다. **경계가 옮겨질 뿐이라 창은 1로 둔다.**
- **실패하면 이름을 찍는다** — `↳ 미해소 자기참조 또는 끊긴 인용: <파일> → <이름>`(ps1은
  `-> unresolved self-reference or wrapped citation:`). **두 가지를 뜻한다** — 어느 쪽인지는 사람이
  그 줄과 앞 줄들을 보고 가른다(어느 쪽이든 고칠 것이 있다). 수를 세는 단언이 붉어져도 원인을
  말하지 않는 문제는 M40에서 겪었다.
- **한글 리터럴은 데이터로 조립한다** — `run.sh`는 `printf '\354\240\210'`, `run.ps1`은 `Uni 0xC808`로
  U+C808을 만든다(ps1의 ASCII 전용 원본 규율 유지 — `종`·상태값과 같은 방식).

**G-5. 규약 집합 밖 대상도 대조한다 (M42)** — G1의 대조 집합은 `docs/conventions*.md`의 앵커뿐이라,
`skills/*/SKILL.md`·`docs/*.md`를 가리킨 인용은 **어느 가드도 보지 않았다**(네 사이클 미반영). 인용
골격이 **파일명을 명시**하므로 대조는 **그 파일 자신의 앵커**로 하면 된다. 이름 **유일성은 규약
집합에만** 유지한다 — 살아 있는 문서 전체로 넓히면 무관한 문서 사이의 이름 충돌이 터진다.

- **골격의 조사를 요구한다**: 경로 백틱 **바로 뒤의 `의`**가 없으면 뒤따르는 따옴표 구획이 그 경로를
  가리킨다는 근거가 없다. **실측 오탐 1건**이 이 조건을 정했다 — 경로를 적은 뒤 **자기 파일**의 절을
  `위 "{앵커 이름}" 절`로 가리키는 줄(그 자리는 G4가 무는 자기참조다). 조사 문자는 `Uni 0xC758`/8진 이스케이프로
  조립한다(G4의 `절`과 같은 방식 — ps1의 ASCII 전용 원본 규율 유지).
- **대상 파일이 레포에 없으면 대조하지 않는다** — Part G는 **앵커**를 묻지 경로의 실재를 묻지 않는다.
- **처음 돌렸을 때 붉었다**: 살아 있는 문서에 **세 자리**가 어긋나 있었고(M41이 사람 눈으로 찾은 하나 +
  이 검사가 처음 드러낸 둘) 셋이 전부 같은 짧은 이름으로 합의하고 있어 **제목을 인용에 맞춰** 닫았다.

**G-8. 절 안의 항목은 번호가 아니라 이름으로 가리킨다 (M44)** — Part G의 나머지는 **절 앵커까지만**
대조하므로 **하위 인덱스**는 어느 케이스도 보지 않았다. M43 리뷰 이슈 5가 그 부류다 — 원장의 인용이
`묻지 않는 것 ⑷`를 가리켰는데 그 번호는 **M40이 닫아 없앤 항목**이었고, 인용을 옮긴 편집이 하류를
함께 고치지 않아 생겼다. 이제 인용 줄에서 `절` 표지 **뒤에** 오는 열거 번호를 **0건**으로 고정한다.

- **무는 문자 집합의 명세**: **U+2460~U+2487**(`①`~`⑳` · `⑴`~`⒇`, **40자**). 양 러너가 같은 집합을
  쓰는지 **각자 단언**한다 — `run.sh`는 40줄·160바이트(줄바꿈 포함), `run.ps1`은 원소 40개·문자당
  1코드포인트. 두 사본 모두 **코드포인트로 조립**하므로(`run.sh`도 리터럴을 두지 않는다) 집합이
  구성상 일치한다. 이 자기 단언이 없으면 한쪽 집합이 조용히 좁아져도 초록이다.
- **금지형이고, 통제 둘이 공허를 막는다**: 살아 있는 사이트가 **0건**이라 *"번호가 가리키는 항목이
  실재하는가"* 를 추출형으로 세우면 추출이 0이라 정상 트리가 붉어진다. 그래서 **금지형**(부재 단언)으로
  세우되 **금지형도 훑을 대상이 비면 공허하므로** 둘을 함께 단언한다 — ⑴ **인용 줄 추출이 0건이면
  FAIL**(`G8b0` — `cite_lines_of`의 정규식이나 `living.txt` 범위가 망가지면 `G8b`가 `0 == 0`으로
  통과하는 것을 막는다. G2·G4·G6의 추출 통제와 동형) ⑵ 위반 한 줄을 주입한 픽스처가 **실제로
  잡히는지**(`G8c` — M43 이슈 5의 실제 형태 `⑷`를 재현한다).
- **경계**(규약이 같은 문장으로 적는다): ⑴ 번호가 `절` **앞**에 오는 산문 열거 참조는 대상이 아니다
  (실측: 살아 있는 인용 줄 중 **1건**이 그 형태이며 정당하다) ⑵ **이름으로** 가리킨 항목의 실재는
  대조하지 않는다(실측: 살아 있는 사이트 **5건** · 관측된 결함 **0건**이라 2단 해소를 세울 근거가 아직
  없다) ⑶ 인용과 번호가 **다른 줄로** 갈리면 빠진다(*"인용은 한 줄 안에 쓴다"* 와 같은 한계).

검증: G1 1 + G2 4(인용 추출·앵커 추출 positive-control, 가짜 이름 부재, **집합 전체** 이름 유일성) +
G3 1 + **G4 3**(자기참조 해소 · 추출 positive-control · 가짜 이름 음성 통제) + **G5~G7 3**(규약 밖
인용 해소 · 추출 positive-control · 주입한 깨진 인용 검출) + **G8 4**(문자 집합 자기 단언 · **인용 줄
추출 positive-control** · 위반 0건 · 주입 픽스처 검출) = **16**. M35의 일반화는 Part G **내부
구현**만 바꾼 것이라 케이스 수를 늘리지 않았고, M41의 G4와 M42의 G5~G7, M44의 G8은 **새 층**이라 늘렸다.

### Part H — 실행 환경 축 선언 정합 (M38 · M39 · M40, sh·ps1 동일, 18 케이스)

Part B~G가 **문서 사이**의 드리프트를 집행한다면, Part H는 **검증이 도는 실행 환경 자체**의 선언을
집행한다. 단일 원본은 `docs/conventions.md`의 "실행 환경 축" 절 — 각 축에 **이름 · 두 극 · 집행처**가
적히고, 집행이 없는 축은 **"미집행"으로 명시**된다.

**축 이름의 ASCII 선언(이 하니스 쪽 사본)**:

<!-- env-axes: posix-shell powershell-runtime launch-context workflow-syntax external-tool -->

| 축 | 두 극 | 집행 |
|---|---|---|
| `axis:posix-shell` | dash ↔ bash | `job:posix` 3 OS |
| `axis:powershell-runtime` | 5.1 ↔ 7 | `job:powershell` 매트릭스 |
| `axis:launch-context` | Git Bash 호스트 ↔ 네이티브 호스트 | `tests/multi-repo/run.ps1` 시작 시 자기 탐침 |
| `axis:workflow-syntax` | 로컬 YAML ↔ GitHub 컴파일 | 실제 푸시 뿐 · `pr` 마무리가 태그 전 PR CI 조회 |
| `axis:external-tool` | GNU sed·awk ↔ BSD sed·awk | `job:posix` macOS 레그 |

`env-axes:` 선언 줄이 축 ASCII 이름의 추출 골격이고, **규약 쪽 선언이 원본**이다 — 이 README의
선언은 집합 일치 대조의 **상대편**이라 한쪽만 고치면 H3이 FAIL한다(Part C의 두 파일 집합 일치와 동형).
축 이름은 전부 ASCII 병기어라 `run.ps1`의 ASCII 전용 규율과 정합한다(Part F 역할 앵커와 같은
**데이터 기반** 방식 — 스크립트에 한글 리터럴을 두지 않는다).

**집행 칸이 CI 잡을 지목하는 축**은 그 잡의 실재까지 문다(M38 재작업 1). **M39부터 매핑의 단일
원본은 규약 표 행의 `job:<이름>` 토큰**이다 — 별도 `env-axis-ci-jobs:` 선언 줄은 표로 흡수돼
사라졌다(선언처 둘 → 하나). 이 README에는 **사본도 현재 값도 두지 않는다**(두 번째 선언처를 만들지
않기 위해서다). 잡 이름 집합은 `.github/workflows/tests.yml`의 `jobs:` 블록에서 **발견**한다(목록
하드코딩 금지).

`job:` 표기가 닫은 것: 집행 칸이 산문이던 동안에는 **실재하지 않는 이름을 잡인 것처럼 적어도**
검사에 닿지 않았다(기계가 임의의 백틱 토큰을 잡 지목으로 구별할 수 없었다 — 집행 칸에는 파일 경로
같은 정당한 백틱도 온다). `job:` 접두사는 그 모호함을 **표기가 붙은 참조에 한해** 없앤다 — 붙인 이상
H7이 실재를 문다. 같은 이유로 H8의 의미도 바뀌었다 — 표가 단일 원본이 된 뒤 "매핑된 잡이 표 행에
있는가"는 **항진명제**(공허 통과)라, 지금은 "표의 `job:` 토큰이 **선언된 축**의 행에 있는가"
(고아 토큰 0)를 묻는다.

**닫지 않은 것(M39 리뷰 실측 · 양 셸)**: 집행 칸의 **산문**이 실재하지 않는 잡을 주장하는 경우는
여전히 초록이다(**FAIL 0**) — ⑴ `job:posix`를 둔 채 같은 칸에 "CI `nowhere` 잡도 집행"을 덧붙여도
초록, ⑵ 토큰 없는 축의 칸을 "CI `nowhere` 잡이 집행"으로 바꿔도 초록. 다만 **실재하는** 잡을 표기
없이 산문으로만 적으면 그 잡이 미등재가 되어 **H11이 문다**(실측) — 남는 구멍은 정확히 "실재하지
않는 이름을 산문으로 주장하는 경우" 하나다. 표기가 바꾼 것은 **무엇을 잡
참조로 셀 것인가라는 정의**이지 오도 표면이 아니다. 그래서 아래 "묻지 않는 것"에서 이 항목을
**지우지 않는다** — 표기를 넣었다는 이유로 고지를 줄이는 것이 `vacuous-pass` 부류다(M39 리뷰가
이 자리를 차단으로 매겨 impl에 반환했고, 재작업 1이 그 고지를 되살렸다).

**등재는 옵트인이 아니다**(M38 재작업 2 · M39 확장) — 워크플로에 **실재하는** 잡은 어느 축 행의
`job:` 토큰으로 등재되거나 규약의 `env-axis-exempt-jobs:` 줄에 **면제로 선언**돼야 하고(H11),
둘 다 아니면 FAIL이다. 면제는 **침묵이 아니라 선언**이다 — 환경 축이 아닌 CI 잡(예: 양 셸 하니스
집합의 짝을 보는 `pairing`)을 축인 척 표에 올리는 것도, 아무 데도 안 적어 조용히 빠지게 두는 것도
틀렸다. 그래서 CI에 잡을 더하면 "축인가, 면제인가"를 **반드시 한 번 결정하게** 된다. 면제 선언도
낡을 수 있으므로 그 이름의 워크플로 실재를 H13이 문다.

**이 파트가 묻지 않는 것(정직 고지)** — 셋이다: ⑴ CI 잡을 **지목하지 않는** 집행 칸
(`launch-context`의 러너 자기 탐침 · `workflow-syntax`의 "실제 푸시 뿐 + `pr` 마무리의 PR CI 조회")이
오늘도 사실인지 ⑵ 잡을 지목한 칸의 **나머지 서술**(예: "3 OS" · "매트릭스" · "macOS 레그")이 실제
구성과 맞는지 — **매트릭스 레그는 기계에 보이지 않는다**(`job:` 토큰의 해상도는 잡 키까지다.
M40 리뷰 실측: `external-tool`의 집행처인 `macos-latest` 레그를 매트릭스에서 빼도 **107/0 초록**)
⑶ **집행 칸의 산문이 실재하지 않는 잡을 주장하는 경우**(위 "닫지 않은 것" 실측). 그 층은 **사람의
리뷰 영역**이다(Part C·D와 같은 분담). 규약의 "기계가 묻지 않는 것" 고지가 단일 원본이다.

**M40에서 닫힌 항목(넷째였던 미선언 표 행)** — `axis:` 표기(H14~H16)와 **데이터 행 수 == 표기 수**
(H17)가 표 쪽에서도 축을 세게 만들어 대조가 **양방향**이 됐다. **항목을 지우기 전에 세 공격을 양
셸에서 실측했다**: ⓐ 미선언 행에 `axis:` 표기를 적음 → **H15 FAIL**, ⓑ 표기가 아예 없는 **순수 산문
행**을 끼워 넣음 → **H17b FAIL**, ⓒ 선언된 축의 표기를 지움 → **H2·H15·H17b FAIL**. 또한
`external-tool`이 ⑴을 떠났다 — 미집행이던 자리에 `job:posix`의 macOS 레그가 붙었다.

이 경계를 지우거나 **항목 수를 줄이면서** "표가 실제 구성과 어긋나면 기계가
문다"고 적는 것이 `vacuous-pass` 부류다 — M38 리뷰가 이 자리를 **두 번**, M39 리뷰가 **한 번 더**
실측으로 반증했다(H6~H9 이전에는 `posix` 잡을 통째로 지워도 **90/0 초록**, H10·H11 이전에는
**선언된** 미등재 축이 실재 잡을 지목해도 초록, 그리고 ⑶은 `job:` 표기를 넣은 뒤에도 초록이다).
그래서 규약이 **고지 재산정 규율**을 두었다 — 줄이려면 실측이 먼저다. 위 ⓐⓑⓒ가 그 절차다.

검증: **H1** 축 이름 추출 positive-control(0건이면 FAIL — 루프가 통째로 공허 통과하는 것을 차단) 1 +
**H2** 선언된 축마다 규약 **표 행** 실재 1(선언만 늘리고 표를 안 고치는 것 = 집행력 과대 주장 차단) +
**H3** 집합 일치(규약 ↔ 이 README) 1 + **H4·H5** 가짜 축 이름(`bogus-axis`) 부재 음성 통제 2 +
**H6** 표의 `job:` 토큰 추출 positive-control 1 + **H7** 표가 적은 잡이 워크플로에 **실재** 1(CI에서
잡을 지우거나 이름을 바꾸면서 표를 두는 것을 차단) + **H8** `job:` 토큰이 **선언된 축의 행**에 있음
(고아 0) 1(미선언 행에 토큰을 숨겨 통과하는 것을 차단) + **H9** 가짜 잡 이름(`bogus-job`) 부재
음성 통제 1 + **H10** 커버리지 대조 positive-control 1 + **H11** 실재 잡의 **등재 또는 면제 선언** 1
(옵트인 회피 차단) + **H12** `job:` 토큰이 **없는** 선언 축의 실재 positive-control 1(토큰 부재가
"CI 잡 집행 없음"의 정직한 표기이므로 그 경로가 FAIL을 만들지 않음을 보인다) + **H13** 면제 선언된
잡의 워크플로 실재 1(낡은 면제 차단) + **H14~H16**(M40) `axis:` 표기 추출 positive-control 1 ·
표기 집합 == `env-axes:` 선언 집합 **양방향** 1 · 가짜 표기(`bogus-axis`) 부재 음성 통제 1 +
**H17a·H17b**(M40) 축 표 데이터 행 추출 positive-control 1 · **데이터 행 수 == 표기 수** 1
(표기 없는 행 = 표 안의 산문. 두 값이 0==0으로 공허 통과하지 않도록 행 수 자체의 positive-control을
함께 둔다) = **18**. 음성 통제는 Part B의 `${N+1}종` 부재 통제와
**동일 취지**다(가드의 구별력 입증).

> **H12가 붉어지는 조건(M39 리뷰 사소4 — 판단 기록)**: H12는 H1·H6·H10과 같은 부류의
> positive-control이고, 그것들처럼 **`>0`을 고정**한다. 따라서 **선언된 축이 전부 CI 잡을 얻으면
> 아무 문제가 없는데도 붉어진다.** 그 상태는 "무토큰 경로가 더는 없다"는 실제 구조 변화이므로,
> 그때는 통제를 **지우고 그 사실을 규약에 적는 것**이 옳은 처리다(수를 조작해 초록을 만드는 것이
> 아니다). 현재 무토큰 축은 3개(`launch-context`·`workflow-syntax`·`external-tool`)라 여유가 있다.
> 이 조건을 적어 두지 않으면 미래의 붉은 케이스가 **원인 불명의 FAIL**로 보인다.

### Part I — 축 상태 주장 정합 (M42, sh·ps1 동일, 20 케이스)

Part H가 축의 **선언**(이름 집합·표 행·잡 매핑)을 집행한다면, Part I는 그 축에 대한 **상태 주장**이
문서 안에서 갈라지는 자리를 집행한다 — 표는 집행된다고 적는데 산문은 반대로 적는 자리. 단일 원본은
`docs/conventions.md`의 "축 상태 주장 정합" 절.

근거는 실측이다: M41 사이클에 이 부류가 **세 건** 나왔고 그중 둘이 축 이름 부류였으며(`workflow-syntax`·
`external-tool`), **리뷰가 두 번 놓친 뒤** 다른 검사의 범위를 넓히다 우연히 드러났다. 카운트는 B1·F1이,
명단은 C-3·C-4가, 인용은 Part G가 물지만 **"두 문단이 반대되는 사실을 말한다"** 는 층에는 수단이 없었다.

- **POS** = 축 표의 `axis:` 토큰 중 **집행 칸이 살아 있는 것만**(칸이 비었거나 `state-neg:` 표지가 든
  축은 제외). 전체 토큰을 쓰면 규약이 **의무화한** 정직 표기가 곧 모순이 되어 **그 축의 표 행 자체가
  FAIL**한다(리뷰 실측). 파생 집합이므로 **자기 positive-control(I1b)** 을 갖는다 — H14가 무는 것은
  `axis:` 토큰 집합이지 이 부분집합이 아니라서, 표 형식이 바뀌면 POS가 비고 I2가 공허 통과한다.
- **NEG** = 살아 있는 문서의 **불릿 블록**에 축 이름과 `state-neg:` 표지가 함께 나타남. 축 이름은
  **블록 머리에서 상속**한다 — 부정어와 축 이름이 **같은 줄에 있는 경우가 오히려 드물다**(실측: 같은
  줄만 보면 M41의 두 건 중 하나를 놓친다).
- **빼는 것 둘**: 인용부호에 싸인 부정어(규칙 자체를 서술하는 문장)와 `state-past:` 표지가 든 줄
  (이력 서술은 오늘의 상태 주장이 아니다).
- **표지는 규약이 단일 선언처**이고 러너는 **읽기만 한다** — 스크립트에 한글 리터럴을 두지 않는 데이터
  기반 검사라 `run.ps1`의 byte>127=0 규율이 유지된다(F2·G4·`site-includes` 용어 추출과 동형).
  그 규율은 이제 **F5가 집행한다**(아래 Part F) — M42 재작업 3까지는 아무도 물지 않았다.
- **선언 줄의 형태와 유일성을 기계가 문다**(M42 재작업 1). 선언 줄은 **불릿 시작 직후에 백틱으로
  감싼 키**가 오는 형태이고, 그 형태의 줄은 키마다 **정확히 하나**여야 하며 **추출도 그 줄에서만**
  한다(I7·I8). 산문 언급은 키가 줄 앞머리에 오지 않아 구별된다 — 그 구별력 자체를 I9가 문다
  (판별자가 "아무 줄이나 잡는" 형태로 퇴화해도 우연히 1이 나올 수 있기 때문이다).
  - **왜 붙였나**: 이 검사가 없던 판본에서 **추출이 양 셸에서 갈렸다** — sh의 `sed "s/.*키//"`는
    탐욕이라 한 줄에 키가 둘이면 **마지막**을, ps1의 `IndexOf`는 **첫 번째**를 집었다. 실측: 선언
    줄에 키를 한 번 더 쓰는 한 줄 편집에 **sh는 129/0 초록**(표지가 통째로 사라져 I1~I3까지 자기
    정합적으로 통과)·**ps1은 붉음**이었다. 지금은 두 셸이 **첫 매치로 고정**돼 같은 값을 잡는다
    (같은 편집에 양 셸이 같은 184건을 낸다 — fail-loud). M38 리뷰 사소 4가 `cases:`에서 잡은
    부류의 재발이었고, M42 리뷰의 차단 2가 그것이다.
- **꼬리의 구분자도 기계가 문다**(M42 재작업 2 — I10~I13). 선언 줄에서 키 뒤 꼬리는 표지를 **ASCII
  공백 하나**로만 구분해야 하고, 탭·CR·NBSP처럼 **두 셸 중 어느 하나라도 공백으로 볼 수 있는 문자**가
  오면 양 셸이 함께 붉어진다(I10·I11). I12·I13은 그 금지가 공허하지 않음의 통제다(탭·NBSP 픽스처를
  실제로 잡는지).
  - **왜 붙였나**: 첫 매치를 고정한 뒤에도 **쪼개는 폭**이 갈려 있었다 — sh는 `tr ' '`(스페이스만),
    ps1은 `-split '\s+'`. 실측: 선언 줄 **끝에 탭 한 글자**(또는 표지 사이에 NBSP 하나)를 넣고 살아
    있는 문서에 **진짜 모순**을 심으면 **sh 132/0 초록**(모순 미검출) ↔ **ps1 131/1**이었다. 폭을
    맞추는 것만으로는 닫히지 않는다 — 폭 **밖** 문자는 양 셸이 나란히 표지를 잃어 다시 공허 통과가
    된다. 그래서 폭을 맞추고(양쪽 다 ASCII 공백 하나) **폭 밖 문자를 금지**했다. M42 리뷰의 차단 1이다.
  - **무는 것과 묻지 않는 것**: 무는 것은 구분자 집합(탭·수직탭·폼피드·CR·U+0085·U+00A0·U+1680·
    U+2000~200A·U+2028·U+2029·U+202F·U+205F·U+3000)이다. **표지 알파벳 자체는 묻지 않는다** —
    단일 원본은 `docs/conventions.md`의 "축 상태 주장 정합" 절이다.

**경계는 실측으로 정했다**(M42-T04): 창을 **불릿 블록**에 두면 후보 **2건·전부 참·오탐 0**이고, `##`
절로 넓히면 **7건**, 문서 전체로 넓히면 **17건**이다(한 블록이 여러 축 이름을 상속해 오탐이 배수로
는다). 표지에 `수단이 없다`·`닫을 수 없다`를 넣으면 2 → **10건**(오탐 7 — 로컬 가능성 서술은 집행
상태 주장이 아니다). 대상 동일성 조건을 없애면 부정 상태어가 든 **15줄**이 전부 후보가 되고 참은 0이다.
**회귀**: v2.14.0 트리(M41이 고치기 전)에서 후보 2건·전부 참, 현행 트리에서 0건.

검증: **I1** 표지 추출 positive-control 1 + **I1b** POS 추출 positive-control 1 + **I2** 살아 있는
문서 0건 1 + **I3** 주입 모순 검출 1 + **I4~I6** 통제 3(인용된 부정어 · 이력 서술 · 대상 없는
부정어는 잡지 않는다) + **I7·I8** 선언 줄 유일성 2(`state-neg:`·`state-past:` 각각 정확히 1개 —
0개도 2개 이상도 FAIL) + **I9** 통제 1(산문 언급은 선언처로 세지 않는다) + **I10·I11** 꼬리 구분자
금지 2(`state-neg:`·`state-past:` 각각 금지 구분자 0건) + **I12·I13** 통제 2(탭·NBSP 픽스처를 실제로
잡는다) + **I14** 규약이 선언한 구분자 전수 검출 1 + **I15** 통제 1(허용 문자는 잡지 않는다) +
**I16·I17** `sep-cps:`·`sep-ok-cps:` 추출 positive-control 2(비면 `I14`가 `0==0`으로 공허 통과한다) +
**I18·I19** 그 두 키의 선언 줄 유일성 2(0개도 2개 이상도 FAIL) = **20**.

> **묻지 않는 것(정직 고지)**: ⑴ 대상이 **축 이름이 아닌** 모순(M41의 세 번째 건이 여기 속한다 —
> 대상 식별자가 기계가 읽는 단일 원본에 없다) ⑵ 표지를 쓰지 않은 모순 ⑶ **반대 방향**(표가 미집행인데
> 산문이 집행한다고 적는 경우)은 오늘 발화 조건이 없어 실측하지 못했고 그래서 집행하지 않는다.
> 이 셋을 뭉뚱그려 "문서 안의 모순을 문다"고 적는 것이 `vacuous-pass` 부류다.

### Part J — 러너 소스의 변수 이름 경계 (M48, sh·ps1 동일, 6 케이스)

Part F의 `F5`(비-ASCII 0줄)·`F9`(로케일 고정)와 **같은 층위**다 — 문서가 아니라 **러너 소스**의 규율을
문다. `$이름` 바로 뒤에 다중바이트 문자가 오면 **셸 구현마다 이름 경계 판정이 갈린다**: 이 기계의
bash 5.2·`dash`는 이름을 거기서 끊지만 macOS가 `sh`로 쓰는 **bash 3.2는 뒤따르는 바이트를 이름에
포함**해 `set -u`에서 죽는다. v2.19.1 릴리즈 PR에서 **로컬 네 실행 환경도 우분투 CI도 전부 초록**인
채 macOS 레그 하나만 붉었다 — 경위와 실측 수치의 단일 출처는 `docs/reports/debug-2.md`이고 규율의
단일 원본은 `docs/conventions.md`의 "실행 환경 축" 절이다. **로컬에서 영원히 초록인 부류**라 사람의
눈이 아니라 기계가 물어야 한다.

- **무는 대상 집합의 명세**: `tests/`와 `hooks/` 아래 **모든 깊이**의 **정규 파일** 중 이름이 `.sh`
  또는 `.ps1`로 끝나는 것 — ⑴ 확장자 비교는 **대소문자 구분**(`.SH`·`.PS1`은 발견하지 않는다)
  ⑵ **숨김 항목도 본다** ⑶ 디렉터리는 세지 않는다. `ps1_files_in` 명세와 **같은 형태**이고 확장자만
  둘로 넓혔다 — 새 명세를 만들지 않고 **같은 명세를 재사용**한다. 이 셋이 갈리면 같은 트리에서 두
  사본의 판정이 갈린다(`F7` 항목이 그 실측을 적고 있다). 다만 **`F7`이 무는 것은 `ps1_files_in`이지
  이 파트가 쓰는 `runner_src_files_in`이 아니다** — 그 틈을 `J6`이 **자기 픽스처로 직접** 문다
  (M48 리뷰 권장 3의 처분). **`J6`이 무는 것은 디렉터리 하나의 명세이지 「어느 루트를 훑는가」가
  아니다** — 라운드 0이 실측한 구멍(루트에서 `hooks/`를 빼면 24 → 22 파일로 줄 뿐 양 사본 초록)은
  `J6`으로 닫히지 않았고, **리뷰 라운드 1이 `J1`을 루트마다 묻는 형태로 바꿔** 닫았다. 스캔 루트의
  단일 선언처는 러너의 `VARBOUND_ROOTS` 한 줄이고, 루트를 지우면 `J1`의 자리 수가 줄어 붉어진다.
- **판정**: 줄의 첫 비-공백 문자(**ASCII 공백·탭만**)가 `#`이면 **주석 줄이라 판정하지 않고**, 나머지
  줄에서 `$` + 이름 첫 글자 `[A-Za-z_]` + 이름 나머지 `[A-Za-z0-9_]*` 직후에 **byte>127**이 오면
  위반이다. CR(byte 13)은 무시한다. **판정은 함수 하나에만 있다** — 실물(`J3`)과 픽스처 통제
  (`J4`·`J5`)가 **같은 함수**를 부른다(M46의 `F16`이 판정을 재구현해 동어반복이 됐던 자리다).
- **중괄호 형태는 구조적으로 대상이 아니다**: `${이름}`은 `$` 다음이 `{`라 판정식이 매치하지 않는다.
  이것을 구별하지 못하면 **정상 코드가 붉어진다** — `J5`의 앞자리가 그 성질을 문다.
- **주석 줄을 제외하는 이유(실측)**: M48-T01의 원시 매치 다섯이 **전부** 주석이었고, 그중 하나는
  **이 규율 자체를 설명하는 주석**이라 제외가 없으면 규율을 적은 자리가 규율 위반으로 붉어진다.
  수치의 단일 출처는 `docs/reports/M48-impl.md`다.
- **양 사본이 같은 바이트를 본다**: `run.sh`는 8진 이스케이프 클래스(`F5`가 쓰는 `NONASCII_RE`를
  **재사용**한다 — 두 곳에서 따로 만들면 두 번째 선언처가 생긴다)를 `LC_ALL=C`로 고정하고,
  `run.ps1`은 원시 바이트를 읽어 ISO-8859-1로 U+0000~U+00FF에 1:1 대응시킨 뒤 코드포인트로 조립한
  범위를 쓴다. **원본은 ASCII로 남는다**(`F5`가 무는 그 규율이다).
- **픽스처는 샌드박스에서 바이트로 조립한다**: 위반 문자열을 러너 소스에 **리터럴로** 쓰면 이 검사가
  **자기 자신을 문다** — M45의 `F12`·`F13`이 정확히 그 자리를 밟았고 그때는 `locale-exempt:` 선언으로
  처분했다. 여기서는 선언 없이 **소스에 그 바이트를 두지 않는 것**으로 닫는다(`run.sh`는 8진 이스케이프,
  `run.ps1`은 바이트 배열). 픽스처를 `tests/`·`hooks/` 아래에 두면 발견 집합에 섞여 `J3`이 붉어지므로
  반드시 샌드박스 안에 둔다. 심는 바이트는 U+AC74이고 **양 사본이 같은 바이트**를 쓴다.
- **살아 있는 위반이 0건이라 금지형이다**: *"위반 0건"* 단언만으로는 공허하므로 픽스처 통제 둘이 그
  공허를 막는다(`G8`과 동형).

검증: **J1** 러너 소스 발견 positive-control 1(**루트마다** 묻는다 — 발견이 0이면 아래가 `0 == 0`으로
공허 통과하고, 루트가 통째로 빠지면 자리 수가 줄어 붉어진다) +
**J2** 스캔한 파일 수 == 발견한 파일 수 1(`J1`이 보지 못하는 축 — *"발견은 다 하고 소비에서 전부
흘림"*. 소비는 직렬화한 목록을 되읽고 이 비교는 **새 열거**와 맞춘다. `F6`과 동형) + **J3** 실물
위반 0건 1 + **J4** 통제 1(심은 경계 위반을 잡는다) + **J5** 통제 1(중괄호 형태와 주석 줄은 잡지
않는다 — 기댓값 `1/0`의 앞자리는 **원시 매치**, 뒷자리는 **판정 결과**라 한 케이스가 두 축을 문다) +
**J6** 통제 1(**발견 명세**를 픽스처로 문다 — 샌드박스 트리에 `runner_src_files_in`을 그대로 걸고
**정렬된 basename**을 대조해 대소문자 구분·숨김 포함·디렉터리 제외 세 축을 한 번에 본다. 수가 아니라
**이름**을 보는 이유는 숨김을 빠뜨리고(-1) 대문자를 더하면(+1) 개수가 상쇄되기 때문이다 — `F7`과
같은 형태다) = **6**.

> **묻지 않는 것(정직 고지)**: ⑴ 판정이 **정적**이라 **변수 경유·`eval`로 조립한 명령**은 보지 못한다
> ⑵ **주석 줄 안의 같은 형태**는 묻지 않는다(실행되지 않으므로 결함이 아니다) ⑶ 이 검사는 **형태**를
> 물지 그 줄이 BSD에서 실제로 도는지를 묻지 않는다 — 실행 확인은 CI의 macOS 레그가 유일한 자리다
> ⑷ `.sh`·`.ps1` 밖의 파일(`hooks/hooks.json`·문서)은 발견 명세에 들어 있지 않다.

### Part K — 하니스 공통 통제 보유 대조 (M48, sh·ps1 동일, 6 케이스)

**기존 하니스가 공통으로 가진 통제를 새 하니스가 빠뜨린다** — M47 사이클의 반환 **셋이 전부 이
부류**였고(자기 `cases:` 미대조 · 선언 줄 유일성 미단언 · `ps1` 완주 가드 미보유) 그 대조를 지금까지
**사람이 매번** 했다. 단일 원본은 `docs/conventions.md`의 "새 하니스가 갖출 공통 통제 (목록 대조 — 기계가 문다)" 절이며, 이 파트는 그 절의 선언 블록을 **읽기만** 한다.

- **선언 추출 명세**: 줄 선두가 `<!-- harness-control: `이고 줄 끝이 ` -->`인 줄. 필드 구분자는
  ` :: `(공백·콜론콜론·공백)이고 순서는 **통제 이름 · `sh` 토큰 · `ps1` 토큰 · 면제 쉼표목록**이다.
  **토큰은 고정 문자열로 대조한다**(정규식이 아니다 — 값에 `$`·`{`·따옴표가 들어 있어 정규식으로
  읽으면 뜻이 달라진다). `-`는 *그 셸에는 요구하지 않음*, `none`은 *면제 없음*이다. 선언 줄은
  **네 필드를 다 갖고 어느 필드도 비어 있지 않아야** 한다(`K2`의 뒷자리) — 빈 넷째 필드는 *면제 없음*과
  *적는 것을 잊었다*를 구별하지 못해 규약의 *"빈 칸으로 두지 않는다"* 가 무집행이 된다.
- **토큰 대조는 주석 줄이 아닌 줄에서만 한다**: 술어는 **Part J와 같다**(줄의 첫 비-공백 문자가 `#`).
  주석까지 세면 `cases:`가 **일곱 하니스 전부의 주석에** 있어(하니스마다 복붙된 정형 문구다) **실제
  대조 코드를 잃어도 보유로 판정**됐고, 그래서 이 파트가 자기 존재 이유로 든 M47 1회차 반환을 정작
  막지 못했다(M48 리뷰 차단 2). 주석 제외 후에도 **면제 집합은 그대로**고 일곱 하니스가 전부 보유다 —
  수치의 단일 출처는 `docs/reports/M48-impl.md`다.
- **무는 대상 집합의 명세(하니스 발견)**: `tests/` **바로 아래(깊이 1)** 디렉터리 중 `run.sh`와
  `run.ps1`을 **둘 다** 가진 것. 러너가 없는 디렉터리(`tests/lib`)는 하니스가 아니라 제외되고,
  점으로 시작하는 디렉터리도 제외된다(POSIX 글롭 의미를 `run.ps1`이 **점 필터 + `-Force`** 로
  맞춘다 — 점 필터만 쓰면 `sh`의 글롭은 **숨김 속성 디렉터리를 보는데** `run.ps1`은 보지 못해 두
  사본의 열거가 갈린다. Part B의 `skills/*/SKILL.md` 글롭이 같은 자리를 이미 한 번 데었다).
  이름 비교·정렬은 `LC_ALL=C`/ordinal로 고정한다. **하니스가 늘면 대상이 는다** — 목록을 하드코딩하지 않는 이유가 그것이다.
- **판정 형태를 「규약 선언 읽기」로 택했다**: 하니스끼리 교차 비교하면 **기준 하니스가 낡을 때 같이
  낡고**, *"전 종이 빠뜨림"* 과 *"전 종이 보유"* 를 구별하지 못한다. 규약 선언 읽기는 대신 **선언 줄
  유일성**이 필요하며(`K2`) 그 선례가 `F14`·`I18`·`I19`다.
- **판정 함수는 하니스 목록을 인자로 받는다**: 실물(`K4`)과 픽스처(`K5`)에 **같은 코드**를 건다 —
  `F7`의 `ps1_files_in`·`F16`의 판정 함수와 같은 형태다. 픽스처를 검사 대상과 **다른 코드**로 재면
  그 픽스처는 아무것도 증명하지 못한다.
- **자기 참조**: `tests/discover` 자신도 대상 집합에 들어간다. 네 통제를 전부 보유하므로 역설이 없고
  **자기 제외를 넣지 않는다** — 자기를 빼면 이 검사는 자기 자신에게만 공허해진다.
- **면제는 침묵이 아니라 선언이다**: 면제 목록이 지목한 이름은 **실재하는 하니스**여야 하고(`K6`),
  하니스 이름이 바뀌거나 사라지면 면제가 고아가 되어 그 통제가 아무도 모르게 헐거워진다(Part H의
  면제 실재 검사와 같은 층).

검증: **K1** 선언 추출 positive-control 1(선언 블록이 사라지면 아래가 `0 == 0`으로 공허 통과한다) +
**K2** 통제 이름 유일성 + 선언 줄 형식 정합 1(**복합 기댓값** — 앞자리는 유일 이름 수, 뒷자리는
**네 필드를 다 갖고 어느 필드도 비어 있지 않은 줄 수**다. 뒷자리가 없으면 빈 넷째 필드가 `none`과
완전히 같게 동작한다) + **K3** 하니스 발견 positive-control 1 +
**K4** 면제를 뺀 모든 (하니스 × 셸) 조합의 토큰 미보유 0건 1 + **K5** 통제 1(토큰을 **주석에만** 가진
픽스처 하니스를 **같은 판정 함수**가 잡는다 — 기댓값 `1/caught`의 앞자리는 **발견 명세**를, 러너
하나뿐인 미끼 디렉터리는 하니스가 아님을 문다. 픽스처의 주석 줄은 **선언 블록에서 파생**하므로
토큰을 러너 소스에 리터럴로 두지 않는다) + **K6** 면제 실재 1(고아 0) = **6**.

> **묻지 않는 것(정직 고지)**: ⑴ 이 검사가 무는 것은 **토큰의 존재**이지 그 통제가 **실제로
> 동작하는가**가 아니다 — 토큰을 두고 도달하지 못하게 만들면 이 파트는 초록이다. 그 층은
> `tests/mutation`과 규약이 요구하는 **케이스별 되돌림 실측**(사람)이 덮는다. ⑵ **목록의 내용**은
> 사람의 판단이다 — 무엇을 공통 통제로 등재할지 잘못 정하면 검사가 **양 사본에서 나란히** 조용해진다.
> ⑶ 토큰이 **주석 줄에만** 있으면 보유로 세지 않지만(Part J와 **같은 술어**), 무는 것은 여전히
> **줄 단위 고정 문자열**이라 *주석이 아닌* 죽은 코드에 둔 토큰은 구별하지 못한다. M48 리뷰 차단 2가
> 닫은 자리가 앞쪽이다 — `cases:`가 일곱 하니스 **전부의 주석**에 복붙돼 있어 실제 대조 코드를 잃어도
> 초록이었다. 넓은 토큰의 위험 자체는 남으므로 규약이 `completion-flag`를 **대입문 형태**까지 좁혀
> 뒀고, 그 좁힘이 적용된 것은 **그 하나뿐**이다.

### Part L — 선언한 수 ↔ 열거 항목 수 (M49, sh·ps1 동일, 13 케이스)

**문서가 개수를 선언해 놓고 실제 열거가 그와 다르다** — M48 라운드 0의 차단 1이 이 부류였고, 그것은
**논리 결함이 아니라 편집 사고**였다(한 줄이 다른 줄을 통째로 덮어써 Part H 정직 고지의 항목 하나가
사라졌는데 서두는 그대로 셋을 선언하고 있었다). 그때 **하니스 7종 × 네 실행 환경이 전부 초록**이었고
어떤 가드도 그 자리를 보지 않았다. 단일 원본은 `docs/conventions.md`의 "선언한 수 ↔ 열거 항목 수" 절이며,
이 파트는 그 절의 표지 선언을 **읽기만** 한다.

- **표지 추출 명세**: 규약의 선언 줄 둘을 읽는다 — `count-word:`(수사와 값을 `=`로 잇는다) ·
  `count-copula:`(수사 **바로 뒤에 붙는** 조사). 러너 소스에 한글 리터럴을 두지 않기 위한 형태이고
  (`run.ps1`의 ASCII-only 규율), 기전은 Part I의 `state-neg:`·Part K의 `harness-control:`과 같다.
  각 키의 선언 줄은 **정확히 하나**여야 한다(`L1`·`L2`).
- **표지 앞 경계(낱말 경계)**: 표지가 성립하려면 **바로 앞이 줄머리이거나 ASCII 문자**여야 한다.
  경계 없이 찾으면 수사가 **다른 낱말 안에** 들어 있을 때 그것이 선언으로 잡힌다 — 한국어에서 열(10)·
  셋(3)·넷(4)은 흔한 낱말의 끝 음절이라, 그 낱말 뒤에 조사가 붙으면 표지와 **바이트가 완전히 같아진다.**
  M49 리뷰가 그 형태로 정상 문서를 붉히는 것을 실측했고(차단 1), `L12`가 **양방향**으로 못박는다.
  - **두 사본이 같은 답을 내는 근거**: `run.sh`는 `LC_ALL=C`라 앞 **바이트**를 보고 `run.ps1`은 앞
    **문자**를 보는데, 비-ASCII 문자는 UTF-8에서 마지막 바이트가 0x80 이상이므로 *"ASCII 문자"* 와
    *"ASCII 바이트"* 의 판정이 **모든 입력에서 일치한다**. 바이트 산술을 쓰지 않는 형태를 고른 이유가
    이것이다(이 저장소는 두 사본의 문자/바이트 의미가 갈리는 층에서 두 번 데였다 — M45의 경로 파싱과
    `debug-2`의 변수 이름 경계).
- **진단은 걸린 표지를 말한다**: 불일치 출력 형식은 `<파일>:<줄>:<표지>:<선언>/<실측>`이다. 수를 세는
  단언은 붉어져도 원인을 말해 주지 않아 M40에서 기전을 재현하지 못했고(그래서 Part G의 `G2`가 중복 앵커
  **이름**을 찍는다), M49 리뷰 차단 1의 재현에서도 `10/2`만으로는 원인이 보이지 않았다. `L13`이 이
  형식을 못박는다.
- **창(window)의 명세**: 선언이 있는 줄의 **나머지**부터 시작해, **빈 줄**(ASCII 공백·탭만 있는 줄)이
  나오거나 **선언 줄과 같거나 얕은 들여쓰기의 목록 항목**이 나오면 끝난다. 단, 그 목록 항목의 머리가
  동그라미 열거 기호면 창에 포함한다. 항목 수는 창 안에서 **1부터 이어지는 최대 구간**이며 두 계열
  (`⑴`~`⒇` = U+2474–U+2487 · `①`~`⑳` = U+2460–U+2473)을 **따로** 세고 큰 쪽을 쓴다 — 합치면 서로
  다른 열거가 한 열거로 뭉쳐진다.
- **왜 창이 이것 하나뿐인가(실측)**: M49-T01이 살아 있는 문서에서 후보를 뽑아 창 후보 셋을 재 봤다 —
  동그라미 열거로 잡으면 **오탐 0**이고, **뒤따르는 불릿 블록**으로 잡으면 전건이 어긋나며, **`·` 구분
  인라인 열거**로 잡아도 대부분 어긋난다(`·`가 이 저장소에서 열거 기호가 아니라 **범용 구분자**다).
  그래서 뒤의 둘은 **세우지 않는다.** 수치의 단일 출처는 `docs/reports/M49-impl.md`다.
- **대상 범위**: Part G와 **같은 살아 있는 문서 집합**이다 — `docs/milestones/*`·`docs/reports/*`는
  역사 기록이라 제외된다. 표지 선언 줄 자신은 대상이 아니다(선언처가 자기 표지에 걸리는 것을 막는다 —
  Part I와 동형).
- **양 사본의 폭을 맞춘 자리 둘**: ⑴ 빈 줄 판정과 들여쓰기 판정은 **ASCII 공백·탭**으로 고정한다
  (`run.sh`는 `LC_ALL=C awk`, `run.ps1`은 `[ 	]`와 `-notmatch '[^ \t]'`). `.NET`의 `Trim()`·`\s`를
  쓰면 유니코드 공백에서 두 사본이 갈리며, 그 부류를 실제로 데인 기록이 `F17`이다. ⑵ **빈 줄 판정의
  폭**이 곧 **창의 경계**다 — U+00A0만 있는 줄은 빈 줄이 **아니고**, `L11`이 그것을 픽스처로 못박는다
  (ps1의 `\s`는 유니코드 공백을 전부 빈 것으로 보므로 그 폭으로 넓히면 창이 거기서 끊긴다).
  - **줄 끝 CR은 `run.sh`가 벗기지만 그것은 케이스 없는 방어다.** `.gitattributes`가 LF로 못박은 것은
    `*.sh`뿐이라 `.md`는 CRLF로 체크아웃될 수 있고 POSIX awk는 그때 빈 줄을 CR 한 글자로 본다. 그런데
    **이 자리는 네 실행 환경 어디에서도 붉힐 수 없다** — `.md`가 CRLF가 되는 것은 Windows 체크아웃
    (`core.autocrlf=true`)뿐인데 거기서 `run.sh`가 쓰는 awk는 Git Bash의 gawk이고 그것은 파일을
    **텍스트 모드로 읽어 CR을 먼저 벗긴다**(M49-T04 실측 — bash·dash 둘 다 `length($0)`가 1이다).
    그래서 **공허한 케이스를 세우는 대신 못 무는 것을 적었다.** Part G의 `anchor_set`이 같은 이유로
    같은 형태(방어만, 케이스 없음)를 두고 있다.
- **공허 방지**: 후보가 **0건이 아니므로**(오늘 살아 있는 사이트가 여럿이다) **추출형**으로 세운다 —
  `L5`가 훑을 문서 집합을, `L6`이 **후보 추출**을 각각 물고, `L6`이 없으면 표지나 창이 망가진 순간
  `L7`이 **0 == 0으로 조용히 통과**한다.
  - **`L5`는 루트마다 묻는다**: *"발견이 0이면 FAIL"* 만으로는 **루트 하나가 사라지는 것**을 보지
    못한다(나머지 루트의 문서가 남아 수는 여전히 0보다 크고 훑는 범위만 조용히 줄어든다). M48 리뷰가
    정확히 그 형태를 `J1`에서 반환했으므로 여기서는 **다섯 부류**(`skills/` · `docs/` · `README.md` ·
    `site/docs/` · `tests/*/README.md`)가 전부 나타나는지를 단언한다. 부류는 **발견 함수가 돌려준
    경로에서** 분류한다 — 다시 발견하면 검사 대상과 다른 코드로 재는 것이 되어 아무것도 증명하지 못한다.
- **픽스처 통제는 실제 판정을 호출한다**(`L8`·`L9`): *"픽스처가 조건을 만족하는가"* 가 아니라
  *"실제 판정이 픽스처를 잡는가"* 를 묻는다(M46 리뷰 차단 #1의 판례). 픽스처 문자열은 **표지에서
  파생**시킨다 — 수사·조사를 러너에 리터럴로 적으면 ps1 사본이 ASCII-only 규율을 어기고, sh 사본은
  자기 소스에 자기 표지를 갖게 된다.
- **되돌림 실측(M49-T04)**: 새 케이스를 하나하나 개별로 무력화해 **양 사본에서 같이** 붉어지는 것을
  확인했다. 무력화 대상에는 **발견 함수 자신**(`living_docs`/`LivingDocs` — 어느 루트를 훑는가)이
  포함된다. 표는 `docs/reports/M49-impl.md`가 단일 출처다.

**검증**: `L1`·`L2` 선언 줄 유일성 2 + `L3` 표지 추출 positive-control 1 + `L4` 열거 기호 두 계열
자기 단언 1 + `L5` 살아 있는 문서 루트 다섯 부류 대조 1 + `L6` 후보 추출 positive-control 1 +
`L7` 본 검사(불일치 0건) 1 + `L8`·`L9` 픽스처 통제 둘(항목이 사라진 선언 · 항목이 늘어난 선언) 2 +
`L10` 음성 통제 1(열거 없음 · 수사와 조사가 떨어진 형태) + `L11` 창 경계의 폭 1(U+00A0만 있는 줄은 빈 줄이 아니다) +
`L12` 오탐 방향 음성 통제 1(수사가 낱말 안이면 표지가 아니다 / ASCII 공백 뒤면 표지다 — 양방향) +
`L13` 진단이 걸린 표지를 담는다 1.

**오탐 방향이 이 파트에 뒤늦게 선 이유를 적어 둔다** — `L1`~`L11`은 전부 *"검사가 죽는가"* 를 묻고
*"검사가 과하게 무는가"* 를 묻는 것이 **하나도 없었다.** 되돌림 실측도 같은 방향만 본다(토큰을 깨면
붉어지는가). M49 리뷰가 그 빈자리에서 차단 하나를 꺼냈고, `L12`가 그 자리를 메운다. **새 검사를 세울
때 두 방향을 다 세우는 것**이 이 사이클이 남긴 규율이다.

> **묻지 않는 것(정직 고지)** — 다섯이다: ⑴ **수를 선언하지 않고** 한 열거 ⑵ 선언과 열거가 **다른 절·
> 다른 문단으로 떨어진** 것 ⑶ 동그라미 기호를 쓰지 않은 열거(불릿·`·` 구분 — 위 실측이 창으로 세울
> 수 없다고 정한 자리다) ⑷ **항목의 내용이 맞는가**(무는 것은 개수의 일치뿐이다) ⑸ 표지 바로 앞이
> **비-ASCII 문자**인 자리(예: `·` 바로 뒤에 붙여 쓴 수사) — 위 표지 앞 경계가 낱말 안을 걸러 내며
> 함께 걸러지는 자리이고, 오늘 살아 있는 사이트는 **전건이 ASCII 공백 뒤**라 잃는 것이 없다.
> 그리고 **오탐이
> 하나 열려 있다** — 어떤 항목의 **본문**이 아직 등장하지 않은 다음 번호를 언급하면 그 번호까지
> 세어져 수가 부풀어 오른다(M49-T01이 픽스처로 재현했다). 오늘 살아 있는 사이트에 그 형태는
> **0건**이고, 규약이 같은 경계를 적는다. **그리고 케이스로 못박지 못한 방어가 하나 있다** — 줄 끝
> CR 벗기기다(위 "양 사본의 폭을 맞춘 자리 둘" 항목의 하위 불릿: Git Bash의 gawk가 텍스트 모드로 CR을
> 먼저 벗겨 이 저장소의 네 실행 환경에서는 붉힐 수 없다).

**두 사본은 같은 판정을 다른 비용으로 낸다** — `run.sh` 1회가 `run.ps1` 1회의 **십수 배**다(수치의
단일 출처는 `docs/reports/M50-impl.md`). 원인은 알고리즘이 아니라 **프로세스 생성**이다: `run.sh`는
외부 명령마다 새 프로세스를 띄우고 윈도우에서 그 비용이 하나당 약 30ms인 반면, `run.ps1`은 한
프로세스 안에서 끝난다. **실무 함의 둘** — ⑴ 되돌림 실측처럼 하니스를 수십 번 돌리는 작업은
**사본별로 비용을 따로 계산**해야 한다(합쳐서 어림하면 크게 틀린다) ⑵ 새 검사를 세울 때 **줄마다
프로세스를 띄우는 형태를 쓰지 않는다**(규약 "실행 환경 축"의 비용 규율). 개발 중 빠른 되먹임이
필요하면 `run.ps1`을 먼저 돌리고 `run.sh`는 확인용으로 쓰는 것이 이 비대칭을 쓰는 방법이다.

### Part M — 에픽(방향) 참조 정합 (M51, sh·ps1 동일, 14 케이스)

**사이클의 방향이 「직전 사이클이 남긴 후속 메모」가 아니라 「선언된 줄기」에서 오게 하는 장치다.**
마일스톤 51개의 `출처:` 줄을 부류로 나눠 보면 축이 좁아지는 것이 그대로 보인다 — *직전 사이클 보고서만
가리키는 것*이 M1~M40에서 **7.5%**였다가 M41~M51에서 **55%**가 됐고, 같은 구간에 네 릴리즈가 `skills/`를
한 파일도 바꾸지 않았다. 수치의 단일 출처는 `docs/reports/M51-impl.md`이고 규약의 단일 원본은
`docs/conventions.md`의 "에픽 (방향) 층" 절이다.

- **표지 추출 명세**: 규약의 선언 줄 셋을 읽는다 — `epic-status:`(열림/닫힘 값 집합) ·
  `epic-since:`(집행이 시작되는 마일스톤 번호) · `epic-members:`(등재 목록을 감싸는 **마커 이름**).
  러너 소스에 값을 두지 않기 위한 형태이고 (`run.ps1`의 ASCII-only 규율), 기전은 Part I의
  `state-neg:`·Part L의 `count-word:`와 같다. 각 키의 선언 줄은 **정확히 하나**여야 한다
  (`M1`·`M2`·`M11`).
- **무는 것 셋**(규약의 규칙 1~3과 같은 순서):
  ⑴ **열린 에픽이 하나라도 있으면** `epic-since:` 이상의 마일스톤은 `epic:` 참조를 갖는다
  ⑵ 그 참조가 **실재하는 에픽**을 가리킨다 ⑶ 에픽의 **역방향**과 **양방향 일치**한다.
- **양방향은 실제로 두 방향을 돈다**: 마일스톤 기준 순회만으로는 **에픽이 어떤 마일스톤을 자기
  줄기라고 주장하는데 그 마일스톤이 부인하는 자리**를 보지 못한다(M51 리뷰 차단 1이 정확히 이
  축의 부재였고, **되돌림은 구현되지 않은 축을 볼 수 없어** 그때 잡지 못했다). 에픽 기준 순회가
  셋을 문다 — ⑴ 등재된 마일스톤이 **실재하지 않으면** FAIL(고아) ⑵ 실재하되 **다른 에픽을
  가리키면** FAIL ⑶ `epic-since:` **미만이면 정상**(아래 소급 경계와 같은 이유다).
- **등재는 마커 블록 안만이다**: 규약이 `epic-members:`로 마커 이름을 선언하고 에픽이
  `<!-- {이름}:start -->`~`<!-- {이름}:end -->`로 여닫는다. 줄머리 `- M{N}`만으로 잡으면 에픽 본문의
  **평범한 산문 목록 항목**이 등재로 세어진다 — 공백으로 끊기는 형태(`- M46 — …`)는 토큰이 정확히
  `M46`이 되어 실재 마일스톤과 일치한다. **마커가 ASCII**라 창을 정확히 자르면서 `run.ps1`의
  byte>127=0 규율을 지킨다(`CHANGELOG.md`가 사이트 인클루드에 쓰는 것과 같은 기전).
- **소급하지 않는 경계**: `epic-since:` **미만**의 마일스톤은 대상이 아니다. 에픽 층이 없던 시절의
  산출물에 사후로 참조를 부여하면 **그때의 실제 의도가 아니라 재구성**이라 거짓 정합이 된다 —
  기계는 초록을 내는데 그 초록이 아무것도 뜻하지 않는다. 경계를 **번호 하나**로 적어 기계가 그것을
  정확히 알게 했다.
- **양방향으로 적는 것이 의도다**: 에픽은 세션 시작에 **혼자 읽는** 문서라 어느 마일스톤이 딸렸는지를
  51개를 훑지 않고 알아야 하고, 그 중복이 곧 **드리프트를 드러내는 대조 지점**이 된다(Part H의
  `job:` 토큰 양방향 대조와 같은 형태다).
- **역방향을 절 제목이 아니라 마커 블록 안의 줄머리 `- M{N}`으로 잡는다**: 절 제목은 한글이라 그것을
  매칭하면 러너 소스가 한글 바이트에 기대게 된다. 줄머리 형태를 쓰면 **양 사본이 문자 그대로 같은
  술어**를 쓴다.
- **하위 호환이 케이스로 걸려 있다**: 에픽이 하나도 없으면 위 셋은 **발동하지 않는다.** tide는 남의
  저장소에 얹는 물건이라 이것이 계약이고, `M9`의 뒷자리가 그 경로를 문다.
- **비용 규율을 지킨다**(M50): 판정은 **한 번 도는 `awk`**(ps1은 한 함수)가 에픽 목록과 마일스톤
  목록을 함께 읽어 낸다 — 파일마다 프로세스를 띄우지 않는다. 새 `awk`에 POSIX 밖 구문이 없다
  (`{n,m}` 인터벌 포함 0건)이고 `LC_ALL=C`가 같은 줄에 걸려 있다.
- **픽스처는 목록을 인자로 받는다**: 판정 함수가 **에픽 목록·마일스톤 목록 두 경로를 인자로** 받으므로
  픽스처가 살아 있는 목록을 덮어쓰고 되돌리는 형태를 쓰지 않는다 — 되돌림이 빠지면 뒤 케이스가
  조용히 픽스처를 보게 된다.

**검증**: `M1`·`M2`·`M11` 선언 줄 유일성 3 + `M3` 표지 추출 positive-control 1(뒷자리가 **없는 키로
같은 추출 경로를 한 번 더 태워** 그것이 비었다고 판정되는지 묻는다 — PowerShell의 null 통과 캐스트가
갈린 자리다) + `M4` 마일스톤 문서 발견 positive-control 1 + `M5` 본 검사(참조 불일치 0건) 1 +
`M6`·`M7`·`M8`·`M12`·`M13` 픽스처 통제 다섯(**마일스톤 기준** 셋: 실재하지 않는 에픽 · 끊긴 역방향 ·
열린 에픽인데 참조 없음 / **에픽 기준** 둘: 실재하지 않는 마일스톤 등재 · 남의 마일스톤 주장 —
다섯 다 **실제 판정을 픽스처에 건다**) 5 + `M9`·`M14` 오탐 방향 음성 통제 2(`M9` 정상 참조 / 에픽 없는
트리 · `M14` **블록 밖 산문은 세지 않는다 / 과거 마일스톤 등재는 붉지 않는다** — 둘 다 **양방향**) +
`M10` 이 저장소에 장치가 실재 1.

> **`M14` 앞자리의 겨냥을 픽스처가 어떻게 지키는가** — 블록 밖에 두는 줄은 **`epic-since:` 이상**의
> 마일스톤을 언급해야 한다. 미만을 쓰면 창을 지워 그 줄이 등재로 세어져도 바로 다음의 **과거 예외가
> 삼켜**, 통제가 창이 아니라 그 예외를 무는 자리가 된다. M51 라운드 1의 되돌림이 이것을 잡았다 —
> 창을 통째로 지운 변이가 **초록으로 돌아왔다**. 지금 픽스처는 `M13`과 **줄의 위치만 다른 한 쌍**이라
> (E2가 남의 마일스톤을 블록 밖에서 언급한다) 창이 없으면 `claim`이 난다.

> **묻지 않는 것(정직 고지)** — 넷이다: ⑴ **「이 마일스톤이 그 줄기에 정말 속하는가」**. *"무관한가"* 는
> 의미 판정이라 정적으로 물을 수 없다(M49의 「머리 위치」·M50의 「while-read 루프」와 같은 부류).
> 무는 것은 **참조의 존재·실재·양방향 일치**뿐이고, 거짓 참조는 문서에 남는 **눈에 보이는 진술**이라
> 리뷰의 영역이다 ⑵ **줄기 자체가 옳은가.** 방향을 고정하는 것과 좋은 방향을 고르는 것은 다른 일이며,
> 후자는 회고와 사용자 판단의 자리다 ⑶ **에픽이 규약의 「필수 섹션」을 갖췄는가** — 이 파트가 무는
> 것은 참조 정합뿐이라 완료 신호를 빠뜨린 에픽도 초록이다 ⑷ **머리의 `status:` 값이 `epic-status:`
> 선언 집합 안에 있는가** — 러너는 `open`인지만 세므로 오타는 그 에픽을 「열리지 않은 것」으로 만들어
> **규칙 1을 조용히 끈다**(이 저장소는 `M10`이 붉어 드러난다). 규약의 고지가 단일 원본이고
> ⑶·⑷는 M51 리뷰가 실측으로 더한 것이다.

## 실행

```sh
sh   tests/discover/run.sh     # Git Bash (여기서 sh = bash)
dash tests/discover/run.sh     # 우분투 러너의 /bin/sh 재현 — CI ubuntu 레그와 같은 방언
```
```powershell
powershell.exe -File tests\discover\run.ps1   # Windows PowerShell 5.1 (러너가 선언한 런타임)
pwsh          -File tests\discover\run.ps1   # PowerShell 7
```

**네 가지를 다 돌린다.** 하나만 돌리고 "양 셸 통과"라고 적으면 안 된다 — 그 문장이 네 라운드 동안
5.1 전용 결함을, 일곱 라운드 동안 dash 결함을 가렸다. `dash`가 없으면 그 축은 CI의 ubuntu 레그가
유일한 집행이다. `.github/workflows/tests.yml`이 이 매트릭스를 강제한다 —
`run.ps1`은 windows × {`powershell`(5.1), `pwsh`(7)}, `run.sh`는 bash × {windows, **ubuntu**, **macOS**}이고
**ubuntu 레그의 `sh`가 dash**이고 **macOS 레그가 BSD sed·awk**(`external-tool` 축)다.

각 러너는 전부 통과 시 exit 0, 하나라도 실패 시 exit 1이고, **위 네 실행 환경이 같은 판정**을 낸다.
그리고 러너가 **중간에 죽으면 반드시 exit 1**이다 — 두 통제는 **한 집합이 아니다**: 종료 오류를 잡는
`trap`(중단 줄 번호·원인 출력)은 **하니스 7종 전부**의 `run.ps1`이 갖고, **결과 줄만 세우는 완주
플래그**는 **6종**이 갖는다(`site-includes`가 규약 선언 블록에 **면제로 등재**돼 있다 — 그 선언이
단일 원본이고 Part K가 그것을 읽어 대조한다). 둘 중 하나라도 걸리면 성공 배너
없이 `# ABORTED …` / `# INCOMPLETE RUN …`을 찍고 exit 1이다. 이 가드가 없던 동안 `run.ps1`은
중간에 죽고도 exit 0 + 성공 배너를 냈다(M37 재작업 3 차단). 결과 줄에는 `[runtime: …]`이 각인돼
어느 런타임에서 나온 수치인지 러너 자신이 말한다. 케이스 수는
맨 위 `cases` 선언 **한 곳**에만 적는다 — 여기 다시 적으면 같은 파일 안에 두 번째 선언처가
생기고, F1이 집행하는 것은 그 첫 선언이다.
픽스처 자식 레포는 `git init`만 하면 되고 **commit은 불필요**하다(발견은 디렉터리·산출물 존재만 본다).

> **활성 가드 주의**: git 차단 동사(commit/tag/push)는 이 러너에 등장하지 않는다(셋업은 init만
> 사용). 러너를 호출하는 명령줄에도 차단 패턴이 없어야 활성 tide-guard가 막지 않는다.
> `run.ps1`은 ASCII 소스 + 한글 토큰을 **코드포인트로 구성**해 BOM 의존을 없앤다(인코딩 규약) —
> 카운터 `종`(U+C885)에 더해 Part C의 상태값·`기준선` 토큰도 `Uni` 헬퍼로 조립한다. 헬퍼 이름이
> `Cp`가 **아닌** 이유: `Cp`는 `Copy-Item`의 빌트인 별칭이고 PowerShell은 별칭을 함수보다 먼저

## 자동화로 못 덮는 부분 — 세션 레벨 수동 절차

감지 힌트의 **서술**(advisory 한 줄 `여러 자식 tide 레포 N개 감지 — 교차 개요는 /tide:fleet`을
status·kickoff 출력 맨 끝에 붙이는 LLM 행위)은 스크립트로 강제되지 않는다. 상위 폴더 단일
세션에서 다음을 수동 확인한다:

1. 자식 tide 레포 2개 이상을 둔 상위 폴더에서 세션을 띄우고 `/tide:status`(또는 `/tide:kickoff`)를
   호출한다.
2. 본래 보고 끝에 `여러 자식 tide 레포 N개 감지 — 교차 개요는 /tide:fleet` 한 줄이 advisory로
   붙고, status는 **완전 읽기 전용**(파일·git·phase 무변경), kickoff는 골격 생성 외 동작 불변임을
   확인한다.
3. 자식 tide 레포가 2개 미만(단일 레포 세션 포함)인 폴더에서 호출하면 **그 줄이 붙지 않음**(소음 0,
   기존 출력 바이트 동일)을 확인한다.

상세 규약은 `docs/conventions.md`의 "멀티 레포 오케스트레이션"(발견) 절 + 발견성 힌트 항목이
단일 원본이다.
